# v0.133: ひかるバンギラス（neo4-082）のマウンテンクラッシュ・はかいのほのお（利用者の指定）

v0.133（版 0.133.0）は、通常対戦の対象のうち最後の未登録カード、ひかるバンギラス（neo4-082。neo 第4弾）を登録する版です。2 つのワザの、原典で決まらない部分（相手の山札・エネルギーカードが

## 3. 利用者が指定した規則

利用者の指定（2026-11-01。この版の依頼）は、次の位置づけです: 「以下は利用者指定の仕様です。公式裁定、最新の説明、エラッタ、転記の訂正として扱いません。」

### 3.1 マウンテンクラッシュ（USER-MOUNTAIN-CRUSH-MILL-UP-TO-DECK）

1. 通常どおり基本30ダメージを処理する。
2. 「うら」が出るまでコインを投げる。
3. 「おもての数と相手の残り山札枚数の少ない方だけ、山札の上からトラッシュする。」

山札が 0 枚でも、山札の枚数を理由にコインを省略・打ち切りしません。ナツメのESPで投げ直した場合は、最終のコイン結果を使います。山札が空になっただけでは、その場で敗北にしません
（番の最初にカードを引けない場合の既存の規定と区別する）。相手の場のポケモンへの防護を、相手の山札への処理に自動的に流用しません。

### 3.2 はかいのほのお（USER-DESTRUCTIVE-FIRE-DECLARE-ORDER-UP-TO）

「以下の順序を採用します。」

1. 必要エネルギーとは別に、自分についている炎エネルギーカードが 1 枚以上あることを、宣言条件として確認する。
2. 自分の炎エネルギーカードの枚数だけコインを投げる。
3. おもての数だけ、自分の炎エネルギーカードを選んでトラッシュする。
4. 基本 50 ダメージを処理する。
5. おもての数だけ、相手のエネルギーカードを選んでトラッシュする。不足なら残っている分すべてを対象にする。

炎カード 0 枚なら、状態・乱数・ログを変えずに宣言を拒否します（ワザを使ってから失敗する扱いにしない）。1 枚以上あれば、おもて 0 回でも成功します（双方のトラッシュ 0 枚・基本 50 の通常の
計算）。相手に防護があっても、コインと自分の炎のトラッシュは行います。相手へのダメージとエネルギーのトラッシュは、それぞれの要素に適用される既存の防護の規定に従います。「基本 50」は
実際に 50 を与える保証ではありません（弱点・抵抗力・悪エネルギー・持続する効果などの既存の計算）。

### 3.3 記録と範囲

- 記録は v0.130・v0.132 の規則と同じ仕組み `effects.USER_SPECIFIED_RULES`（`UserSpecifiedRule`）の 2 つの対象 `neo4-082/attack/0`・`neo4-082/attack/1` です。印刷の文面・処理に使う文面
  （どちらも印刷の文面）・当てはめる場面・規則・範囲・決めないこと・利用者の指定の文・kyuura の記録の場所（記録なし）・記録しない扱い・解決済みにしない論点・指定した主体 `user`・日
  2026-11-01・出典（`source`。この文書の 3 章）に加えて、この版で加えた欄 `text_difference`（処理に使う文面と、採用した処理の差）を持ちます（v0.130・v0.132 の記録は既定値の空のまま）。
- **公式の裁定ではない記録**です。最新の説明・エラッタ・転記の訂正としては記録しません。**UQ-STATED-COUNT-SHORT・UQ-DESTRUCTIVE-FIRE-FAILURE は歴史資料上は未解決のまま**です。
- 採用した処理と原文との差（`text_difference`）:

  | 対象 | 印刷の文面が書くこと | 採用した処理 | 差 |
  |---|---|---|---|
  | マウンテンクラッシュ | 「おもて」の数ぶんのカードを相手の山札の上からトラッシュ | 「おもて」の数と山札の枚数の少ない方 | 山札が足りないときを印刷は書かない（UQ-STATED-COUNT-SHORT）。「少なければあるだけ」を補った |
  | はかいのほのお | 炎エネルギーカードを「トラッシュできないとき、このワザは失敗する」 | 0 枚は宣言の拒否、1 枚以上は「おもて」0 でも成功 | 印刷はワザを使ったあとの失敗として書く。0 枚をワザを使ったことにならない拒否にし、「おもて」0 を失敗にしない |

## 4. マウンテンクラッシュ（`DamageThenMillOpponentUntilTailsUpToDeck`）

- 要素: `Damage(OPP, Printed())` → `MillOpponentDeckUntilTailsUpTo`（`resolution/programs.py`）。ダメージは既存の計算（悪エネルギー +10・弱点・抵抗力・持続する効果・「ダメージを受けない」
  状態）で、そのあとにコイン。
- コインはワザの説明のコイン（`AttackRun.flip_until_tails`。v0.118 の「うら」が出るまで投げる共通の処理）。山札の枚数 D はコインの前に数えますが、コインを省いたり打ち切ったりはしません
  （D = 0 でも 1 枚目から投げる）。
- トラッシュは `min(H, D)` 枚（`zones.discard_from_deck`。ログ `discard_from_deck`）。H > D なら、ログ `user_rule_count_short`（公開。必要な数 H・処理できる数 D・処理した数 D・規則の id・
  処理した側のプレイヤー）を残します。H = 0 なら何もしません（ログもない）。
- 山札が 0 枚になっても負けにしません。既存の負けの判定は、番の最初に引くとき（`procedures`）だけで、この要素は判定を足していません（テストで、トラッシュのあとの局面が続き、相手の番の
  最初の引く処理で山札切れの終局になることを確かめた）。
- 相手の山札への処理で、相手のポケモンへの効果ではありません（要素の `coin_receiver` は None。相手の対戦ポケモンの「ダメージを受けない」状態はダメージの要素だけ、「ワザのダメージや効果を
  受けない」状態もダメージの要素だけを止め、山札のトラッシュには当てはめない）。これは v0.115 の `MillOpponentDeck`（やまくだき）の既存の扱いと同じです（防護を山札に広げる新しい規定は
  作っていない）。

## 5. はかいのほのお（`CoinsPerOwnTypedCardsDiscardThenDamageThenOpponentEnergy`）

要素の並び（`resolution/programs.py`）:

1. `OwnTypedEnergyCardsRequired(FIRE)`（ワザを使うための条件。処理はしない）。宣言の拒否は、実装の `usage_problem`（`effects.typed_energy_card_usage_problem`）が
   `checks.attack_request` の中で、必要なエネルギーの確かめのあと・こんらんのコインの前に返します（`IllegalActionError("NO_TYPED_ENERGY_CARDS")`。状態・乱数・ログを変えない）。数え方は
   コインの枚数と同じ `attached_basic_energy`（「炎」の基本エネルギーカードの枚数。エネルギーの個数ではない）です。
2. `Coin("coin", per_attached=FIRE)`（v0.31 の既存の要素）。その時点の「炎」エネルギーカードの枚数ぶん。ナツメのESPのやり直しの対象で、最後の結果を使います。
3. `DiscardOwnTypedEnergyByHeads(FIRE, heads_of="coin")`（`DiscardOwnEnergy` の `heads_of` と同じ処理・決定 `DISCARD_ENERGY`・ログ `discard_energy`）。選べるのはその時点でついている
   「炎」エネルギーカード、選ぶのはワザを使ったプレイヤー、ちょうど H 枚（1 枚しかなくても決定を出す既存の形）。コインの枚数がその枚数なので、足りなくなることはありません。
4. `Damage(OPP, Printed())`。自分のトラッシュのあとの、その時点の盤面で既存の計算をします（宣言のときの値を持ち越さない）。
5. `DiscardOpponentEnergyUpToHeads(heads_of="coin")`（v0.120 の `DiscardOpponentEnergyByHeads` の子）。数えるのはこの要素の時点（ダメージのあと）の相手の対戦ポケモンのエネルギーカード M
   （特殊エネルギーも 1 枚）。`min(H, M)` 枚で、`= M` ならすべて（決定なし）、`< M` ならワザを使ったプレイヤーがちょうどその枚数を選ぶ（決定 `DISCARD_OPPONENT_ENERGY`。すべての組を選べる）。
   H > M（M = 0 をふくむ）ならログ `user_rule_count_short`。親の型（たつまき）の H > M の FC1（`stated_cards_short`）はそのままです。

- **炎エネルギーカードの数え方と色の問い**: 「炎」エネルギーカードは既存の `per_attached` の数え方（基本エネルギーカード）で、色の読み方で枚数が変わりうるとき（［へんしん］TE1・
  ［すごいへんしん］SV5・レインボーエネルギー RB1・［エネエネ］BZ2・ミラクルエネルギー MEC1・色を変えたカード CE3）は、宣言の条件では拒否せず、コインの要素の既存の止め方
  （`transform_energy_question`）で宣言の前に止めます（状態を変えない）。今回の指定で色の論点（UQ-SPECIAL-ENERGY-AS-TYPED-ENERGY・UQ-SUPER-TRANSFORM-ENERGY-COLORS）を決めたことには
  していません。
- **相手の防護**: コインの要素が決める要素のうち、自分のトラッシュは相手の対戦ポケモンへの要素ではない（`coin_receiver` は None）ので、相手が「ワザをうけない」状態などでもコインを投げ
  （既存の `void_coin_question` の読み方）、自分の炎をトラッシュします。ダメージは既存のダメージの防護（かたまる・バリアー・「ダメージを受けない」など）、相手のトラッシュは既存の効果の
  防護（「ワザをうけない」状態の `reaches`・タケシの保護・［KEEP］・「とうめい」）です。ダメージだけを防ぐ状態ではトラッシュは起こり、効果も防ぐ状態ではどちらも起こりません。
- **このワザで相手が HP 以上**になったら、相手のトラッシュは処理の対象がないので処理しません（親の型と同じ。p.309）。
- **時点**: N はコインの要素の時点、自分の選べるカードはトラッシュの要素の時点（コインのあいだは変わらない）、M は相手のトラッシュの要素の時点。決定・ESPをまたぐ値は決定の続きの情報
  （`target`・`heads`。ESPは既存の `esp` の続き）に持ちます。
- **コピー・変身**: 数えるカード・トラッシュするカードは、ワザを実際に使うポケモンのカードです（`run.attacker()`）。［へんしん］・［すごいへんしん］で写したワザ・［サイコリンク］で使うワザも
  同じです（色の問いは上のとおり）。相手のワザとして使うとき（ピッピ・ピクシーの「ゆびをふる」など）は、要素の `copy_problem` がまねるポケモンのカードで数え、0 枚なら、説明が「使えない」
  「説明にしたがう」と書くコピーでは選べず（`ILLEGAL`）、条件を書かないコピーでは既存の HC9（`UNRESOLVED`）です。HC9 は既存の未解決で、今回の指定が決めたことではありません。

## 6. 先読み・上限なしのコイン・ナツメのESP

- **実際のコイン**: どちらのワザも、実際の対戦では既存の処理で投げます（マウンテンクラッシュは「うら」が出るまで 1 枚ずつ、はかいのほのおは N 枚）。山札・エネルギーカードの数で打ち切らず、
  `min` に丸めた値・先読みの代表を実際の結果にしません。ログの `coin_flip` は実際の並びです。
- **マウンテンクラッシュの先読みの組**（`capped_classes(D)`）: h = 0, 1, …, D と、D 以上の 1 つの組（代表 D）。D 以上はどれも山札をすべてトラッシュし、そのあとの処理（ワザの終わり・きぜつの
  判定）は h を読みません（h はコインの並びと `user_rule_count_short` の必要な数にだけ残る）。先読みが試すのは受け付けられるかだけで、ログ・乱数は実際の対戦のものです。v0.118 の
  `draw_classes` と同じ形ですが、根拠は p.312 の「引けるだけ」ではなく利用者の指定です（引く処理の組をトラッシュに流用していない）。H = D と H = D + 1 は、観測できる結果（トラッシュの
  枚数・場）が同じで、違うのはコインの並びと不足の記録だけです。
- **はかいのほのおの先読み**: コインは既存の `Coin` の「おもて」の数の組（N + 1）。トラッシュするカードの組（自分・相手）は、カードの種類（カード id と、この番の色の記録・エネルギー
  としての役割の有無）ごとに 1 つだけ試します（`kind_grouped_answers`。v0.127 のドライアップの先読みと同じ分け方）。同じ種類のカードは、入れかえてもこのワザの残りの処理（ダメージの
  計算・相手のトラッシュ・きぜつの判定）の結果が同じで、トラッシュしたカードの uid を読む処理がありません。実際の決定は、ちょうどその枚数のすべての組を選べます（選べるものを削っていない）。
  選ぶと止めるカード（TE2 などの `unresolved_choices`）は試しません（既存の扱い）。
- **ナツメのESP**: ナツメのESPは「ナツメのポケモン」にだけつくので、ひかるバンギラスが自分で使うときは当たりません。ナツメのフーディンが［サイコリンク］でベンチのひかるバンギラス（超の
  色マーカー）のワザを使うときに当たります。マウンテンクラッシュは「うら」が出るまでの一まとまりのあとに 1 回だけ聞き、やり直すなら最初から「うら」まで投げ直します（前のダメージの要素は
  くり返さない。決定のあと、山札のトラッシュの要素から処理し直す）。はかいのほのおは N 枚のあとに聞き、やり直すなら N 枚を投げ直します（自分のトラッシュ・ダメージ・相手のトラッシュは
  決定のあとに 1 回だけ）。
- **上限**: 先読みの上限 4,096・マチスの秘策の上限 512 は変えていません。マウンテンクラッシュの組は D + 1（山札は多くても 60 枚）、はかいのほのおの組は N + 1 と種類ごとのトラッシュの組
  なので、この 2 つのワザだけでは上限に届きません。届くのは、ほかの決定（ESPのやり直しを含む）と重なって組が増えたときで、そのときは既存の `UNSUPPORTED_PREFLIGHT_LIMIT` です（エンジンの
  未対応。正式な対戦の結果は 10 章）。

## 7. 観測・保存・不正な答え

- **観測**: `user_rule_count_short` は公開のログ（山札の枚数・場のエネルギーカードは公開の情報）。トラッシュした山札のカード（`discard_from_deck`）・エネルギーカードのログは既存のままです。
  決定は、決めるプレイヤーに選べるものを、ほかの人には種類・数だけを見せる既存の形です。
- **保存**: 決定・続きの情報は既存の `decision` の項目（`target`・`heads`・`esp`）で書けるので、**書き出しの形式は変えていません**（33 のまま）。新しいログの種類は、ログの項目をそのまま
  書く既存の形式で落ちません。決定を待つ状態の書き出し・読み込み・pickle・deepcopy・clone のあとも、同じ答え・同じ乱数から同じ結果です（テスト）。
- **不正な答え**: 決めるのでないプレイヤー・違う決定の番号・選べないカード・枚数の違う答え・決定を待つ間のほかの操作は、状態・乱数・ログを変えずに拒否します（既存の確かめ）。
- **研究上の未解決とエンジンの未対応の区別**: 利用者の指定の規則で処理する場面（3 章）は、研究上は未解決のままで、エンジンは指定に従って処理します。色の読み方・HC9 は既存の研究上の
  未解決（止める）。先読みの上限は既存のエンジンの未対応です。
