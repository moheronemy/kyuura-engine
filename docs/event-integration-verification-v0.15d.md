# 解決の基盤の全体の検証と標準の経路の切り替え（v0.15d）

v0.15d では、解決の基盤（経路 `KERNEL`。[kernel-integration-v0.15b.md](kernel-integration-v0.15b.md)・[preflight-optimization-v0.15c.md](preflight-optimization-v0.15c.md)）を、最終のコードで、固定した v0.13・同じ木の v0.13 の経路と比べ、独立した不変条件と変異試験で確かめたうえで、標準の経路（公開の `apply_command` が使う `engine.DEFAULT_ROUTE`）を `LEGACY` から `KERNEL` に切り替えました。v0.13 の経路は消していません（v0.16 で外す候補）。

- この文書の数は、すべてこのコミットの最終のコード（標準の経路 `KERNEL`）で得たものです。前の段階（v0.15a〜v0.15c）の比較の結果は流用していません。
- 「確認した事実」は実際に動かした結果、「評価」はその解釈です。

## 4. 解決の基盤の独立した不変条件

比較（v0.13 と同じ結果か）とは別に、解決の基盤そのものが守るべき性質を、解決の記録（`Trace`）と、v0.13 の公開の問い合わせ（解決の基盤の判定とは別の実装）で確かめます（tests/test_kernel_invariants_v0_15.py。経路 `KERNEL` を明示する）。対戦の集まりは、特殊能力・持続する効果がはたらく対戦のテストの方針 8 つ × seed 0〜9 と、ストレス実行の 26 組 × seed 0〜1（拒否されるコマンドを 5% 混ぜる）です。

| | 性質 | 確かめ方 |
|---|---|---|
| 1 | 窓の順番 | 枠ごとに、ダメージの要素の窓（適用の前・受けるとき）は「ダメージの要素のあと」の窓より前。受けるときの窓の直前は適用の前の窓。きぜつの判定の窓は 1 コマンドに 1 回までで、そのあとにそれまでの枠の窓がない。番の終わりの窓は 1 回まで |
| 2 | 枠の表 | 子の枠の種類は、親の枠の種類の `events.SPAWNS` にある。根の枠はワザかこんらん |
| 3 | 許されない連鎖がない | 返す効果の枠の下に返す効果の枠がない。特殊能力のダメージ・こんらんの枠は子を持たない |
| 4 | 二重の処理がない | 「ダメージの要素のあと」の窓の発動は (定義, 持ち主, 枠) ごとに 1 回。子の枠の数は発動の数以下 |
| 5 | はたらいていない特殊能力が発動しない | 「とうめい」「はんげき」の発動は、コマンドの前の状態で v0.13 の `working_evasion_power`・`working_counterattack_power` がはたらいていると答えるポケモンだけ（かがくへんかガス・ねむり・マヒ・こんらん） |
| 6 | 持続する効果ははたらく番だけ | 返す効果の発動は v0.13 の `persistent.retaliation`（はたらく番の効果）があるポケモンだけ。ダメージを無効にしたのは `persistent.damage_prevention` があるポケモンだけ |
| 7 | きぜつの順番 | 公開のログの `knock_out` は、番でないプレイヤー → 番のプレイヤー、それぞれバトル場 → ベンチ（p.323〜p.324。v0.13 と同じ） |
| 8 | 決定を待つ状態 | 再開先が解決の基盤のものなら、段階が決定の段階で、続きの情報に読みかえられ、このコマンドが出した決定は解決の記録の最後の中断と再開先・種類・プレイヤーが合う |
| 9 | 保存・復元の連続性 | 決定を待つ状態を pickle で保存・復元して答えても、そのまま答えたのと同じ結果（状態・乱数）。決定を待つ状態の保存・復元で書き出しが変わらない |
