# ディフェンダー（v0.2e）: 原典照合と実装

v0.2e で対応したディフェンダー（PMCG1-079）について、原典で確かめたこと、決められなかったこと、実装、テストを対応づけた記録です。設計（相手の番にまたがる有効期限・防御側のダメージ変更・不変条件）は [architecture-v0.2e.md](architecture-v0.2e.md) にあります。

- 基準のルール: 「ポケットモンスターカードゲーム公式ルール 2000.02.14版」（『ポケモンカードオフィシャルブック2000』pp.306〜326 [P43]、kyuura `NEO-2000-OFFICIAL-RULES`）
- カードの処理: 同じ本のカードのページの「最新の説明」（p.6「わからない内容があれば、この記述にしたがってください」。v0.2b で照合）
- kyuura の基準コミット: `ecb2d694e6280ec5dc9ddd2a8f709cea16a6b691`（読むだけ。変更していない）。カードの記録 PMCG1-079（data/cards.json）と data/rule_history.json を読んだ
- 照合の方法: Internet Archive のスキャン [J38] の PDF からページを画像にし（p.257 は約 400dpi、ほかは 200dpi）、画像を目で読んだ（2026-10-12）。OCR の文字はページの位置を探すのに使っただけ。印刷物の実物ではない
- 読んだページ: p.257（ディフェンダー。プラスパワーと同じページ）、p.309（番の流れ・ワザを使う手順）、p.310（トレーナーカードを使う）、p.311（にげる）、p.312〜313（場・ついているトレーナーの場所）、p.321（ダメージ計算の 7 段階）、p.322（どく）、p.323（ポケモンチェック・きぜつ）

分類は [pluspower-v0.2c.md](pluspower-v0.2c.md) と同じです（CONFIRMED: 原典に直接の根拠がある、SUPPORTED: 確定した規則から導出できる、UNRESOLVED: 資料だけでは決められない、CONFLICT: 資料のあいだで矛盾がある）。

**CONFLICT（印刷の文面と最新の説明）**

| 項目 | 第1弾の印刷（kyuura） | 最新の説明（p.257・p.321） |
|---|---|---|
| 効果が続く期間 | 「次の相手の番の終わりまで」 | 書かれていない。効果は「このカードをつけているポケモン」に働く（ついている間） |
| カードを捨てる時点 | 「次の自分の番の最初にはがしてすてる」 | 「次の相手の番の終わりにトラッシュする」 |
| 効果の強さ | 「「-20」できる」（任意と読める） | 「「-20」される」（必ず） |
| 効果の範囲 | 「「ワザ」によって受けるダメージ」 | 「ワザによるダメージを受けるとき」 |

第1弾の文面では、効果の終わり（次の相手の番の終わり）とカードを捨てる時点（次の自分の番の最初）が別です。最新の説明では、カードを次の相手の番の終わりにトラッシュし、効果はついている間だけなので、**効果の終わりとトラッシュの時点は同じ**です。2000.02.14版のルールの対戦では、p.6 により最新の説明にしたがいます。英語版の文面は処理の根拠にしていません。

## 2. 裁定の分類

| 4 | つける場所 | CONFIRMED | p.257、p.313 | 「つけて使い」。「ポケモンにつけて使うトレーナーカードは、それをつけているポケモンのいる場所にあることになります。たとえば、あなたの対戦ポケモンについている「ディフェンダー」は、「自分の場」にあるカードです。」 | `PokemonInPlay.trainers`（v0.2c のプラスパワーと同じ） |
| 5 | 減らす量・必ずか | CONFIRMED | p.257 最新の説明 | 「そのダメージは「-20」される。」 | -20。選べない（必ず） |

| 7 | 途中の値・最後の値 | CONFIRMED | p.321 | 「ダメージを計算している途中で、その数が0やマイナスの数字になってもかまいません。」「計算の結果、ダメージが0やマイナスの数字になったときは、ポケモンは「ダメージを受けなかった」ことになります。」 | 途中のマイナスはそのまま。最後に 0 以下なら 0 |

| 状況 | 計算（p.321 の段階） | 受けるダメージ |
|---|---|---|
| 基本 10（ビリリダマ たいあたり） | 1: 10 → 7: −10 | 0 |
| 基本 20（ワンリキー けたぐり） | 1: 20 → 7: 0 | 0 |
| 基本 30（ポニータ ほのおのしっぽ） | 1: 30 → 7: 10 | 10 |

| ディフェンダー 2 枚、基本 40 | 1: 40 → 7: 20 → 7: 0 | 0 |
| 弱点（水 → ガーディ）、基本 20 | 1: 20 → 3: 40 → 7: 20 | 20 |

| みだれづき「おもて」2 枚 + プラスパワー + ディフェンダー | 1: 20 → 5: 30 → 7: 10 | 10 |

## 4. 有効期限と番の流れ

自分（プレイヤー P）の番 n に使った場合:

| 時点 | ディフェンダー | 根拠 |
|---|---|---|
| 使った直後（番 n） | 選んだポケモンについている（`discard_at_end_of_turn = n + 1`） | p.257 |
| 番 n の終わり | ついたまま（プラスパワーはここでトラッシュ） | p.257 |
| 相手の番 n + 1 の始まり（ドロー） | ついたまま。山札がなくて相手が負けたら、対戦が終わり、ついたまま | p.309、p.311 |
| 相手の番 n + 1 のワザ | ついているポケモンが受けるダメージは 7 段階で −20 | p.257、p.321 |
| ワザのあとのきぜつ・サイド・交代 | 番はまだ終わっていない。ついているポケモンがきぜつしたら、いっしょにトラッシュ | p.323 |
| 相手の番 n + 1 の終わり | トラッシュ（ワザを使わずに番を終えても同じ）。ポケモンチェックの前 | p.257、p.309、p.323 |
| 自分の番 n + 2 | ついていない。効果もない | — |

## 6. kyuura の記録との違い（報告事項）

- kyuura の cards.json の `trainer.text.ja` は第1弾の印刷の文面で、最新の説明（p.257）とは、トラッシュの時点（次の自分の番の最初 / 次の相手の番の終わり）と「できる」/「される」が違います。エンジンは登録の照合（`TrainerEntry.text_ja`）にだけ使います。
- プラスパワーには、印刷の文面と最新の説明を分けた記録 `ERR-PLUSPOWER` がありますが、ディフェンダーにはありません（参照コミットの data/rule_history.json で確認）。kyuura 側で、同じ形の記録を加えるかを検討してください。kyuura は変更していません。
