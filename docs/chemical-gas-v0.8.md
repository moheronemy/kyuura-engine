# ベトベトンの「かがくへんかガス」の原典の照合と裁定（v0.8）

v0.8 でベトベトン（PMCG3-007。ポケモンカード第3弾化石の秘密）のポケモンパワー「かがくへんかガス」を対戦で使えるようにするために、『ポケモンカードオフィシャルブック2000』[P43] で確かめた記録です。進化元のベトベターとワザは [grimer-line-v0.8.md](grimer-line-v0.8.md)、常にはたらく効果の求め方は [continuous-effects-v0.8.md](continuous-effects-v0.8.md)、設計は [architecture-v0.8.md](architecture-v0.8.md)、確かめた結果は [v0.8-verification.md](v0.8-verification.md) です。照合の記録は kyuura_engine/data/card_verification.json の PMCG3-007。

## 1. 確かめ方と使わなかった資料

- Internet Archive のスキャンの PDF からページを画像にし（300dpi。カードの図版の小さな文字は 600dpi で拡大）、目で読んだ。PDF の文字（OCR）は、ページの位置を探すのに使っただけ。
- 照合したのは p.48 の真ん中の「ベターから進化 ベトベトン LV.34／HP70」「ポケモンカード第3弾化石の秘密」のカード。同じページのキョウのベトベター（ジム拡張第2弾）・わるいベトベトン（第4弾ロケット団。［ねんちゃくえき］）、p.49 のキョウのベトベトンは別のカードで、代わりにしていない。
- 当時の公式の Q&A・訂正をウェブで探したが、2000.02.14 版の時期の日本語の資料は見つからなかった（見つかったのは現代のカードの「かがくへんかガス」（特性）だけで、使っていない）。
- 使わなかった資料: 英語版の文面（kyuura の `text.en`。「Ignore all Pokémon Powers other than Toxic Gases…」）、後年の規定（kyuura の rule_history.json の `card_lists.poke_body`。2002-05-24 の Q&A の「ポケボディー」一覧で、2000.02.14 版の規定ではない）、現代の「特性」「ポケボディー」「ポケパワー」のルール。

## 4. 「使えず」と「力も消える」（A4）

| 区別 | 原典の確認結果 | 分類 | 実装 |
|---|---|---|---|
| 1. 宣言して使う特殊能力を禁止する | 「すべての「特殊能力」は使えず」。p.311 は「そのとき使うことのできるもの」の使用を宣言できる | CONFIRMED | エナジートランス・あまごい・ダメージスワップの使用を、宣言の前に `POWER_SUPPRESSED` で拒否（宣言のログもない。v0.5 の P12 と同じ考え方） |
| 2. 継続的にはたらく特殊能力の効果を消す | 「その力も消える」。p.323 の例は、常にはたらく・自動的にはたらく特殊能力について「この力は消える」と書く | SUPPORTED（「使えず」と「力も消える」の書き分け） | v0.8 の対応カードに、ほかの常にはたらく・自動的にはたらく特殊能力がないので、処理はない（加えるときに、その効果を使う前に `continuous.suppressors_of` を聞く） |
| 3. 既に完了した特殊能力の処理を取り消す | 取り消すとは書かれていない。処理はすませてある（p.311・p.323） | SUPPORTED（取り消さない） | 何も戻さない（G27） |
| 4. 特殊能力の実行途中に条件が変わる | 起こらない（宣言したら、すべてすませてからでないと他のことはできない。p.311・p.323。v0.8 の対応の特殊能力は、ベトベトンの場所・特殊状態を変えない） | CONFIRMED（起こらない） | 宣言の前に 1 回だけ求める |
| 5. 能力が再び有効になったときの扱い | 「場にいるかぎり」「状態のとき」は条件で、条件がなくなれば消えていた効果はなくなる（p.265「一時的に消す」） | ベトベトンがいなくなる: CONFIRMED。特殊状態からの回復: SUPPORTED | その時点の状態から求めるので、同じ番でも使える |

5 つを同じ処理にまとめていない。実装したのは 1 だけ（2 は対象がない、3 は何もしない、4 は起こらない、5 は状態から求めることの結果）。

## 5. 原典で決められないこと

かがくへんかガスの処理で、原典で決められない場合は見つからなかった。新しい `UNRESOLVED_…` のコードは加えていない（v0.7 までの 12 のコードは変えていない）。v0.6 の R13（`UNRESOLVED_ATTACH_AFTER_POWER_ATTACH`）は変えていない（G29）。

実装上の仮定: G30 の拒否のコード（`POWER_NOT_DECLARABLE`）、G32 の拒否のコードの順番、消されている特殊能力の使用は宣言もなかったものとして拒否する（v0.5 の P12 と同じ）。
