# v0.188: R-2 の初回対応（うらのバトル場のワザの宣言にクチバシティジムのコインを示す）

2026-11-16。`kyuura_engine` の版は 0.188.0。設計と採用の経緯は [legal-actions-r2-face-down-declaration-design.md](legal-actions-r2-face-down-declaration-design.md) の 9 章・10 章です。

## 1. 変えたこと

- 合法手 API の本人のうらのバトル場のポケモンのワザの候補（`legal_actions._face_down_attack_candidate`）の 2 段目に、次のすべてを満たすときだけ、クチバシティジムのコイン（`stadium_coin`）を 1 つ示します（どのワザにも同じ選択肢）。
  - 番のプレイヤーの main の段階で、本人のバトル場のポケモンがうら
  - 場のスタジアムがクチバシティジム（`AttackCoinStadium`。`stadium_of`）
  - 本人が知る本当のカードの印刷の名前が「マチスの」で始まる（`_owner_named`）
  - 本当のカードが特殊能力を持たない
- たねでない「マチスの」カードにも同じ条件で示します（公開のあとのトラッシュを予告しません）。
- 候補・選べるものは `unverified`・`face_down_reveal_not_evaluated` のままです。check は入力の形だけを確かめ、エンジンを呼びません。**コインを示すことは、受理・コインを投げることの保証ではありません。**
- 段・選べるもの・組の形は、おもてのワザの宣言のコインと同じです（`_stadium_coin_addon` を共有）。示さないときの 2 段目は 0.187.0 と同じです。
- `GUARANTEE_FACE_DOWN_ATTACK` の文と、R-2 の residual の note を動作に合わせました。R-2 は residual に残ります（`not_offered`。ほかの追加選択、特に場のポケモンの特殊能力 `with_power` は未対応）。

変えていないこと: 送信の処理の順（おもてにする → たねでなければトラッシュして受理 → 確かめ・先読み・処理）、エンジンのゲーム処理・裁定・規約、judge の判定条件、検証用 AI の方策、GUI、API・計画・完了の形式。

## 2. エンジンが拒否する場合（既存の動作。変えていない）

構築盤面で、登録の「マチスの」ポケモン 28 枚の印刷のワザを、クチバシティジムの場で直接のコマンドで送って数えました（証跡の `probe_engine_coin.json`）。

- たねでない 10 枚: コインの有無によらず受理（おもてにしてトラッシュ。コインは投げない）。
- たね 18 枚・32 のワザ: コインつきで受理は 7 ワザ。25 ワザはエンジンが拒否します。24 は `UNRESOLVED_SECRET_PLAN_HIDDEN_PROPERTY`、1 はクチバシティジムの VM1 です。コインなしで受理されるのは 14 ワザで、7 ワザはコインを選ぶと拒否に変わります。
- 理由: 宣言の前の先読み（`derived` の `siblings`）が、実際と違うコインの結果を、コマンドの入口の状態（おもてにする前）の複製で試します。そこでうらのカードの項目（最大HPなど）を読み、FD1 で止まります。ワザ自身がコインを投げる場合はコインなしでも同じです。拒否は状態・乱数・ログを変えず、相手・観戦者へ知らせません。
- この扱いを変えるかは、エンジンの先読みの別の単位です（利用者の判断）。→ 2026-11-16: 原因を調べ、修正を設計した（未実装）: [先読みの FD1 の調査と修正設計](r2-coin-preflight-design.md)
