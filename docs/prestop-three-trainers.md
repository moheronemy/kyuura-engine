## 3. 根拠の強さの区分

| 条件 | 区分 | 理由 |
|---|---|---|
| きずぐすり: ダメージのあるポケモンがいない | エンジンが保守的に止めている（一次資料に記述がない） | P43 p.254・p.310 に、使うための条件も効果のない使い方も書かれていない（エンジンの記録）。kyuura は原典を確かめていない（`out_of_scope`） |
| ポケモンいれかえ: 自分の控えがいない | 同上 | p.311 の規定は「にげる」のもので、トレーナーには書かれていない（エンジンの記録）。kyuura は `out_of_scope` |
| 突風: 相手の控えがいない | 資料のあいだの解釈が未確定 | 印刷の文面（使えない）と最新の説明（書いていない）が食い違う。エンジンの方針（最新の説明を採り、印刷で補わない）と kyuura の論点（UNRESOLVED）がある |
| AL2・SG1・MH1・MH2・TK1 | 既存の裁定の記録（エンジン）がある未裁定 | どれも 3 枚に固有でない共通の条件（各版の文書・停止の台帳） |
| MG1 | 同上 | トレーナー全般の条件 |
| x1 でどの条件だったか | 記録不足で特定できない | 記録に停止コードがない（応答に出ない） |

- 新しい解釈は確定していません。現代のルールを遡って当てていません。

**候補・check・送信の違い**

| 扱い | 起こること | どこで決まるか |
|---|---|---|
| 候補に出さない | ゲーム上できない（`IllegalActionError`。使用の禁止・番でない など） | `legal_actions._trainer_candidate` が、そのカードを選択肢に入れない |
| 未裁定として示す | `UnsupportedError` のカードは、選択肢に `processability: unresolved_ruling`・`eligible: false`・理由 `stops_before_acceptance` で入る。手札のトレーナーがすべてそうなら、候補全体が `unresolved_ruling` | 同上（`_stop_processability`。停止コードは区分に変えるだけで、応答に出さない） |
| check | その選択肢を選んだ入力は `CANDIDATE_NOT_EXECUTABLE`（形だけを確かめ、受理の保証ではない） | `_input_problem` |
| 送ると拒否 | API の送信は check と同じ確かめで断る。エンジンへ直接コマンドを送れば、`apply_command` が同じ確かめで `UnsupportedError`（状態は変えない） | `engine.check_play_trainer` |
| 方策 | 候補全体が未裁定なら範囲の外（`processability:unresolved_ruling`）。選ばれた候補の中の未裁定の選択肢は、入力の組み立てで外す（`option_allowed`） | `runner._scope`・`actions.option_allowed` |
