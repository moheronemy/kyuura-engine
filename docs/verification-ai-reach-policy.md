## 2. 新しい方策の責任

- 名前・版: 方策 `reach`・版 1。既存の uniform・rules-v1・rules-v2・mixed・boundary は変えない（別の名前・別の版。既存の方策の行動の指紋を保つ）
- 方策がするのは、ランナーが渡した**範囲の中の候補**と、行動生成が渡した**段の選べるもの**から位置を選ぶことと、送る前の評価（`review`）で送らないことを選ぶことだけ
- 共通の部品をそのまま使う: 範囲（プロファイル boundary: 表示だけ・入力を返さない・実行できない区分は外す）、行動生成（`actions.build_choices`）、check、submit、記録、判定（規則 6）。
  表示だけ・`withheld`・実行できない候補は範囲に入らないので、方策は送れない
- 合法性・処理可能性・受理を判定しない。カードの効果・費用・タイプ・段階・ベンチの上限を読まない。内部状態・相手の秘密・エンジンの乱数・効果の試行を参照しない。
  公開の API にない入力を作らない（選べるものの位置を返すだけ）
- **本人の観測の `real`（自分のうらのカードの本当のカード）は使わない**。P6・U-R3a の候補は API の契約の値（種類・理由・`face_down`・段の数）だけで見分けられ、
  うらのカードがあるかは観測の `face_down` で分かる
- カード別の準備・到達目標は**実行の設定**（計画の局の `config.reach`。3.1 節）に閉じ込める。共通の行動生成・範囲・判定にカード名・カード ID の分岐を加えない。方策が設定のカード ID と
  照らすのは、本人に見える手札の `card_id`（観測の手札・候補の段の選べるもの）だけ

## 3. 選択規則（仕様）

### 3.1 設定（計画に保存する。局ごとに同じ値を両方の主体に）

| 項目 | P6 | U-R3a | 意味 |
|---|---|---|---|
| `goal` | `p6` | `u_r3a` | 目標 |
| `place_trainers` | `["PMCG5-093"]` | `["PMCG5-093"]` | うらで出すトレーナーの `card_id`（マチスの秘策） |
| `place_cards` | `[]`（どれでもよい） | `["PMCG1-049"]` | 秘策の決定で選ぶ手札の `card_id`。空なら手札のどれでもよい（均等） |
| `move_to_active` | `true` | `false` | うらの控えをバトル場へ移す選好（1.1 節の d） |
| `protect_own_turns` | 3 | 3 | うらで出した番を 1 として、守る自分の番の数 |

| `base` | `rules-v2` | `rules-v2` | 上の規則が当たらないときの選び方（閾値 2） |

### 3.2 状態（主体ごと。毎回のエピソードの始めに本人の観測から決め直す）

- `fd_bench`・`fd_active`: 本人の観測の自分の場のうらのカードの有無と位置（`face_down`。`real` は読まない）
- `phase`: `seek`（自分のうらのカードがない）→ `placed`（ベンチにうら）→ `active`（バトル場にうら。P6 だけ）→ `done`（目標の操作を送った。または送る回数を使い切った）。
  `seek`・`placed`・`active` は観測から毎回決める（相手のワザ・効果でおもてになれば、次のエピソードで `seek` に戻る）。`done` は方策が持つ
- `protect_until`: うらで出した番（観測の区間・番の番号）から自分の番を `protect_own_turns` 回数えるまで。過ぎたら `expired`（保護をやめ、そのうらのカードが場から消えるまで
  P6 の移す選好・置く選好も止める）
- `tries`: 目標の操作を送った回数（`review` で送ると決めたときに数える。P6・U-R3a の check は形だけなので、作った入力は通る。通らなければ既存の異常として記録される）

### 3.3 候補の順位（番の操作。小さいほど先。同順位は方策の乱数で均等）

`done` でなく、`expired` でないときだけ R0〜R2 と保護を当てる。どれも当たらなければ、基礎（rules-v2 の順位と反復の抑制）で選ぶ。

| 順位 | 規則 | 当てる条件 | 選ぶ候補 |
|---|---|---|---|
| R0 | 目標の操作 | P6: 候補に `kind` `retreat` で理由 `face_down_reveal_not_evaluated` があるとき。U-R3a: 候補に、`kind` `use_power`・`power.face_down` と `pokemon.face_down` が真・理由 `face_down_reveal_not_evaluated`・`input_stages` が 2〜3 段のものがあるとき | その候補 |
| R1 | うらの控えをバトル場へ（P6 だけ） | `phase` が `placed`、`move_to_active` が真、P6 の候補がなく、通常のにげるの候補（理由に `face_down_reveal_not_evaluated` がない `retreat`）があるとき。同じ番に 1 回まで | 通常のにげる（入れ替え先は 3.4 節） |
| R2 | うらで出す | `phase` が `seek`、本人の手札（観測）に `place_trainers` のカードがあり、U-R3a では `place_cards` のカードもあるとき。同じ番に 1 回まで | `play_trainer`（トレーナーの段は 3.4 節） |
| 保護 | おもてにしない | `phase` が `placed`・`active` のあいだ | `reveal_face_down` を基礎の `end_turn` より後ろ（rules-v2 の下げた順位 7 と同じ位置）へ下げる |
| 基礎 | rules-v2 | ほか | 既存の `RulePolicy`（版 2）と同じ |

- R0 はどちらの目標でも、置いた番か次の自分の番かを問わない（番をまたいだ場合も同じ）。R1 は P6 の候補がまだないときだけ（同じ番に R1 → R0 と続く）
- 答える決定（`answer_decision`）だけの場面は候補の順位を使わず、段の選好（3.4 節）だけを当てる（決定の候補は 1 つ）

### 3.4 入力の段の選好（ほかは uniform-stage のまま）

行動生成が段ごとに方策を呼ぶとき（`purpose` が `count`・`option`。文脈に候補と段がある）だけ当てる。選べるもの・数の範囲は行動生成が契約から作ったもので、方策は位置を選ぶだけ。

| 場面 | 当てる条件 | 選好 |
|---|---|---|
| トレーナーの段（`play_trainer`・`role` `trainer`） | R2 で選んだ候補 | `card_id` が `place_trainers` の選べるもの（同じものが 2 枚以上なら均等）。なければ均等（理由 `reach:trainer_not_offered`。3.5 節の送る前の評価で 1 回止める） |
| 秘策の決定（`decision_kind` `secret_plan_card`） | `done` でない | `count`: 置くカードがあれば 1、なければ 0（U-R3a で `place_cards` が選べるものにない）。`option`: `place_cards` があればその中で均等、空ならすべてで均等 |
| 通常のにげるの入れ替え先（`role` `new_active`） | R1 で選んだ候補 | `face_down: true` の選べるもの（2 匹以上なら均等） |
| バトル場に出す決定（`decision_kind` `promote_active`） | P6 で `phase` が `placed` | `face_down: true` の選べるもの。U-R3a は均等（基礎のまま） |
| 目標の操作の段（P6 のトラッシュ・U-R3a の `source`・`target`） | R0 | uniform-stage のまま（入力の中身は目標ではない。受け付けるかはエンジンが決める） |
| ほかの段（保護のあいだ） | `phase` が `placed`・`active` | `face_down: true` でない選べるものがあれば、その中で均等（うらのカードを効果の対象に指定しない選好。なければ均等） |

### 3.5 送る前の評価（`review`。送らないことを選べる。合法性の判定ではない）

1. 保護のあいだ、選んだ入力の意味（`action_key` の入力）が、上の表で許した場面（入れ替え先・`promote_active`・目標の操作）以外で `face_down` の選べるものを含むなら、
   1 回だけ送らない（理由 `reach:protect_veto`）。同じエピソードでその候補を下げ（rules-v2 の下げた候補と同じ位置）、下げた候補しか残らなければ送る（`reach:protect_no_alternative`）。
   これで、うらのカードへの進化（`evolve` の unverified の組）などを避けつつ、選び直しが止まらないことを防ぐ
2. R2 で選んだ `play_trainer` の入力が `place_trainers` でないなら、1 と同じく 1 回だけ送らない（`reach:trainer_not_offered`）
3. 目標の操作（R0）なら送る（`reach:target_send`）。`tries` を 1 増やし、`tries_per_game` に届けば `done`
4. ほかは rules-v2 の評価（同じ番の同じ操作の受理 2 回で抑える）

### 3.6 目標の達成・断念・復帰

- **達成（到達）**: 目標の操作を送った（受理・拒否・停止のどれでも）。そのあと、その主体はその局の終わりまで基礎（rules-v2）だけで選ぶ（`done`。保護もやめる）
- **断念**: (1) 保護の番数を過ぎた（`expired`。そのうらのカードは基礎のまま扱う。場から消えたら `seek` に戻り、置く選好を再開）、(2) 前提が揃わないまま局が終わった・単局の上限に
  届いた（方策は何もしない。計測で段ごとに分ける）。前提を満たすために局・seed・条件を足さない
- **復帰**: R0〜R2 と保護が当たらないときは、いつも基礎で選ぶ。目標のために `end_turn` を遅らせ続けない（R1・R2 は同じ番に 1 回まで、保護は `reveal_face_down` を下げるだけ）
- **無限の反復を防ぐ**: 目標の操作は主体ごとに局で 1 回、R1・R2 は番ごとに 1 回、送らない評価は候補ごとに 1 回で、そのあとは下げる。ランナーの既存の上限（同じ状態の選び直し 64・
  拒否 16・操作・受理・番・時間）はそのまま

|---|---|
| 候補の `kind`・`reasons`・`processability`・`input_stages`・`power.face_down`・`pokemon.face_down` | 目標の操作・通常のにげるの見分け（契約の値） |
| 段の `role`・`decision_kind`・選べるものの `face_down`・`card_id`（本人の手札・場の公開の値） | 段の選好 |
| 本人の観測の自分の場の `face_down` の位置、手札の `card_id`、区間・番の番号・番のプレイヤー・段階 | 状態（3.2 節）・R2 の条件 |
| 計画の `config.reach` | 目標とカード ID |

使わないもの: 観測の `real`、相手の手札・山札・サイド・うらのカード、エンジンの状態・乱数・ログの完全な記録、check・submit の結果（`review` で送ると決めたことだけを数える）、
カードの効果・費用・タイプ・段階・ベンチの上限。

### 3.8 既存の boundary との違い

boundary は、処理可能性の区分を均等に選び、その中の候補を均等に選ぶ（目標を持たない）。`reach` は目標の段に当たる候補・選べるものを先に選び、ほかは rules-v2 の順位で選ぶ
（区分の均等は使わない）。範囲はどちらもプロファイル boundary（`unverified` を範囲に入れる。P6・U-R3a の候補は `unverified` なので、deep では代替のときしか範囲に入らない）。

## 5. 計測と分類

`reach` の局は、既存の方式と別の方式名で集計する（`aggregate` の方式ごと）。目標・主体ごとに、次の段を数える（数えるのは `reach_report`。公開の要約には件数だけ）。

| 段 | P6 | U-R3a | 読むもの |
|---|---|---|---|
| 1 | 自分の番の MAIN に、秘策が手札にある | 秘策と `place_cards` が同時に手札にある | 本人の観測 |
| 2 | 秘策を使って受理 | 同じ | 選択・submit |
| 3 | 秘策の決定で 1 枚出した（`secret_plan_none` は前提不足） | `place_cards` を出した | 決定の入力・公開ログ |
| 4 | うらのままバトル場へ移った（R1 のにげる・`promote_active` の別に） | —（要らない） | 本人の観測 |
| 5 | 候補が示された | 同じ | 候補 |
| 6 | 入力を作れた | 同じ | 行動生成の記録 |
| 7 | check を通った | 同じ | check |
| 8 | submit した | 同じ | submit |
| 9 | 受理・拒否・停止 | 同じ | 判定（規則 4・5） |
| 10 | 受理の内訳: おもてにしてにげた・たねでないのでトラッシュ。拒否の元のコード | 受理の内訳: おもてにして使った・たねでないのでトラッシュ。拒否の元のコード | 公開ログ（`public_events_after_accept`）・判定 |

届かなかった理由は、最後に届いた段で分ける:

- **前提不足**: 秘策・対象のカードが手札に来ない、ベンチが満杯（`secret_plan_none`）、控えがいない、にげるの候補が出ない（ねむり・マヒなど）、局が先に終わった
- **相手・効果でおもてにされた**: うらのカードが、相手のワザのダメージ・効果の指定で `secret_plan_revealed` になった（段 3 と段 5 のあいだ）
- **方策が選ばなかった**: 候補・選べるものはあったが選ばなかった（保護の期限切れ・`done` のあと・送らない評価）
- **入力非公開**: 候補が `unconfirmed`（範囲の外）
- **入力を作れない・check 不合格**: 行動生成の `Unbuildable`・check の invalid（P6・U-R3a では契約との矛盾として既存の異常に記録される）
- **拒否・停止**: 判定の規則で正常な拒否・known_stop・undetermined に分ける。拒否・未到達をすぐにエンジンの不具合としない

観測の記録（必須）では、計画 4 の 7.2 節と同じ境界（本人の観測にだけ本当のカード・おもてにしたあとの 3 主体の同じ公開・拒否で相手と観戦者へ更新がない）を、到達した場面だけ確かめる。
