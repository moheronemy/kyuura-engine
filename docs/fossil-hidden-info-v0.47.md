## 2. 印刷の分類と場での役割（なにかの化石・ピッピ人形）

カードの文面: なにかの化石「このカードはポケモンとして場に出すことができ、場に出ている限りポケモンとしてあつかわれる。このカードには、「なにかの化石から進化」と
書かれている進化カードを重ねることができる。進化カードがのっていないときに限り、「きぜつ」しても「きぜつ」とカウントされず、自分の番の好きなときに自分のトラッシュに
すてることができる。」、ピッピ人形「ポケモンとして場に出すことができる。「きぜつ」しても「きぜつ」ポケモンとしてカウントされない。自分の番の好きなときにすてることが
できる。場に出ているとき以外は、トレーナーカードとしてあつかう。」。カードの文面はルールに優先します（GR-2000-P307-CARD-OVER-RULE）。

### 2.1 カードの定義の持ち方

- 印刷の分類はトレーナーカードのままです（写し・`CardDefinition` を変えない。写しを手で直さない）。場にいるあいだだけ、場での役割の定義（`PlayAsPokemon.in_play_definition`。
  `category` は `"pokemon"`・`stage` は `"basic"`・HP 10・タイプなし・弱点なし・抵抗力なし・ワザなし・特殊能力なし・`play_role` は `"fossil"`／`"doll"`）でポケモンとして
  あつかいます。印刷の定義とは別のインスタンスで、印刷の定義の `play_role` はいつも None です。
- どちらの定義を使うかは、カードの場所で決まります。`GameState.card_def(uid)` は、そのカードが場のポケモンを作っているカード（いちばん上か、進化して下に重なった
  カード）であるあいだだけ場での役割の定義を返し、手札・山札・サイド・トラッシュ・使っている最中のトレーナーでは印刷の定義を返します。ほかのカードはどこにあっても
  印刷の定義で、v0.46 までと同じです。場所によらない定義は `GameState.printed_def(uid)`（印刷の定義）と `GameState.in_play_def(uid)`（場にいたときの定義。ログから
  場を組み立て直す監査・不変条件が使う）。「場にいる」の印・一覧を状態に持たず、問い合わせのたびにその時点の場から求めます（進化・きぜつ・場をはなれる・保存と復元の
  あとも同じ答え）。
- そのため、場の外ではトレーナーカードとしての規定がそのまま当てはまります: デッキの検査（同じ名前のカードは 4 枚まで。トレーナーとして数える）・対戦準備の
  たねポケモンの確かめ（3 章の PF1）・手札のたねポケモンをベンチに出す操作（`PlayBasicToBench` は受け付けない）・山札からたねポケモン・ポケモンを選ぶ効果（なかまを
  よぶ・たすけをよぶ・ポケモン交換おじさんなど。選べるものに入らない）・トレーナーを選ぶ効果（おつかい・トラッシュのトレーナーを手札にもどす効果。選べるものに入る）・
  トレーナーの使用の禁止（5 章）。
- HP 10・弱点なし・抵抗力なしは、pcg-search.com の同じ版のページの「トレーナー」「HP:10」「弱点 -」「抵抗力 -」の表示です（kyuura の写しのトレーナーのデータに
  HP などの欄がないので、採用の記録に書いた。kyuura のデータは書き換えていない。kyuura への報告事項）。タイプ（色）は、印刷の文面・ページのどちらにもないので「なし」です。

### 2.2 場に出す

- 使う（`PlayTrainer`）と、手札から出し（ログ `play_trainer`）、自分のベンチの最後にポケモンとして出します（`zones.put_trainer_into_play`。ログ
  `play_trainer_as_pokemon`）。トラッシュしません（`TrainerEffect.enters_play`。使い終わったら場にいることを不変条件で確かめる）。カードは使用中（`trainer_in_use`）から
  場に移り、同じカードが 2 か所にある瞬間はありません。場のポケモンの番号・場に出た番は、手札から出すたねポケモンと同じ `zones.enter_play` で決まります。
- ベンチに空きがなければ、手札から出す前に `BENCH_FULL` で拒否します（状態・乱数・ログは変わらない）。バトル場には直接出しません（手札からポケモンを出す先は
  ベンチ。p.309）。トレーナーカードを使うことなので、トレーナーの使用の禁止（［アレルギーかふん］・ずつう・こうしゅうは）で止まります（5.2 節）。

### 2.3 場にいるあいだ

- 場のポケモンの規定のまま扱います: エネルギーをつける・ついているトレーナー（プラスパワー・ディフェンダーなど）・特殊状態（どく・ねむり・マヒ・こんらん）・
  ダメージ・ポケモンいれかえ・突風・ワザの入れ替えの対象。印刷の文面に制限がないので、英語版の「can't be Asleep, Confused, Paralyzed, or Poisoned」「can't retreat」は
  持ち込んでいません。ワザ・特殊能力はないので、バトル場にいてもワザは使えません（`UseAttack` は既存の確かめで拒否）。「にげる」は 3 章の PF2 です。
- 進化: なにかの化石には「なにかの化石から進化」の 1 進化カード（オムナイト・カブト・プテラ）を、たねポケモンと同じ手順（`EvolvePokemon`・`evolution.place_evolution_card`。
  p.310 の制限（おたがいの最初の番・その番に場に出したポケモン）も同じ）で重ねます。ダメージ・エネルギー・ついているトレーナーは受け継ぎます。重なったなにかの化石の
  カードも場にあるので、場での役割の定義のままです（いちばん下の「たね」の位置）。進化カードがのったら、いちばん上の定義（オムナイトなど）がそのポケモンで、
  きぜつはカウントされ、場からすてられません。ピッピ人形に重ねられる進化カードはありません（`EVOLUTION_NAME_MISMATCH`）。
- 「きぜつ」してもカウントされない（いちばん上がなにかの化石・ピッピ人形のとき。`effects.counts_as_knockout`。きぜつの処理の前に、場にいるうちに聞く）: きぜつの処理
  （トラッシュ。ついているカードも）はしますが、相手はサイドを取りません。ログ `knock_out` に `counted: False` を書きます（カウントされるきぜつのログは v0.46 と同じ形）。
  ワザのあと・特殊能力のあと・ポケモンチェック（どく）のどのきぜつでも同じです（解決の基盤の `_knock_out_all` に共通にした）。バトル場が空けば今までどおり控えから出し、
  控えがいなければ負けです（p.311。サイドを取らなくても、場にポケモンがいない）。不変条件（サイドを取る決定の並び）とログの監査は、カウントされないきぜつを
  サイドの数に入れません。

### 2.4 場からすてる（`DiscardFromPlay`）

- 新しいコマンド `DiscardFromPlay(player, pokemon)`（辞書の `"discard_from_play"`）で、自分の番（`Phase.MAIN`）に、自分の場のなにかの化石・ピッピ人形（進化カードが
  のっていないもの。バトル場でもベンチでもよい）を、ついているカードといっしょにトラッシュにすてます（`zones.discard_from_play`。ログ `discard_from_play`。持続する効果は
  理由 `discard_from_play` で消す）。きぜつではないので、相手はサイドを取りません。
- トレーナーカードを使うことでも、特殊能力の使用でもありません（宣言しない）。トレーナーの使用の禁止・かがくへんかガス・特殊状態はすてることを止めません（文面に制限がない）。
- バトル場のものをすてたら、v0.42 の特殊能力のあとと同じ使用後の処理（`resolution.after_power`。勝ち負けの判定 → バトル場に出す決定 → 自分の番にもどる）に進みます。
  控えがいなければ、場にポケモンがいないので負けです（p.311）。
- 拒否（どれも状態を変える前）: 進化カードがのっている・ふつうのポケモン（`NOT_DISCARDABLE`）、相手の場のポケモン（`POKEMON_NOT_YOURS`）、場にいない番号
  （`POKEMON_NOT_IN_PLAY`）、自分の番でない（`NOT_YOUR_TURN`）。

## 3. 決められない場合（PF1・PF2・PF3）と実装上の判断

| 裁定 | 停止コード | 場面 | 止める時点 |
| --- | --- | --- | --- |
| PF1 | `UNRESOLVED_PLAY_AS_POKEMON_SETUP` | 対戦準備で、手札にたねポケモンがなく、なにかの化石・ピッピ人形がある（切り直すか、最初のポケモンとして出せるか）。また、対戦準備で、これらを最初のポケモン（バトル場・ベンチ）として出す操作 | 切り直しの前（`Phase.HALTED`）／その操作を状態を変える前に拒否 |
| PF2 | `UNRESOLVED_PLAY_AS_POKEMON_RETREAT` | バトル場のなにかの化石・ピッピ人形が「にげる」（にげるエネルギーの数） | エネルギーのトラッシュ・こんらんのコインの前 |
| PF3 | `UNRESOLVED_BREEDER_ON_PLAY_AS_POKEMON` | ポケモン育て屋さんで、場のなにかの化石に 1 進化を飛ばして 2 進化カード（オムスター・カブトプス）を重ねる | 組がそれだけなら使う前、ほかに組があればなにかの化石を選ぶ答え（`unresolved_choices`） |

- PF1: 公式ルール 2000.02.14版（p.308 の「たねポケモン」の記録）とカードの文面は、場に出ているとき以外トレーナーカードであるこれらを、対戦準備で最初のポケモンとして
  出せるかを書いていません。1997 年の会報 Vol.2 の第2版の時期の記述（kyuura rule_history.json の P35）は別の版の記録なので使いません。推測で決めず、v0.1 の切り直しの
  補償（`UNRESOLVED_MULLIGAN_COMPENSATION`）と同じ形で対戦を止めます（ログ `halted` の `players` に当たったプレイヤー）。手札にたねポケモンもあれば対戦準備は続き、
  なにかの化石・ピッピ人形を最初のポケモンとして出す操作だけを止めます。
- PF2: 印刷の文面に「にげる」の記述がなく、kyuura の写しのトレーナーのデータに「にげる」の欄がなく、pcg-search.com のページの「にげる -」は、にげるエネルギーが 0 の
  ポケモン（マンキーなど）と同じ表示で 0 と「にげることができない」を区別しません。英語版の「can't retreat」は持ち込みません。`effects.retreat_cost`（v0.46 の公開の
  問い合わせ）もこの場合は PF2 を投げます。ポケモンいれかえ・突風・ワザの入れ替え・きぜつのあとのバトル場に出す決定は「にげる」ではないので使えます（p.325）。バトル場の
  ふつうのポケモンが「にげる」でベンチのなにかの化石と入れかわることもできます（にげるエネルギーはバトル場のポケモンの数）。
- PF3: 場のなにかの化石は「ポケモンとしてあつかわれる」が、印刷のたねポケモンのカードではありません。ポケモン育て屋さんの最新の説明（p.259。v0.25 の記録）・解説（たね
  ポケモンの例）・なにかの化石の文面（「なにかの化石から進化」と書かれている進化カードを重ねる）から、1 進化を飛ばす進化に使えるかは決まりません。系統の確かめ
  （v0.25 の `stage1_evolves_from`）はなにかの化石の名前で合ってしまうので、場での役割の組を別に止めます（`_skip_unresolved_targets`）。
- 実装上の判断（タイプのない場のポケモン）: 場のなにかの化石・ピッピ人形はタイプ（色）を持ちません。「相手の対戦ポケモンと同じ色の控えポケモン全員」（v0.39 の
  ビリビリ）で、相手の対戦ポケモンがこれらなら、同じ色の控えポケモンはいないとします（タイプなしを「タイプでしぼらない」と読まない。`programs.BenchDamage.targets`）。
  「「水」ポケモン以外のポケモン全員」（ウォーターリング）にはふくまれます。弱点・抵抗力はどちらもないので、計算の 3・4 段階は何もしません。

## 4. 化石のポケモンと、見えないカードを扱う特殊能力・ワザ

### 4.1 ［おみとおし］（オムナイト）

- 「オムナイトが場にいる限り、相手プレイヤーは自分の手札が全員に見えるようにしてプレイしなければならない。「ねむり・マヒ・こんらん」状態の時、この力は消える。」
  v0.46 の常にはたらく特殊能力（`ContinuousPower`）で、場（バトル場・ベンチ）のどこでもはたらき、ねむり・マヒ・こんらん・かがくへんかガスで消えます。
- ゲームの処理（ワザ・トレーナー・選び方）は変えません。プレイヤーに渡す観測（5.1 節）で、相手の手札を全員（両方のプレイヤーと観戦者）に見せるだけです。公開して
  いるかは問い合わせのたびに今の場から求めます（`effects.hand_revealed_by`。公開の問い合わせ）。手札が増えた・減った・入れかわったあとも、その時点の手札全体が見えます。
  はたらかなくなったら（進化・特殊状態・ガス・場をはなれる）、その時点からは見せません。前の観測で見えていた情報は、その観測の値として残ります（状態に「見た」記録を
  持たない）。1 枚を 1 度見る効果ではありません。

### 4.2 ［カブトアーマー］（カブト）と KA1

- 「このカードが受けるダメージは半分(切りすて)になる。(ダメージ以外の効果はそのまま)。「ねむり・マヒ・こんらん」状態の時、この力は使えない。」p.321 の 8 段階（ワザを
  受けるポケモンの持っている効果。GR-2000-P321-DAMAGE-ORDER）で、その段階のダメージを半分（切りすて。v0.46 のリフレクターと同じ `damage.HALVE_DOWN`。ダメージ
  カウンターの単位の丸め。30 → 10、50 → 20）にします。どのポケモンのワザのダメージでも（自分のワザ・控えへのダメージも）、ワザでない特殊能力のダメージ（はんげき・
  わるいねぞう・こっそりかみつく。v0.46 の `received_power_damage`）にも当てはめます。ダメージ以外の効果は受けます。同じ 8 段階にほかの効果（なぞのかべ・リフレクター
  など）があり、順番で結果が変われば v0.35 の決定で選ばせます。
- こんらんの 20（自分のワザがこんらんして受ける）: こんらん状態のカブトはこの力を使えないので、そのまま受けます（v0.46 の `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS` の
  問いは起こらない）。
- KA1（`UNRESOLVED_POISON_DAMAGE_RECEIVED_POWER`）: ポケモンチェックの「どく」のダメージは、ワザによるダメージではありません（p.321・p.322 の記録）。説明の「受ける
  ダメージ」が、「(ダメージ以外の効果はそのまま)」とともにワザのダメージを指すのか、どくのダメージも含むのかは決まりません。当てはめると量が変わる（どく 10 → 0、
  特殊などく 20 → 10）ので、ポケモンチェックのどくのダメージを与える前に対戦を止めます（`procedures.pokemon_check_poison`。`Phase.HALTED`）。v0.46 の［なぞのかべ］の
  しきい値（30）はどくの量より大きく結果が変わらないので止めません（`effects.poison_received_power_problem`）。［ふしぎなバリアー］は、どくがポケモンから受けるダメージ
  ではない（GR-2000-P319-HP-AND-DAMAGE）ので当てはめません（v0.46 と同じ）。
- 進化（カブトプス）すると、いちばん上のカードの定義になり、この力はなくなります（p.310）。

### 4.3 ［げんしのちから］（プテラ）

- 「プテラが場にいる限り、全てのポケモンは進化することができない。(すでに進化しているポケモンに影響はない)。「ねむり・マヒ・こんらん」状態の時、この力は消える。」
  お互いの場のすべてのポケモンの、どの方法の進化も止めます（`effects.evolution_preventers`。公開の問い合わせ）。進化の入口の共通の確かめ `evolution.evolution_block` の
  最初に聞く（`evolution.evolution_prevented`）ので、手札から重ねる通常の操作（`EvolvePokemon`。`EVOLUTION_PREVENTED`）・ワザで山札から重ねる（つきのちから・たきのぼり
  しんか。重ねられるカードがない）・特殊能力で山札から重ねる（［うか］）のどれも同じです。ポケモン育て屋さんは使う前に同じ問い合わせで止めます（`EVOLUTION_PREVENTED`）。進化カードを手札に加える
  効果（しんかのひかり）は進化ではないので止めません。
- すでに進化しているポケモンはそのまま（重なりを変えない）。場にプテラがいると、別のなにかの化石にプテラを重ねることもできません。ねむり・マヒ・こんらん・かがくへんか
  ガスで消え、消えたらその時点から進化できます（今の場から求める）。

### 4.4 ［スパイ］（マンキー）

- 「どちらかの山札の1番上、またはどちらかのサイドカード1枚、または相手の手札1枚を、自分の番に1回だけ見ることができる。見たカードは元の場所に戻す。…」宣言して使い、
  自分の番に 1 回（v0.42 の `once_per_turn`。宣言のときに `power_uses_this_turn` に記録。2 匹いればそれぞれ 1 回）。ねむり・マヒ・こんらんのこのカードは使えません。
- 宣言のあと決定 `peek_card`（使ったプレイヤー。選べるものは `effects.peek_targets` の位置の番号。`context` の `"targets"`）で、見るカードを位置で選びます: 自分の山札の
  一番上 → 相手の山札の一番上 → 自分のサイド（位置の順）→ 相手のサイド → 相手の手札（位置の順）。サイド・相手の手札・山札は裏向き・見えないカードなので、位置で選び、
  選ぶ前に内容を見せません。相手の手札の 1 枚は使ったプレイヤーが位置で選びます（日本語の文面は無作為に選ぶとは書かない。英語版の「random」は持ち込まない）。
- 見る（`zones.look_at_card`。ログ `look_at_card` の `card` は見たプレイヤーにだけ見える）だけで、カードは動かしません（並びは変わらない）。相手には見せません（「見る」で
  「見せる」ではない）。見られるカードがない（両方の山札・サイド・相手の手札が 0 枚）ときは、v0.43 の PW3（`UNRESOLVED_POWER_ZERO_CARDS`）と同じ問いで宣言の前に止めます。

### 4.5 ［わるふざけ］（コラッタ）

- 「自分の番ごとに1回使える。自分のサイドカードから1枚を選び、自分の山札の一番上のカードと入れ替える。…」宣言して使い、自分の番ごとに 1 回。ねむり・マヒ・こんらんの
  このカードは使えません。
- 決定 `select_prize_card`（使ったプレイヤー。選べるものは自分のサイドの位置）で選び、`zones.swap_prize_with_deck_top` で入れかえます。どちらのカードも見ない・見せません
  （説明に「見る」がない。ログ `swap_prize_with_deck_top` は位置だけで、カードを書かない）。サイドの枚数・位置、山札の枚数・ほかのカードの並びは変わらず、山札は切りません。
  サイドか山札が 0 枚なら PW3 で宣言の前に止めます。

### 4.6 みらいよち（スリーパー）

- 「自分または相手の山札の上から3枚まで見て、好きな順番に入れ替えて、もとの山札の上にもどす。」選ぶのはワザを使ったプレイヤーです: 見る山札の持ち主（決定
  `select_deck_owner`）→ 見る枚数（決定 `select_look_count`。0〜min(3, その山札の枚数)）→ 見る（ログ `look_at_deck_top`。`cards` は見たプレイヤーにだけ見える）→ 2 枚
  以上なら新しい並び（決定 `arrange_deck_top`。見たカードを上から順に並べた答え）→ もどす（ログ `arrange_deck_top`）。1 枚なら並べかえる決定はありません。見た部分より
  下の並びは変えず、山札は切りません。相手の山札を見ても、相手には見せません。
- 選んだ山札が 0 枚なら見るカードがありません（p.309。ログ `look_at_deck_top_none`）。山札があるときに 0 枚を選べるか（「3枚まで」が 0 を含むか）は決まらないので、v0.39 の
  GS1（`UNRESOLVED_BENCH_TARGETS_ZERO_CHOICE`。ワザの説明の「最大N」が 0 を含むか）と同じ問いで、答えのときに止めます（決定は待ったまま。先読みは 0 を試さない）。

### 4.7 おどろかす（マチスのイーブイ）

- 「相手の手札から、おもてを見ないで1枚選び、そのカードを見る。その後、そのカードを相手の山札にもどさせ、その山札をよく切る。」選ぶのはワザを使ったプレイヤー（決定
  `select_hand_card`。選べるものは相手の手札の位置。カードの内容は渡さない）→ 見る（ログ `look_at_card`。見たプレイヤーと持ち主にだけ見える）→ 相手がそのカードを山札に
  もどす（`zones.return_hand_cards_to_deck`。ログ `hand_to_deck`）→ その山札を切る（1 回）。この順番を変えません。日本語の文面は無作為に選ぶとは書かない（英語版の
  「random」は持ち込まない）。
- 相手の対戦ポケモンではなく相手の手札・山札への効果なので、「ワザをうけない」状態・「とうめい」は評価しません。相手の手札が 0 枚なら、v0.44 の FC1
  （`UNRESOLVED_STATED_CARDS_SHORT`。説明が決まった枚数のカードを選ばせるとき、選べるカードが足りない）と同じ問いで、宣言の前に止めます（先読みが見つける）。

### 4.8 そのほかのワザ

- こうしゅうは・ずつうは 5.2 節。いかりのサンダー: ダメージの目安 + 自分にのっているダメージカウンターの数 × 10（p.321 の 1 段階。ダメージを計算する時の数）→
  その後コインの「うら」で自分にも 30（v0.46 の「いかり」と v0.2f の「でんげき」の要素の組み合わせ）。

## 5. 情報の公開（観測）と、期限のあるトレーナーの使用の禁止・書き出しの形式 12

### 5.1 プレイヤーに渡す観測（`kyuura_engine/observation.py`）

ゲームの状態（`GameState`）とログは、引いたカード・山札とサイドの中身・相手の手札などの見えない情報を含む、内部の完全な記録です（エンジンの処理と監査に使う。
v0.2b からの約束）。新しい部品 `observation` は、それをプレイヤー（または観戦者）に渡すときに、その人が見てよい情報だけを取り出します。画面・通信は作らず、データの形と
約束（だれに何が見えるか）だけを決めます。状態を変えず、乱数を使いません。公開の API に `observe`・`visible_log` を加えました。

- `observe(state, viewer)`（`viewer` は 0・1 のプレイヤー、`None` は観戦者）: その時点の盤面。
  - 手札: 持ち主にだけカードが見えます（ほかの人は枚数だけ）。相手の［おみとおし］がはたらいているあいだは全員に見えます（`revealed_by` に発生源）。
  - 山札・サイド: だれにも中身は見えません（枚数だけ。カードの uid も渡さない。uid の付け方はデッキリストの順で決まるので、uid から中身がわかる）。
  - トラッシュ・場のポケモン（重なったカード・ついているカード・ダメージ・特殊状態・持続する効果・場での役割と HP）・使用中のトレーナー・期限のあるトレーナーの使用の
    禁止: 全員に見えます。対戦準備で出したポケモンは、表にする（ログ `reveal_pokemon`）までは持ち主にだけ見えます（`face_down`）。
  - 保留中の決定: 種類・決めるプレイヤー・選ぶ数は全員に見えます。選べるものは決めるプレイヤーにだけ渡します。選べるものがカードなら、決めるプレイヤーに見えるカード
    （公開のゾーン・自分の手札（［おみとおし］で見える相手の手札も）・山札をさがす効果のその山札・見たカード（`DECK_REVEALING_KINDS`））にだけカードの id を添えます。
    位置で選ぶ決定（サイド・相手の手札・［スパイ］の見る場所）は位置だけを渡します（選ぶ前に内容を漏らさない）。選べるものの意味は決定の種類ごとに `OPTION_MEANINGS` に
    書き、ない種類は `ValueError`（新しい決定の種類を加えたら、意味を決めて表に加える）。
- `visible_log(state, viewer)`: ログを、その人が見てよい項目だけにした写し。見えない項目は除き、`"hidden"` に項目の名前と（並びなら）枚数を書きます。イベントの種類ごとの
  見える範囲は `PRIVATE_FIELDS`（見えない項目と、見える人を決める関数）と `PUBLIC_EVENTS` に書き、どちらにもない種類は `ValueError` です（新しいイベントを加えたら、
  見える範囲を決めて表に加える。黙って全部を見せない。テストが今のすべての種類を確かめる）。例: `draw`・`search_deck`・`hand_to_deck`・`look_at_deck_top`・
  `arrange_deck_top` のカードは本人だけ、`look_at_card` は見たプレイヤーと（手札なら）持ち主、`game_created` の seed はだれにも見えない（seed から山札の並び・コインが
  わかる）、`place_starting_pokemon` は表にするまで本人だけ。ログは起こったことの記録なので、［おみとおし］で手札が見えているあいだに引いたカードも、ログの `draw` では
  本人だけです（今の手札は `observe` で見える）。
- 内部の完全な記録（`GameState`・`GameState.log`・`state_to_dict`）を、観測のかわりにプレイヤーに渡さないでください。

### 5.2 期限のあるトレーナーの使用の禁止（ずつう・こうしゅうは）

- ずつう「次の相手の番の終わりまで、相手プレイヤーはトレーナーカードを使うことができない。」・こうしゅうは「コインを投げて「おもて」なら、次の相手の番が終わるまで、
  相手プレイヤーは「トレーナーカード」を使うことができない。」は、場のポケモンではなく相手プレイヤーに与える効果です。状態 `GameState.trainer_locks`（`state.TrainerUseLock`
  の並び。使えなくなるプレイヤー・与えたプレイヤー・ワザを使ったポケモンのいちばん上のカード・ワザ・与えた番・消える番）に持ちます。ワザによる持続する効果
  （`PokemonInPlay.persistent_effects`。場のポケモンが受け、ベンチにもどる・進化・きぜつで消える）とは別に持ち、対戦ポケモンの入れ替え・効果を与えたポケモンが場を
  はなれることでは消えません。
- 消える番は与えた番 + 1（「次の相手の番」。番は交互に進む。v0.2e と同じ前提）で、その番の終わりに消します（`procedures.remove_expired_trainer_locks`。ログ
  `trainer_lock_removed` の `reason` は `expired`）。与えたらログ `trainer_lock_added`。
- 確かめるのは `effects.trainer_use_blockers(state, player)`（公開の問い合わせ）だけです。v0.46 の［アレルギーかふん］（常にはたらく特殊能力。場から問い合わせる）と
  このプレイヤーへの禁止を、別の記録として、それぞれの期間で判定します（重なっても、片方が消えればもう片方で判定する）。`engine._play_trainer` が、カードを手札から
  出す前に `TRAINER_PREVENTED`（`IllegalActionError`。理由の文に、はたらいている特殊能力・禁止を与えたワザと消える番）で拒否します（状態・乱数・ログは変わらない）。
  なにかの化石・ピッピ人形を場に出すのもトレーナーカードを使うことなので止めます。すでについているトレーナー・使っている最中のトレーナー・場からすてる操作は止めません。
- 要素 `programs.LockOpponentTrainers`（`local_coin`）: こうしゅうはのコインはダメージのあと（説明の順）です。禁止は相手プレイヤーへの効果なので、相手の対戦ポケモンの
  「ダメージを受けない」「ワザをうけない」状態・「とうめい」を評価せず、コインを投げ、「おもて」なら与えます（v0.34 の `void_coin_question` に当たらない）。相手の対戦
  ポケモンがこのダメージできぜつしても与えます。相手のワザとして使った（ゆびをふる・ちょうのうりょく）ずつうは、まねたポケモンが与えます。同じプレイヤー・同じ消える番の
  禁止が 2 つになることはありません（1 番に使えるワザは 1 つ。起これば RuntimeError）。
- 不変条件（`engine._trainer_lock_problems`）: 型・使えなくなるプレイヤーが与えたプレイヤーの相手・消える番は与えた番 + 1・今の番が与えた番〜消える番・与えた番が与えた
  プレイヤーの番・与えたワザの登録が禁止を与える実装（`lock_terms()`）・重なり・ログとの対応（与えてまだ消していない禁止と状態が同じ）。エンジンは禁止をログから決めません。

### 5.3 書き出しの形式 12

- 形式 12 = 形式 11 + 最上位の `trainer_locks`（`{"player", "source_player", "source_card", "source_card_id", "effect", "created_turn", "expires_turn"}` の並び。与えた順。
  なければ `[]`）。形式 1〜11 は、禁止があると `ValueError`（なければ v0.46 と同じ書き出し）。禁止は場のポケモンの項目ではなくプレイヤーの記録なので、最上位の項目に
  しました。書き出しの監査（tests/log_audit.py）の `LATEST_FORMAT` は 12、`TOP_FIELDS_SINCE` に `trainer_locks` を加えました。次の新しい形式は 13 です。
- なにかの化石・ピッピ人形は、場にいるあいだも書き出しの形を変えません（場のポケモンの `card`・`card_id` はそのカード。ポケモンとしてあつかうことは状態の定義
  （`GameState.card_def`）が決める）。

## 6. 停止コード・既存の問い・拒否のコード

新しい停止コードは 3 章の PF1・PF2・PF3 と 4.2 節の KA1 の 4 つです。どれも未解決の裁定のままです（根拠が見つかるまで決めない）。kyuura の未解決の一覧にないので、研究の
対応表の `kyuura_disposition` は `not_in_kyuura`（kyuura への報告事項）。隣の止まらない場合: PF1 は手札にたねポケモンがあるとき（対戦準備は続く）、PF2 はベンチのなにかの
化石とバトル場のふつうのポケモンの「にげる」・ポケモンいれかえ、PF3 は場のたねポケモンの組（ほかの組は選べる）、KA1 は［なぞのかべ］・どくでないダメージ（`PlayAsPokemonTest`・
`KabutoArmorTest`）。

再利用した既存の問い・コード（新しいコードにしていない）:

- 見られる・入れかえるカードがない［スパイ］・［わるふざけ］: v0.43 の PW3（`UNRESOLVED_POWER_ZERO_CARDS`）。
- みらいよちで山札があるときの 0 枚: v0.39 の GS1（`UNRESOLVED_BENCH_TARGETS_ZERO_CHOICE`）。
- おどろかすで相手の手札が 0 枚: v0.44 の FC1（`UNRESOLVED_STATED_CARDS_SHORT`）。
- オムスターのみずでっぽうで、無色のぶんの払い方で多い「水」の数が変わる: v0.31 の HC4（`UNRESOLVED_EXTRA_ENERGY_COLORLESS`）。

新しい拒否のコード（`IllegalActionError`。どれも状態を変える前）: `EVOLUTION_PREVENTED`（［げんしのちから］）・`NOT_DISCARDABLE`（場からすてられないポケモン）。
`TRAINER_PREVENTED`（v0.46）は期限のある禁止にも使います。エンジンの未対応で止める場面はありません。
