## 3. 特殊能力の共通の処理

### 3.1 宣言と回数（engine.py の `_use_pokemon_power`）

- 宣言の前の確認（使うポケモン・特殊能力の有無・登録・宣言するか（`POWER_NOT_DECLARABLE`）・かがくへんかガス（`POWER_SUPPRESSED`）・実装の `check_usable`）は
  v0.5〜v0.31 と同じ順番です。実装の `check_usable` は、使うポケモンの特殊状態（説明に「ねむり・マヒ・こんらん」状態の時、この力は使えないとあるものだけ。
  どくは制限しない）→ 選ばせるもの → 回数（`effects.require_power_not_used`。`POWER_ALREADY_USED`）→ パワーごとの確認 → 原典で決められない場合（`UNRESOLVED_…`）。
- 宣言（ログ `pokemon_power`）のあと、「自分の番ごとに1回」の特殊能力（`PowerEffect.once_per_turn`）は、その時点で使ったことを状態に記録します
  （`GameState.power_uses_this_turn`。v0.31 の形式 10 の項目。ログから数えない）。コインの「うら」・決定の途中でも使ったことになります。v0.31 のしぜんになおるは
  処理の中で記録していました。記録する時点を宣言のときに移しただけで、状態の結果は同じです（固定した v0.41 との比較で確かめた。10 章）。
- 特殊能力はワザではありません。使っても番は終わらず（段階 MAIN・番の番号・番のプレイヤーは同じ）、こんらんのコインを投げず、ワザのログはありません（p.311・
  p.323。v0.5 の記録）。使ったあとにワザを使えます。

### 3.2 処理の途中の決定と再開

- 決定を出す特殊能力（ヒーリング・かおりのわな・ぶっしつこうかん）は、実装の `resolve` が `decisions.push_power_decision`（再開先 `"power"`。`context` の `"use"` は
  (プレイヤー, 場のポケモンの番号, カード id, 特殊能力の位置)）で決定を出して止まります。決定するのは使ったプレイヤーで、段階は既存の `Phase.DECISION`。新しい段階・
  コマンドは加えていません（v0.4e のトレーナーの決定と同じ形）。決定を待つ間はほかのコマンドを受け付けません（`WRONG_PHASE`）。
- 答え（`ResolveDecision`）は `engine._resume_power` が受け、続きの情報から実装を引いて `PowerEffect.resume` を呼びます。宣言・回数の記録・コインは繰り返しません。
  不正な答え（相手のプレイヤー・選べないもの・数・古い決定・原典で決められない選択）は、状態を変えずに拒否します。
- 不変条件 `engine._power_decision_problems` が、続きの情報（番のプレイヤー・場のポケモン・いちばん上のカード・登録された宣言する特殊能力）・今の番の最後の宣言が
  この特殊能力の宣言であること・回数の記録・実装の `PowerEffect.decision_problems`（決定するプレイヤー・種類・選ぶ数・選べるもの・選ぶと止める選択）を確かめます。
- 書き出し: 決定は既存の `decision` の項目で表します（形式 2 以上。決定を出す特殊能力はどれも回数の記録があるので、実際には形式 10）。形式 1 は再開先 `"power"` の
  決定を `ValueError` にします（黙って落とさない）。

### 3.3 使用後の処理（`resolution.after_power`）

処理（宣言・決定への答え）が終わり、決定がなくなったら、`engine._after_power_step` が解決の基盤の `after_power` を呼びます。

- HP 以上のダメージのポケモンがいれば（ゲンガーの［のろい］でダメージカウンターをのせた）、ワザのあとと同じきぜつの処理（`procedures.knock_out`。ログ `knock_out` の
  `timing` は `"power"`）→ サイド → 勝ち負けの判定（p.311）→ ふしちょう（v0.12）→ バトル場に出す（`_after_knockouts`）。続きは新しい値 `continue_turn`
  （`procedures.CONTINUE_TURN`）で、終わったら番のプレイヤーの `Phase.MAIN` にもどります（ワザのあとの続き・ポケモンチェックの `next_turn` と違い、番を終えない）。
  こんじょう（相手のワザのダメージで「きぜつ」するとき。v0.11 の G3〜G7）・みちづれ（ワザのあと）は候補にしません。1 回の使用できぜつするのは 1 匹です
  （2 匹以上は `RuntimeError`）。
- きぜつがなく、バトル場が空いたプレイヤーがいれば（メノクラゲの［おくびょう］で自分を手札にもどした。きぜつではないのでサイドはない）、勝ち負けの判定（場に
  ポケモンがいない）→ バトル場に出す（v0.36 の RD の場をはなれたあとと同じ）。続きは `continue_turn`。
- どちらもなければ何もしません（番のプレイヤーの MAIN のまま）。
- 特殊能力の処理で「きぜつ」させうるかは実装が宣言します（`PowerEffect.may_knock_out`。今はのろいだけ。説明に「きぜつ」しない範囲の条件がない）。偽の特殊能力
  （ダメージスワップ・へんなこうどうなど）の処理のあとに HP 以上のポケモンがいれば、きぜつの処理をせず、不変条件（場のポケモンのダメージは HP 未満）で
  `StateIntegrityError` にします（確認の漏れを黙ってきぜつにしない。v0.7 の二重の確かめ。tests/test_damage_swap_v0_7.py の
  `test_invariants_catch_a_broken_check` はそのまま通る）。
- 不変条件: 続き `continue_turn` の決定（サイド・ふしちょう・バトル場に出す）の前の、今の番の最後の宣言が特殊能力の宣言であること
  （`engine._power_aftermath_problems`）。バトル場に出すプレイヤーは 1 人だけ。

### 3.4 自動的にはたらく反応（エリカのラフレシアの［ぼうぎょかふん］）

- 宣言しない（`declared = False`。`UsePokemonPower` は `POWER_NOT_DECLARABLE`）。効果の定義 `catalog.DEFENSIVE_POLLEN` は、v0.10 のはんげき・v0.17b のわるいねぞうと
  同じ窓（DEFER。相手のワザのダメージの要素の処理がすべて終わったあと・ダメージ以外の効果（それを決めるコインを含む）の前。CR-COUNTERATTACK-TIMING）で処理します
  （処理 `kernel.power_confusion_to_damage_source`。決定を出さない。v0.18d の「窓の途中の決定はない」という前提は変わらない）。
- はたらくのは、このカードがバトル場でワザのダメージ（0 より大きい）を受けたときだけです（効果の定義の新しい項目 `active_only`。控えで受けたダメージ・
  どく・ダメージカウンターをのせる効果（ライフダウン）・カウンターの移動では、はたらかない）。説明は「ワザによるダメージ」で「相手の」と書かないので、
  効果の定義の `by_opponent` は偽です（今の対応カードでは、エリカのラフレシアがバトル場で自分のワザのダメージを受けることはない）。説明のとおり、このカードが「ねむり・マヒ・こんらん」状態でも、
  このカードが「きぜつ」してもはたらきます（`disabled_by` は空）。かがくへんかガスは止めます（v0.8 の G7）。
- 持ち主がコインを投げ（`flip_coins` の `source="power"`）、「おもて」ならダメージを与えたポケモン（ワザを使ったポケモン）をこんらんにします（ログ
  `power_confusion`・`special_condition`）。ダメージを与えたポケモンがすでに HP 以上（相手の「はんげき」など）なら、コインを投げません（`power_confusion_skipped`）。

### 3.5 区別

| 区別 | 内容 |
|---|---|
| 宣言する／自動的にはたらく | 宣言する 7 つ（ヒーリング・へんなこうどう・のろい・かけつける・かおりのわな・ぶっしつこうかん・おくびょう）は `UsePokemonPower` で使う。ぼうぎょかふんは宣言しない（ダメージの窓で自動的にはたらく） |
| 自分の番ごとに 1 回／何度でも | 1 回: ヒーリング・のろい・かけつける・かおりのわな・ぶっしつこうかん（`once_per_turn`。宣言のときに記録）。何度でも: へんなこうどう（1 回の使用で 1 個。ダメージスワップと同じ実装上の仮定）・おくびょう（使えば場をはなれる） |
| バトル場／ベンチ | かけつけるはベンチにいるときだけ（`POKEMON_NOT_ON_BENCH`）。ぼうぎょかふんはバトル場で受けたダメージだけ（`active_only`）。ほかはどちらでも使える（p.311） |
| 特殊状態の制限 | 説明に書いてあるものだけ（ヒーリング・へんなこうどう・のろい・かおりのわな・ぶっしつこうかん・おくびょう）。どくは制限しない。かけつけるは処理に使う最新の説明に制限がない（ベンチのポケモンは特殊状態にならないので結果は同じ）。ぼうぎょかふんは特殊状態でもはたらく |
| かがくへんかガス | 宣言する特殊能力は `POWER_SUPPRESSED`（コイン・決定の前）。ぼうぎょかふんははたらかない（コインもない） |
| ワザを防ぐ効果と特殊能力の効果 | 「ワザをうけない」状態・「とうめい」・「ダメージを受けない」状態は、ワザによるダメージ・効果を防ぐもので、特殊能力の効果（のろいでのせるカウンター・かおりのわなの入れ替え）には当てはめない（判定のコインもない）。ワザの効果（よいおこない・ライフダウン・つきのちから・ようせいのきせき）は、相手・自分のポケモンへの効果ごとに既存の `reaches` で評価する |
| 使用後の処理 | のろいのきぜつ・おくびょうで空いたバトル場は、3.3 節の `after_power`。ほかの特殊能力は処理だけで番のプレイヤーの MAIN にもどる |

## 4. 特殊能力ごとの規定と根拠

- ［ヒーリング］（ラフレシア。`HealOwnPokemonOnHeads(1)`）: 宣言 → 持ち主のコイン（文面の順番どおり、コインを投げてから選ぶ）→「おもて」なら決定 `SELECT_POKEMON`
  （選べるものは自分の場の、ダメージカウンターがのったポケモン。バトル場 → ベンチ。このカードを含む。1 匹でも決定を出す）→ 1 つとりのぞく（ログ `power_heal`。
  `user_pokemon_id` は使ったポケモン）。「うら」は何もしない。自分の場のどのポケモンにもダメージカウンターがなければ、v0.31 のしぜんになおると同じ問い
  （HC8。`UNRESOLVED_POWER_HEAL_WITHOUT_DAMAGE`。コインの前に止める）。回復は、のっている数まで（GR-2000-P320-RECOVERY）。
- ［へんなこうどう］（ヤドラン。`MoveDamageCounterToSelf`）: 選ぶのは移動元（`source`。自分の場のこのカード以外のポケモン）だけで、移動先はこのカード
  （`target` を指定したら `POWER_CHOICE_NOT_USED`）。1 回の使用で 1 個（v0.7 のダメージスワップの S3 と同じ実装上の仮定。何度でも使えるので、どの取り方も
  1 個ずつの移動に分けられる）。「このカードが「きぜつ」しない範囲なら」は、状態を変える前に `WOULD_KNOCK_OUT` で拒否します。ダメージカウンターの移動は
  ダメージではない（GR-2000-P320-COUNTER-MOVE。v0.7 の S19）ので、ダメージの計算・「ダメージを受けたとき」の効果はありません（ログ `move_damage_counter`）。
- ［のろい］（ゲンガー。`MoveOpponentDamageCounter`。自分の番ごとに 1 回）: 移動元・移動先はどちらも相手の場の別のポケモン（`SOURCE_NOT_OPPONENTS`・
  `TARGET_NOT_OPPONENTS`・`SAME_POKEMON`・`NO_DAMAGE_COUNTERS`）。説明に「きぜつ」しない範囲の条件はないので、移動先が HP 以上になってもよく、使用後の処理で
  きぜつします（3.3 節。サイドは使ったプレイヤーが取る）。文面にない「きぜつさせてはいけない」という条件は付けていません。カウンターをのせることをワザによる
  ダメージに置きかえていません（弱点・抵抗力・ディフェンダー・「とうめい」・はんげきは関係しない）。ログ `move_damage_counter` に `owner`（カウンターの持ち主＝
  相手）。
- ［かけつける］（カイリュー。`SwitchSelfFromBench`。自分の番ごとに 1 回）: ベンチにいるとき、バトル場の自分のポケモンと入れ替えます。入れ替えはポケモンいれかえと
  同じ処理（`effects._switch_active_with_bench`。にげるではないので、にげるエネルギー・こんらんのコインはなく、ベンチにもどったポケモンの特殊状態・持続する効果は
  消える。ログ `switch` の `effect` は特殊能力）。処理に使う文面は card_differences の最新の説明（8 章）。
- ［かおりのわな］（エリカのウツボット。`SwitchOpponentOnHeads`。自分の番ごとに 1 回）: 宣言 → コイン →「おもて」なら使ったプレイヤーが相手の控えを選ぶ（決定
  `SELECT_POKEMON`）→ 相手の対戦ポケモンと入れ替える（突風と同じ処理。v0.21）。「うら」は何もしない。相手に控えがいないときは PW1（6 章）。v0.40 のすごむの効果を
  与えた相手のポケモンを選ぶ答えは SG1（選べるが選ぶと止める。それしか選べなければコインの前に止める）。
- ［ぶっしつこうかん］（わるいユンゲラー。`DiscardThenDraw`。自分の番ごとに 1 回）: 宣言 → 決定 `DISCARD_FROM_HAND`（手札から 1 枚。v0.22 のパソコン通信と同じ種類）
  → `zones.discard_from_hand`（ログ `discard_from_hand` に `power`。トレーナーを使うためのトラッシュのログは v0.41 と同じ形）→ 山札から 1 枚引く（山札が 0 枚なら
  引けない。負けではない。p.312）。手札がないときは PW2（6 章）。
- ［おくびょう］（メノクラゲ。`ReturnSelfToHand`）: 場に出した番は使えない（`PLAYED_THIS_TURN`）。ダメージカウンターをすべてとりのぞき（ログ
  `remove_all_damage_counters` に `power`）→ ついているカード（エネルギー・トレーナー）をトラッシュ（`zones.discard_attached_cards`）→ このカードを手札にもどす
  （新しい `zones.return_in_play_to_hand`。ログ `return_in_play_to_hand`）→ 持続する効果を消す（理由 `return_in_play_to_hand`）。きぜつではありません（サイド・
  ログ `knock_out`・きぜつしたときの特殊能力はない）。行き先は手札で、山札を切りません（v0.36 の山札にもどす処理 `return_in_play_to_deck` とは行き先と
  シャッフルの有無が違う。同じ関数を流用していない）。バトル場からもどしたら使用後の処理でバトル場に出し、控えがいなければ負け（p.311）。
- ［ぼうぎょかふん］: 3.4 節。
