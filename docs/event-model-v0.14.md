# イベントモデル（v0.14 Phase C）

[event-architecture-options-v0.14.md](event-architecture-options-v0.14.md) で採用の候補にした「段階（窓）を明示したパイプライン（案C）＋型付きの内部のイベント（案B の一部）＋ワザの要素の宣言（案D の一部）」の、データの形と処理の流れです。実装は `experiments/event_kernel/`（プロトタイプ。本番の `kyuura_engine/` は変えない）です。

- 「規定」は原典で確かめた・既存の版で確かめた裁定、「正規化」はルールの裁定ではない実装の順番、「仮定」はプロトタイプの設計上の決めごとです。
- プロトタイプで確かめた結果は [event-prototype-verification-v0.14.md](event-prototype-verification-v0.14.md) に書きます。この文書は設計です。

## 0. 位置づけ

- 本番の CLAUDE.md は「汎用のイベントの仕組み（購読・発行）にしないでください」と繰り返し書いています（v0.9〜v0.12 の設計で不採用にした理由。順番を仕組みが決めてしまう）。v0.14 のプロトタイプはその本番の規則を変えず、本番の外（`experiments/`）で、**購読・発行の仕組みではなく**、窓と枠で順番を原典に合わせたまま共通化できるかを確かめます。
- プロトタイプは、v0.13 の状態の型（`GameState`）・書き出しの形式（9）・ログのイベントの形・決定の形をそのまま使います。ルールの意味を変えないことを、同じ入力で v0.13 と比べて確かめるためです。

## 1. イベント（C1）

6 つの概念を分けます。

| 概念 | 形 | 持つ場所 | 例 |
|---|---|---|---|
| これから起こる出来事（提案） | `DamageProposal`（frozen。枠・受けるポケモン・基本となるダメージ） | 解決の記録（`Trace`） | ワザのダメージの要素「相手のバトル場に 30」 |
| 起こった出来事（確定） | `DamageApplied`（枠・分類・前後のダメージ・相手のワザか）・`DamageVoided`・`DamageEvaded`・`KnockedOutRecorded`（HP 以上になった枠） | 同上 | 「ポケモン 5 が 30 を受け、40 になった（ワザの分類・相手のワザ）」 |
| 発動の候補 | `CandidateFound`（窓・効果の定義・ポケモン・枠）。そのときの状態の写しは、送る効果（`Deferred`。受けたダメージ）と `Resolution.ko_prevention_able`（こんじょう）・決定の `context`（ふしちょう） | 解決の中だけ | 「ポケモン 5 の［はんげき］が、受けたときにねむりでなかった」 |
| 実際に発動する効果 | `Activated`（窓・効果の定義・ポケモン・枠） | 解決の記録 | 「ダメージの要素のあとの窓で［はんげき］を与える」 |
| ゲームの状態の変更 | 既存の部品（`damage` の値・`conditions.poison`・`persistent.add_persistent_effect`・`_knock_out` など） | `GameState` | ダメージを足す・特殊状態を付ける |
| 外部向けのイベントログ | 既存の `GameState.log`（形は v0.13 のまま） | `GameState` | `damage`・`counterattack`・`knock_out` |

- 内部の出来事は公開のログではありません。解決の記録（`Trace`。上の出来事と、開いた窓 `WindowOpened`・開いた枠 `FrameOpened`・処理した要素 `ElementStarted`・当たった問い `QuestionHit`・出した決定 `Suspended`・v0.13 に渡したコマンド `Delegated`・先読みの結果 `PreflightResult` の並び）は、検証のための別の出力（`apply_command_traced`）で、状態に保存しません（書き出しの形式を変えない）。
- 公開のログは、既存の部品が状態を変えるときに残します（v0.13 と同じ場所・同じ形）。内部の出来事からログを作り直すことはしません（ログの順番が v0.13 と変わるのを避ける）。

## 2. 効果（C2）

効果の定義（`EffectDefinition`）は、必要な項目だけを持ちます。

| 項目 | 意味 | 持つ効果の例 |
|---|---|---|
| 名前 | 安定した識別子（`strikes_back` など） | すべて |
| 発生源（`origin`） | 印刷された特殊能力（いちばん上のカード。p.310）・持続する効果（`PokemonInPlay.persistent_effects`）・常にはたらく特殊能力 | すべて |
| 発動の契機（`windows`・`trigger_classes`・`by_opponent`） | どの窓の、どの出来事で候補になるか | ［はんげき］は「ダメージを受けたとき」の窓・相手のワザの分類のダメージ |
| 条件（`disabled_by`・`status_time`・`suppressible`） | 特殊状態（いつの時点の状態か）・かがくへんかガスで消えるか（印刷された特殊能力だけ）・はたらく番（持続する効果） | ［はんげき］・［こんじょう］は「ダメージを受けるとき、すでに」ねむり・マヒ・こんらんでない |
| 対象（`target`） | 「ダメージを与えたポケモン」「自分」「トラッシュのこのカード」 | ［はんげき］はダメージを与えたポケモン |
| 処理（`action`） | 効果の中身（既存の部品を呼ぶ Python の関数） | 特殊能力のダメージ 10 |
| 発動のタイミング（`timing`） | すぐ（窓の中）・あとの窓へ送る | ［はんげき］はダメージの要素のあとの窓へ送る |
| 有効期限（定義には持たない。持続する効果の値の `active_turn`） | 持続する効果のはたらく番（状態の `active_turn`） | 「ほのおのかべ」「こうらがえし」「かたまる」 |
| 無効化の条件（`suppressible`） | 印刷された特殊能力は、かがくへんかガス（今の状態から求める） | ［とうめい］［はんげき］［こんじょう］［ふしちょう］ |
| プレイヤーの選択（`mode`） | 自動（`AUTOMATIC`）・任意（`OPTIONAL`。決定で使うかを聞く） | ［こんじょう］［ふしちょう］は任意 |

効果の定義は、v0.13 の効果の登録表（`EffectRegistry`）の実装の型から、対応表（`experiments/event_kernel/catalog.py`）で作ります。v0.13 で 5 か所に分かれていた「実装の型で探す」処理（[event-architecture-audit-v0.14.md](event-architecture-audit-v0.14.md) 4.1）を、この対応表の 1 か所にまとめます。効果の数値（10・残り HP 10 など）は v0.13 の実装の値を読みます。

| v0.13 の実装 | 効果の定義 | 窓 | 自動・任意 |
|---|---|---|---|
| `AttackImmunityOnHeads`（とうめい） | `transparency`（受ける前の置きかえ。コイン。1 つのワザで 1 匹 1 回） | ダメージの適用の前・効果の適用の前 | 自動 |
| `CounterattackDamage`（はんげき） | `strikes_back`（特殊能力のダメージを、ダメージを与えたポケモンに） | ダメージを受けたとき → ダメージの要素のあと | 自動 |
| `PreventKnockOutOnHeads`（こんじょう） | `guts`（受けたときの特殊状態の写し → きぜつの判定で決定） | ダメージを受けたとき → きぜつの判定 | 任意 |
| `ReturnToHandOnKnockOut`（ふしちょう） | `rebirth`（きぜつの処理の前の写し → 勝ち負けのあとで決定） | きぜつの処理 → 勝ち負けのあと | 任意 |
| `SuppressOtherPowers`（かがくへんかガス） | `chemical_gas`（候補を集めるたびに今の状態から求める） | （窓を持たない） | 常に |
| 持続する効果 `PreventDamage`（かたまる） | `harden`（ダメージの要素を無効にする置きかえ） | ダメージの適用の前 | 自動 |
| 持続する効果 `Retaliation`（ほのおのかべ・こうらがえし） | `retaliation`（ワザの分類のダメージを返す枠を起こす。量は `basis`） | ダメージを受けたとき → ダメージの要素のあと | 自動 |

ワザは「要素」の並び（`AttackProgram`）で書きます。要素は `phase`（ダメージ・効果・コイン）を持ち、コインはそれが決める要素に属します（でんげきのコインは自分へのダメージの要素、どくばりのコインはどくの要素、ねばりつくのコインはワザ全体の要素で、ダメージとマヒの両方を決める）。v0.13 の 24 種類のワザの実装を、要素の並びに置きかえます（`experiments/event_kernel/programs.py`）。効果の中身（量の求め方・特殊状態の付け方）は Python の関数で、DSL にはしません。

## 3. 処理の段階（窓。C3）

ワザのコマンド 1 回の窓の順番（[event-architecture-audit-v0.14.md](event-architecture-audit-v0.14.md) の v0.13 の順番と同じ）:

```
宣言の前（合法性・原典で決められない場合の先読み）
→ 宣言（ログ attack）→ こんらんのコイン
→ 要素を順に処理:
     ダメージの要素: [適用の前] 無効（かたまる）→ 計算（p.321）→ 置きかえ（とうめい。最終ダメージ > 0 のとき）
                    [受けるとき] 状態の写し（はんげき・こんじょう・返す効果の条件）→ 適用 → [受けたとき] 送る効果を枠の列に入れる
     効果の要素の前に、枠の列が空でなければ [ダメージの要素のあと] の窓を開く（p.89）
     効果の要素: 対象がきぜつしていれば飛ばす（p.309）→ [適用の前] 置きかえ（とうめい）→ 適用
     決定の要素: 決定を出して止まる（続きの情報を決定に書く）
→ 最後に [ダメージの要素のあと] の窓（枠の列が空でなければ）
→ [きぜつの判定] 任意の効果（こんじょう）の決定
→ [きぜつの処理] 写し（ふしちょうを使えるか）→ トラッシュ
→ サイド → 勝ち負けの判定 → [勝ち負けのあと] 任意の効果（ふしちょう）の決定 → バトル場に出す
→ [番の終わり] 期限（ついているトレーナー・持続する効果）→ ポケモンチェック（どく → きぜつ → … → ねむり・マヒ）→ 次の番
```

窓の中の順番の扱い:

| 窓 | 規則 | 分類 |
|---|---|---|
| ダメージの適用の前 | 無効（「ダメージを受けない」状態）を計算より先に見る（p.321）。置きかえ（とうめい）は最終ダメージ > 0 のときだけ（v0.9 の T21） | 規定 |
| ダメージの要素のあと | 候補が 1 つなら発動。2 つ以上なら、与える順番が原典で決まらない（C34・C35）。今の対応カードでは起こらないので、エンジンの不具合として止める | 規定（時点。p.89）・未解決（順番） |
| きぜつの判定 | 任意の効果の候補が 2 つ以上なら、宣言の順番が原典で決まらない（G40）。起こらないので止める | 未解決 |
| きぜつの判定（同時のきぜつ） | きぜつするポケモンの「HP 以上になった枠」が、ワザの枠と、そのワザが起こした別の枠（はんげき・返す効果）に分かれるなら、同時のきぜつか（p.324）が決まらない（C18・W24・S37）。先読みで、宣言の前に止める | 未解決 |
| 勝ち負けのあと | 「ふしちょう」とサイド・勝ち負け・交代の順番は原典で決まらない（P27〜P30）が、どの順番でも結果が変わらないので、v0.12 と同じ順番に正規化。候補が 2 つ以上なら止める（P32） | 正規化・未解決 |
| サイドを取る順番 | 番のプレイヤーから（p.325 を v0.2f で正規化） | 正規化 |

窓が出来事の発行の順番で決まるのではなく、窓の順番そのものが原典の処理の順番です。内部の出来事は、窓の中で何が起こったかの記録で、次の処理を決める入口ではありません。

## 4. 連鎖と再入（C4）

- **処理の枠（`Frame`）**: ワザの枠（宣言したワザ）・返す効果の枠（前の番のワザの効果。与えるダメージはワザの分類）・特殊能力のダメージの枠（はんげき）・こんらんの枠。枠はダメージの分類（ワザ・特殊能力・こんらん）と、親の枠を持ちます。
- **送る効果の列**: 枠ごとに、ダメージを受けたときに候補になった効果を列に入れ、その枠の「ダメージの要素のあと」の窓で処理します。返す効果の枠は自分の列を持ち、自分の窓で処理してから親にもどります（明示した列。コールスタックの再帰の深さで止めない）。
- **どの枠がどの枠を起こせるか（表）**: ワザの分類のダメージ（ワザの枠・返す効果の枠）を相手が受けたときだけ、「ワザのダメージを受けたとき」の効果が候補になります。特殊能力のダメージの枠は、どの効果も候補にしません（v0.10 の C13・C14）。返す効果の枠のダメージを受けるのは番のプレイヤーのポケモンで、その返す効果は持ち主の相手の番だけにはたらく（v0.13 の S45）ので、返す効果の枠から返す効果の枠は起こりません。

  | 親の枠 → | 起こせる枠 |
  |---|---|
  | ワザ | 特殊能力のダメージ（はんげき）・返す効果 |
  | 返す効果 | 特殊能力のダメージ（はんげき） |
  | 特殊能力のダメージ | なし |
  | こんらん | なし |

  表にない枠を起こそうとしたら、規定から起こらないはずのことなので、エンジンの不具合として止めます（回数の上限ではない）。枠の深さは表から最大 3 で、循環しません。
- **きぜつの原因**: ポケモンのダメージが HP 以上になった枠を、解決の中で記録します（`Resolution.knocked_by`）。きぜつの判定の窓で、原因がワザの枠と別の枠に分かれていれば、同時のきぜつかが決まらない場合（C18・W24・S37）です。v0.13 では、この判定を効果の組み合わせごとの関数（`counterattack_double_knockout_problem`・`retaliation_double_knockout_problem`）で書いていました。

## 5. 中断・再開（C5）

続きの情報（`Continuation`）は frozen の値で、決定（`PendingDecision`）の `resume` と `context` に書きます（`experiments/event_kernel/codec.py`）。v0.13 の決定と同じ形にするので、書き出しの形式は 9 のままです（仮説 H3）。

| 続き | 決定（`resume`） | `context` | 再開の位置 |
|---|---|---|---|
| ワザの要素の途中 | `attack` | `use`（プレイヤー・ポケモンの番号・カード id・ワザの位置）＋要素ごとの値（ふきとばしの `target`。再開した要素は、決定の `context` を直接読まず、続きの情報 `AttackRun.carried` から読む） | 決定を出した要素の次（要素の並びの中で決定を出す要素は 1 つなので、決定の種類から位置が決まる） |
| きぜつの判定 | `knock_out` | `attack`・`power` | 任意の効果の処理 → きぜつの処理 |
| きぜつのあと | `take_prize`・`post_knockout`・`promote_active` | `remaining`・`then`・`post_knockout` | サイド → 勝ち負け → ふしちょう → 交代 → 番の終わり（またはポケモンチェックの続き） |

維持するもの:

| 項目 | 方法 |
|---|---|
| 実行の位置 | 続きの情報（上の表） |
| 保留中の処理 | 決定の `context`（`remaining`・`then`） |
| 発動済みの効果 | 状態と公開のログ（v0.13 と同じ。内部の記録は持たない） |
| 発動待ちの効果 | 決定を出す前に、送る効果の列を空にする（窓の位置が要素の分類で決まるので、構造的に空になる）。きぜつのあとの効果の写し（ふしちょう）は `context` の `post_knockout` |
| 選べる対象 | 決定の `options`（v0.13 と同じ） |
| 乱数の状態 | `GameState.rng`（決定を出すまでに使った分だけ進む。決定を出す時点ではコインを投げない） |
| 保存・復元のあとの再開 | 続きの情報は状態（形式 9）に入っているので、`pickle`・`deepcopy`・`clone`・v0.13 のエンジンのどれで保存・再開しても同じ |

ワザ 1 回の中の値（「とうめい」の結果・「こんじょう」の写し）は、v0.13 と同じく決定をまたぎません。決定をまたいでも要る値（HP 以上のポケモンの「こんじょう」の写し）が残るなら、続きの情報に書けないので、エンジンの不具合として止めます（v0.13 の engine.py:1045 と同じ扱い）。要らない値（HP 未満のポケモンの写し）は捨てます。これは v0.13 との互換のための制約で、将来の効果（だつりょくえき など）のために広げるなら `context` の項目を増やします（形式は 9 のまま表せるが、v0.13 の決定と形が変わる）。

## 6. 常にはたらく効果と持続する効果（C6）

| 種類 | 例 | 求め方 | 状態に持つか |
|---|---|---|---|
| 常にはたらく効果 | かがくへんかガス | 候補を集めるたびに、今の状態（場のポケモン・いちばん上のカード・特殊状態）から `continuous.suppressors_of` で求める | 持たない（過去のイベントの記録で決めない） |
| 番をまたぐ持続する効果 | かたまる・ほのおのかべ・こうらがえし | `PokemonInPlay.persistent_effects`（はたらく番 `active_turn`） | 持つ（v0.4b〜v0.13 と同じ） |
| ある時点の状態の写し | 「ダメージを受けるとき、すでに」（はんげき・こんじょう）、「きぜつするとき」（ふしちょう） | その時点の窓で写す | 解決の中だけ（ふしちょうは決定の `context` で運ぶ） |
| 期限の失効 | 持続する効果・ついているトレーナー | 番の終わりの窓（v0.13 の部品） | 状態から消す |

## 7. 原典で決められない場合の扱い

- プロトタイプは、原典で決められない場合を推測で解決しません。v0.13 の 17 のコード・22 の未解決の裁定のどれも変えません。
- **既知の問いの表**（`experiments/event_kernel/questions.py`）: 検出の種類（同時のきぜつの原因の分かれ方・ダメージを受けない相手へのコイン・受けないと決まったポケモンへのコイン・こんじょうと効果・こんらんのダメージの変更効果・マヒの再付与）→ v0.13 の `UNRESOLVED_…` のコードと裁定の番号。表にない検出は、エンジンの不具合として止めます。
- **先読み（仮説 H2）**: ワザの宣言の前に、状態の複製の上で、コインのすべての結果（こんらんのコイン・ワザのコイン・「とうめい」のコイン）を順に試し、どれかの結果で既知の問いに当たれば、宣言の前に `UnsupportedError` で止めます（受け付けるかがコインの結果で変わらない）。v0.13 の止める関数（5 つ）と補助の情報（`damage_profile`・`opponent_effect_elements`）を使わずに、同じ答えになるかを確かめます。比べるために、v0.13 の止める関数をそのまま呼ぶ形（`preflight="legacy"`）も残します。
- 2 つ以上の問いに当たる場合は、v0.13 の確認の順番（ワザの実装の `problem` → こんらんのダメージの変更効果 → C18 → G37 → W24 → ワザの途中の確認）と同じ優先度で 1 つを選びます。
