増やすことで、カードの強さ・勝率・デッキの釣り合いは評価していません。

- ルールの基準（2000.02.14 版）・公開の固定のデッキ・固定の参照データ・書き出しの形式（22）・公開の API の呼び方は変えていません。既存の `UNRESOLVED_…` の分類は変えていません。

### 3.2 新しい小さな型（8 つ）

どれも解決の基盤の要素の並び（`programs.BUILDERS`）で、v0.13 の約束（`resolve`・`resume`）を持たず、`v013_checks.VERIFIED` に入れていません（tests/helpers.py の
`ATTACK_TYPES_SINCE_V0_17` に加えた）。`engine.py`・`resolution/` にカード id の分岐はありません。

- `CoinsHeadsTimesBonusDamage(2, 20)`（ルギアの「エアロブラスト」。目安 20+）: 値 `PrintedPlusHeadsTimes`。基本となるダメージ（p.321 の 1 段階）は 20・40・60。「おもて」が 0 でも 20
  （ワザの失敗ではない）。コインはダメージの量だけを決めるので、「ダメージを受けない」「ワザをうけない」相手には投げる前に v0.4b の `UNRESOLVED_PREVENTED_COIN_DAMAGE`。結果は
  「おもて」の数だけを使う（`by_heads`）。`damage_profile` は (20, 40, 60)。v0.13 の `CoinFlipDamage`・v0.40 の `CoinsAllHeadsBonusDamage` とは別の型。
- `DamageThenStatusSelfAndOpponent(ねむり / こんらん)`（エリカのクサイハナの「ゆめみのまい」・「くさいにおい」）: `Damage(OPP)` → `Status(target=SELF, after_damage)` →
  `Status(after_damage)`（説明の「自分と相手」の順。受けるポケモンが違うので順番で結果は変わらない）。「ダメージを与えた後、…」なので、ダメージを与えなかったときは自分にも相手にも
  v0.17b の Z23（`UNRESOLVED_EFFECT_AFTER_NO_DAMAGE`）。第2弾のクサイハナの「くさいにおい」（v0.41 の `DamageThenConfuseBoth`。「相手を…。その後、自分も…」で条件にしない）とは
  書き方が違うので型を分けた。
  - **ゆめみのまいで両方の対戦ポケモンがねむりになると、そのあとのポケモンチェックのねむりのコインの順番が決まらない**（v0.3b の既存の未解決
    `UNRESOLVED_POKEMON_CHECK_SLEEP_COIN_ORDER`）ので、コインの前に対戦が止まります（`Phase.HALTED`。v0.72 で新しく決めたことではない。
    `SelfAndOpponentStatusTest.test_dream_dance_makes_both_actives_asleep_and_the_pokemon_check_halts`）。相手がこのワザで HP 以上になる・ねむりを受けない（「ワザをうけない」・
    「とうめい」）・ワザを使ったポケモンが受けないときは止まりません。正式な対戦でも 16 局のうち 3 局がこれで止まりました（8 章）。
- `PoisonAndSleepWithoutDamage`（エリカのウツドンの「ねむけどく」）: `Status(どく)` → `Status(ねむり)`。ダメージの要素はない（ログ `damage` もない）。どくはねむりと重複する（p.322）。
- `DamageThenWakeOpponent`（ナツメのルージュラの「めざめのキッス」）: 要素 `WakeOpponent`。ねむりのときだけ、「ワザをうけない」状態・「とうめい」を評価してから、ねむりだけを回復させる
  （どくは残す。`conditions.wake_up`。ログ `special_conditions_removed` の `reason` は `cured`・`effect` はワザ）。ねむりでなければ何もしない（「とうめい」も評価しない）。相手がこの
  ワザで HP 以上なら回復させない（p.309）。要素の種類 `effects.WAKE_ELEMENT` を `ATTACK_ELEMENTS` に加えた。
- `DamageAndOptionalFullDrain`（ゴルバット ES1-009・パラセクト ES1-011 の「きゅうけつ」の「…取りのぞいてよい。」）: `Drain(full=True, optional=True)`。取りのぞけるカウンターがあれば、
  ワザを使ったプレイヤーが取りのぞくかを選ぶ（決定 `decisions.OPTIONAL_DRAIN`。選べるものはワザを使ったポケモンの番号 1 つで、0 個か 1 個。`context` の `dealt`・`counters`。
  `carry`）。取りのぞくなら与えたぶん（のっている数まで。ログ `drain_heal`）、取りのぞかないならログ `drain_heal_declined`。与えたぶんの一部だけを取りのぞく答えはない（「取りのぞいて
  よい」を、与えたぶんを取りのぞくかどうかの選択と読む。実装上の読み方）。ダメージを与えなかった・のっていない・ワザを使ったポケモンが HP 以上（C16）なら決定を出さない。
  v0.32 の `DamageAndFullDrain`（「…とりのぞく。」。いつも取りのぞく）は変えていない。
- `DamageThenMoveOneEnergyToBench(雷)`（マチスのエレブー GD3-010・PR1-040 の「デンキとばし」）: 要素 `MoveOneEnergyToBench`。ワザを使ったプレイヤーが、はがす「雷」の基本エネルギー
  カード（決定 `MOVE_ENERGY`。`context` の `stage` は `energy`。1 枚でも出す）→ つける控え（決定 `ATTACH_TO_BENCH`。`stage` は `bench`・`energy` は選んだカード）を選ぶ。2 つの決定の
  あいだ、カードはワザを使ったポケモンについたまま（2 つ目の答えで動かす。カードの置き場所をなくさない。結果は同じ）。控えがいなければ持ち主のトラッシュ（ログ `discard_energy` の
  `reason` は `no_bench`）。つける控えの「とうめい」を評価し、受けないならトラッシュ（v0.31 のエナジーボムと同じ。CR-TRANSPARENCY-ENERGY-BOMB）。つけたら `after_energy_attached`
  （手札からつけたことにはしない）。レインボーエネルギー・［エネエネ］の役割のカード・［へんしん］のメタモンは v0.49・v0.58・v0.59 の共通の確かめ（RB1・BZ2・TE1）。クリスタル
  ビームの効果はベンチにもどると消えるので、つける控えが受けていることはない（v0.59 の CB1 は起こらない。受けていたらエンジンの不具合として止める）。
- `RevealBasicEnergyFromDeck`（エリカのピッピの「おつきみ」）: v0.44 の「おつかい」の要素 `RevealTrainerFromDeck` に、選べるカードの種類 `category`（`"basic_energy"`）を加え、コインなし
  で使う。山札の基本エネルギーカード（どのタイプでも。uid の小さい順）から 0〜1 枚（「加えてよい」）を見せて手札に加え（ログ `reveal_from_deck`）、どの場合も山札を 1 回切る。山札に
  なければログ `reveal_from_deck_none`（`category` は `basic_energy`）。特殊エネルギーカードは「基本エネルギーカード」ではない（v0.58）。トレーナーの使用ではない。
- `DamageThenForceSwitchAfterDamage`（タケシのサイホーンの「つのでなげる」）: `ForceSwitch(after_damage="damage")`。入れ替わるポケモンは相手が選ぶ（ふきとばしと同じ決定
  `FORCED_SWITCH`）。「ダメージを与えた後、…」なので、ダメージを与えなかったときは Z23。相手に控えがいない・相手が HP 以上なら、どちらの読み方でも入れ替えないので聞かない。
  `DamageAndForceSwitch`（形だけを確かめる型）を使うと Z23 を見落とすので、型を分けた。カツラのガーディの「ふりとばす」は「ダメージを与えた後」と書かないので `DamageAndForceSwitch`。

## 4. 再録のなんでもなおし・ポケモン図鑑（v0.71 の登録の見直し）

### 4.1 なんでもなおし（GD1-020・GD3-019・GD4-022・GD5-020・GD6-020・IP2-007・NIP1-007・NIP2-008）

再録の版の印刷の文面「あなたの対戦ポケモンの「どく」「マヒ」「ねむり」「こんらん」状態を、すべて回復させる。」は、対象を自分の対戦ポケモンと書きます。v0.71 では第1弾の版
（PMCG1-080。対象を書かない）と同じ FH1（`UNRESOLVED_FULL_HEAL_SCOPE`）の止める範囲のままで、この版には必要より広いことを限界に挙げていました。

- v0.72 から、型 `CureSpecialConditionsTrainer` の明示的な設定 `scope`（`FULL_HEAL_SCOPE_UNSTATED` / `FULL_HEAL_SCOPE_OWN_ACTIVE`）で分けます。型の `check` が文面と設定の組
  （`FULL_HEAL_TEXTS`）を確かめます。カード id の分岐はしていません（再録の表 `REPRINT_CARDS` の `behavior` に、この版の文面と設定で登録した）。
- 再録の版: 自分の対戦ポケモンの特殊状態だけを回復させます。相手の対戦ポケモンが特殊状態でも、相手のものは回復させず、使えます（FH1 で止めない）。
- 自分の対戦ポケモンに特殊状態がないときに使えるかは、印刷の文面・kyuura の記録で決まらない（kyuura の UQ-CARD-USE-WITHOUT-TARGET と同じ形の問い）ので、手札から出す前に
  **FH2**（`UNRESOLVED_FULL_HEAL_WITHOUT_CONDITION`）で止めます。推測で「何もせずに使い終わる」「使えない」のどちらにもしていません。
- 第1弾の版（PMCG1-080）は FH1 のまま（変えていない）。
- 採用の記録の `behavior_differs` に `trainer` を加え、notes に理由を書きました（10 件。ポケモン図鑑の 2 件を含む）。

### 4.2 ポケモン図鑑（GD1-022・GD5-023）

再録の版の印刷の文面「あなたの山札の上から最大5枚のカードを見て、…」には、第1弾の版（PMCG1-082）の「…ことができる」（v0.54 で 0 枚を見ないこととして受け付けた。PD1）がありません。
「最大5枚」が 0 枚を含むかを、記録で決める根拠は見つかりませんでした（kyuura の UQ-UP-TO-ZERO-CHOICE と同じ形の問い）。

- v0.72 から、型 `ArrangeOwnDeckTopTrainer` の明示的な設定 `zero_allowed`（第1弾の版は True、再録の版は False）で分けます。型の `check` が文面と設定の組を確かめます。
- 再録の版で、山札にカードがあるときの 0 枚の答えだけを **PD2**（`UNRESOLVED_POKEDEX_UP_TO_ZERO`）で止めます（決定の `unresolved_choices`。決定は待ったままで、状態は変わらない）。
  1〜min(5, 山札の枚数) 枚は今までどおり見て並べかえます。
- 山札が 0 枚のとき（見るカードがない）の扱いは変えていません（今までどおり、決定を出さずに使い終わる）。PD1（第1弾の版の 0 枚）も変えていません。
