  番 [0, 24] は別の局面から入っています。その番の rules-v7 の失敗は 3 回、同じ条件での選び直しは 0 回でした。
- **エネルギーの移動で払えるようになった「にげる」は選べるまま残りました。** 構築盤面 M3 では、seed 4 つすべてで、バトル場へ移したあとのにげるが

  その番のうちにワザも受理しました。ただし分岐のあと、旧局でにげるを受理した局面には到達していません（旧局の観測 108 件のうち一致 0）。
  **旧局面でのにげるとワザは、通常対戦では未確認です。**
- **4 局とも完走しました**（すべて `game_over`。勝者は各 seed で rules-v6 と同じ）。停止方針の発動・照合の異常・予算の不足はありません。
- **既存の方策との一致**: 新しい rules-v6 の 2 局は旧局と行動の列が完全に一致しました。rules-v7 は、最初の後回しの試みまで rules-v6 と試みの列が同じです。
- **観測が足りず適用を見送った場面は 0 件**でした（rules-v7 の 2 局で、記録しなかった失敗・鍵の取れない選択ともに 0）。
- 2 組だけの比較なので、一般の完走率や既定化の妥当性は推定しません。`rules-v7` は明示的に選んだときだけ使う試験の方策のままです。

## 2. 実装（`rules-v7`）

`policies.RetreatDeferralRulePolicy` は rules-v6（`EnergyTransRulePolicy`）を土台に、次の規則だけを加えます。

- **記録する場合**: 本人の「にげる」の入力の組み立てが `total_units_unreachable` で失敗したときだけ、その番の（支払い条件の鍵, 候補の中身）を記録します。
  ランナーは組み立ての失敗のあと、`retreat_build_failed` を持つ方策だけに渡し、試みの行に `retreat_deferral` を書きます。
- **支払い条件の鍵**（`retreat_payment_key`）: 本人のエピソードの始めの観測の応答から、観測の外の識別子と、**本人のベンチのポケモンの
  `energy`・`energy_units`・`energy_units_determined` だけ**を除いた正準 JSON です。次はすべて残します。
  - バトル場の個体（番号・カード・姿・進化の重なり）、ついているエネルギーのカードと単位、トレーナー、特殊状態、マーカー、持続効果、特殊能力
  - ベンチの個体（交代先と、［にげるサポート］などの特殊能力の持ち主）、手札、相手の場、スタジアム、場の効果、番
  前回の分析で使った 4 項目（バトル場の個体・単位の並び・`total_units`・`count`）だけでは判定しません。
  カード ID の分岐は入れていません。ベンチのエネルギーを除く根拠は、にげる費用・交代先の適格性に関わる 0.198.0 のカードの効果
  （［にげるサポート］・［ねんちゃくえき］・［ZOOM］・スタジアム・ポケモンのどうぐ ほか）が、どれもベンチのエネルギーを参照しないことです。
- **後回し**: 同じ番で（鍵, 候補）が記録にあれば、その「にげる」を順位 7（`end_turn` より後ろ）にします。候補は消しません。
  順位 7 しか残らなければ rules-v2 と同じく選びます（理由 `:retreat_no_alternative`）。理由のコードには `:retreat_deferredN` を付けます。
- **通常の順位で再評価する場合**: 鍵が変わったとき（バトル場のエネルギー・個体・特殊状態・スタジアム・場の効果・ベンチの個体など）。
  番が変われば記録を消します。観測から鍵が取れない選択では下げません。
- **適用外（記録しない）**: 観測が取れない、本人のバトル場がない、バトル場のエネルギーの単位が決まらない（CE1・CE2）、トラッシュの段に `total_units` がない、
  ほかの理由の組み立て失敗、にげるでない候補。数は方策の記録 `loop.counts` に `retreat_not_applicable:<理由>` として残ります。
- **変えていないもの**: rules-v2〜rules-v6、既定の方式、rules-v6 の［エナジートランス］の処理、［ダメージスワップ］の 6 回の上限、入力 API、入力の組み立ての支払いの判定、
  エンジン、規約、judge、単局の上限。道具の版は 17 → 18（計画の形式 7・完了の形式 7・判定の規則 10 は同じ）。
