# T-F1: 錯乱ジムで相手がかわりに使えるかの判定からの情報漏れの修正（v0.168）

U7-5 の設計で見つけた F-1（[legal-actions-u7-5-design](legal-actions-u7-5-design.md) 8 章）を、両方のモード（厳密側・プレイ側）に共通の不具合として直しました。

- 同じ確かめを使うナツメのサイキックコントロールの選べるものにも、同じ漏れがありました（F-8）。F-1 とは別の事例で、今回の調査で見つけて直しました（共通の確かめを通る経路のため）。U7-5 の設計の台帳に F-8 として分けて記録しています
- トレーナーの候補 API（U7-5c）は実装していません

## 1. 修正の前の再現と原因

### 1.1 再現

修正の前の木で `tests/test_chaos_gym_borrow_t_f1.py` を流しました（11 件）。結果は失敗 4・エラー 5・成功 2 でした。

- **失敗 4 件**（実際の漏れを見つけた失敗）: 使ったプレイヤー（0）と観戦者の観測・見えるログが、双子で違いました。片方は決定待ち（`decision`）、片方は番の続き（`main`）です。
  - 錯乱ジムの双子 3 件: ポケモン交換おじさん・ポケモン育て屋さん・礼儀作法で、相手（1）の手札 1 枚だけが違います
  - サイキックコントロールの双子 1 件: 使う人（0）の手札 1 枚だけが違います。相手（1）と観戦者の観測・ログが違いました
- **エラー 5 件**: 修正のあとの契約（使えない人にも決定を出し、「使う」の答えを拒否する）を確かめるテストです。修正の前は決定が出ないので `NoneType` になりました。新しい API がないためのエラーではなく、同じ漏れの現れです
- **成功 2 件**: 公開の情報だけで使えないカード（プラスパワー）と、決められない使うための条件の扱いです。今までどおりの挙動の確かめです

設計の双子（相手の手札の 1 枚がリザードンか水エネルギーか）も、`NO_EVOLUTION_TARGET` の公開のログと `ACCEPT_REQUEST` の決定に分かれることを、現行のコードで確かめました。

## 3. 修正の方法と、裁定を変えていない根拠

- **錯乱ジム（`_chaos_tails`）**
  - 聞かずにトラッシュするのは、公開の情報だけで使えないと決まるときだけです（`borrow_public_unusable_reason`）。対象は、カードの性質（ポケモンにつけて使う・場に出して使う・スタジアム）と、場の力・期限のある禁止です
  - それ以外は、いつも相手に `ACCEPT_REQUEST`（選べるもの (1,)・0〜1 個）を出します
  - 決められない使うための条件（`UnsupportedError`）は、今までどおり「使うことを選ぶと止める」選択にします（`borrow_condition_stop`。決定の続きの情報で、答える人の候補にだけ出ます）
- **承諾（`_resume_trainer`）**: 「使う」と答えたら、その人の手札・場で使うための条件を確かめます（`require_borrow_playable`）。満たせなければ、そのカードの確かめの `IllegalActionError` で答えを拒否します（状態・乱数・ログを変えない）。「使わない」はいつも受け付けます
- **サイキックコントロール（`discard_trainer_use_choices`・`resume`）**
  - 選べるものは、公開の情報で決まる部分だけで作ります
  - 使うための条件を満たせないカードを選んだら、答えを拒否します
  - 選べるものがないときのログ `discard_trainer_use_none` は、公開の情報で選べるものがないときだけ出ます

裁定を変えていない根拠:

- 最終的にできること・できないことは同じです。使うための条件を満たせない人は使えません（答えの拒否）。条件を満たせる人は今までどおり使えます。使わない・使えないカードは、どちらも持ち主のトラッシュです
- 文面の「のぞむなら」「使ってもよい」は相手の任意の選択で、相手に聞くことは文面の手順どおりです
- 使うための条件を緩めていません。対象 0 枚を新しく許していません
- 使う前の確かめ・コイン・費用・カードの移動・効果・番の終わりの順は変えていません
- CH1・MG1・TL1 の止め方は変えていません
- 続行規約を加えていません。カード ID・モード名による共通処理の分岐を加えていません

## 4. 閲覧者ごとの情報境界

| 閲覧者 | 見えるもの |
|---|---|
| 使ったプレイヤー・観戦者 | 決定の種類・決める人・選ぶ数・選べるものの数（いつも 1）、ログ `chaos_check`・`chaos_answered`（使ったか）。相手が使えたかどうか・理由は見えない |
| 相手（かわりに使う人） | 自分の手札・場（本人の知識）。「使う」の答えが拒否されたときの理由のコード・文（答えた人にだけ返る） |
| サイキックコントロールの相手 | 選べるものの数は、相手のトラッシュの公開の情報だけで決まる。使う人の手札による違いは見えない |

双子の確かめ（相手の手札の中身・山札とサイドの配分だけが違う）で、使ったプレイヤーと観戦者の観測・ログが一致しました。かわりに使う人に向けた情報（答えの拒否の理由）は、許された本人の情報なので同じにしていません。

## 5. 承諾・辞退・使用不能・不正な答えの扱い

- **承諾（使える）**: 今までどおり。ログ `chaos_answered`（`accepted: true`）→ 相手の手札・場で効果
- **辞退**: ログ `chaos_answered`（`accepted: false`）→ 持ち主のトラッシュ。使えない人の辞退と、使える人の辞退は、公開の値で区別できません
- **使えない人の承諾**: 答えの拒否（`IllegalActionError`。コードはカードの使うための条件の確かめのもの）。状態・乱数・ログ・決定の番号は変わりません。何度送っても同じ拒否です。拒否は答えた人にだけ返り、相手・観戦者への公開の更新を作りません
  - 拒否の内容は答えた人の情報だけなので、使ったプレイヤーは答えを送れず（決める人ではない）、反復で秘密を探れません
  - 拒否のあとも決定は待ったままで、「使わない」で進みます。コインや秘密を見たあとに、使う操作全体をやり直す経路はありません（使ったプレイヤーの `PlayTrainer` は受理済み）
- **公開の情報だけで使えないカード**（プラスパワー・ピッピ人形・スタジアム・禁止）: 今までどおり聞かずにトラッシュします（ログ `chaos_not_borrowable`。理由はカードの性質・禁止）
- **内部エラー**: 未対応にまとめて変換していません（新しい捕まえる箇所は、使うための条件の確かめの `IllegalActionError`・`UnsupportedError` だけ）
