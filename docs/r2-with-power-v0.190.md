# v0.190: R-2 の［めいれい］の限定提示（うらのバトル場のワザの宣言）

2026-11-17。`kyuura_engine` の版は 0.190.0。設計は [r2-with-power-design.md](r2-with-power-design.md) で、その 8 章に採用と結果を書きました。

これは R-2 の残りのうち［めいれい］だけの限定提示です。R-2 全体は解消していません。アンノーンの［XXXXX］・［ANGER］（別の単位）と［すいりょくはつでん］（変身の経路。今のまま）は対象外で、示しません。

## 1. 変えたこと

`kyuura_engine/legal_actions.py` の、うらのバトル場のポケモンのワザの候補（`_face_down_attack_candidate`）だけを変えました。

- 2 段目（宣言といっしょに選ぶもの）に、次のすべてを満たすとき、自分の場のおもてのポケモンの［めいれい］（`with_power`）を、持ち主ごとに 1 つ示します。
  - 番のプレイヤーの main の段階で、本人のバトル場のポケモンがうら（呼び出し元の条件）。
  - 本人が知る本当のカード（`printed_def`）が特殊能力を持たない。
  - 自分の場のおもてのポケモン（使い手と別）の力が `CommandBonusToNamedAttackers`（`group_attack_power_slot`）。
  - 本当のカードの印刷の名前が、その力の `names` のどれかと完全に同じ（型の値を使う。カード id の一覧は作らない）。
  - 持ち主の力が消えていない（`power_suppressed`）・使えない効果を受けていない（`powers_use_prevented`）。
- 値・表示はおもての宣言（`_addon_specs`）と同じ形です（`addon: with_power`・持ち主の場の表示・`power`）。並びは コイン → 場の並び（バトル場 → ベンチ）。どの印刷のワザにも同じ選択肢を示します。
- 区分は `unverified`、理由は `face_down_reveal_not_evaluated` のままです。示しても受理・ダメージの増加を保証しません。
- 入力の検査（check）は形のほかに、同じ力（`exclusive_key`。2 匹の［めいれい］）を 2 つ選ぶ組だけを、おもての宣言と同じ区分（`CANDIDATE_INPUT_INVALID`）で拒否します（示した持ち主の力の登録だけを読む）。
- 2 段目の note は、コインだけのときは 0.188.0 の文のまま、［めいれい］を示すときは新しい文です。うらのワザの保証の文（`GUARANTEE_FACE_DOWN_ATTACK`）の preconditions・acceptance を実装に合わせました（`test_legal_actions_f1_v0_180` の固定の sha256 を更新。旧の値は説明に残す）。

**変えていないこと:**
- 送信のあとの順（おもてにする → たねでなければトラッシュして受理 → `check_use_attack`（`group_attack_powers_check`）→ 先読み → 処理）と、拒否のときの状態・乱数・ログの巻き戻し。
- 候補の作成・入力の検査で、おもてにする処理・エンジンの確かめ・複製の上の試行・相手のうらのカードの割り当て・乱数を使わないこと。
- エンジンのゲーム処理・裁定・規約・judge・検証用 AI の方策・API の形式・GUI。

## 2. 直接のコマンドの前提確認（入力の提示を変える前）

構築盤面（うらのサカキのニドラン♂・ベンチにおもてのサカキのニドキング PR1-068）で、0.189.0 のエンジンに直接 `UseAttack` を送りました。

| 確かめ | 結果 |
|---|---|
| にどげり ＋［めいれい］（コイン おもて 2・1・0） | 受理。相手のダメージ 30・20・0（力なしは 20・10・0）。+10 は p.321 の 6 段階。「おもて」0 枚は 2 段階までで終わるので加えない（既存の処理） |
| おもての同じ使い手（対照） | 同じ値（30 と 20） |
| いかりのいちげき | 力のあり・なし、おもて・うらとも、自分にダメージカウンターがないためワザの条件で拒否（［めいれい］とは別の理由） |
| 持ち主 2 匹 | どちらか 1 匹は受理（同じ値）。2 匹いっしょは `POWER_ALREADY_USED`、同じ持ち主の重なりは `DUPLICATE_POWER` |
| かがくへんかガス・使えない効果（注入）・名前が違う本当のカード | `POWER_SUPPRESSED`・`POWER_USE_PREVENTED`・`ATTACK_POWER_NOT_AVAILABLE` で拒否 |

拒否はどれも状態・乱数・ログ・決定の通し番号が変わりませんでした。エンジンの処理・先読みの問題は見つからず、そのまま入力の提示へ進みました。
