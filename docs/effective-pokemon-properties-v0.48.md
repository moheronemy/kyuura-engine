## 2. 今有効な値の求め方（共通の処理）

### 2.1 3 つの定義を分ける

| 区別 | どこにあるか | 変わるか |
| --- | --- | --- |
| 印刷の定義 | `GameState.printed_def(uid)`（写しのカード。`CardDefinition`） | 変えない |
| 場での役割（v0.47） | `GameState.card_def(uid)`（なにかの化石・ピッピ人形が場にいるあいだ。HP 10・タイプなし） | 場所で決まる。変えない |
| 今有効な値（v0.48） | `effects.max_hp`・`weakness_of`・`resistance_of`・`type_readings`・`definition_views` | 問い合わせのたびに、カードの定義（`card_def`）に今の効果を当てはめて求める |

共有する `CardDefinition` は書きかえません。ダメージの計算などに定義の形で渡すときは、`definition_views` が `dataclasses.replace` で新しい値を作ります（値がカードの
定義と同じなら定義そのもの）。今有効な値を状態に書き写していません（ログは、その時点の値を記録するイベント（`ko_prevention_declared` の `hp`）だけ）。保存しているのは、
値を求めるのに要る履歴だけです:

- ワザによる持続する効果（`PokemonInPlay.persistent_effects`）: `WeaknessChange`（テクスチャー1）・`ResistanceChange`（テクスチャー2）・`MaxHpSet`（きょだいか）。3 章
- 特殊能力で色を変えた記録（`PokemonInPlay.type_shift`。`TypeShift`）: ［へんしょく］。4 章（書き出しの形式 13）
- 常にはたらく特殊能力（［ガスのからだ］）の効果は記録しません。はたらいているかは v0.46 と同じく、今の場（いちばん上のカード・場所・特殊状態・かがくへんかガス）から
  求めます（`effects._own_working_continuous`。かがくへんかガスは `continuous.suppressors_of`）

### 2.2 問い合わせ

| 関数 | 求めるもの |
| --- | --- |
| `max_hp(state, pokemon)`（公開） | カードの定義の HP。きょだいかの効果（`persistent.max_hp_set`）があればその数（80）。はたらいている［ガスのからだ］の分だけ大きくする。2 つが同時にはたらくポケモンは今の写しにないので `RuntimeError` |
| `weakness_of(state, pokemon)`（公開） | テクスチャー1の効果があればその色、なければカードの定義の弱点（倍数は変えない） |
| `resistance_of(state, pokemon)`（公開） | (色, 数)。テクスチャー2の効果があれば色だけ変わる（数はカードの定義の値。−30） |
| `type_readings(state, pokemon)`（公開） | 色の読み方。ふつうは 1 つ。［へんしょく］の色が有効と決まらないときは (変えた色, カードの定義の色) の 2 つ（4 章） |
| `definition_views(state, pokemon)` | 読み方ごとの、今有効な値を入れた定義（ダメージの計算に渡す） |
| `same_for_type_readings(state, pokemons, compute)` | 読み方のすべての組で計算し、同じならその値。違えば `TypeReadingsDiffer`（呼ぶ側が VS1 で止める）。読み方が 1 つなら 1 回だけ計算する（v0.47 と同じ計算） |
| `evolution_hp(state, pokemon, card)` | そのカードを重ねたあとの最大HP（進化すると持続する効果は消えるので、重ねるカードの HP と、そのカードの常にはたらく特殊能力だけ） |
| `max_hp_drops(before, after)` | 2 つの状態のあいだで、最大HPが下がってのっているダメージ以下になった場のポケモン（MH1。5 章） |

カード id で分ける処理は `engine.py`・`resolution/` に加えていません。判定は型（`MaxHpPerAttachedEnergyCards`・`ShiftColor`・持続する効果の型）で探します。

### 2.3 点検した処理

HP・タイプ・弱点・抵抗力を読む処理を探し、印刷の値・カードの定義の値を直接読んでいたところを、上の問い合わせに置きかえました。

| 処理 | 今有効な値の読み方 |
| --- | --- |
| 通常のダメージ（p.321。`kernel.deal_damage`）と宣言の前の計算（`preview_attack_damage`） | ワザを使うポケモン・受けるポケモンの `definition_views`（色・弱点・抵抗力）を `same_for_type_readings` で計算。読み方で最終ダメージが変わるなら VS1 |
| 控えへのダメージの弱点・抵抗力の読み方（JS1。`kernel.weakness_resistance_matters`） | 読み方のすべての組で比べる |
| こんらんの 20（`procedures.confusion_damage_problem`・`confusion_damage`） | 自分の色・弱点・抵抗力（読み方で 20 が変わるなら宣言の前に VS1） |
| 特殊能力によるダメージの弱点・抵抗力（Z9。`kernel` の `power_damage_weakness_resistance`） | 与えるポケモンの読み方のどれかが、受けるポケモンの今有効な弱点・抵抗力の色なら止める |
| 返すダメージにくつろぐかおりを当てはめるか（CP1。`kernel.calming_retaliation_question`） | 読み方の組ごとに比べる |
| きぜつの判定（ワザのあと・特殊能力のあと・ポケモンチェックのどく・不変条件・こんじょう） | `max_hp`（`kernel.hp_of`・`effects.knocked_by_hp`・`procedures`・`engine._…`） |
| 残りの HP を使うワザ（いかりのまえば `HalfRemainingHp`・ライフダウン `CountersToRemainingHp`）・こんじょうの残り HP 10 | `max_hp` |
| 最大HPの条件（すごむの「最大HPが50以下」） | 効果を与えるときの `max_hp`（与えたあとに最大HPが変わっても効果は消さない） |
| ダメージスワップ・へんなこうどうの「きぜつさせない」移動（`effects.would_be_knocked_out`） | `max_hp` |
| 回復（ダメージカウンターをとりのぞく） | のっている数までとりのぞく（最大HPで上限をつけない処理は v0.47 から変えていない） |
| 進化の確認（通常の進化・ポケモン育て屋さん・つきのちから・たきのぼりしんか・［うか］の H1） | `evolution_hp`（重ねるカードの HP と、そのカードのはたらく常にはたらく特殊能力） |
| タイプで対象を選ぶワザ（ビリビリの「同じ色」・ウォーターリングの除く色・`PrintedTimesIfDefenderType`） | `type_readings`（読み方で対象・量が変わるなら VS1） |
| タイプで決まる特殊能力（あまごいの「水」ポケモン） | `type_readings`（読み方で答えが変わるならエネルギーを動かす前に VS1） |
| ［へんしょく］で選べる色 | 場にいるポケモンの `type_readings`（4 章） |
| ベンチに移る・進化・場をはなれる | 持続する効果は v0.4b と同じ契機で消える。`TypeShift` はベンチにもどったら `returned_to_bench`、進化したら消す、場をはなれたら場のポケモンといっしょになくなる |
| 観測（`observation.observe`） | `hp` は `max_hp`、`pokemon_type`・`weakness`・`resistance` は今有効な値（7 章） |
| ログの監査・不変条件・書き出し・先読み | 9 章・7 章・tests/log_audit.py |

場以外のカード（手札・山札・トラッシュ・サイド・使用中）には今の場の変更を当てはめません。問い合わせは場のポケモン（`PokemonInPlay`）を受け取り、カードの定義
（`card_def`）は場以外ではいつも印刷の定義（なにかの化石・ピッピ人形はトレーナー）です。

## 3. テクスチャー1・テクスチャー2・きょだいか（ワザによる持続する効果）と PG1

### 3.1 持続する効果の型

| 型（`kind`） | 与える相手 | 値 | はたらく番 | 消える契機 |
| --- | --- | --- | --- | --- |
| `WeaknessChange`（`weakness_change`） | 相手の対戦ポケモン（`on_opponent`） | 弱点の色 `color` | 与えたときから（`turns_until_active` 0） | ベンチにもどる・場をはなれる・進化・きぜつ。期限では消えない（`lasting`） |
| `ResistanceChange`（`resistance_change`） | 自分 | 抵抗力の色 `color`（数は変えない） | 与えたときから | 同上 |
| `MaxHpSet`（`max_hp_set`） | 自分 | 最大HP `amount`（80） | 与えたときから | 同上（説明の「バトル場をはなれた時」） |

- 説明は番の期限を書かないので、期限のない効果（v0.45 の `lasting`）にしました。「相手がベンチに戻った時」（第1弾）・「そのポケモンがバトル場をはなれた時」
  （ロケット団）・「自分がベンチに戻ったとき」・「バトル場をはなれた時」は、どれもバトル場をはなれると消える同じ処理です。場をはなれる・進化するときは、持続する効果の
  一般の規定（GR-2000-P322-PERSISTENT-EFFECTS）でも消えます。
- もう一度受けたら、前の効果を理由 `replaced`（新しい理由。`persistent.REPLACED`）で消してから与えます（`persistent.replace_persistent_effect`）。同じポケモンに同じ型の効果は
  1 つです。テクスチャー1を受けたポケモンにテクスチャー1をもう一度使えば、新しい色が今有効な弱点です。
- 弱点の倍数（×2）・抵抗力の数（−30）は変えません（文面は「色」を変える）。抵抗力の色と数を混同しないよう、`resistance_of` は (色, 数) を返します。
- テクスチャー1は相手のポケモンへの効果なので、色を選ぶ前に「ワザをうけない」状態・「とうめい」を評価します（要素の種類 `weakness_change`。受けないなら選ばない）。
  テクスチャー2・きょだいかは自分への効果で、評価しません（ポリゴン・キョウのメタモン・まねるワザを持つポケモンは「とうめい」を持たない）。
- きょだいかの「はたく」の「このカードに「きょだいか」の効果がはたらいているとき」は、最大HPと同じ問い合わせ（`persistent.max_hp_set`）で効果の有無を見ます。効果が
  あれば基本となるダメージ（p.321 の 1 段階）が 30、なければ印刷の 10 です（v0.40 の `AmountIfOwnBenchNamed` と同じ 1 段階の値）。
- きょだいかの「うら」は何もしません（前の効果はそのまま残る）。ワザを使ったポケモンがこのワザの前にすでに HP 以上なら与えません（`persistent_effect_skipped`）。

### 3.2 選べる色（実装上の判断）

テクスチャー1・2の色を選ぶのはワザを使ったプレイヤーです（決定 `SELECT_COLOR`。選べるものは `effects.COLORS` の位置）。選べる色は、無色以外の 8 つ（草・炎・水・雷・
超・闘・悪・鋼）です。2000.02.14 版のルールのダメージの計算の例に悪エネルギー・鋼エネルギーがある（kyuura rule_history.json の P43 の記録。p.321 の順番の例）ので、
悪・鋼もタイプ（色）として選べるものに含めました（実装上の判断。今の写しに悪・鋼のポケモンはいないので、悪・鋼の弱点に変えても、その弱点を突くワザはない）。
［へんしょく］の色は 4 章のとおり場にいるポケモンの色だけです。

### 3.3 PG1: 弱点・抵抗力のないポケモン

弱点を持たないポケモン（ナツメのゴース・ゴースト・ゲンガーなど）の弱点、抵抗力を持たないポケモンの抵抗力を「好きな「色」にかえる」とき、弱点（抵抗力）を新しく
持たせるのか、何もしないのか（抵抗力なら引く数も）は、印刷の文面・kyuura の記録から決められません（英語版の「If the Defending Pokémon has a Weakness」は持ち込まない）。
宣言の前に `UNRESOLVED_CHANGE_ABSENT_WEAKNESS_RESISTANCE`（問い `change_absent_weakness_resistance`）で止めます（先読みが見つけるので、状態・乱数・ログは変わらない）。
弱点・抵抗力のあるポケモンには止めません。カード全体を未対応にはしていません。

### 3.4 まねるワザで使う場合

ピッピの「ゆびをふる」・ピクシーの「ゆびをふる」・カスミのコダックの「ぼーっとする」で、テクスチャー1・2・きょだいか・はたくを自分のワザとして使えます（既存の
`CopyOpponentAttack`。色を選ぶのはまねたプレイヤー。持続する効果の発生源はまねたポケモン）。テクスチャー2を、抵抗力のないカスミのコダックがまねる場合は PG1 です。
まねるワザの決定（使うワザの選択）を出す前に、選べるワザのどれかが問いに当たると宣言の前に止めるのは既存の先読みの扱い（v0.31 の HC9 と同じ時点）で、この場合も宣言の
前に PG1 で止まります（技術的な制限。11 章）。

## 4. ［へんしょく］（モルフォン）と VS1

- 宣言して使う特殊能力（`ShiftColor`。v0.42 の共通の処理）。自分の番に 1 回（`once_per_turn`。宣言のときに `power_uses_this_turn` に記録）。ねむり・マヒ・こんらんの
  このカードは使えません（`POKEMON_ASLEEP` など）。かがくへんかガスで消えます（`POWER_SUPPRESSED`）。
- 宣言のあと、使ったプレイヤーが色を選びます（決定 `SELECT_COLOR`、再開先 `"power"`）。選べるのは、場にいるポケモン（お互いのバトル場・ベンチ）の今有効な色です
  （`shift_color_options`）。色のないポケモン（場のなにかの化石・ピッピ人形）は数えません。無色も選べます（日本語の文面は無色を除かない。英語版の「other than
  Colorless」は持ち込まない）。
- 選んだ色を場のポケモンの記録 `TypeShift`（色・使った番・使ったときのいちばん上のカード・ベンチにもどったか）に残し、ログ `type_shift`（前の記録があれば
  `previous_color`・`previous_turn`）。前の記録は置きかえます。
- 記録は特殊能力の効果で、ワザによる持続する効果ではありません（P322 の持続する効果の規定はワザの効果のもの）。場をはなれたら場のポケモンといっしょになくなり、
  進化したら消します（進化したポケモンは別のポケモン。p.310。モルフォンから進化するカードは写しにない）。

### 4.1 変えた色がいつまで続くか（VS1）

文面は効果の期限を書きません。変えた色が、使った番のあと（次の番以後）・バトル場からベンチにもどったあと・この力が消えているあいだ（ねむり・マヒ・こんらん・かがく
へんかガス）も続くかは、印刷の文面・kyuura の記録から決められません（VS1。`UNRESOLVED_SHIFT_COLOR_DURATION`）。

- 決まっているのは、使った番のうちで、使ってからベンチにもどっておらず、いちばん上のカードが同じで、力が消えていないときだけです（`type_shift_determined`）。そのときの
  色は変えた色です。
- それ以外は、変えた色とカードの定義の色の 2 つの読み方（`type_readings`）を持ち、色を読む処理は 2 つの読み方で結果が変わるときだけ止めます（変わらなければ止めない。
  どちらか 1 つを選んで続けない）。ワザのダメージなら宣言の前（先読みが見つける）、特殊能力（あまごいの対象）ならエネルギーを動かす前、［へんしょく］の色の候補なら
  その色を選ぶと止める（決まって場にいる色がなければ使う前に止める）。
- 「能力を使えなくすること」と「すでに変えた色を消すこと」は同じ処理にしていません。特殊状態・かがくへんかガスで使えなくなっても記録は消さず、その間の色は決まらない
  （2 つの読み方）として扱います。消えたことにも、続くことにもしていません。
- 観測は、決まらないとき `pokemon_type` を None にし、`pokemon_type_readings` に 2 つの読み方、`type_shift.determined` に偽を書きます。

## 5. 最大HPの変化と MH1

### 5.1 ［ガスのからだ］（ナツメのゴース）

- 常にはたらく特殊能力（v0.46 の `ContinuousPower`。宣言しない。`UsePokemonPower` は `POWER_NOT_DECLARABLE`）。場（バトル場・ベンチ）のどこでもはたらきます。
- 最大HP = カードの定義の HP 40 + ついている「超」の基本エネルギーカードの枚数 × 10。数えるのはカードの枚数で、供給するエネルギーの個数（`state.energy_types`）では
  ありません（エナジーバーンなどで供給するタイプが変わっても、カードの種類で数える）。今の写しに特殊エネルギーのカードはありません。
- 説明のとおり、ねむり・マヒ・こんらんでもはたらきます（`blocked_by_status` が偽）。かがくへんかガスでは消えます（G4。抑止は `continuous.suppressors_of` で別に判定）。
- 最大HPは、エネルギーカードをつける・はがす・つけかえる・かがくへんかガスがはたらく／消える・進化する（いちばん上のカードが変わる）と変わります。どれも問い合わせのたびに
  今の場から求めるので、記録を直す処理はありません。

### 5.2 最大HPが上がる・下がるとき

| 場面 | 処理 | 根拠・分類 |
| --- | --- | --- |
| 最大HPが上がる（超のカードをつける・きょだいかの「おもて」・ガスが消える） | 今有効な最大HPを使うだけ | — |
| ワザの効果で下がり、のっているダメージ以下になる（はかいこうせんで超のカードをトラッシュ） | ワザのあとのきぜつの判定（ワザの要素をすべて処理したあと）で、ほかの HP 以上のポケモンとまとめてきぜつ | GR-2000-P323-KNOCKOUT（1 つのワザなどによって引き起こされることがらによるきぜつは同時。この場面への当てはめは SUPPORTED） |
| そのポケモン自身を進化させ、進化先の最大HPがのっているダメージ以下になる | v0.4a の H1（`UNRESOLVED_EVOLUTION_HP`）。`evolution_hp` で求める | 既存の問い。進化のときだけ |
| ワザの外で下がり、のっているダメージ以下になる（にげるで超のカードをトラッシュ・きょだいかのメタモンがベンチにもどる・ベトベターをベトベトンに進化させてかがくへんかガスが［ガスのからだ］を消す・エナジートランスで超のカードを移す・ポケモンいれかえ／突風／かおりのわなでベンチにもどす・ポケモンチェックでねむり・マヒのベトベトンが回復してガスがはたらく など） | MH1（`UNRESOLVED_MAX_HP_DROP`）で止める | 決められない（下） |
| ワザの途中の決定を待つあいだに、ワザの効果で下がる | `UNSUPPORTED_MAX_HP_DROP_DURING_ATTACK`（エンジンの未対応。研究の対応表の停止コードに入れない。今の対応カードでは起こらない） | 技術的な制限 |

MH1: ダメージ以外の原因で最大HPが下がって、のっているダメージ以下になるとき、きぜつするか・いつきぜつの判定をするかは、ワザのあとのきぜつの判定（p.309・
GR-2000-P323-KNOCKOUT）のほかに記録がなく、決められません。v0.4a の H1 は「進化すると HP がのっているダメージ以下になる」問いで、進化のときの問いです。別の原因
（エネルギーの減少・効果の消失・ガス）に理由なく広げず、新しい問いとして記録しました（kyuura の未解決の一覧にない `not_in_kyuura`）。

止め方:

- コマンドの終わり（`engine._apply`）で、受け付ける前の状態と比べて（`max_hp_drops`）、下がってダメージ以下になったポケモンが残っていれば、そのコマンドを受け付けません
  （渡した状態は変えない）。ワザの中で下がったポケモンは、ワザのあとのきぜつの判定できぜつしているので残りません。
- コインの結果で受け付けるかが変わらないよう、コインの前に確かめる処理を加えました: にげる（`engine._retreat_max_hp_drop_check`。エネルギーをトラッシュした状態と、
  ベンチにもどした状態の両方を複製の上で確かめる。エネルギーのトラッシュ・こんらんのコインの前）、ポケモンいれかえ・突風（`switch_max_hp_drop_check`。手札から出す前。
  決定への答えで止めない）、かおりのわな（コインの前）、ポケモンチェック（ねむりのコイン・マヒの回復の前に `Phase.HALTED`）。
- 止めるのはその操作・その場面だけで、カードは対応のままです。

### 5.3 ナツメのゴースの系統の進化

ナツメのゴースト・ゲンガーは［ガスのからだ］を持たないので、進化すると最大HPはそのカードの HP（50・80）になります。超 2 枚・ダメージ 50 のナツメのゴース（最大HP 60）を
ナツメのゴースト（HP 50）に進化させるのは H1 です（`evolution_hp`。進化すると持続する効果・特殊状態は消えるので、重ねるカードの HP と、そのカードの常にはたらく
特殊能力だけを当てはめる）。

## 6. そのほかのワザ

- りんぷん（モルフォン）: ダメージ → 1 枚のコイン（`Coin`）→「おもて」ならどくとこんらん（`Status` の 2 つの要素が同じコインの面を見る。要素ごとに投げ直さない）。
- ガスでつつむ（ナツメのゴース）: 説明のないワザ（`DamageOnly`）。
- ナイトスピリッツ（ナツメのゴースト）: 自分の場にいる「ナツメのゴース」「ナツメのゴースト」「ナツメのゲンガー」の数だけコインを投げ、「おもて」の数 × 30 を基本となる
  ダメージ（p.321 の 1 段階）にします（値 `HeadsTimesNamedPokemon`）。数えるのは場のポケモン（いちばん上のカードの名前の完全一致。進化して重なったカードは別の
  ポケモンとして数えない。v0.39 の `counted_pokemon`）。名前は文面が指定する名前の組を登録の引数（`names`）にし、カード id の一覧にしていません（ゴース・ゴースト
  （化石の秘密）は名前が違うので数えない）。コインの結果は「おもて」の数だけを使うので、先読みは「おもて」の数でまとめます（v0.35。n 枚を n + 1 通り）。実際の対戦の
  コインは今までどおり 1 枚ずつ投げ、乱数・ログは変わりません。0 枚が「おもて」なら 0 で、ダメージを与えません。
- ダメージぞうふく（ナツメのゲンガー）: 相手の場（バトル場 → ベンチの順）の、ダメージカウンターがのっているポケモン全員に 1 個ずつのせます。ダメージカウンターを
  のせることはワザによるダメージではありません（GR-2000-P320-COUNTER-MOVE。v0.41 のダメージシフトと同じ）。弱点・抵抗力・プラスパワー・ディフェンダー・
  「ダメージを受けない」状態を計算せず、「ダメージを受けたとき」の効果ははたらきません。ポケモンごとに「ワザをうけない」状態・「とうめい」を評価します（2 匹以上が
  「とうめい」なら T27）。ログはポケモンごとの `place_damage_counters`。HP 以上になったポケモンは、ワザのあとのきぜつの判定でまとめてきぜつします（こんじょうは
  使えない）。対象がいなければ何もしません。
- やみのこえ（ナツメのゲンガー）: 40 のあと、相手が「きぜつ」しなかったなら（このワザのダメージで HP 以上になっていなければ）コインを 2 枚投げ、2 枚とも「おもて」なら、
  相手と、ついているすべてのカードを持ち主の山札にもどして切ります（v0.40 の `ReturnOpponentToDeck`。きぜつではない。サイドは取らない。空いたバトル場はワザのあとに
  相手が控えから出し、控えがいなければ相手の負け）。「つまみだす」の「相手に控えがいない時、このワザは使えない」は、このワザの説明にないので持ち込みません
  （`required` が偽）。「ダメージを受けない」状態でダメージを受けなかった相手はきぜつしていないのでコインを投げ、もどします（もどす効果はダメージではない）。
  「ワザをうけない」相手・「とうめい」で受けないと決まった相手には、効果だけを決めるコインなので HC3・T19b（既存の問い）。同じワザで HP 以上になるポケモンがいて
  もどす場合は RD9（v0.36）。
- サイケこうせん（ロケット団のポリゴン）: 既存の `ConfuseOnHeads`。
- はたく（キョウのメタモン）: 3.1 節。

### 11.2 技術的な制限

- `UNSUPPORTED_MAX_HP_DROP_DURING_ATTACK`: ワザの途中の決定を待つあいだにワザの効果で最大HPがダメージ以下に下がる場合（今の対応カードでは起こらない）。
- まねるワザ（ゆびをふる・ぼーっとする）は、選べるワザのどれかが問いに当たると宣言の前に止まります（既存の先読みの扱い）。カスミのコダックがテクスチャー2を選べる
  場面では、テクスチャー2を選ばなくても PG1 で止まります。
- 最大HPをその数にする効果（きょだいか）と大きくする特殊能力（［ガスのからだ］）が同じポケモンに同時にはたらく場合は、順番が決まらないので `RuntimeError` です（今の写しの
  カードの組み合わせでは起こらない）。そのようなカードを加えるときは、先に問いを加えてください。
- ログの監査は、きぜつの最大HPの下限を、きょだいかの効果があればその数、なければ印刷の HP で確かめます（かがくへんかガスで［ガスのからだ］が消えるきぜつの時点を
  ログから組み立て直さないため。エンジンの不変条件は今有効な最大HPで確かめる）。
