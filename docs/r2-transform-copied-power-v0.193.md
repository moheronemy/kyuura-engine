- 日付: 2026-11-18。版 0.193.0（0.192.0 から）。基点 `claude/r2-transform-c-tf0` @ `af1ccb4`。
- 実装・テスト・台帳の同期 `ff70892`、版 `a85b773`（配布の確かめの固定コミット）。設計: [変身の経路と［すいりょくはつでん］の設計](r2-transform-hydro-design.md) 9 章（C-TF0）・10 章（この単位）。

## 1. 何を直したか

v0.124（[docs/super-transform-dark-pulse-v0.124.md](super-transform-dark-pulse-v0.124.md) 3.1 節）の方針は、変身したポケモンが写したカードの特殊能力を持つ（CR-TRANSFORM-COPIES-TOP-CARD）が、
写すことをエンジンが確かめた宣言する特殊能力（`COPY_VERIFIED_DECLARED` の 4 型）でなければ、使う宣言を未対応（`UNSUPPORTED_TRANSFORM_COPIED_POWER`。研究上の未解決ではない）で止める、です。

0.192.0 まで、この確かめ（`effects.copied_declared_power_problem`）を呼ぶのは `UsePokemonPower` の経路だけでした。ワザといっしょに使う力は通っていました（C-TF0 の SF1）:

| 盤面（構築盤面。new_game からの到達ではない） | 0.192.0 | 0.193.0 |
|---|---|---|
| メタモン（おもて・うら）が写したランターンの［すいりょくはつでん］を `attack_power`（水 3。`card` を省く・写す相手の uid） | 受理・20 → 50 | `UNSUPPORTED_TRANSFORM_COPIED_POWER` |
| 同じ（水・水・闘。SF2 の TE1 を聞かない盤面） | 受理・40 | 同じ未対応（数えるところに着かない） |
| メタモンが写したアンノーンX の［XXXXX］を自身で `with_power` | 受理・60 | 同じ未対応 |
| メタモンが写したアンノーンA の［ANGER］を自身で `with_power` | 受理・20 | 同じ未対応 |
| `with_powers`（写した自身の力・ベンチのアンノーンA）。並びの順はどちらでも | 受理・60 | 同じ未対応 |
| ベンチのアンノーンA（写していない別の持ち主）だけ | 受理・20 | 受理・20（変えない） |
| 力なしの写したワザ | 受理・20 | 受理・20（変えない） |
| 本来のランターン（雷・雷・水）・アンノーンX・A 自身・アンノーンX ＋ ベンチの A | 受理・30・30・10・30 | 同じ（変えない） |
| `UsePokemonPower` で写した［すいりょくはつでん］ | 未対応 | 未対応（変えない） |

## 2. 共通の確かめと判定の順

- 新しい関数 `effects.copied_attack_power_check(state, user, slot)` は `copied_declared_power_problem` を呼び、止めるなら `UnsupportedError` を投げるだけです（カード名・ランターン・アンノーンの例外はない）。
  写した力でない（自分のカードの力・変身していない持ち主の力・`slot.card` が今の姿のカードでない）なら何もしません。変身していることだけでは拒否しません。
- `attack_power_check`（使い手自身の力）: 特殊状態（ねむり・マヒ・こんらん）→ 力が消える（`power_suppressed`）→ 使えない効果（`powers_use_prevented`）→ **写した力（新）** → 数え方
  （RB1・BZ2・MEC1・CE1・CE2・TE1 の型）。
- `group_attack_power_check`（持ち主ごと。使い手自身でも別の持ち主でも同じ）: 持ち主が場にいる → 力がある → 使い手とワザの条件（`usable_for`）→ 力が消える → 使えない効果 → **写した力（新）** →
  この番の使用の記録（`other_use_problem`）。`with_powers` は並びの順に 1 つずつ確かめるので、写した力を含む並びは順によらず未対応です。
- `UsePokemonPower` との比べ: そちらは 消す効果 → 使えない効果 → 写した力 → 型ごとの確かめ（`check_usable`。特殊状態・回数を含む）の順です。今回、既存の確かめの順は変えていません。
  そのため次の 2 点だけが違います（どちらも拒否どうしで、受理・拒否は変わらない）:
  - こんらんのメタモンが写した［すいりょくはつでん］を選ぶと、0.193.0 でも既存の `POKEMON_CONFUSED`（`attack_power_check` の既存の順。`UsePokemonPower` なら未対応が先）。
  - 写した［すいりょくはつでん］で、数え方が決まらない（RB1 など）盤面は、0.192.0 の数え方の停止ではなく未対応になります（写した力の数え方には着かない。SF2 と同じ理由）。
- 既存の不正入力・能力無効化の優先は変えていません（`POWER_USE_PREVENTED` が先: テストの `injected`）。

## 3. 入力 API

- おもての使い手のワザの候補（`_attack_candidate`）は、2 段目の組ごとに、同じ構造の確かめ（`_copied_addon` → `copied_declared_power_problem`。今の姿・力の供給元のカード・型だけ。
  エンジンを試さない）が止める写した力を示しません。組を作らず、番号は欠番のまま（ゲーム上できない組と同じ扱い）です。送ると `check` は `CANDIDATE_INPUT_INVALID`（示していない番号）です。
  - おもてのメタモンが写したランターン・アンノーンX・A: 2 段目は空（0.192.0 は `attack_power`・自身の `with_power` を may_stop_later で示した）。
  - 写したアンノーンX のメタモン ＋ ベンチのアンノーンA: 0.192.0 の `o2`（自身の［XXXXX］）は欠番、`o3`（ベンチの［ANGER］）は同じ番号で示し、送信は直接のコマンドと同じ結果。
  - 本来のランターン・アンノーンの 2 段目は 0.192.0 と同じ。
- ほかの選択肢（コイン・［めいれい］・写していない持ち主）は巻き込みません。GUI にカード別の除外は要りません（候補が示さない）。
- 保証の文 `GUARANTEE_ATTACK`（0.179.0 からの固定値）は変えていません。示す組は今も `check_use_attack` で確かめ、示さない組はそれが止める組の一部です。
  U7-4 の「止める組み合わせは `CANDIDATE_NOT_EXECUTABLE`」に対して、未検証の写した力だけは示さない（未提示の番号として `CANDIDATE_INPUT_INVALID`）という例外です。
  - 追記（2026-11-18、C-TF2）: この例外と U7-4 の文書・`GUARANTEE_ATTACK` の整合を確かめ、U7-4 の文書の訂正候補 AC-1〜3 を記録しました（API・定数は変えない）: [C-TF2 の修正設計](r2-transform-frozen-reveal-design.md)（2.2 節）
  `UsePokemonPower` の候補（写した力は実行できない候補で示す）は変えていません。
- うらのメタモンのワザの候補は今の `no_printed_attack`（not_implemented・段なし）の保留のままです。変身のあとのワザ・2 段目は示しません。うらの使い手の 2 段目が読むのはベンチの持ち主だけで、
  ベンチのポケモンは写した姿を持たない（化石のメタモンはバトル場でだけ変身し、［すごいへんしん］はバトル場をはなれるともどる。v0.124 の 5 章・v0.125 のテスト）ので、その分岐は変えていません（静的な確かめ）。
