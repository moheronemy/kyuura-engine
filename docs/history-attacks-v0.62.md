## 2. 履歴の設計

### 2.1 3 種類の記録を分ける

前の番のことを読むワザは、読むものが違います。1 つの「直前のワザ」にまとめず、場のポケモンの `PokemonInPlay.history`（frozen の値のタプル。`kyuura_engine/history.py`）に
3 種類を分けて持ちます。

| 記録 | 型 | 内容 | 作る時点 | 読むワザ |
|---|---|---|---|---|
| A: 自分の前の番に使ったワザ | `AttackUsed(turn, card, declared, processed)` | 宣言したワザ（`declared`）と、相手のワザ・受けたワザを自分のワザとして使ったときに処理したワザ（`processed`） | ワザの宣言（p.309 の手順 3。`resolution.flow._attack_body`）。切りかえたら `processed`（`programs.apply_redirect`） | ドリルホール |
| B: 相手の前の番に受けたワザ | `AttackReceived(turn, card, player, source, declared, processed, …)` の前半 | 受けた相手のワザ（宣言したワザ・処理したワザ・ワザを使ったポケモン） | 解決の基盤のダメージの要素（`kernel.deal_damage`）・効果の要素（`kernel.reaches`）が、このポケモンを対象にしたとき | ピジョンのオウムがえし |
| C: 実際に受けたダメージと効果 | 同じ記録の後半 `damage`・`reached`・`voided` | 受けた最終ダメージの合計・受けた要素の種類（`damage`・`paralysis` など）・受けなかった要素と理由 | 同上（最終ダメージ・受けたかが決まったとき） | オニスズメのオウムがえし |
| ワザ以外で受けたこと | `OtherReceived(turn, card)` | 相手の番に、相手のワザ以外（トレーナー・特殊能力など）でダメージ・効果を受けた | コマンドの前後の比べ（2.3） | オニスズメのオウムがえし（OM2） |

B と C は同じ記録の値ですが、読むワザが別の値を読みます（ピジョンは B の `processed` だけ、オニスズメは C の `damage`・`reached` だけ）。受けなかった要素の理由
（`voided`）は `attack_barrier`（「ワザをうけない」）・`damage_only`（「ダメージを受けない」状態・見えない壁）・`evaded`（「とうめい」）・`dodged`（かげぶんしん）・
`immune`（［めんえき］で特殊状態にならなかった）です。

記録は状態の正本です。ログ・過去のコマンドを読み直して作らず、今の盤面から逆算しません。過去のカードの uid（`card`）は「このカード」の確かめ（2.4）にだけ使い、新しい
対象として使いません。

### 2.2 記録する範囲と、記録しない場合

- 履歴を読むワザ（効果の登録の `AttackEffect.reads_history`）を持つカードが対戦のカードの定義にあるときだけ記録します（`history.history_needed`。状態に持たず、カードの
  定義と効果の登録表から求める）。ないときの状態・書き出し・ログは v0.61 と同じです（固定した参照データ・前の版との比べが変わらない）。
- B・C は、番のプレイヤーのワザの要素が、相手の場のポケモンを対象にしたときだけです。相手のワザの自分へのダメージ・相手が自分の控えに与える効果（受けるポケモンの持ち主が
  ワザを使ったプレイヤー）・返す効果のダメージ（番のプレイヤーのポケモンが受ける）は記録しません。1 つの番に受ける相手のワザは 1 つです（違うワザの記録が同じ番に 2 つ
  できたら RuntimeError）。
- 先読み（宣言の前に状態の複製の上で試す処理）・拒否された宣言（エネルギー不足・使うための条件・`UNRESOLVED_…`）は返す状態を変えないので、記録も残りません。

### 2.3 ワザ以外で受けたこと

`engine._apply` が、番のプレイヤーのワザ（`UseAttack`）・番の終わり（`EndTurn`）・ワザの途中の決定への答え（解決の基盤の再開先 `codec.RESUMES`）以外のコマンドの前に、
番でないプレイヤーの場のポケモンの状態（場所・重なり・のせたカード・ダメージ・特殊状態・エネルギー・ついているトレーナー・持続する効果・［へんしょく］の記録）を写し
（`history.open_probe`）、コマンドのあとに比べます（`close_probe`）。変わったポケモンに `OtherReceived` を記録します。番の終わり（`flow._end_turn`）は、番を終える前に
比べを閉じます。ポケモンチェック（どく。p.323。どちらの番でもない）・番の最初は相手の番のことではないので、比べません。写しは状態の一時的な値で、書き出し・比べに
含めません（比べの前に番が変わったら RuntimeError）。

### 2.4 「このカード」・消える時点

| 場面 | 記録 | 根拠 |
|---|---|---|
| にげる・ポケモンいれかえ・ワザの入れ替えでベンチにもどる・バトル場にもどる | 残る（場のポケモンの番号が同じ・使った/受けたことは変わらない） | 実装上の判断（説明は場所を書かない） |
| 進化・退化 | 消す（`history.clear_history`。`evolution.place_evolution_card`・`devolve`） | p.310「進化前のポケモンとは別のポケモン」（kyuura の GR-2000-P310-EVOLUTION・GR-2000-P324-DEVOLUTION） |
| 場をはなれる（きぜつ・手札・山札・トラッシュ） | 場のポケモンとともになくなる。出し直したポケモンは新しい番号で、記録はない | 場のポケモンの番号の規則（v0.2a） |
| ［へんしん］のメタモン・「ばける」のタケシのキュウコン | 残る（今の姿が変わっても、実際のカード・番号は同じ。記録は場のポケモンのもの） | 実装上の判断（v0.49 の今の姿と実際のカードの区別） |
| 番の最初 | 2 つ前の番より古い記録を消す（`history.prune`。`procedures.begin_turn`） | 読むのは 1 つ前・2 つ前の番だけ |

読むときは、記録のカードの uid が今のいちばん上のカードと同じで、記録の番が今の姿になった番（`current_form_turn`）より前でないことも確かめます（`history._this_card`）。
進化・退化で消しているので二重の確かめで、不変条件（`engine._history_problems`。型・番の範囲・カード・同じ番の記録の数・受けなかった理由）も確かめます。

### 2.5 消費

「「オウムがえし」の効果は1回で消える」は、記録を使ったら消す、という状態を要りません。読むのは前の相手の番の記録だけで、ワザは番に 1 回なので、同じ記録を 2 回読むことは
ありません。次の自分の番には、その記録はもう「前の相手の番」の記録ではありません。この文の意味（受けた効果を 1 度だけ与えるのか、与えた効果が 1 回で消えるのか）が
処理に影響する場合は OM1 で止めます（5 章）。

## 3. タケシのダグトリオ「ドリルホール」（記録 A）

- 「このワザは、このカードが、前の自分の番に「あながくれ」を使っていた時だけ、使える。」: 今の番の 2 つ前の番（番は交互に進む）の記録 A で、宣言したワザが同じカードの
  位置 0・名前「あながくれ」なら使えます（`effects.used_attack_last_turn`）。前の相手の番のこと・場に出てから 1 度だけ使えるワザの記録・ログでは決めません。
- 使えないなら、ワザを使うための条件（`usage_problem`。必要なエネルギーの確認のあと・こんらんのコインの前）の `IllegalActionError("PREVIOUS_ATTACK_NOT_USED")` で、状態・乱数・
  ログは変わりません。
- 「あながくれ」の宣言が失敗した（手順 4 のコインの「うら」・こんらんの「うら」）ときも使ったことになります（宣言のときに記録する。v0.44 の 1 度だけ使えるワザと同じ時点。
  p.323「12」・v0.3d の A12 の記録の再利用）。
- 「あながくれ」は化石の秘密のベトベターの「ちいさくなる」と同じ意味の `ReduceDamageNextTurn(20)`（8 段階で −20）。型の `check` が受け付ける書き方に「次の相手の番、
  このカードが受けるダメージは「-20」される。(ダメージ以外の効果はそのまま)」を加えました（意味が同じと確かめた書き方だけ。v0.37 の方針）。
- ほかのワザで「あながくれ」を自分のワザとして使った記録（宣言したワザが違い、処理したワザが「あながくれ」）が「使っていた」に当たるかは決まりません（ED1）。このワザを
  自分のワザとして持つポケモン（タケシのダグトリオ・［へんしん］のメタモン・「ばける」のタケシのキュウコン）は「あながくれ」も持つので、今の写しでは起こりません（コードの
  ない問い。起こったら宣言の前に止める）。
- 「ゆびをふる」などでドリルホールを自分のワザとして使うときは、まねたポケモンの記録 A で答えます（`UsedAttackCondition.copy_problem`。条件をみたさなければ、説明にしたがう
  ピッピ・使えないとするピクシーでは選べず、条件を書かないカスミのコダックでは HC9）。

## 4. ピジョン「オウムがえし」（記録 B。同じワザを出す）

- 「前の相手の番で受けた「ワザ」と同じ「ワザ」をだす。」: 前の番の記録 B の処理したワザ（`processed`）の要素の並びに切りかえ、このワザの枠の中で、ワザを使ったポケモン
  （ピジョン）のワザとして処理します（`programs.RepeatReceivedAttack`。v0.31 の「ゆびをふる」と同じ `run.redirect`）。弱点・抵抗力・「このカード」はピジョン、コイン・選ぶものは
  新しく決めます。前の結果（ダメージ・コインの面）を使いません。今の相手の対戦ポケモンのワザから選び直しません。ログは `copy_attack`（`received_turn` に受けた番）。
- 出したワザのふきとばし（相手が選ぶ）は、相手が選ぶ決定のままです（`RepeatReceivedAttack.decision_problems` が、決定の `context` の `copied` のワザの宣言に委ねる）。
- 受けた記録がない・どの要素も受けなかった（理由がどれも「ワザをうけない」・「とうめい」）: 何もしません（p.309。ログ `mirror_move_none` の `reason` `no_attack`・`not_received`）。
- ダメージの要素だけを受けなかった（「ダメージを受けない」状態・見えない壁・かげぶんしん）・受けたワザが相手のワザを自分のワザとして使ったもの（宣言したワザと処理したワザが
  違う）: 受けた「ワザ」が決まらない（MM1）。
- 出すワザに必要なエネルギー・説明が書く使うための条件をみたす必要があるかは説明が書きません（「ゆびをふる」の「必要なエネルギーがついていなくても、かまわない」がない）。
  ピジョンのエネルギーで払え、条件もみたすなら、どちらの読み方でも同じなので処理し、そうでなければ MM2 で止めます。
- 出すワザが場に出てから 1 度だけ使えるワザ・要素の並びのないワザ（v0.13 の約束の実装）: エンジンの未対応（`UNSUPPORTED_MIRROR_MOVE_ATTACK`）。オウムがえしをさらに自分の
  ワザとして使う（「ゆびをふる」でオウムがえしを選ぶ）: `UNRESOLVED`（HC9 と同じ扱い。`copy_problem`）。
- 受けたワザがオニスズメのオウムがえし（宣言したワザと処理したワザが同じ）なら、それを出します。出したオニスズメのオウムがえしの「このカード」はピジョンなので、ピジョンが
  前の相手の番に受けた記録（そのオウムがえしで受けたダメージ）を与えます（実装上の読み方。対戦で 3 回（2 局）起こった。10.2）。

## 5. オニスズメ「オウムがえし」（記録 C。受けた結果を与える）

- 「前の相手の番に、このカードが受けたダメージと効果を【相手】に与える。「オウムがえし」の効果は1回で消える。」: ピジョンとは違い、ワザを出し直しません。受けた記録の C
  （最終ダメージの合計と受けた効果の種類）を与えます（`programs.ReflectCheck` → `ReflectedDamage` → `ReflectedParalysis`）。
- ダメージ: 受けた最終ダメージ（p.321 の 1〜7 段階のあと）の合計を、このワザの基本となるダメージ（1 段階）にして、このワザのダメージとして p.321 の計算をします（弱点・
  抵抗力はオニスズメのタイプと今の相手で計算し、「ダメージを受けない」状態・「とうめい」なども評価する）。受けたダメージの数をそのまま相手にのせる・ダメージカウンターを
  移す処理にしません。「こうらがえし」（p.89 の「100 ダメージを受けたらそのまま 100」。受けたダメージを返すワザのダメージとして計算する。kyuura の GR-2000-P321-ATTACK-DAMAGE）
  と同じ読み方です。受けた最終ダメージが 0 なら、ダメージの要素はありません。
- 効果は種類ごとに分けます（`effects.REFLECTABLE_RECEIVED_ELEMENTS`・`LASTING_RECEIVED_ELEMENTS`）:
  - マヒ: 与えます（ほかのマヒを与える要素と同じ `Status`。「とうめい」・「ワザをうけない」・［めんえき］・マヒの再付与・HP 以上の相手を評価する）。マヒは持ち主の次の番の
    あとで回復するので、「1回で消える」の読み方で結果が変わりません。
  - 続く効果（ねむり・こんらん・どく・持続する効果）: 「1回で消える」の読み方（受けたものを 1 度だけ与えるのか・与えた効果が 1 回で消えるのか）で与えたあとが変わる
    ので、OM1 で止めます。
  - ほかの効果（入れ替え・エネルギー・ダメージカウンター・回復など）: 与えるのはエンジンの未対応（`UNSUPPORTED_MIRROR_MOVE_EFFECT`。ルールの問いではない）。
- 前の相手の番にワザ以外でダメージ・効果を受けていた（`OtherReceived`。バトル場は穴だらけ!・のろいなど）: 「受けたダメージと効果」に含むかが決まらないので OM2 で止めます。
- 受けた記録がない・どの要素も受けなかった: 何もしません（ログ `mirror_move_none`）。与えるものが決まったら、ログ `reflect_received`（受けた番・受けたワザ・受けた最終
  ダメージ・効果の種類）。
- ピジョンとの違い: ピジョンは受けた「ワザ」（B）を新しく出す（コイン・計算・選ぶものを新しく決める）、オニスズメは受けた「結果」（C）を与える（受けた最終ダメージを
  基本のダメージにし、受けた効果の種類を与える）。1 つの処理・1 つの記録の値にまとめていません（tests の `RepeatReceivedTest`・`ReflectReceivedTest` が、同じ盤面で
  違う結果になることを確かめる）。

## 6. ピジョット「ハリケーン」（相手を手札にもどす）

- 「相手の対戦ポケモンが「きぜつ」しなければ、そのカードにのっていたダメージカウンターをとりのぞき、そのカードとついていた全てのカードを持ち主の手札にもどす。」:
  ダメージ（30）→ 要素 `programs.ReturnOpponentToHand` → v0.42 の `zones.return_in_play_to_hand`（重なったカード・「ばける」でのせたカード・エネルギー・トレーナーを持ち主の
  手札に。ダメージカウンター・特殊状態はなくなる）→ 持続する効果を消す（理由 `return_in_play_to_hand`）。手札にもどす処理を新しく作っていません。
- 「きぜつ」しないかは、このワザのダメージのあと（HP 以上なら処理しない。きぜつの処理はワザのあと）。ダメージを受けなかった（「ダメージを受けない」状態・最終ダメージ 0）
  ときも「きぜつ」しないのでもどします（「ダメージを与えた後」の条件ではない。Z23 は当たらない）。
- 相手への効果なので「ワザをうけない」状態・「とうめい」を評価します（受けないならもどさない）。
- こんじょうを使える相手が HP 以上になる場合は G37（`UNRESOLVED_KO_PREVENTION_ATTACK_EFFECT`。`opponent_effect_elements` で宣言）、同じワザで HP 以上になるポケモン（はんげき・
  ほのおのかべで返されたピジョット）がいる場合は RD9（`UNRESOLVED_RETURN_IN_PLAY_TO_DECK_KNOCKOUT`。v0.36・v0.44 と同じ問い）、残り HP 10 の［ずらかる］とワザの残りの
  要素の順番は SC1（`UNRESOLVED_SCRAM_TIMING`。v0.61）で、どれも宣言の前に止めます（新しいコードにしていない）。
- きぜつではありません（サイドは取らない）。空いたバトル場は、ワザのあとの既存の勝ち負けの判定・バトル場に出す決定でうめます（相手に控えがいなければ負け。p.311）。

## 9. 書き出し・API・ログ・観測への影響

- 書き出しの形式 20 = 形式 19 + 場のポケモンの `history`（記録の種類 `used`・`received`・`other` と値。`serialize.history_record`）。形式 1〜19 は、記録があると
  `ValueError`（黙って落とさない）。記録のない状態は形式 1〜19 で今までどおり書き出せます（履歴を読むカードのない対戦は記録を作らない）。監査の `LATEST_FORMAT` は 20、
  次の新しい形式は 21。
- 公開の API の呼び方・コマンド・決定の種類は変えていません。新しい拒否のコードは `PREVIOUS_ATTACK_NOT_USED`。
- 新しいログのイベント（公開）は `mirror_move_none`・`reflect_received`。`copy_attack` に `received_turn`（ピジョンのオウムがえしのときだけ）。
- 観測（`observe`）の場のポケモンに `history`（書き出しと同じ形）。使ったワザ・受けたワザと結果は、両方のプレイヤーが見た公開の情報なので、全員に見せます（隠れた情報を
  含まない。ワザ以外で受けたことも、見えるコマンドの結果）。
- ログの監査（tests/log_audit.py）は、ハリケーンで手札にもどしたポケモン（ワザのダメージの要素のあと・相手の対戦ポケモン）を確かめます。
