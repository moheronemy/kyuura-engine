## 2. 状態の設計: 場所・見える範囲・決まった選択と期限を分ける

### 2.1 一時的に置いておくカード（`GameState.set_aside`）

手札・山札・ベンチ・トラッシュ・サイドのどれでもないカードの置き場所を、`state.SetAsideCards`（frozen）の並びで持ちます。

| 項目 | 意味 |
|---|---|
| `kind` | 置き場所の種類（物理的な場所の名前）: `hand_set_aside`（くすぐりマシーン）・`face_down_bench`（挑戦状のうらのベンチ）・`quiz_card`（クイズで伏せたカード） |
| `owner` | カードの持ち主（置いたカードはいつも持ち主のもの） |
| `cards` | 置いたカード（同じ uid。複製しない。置いた順） |
| `visible_to` | 中身を見られるプレイヤー（くすぐりマシーンは `()` = だれも見ない（持ち主も）。挑戦状・クイズは持ち主だけ） |
| `user`・`trainer_card`・`card_id` | 置いたトレーナーを使ったプレイヤー・そのカードの uid と id（出どころ） |
| `created_turn`・`return_turn` | 置いた番・もどす番（期限のある置き場所だけ。くすぐりマシーンは「次の相手の番」） |

- 置き場所と見える範囲を分けました: 手札に「使えない」「見えない」印を付けて残す・ベンチのポケモンにうらの印を付ける形にしていません（手札の枚数・手札をすべて動かす効果・
  ［おみとおし］・スパイ作戦・使うための条件・ベンチの数え方が、印を知らずに数えてしまうため）。置いたカードは手札・ベンチのどれとも混ぜません。
- 決まった選択（クイズで伏せたカード・伝えたワザ）は、置き場所と決定の続きの情報（`context`）に持ち、答えの前に決まります。期限（`return_turn`）は置き場所に持ちます。
- 動かすのは `zones.set_aside_hand`・`set_aside_face_down_bench`・`reveal_face_down_bench`・`set_aside_quiz_card`・`return_set_aside`・`return_expired_set_aside` だけです。期限のもどしは
  番の終わりの窓（`procedures.expire_at_turn_end` の最初。ログ `turn_end` の前）で行います（v0.56 の期限のある効果と同じ置き方）。
- 不変条件（`engine._set_aside_problems`）: カードの保存則（置いたカードを含めて 60 枚ずつ。使用中・外側の使用も含む）・持ち主・重なりなし・種類ごとの見える範囲・出どころの
  トレーナー・もどす番（くすぐりマシーンは置いた番より後の、持ち主の最初の番）。対戦が終わった状態では、挑戦状・クイズの置き場所は残りません（トレーナーの途中で対戦は
  終わらない）。くすぐりマシーンの置き場所は、対戦が先に終わったら置いたまま残ります（番の終わりが来ない。4 章）。

### 2.2 おもてのサイド（`GameState.face_up_prizes`）

- サイドのカードをカードごと（uid）に記録します。プレイヤーごとの「サイドはすべておもて」の印にしていません（あとからサイドに置かれたカード（わるふざけ・カスミのわがままで
  入れかえたカード）は、おもてにする指示がないので裏のまま）。
- カードがサイドをはなれたら、記録から除きます（`zones.prize_left`。サイドを取る・トレーナーで取る・入れかえる）。手札に来ても手札は公開になりません。取った・入れかえたログには
  おもてだったことを書き（項目 `face_up`。7 章）、観測はその項目だけを全員に見せます。
- 不変条件（`engine._face_up_prize_problems`）: 記録のカードはどれもサイドにある・重なりなし。

## 3. ロケット団参上!（PMCG4-062）

印刷の文面: 「お互いのプレイヤーのサイドカード全てをおもてにして、お互いのプレイヤーに見えるようにする。(おもてになったサイドカードは、対戦が終わるまでそのまま)」

順番と根拠:

1. 使ったプレイヤー → 相手プレイヤーの順に、そのときサイドにあるカードをすべておもてにする（`zones.reveal_prizes`。ログ `prizes_revealed` は公開。位置とカード）。順番は実装上の
   順番で、結果は変わらない。
2. おもてにした範囲は使ったときのサイドだけ（2.2）。「対戦が終わるまでそのまま」は、おもてにしたカードがサイドにあるあいだ裏にもどさないこと、と読みます（実装上の読み方。
   英語版の「for the rest of the game」で、あとから置いたカードまでおもてにしない）。
3. もう一度使えば、そのときの裏のカードがおもてになります（再利用）。サイドが 0 枚のプレイヤーは何もしない（対戦中には起こらない）。
4. 「お互い」なので、使ったプレイヤー・持ち主・番のプレイヤーによりません。錯乱ジムで相手が使っても同じです（`refers_to_user_turn` ではない）。

おもてにしたあと: サイドを取る決定（`take_prize`）・わるふざけ（`select_prize_card`）の選べるもの（サイドの位置）に、おもての位置だけカードの id を添えます（観測。7 章）。
マチスの交渉・カスミのわがまま・わるふざけの処理は変えていません（取った・入れかえたカードがおもてだったことをログに書くだけ）。

## 4. くすぐりマシーン（PMCG6-084）

印刷の文面: 「コインを投げて「おもて」なら、次の相手の番の終わりまで、相手プレイヤーは、いま手札として持っているカードをすべて、うらにして置いておく。置いたカードは、相手
プレイヤーの手札とはみなされない。(相手プレイヤーは、それらのカードを見ることも、使うこともできない)。コインが「うら」なら、あなたの番は終わりになる。」（kyuura の種類
`rockets_secret_machine`。v0.53 の `secret_machine_ok` で受け付ける）

1. 使ったプレイヤーがコインを 1 枚投げる（`source="trainer"`）。
2. 「おもて」: 使ったプレイヤーの相手の手札をすべて、手札とは別の置き場所（`hand_set_aside`。だれも見ない）に移す（`zones.set_aside_hand`。ログ `set_aside_hand` の `cards` はだれにも
   見せない。枚数は公開）。もどす番 `return_turn` は、今の番より後の、相手プレイヤーの最初の番（`next_turn_of`）。手札が 0 枚なら置くカードはなく、置き場所を作りません。
3. 置いたあとに引いたカードはふつうの手札です。手札の枚数・手札をすべて動かす効果・手札を見る効果・使うための条件は、置いたカードを数えません（「手札とはみなされない」）。
4. 次の相手の番の終わり（番の終わりの窓）に、同じカードを置いた順に持ち主の手札にもどします（ログ `set_aside_returned` の `reason` `expired`。`cards` は持ち主だけ）。
5. くり返し使えば、そのときの手札を別のまとまりとして置きます（出どころ・もどす番をそれぞれ持つ）。
6. 対戦が先に終わったら、置いたまま残ります（番の終わりが来ない。勝敗はふつうの規定のまま。山札・手札の枚数で負けを判定する規定に、置いたカードを数えない）。
7. 「うら」: `END_TURN` を返し、エンジンが使用中のカード（サイキックコントロールの外側のカードも）をトラッシュしてから番の終わりに進みます（v0.56 のロケット団員と同じ）。
8. 説明が使ったプレイヤーの番（「次の相手の番」「あなたの番は終わり」）を書くので、錯乱ジムで相手が使うことを選ぶと CH1（v0.57。`refers_to_user_turn = True`）。
   サイキックコントロールで使うときは、使ったプレイヤー（`using_player`）の相手の手札を置き、「うら」で終わるのは使ったプレイヤーの番です（8.1）。

## 5. たたきつけろ!挑戦状（PMCG4-058）

印刷の文面: 「あなたの挑戦を受けるかどうか、相手プレイヤーにたずねる。相手が挑戦を受けないなら、あなたは山札からカードを2枚引く。相手が挑戦を受けるのなら、お互いのプレイヤーは、
それぞれの山札から好きなだけポケモンカード(進化カード以外)を選び出し、ベンチに出す。(お互いが出し終わるまで、ポケモンはうらにしておく)。その後、それぞれの山札をよく切る。」

1. 相手プレイヤーにたずねる（v0.56 の `ACCEPT_REQUEST`。決めるのは相手。答えはログ `request_answered`）。
2. 受けない: 使ったプレイヤーが 2 枚引く（効果で引く。山札が足りなければ引けるだけ。p.312 の記録の再利用）。英語版の「(or if both Benches are full)」は持ち込まない。
3. 受ける: 使ったプレイヤー → 相手プレイヤーの順に、自分の山札のたねポケモンのカード（山札にある間の印刷の定義。なにかの化石・ピッピ人形は山札ではトレーナーカードなので入らない）
   から、0〜min(ベンチの空き, 選べる枚数) 枚を選ぶ（決定 `challenge_bench`。山札を見るのは選ぶプレイヤーだけ）。ベンチの空きは `stadiums.bench_limit`（せまいジムの 4 匹を含む）。
   選んだカードはうらにして置く（`face_down_bench`。場のポケモンにはしない）。順番は実装上の順番で、あとで選ぶプレイヤーは先のプレイヤーのカードを見ません（うら）。
   選べるカードがない・ベンチに空きがないプレイヤーは選ばずに次へ進みます（ログ `challenge_bench_skipped`。理由は選ぶプレイヤーだけが見る。「好きなだけ」なので止めない）。
4. 選べるカードがあるのに 0 枚を選ぶのは、v0.31 の HC5（`UNRESOLVED_DISCARD_ANY_NUMBER_ZERO`。「のぞむなら」のない「好きなだけ」）と同じ問いなので、そのコードで止めます
   （決定は待ったまま）。新しい問いを作っていません。
5. お互いが出し終わったら、使ったプレイヤー → 相手プレイヤーの順に、置いた順に表にして場に出します（`zones.reveal_face_down_bench`。`enter_play`。今の番に場に出たので、その番は
   進化できない）。そのあと、それぞれの山札を切ります（選ばなかったプレイヤーの山札も切る）。
6. まきちらせ!ベトベトガスの効果のはたらく間に、特殊能力を持つたねポケモンを場に出すのは v0.59 の GG1（`UNRESOLVED_GOOP_GAS_NEW_POKEMON`）。選べるが選ぶと止める選択
   （`unresolved_choices`）にし、選べるものがどれもそうなら決定の前に止めます。場に出たときの特殊能力を持つたねポケモンは写しにありません（`placed_entry_power_guard`）。
7. 見える範囲: 選ぶ決定は、決めるプレイヤーでない人には種類と決めるプレイヤーだけを見せます（選ぶ数・選べる枚数は山札のたねポケモンの数を漏らすため。7 章）。うらのカードは
   持ち主だけが見て、枚数は公開です（ベンチにうらのカードを何枚置いたかは見える）。

## 6. カツラのクイズ その3（PMCG6-082）

印刷の文面: 「あなたの手札から「ポケモン」のカードを1枚選び、おもてを下にして、置く。そのカードが持っているワザの名前を1つ、相手プレイヤーに伝え、そのカードの名前を答えて
もらう。その後、置いたカードをおもてにして、正解なら、相手プレイヤーは山札からカードを3枚引く。正解でないなら、あなたは山札からカードを3枚引く。(置いたカードは、手札にもどす)」

1. 使ったプレイヤーが手札のポケモンのカード（ワザを持つもの）を 1 枚選び、伏せて置く（決定 `quiz_card`。`quiz_card` の置き場所。置いたカードは手札ではなく、使ったプレイヤーだけが
   見る）。ワザを持たないポケモンのカード（メタモン PMCG3-042）は、伝えるワザの名前がないので選べません。手札のなにかの化石・ピッピ人形はトレーナーカードです。
2. 置いたカードのワザから 1 つ選び、その名前だけを相手に伝える（決定 `quiz_attack`。ログ `quiz_hint` は名前だけ。カードの id・収録・HP・段階は伝えない）。
3. 相手プレイヤーがカードの名前を答える（決定 `quiz_answer`。決めるのは相手）。答えの候補は、同梱のカードのデータとこの対戦のカードの定義のポケモンの名前（重ねず、文字の順）で、
   置いたカード・手札・山札によりません（候補から置いたカードを推測できない）。候補にない値の答えは不正な操作（`INVALID_CHOICE`。決定は待ったまま・状態・乱数・ログは変わらない）
   で、正解でない答えとは別です。
4. 置いたカードをおもてにする（ログ `quiz_answer`・`quiz_reveal`。正解かを書く）。正解は、答えの名前が置いたカードの名前と同じこと（同じ名前の別の収録のカードも正解。
   「わるい」「○○の」の付いた名前は別の名前）。
5. 正解なら相手プレイヤーが、正解でないなら使ったプレイヤーが 3 枚引く（効果で引く。山札が足りなければ引けるだけ）。
6. 置いたカードを手札にもどす（ログ `set_aside_returned` の `reason` `quiz`。表にしたので `face_up` で全員に見せる）。順番は説明の文の順（おもてにする → 引く → もどす）。
7. 置いたカードと伝えたワザは答えの前に決まり、あとで入れかえません（置き場所と続きの情報）。決定をまたぐ保存と復元で保たれます。

QZ1（新規。`UNRESOLVED_BLAINES_QUIZ_WITHOUT_POKEMON`）: 手札にワザを持つポケモンのカードがないとき。説明は選べるカードがないときに使えるか（何も起こらずに使い終わるか・使え
ないか）を書いていないので、使う前に止めます。ほかのカードの「対象がない」ときの問い（ST1・RV1・TR1 など）の答えを当てはめていません。

## 7. 書き出し・API・ログ・観測への影響

- 書き出しの形式 21 = 形式 20 + 最上位の `set_aside`（置き場所。カードの id も書く）・`face_up_prizes`。形式 1〜20 は、置き場所かおもてのサイドがあると `ValueError`（黙って
  落とさない）。どちらもない状態は形式 20 以下で今までと同じに書き出します。監査の `LATEST_FORMAT` は 21。次の新しい形式は 22。
- 公開の API の呼び方・コマンド・拒否のコードは変えていません。新しい決定の種類は `challenge_bench`・`quiz_card`・`quiz_attack`・`quiz_answer`。
- 新しいログのイベント: 公開 `prizes_revealed`・`face_down_revealed`・`quiz_hint`・`quiz_answer`・`quiz_reveal`、非公開の項目のあるもの `set_aside_hand`（`cards` はだれにも
  見せない）・`set_aside_returned`（`cards` は持ち主だけ。クイズは `face_up`）・`face_down_bench`（`cards` は持ち主だけ）・`challenge_bench_skipped`（`reason` は選ぶプレイヤー
  だけ）・`quiz_card_set`（`card` は置いたプレイヤーだけ）。
- ログの項目 `face_up`（イベントのうち全員に見えていた項目の名前の並び）: `take_prize`・`trainer_take_prize`・`swap_prize_with_hand`（手札に来たカード）・`set_aside_returned`
  （クイズ）。わるふざけの `swap_prize_with_deck_top` は、入れかえたサイドがおもてだったときだけ `face_up_card`。観測（`visible_log`）は `face_up` の項目を全員に見せます。
- 観測（`observe`）: プレイヤーごとに `prizes.face_up`（おもてのサイドの位置とカード）・`set_aside`（種類・枚数・出どころ・もどす番は全員、カードは見られるプレイヤーにだけ）。
  サイドの位置を選ぶ決定のおもての位置にカードの id、`quiz_attack` の選べるもの（決めるプレイヤー）にワザの名前、`quiz_answer` に伝えたワザの名前（全員）と候補の名前を添えます。
  `challenge_bench`・`quiz_card`・`quiz_attack` は、決めるプレイヤーでない人には種類と決めるプレイヤーだけ（選ぶ数・選べるものの数・uid を見せない。`HIDDEN_COUNT_KINDS`）。
- 区別できないことのテスト（tests/test_hidden_card_trainers_v0_63.py）: 置いた手札の中身だけが違う 2 つの盤面・挑戦状で選んだカードだけが違う 2 つの盤面（表にする前）・クイズで
  同じワザの名前の別のカード（ロコンとフーディンの「あやしいひかり」。たねポケモンと 2 進化）を置いた 2 つの盤面（答えの前）は、相手・観戦者の観測とログで同じです（uid を除いて
  比べる。uid は置き場所の外の情報なので観測にない）。

## 8. 既存の共通の処理の変更

### 8.1 番を終えるトレーナーの、番を終えるプレイヤー（不具合の修正）

`engine._finish_trainer` は、番を終えるトレーナー（`may_end_turn`）の使用のあと、v0.62 まで `resolution.end_turn_after_trainer` に使用の記録の `player`（カードの持ち主）を
渡していました。サイキックコントロール（v0.58）で相手のトラッシュから使ったロケット団員（v0.56）の「うら」で、カードの持ち主（相手）の番を終えようとして `NOT_YOUR_TURN` で
拒否されていました（v0.62 の木でも起こる。v0.62 までの対戦の組では起こらなかった）。v0.63 から、使ったプレイヤー（`using_player`）を渡します。くすぐりマシーンも同じ
経路を通ります。回帰のテストは `TicklingMachineTest.test_rocket_grunt_through_psychic_control_ends_the_users_turn`。

### 8.2 決定の答えを全部作らずに数える

トレーナーの効果の途中で受け付けられる答えがあるかの確かめ（`engine._trainer_dead_end`・`_decision_has_unstopped_answer`）は、答えをすべて並べてから数えていました。クイズの答えの
決定（候補 307 の名前）・挑戦状の選ぶ決定（山札のたねポケモンから好きなだけ）で数が大きくなるので、答えを順に作る `resolution.programs.iter_answers` と、数だけを求める
`answer_count`（`math.perm`）を加え、`all_answers` は `list(iter_answers(...))` にしました。答えの並びと上限（256）は変えていないので、受け付ける答えは v0.62 と同じです（10.3）。
