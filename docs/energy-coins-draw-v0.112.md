# v0.112: 水エネルギーの個数によるコインとドローの 2 枚

v0.112 は、ドククラゲ（SI-016）・オムスター（PR1-051）の 2 枚を、ワザ 4 とともに登録する版です。2 枚の「しょくしゅをつかう」は新しい型 `CoinsPerOwnTypedEnergyDraw(水, 2)`（型・登録の値を
共有）、どくばりは既存の `PoisonOnHeads`、ふしょくえきは新しい型 `DamageParalyzeOnHeadsElseLockSelf` です。

共通処理として、ワザ全体のコイン `programs.Coin` に、実際にワザを使ったポケモンの指定色のエネルギーの個数をコインの枚数にする項目 `per_own_typed`（数え方は既存の
`programs.typed_units_for`）を、山札から引く要素 `programs.Draw` に、名前付きのワザ全体のコインの「おもて」の数 × 係数を引く項目 `heads_of`・`per_heads` を加えました。既存の項目
（`Coin.count`・`per_attached`（指定色の基本エネルギーカードの枚数）・`per_opponent_energy`（相手のエネルギーの個数）、`Draw.count`・`gate`・`requires`）の意味と既定の動きは変えていません。
ふしょくえきは既存の要素（`Damage` → 共有の `Coin` → 「おもて」の `Status(PARALYSIS)` → 「うら」の `SelfAttackLock`）の組み合わせです。新しい停止コード・状態の項目はなく、写しの元と
研究の基準は v0.97 のまま（kyuura `73a1690`）、書き出しの形式は 26 のままです。

## 3. しょくしゅをつかう（水の個数 → コイン → ドロー）

### 3.1 型と要素

- 型 `CoinsPerOwnTypedEnergyDraw(energy_type, per_heads)`: 確かめ（`check`）は、ダメージの目安がないこと、全文が `OWN_TYPED_ENERGY_COINS_DRAW_TEXT`（「自分についている「{色}」エネルギーの数だけ
  コインを投げ、「おもて」の数×{per}枚のカードを、自分の山札から引く。」）と同じことです。色・係数を取り違えた登録、v0.37 の `DrawOnHeads(2)`（コイン 1 枚で決まった 2 枚）は受け付けません。
  「無色」・1 未満の係数は作れません。
- 要素は `Coin("coin", per_own_typed=水)` → `Draw(heads_of="coin", per_heads=2)` です。

### 3.2 数えるもの（個数とカードの枚数）

- N は、実際にワザを使ったポケモンの今の「水」エネルギーの個数です（`Coin.per_own_typed` → `programs.typed_units_for`。v0.89 の ``typed_energy_units`` と同じ数え方）。基本エネルギーカードの
  枚数（`Coin.per_attached`）・すべての色の個数・相手の個数（`per_opponent_energy`）・場全体の枚数（v0.111 の `field_energy_cards_of_type`）ではありません。
- 個数とカードの枚数が分かれる、確定した例: ［エナジーコンバーター］（v0.88）で「水」にした雷エネルギーカードは、「水」の基本エネルギーカードではないが「水」エネルギー 1 個として数えます
  （`test_counts_units_not_cards_other_colors_or_the_opponent`）。無色2個エネルギー・ほかの色・相手の「水」は数えません。
- 読み方で個数が変わるなら、既存の問いで止めます（`typed_units_for` の `transform_energy_question(cards=False)`: TE1・RB1・BZ2・MEC1・CE1・CE2）。例えばレインボーエネルギーは RB1。「草」でないので
  ［おいしげる］の「草」の問いは当てはめません（`test_color_questions_and_wild_growth`）。
- N = 0 ならコインを投げず 0 枚引きます（ワザの失敗にしない。必要なエネルギーの支払いは別に要る）。ゆびをふるなどで使うときも、実際に使ったポケモン（ピクシー）の「水」を数えます
  （`test_copied_grip_counts_the_actual_user`）。

### 3.3 コインとドロー

- N 枚はワザの説明のコイン（`AttackRun.flip`。`by_heads`。「おもて」の数だけを使う）で、すべて投げて確定してから、`Draw` が「おもて」の数 H × 2 枚を 1 回で引きます。引く枚数は山札の枚数まで
  （p.311・p.312。`draw_cards`。効果で引くので、番の始めに引けない負けにしない）。N = 3・H = 2 なら 4 枚、山札が 3 枚なら 3 枚。
- 山札が 0 枚・足りないときのコインの扱いは、既存のコインで引くワザ（v0.37 の `DrawOnHeads`）と同じです: `Draw` は処理の対象を持つ要素として扱われ（``has_target`` の既定）、コインは投げ、引ける
  だけ（0 枚なら 0 枚）引きます。今回だけの省略の規則は作っていません（旧カードも変えていない）。
- 自分への効果なので、`Draw` は相手の対戦ポケモンへの要素ではありません（`coin_receiver` は None）。相手のバリアー・「とうめい」・［ニュートラルシールド］では無効にならず、相手への効果だけを
  決めるコインの問い（HC3・T19b）に止めません（`test_opponent_barrier_does_not_stop_the_draw`）。`coin_dependent`（`heads_of`）は既存の確かめのまま。

### 3.4 ESP・再開・先読み・情報

- ナツメのESPのやり直しは、既存の経路（`AttackRun.flip` の `EspRedoOffer` と、決定のあとの要素のやり直しで決定の前の結果を使う `esp_preset`）のままです。やり直すなら同じ N 枚をすべて投げ直し、
  確定した H だけで 1 回引きます。決定の前に引かず、山札を見せません（`test_esp_redo_draws_once_from_the_final_result`。ESPの関数を差しかえた仕組みの確かめ）。
  （v0.113 で訂正: この版では「ESPを持てるナツメのポケモンにこのワザを使えるものは今の写しにない」と書いていましたが、誤りでした。超の色マーカーがのったドククラゲ（SI-016）を
  ベンチに置けば、ナツメのフーディンが［サイコリンク］でしょくしゅをつかうを持ち、ESPをつけて使えます。通常の登録・操作（`PlayTrainer`・`ResolveDecision`・`UseAttack` の供給元のカード）を
  通る確かめは v0.113 で加えました（docs/variable-coins-search-attachments-v0.113.md・`EspRealPathTest`）。エンジンの処理は変えていない文書の訂正です）確定した N・コインは既存の続きの情報（ワザ全体のコインの結果 `fs.coins`）で運び、再開時に別の枚数に読み替えたり、元のコインを投げ直したりしません。clone・deepcopy・
  pickle から同じ答えで同じ続きになり、不正な答えは状態・乱数・ログ・決定を変えません。
- `Draw.reads_deck_order` は真のまま（山札の並びを読む要素）、`draw_cards` の非公開の扱い（引いたカードの id は持ち主だけ。相手・観戦者には枚数）も変えていません（`test_drawn_cards_stay_hidden`）。
- 先読みは、「おもて」の数だけを使うコインとして既存の `Oracle.coin_group` で N + 1 通りにまとめます。まとめない先読みと同じ答え（結果の数は少ないか同じ）で、3 つの方法（derived・derived_full・
  legacy）で同じ結果です（`test_preflight_groups_by_heads_and_modes_agree`）。実際の対戦では N 枚を 1 枚ずつ投げ、分岐の都合でコインを減らしたり、引ける枚数で打ち切ったりしません。新しい型は
  v0.13 の止める関数の確かめた型（`VERIFIED`）ではないので、legacy でもすべての結果を試す方法で確かめます（旧 legacy に黙って落とさない）。`MAX_BRANCHES` は 4096 のまま。大きな N で上限を
  超えるときは、既存の明示的な扱い（`UNSUPPORTED_PREFLIGHT_LIMIT`）のままです。

## 4. どくばり・ふしょくえき

### 4.1 どくばり（`PoisonOnHeads`）

- 相手に 20 のあと、1 枚のコイン（この要素のコイン）の「おもて」で通常のどく（ポケモンチェックで 10）。「うら」なら何もしません。既存の型の確かめは形だけ（`ParalyzeOnHeads` も通る）なので、
  全文・登録・どくの動作をテストで照らしました（`test_terms_are_bound_to_the_texts`・`test_damage_then_ordinary_poison_on_heads`）。既存の状態異常の型の確かめの一括の改修はしていません。

### 4.2 ふしょくえき（`DamageParalyzeOnHeadsElseLockSelf`）

- 要素は `Damage(OPP, Printed())` → `Coin("coin")` → `Status(PARALYSIS, gate=おもて, reparalysis_check=True)` → `SelfAttackLock(local_coin=None, gate=うら)` です。1 枚の共有のコインの同じ結果を
  両方が使い（別々に投げない）、ESPでやり直したならやり直した結果を使います（`test_esp_redo_shares_the_final_result`）。「うら」でも 40 は残ります（ワザの失敗・自分へのダメージにしない）。
- 「うら」の効果は v0.35 の「あわあわ」と同じ持続する効果 `CannotUseOwnAttack`（実際に使ったポケモン自身。はたらくのは次の自分の番だけ。そのワザ（位置）だけを使えない。もう 1 つのワザ・
  相手の番・期間のあとには広げない。ベンチ・進化・きぜつで消えるのは既存の仕組み）。型の `attack_lock_terms` は (`CannotUseOwnAttack`, None)（効果を与えたワザ自身）で、不変条件が照らします。
- 型の確かめは全文（面・マヒ・次の自分の番・このワザ）を照らします。`ParalyzeOnHeads` では「うら」の制限が落ち、`DamageThenParalyzeOrSelfDamage` は「うら」の意味（自分へのダメージ）が違う
  ので使っていません。
- 自分の制限は相手への効果ではないので、相手へのマヒが無効（ミュウツーのバリアーの「ワザをうけない」）でも、共有のコインを省いたり HC3 に止めたりしません（`void_coin_question` は自分への
  要素があれば投げる。v0.76 の「きあいいっぱつ」と同じ。`test_lock_survives_a_void_opponent_effect`）。
- 処理の対象がない要素の扱いは既存のままです: 相手がこのワザで HP 以上なら「おもて」のマヒは処理しませんが、コインは自分の制限のために投げます（`Coin` が決める要素のどれかに対象があれば
  投げる。v0.38）。反撃（カイリキーの［はんげき］）でオムスター自身が HP 以上なら、「うら」でも制限を与えません（`SelfAttackLock` のログ `persistent_effect_skipped`）
  （`test_knocked_out_target_or_user`）。
- 相手のワザとして使うとき: `SelfAttackLock.copy_problem` は、番をまたぐ「このワザ」を、効果を持つポケモンのカードのワザの位置で記録するので表せないとして、エンジンの未対応を返します

## 6. ログの監査・対戦の道具

- ログの監査（`tests/log_audit.py` の `v112_problems`）は、エンジンの登録・計算を読まずに確かめます:
  - 処理したワザの印刷の文面が「自分についている「X」エネルギーの数だけコインを投げ、「おもて」の数×N枚のカードを、自分の山札から引く。」なら、そのワザのコイン（ワザの説明のコイン）の枚数が、
    ログから組み立てた実際に使ったポケモンのエネルギーの「X」の個数（基本エネルギーカードは印刷の色、特殊エネルギーカードは登録の出すエネルギーのうち「X」だけのもの。色を変える効果は
    組み立てない）と同じ。コインのあとに 1 回だけ引き、引いた枚数は「おもて」の数 × N まで。引いたのは自分のカードで、ログから組み立てた手札にないもの。「おもて」の数 × N より少なければ山札が
    なくなっている（そのあと山札にカードをもどさずに引いたら報告する）
  - 印刷の文面が「コインを投げて「おもて」なら、相手を「マヒ」状態にする。「うら」なら、次の自分の番、このカードはこのワザを使えない。」なら、そのワザのコインはちょうど 1 枚で、「おもて」なら
    自分に使えない効果を与えず、「うら」なら相手をマヒにせず、ワザを使ったポケモン自身にこのワザ（同じ位置）を使えない効果を 1 つ与える（HP 以上なら与えない）。次の自分の番にそのワザを
    使っていないことは、既存の監査（「あわあわ」の効果の確かめ）が見る
- 対戦の道具（`tools/existing_effect_games.py`）に v0.112 のデッキ（T112・O112）・組（`PAIRINGS_V0_112`）・数え方（`v112_uses`。ログから）・宣言の時点の場の照らし（`_v112_attack_observe`。
  道具がワザを使うポケモンの「水」の基本エネルギーカードと山札の枚数を数え、引いた枚数が「おもて」の数 × 2 と山札の枚数の小さいほうと同じかを照らす）を加えました。使っていないワザのために
  エネルギーをためる既存の手順（v0.38〜の「待つ」）を v0.112 のポケモンにも当てはめ、この番にふしょくえきを「うら」の制限で拒否されたときは待ちません。v0.112 のカードのない局では何も
  しません。
