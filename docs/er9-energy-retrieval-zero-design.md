- **範囲:** 保存記録・ソース・裁定の文書の読み取り、設計、文書化だけです。規約の採用、コード・版の変更、新しい対戦、judge・replay はしていません（次の単位）。

## 0. 先に結論

- **保存記録:** TR3 の本実行（24 局）で ER9 が返ったのは、C2 の 3 局・3 件で、3 件とも照合できました（欠け・矛盾 0）。
  - どれも手札から通常に使ったエネルギー回収です（借りた使用・サイキックコントロールの使用・錯乱ジム・リムーブ禁止ジムの追加の条件は 0）。
  - 費用（手札 1 枚のトラッシュ）は、回収の決定が出る前の操作として受理され、確定していました。
  - 回収の決定は最小 0・最大 2 で、選べるものは 4・4・6 枚でした。トラッシュしたカードは選べるものに入っていません。
  - 入力は `decline` 真（0 枚を入力として示す）で、方策は枚数を一様に選んで 0 を引きました。`check` は 3 件とも有効と答え、`submit` が `UNRESOLVED_ENERGY_RETRIEVAL_ZERO_CHOICE`（`unresolved_ruling`・続行できる・決定待ち）で拒否しました。
  - 拒否の前後で、どの見る人の観測も変わっていません（更新 0・観測の照合値とログの長さが同じ）。
  - 3 件とも、同じ入力に 2 枚で答え直して受理され、番が続きました。3 局とも対戦は最後まで進みました（game_over）。**対戦を終わらせた停止ではありません。**
- **0 枚について史料が書くこと:** 処理の根拠の最新の説明（p.257）は「最大2枚選び出し、手札に加える」で、0 枚を含むかを書きません。解説にもありません。kyuura の論点 `UQ-ENERGY-RETRIEVAL-ZERO-CHOICE` も未解決で、公式の資料が足りないとしています。再録の版の印刷の「手札に加えてよい」は最新の説明ではないので、裁定の根拠にしません（v0.71）。
- **推奨: B（0 枚を認める）。** 明示して選んだプレイ用の集合だけで当てます。CURRENT と TR3@1 の定義と照合値は変えません。
  - 0 枚の答えを受理し、何も手札に加えずに使用を終えます。払った費用はもどさず、エネルギー回収は持ち主のトラッシュに置き、番を続けます。
  - 規約を当てた記録として `convention_applied` を 1 つ書きます。
  - 0 枚は使用の取り消しではありません。取り消しと同じに扱う根拠はありません（3.3）。
  - 初回の範囲は手札からの通常の使用（再録の版を含む）だけです。借りた使用・サイキックコントロール・リムーブ禁止ジムの追加の条件のあとは、ER9 の停止のままにします（採用前の判断 D4）。
- **実際に増える選択肢:** 回収の決定ごとに、受理される答えが**ちょうど 1 つ（0 枚の答え）**増えます。保存記録の 3 件では、受理される答えは 10・10・21 通りから 11・11・22 通りになります。選べるカードの数・選ぶ数の上限・1 枚以上の答えは変わりません。
- **C（1 枚以上を必須にする）は推奨しません。** 0 枚の拒否は入力の誤りに変わってなくなりますが、受理される答えは増えません。そのうえ「0 枚は選べない」という、史料にない裁定を規約にすることになります。

## 2. 根拠と、プレイ用に決める必要があること

### 2.1 史料と既存の裁定が書くこと

| 資料 | 書かれていること | 0 枚への使い方 |
|---|---|---|
| p.257 の最新の説明（処理の根拠） | 「手札からカードを1枚選んでトラッシュしなければ、このカードは使えない。あなたのトラッシュから「基本エネルギーカード」を最大2枚選び出し、手札に加える。ただし、このカードを使うためにトラッシュしたカードを選ぶことはできない。」 | 0 枚を含むかは書かれていない（ER9） |
| p.257 の解説 | 使うときにトラッシュしたエネルギーは回収できない、特殊エネルギーは加えられない | 0 枚の記述はない |
| p.257 の図版・再録の版の印刷 | 「…最大2枚選び、手札に加えてよい。」 | 最新の説明ではないので、0 枚の扱いを決めない（ER9・v0.71） |
| p.310 のトレーナーの手順 | 1 手札から出す → 2 名前を伝える → 3 使うための条件にしたがう → 4 残りの説明。使ったらトラッシュする | 費用は手順 3 で払い、回収は手順 4。取り消しの手順はない |
| 会報 Vol.5（1998） | 「最大2枚」なので 1 枚だけでも手札に加えられる | 基準の資料ではない。1 枚のこと（ER8 の参考）で、0 枚を決めない |
| kyuura `UQ-ENERGY-RETRIEVAL-ZERO-CHOICE`（研究の基準 `71d1728`） | 未解決。公式の資料が足りない | 規約は裁定の代わりで、論点を解決済みにしない |
| kyuura `UQ-UP-TO-ZERO-CHOICE` | 「最大N枚」で 0 を選べるかの一般の問い（未解決。エネルギー回収は事例に入っていない） | 同じ形の問いとして記録するだけ |
| 既存の規定 ER7・ER11・ER16（docs/energy-retrieval-v0.23.md） | トラッシュしたカードは選べない。選べるものは使う前のトラッシュの基本エネルギーと同じ。段階 2 の不正な答えでも段階 1 のトラッシュは取り消さない | 費用はもどさない前提の根拠（ER16 は実装上の判断） |

したがって、**0 枚を選べるかは史料で決まりません。** プレイ用に決める必要があるのは次のことです。

1. 0 枚の答えを受理するか（B）、0 枚を入力で選べなくするか（C）、今のまま止めるか（A）。
2. 受理するなら、払った費用・使ったカードの行き先・番の続き・記録。
3. どの使用の経路に当てるか。

### 2.2 今のソース（`10da29d`）の流れ

| 段 | 処理 | 0 枚との関係 |
|---|---|---|
| 使う前 | `check_playable`: このカードを除く手札が 1 枚以上（ER2。足りなければ `INSUFFICIENT_CARDS_IN_HAND`）→ ポケモンタワー（PT1）→ トラッシュに基本エネルギーカードがなければ ER10 | ここで止まる場面は今回の範囲外。ER9 には届かない |
| 段階 1 | `resolve`: 決定 `discard_from_hand`（1〜1 枚） | — |

### 3.2 B: 0 枚を受理したときの処理

以下は、4 章の適用条件（手札からの通常の使用）に当てはまるときの処理です。

| 項目 | 規約が有効な集合での処理 | 根拠 |
|---|---|---|
| 費用（トラッシュした手札） | もどさない。トラッシュのまま | 費用は段階 1 の受理で確定している（1.2）。p.310 の手順 3 のあとに取り消しの手順はない。ER16 |
| 回収 | 何も手札に加えない。`zones.return_discard_to_hand` を呼ばない | 0 枚の答え |
| 使ったエネルギー回収 | 持ち主のトラッシュ（ログ `discard_trainer`）。1 枚以上の答えと同じ `_finish_trainer` | p.310（使いすて）・ER14 |
| 手札・トラッシュの移動 | 回収の答えでは移動なし。使用全体では、手札 −2（このカードと費用）、トラッシュ +2（費用と使い終えたこのカード） | 上の 3 行 |

| サイキックコントロールで相手のトラッシュから使う | 届く（`_start_nested_trainer` → `_start_trainer_use`。使い終えると外側のカードも捨てる） | 0 | 含めない（同上） |
| リムーブ禁止ジムの追加の条件のあと | 届く（`_resume_trainer(stadium_cost)` → `_resolve_trainer`） | 0 | 含めない（同上） |

手札以外の経路は、同じ `resume` に届くので、コードだけで引くと同じ規約が当たります。初回の範囲を手札からの使用に限るには、規約の処理が使用中のカードの記録（`TrainerInUse` の `user`・`via`）と、場のスタジアム（錯乱ジム・リムーブ禁止ジム）を公開の値で確かめ、当てはまらなければ今までどおり ER9 で止めます（4 章の適用条件）。手札以外の経路は保存記録とテストの実績がないため、根拠のある経路だけを初回の範囲にしました。錯乱ジムのコインが「おもて」で持ち主がそのまま使う場合も、初回の範囲では外します（錯乱ジムが場にあるため）。

### 3.4 C: 有効な回収対象を確かめる時点

- 対象があることは、使う前の `check_playable`（ER10）で確かめています。トラッシュしたカードは選べないので、回収の決定を出す時点の選べるものは使う前と同じです（ER11）。決定を待つ間は、ほかの操作が起きないので、選べるものは減りません。
- 今のソースでは、回収の決定を出す時点で対象がなくなることはありません（なければ `RuntimeError`。エンジンの不具合）。C でも B でも、この場合を規約の処理に入れる必要はありません。ER10 の場面に規約ができた場合は、そちらの規約が回収の決定を出すかを決めます（今回は扱わない）。
- C を採ると、0 枚の拒否は入力の誤りに変わってなくなります。ただし実行できる答えは増えず、表示が変わるだけです。決定の最小を規約で変えるので、決定を出す処理、不変条件（`decision_problems` の数の範囲）、合法手 API の `decline` の 3 か所が集合によって変わります。

### 3.5 推奨の理由

1. 判断の基準は、実際に拒否された 0 枚の答えを有効な手として処理できるかです。B だけが満たします（3 件とも受理される）。C は 0 枚を処理できないままです。
2. B は決定の形・選べるもの・1 枚以上の答えを変えず、0 枚の答えの続きだけを決めます。費用・使ったカードの行き先は 1 枚以上の答えと同じ道で、新しい移動はありません。
3. 族の案 PC-UP-TO-ZERO（[play-policy-family-plan.md](play-policy-family-plan.md)。判断事項 DEC-UP-TO-ZERO は proposal）の推奨と同じ向きです。ただし、族の 13 場面には個別の続き（山札を切るか・ログ）がまだ確かめられていないので、この規約は ER9 の 1 場面だけにします。ほかの場面には当てません（H4・SR2 を含む）。

### 4.1 既存の ER9 の判定規則と旧記録

- 判定の規則 6（`tools/verification_ai/judge.py` の `RECORDED_STOP_CONDITIONS`。ER9 の送信の値だけで既知の停止の根拠にする）は変えません。厳密側の集合と、初回の範囲の外の経路では、今までどおり ER9 が返り、規則 6 が根拠になります。
- 規約が有効な集合の対戦では、手札からの 0 枚の答えは受理になるので、規則 6 の対象の送信（ER9 の拒否）は出ません。規約を当てた受理を judge がどう判定するか（`convention_applied` の扱い）は、今回は確かめていません。実装の単位で確かめます（V11）。
- 本実行（TR3@1）の 3 件を含む旧記録は、記録の集合（TR3@1）のまま ER9 の既知の停止として扱います。新しい規約で読み直したり、判定を書き換えたりしません。
- 規約を加えても、CURRENT@1・TR3@1 の照合値（TR3@1 は `sha256:a7b800cf…`）は変わりません（集合の構成に入れないため）。
