## 0. 先に結論

- **推奨: 3 条件とも B（使えない。カードを消費しない）**。それぞれ別の続行規約として、新しい開発用の規約集合に入れます。利用者が明示的にその集合を選んだ対戦だけで有効にします。
  - 推奨の性質は、プレイ用の取り決めです。史実の裁定の証明ではありません。突風には、制限を明記した当時の印刷（第1弾・ジムの版。画像で確かめた）があります。ポケモンいれかえ・きずぐすりの B は、取り決めとして補う部分です。
  - コードとの整合: B は、受理の前の確かめの 1 か所で、今の `UnsupportedError` を `IllegalActionError` に替えるだけで済みます。錯乱ジムでかわりに使う経路と、サイキックコントロールの経路も、既存の処理がそのまま「答えの拒否」にします。カードの消費・空の決定・乱数・ログの新しい処理は要りません（2・4 章）。C は、通常のトレーナーの使用の処理（錯乱ジムのコイン・リムーブ禁止ジムの費用・［ちえくらべ］・効果の段階）を通るため、追加で決めることが多くなります。

- **利用者が決める項目**（7 章）: (1) 3 条件とも B か、(2) 推奨の組み込み先（新しい開発用の集合 `CS-KYUURA-PLAY-TR3@1`）か、(3) 通常の使用と代用の使用に同じ条件を当てるか。実装に要るほかの判断は 7.2 節に推奨値つきで並べました。

### 2.3 C を採る場合の、省けない処理と決めること

通常のトレーナーの使用の処理（`engine._start_trainer_use`）は、効果の前に次を行います。C ではどれも省けません。

- 錯乱ジムのコイン（「うら」なら相手がかわりに使うかの決定。相手から見た条件で、もう一度 C を当てる）
- リムーブ禁止ジムの追加の費用（手札 2 枚）
- ［ちえくらべ］（相手のヤドキングの反応の決定・コイン）
- ［でんせつのからだ］の確かめ

決めることは、カードを消費するか、何もしないことのログ、AL2・SG1・MH1 の確かめを残すか、錯乱ジム・サイキックコントロールで同じに扱うか、です。乱数の列も変わります。C を推奨しない主な理由はこの量で、資料の不足ではありません。

## 3. 推奨案の検討

**推奨（案）: 3 条件とも B。** 支持できると考えます。理由は次のとおりです。

1. **コードの整合**: 3 つの確かめは、どれも `check_playable` の最初の分岐です。続行規約があれば `IllegalActionError` を投げ、なければ今の `UnsupportedError` を投げる、という形で済みます。受理の前なので、状態・乱数・ログは変わりません（今の `check_play_trainer` の約束のまま）。
2. **代用の使用の経路の整合**: 錯乱ジムでかわりに使う経路（`borrow_condition_stop`・`require_borrow_playable`）とサイキックコントロール（`discard_trainer_use_choices`・`require_borrow_playable`）は、`check_playable` の `IllegalActionError` を、すでに「満たせない（使うと答えたら拒否）」として扱っています。B を `check_playable` に置けば、通常の使用と代用の使用に、同じ条件が自動で当たります。
3. **既存の規約の前例**: `PC-SETUP-PLAY-AS-POKEMON@1`（v0.143）の配置の拒否が同じ形です（続行側だけで `IllegalActionError NOT_BASIC_POKEMON`、理由の文に規約 ID、記録を残さない、候補で `excluded_by_convention`）。
4. **秘密への非依存**: 3 つの条件は、相手・自分のベンチの数と、自分の場のダメージだけで決まります。どれも公開の値です（本人のうらのカードのダメージも公開の 0）。規約の判定で、新たに秘密を読みません。
5. **3 枚を別の規約にする**: 根拠の強さが違います（突風だけ当時の印刷がある）。モードの設計 6.2 節は、記録が別の問いとして扱うカードは規約を共有しないとしています。同じ B でも 3 つの規約 ID に分け、利用者が 1 つずつ採れるようにします。

**注意（支持の範囲）**

- B は「使える・使えない」の史実を決めません。厳密モードの GW5 などは UNRESOLVED のままで、kyuura の論点も解決にしません。
- 族の規約 `PC-USE-WITHOUT-TARGET`（約 37 コードの案）の承認ではありません。ほかのカードに広げません。
- 代案として、突風だけ B、ほかの 2 枚は A のまま、もありえます（根拠の強さで分ける）。ただ、プレイ用の判断を無期限に保留する構成にはしないため、推奨は 3 枚とも B です。

### 5.2 判定の順序（`engine.check_play_trainer`）

1. 番・手札・トレーナーであること
2. トレーナーの使用の禁止（`TRAINER_PREVENTED`。ゲーム上できない）
3. 効果の登録
4. `check_playable`。**3 つの条件はどれも最初の確かめ**です。続いて突風は AL2 → SG1 → MH1/MH2/TK1、ポケモンいれかえは AL2 → MH1/MH2/TK1。きずぐすりは条件 1 つだけです
5. スタジアムの追加の費用
6. MG1（錯乱ジムと［ちえくらべ］）

- B では、条件が成り立てば 4 の最初で拒否します。AL2〜MG1 は確かめません。ベンチが空なら AL2・SG1・MH1 はもともと当たらない（MH1 は控えなしで何もしない）ので、これは厳密と同じ順序です。MG1 は、厳密でも GW5 などの停止が先です。
- 条件が成り立たないとき（対象がいる）は、続く AL2〜MG1 の停止が今までどおり起こります。B はそれを隠しません。

### 5.3 経路

| 経路 | 条件の確かめ | B の結果 |
|---|---|---|
| 手札から使う（`PlayTrainer`） | `check_play_trainer`（使うための条件を呼ぶ） | 宣言を拒否。カードは手札のまま |
| 候補（`legal_actions._trainer_candidate`） | 同じ関数を状態の複製で試す | 選択肢を出さない（今の不正な操作の扱い）、または「規約による除外」として示す（7.2 節） |
| 錯乱ジムの「うら」でかわりに使う | 決定を出すときに `borrow_condition_stop`。「使う」と答えたときに `require_borrow_playable` | 決定は出る（「使わない」はいつも答えになる）。「使う」は答えの拒否（今の「選ぶと止める」から変わる）。カードは錯乱ジムの「うら」の処理で、もとからトラッシュに行く（規約による消費ではない） |
| サイキックコントロール | 選べるもの（`discard_trainer_use_choices`）は、満たせないカードも選べるものに残す。選んだときに `require_borrow_playable` | そのカードを選ぶと答えの拒否。ほかのカードを選ぶか使わない（サイキックコントロールそのものは使い終えている） |

### 5.4 そのほかの確かめ

- 受理の前に対象がいない場合だけが対象です。受理のあとに対象がいなくなった場合（決定の途中・うらのカードの指定。v0.67）は、今の処理のままです。
- うらのカード: 判定はベンチの数とダメージの値だけで、本当のカードを読みません。候補の作成の、うらのカードの本当のカードを読んだ試行の保守的な扱い（PT-5t-C1）も変えません。
- 規約の対象外の未裁定は、続行側の集合でも今までどおり止めます。

## 8. 採用したあとの最小の実装の単位（コードは今回変えない）

1. `conventions.py`: 規約 3 件（`content` に適用条件・拒否のコード・変えないもの）と集合 `CS-KYUURA-PLAY-TR3@1` を加える。`IMPLEMENTED_CONTINUATIONS` に 3 件、固定した照合値に 3 件 ＋ 1 集合を加える。既存の値は変えない

5. テスト（9 章）
