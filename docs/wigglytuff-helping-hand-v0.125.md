### 3.1 印刷の未読の字と、最新の説明の採用

- ふくらむの印刷は、カードの画像（IMG-ES1-027）でも書籍の図版でも「このカードが次の相手の■に受ける…」と読まれ、■ の漢字 1 字は読めません。kyuura の文面（pcg-search.com の転記）は「の」と
  その 1 字が欠けた「次の相手に受ける」で、訂正の候補（`held_illegible_print`）のままです。最新の説明を採用しても、印刷の未読の字を「番」と補った訂正を作っていません。候補の履歴
  （`later_notes`）もそのままです。
- 採用の記録では、印刷の文面（`AttackEntry.text_ja`。写しの値）、処理に使う文面（`play_text_ja`）、その出典（`play_text` の `attack/0` = LD-ES1-027-ATK0）を分けて持ちます。CC-ES1-027-P226 の
  データの誤り（ふくらむの文面の欄）は、採用の記録の論点に挙げ、`affects_behavior: false` にしました（処理は同じ欄の最新の説明の全文にしたがい、欠けた写しの文面は照合だけに使う）。
- 既存の検査は、この論点を無条件に受け付けていました（`affects_behavior: false` の論点を照らす確かめがなかった）。未読・訂正の候補を一律に許可しないよう、`scripts/check_research_links.py` に
  確かめを加えました: データの誤りの欄を「挙動に影響しない」とした採用は、その欄が説明文で、その対象の処理に使う文面の根拠が最新の説明（LD-）の id で、その記録がこのカード・この対象を指し、
  印刷の文面の欄（`printed_text.path`）がこの欄・写しの値（`printed_text.text_ja`）がデータの誤りの kyuura の値と同じときだけ受け付けます（ほかの採用の記録に、この形の論点はない）。
- 効果の型の文面の確かめも、印刷の文面を広く許可していません。ふくらむの印刷の文面は、`effects.INFLATE_PRINTED_UNDER_LATEST`（印刷の文面 → (最新の説明の全文, 量 10)）の組で、最新の説明に
  したがう登録（`latest`）のときだけ受け付けます（v0.121 のなきごえの `GROWL_PRINTED_UNDER_LATEST` と同じ形）。量・コイン・最新の説明の全文のどれかが違う組や、句読点を落とした・未読の字を補った
  文面は拒否します（`RegistrationTest.test_text_checks_are_bound_not_relaxed`）。
- ［てだすけ］の印刷の文面と最新の説明の違いは「ベンチにいる時にだけ使える」→「ベンチにいるとき使える」だけです（kyuura の `meaning_change` は `none_apparent`。同じ欄の解説は「ベンチにいる
  ときしか使えない」）。使える場所はベンチだけです（CR-HELPING-HAND-USE）。

## 4. ふくらむ（既存の持続する効果の再利用）

- 既存の型 `DamageThenReduceDamageNextTurn`（v0.38。ナツメのポリゴンのバリアアタック・v0.79 のプリン neo4-085 のふくらむ）を、最新の説明の全文と量 10 を結んだ登録で使います。要素の並びは
  v0.38 と同じ（相手に 20 → ワザを使ったポケモン自身に `DamageReduction`）。弱点・抵抗力のあと、p.321 の 8 段階（受けるポケモンの「ダメージを変更する効果」）で 10 を引き、最終的に 0 以下なら
  「ダメージを受けなかった」（CR-INFLATE-DAMAGE-STEP）。攻撃側の 2 段階の -10 や、相手に与えるなきごえの効果にはしていません。重なり・順番は既存のダメージ計算のままです。
- 発生源と対象は、どちらも実際にワザを使ったポケモンです。化石のメタモンが相手のプクリンを写して使えば、効果はメタモン自身に付き、供給元（相手のプクリン）には付きません
  （`InflateTest.test_copied_inflate_goes_to_the_actual_user`）。このカードが相手の反撃などで HP 以上になったら与えない（p.309）、期限（次の相手の番の終わり）、ベンチにもどる・場を
  はなれる・進化で消えることは、既存の型・既存の契機のままです。ダメージ以外の効果（相手のワザのこんらんなど）は防ぎません。
- **ワザ以外のダメージ**（kyuura の UQ-NON-ATTACK-DAMAGE-MODIFIERS の事例）: 既存の止め方が、結果の分かれる場面を扱うかを確かめました。

| どく（ポケモンチェック） | 持続する効果を当てはめない | そのまま。ポケモンチェックはどちらの番でもない（p.323）ので「次の相手の番」に当たらないと読める（kyuura の事例の注記の推論） |

## 5. ［てだすけ］

- 新しい型 `CureOneActiveConditionOnHeadsFromBench`（宣言する特殊能力）。能力の回数・場所・抑止・持ち主の確かめは共通の処理（`require_power_not_used`・エンジンの抑止の確かめ・
  `powers_of`）に通します。使った記録は場のポケモンごと（宣言のときに記録する。「うら」でも使ったことになる）で、毎回新しい個体を作ったり、使用済みを戻したりしません。
- 宣言の前の確かめ（状態・使用済みの記録・乱数・ログを変えない）:

| 場面 | 扱い |
|---|---|
| このカードがバトル場 | `POKEMON_NOT_ON_BENCH`（拒否） |
| この番にこのポケモンがもう使った | `POWER_ALREADY_USED` |
| 自分の対戦ポケモンの状態が 0 個 | **HH1**（`UNRESOLVED_HELPING_HAND_WITHOUT_CONDITION`。kyuura の UQ-CARD-USE-WITHOUT-TARGET の事例）。0 個だからコインを省いて使用済みにする、とは決めていない。なんでもなおしの FH1・FH2、ヒーリングの答えを名前だけで流用していない |

| 状態がちょうど 1 個 | 受け付ける。だれがいつ選ぶ読みでも回復する状態は同じなので、新しい選択の決定を出さない |

- 処理: 特殊能力のコイン 1 枚（`_power_coin`。`source="power"`。ナツメのESPのやり直しの対象ではない）。「おもて」なら、その 1 つだけを `conditions.cure_conditions` で回復します（どくなら毒
  （倍率 `multiplier` をふくむ）だけ、ねむり・マヒ・こんらんならその状態だけ）。ダメージ・マーカー・持続する効果・ついているカードは変えません。ログは宣言（`pokemon_power`）・コイン
  （`coin_flip`）・回復（`special_conditions_removed` の `effect` が `ES1-027@power0`・`reason` が `cured`）が一度ずつで、実装用の直接の乱数・ログだけの処理はありません。
- 真に場をはなれて出し直した個体は、新しい場のポケモンの番号なので別の記録です。進化・退化・姿の変化では、v0.50 の `retag_power_uses`・DV3 の共通の扱いのままです（ベンチの 2 匹のプクリンは
