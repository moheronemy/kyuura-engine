## 2. サンダーストーム（控えポケモンそれぞれへのコイン）

要素 `programs.CoinPerOpponentBench(bench_damage=20, self_per=10)` を加えました（汎用の「控えごとにコイン」の要素。カード id で分けない）。

1. 相手の対戦ポケモンにダメージの目安 40（ふつうのダメージの要素。p.321 の計算・「とうめい」・かげぶんしん・「ダメージを受けたとき」の効果などは今までどおり）。
2. 相手の控えポケモンの並び（この要素を処理する時点のベンチの順）の 1 匹ごとにコインを 1 枚。1 回の `flip` で並びの順に投げ、`i` 枚目は `i` 番目の控えのもの
   （ログ `bench_coin_results` に控えの番号と面の対応）。「おもて」の数でまとめません（どの控えが「おもて」かが要るので、先読みは 2 の控えの数乗通りを試す）。
3. すべて投げてから、「おもて」の控えに並びの順で 20（`OPPONENT_BENCH`・弱点・抵抗力なし。プラスパワーは変えない・ディフェンダーは変える。v0.31 からの控えへのダメージ）。
4. 同じコインの「うら」の数 × 10 をワザを使ったポケモンに（ワザによる自分へのダメージ。v0.2f・v0.3d。「うら」が 0 なら与えない。投げ直さない）。

- 控えがいなければコインも自分へのダメージもありません（「その間に出た「うら」の数」が 0）。相手の対戦ポケモンがダメージを受けなくても（0・防いだ・受けなかった）、控えのコインは
  投げます（コインが決めるのは控えへのダメージと自分へのダメージで、自分へのダメージは有効な要素。v0.34 の `void_coin_question` の対象にしない）。
- 「コインを投げ終わったら」なので、自分へのダメージは控えへのダメージのあとです。相手の控えのカイリキーの［はんげき］などの「ダメージを受けたとき」の効果は、ワザのダメージの
  処理（自分へのダメージを含む）がすべて終わってから（v0.10 の `finish_damage_elements`。CR-COUNTERATTACK-TIMING）。同じワザでサンダーと控えがきぜつするのは、ワザのあとの
  きぜつの判定で同時のきぜつ（p.324）として処理します。
- 実装上の読み方: 「それぞれに対してコインを投げ、「おもて」ならそのポケモンに…ダメージ」を、すべて投げてからダメージを与えると読みました（1 匹ずつ投げてダメージを与えても、
  ふつうはコインと結果の分布は同じ）。
- TS1（新規。`UNRESOLVED_BENCH_COIN_TRANSPARENCY_ORDER`。問い `bench_coin_transparency_order`）: はたらいている「とうめい」を持つ控えポケモンの後ろにほかの控えがいると、
  「とうめい」のコイン（そのポケモンがダメージを受けるとき）が控えのコインのあいだに入るか（1 匹ずつ）、すべてのあとか（すべて投げてから）で乱数の割り当てが変わります。印刷の文面・
  kyuura の記録から決まらないので、コインの前に止めます（宣言の前。先読みが見つける）。「とうめい」が並びの最後なら、どちらの読み方でも同じ割り当てなので止めません。2 匹以上の
  「とうめい」は今までどおり T27（`UNRESOLVED_TRANSPARENCY_COIN_ORDER`）です。
- 相手のワザとして使う（ゆびをふる・ちょうのうりょく・ぼーっとする）ときも同じ要素です（自分へのダメージはまねたポケモンに。ワザを使うための条件はない）。

## 3. かげぶんしん（相手のワザのダメージを受ける時のコイン）

ワザを使ったポケモン自身に、持続する効果 `state.TailsDamageGuard`（種類 `tails_damage_guard`。`on_opponent` は偽）を与えます（要素 `programs.SelfDamageGuard`）。

- はたらく時: 与えた番から（「これ以降」。`turns_until_active` 0）。期限では消えません（`lasting`）。消えるのは、このポケモンがダメージを受けた時（理由 `damaged`。
  `persistent.remove_on_damage`）と、バトル場をはなれた時（にげる・入れ替え・きぜつ・山札や手札にもどる。既存の契機）、進化した時（v0.4b と同じ。p.310・p.323）です。
  同じワザをもう一度使ったら、前の効果を理由 `replaced` で消してから与えます（`replace_persistent_effect`。重ねない）。
- コイン: 相手のワザによるダメージ（`kernel.deal_damage` を通り、最終ダメージが 0 より大きく、受けるポケモンの持ち主がワザを使ったプレイヤーでない）を受ける時、ダメージを
  のせる直前に、相手プレイヤー（ワザ・返す効果を使うプレイヤー）がコインを 1 枚（`coin_flip` の `source` は `persistent_effect`。ログ `damage_guard_check`）。「うら」なら
  そのダメージを受けません（`DamageResult.dodged`。ダメージを与えなかったことになる。「ダメージを受けたとき」の効果もはたらかない）。「おもて」ならダメージを受けて、効果は消えます。
  ダメージの要素ごとに投げます（同じワザでもう一度ダメージを受ける時も、効果が残っていればまた投げる）。
- 「(ダメージ以外の効果は、そのまま)」: 受けないのはそのダメージの要素だけで、ワザ全体を無効にしません（特殊状態・入れ替えなどの効果は受ける。「とうめい」の T19b の
  「受けない」とは別）。
- 最終ダメージが 0（抵抗力・ディフェンダーなど）ならダメージを受ける時ではないのでコインを投げません。自分のワザによる自分へのダメージ・こんらんの 20・どくのダメージ・特殊能力の
  ダメージ（［はんげき］など）・レインボーエネルギー・ロケット団の爆発ジムのダメージではコインを投げませんが、ダメージを受けたので効果は消えます（「このカードがダメージを受けるか」）。
  ダメージカウンターをのせる・移す効果（ダメージスワップ・のろい・ダメージシフトなど）はダメージではない（GR-2000-P320-COUNTER-MOVE）ので、消えません。
- 「ダメージを与えた後」の効果を持つワザで、かげぶんしんの「うら」でダメージを受けなかった場合は、既存の Z23（`UNRESOLVED_EFFECT_AFTER_NO_DAMAGE`。ダメージを与えなかったときに
  効果を与えるか）と同じ問いです（理由の文に「「かげぶんしん」のコインが「うら」で受けなかった」を加えた。新しいコードにしない）。先読みがコインの「うら」の結果を試すので、
  そのようなワザでかげぶんしんの効果を持つ相手を攻撃すると、宣言の前に止まります。
- 「とうめい」と同じポケモンに重なることは今の写しでは起こらない（R団のストライクは「とうめい」を持たず、［へんしん］で写す特殊能力は TF1 で止まる）ので、重なったら
  `RuntimeError` です（順番を推測しない）。
- 不変条件 `engine._damage_guard_problems`（効果を与えたワザの登録の `guard_terms()` と照らす）。相手のワザとして使ったときは、ワザを使ったポケモン（まねたポケモン）に与えます。

## 4. ［はんこう］（ワザを使う時に、手順 4 の効果としてはたらく特殊能力）

`effects.FailAndReturnOnAttack`（`PowerKey("PMCG5-035", 0)`）。使用を宣言しない自動的にはたらく特殊能力（`declared = False`。`UsePokemonPower` は `POWER_NOT_DECLARABLE`）です。

- 時点: 「このカードがワザを使う時」「そのワザは失敗となり」を、p.309 のワザを使う手順 4「ワザを失敗させたりワザの内容を変えてしまう効果」と読みました（v0.36 のすなかけと同じ
  時点。宣言（手順 3）のあと・こんらんのコイン（手順 5）とワザの要素の前。`resolution.flow._attack_check_failed` → `_rebellion_failed`）。持ち主がコインを 2 枚
  （`flip_coins` の `source="power"`。ログ `rebellion_check`）。宣言できないワザ（ねむり・マヒ・エネルギー不足など）はこの前に拒否するので、コインを投げません。
- すべて「うら」なら: ワザは失敗（ログ `attack_failed` の `reason` `power`。ワザは使ったことになり番は終わる。p.323 の 12）→ このカードと、ついているすべてのカード（重なった
  進化前のカード・エネルギー・ついているトレーナー・「ばける」でのせたカード）を同じ uid のまま持ち主の山札にもどす（v0.36 の `zones.return_in_play_to_deck`。ログの出どころは
  `power`）→ 持続する効果を理由 `return_in_play_to_deck` で消す → 山札を切る（先読みでは切らない）。きぜつではありません（サイド・ログ `knock_out`・きぜつしたときの特殊能力は
  ない。GR-2000-P312-FIELD）。空いたバトル場は、ワザのあとの既存の勝ち負けの判定とバトル場に出す決定（`promote_active`）でうめます（控えがいなければ負け）。
- 1 枚でも「おもて」ならワザはそのまま続きます（手順 5 のこんらんのコインに進む）。
- 「こんらん」状態でもはたらきます（説明のとおり）。v0.36 の AC6（手順 4 の効果のあとに手順 5 をするか）は、すなかけなどの効果では、失敗したワザのあとにこんらんのコインを投げるかが
  決まらない問いです。［はんこう］で失敗したらこのポケモンは場にいない（処理の対象がない。p.309）ので、どちらの読み方でも同じ結果です。こんらんでは止めません。
- ほかの手順 4 の効果（すなかけ・えんまく・スミをかけるなど）を同時に受けている場合は、どの順番でコインを投げるかが決まらないので、既存の AC13（`UNRESOLVED_MULTIPLE_ATTACK_CHECKS`）
  で止めます（［はんこう］を手順 4 の効果として数える）。v0.57 のクチバシティジムのコインとの順番は既存の VM1 です。
- かがくへんかガス・まきちらせ!ベトベトガスでは消えます（`continuous.power_suppressed`）。ショックアイ（「使うことができない」だけ）では止まりません（宣言して使う特殊能力の使用を
  止める効果。CR-CHEMICAL-GAS-USE-VS-POWER と同じ区別。v0.59）。説明のとおり、ねむり・マヒ・こんらんでは止まりません（ねむり・マヒはワザを宣言できない）。

## 5. スピードスター（相手の持っている効果の影響を受けないダメージ）

要素 `Damage` に `defender_effects`（既定は真）を加え、スピードスターは `defender_effects=False` にしました（`kernel.deal_damage(..., defender_effects=False)`。相手の対戦
ポケモンへのダメージだけ。ほかの対象に渡すと `ValueError`）。

- 計算しないもの（相手の対戦ポケモン自身が持っている効果）: 弱点・抵抗力（p.321 の 3・4 段階）、ついているトレーナー（ディフェンダーの 7 段階）、受けるポケモンの持続する効果
  （「ダメージを受けない」「ワザをうけない」状態・ちいさくなる・かたくなる・リフレクター・かげぶんしん）、受けるポケモン自身の特殊能力（なぞのかべ・ふしぎなバリアー・
  カブトアーマー・くつろぐかおり・「とうめい」）。`effects.attack_damage_modifiers(..., exclude=EXCLUDE_DEFENDER_HELD)`・`kernel.first_void(..., held_by_receiver=False)`。
- 計算するもの: ワザを使うポケモンの持っている効果（プラスパワー・つるぎのまい・きあいだめ・ワザを使うポケモンが受けている「なきつく」・きょうぼう）、プレイヤー・場の効果
  （カスミの + 20・スタジアム）。効果を持っているのがだれかで分け、だれが与えたかでは分けません（実装上の読み方）。
- ダメージを受けたあとの反応（［はんげき］・［わるいねぞう］・［ぼうぎょかふん］・ほのおのかべ・こうらがえし・クロスカウンター）は、「このワザのダメージ」の計算ではないので
  はたらきます（実装上の読み方）。ダメージのログに `ignore_defender_effects`。
- 「相手」は p.320 の太字の定義（相手の対戦ポケモン）と読みました。「相手の持っている」が相手プレイヤーの場のほかのポケモンが持つ効果（ワザのダメージを変える常にはたらく特殊能力
  で、バトル場以外ではたらくもの）を含むかは印刷の文面・kyuura の記録から決まりません（v0.33 の CD4 と同じ理由で決めない）。2 つの読み方（`EXCLUDE_DEFENDER_HELD`・
  `EXCLUDE_DEFENDER_SIDE`）で最終ダメージ（または順番の決定の要否）が変わるときだけ止める問い SS1（`speed_star_scope`）を置きました。今の写しのワザのダメージを変える常にはたらく
  特殊能力はどれもバトル場にいる限りはたらく（持っているのは受けるポケモン自身）ので起こらず、コードのない問いです（当たったらエンジンの不具合として止まる。研究の対応表の
  `codeless_questions`）。
- 相手のワザとして使うときも同じです。
