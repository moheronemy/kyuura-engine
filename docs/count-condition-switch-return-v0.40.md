- 写しは既存の手順（`python3 scripts/extract_kyuura_cards.py --kyuura ../kyuura`）で作り直しました（組 `pool_v0_40`。参照するコミット `ecb2d69` は変えていない）。

  wiki）ので、pcg-search.com との照合は独立した照合です。
- pcg-search.com の同じ版のページと照合しました（2026-10-16。照合した欄は名前・段階・HP・タイプ・弱点・抵抗力・にげる・ワザの名前・エネルギー・ダメージ・
  説明文。カードの画像は読んでいない）。版はカード名だけでなく、収録とサイトの一覧の番号・HP・ワザで決めました（わるいゴーリキー 043/065・マンキー 040/065・
  オコリザル 029/048・キョウのズバット 010/098・サカキのニドラン♂ 021/098 など、サイトの一覧の番号が kyuura の id の番号と違うカードがある）。8 件は `match`、
  7 件は `differences`（どれも処理に影響しない。`affects_behavior: false`）です。
  - キョウのズバットのむれでおそう: サイトは「×10のダメージ」、kyuura は「×10ダメージ」（「の」の有無）。
  - わるいマタドガスのみんなでばくはつ: サイトは 2 つめも「すべての」、kyuura は「全ての」（表記の違い）。
  - わるいスリーパーのベンチをあやつる: サイトは「…×20のダメージ。(このワザの…)」と句点がある。kyuura は句点がない。
  - サカキのニドラン♂のにどげり: サイトは「コインを2枚投げ、」、kyuura は「コインを2枚投げて」。
  - サカキのニドリーノのつのでえぐる: サイトは「のっていたなら」、kyuura は「のっているなら」。どちらも「このワザを使う時、すでに」相手にカウンターがのっているかで
    決める同じ条件（4 章の HD1）。
  - サカキのニドクインのラブラリアット: サイトのダメージの表示は「50」、kyuura は「50+」（「+」の有無）。処理は説明の「このワザのダメージは「100」になる」と目安の
    数字 50 で決まり、記号では変わらない（登録は写しの「50+」で照らす。kyuura への報告事項。11 章）。
  - わるいゴーリキー: ひきずりだすのかっこはサイトが半角・kyuura が全角。なぐりとばすはサイトが「入れ替わるポケモンは相手が選ぶ。(…入れ替えはおこらない)」、
    kyuura が「入れ替えるポケモンは相手が選ぶ。（…入れ替えは起こらない）」（表記・かっこの違い。選ぶのは相手で、控えがいなければ入れ替えない処理は同じ）。
- 採用の記録（`card_sources.json`）は 15 件 `adopted`（`kyuura_commit` は `ecb2d69`、記録した日は 2026-10-16、説明文のあるワザの `play_text` は
  `kyuura_printed_text`）。過去の原典照合の記録（`card_verification.json`）には加えていません。ガイドブックの項目は書いていません。

## 3. 共通の処理

### 3.1 新しく加えた型

どれも解決の基盤の要素の並び（`programs.BUILDERS`）で処理し、v0.13 の約束（`resolve`・`resume`）は上書きしていません。`v013_checks.VERIFIED` には入れず、
tests/helpers.py の `ATTACK_TYPES_SINCE_V0_17` に加えました。型の `check` は、登録したワザの印刷の文面と同じ書き方だけを受け付けます（`TextTest`。ひきずりだす
（全角のかっこ）とさそってとかす（半角のかっこ）は、記号だけが違う同じ文面として、どちらも `SwitchOpponentThenDamage` で受け付ける）。

### 3.2 要素・値に加えた項目と新しい要素

- 新しい要素 `BenchFromDeckAny(names)`（むれでおそう）: 選ぶのはワザを使ったプレイヤー（v0.32 と同じ決定 `BENCH_FROM_DECK`）。選べるものは山札の、名前の合う
  たねポケモン（uid の小さい順）、選ぶ数は 0〜min(ベンチの空き, 選べるものの数)。同じカードを 2 回選べない（`DUPLICATE_CHOICE`）。選べるものがない・ベンチに空きが
  ないなら決定を出さない。出すのは答えの並びの順に 1 枚ずつ（`zones.bench_from_deck`。ログ `bench_from_deck` は v0.32 と同じ形で 1 枚に 1 つ）で、そのあと山札を
  1 回だけ切る。0 枚を選んだら出さず、切らない（新しいログ `bench_from_deck_declined`）。
- 新しい値 `PokemonCountTimes(per, scope, names)`: 数えた場のポケモンの数 × `per` を p.321 の 1 段階の基本となるダメージにする（v0.39 の `PrintedPlusPokemonCount`
  の、目安の数字を足さない形。数えるのは v0.39 の `counted_pokemon` で、進化して重なったカードは 1 匹・名前の完全一致）。`scope` に `both_in_play`（お互いの場）を
  加えた。
- 新しい値 `TailsOfOpponentBenchCoins(per)`: 相手の控えの数だけ相手プレイヤーが投げるコインの「うら」の数 × `per`。値の `flipped_by_opponent` で、`Damage` の
  要素がコインを投げるプレイヤーを相手にする（`AttackRun.flip` に `player` を加えた。既定はワザを使ったプレイヤー）。
- 新しい要素 `OwnCountersAtLeast(minimum)`: ワザを使うための条件（実装の `usage_problem` が宣言の前に `NOT_ENOUGH_DAMAGE_COUNTERS` で拒否）の、相手のワザとして
  使うときの扱い（`copy_problem`）だけを持つ。
- 新しい値 `PrintedPlusBonusIfDefenderDamaged(bonus)`・`AmountIfOwnBenchNamed(names, amount)`・`PrintedPlusBonusOnAllHeads(coins, bonus)`: どれも p.321 の 1 段階の
  基本となるダメージ。
- 新しい要素 `OpponentAttackLockWhileSourceActive(max_hp)` と持続する効果 `state.CannotAttackWhileSourceActive`（すごむ。5 章・4 章の IM1〜IM6）。
- 新しい要素 `ReturnOpponentToDeck()`（つまみだす）: v0.36 の `zones.return_in_play_to_deck` を持ち主（相手）で呼び、持続する効果を消し、持ち主の山札を切る。
- 新しい要素 `ShuffleDeck(own)`（ひまつぶし・いたずら）。
- ワザの効果で山札を切る処理は `programs.shuffle_in_attack` にまとめた（v0.40 のワザだけが使う）。`zones.shuffle_deck` に `effect` を加え、渡したときだけログ `shuffle`
  に `effect`（ワザの識別子）を書く（v0.39 までの呼び出しのログは同じ形）。先読み（`res.dry_run`）では切らない（乱数はコインだけ）。そのとき、切る要素のあとに山札の

  対応カードでは起こらない）。
- `Damage` に `names`（受けるポケモンのいちばん上のカードの名前がこのどれかのときだけ与える。合わなければダメージの要素はなく、ログもない）、`BenchDamage` に
  `names`（受ける控えを名前でしぼる）を加えた（みんなでばくはつ）。既定の `None` は今までどおり。

  またいで枠の値（「とうめい」の結果など）を運ぶ。v0.34 の `AttackRun.suspend(carry=True)`）を加えた。既定はどちらも `False` で、v0.39 までのワザは変わらない。

## 5. SG1: すごむの効果を与えたポケモンが同じ番にバトル場にもどった場合

| 項目 | 内容 |
|---|---|
| 問い | サカキのニドキングの「すごむ」の効果（「次の相手の番、このカードがバトル場にいる限り、ワザを使えない」）を受けたポケモンの持ち主が、その番に突風でサカキのニドキングを控えにもどした（ワザを使えるようになった）あと、もう一度突風でサカキのニドキングをバトル場にもどした場合、効果はまたはたらくか（「いる限り」が、はなれた時点で終わるか） |
