# テストの実行と追加

カードの挙動、決定の再開、見えない情報、乱数、保存・復元、対戦と監査のテストを維持します。テストの件数を減らすこと自体は目的にしません。

## 実行範囲

開発中は変更したクラスやメソッドを指定します。たとえば v0.88 の保存の検査だけなら:

```sh
python3 -m unittest tests.test_type_energy_colors_v0_88.SerializationTest
```

関連する共通処理を変えたら、それを使う既存のテストも実行します。完了時には、コードとテストを変更しない状態で全体を実行します:

```sh
python3 -m unittest
```

`../kyuura` に固定コミットの履歴があれば、写し・対象カタログとの比較も実行されます。条件による skip は、件数と理由を実行結果から報告します。

結果を書き入れただけの文書変更では、そのファイルを読むテストのメソッドまたはクラスを再実行します。文書を読む全モジュールを一律に実行する必要はありません。たとえば v0.87 の文書なら:

```sh
rg -n 'movement-damage-reactions-v0.87.md|DOC.read_text' tests
python3 -m unittest tests.test_movement_damage_reactions_v0_87.DocumentTest
```

これは全体の検証後に行う、文書だけの変更の扱いです。コードやテストを直したときは、直した範囲に応じて検証をやり直します。

## 現在の総数と版ごとの範囲

- 現在のカード総数・種類別の数・登録数・未対応数・研究の総数・最新の保存形式の期待値は、`tests/test_catalog_contract.py` にまとめます。期待値は独立した固定値です。実装から計算した値を期待値に流用しません。
- 各版のテストは、その版のカード一覧、登録内容、出典、動作を確かめます。現在の全カード総数を重ねて検査しません。
- 登録を除くテストでは、除いたカードの集合がその版のカードと一致し、ほかのカードが失われないことを比べます。
- 過去のカタログの範囲を調べるときは、`tests/release_catalog.py` の `cards_after(extract, "0.73")`・`cards_before` を使います。後続の `pool_v0_74`、`pool_v0_75`、… を列挙しません。これはカードの集合の切り出しであり、当時のエンジンの挙動を再現するものではありません。
- 旧保存形式で表せる・表せない項目のテストは、その形式の番号を明示したまま残します。存在しない形式のテストは `max(FORMAT_VERSIONS) + 1` を使います。
- `tests/log_audit.py` の形式の番号と項目表は独立して更新します。形式の番号を実装から自動取得すると、監査への新項目の追加漏れを隠すためです。

登録キー・ワザの型・出典など、意味のある期待一覧は引き続き検査します。新しいカードや型を加えたときは、その意味に応じて更新します。

## 実行時間を測る

Python 3.11 以降の標準ライブラリだけで動く道具を用意しています。指定を省くと通常と同じ全テストを収集します。テストを省くためのフィルターはありません。

```sh
python3 tools/test_runner.py --report /tmp/test-timings.json --slowest 15
python3 tools/test_runner.py tests.test_catalog_contract --slowest 5
```

レポートは収集時間、テストの成否・skip、モジュールごとの時間、個々のテストの時間を持ちます。モジュール時間には `setUpModule`・`setUpClass`・後片づけを含めます。個々のテストの時間だけでは、共通の準備で対戦を実行するテストの負荷が見えないためです。モジュールとテストの時間は重なるので足し合わせません。

遅いテストは、まず何を確かめているかと共通の準備を調べます。件数や実行時間だけを理由に、対戦・監査・乱数・情報漏れ・再開処理の検査を削りません。
