# エネルギーをトラッシュしてダメージを与えるワザの共通化と、ポケモン 5 枚の追加（v0.30）

「自分の炎エネルギーカードを 1 枚トラッシュして、相手にダメージを与える」ワザを、1 つの効果の型（`effects.DiscardEnergyThenDamage`）にまとめ、
その型で対応できるポケモン 5 枚（ワザ 9。うち 8 つを新しく登録）をまとめて加えました（版 0.30.0）。

- 追加したカード: ヒトカゲ（PMCG1-014）・リザード（PMCG1-017）・ウインディ（PMCG1-019）・ブーバー（PMCG1-020）・第4弾ロケット団のポニータ（PMCG4-013）。
  対応ポケモンは 72 枚から 77 枚になりました（写しの対応済みのポケモン。写しは 95 枚から 99 枚、ワザの登録は 116 から 124）。
- 新しい効果の型は 1 つ（`DiscardEnergyThenDamage`）、新しい要素はありません。v0.7 のじこさいせいの要素（`DiscardEnergyHealAll`）を、トラッシュ
  （`DiscardOwnEnergy`）とダメージカウンターをとりのぞく処理（`HealAllCounters`）の 2 つに分け、トラッシュの要素を共通にしました。決定の種類・
  ログのイベントの種類・状態の型・書き出しの形式（9）・公開の API・効果の登録表の id（`kyuura-engine-0.13`）は変えていません。`engine.py` は
  変えていません。`engine.py`・`resolution/` にカード id での分岐はありません。
- 新しい未解決の裁定・停止コードはありません（未解決の裁定 28 件・停止コード 22 件のまま）。保留したカードは 4 章。
- 公開の固定のデッキ・固定した参照データ・研究の基準（`3f34908`）・写しの元（`ecb2d69`）は変えていません。
- ガイドブック（『オフィシャルブック2000』）は読んでいません（キャプチャ・OCR・画像の読み直しをしていない）。

## 1. 共通の効果の仕様（`DiscardEnergyThenDamage`）

根拠は kyuura の `RUL-ENERGY-DISCARD-ATTACKS`（研究の基準のコミットの `data/rule_history.json` の errata。確度「確実」。kyuura が『オフィシャルブック2000』
p.63 のワザ解説と『トレーナーズ』Vol.5 p.63・Vol.9 p.22 の誌面で確かめた記録）と、一般の規定の既存の記録（kyuura の `GR-2000-P309-ATTACK-PROCEDURE`。
エンジンの p.309・p.320・p.321 の照合の記録）です。記録の要点:

- 「これまでワザの条件として、炎エネルギーカードをトラッシュしましたが、これからはワザの効果としてトラッシュすることになります。炎エネルギーカードを
  トラッシュするタイプのワザ（「かえんほうしゃ」など）は、すべて同じ処理になります。」
- 最新の説明（第1弾のヒトカゲの「ひのこ」・ウインディの「かえんほうしゃ」）:「自分についている「炎」エネルギーカードを1枚トラッシュする。トラッシュ
  できないとき、このワザのダメージはなくなる。」
- 流れ: ワザ宣言 → 持続する効果のチェックと処理 → こんらん状態のチェックと処理 → ワザ内容の処理（ここでトラッシュ）。
- 未解決の問い（記録の open_questions）: 炎エネルギー以外のエネルギーをトラッシュするワザにも同じ説明が当てはまるか。

カードごとの整理（5 つのワザで同じ。トラッシュが使用条件か効果かは、この記録で決めた。現代のルールや似た別のカードから推測していない）:

| 項目 | 処理 | 根拠 |
|---|---|---|
| トラッシュするカードの種類と枚数 | ワザを使うポケモン自身についている「炎」の基本エネルギーカード 1 枚。余分にトラッシュしない | RUL- の最新の説明・p.309（特に指示されていないかぎりエネルギーをトラッシュしない。GR-2000-P309-ATTACK-PROCEDURE） |
| 選択の要否 | 「炎」が 2 枚以上ついていればどれを捨てるかで状態が変わるので、ワザを使うプレイヤーが選ぶ（決定 `discard_energy`。選べるものはついている順）。1 枚だけでも決定を出す | v0.7 のじこさいせいと同じ決定・同じ実装上の仮定（K2）。選択の仕組みは新設していない |
| 宣言の条件 | ほかのワザと同じ（必要なエネルギー）。トラッシュは宣言の条件ではなく、宣言のときにトラッシュしない | RUL-（「ワザの効果としてトラッシュ」）・p.309 |
| トラッシュとダメージの順 | トラッシュ → 相手の対戦ポケモンへのダメージ（ダメージの目安の数字。p.321 の順番で計算） | RUL- の流れ・最新の説明（「トラッシュできないとき、このワザのダメージはなくなる」がダメージを決める） |
| こんらん | コインが「うら」なら、ワザの内容（トラッシュ・ダメージ）を処理しない（自分に 20）。「おもて」ならトラッシュの決定を出す | RUL- の流れ・p.309 の手順 5 |
| 相手がダメージを受けない場合 | トラッシュはダメージより先にすんでいる（「ダメージを受けない」状態でダメージの要素が無効・「とうめい」で受けない・抵抗力などで最終ダメージが 0 のどれでも）。「ダメージを与えた後」の効果ではないので Z23 にはかかわらない | RUL- の流れ・p.321 |
| トラッシュできない場合 | 必要なエネルギーに「炎」があり、今の写しのエネルギーは基本エネルギーだけなので起こらない。起こったらエンジンの不具合として `RuntimeError`（状態を変える前） | じこさいせいの K3 と同じ扱い。特殊エネルギー・ほかのワザを使うワザを加えるときに、この場合の処理を加える |
| 既存の裁定で止める場面 | 相手のワザのダメージでのきぜつと、相手の効果の 10（「はんげき」C18・「ほのおのかべ」W24）での自分のきぜつがそろいうるときは、宣言の前（トラッシュの決定の前）に止める | 既存の C18・W24（新しい裁定・コードはない） |
| 先読みへの反映 | 実際の処理と、宣言の前の先読み（`derived`・`derived_full`・比べる方法 `legacy`）は同じ要素の並びを使う。先読みはトラッシュの決定のすべての答えを試す（`legacy` でも、この型は v0.13 の止める関数で確かめる型 `VERIFIED` に入れず、すべての結果を試す方法で確かめる） | v0.16c・v0.17d の約束 |

型の `check`（合わない登録のカードは未対応になる。効果のないワザとして扱わない）: ダメージの目安が 10 の倍数の正の数・目安に「×」「+」「−」がない・
説明文がある・必要なエネルギーにトラッシュするタイプがある・トラッシュするタイプが「炎」（記録の未解決の問いのため、炎以外のワザに当てはめない）。

要素の並び（`programs.BUILDERS`）:

```
DiscardEnergyThenDamage(炎)            → DiscardOwnEnergy(炎), Damage(OPP, Printed())
DiscardEnergyAndRemoveAllCounters(超・水) → DiscardOwnEnergy(超・水), HealAllCounters()   （v0.29 までは DiscardEnergyHealAll の 1 つ）
```

### 3.2 研究の対応表（`kyuura_engine/data/research_links.json`）

- `latest_descriptions.errata_text`（v0.30）: 処理に使う文面を kyuura のエラッタ（ERR-・TXT-・RUL-）にした登録。4 つ（ひのこ・かえんほうしゃ 3 つ）が

  範囲に書かずに記録が挙げないカードにエラッタの文面を使う、を拒否する）。
- `adopted_printed_text`: とっしん（PMCG1-019/attack/1）・第4弾のポニータのひのこ（PMCG4-013/attack/0）を加えた（16 件）。
