# v0.198: ラッキースタジアムの別の個体の同じ番の使用のプレイ用の続行規約（開発用の集合 CS-KYUURA-PLAY-TR8@1）

2026-11-23。`kyuura_engine` の版は 0.198.0 です。

- **プレイ用の取り決めです。** 史実の裁定は確定していません。停止コード `UNRESOLVED_STADIUM_REUSE_AFTER_REPLACEMENT`（RS1）は、厳密側・既存の集合・事例 `#other` で active のままです。kyuura の論点も解決にしていません。
- **既定では有効になりません。** 省略したときの集合は `CS-KYUURA-CURRENT@1` のままです。`new_game(..., conventions="CS-KYUURA-PLAY-TR8@1")` のように明示して選んだ対戦だけで当たります。
- **規約の中身:** 規約 `PC-LUCKY-STADIUM-REPLACEMENT@1` は、「自分の番ごとに1回」と書かれたラッキースタジアムをこの番に使ったあと、同じ名前の別の個体に入れかわったとき、その個体を 1 回使えるようにします。回数は、プレイヤー・自分の番・カードの個体で数えます。
- **当たる条件:** 場のカードと、この番の同じ名前の記録のすべてが、効果の登録の型 `CoinDrawStadium` で `once_stated` のときだけです。
- **設計:** [rs1-lucky-stadium-replacement-design](rs1-lucky-stadium-replacement-design.md) 12 章。この版の実測は同じ文書の 13 章にも書きました。

## 3. 実装

- **回数の確かめ**（`effects._check_stadium_use_count`）: 判定の順番は今のままです（SX2 → 同じ個体の 2 回目 → STB1 → LK1 → RS1）。RS1 の分岐だけで、事例を決めて続行規約を引きます（`stadium_reuse_case` → `continuation_for(state, RS1, case)`）。
  - 規約があれば受け付けます。
  - なければ `stop_without_continuation` のあと、今と同じコード・同じ文で止めます。
  - 事例は効果の登録の型で決め、カード ID では分けません。
- **候補 API と直接のコマンド:** どちらも同じ確かめ（`engine.check_use_stadium` → `CoinDrawStadium.check_activation`）を通ります。候補の区分・入力・`check` は、この確かめの結果から作られます（`legal_actions` は変えていない）。
- **受理の処理**（`engine._use_stadium`）: 確かめのあと・使った記録を足す前の状態で、同じ照会（`stadium_reuse_continuation`）を引きます。当たったときだけ、`stadium_used` のすぐあと・コインの前に `convention_applied` を 1 回書きます。
- **`convention_applied` の項目:**
  - `convention`・`version`・`scene`（`…#lucky-once-stated-replacement`）・`code`
  - `player`
  - `card`: 新しい個体の uid。場に表で出ている。
  - `used_cards`: この番に使った同じ名前のカードの版（card_id）の並び。
- **設計との差（`used_cards`）:** 設計 12.5 は「使った同じ名前のカード」と書いただけでした。実装では uid ではなく版を書きます。
  - 先に使ったカードは、今は手札や山札にあるかもしれません。その uid を新しいログに書かないためです。
  - 版は、使ったときに場に表で出ていた公開の情報です。
- **停止の方針の台帳:** RS1 を 2 つの事例 `#lucky-once-stated-replacement`・`#other` に分けました（停止コード・理由の文は同じ）。採用の記録は `AGR-PLAY-TR8-SET`・`AGR-PLAY-TR8-LUCKY-STADIUM-REPLACEMENT` で、`DEC-LASTING-READINGS` に 1 事例を加えました。
  - 共通規約の設計案は、`PC-ONCE-PER-TURN-IDENTITY` の対象の場面 ID を事例に合わせただけです。案は proposal のままです。
  - 案の文は「同じ名前に記録が続く・使い直せない」で、今回の採用はその 1 事例を反対の読み方で決めたものです。
- **識別の差（診断）:** RS1 の診断のコード表の項目は、事例が 2 つになったため `case_id` が null、`case_status` が `not_identified` になりました。厳密側の拒否の `diagnostic_id`・区分・文は同じです（ほかの事例のある停止コードと同じ扱い）。
- **ログの監査**（`tests/log_audit.py`）: TR8 の表を加えました。次の 3 つを、監査が独立に照らします。
  - 記録が同じプレイヤーの同じ個体の `stadium_used` のすぐあと・スタジアムのコインのすぐ前にあること。
  - `used_cards` が、この番の同じ名前の使用の版と同じこと。
  - uid を書いていないこと。
- **変えていないもの:** `legal_actions.py`・judge・方策・GUI・既存の集合・既定の集合。

## 4. 適用範囲と識別

- **対象の版:** 登録の全体で、効果の型が `CoinDrawStadium` で `once_stated` が真のトレーナーは 10 版です。NIP2X-009・PRN-015〜PRN-022・neo4-106 で、設計の 10 版と一致しました（テストで登録の全体から求めて照らす）。
- **対象の外の版:** PRN-027 は同じ型で `once_stated` が偽です。
- **先に使ったカードの版:** 版は、使用の記録の uid から `CardInstance.card_id` で引きます。対戦の中で変わらず、場所は読みません。
- **非公開の場所への移動:** 先に使った A を手札（ダウジングマシーン）・山札（リサイクル）へ移したあとの B を、双子で比べました。双子は、手札のほかのカードの構成、山札のほかのカードの並びだけを変えています。
  - 結果: 判定・公開の規約の記録・相手と観戦者の閲覧で見える新しいログは、双子で同じでした。新しいログに A の uid は出ません。
  - 限界: リサイクルは A を山札のいちばん上に置きます（公開の操作）。そのため、山札の中での A の位置は双子で同じで、変えたのはほかのカードの並びだけです。
