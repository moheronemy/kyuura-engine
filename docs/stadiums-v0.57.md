## 1. 資料と規定の範囲

- スタジアムの一般の規定は、kyuura の rule_differences の「stadium」の 2000.02.14 版の行と、場の定義（GR-2000-P312-FIELD）を再利用しました: スタジアムカードはトレーナーカードの
  種類のひとつ（kyuura の種類 `stadium`）で、自分の場と相手の場の境界線上に出し、両方の場に出ているカードとして扱う。場に出ているスタジアムは 1 枚で、新しいスタジアムが場に
  出たら古いものをトラッシュする（14 枚の印刷の文面のどれにもある）。
- 2003 年の規定（kyuura `MIX-ADV-RULES-2003` の「これまでトレーナー「スタジアム」は、1回の自分の番に何枚でも出すことができたが、1枚だけになった」）は 2000.02.14 版のあとの変更
  なので使いません。1 番に出せるスタジアムの枚数は制限しません。同じ名前のスタジアムを出すことも制限しません（同じ名前でも別のカードとして入れかわる）。
- 印刷の文面の置き方の文は 3 通りの書き方（「別のスタジアムカードが場に出た時、このカードをトラッシュする」「新しいスタジアムカードが場に出た時、古いスタジアムカードは
  トラッシュされる」「このカード以外のスタジアムカードが場に出た時、このカードをトラッシュする」）があり、どれも同じ処理です（型の `check` が文面に「バトル場の横に出して使う」
  と、どれかの文があることを確かめる）。
- 関連するカード（「タケシの」「カスミの」などのポケモン、タケシのゴローンなど）は、このバッチでは加えていません。スタジアムの効果がそれらにはたらくことは、すでに対応している
  「○○の」ポケモンで確かめ、未対応のカードはあとで同じ処理を再利用する対象として記録します。

## 2. 共通の処理

1. **場のスタジアム**（`GameState.stadium`。`state.StadiumInPlay(owner, card, placed_turn)`）: 実際のカード 1 枚だけを持ちます。効果は問い合わせのたびに、効果の登録表のその
   カードの実装（`effects.StadiumEffect` の部分型）から求めます（`stadiums.stadium_in_play`・`effects.stadium_of`。型で探す）。効果の結果を状態・カードの定義・共有するルールの値
   （`RuleSet`）に写しません。スタジアムが場をはなれたら、効果も問い合わせから消えます。かがくへんかガス・特殊状態ではスタジアムの効果は消えません（特殊能力ではない）。
2. **手札から出す**（`PlayTrainer`。`engine._play_stadium`・`zones.place_stadium`）: トレーナーカードを使うことなので、トレーナーの使用の禁止（［アレルギーかふん］・ずつう・
   こうしゅうは・ロケット団の実験の「うら」）で止まります。使いすてのトレーナーとしてトラッシュせず場に出し（ログ `stadium_placed`）、古いスタジアムを持ち主のトラッシュに
   すてます（ログ `stadium_discarded`。持ち主はそのカードの持ち主で、出したプレイヤーではない）。場に出た時の効果（せまいジム）があれば決定を出します。錯乱ジムのコインは
   スタジアムカードには投げません（「スタジアムカード以外」）。
3. **自分の番に使う効果**（新しいコマンド `UseStadium(player, energy=None)`。`engine._use_stadium`）: タマムシシティジム・セキチクシティジム・ヤマブキシティジム。自分の番の
   `Phase.MAIN` だけ。使う（ログ `stadium_used`）→「自分の番ごとに1回」なら記録（`GameState.stadium_uses_this_turn` の (使ったプレイヤー, スタジアムカード)。ログから数えない）→
   実装の `activate`。決定は再開先 `"stadium"`（`engine._resume_stadium`。段階 `narrow`・`fuchsia`・`evolution_heal`）。終わったら `resolution.after_stadium` が、空いたバトル場の
   勝ち負けの判定 → バトル場に出す決定 → 同じ番の `Phase.MAIN`（v0.42 の `after_power` と同じ形。きぜつはない）。場にスタジアムがなければ `NO_STADIUM`、場のスタジアムに使ってよい効果がなければ `STADIUM_NOT_USABLE`。
   トレーナーカードを手札から使うこと・特殊能力の使用ではありません。トレーナーの使用の禁止がはたらいているプレイヤーが使えるかは STB1（7 章）。
4. **ダメージの計算**（`damage.calculate_with_stadium`・`effects.stadium_damage_options`）: ニビシティジム（p.321 の 4 段階を計算しない）・グレンタウンジム（3 段階を計算しない）・
   抵抗力低下ジム（今有効な抵抗力の数をへらす。`effects.resistance_of`・`definition_views`）・クチバシティジム（6 段階の + 10）。ワザのダメージ（`kernel.deal_damage`）と宣言の
   前の計算（`preview_attack_damage`）が同じ関数を使います。
5. **にげるの数**（`effects.retreat_cost` の `stadium_increases`・`stadium_reductions`）: ロケット団の特訓ジム（決まって + 1）・ハナダシティジム（「カスミのポケモン」は決まって
   − 1。0 より小さくならない）。決まって変える数なので、にげるサポート（「少なくできる」）とは別に記録し、選べません。特殊能力の増減（［ねんちゃくえき］・［にげるサポート］）と
   重なり、下限 0 の当てはめ方で答えが変わる数は v0.46 の CP2（`UNRESOLVED_RETREAT_COST_FLOOR`）で止めます（`RetreatCost` の `floor_first_*`・`floor_ambiguous`。新しいコードに
   しない）。数が変わったときだけ、ログ `retreat` に `retreat_cost_stadium` を書きます。
6. **ベンチの数**（`stadiums.bench_limit`・`bench_has_room`）: せまいジムの「4匹まで」。ベンチに出すどの経路（手札から・山札から・トラッシュから・効果で出させる・ポケモンとして
   出すトレーナー・道具や検証の手順）も、ベンチに空きがあるかをこれで確かめます。共有するルールの値（`rules.max_bench`。5 匹）は変えません。
7. **反応**（スタジアムが決まった処理の中ではたらく効果）: ロケット団の爆発ジム（手札からたねポケモンをベンチに出す時）・トキワシティジム（進化させる時）・リムーブ禁止ジム
   （トレーナーを使う時）・錯乱ジム（トレーナーを使う時）・クチバシティジム（ワザを使う時）。それぞれ決まった処理の入口から問い合わせます（3〜7 章）。
8. **書き出し**（形式 17）: 8 章。

## 4. 自分の番に使う効果（タマムシ・セキチク・ヤマブキ）と STB1

- **タマムシシティジム**: `UseStadium(player, energy)` の `energy` は、トラッシュするエネルギーカード（自分の「エリカのポケモン」についているもの。基本エネルギーに限らない）。
  そのカードがついているポケモンの特殊状態（どく・ねむり・マヒ・こんらん）をすべて回復します（`conditions.clear_special_conditions`。理由 `cured`。ダメージ・持続する効果は
  変えない。ログ `stadium_discard_energy`）。回数の制限は書かれていないので数えません。そのポケモンに特殊状態がなければ TG1（ほかの確認のあと・トラッシュの前）。
- **セキチクシティジム**: 使う（記録。コインの「うら」でも使ったことになる）→ 使ったプレイヤーがコインを 1 枚（`source="stadium"`）→「おもて」なら、自分の場の「キョウの
  ポケモン」を選ぶ（決定 `SELECT_POKEMON`。1 匹でも選ぶ）→ そのポケモンと、ついているすべてのカードを持ち主の山札にもどし（v0.36 の `zones.return_in_play_to_deck`。
  ログの出どころ `stadium_card`。持続する効果を理由 `return_in_play_to_deck` で消す）→ 切る。きぜつではありません（サイドはない）。バトル場のポケモンをもどしたら、
  `after_stadium` が勝ち負けの判定 → バトル場に出す決定へ進みます。回数は (使ったプレイヤー, スタジアムカード) で数え、同じカードで 2 回目は `STADIUM_ALREADY_USED`。この番に
  別のセキチクシティジムのカードで使っていたら FG1、自分の場に「キョウのポケモン」がいなければ FG2（どちらもコインの前）。カードの持ち主でないプレイヤーも使えます（「お互いの
  プレイヤーは」）。
- **ヤマブキシティジム**: `energy` は、手札に加える基本エネルギーカード（カードの種類で決める。エナジーバーンなど今出しているエネルギーのタイプでは決めない）。1 回の使用で 1 枚
  （何度でも使えるので何枚でもはがせる。実装上の仮定。v0.7 のダメージスワップの S3 と同じ形）。ログ `stadium_return_energy`。手札からつける通常の操作の回数・特殊能力でつけた
  枚数は変えません。はがして最大HPがのっているダメージ以下になる（ナツメのゴースの［ガスのからだ］）なら、エンジンの共通の MH1 で受け付けません（新しいコードにしない）。
- **STB1**: トレーナーカードの使用の禁止がはたらいているプレイヤーが、場のスタジアムの効果を使えるかは決まらないので、ほかの確認のあと・状態を変える前に止めます（7 章）。

## 5. ベンチ・進化・ベンチに出す時の反応（せまいジム・トキワシティジム・ロケット団の爆発ジム）

- **せまいジム**: 場に出た時（`on_placed`）、ベンチが上限（4 匹）より多いプレイヤーが、それぞれ自分のベンチから 1 匹を選びます（決定 `STADIUM_RETURN_BENCH`。決めるのは
  ベンチの持ち主。再開先 `"stadium"`。段階 `narrow`）。もどすのは v0.42 の `zones.return_in_play_to_hand`（ポケモンと、ついているすべてのカード。ログの出どころ `stadium_card`。
  持続する効果を消す）。きぜつではありません。両方のプレイヤーが 5 匹なら、番でないプレイヤーが先です（実装上の順番。日本語の印刷の文面に順番はなく、英語版の「your opponent
  returns a Pokémon first」は根拠にしない。選べるものは自分のベンチなので、どちらが先でも結果の場は同じ。pp.323〜324 のバトル場に出す順番と同じ向きにそろえた）。決定を待つ
  間だけ、そのプレイヤーのベンチが上限より多いことを不変条件が許します（`engine._narrow_cleanup_pending`。広げない）。せまいジムが場をはなれたら 5 匹にもどります（手札にもどした
  ポケモンは自動では場にもどらない）。
- **トキワシティジム**: 進化させるすべての経路（手札からの進化 `EvolvePokemon`・ポケモン育て屋さん・ワザで山札から重ねる進化（つきのちから・たきのぼりしんか））で、進化の手順
  （`evolution.place_evolution_card`）のあと、場に出たときに使える特殊能力の機会（v0.43）の前に、持ち主に聞きます（`effects.offer_evolution_heal`。決定 `EVOLUTION_HEAL`。0〜1 個。
  選ばない = とりのぞかない。続きの情報の `after_heal` にもとの処理。ログ `evolution_heal`・`evolution_heal_declined`）。「サカキのポケモン」は、進化させるポケモン（重ねる前の今の
  姿の名前）で決めます（写しの「サカキの」系統はどれも進化先も「サカキの」）。のっているカウンターが 0 なら聞きません。1 つだけなら VG1（選ぶと止める。選ばないことは受け付ける）。
  進化したあとの HP がダメージ以下になる組は、とりのぞく前の進化の確認（H1。`UNRESOLVED_EVOLUTION_HP`）で止めます（とりのぞくことで H1 を避けない）。「ばける」は進化ではない
  ので当てはまりません。特殊能力で重ねる進化（［うか］）で「サカキのポケモン」を進化させるカードは写しになく、来たら `RuntimeError`（エンジンの制限）です。
- **ロケット団の爆発ジム**: 当てはまるのは、手札のたねポケモンのカード（手札にある間の印刷の分類。なにかの化石・ピッピ人形は手札ではトレーナーカードなので当てはまらない）を
  ベンチに出す経路だけです（通常の操作 `PlayBasicToBench`・エリカの香水で出させる（持ち主は相手））。山札・トラッシュから出す・場のポケモンを動かす・手札からバトル場に出す
  （マチス）は当てはまりません。コインは持ち主が投げ（`source="stadium"`）、「うら」なら 20 ダメージ（ログ `stadium_damage`）。ダメージカウンターではなくダメージです（英語版の
  「put damage counters」を根拠にしない）。ワザによるダメージではないので、弱点・抵抗力・プラスパワー・ディフェンダー・「ダメージを受けない」状態・「とうめい」・「ダメージを
  受けたとき」の効果を当てはめません。受けるダメージ全体を書く常にはたらく特殊能力（［カブトアーマー］）を当てはめると量が変わるなら、EX1 でコインの前に止めます（v0.47 の KA1 と
  同じ問いの形の、別のダメージの問い）。今の写しのたねポケモンの HP はどれも 30 以上で、出したばかりのポケモンにダメージはないので、このダメージではきぜつしません（起こったら
  エンジンの不具合として `RuntimeError`）。

## 6. ワザを使う時のコイン（クチバシティジム）と VM1

- 投げるかは、ワザの宣言といっしょに選びます（`UseAttack(..., stadium_coin=True)`。既定の False は辞書に書かない）。場のスタジアムがクチバシティジムで、自分の番に、ワザを使う
  ポケモンの今の姿の名前が「マチスの」で始まるときだけ受け付けます（`effects.stadium_attack_coin_available`。ほかは `STADIUM_COIN_NOT_AVAILABLE`）。宣言が拒否されたらコインは投げません。
- コインは、ワザの宣言（p.309 の手順 3）のあと・ワザの要素の前に、ワザを使ったプレイヤーが投げます（`resolution.flow._stadium_attack_coin`。ログ `stadium_attack_coin`）。
  結果はそのワザの間（決定をまたいでも。続きの情報の `stadium_coin`）同じで、投げ直しません。
- 「おもて」: そのワザの相手の対戦ポケモンへのダメージの要素に、p.321 の 6 段階（スタジアム。kyuura の GR-2000-P321-DAMAGE-ORDER の「それ以外の効果」）で + 10（2 段階で 0 以下

## 7. トレーナーを使う時の反応（リムーブ禁止ジム・錯乱ジム）と CH1

- **リムーブ禁止ジム**: 当てはまるトレーナーは、登録の名前（「エネルギーリムーブ」「超エネルギーリムーブ」）と、トレーナーカードの名前を「・」を除いて比べて決めます（文面の
  「エネルギーリムーブ」とカードの名前「エネルギー・リムーブ」の書き方の違い。カード id では分けない）。追加の条件は、このカードを除く自分の手札が 2 枚以上（足りなければ
  `INSUFFICIENT_CARDS_IN_HAND`。カード自身の使うための条件の確認のあと・手札から出す前）。払うのは手札から出したあと・カードの効果の前（決定 `DISCARD_FROM_HAND`。再開先
  `"trainer"`。続きの情報の `stadium_cost`）。そのあと、カード自身の効果（超エネルギーリムーブの自分のエネルギーのトラッシュなど）を今までどおり処理します（二重に払わない）。
- **錯乱ジム**: コインは、手札から出して相手に見せ、名前を伝えたあと（p.310 の手順 1・2。ログ `play_trainer`）、使うための条件を払う前に、使ったプレイヤーが投げます（ログ
  `chaos_check`）。使うための条件を満たせるかは、手札から出す前に今までどおり確かめます（満たせないカードは使えない。コインを投げない）。「おもて」なら今までどおり使います。
  「うら」なら使ったプレイヤーは使えず（条件を払わない）、相手プレイヤーが使えるかを確かめます: ポケモンにつけて使うカード・場に出して使うカード（`stays_in_play`・`enters_play`。
  プラスパワー・ピッピ人形など）は使えない（ログ `chaos_not_borrowable`）、使うための条件を相手として満たせない・相手がトレーナーを使えない（禁止）なら使えない。使えるなら相手
  プレイヤーに聞きます（v0.56 の決定 `ACCEPT_REQUEST`。決めるのは相手。続きの情報の `chaos`。答えはログ `chaos_answered`）。使うなら、そのカードの説明の「あなた」は相手プレイヤー
  （手札・山札・場・トラッシュは相手のもの）で、`TrainerInUse.user` に記録し、処理は `using_player` を見ます。番のプレイヤーは変えません。同じ使用で錯乱ジムのコインを 2 度
  投げません。使ったトレーナーカード・使えなかった・使わなかったカードは、どれも持ち主のトラッシュにすてます。
- **CH1**: 相手プレイヤーがかわりに使うトレーナーの説明が、使ったプレイヤーの番（「この番」「次の相手の番」「あなたの番は終わりになる」・自分のポケモンを進化させる時など）を書く
  とき（`TrainerEffect.refers_to_user_turn`）、相手の番の中で使った場合にどの番を指すか・できるかは決まらないので、相手プレイヤーが使うことを選ぶと止めます（選ばないことは
  受け付ける。どの答えも止まる決定を残さないよう、相手プレイヤーに聞く決定は「使わない」がいつも答えになる）。
