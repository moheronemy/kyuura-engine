# v0.100: スケッチ・ほろびのうたと、前の相手の番のワザの記録・ワザの効果による「きぜつ」

v0.100 は、ドーブル（「スケッチ」）・ムウマ（「やみのひとみ」「ほろびのうた」）の 2 枚を、ワザ 3 とともに登録する版です。「スケッチ」の「前の相手の番に、相手のポケモンがワザを
使っていたなら」のために、場のポケモンの履歴（v0.62）とは別に、プレイヤーの番ごとの短い記録（使ったワザ・番でないプレイヤーの場にいたカード）を加え（書き出しの形式 26）、
「ほろびのうた」の「相手は「きぜつ」する」のために、ワザの効果による「きぜつ」の原因を運ぶ共通の処理を整えました。先に、v0.99 の略号 PF1 の重なりを PFM1 に分けて直しました。
写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）です。

## 3. 前の相手の番のワザの記録（共通の処理）

v0.99 までの履歴（v0.62。`PokemonInPlay.history`）は場のポケモンごとの記録で、`AttackUsed`（このポケモンが使ったワザ）・`AttackReceived`（このポケモンが受けた相手のワザと結果。
v0.99 の `active_damage` は受けた場所ごとの量）です。これは「スケッチ」の「前の相手の番に、相手のポケモンがワザを使っていたなら」の代わりになりません。相手のワザをドーブルが受けなかった
（ダメージのないワザ・自分の場だけに作用するワザ）・ワザを使った相手のポケモンがそのあと場をはなれた（手札・山札にもどる・きぜつ・みずからきぜつ）・ベンチにもどった・今の相手の対戦
ポケモンが別の個体になった、のどれでも、今の場の個体から探すと事実が失われるためです。

| 記録 | 型 | 内容 | 作る時点 | 読むワザ |
|---|---|---|---|---|
| 使ったワザ（プレイヤーの記録） | `TurnAttack(turn, player, pokemon_id, card, declared, processed)` | 番のプレイヤーがその番に宣言したワザと、相手のワザなどを自分のワザとして使ったときの処理したワザ。ワザを使った場のポケモンの番号・いちばん上のカードは過去の参照 | ワザの宣言（p.309 の手順 3。`history.note_used`）・切りかえ（`note_processed`）。場のポケモンの `AttackUsed` と同じ時点 | スケッチ |
| 番でないプレイヤーの場にいたカード | `TurnField(turn, player, cards, face_down)` | 番の始めに場にいたポケモンのカード（重なり・のせたカードを含む）と、その番に場に出たカード。うらのカードは数だけ | 番の最初（`history.note_turn_start`。古い記録を消したあと）・場に出たとき（`zones.enter_play` → `note_entered`） | スケッチ（このカードが場に出ていたか） |

- 置き場所は `GameState.turn_history`（番の順。場のポケモンとは別）。ワザを使ったポケモンが場をはなれても、ベンチにもどっても、記録は残ります。記録の場のポケモンの番号・カードの uid は
  過去の参照で、ログ・確かめにだけ使い、新しい操作の対象にしません（スケッチは記録のワザの要素を新しく処理するだけで、使ったポケモンを読まない）。履歴からワザを読むために、元のポケモンを
  場に残しません。
- 宣言の前の拒否（エネルギー不足・使うための条件・先読みの停止）は状態ごと捨てるので、記録は残りません。宣言のあとの失敗（手順 4・こんらんの「うら」・ワザの失敗）は使ったことになります
  （v0.44・v0.62 の採用済みの時点のまま。変えていない）。
- 宣言したワザ（`declared`）と処理したワザ（`processed`）を区別します（ゆびをふる・オウムがえし・スケッチで切りかえたら `processed`。v0.62 の `AttackUsed` と同じ）。
- プレイヤーの記録を読むワザ（`AttackEffect.reads_turn_history`。スケッチ）のカードが対戦にあるときだけ記録します（`history.turn_history_needed`。場のポケモンの履歴の `history_needed` と
  別に決める）。ムウマだけの対戦は場のポケモンの履歴だけを、どちらもない対戦は v0.99 と同じ状態を持ちます（`TurnHistoryTest.test_records_only_when_a_reader_is_in_the_game`）。保持するのは
  場のポケモンの履歴と同じ 2 つ前の番まで（番の最初に `history.prune` が消す）で、全対戦の履歴にしていません。
- 「このカード」とプレイヤーに残す過去の事実を区別します。場のポケモンの履歴は今の「このカード」（いちばん上のカードと今の姿になった番。進化・退化で消し、場をはなれて出し直したら別の
  ポケモン）のままで、プレイヤーの記録は「相手がワザを使った」「そのカードが場にいた」という事実です。既存のドリルホール・2 種のオウムがえし・［PERFORM］・ひれがえしの記録は変えていません。
- 記録は処理のときに状態へ書き、実行のときの判断をログの逆算で代用しません。番の途中から作った状態（v0.99 までの状態の写し・テストの盤面）では、番の始めの記録を途中から作らず
  （`note_entered`・`note_processed` は何もしない）、あとで読むときに情報の不足として止めます（`MidTurnStateTest`）。
- 記録がないことと、実際にワザを使わなかったことを区別します。前の相手の番の `TurnField` があれば、その番は記録していたので、`TurnAttack` がなければ「ワザを使わなかった」。`TurnField` が
  なければ（v0.99 までの状態の写しは項目がなく、既定値の空）、エンジンの情報の不足 `UNSUPPORTED_HISTORY_TURN_RECORD_MISSING`（研究上の未解決ではない。宣言の前の先読みで拒否する）です
  （`SketchPresenceTest.test_missing_records_are_not_read_as_no_attack`）。
- 不変条件（`engine._turn_history_problems`）: 読むカードのない対戦では空、型、番の範囲と順、`TurnAttack` は番ごとに 1 つでその番のプレイヤーのもの・ワザは登録表にある、`TurnField` は番ごとに
  1 つでその番でないプレイヤーのもの・カードはそのプレイヤーの重ならない uid・うらのカードの数は 0 以上。

## 4. ドーブル「スケッチ」

「前の相手の番に、相手のポケモンがワザを使っていたなら、そのワザを、このカードが持っているワザとして使う。(そのワザに必要な「エネルギー」がついていなくても、かまわない。)前の相手の番、
このカードが場に出ていなければ、このワザは失敗する。」

### 4.1 処理の順番と結果

| 場面 | 結果 | ログ |
|---|---|---|
| このカードが前の相手の番に場に出ていなかった（今の番に場に出た・今の姿になったカードで、前の相手の番に場にいたカードの記録にない） | ワザの失敗（p.323「12」。使ったことになり、番は終わる。宣言の拒否にしない） | `attack_failed`（`reason` `not_in_play`） |
| 場に出ていたかが読み方で変わる | SK1（宣言の前に止める） | なし |
| 場に出ていて、前の相手の番に相手がワザを使っていない | 処理の対象がないので何もしない（p.309。失敗ではない） | `sketch_none`（`reason` `no_attack`・`used_turn`） |
| 使ったワザが、相手のワザなどを自分のワザとして使ったもの | SK2 | なし |
| 使ったワザを、このカードのワザとして処理できない（使うための条件をみたさない・まねるワザ・1 度だけ使えるワザなど） | HC9（`UNRESOLVED_COPIED_ATTACK`）・エンジンの未対応（`UNSUPPORTED_COPIED_ATTACK`） | なし |
| そのほか | そのワザの要素の並びに切りかえ、このワザの枠の中で、このカードのワザとして処理する | `copy_attack`（`used_turn`・`used_by`） |

- 失敗の確かめは、前の相手の番のワザの記録より先です（場に出ていなければ、相手のワザによらず失敗する）。
- 読むのは前の相手の番（今の番の 1 つ前）の、相手（番のプレイヤーの相手）が使ったワザのプレイヤーの記録です。日本語にない「今の相手の対戦ポケモンが使った」「ドーブル自身が受けた」の限定を
  加えません。ロコンが「あやしいひかり」を使い、番の終わりのどくできぜつしてパラスに交代しても、スケッチは「あやしいひかり」を使います（`TurnHistoryTest.test_attack_record_survives_the_attacker_leaving`）。
- 相手の前の番のワザが宣言のあとに失敗していた（こんらんの「うら」など）ときも、使ったことになるので、そのワザを使います（`SketchTest.test_failed_original_attack_still_counts`）。

### 4.2 「このカードが場に出ていなければ」（SK1）

- 既存の `played_turn`・`current_form_turn` は、このポケモンが場に出た番・今の姿になった番です。場をはなれて出し直すと新しくなる（v0.2a の場のポケモンの番号の規則・p.310 の
  「その番に場に出した」）ので、「前の相手の番に場にいたカードを、そのあと出し直した」場合の区別を失います。それを保つため、番でないプレイヤーの場にいたカードの記録（`TurnField`）を
  加えました。
- 今の姿になった番が前の相手の番より前なら、前の相手の番の始めから同じポケモンとして場にいました（場に出ていた。ドーブルはたねポケモンで進化・退化しないので、場に出た番と同じ）。
  ベンチにいた・バトル場に出し直した（入れ替え・にげる）は、場所を問いません。
- 今の番に場に出た・今の姿になったカードで、前の相手の番に場にいたカードの記録になく、うらのカードもなかったなら、場に出ていなかった（失敗）。
- 読み方で失敗するかが変わる境界は SK1（`UNRESOLVED_SKETCH_PRESENCE`）で止めます。kyuura の記録（cards.json・カードの裁定・論点・ルールの歴史）に「場に出ていなければ」を決める記録は
  ありませんでした（文字列で探した）。英語版の「Smeargle was in play during that attack」を、日本語の条件に無条件で足していません。
  - 前の相手の番の途中に場に出た（相手のポケモンの笛・エリカの香水で自分のベンチに出された）: 「その番に場にいた」か「その番の始めから」かで変わる
  - 前の相手の番に場にいたカードを、そのあと場をはなれて今の番に出し直した（ピジョットのハリケーンで手札にもどされたなど）: カードとしては場にいたが、場のポケモンとしては別
  - 前の相手の番に、自分の場にうらのカード（マチスの秘策）があった: 正体を記録しない（7 章）ので、今の番に出したドーブルがそのカードでないと言えない（うらのカードの正体を読まず、正体に
    よらず同じ答え）
  - 前の相手の番がない（先攻の最初の番。対戦準備は相手の番ではない）: 失敗するか、何もしないか
- 隣の止まらない例: 前の相手の番の始めからベンチにいたドーブル（使う）・手札にあった別のドーブルを今の番に出した（失敗）（`SketchPresenceTest`）。

### 4.3 「そのワザ」（SK2）とまねるワザ

- 前の相手の番に相手が使ったワザが、相手のワザなどを自分のワザとして使ったもの（ゆびをふる・スケッチ・オウムがえしで切りかえた。宣言したワザと処理したワザが違う）なら、「そのワザ」が
  宣言したワザか処理したワザかで結果が変わるので、SK2（`UNRESOLVED_SKETCH_COPIED_ATTACK`）で止めます。ピジョンの MM1 は「前の相手の番で受けた「ワザ」」の問いで、文面が違うので、
  一律に当てはめていません。
- 切りかえずに何もしなかったまねるワザ（受けた記録のないピジョンのオウムがえし）は、宣言したワザだけで、それをさらに自分のワザとして使うので、既存の HC9（v0.62 のオウムがえしの
  `copy_problem` の未解決）のままです。相手のドーブルにゆびをふるを使うと、選べるワザがスケッチだけで処理できないので、答えのない決定を出さず、宣言の前に HC9 で止めます
  （`CopyInteractionTest`）。スケッチをゆびをふる・オウムがえしで使うのも同じ（`UseLastOpponentAttack.copy_problem` は UNRESOLVED）。無限の切りかえを許していません。

### 4.4 そのワザを新しく処理する

- 元のワザの結果・ダメージの量を再現するのでなく、そのワザの要素の並びを、このワザの枠の中で、このカードのワザとして新しく処理します（v0.31 の `CopyOpponentAttack`・v0.62 の
  `RepeatReceivedAttack` と同じ `run.redirect`）。コインと選ぶものは新しく決め、タイプ・弱点・抵抗力・「このカード」・自分/相手は使う側です。元のワザの使用者・過去の対象・過去の乱数に
  結びつけません。
  - みだれづき: 相手の前の番の 0 を写さず、新しくコインを投げて 20（`SketchTest.test_uses_the_attack_with_new_coins`）
  - あやしいひかり（炎）: ドーブル（無色）のワザなので、パラスの弱点「炎」は当たらない（10）
  - ひれがえし: 「このカード」はドーブル（前の相手の番にドーブルが受けたダメージで +10）
  - ふきとばし: 入れ替える控えは相手が選ぶ決定のまま。決定は続きの情報の `copied` のワザの宣言に委ねる（`UseLastOpponentAttack.decision_problems`）。複製・deepcopy・pickle から同じ答えで
    同じ結果、不正な答えは状態・乱数・ログを変えない、決定のあとで切りかえ・コイン・使った記録を重ねない（`SketchTest.test_decision_in_the_copied_attack`）
- 切りかえたら、使ったワザの記録（場のポケモンの `AttackUsed`・プレイヤーの `TurnAttack`）の処理したワザに、使ったワザを書きます（v0.62 の `note_processed`）。

### 4.5 必要なエネルギーと、ほかの条件

- スケッチ自体の無色 2 個は通常どおり要ります（`INSUFFICIENT_ENERGY`）。免除するのは、使うワザに必要なエネルギーだけです（ギャラドスの「りゅうのいかり」（水水水）を無色 2 個のドーブルが使う）。
- 日本語は、エネルギー以外の使うための条件までは免除していません（kyuura の card_differences の日英の違いの記録）。使うワザの条件は、既存の `copy_status`・要素の `copy_problem` で確かめます。
- `FOLLOW_TEXT`（説明にしたがう）は、ピッピの「ゆびをふる」の kyuura の card_differences の PMCG1-067 の記録（最新の説明と、p.223 の解説「基本的にワザに必要なエネルギー以外はワザの
  説明にしたがいます」）を根拠にした区分で、ドーブルには同じ記録がないので当てはめませんでした。スケッチの印刷の文面は、条件をみたさないときの処理を書かないので、同じかっこ書きを持つ
  カスミのコダックの「ちょうのうりょく」と同じ `clause` なし（条件をみたさなければ決められない。HC9）です。たとえばヤドンの「ぼーっとする」（このカードにダメージカウンターがのってない時には
  使えない）を、ダメージのないドーブルが使う場面は HC9 で止め、のっていれば使います（`SketchTest.test_other_conditions_are_not_waived`）。条件を免除して処理することはしていません。
- ピジョンの MM2（出すワザの必要なエネルギーをピジョンのエネルギーで払えるかを確かめる）は、エネルギーを免除するスケッチに持ち込んでいません。
- エネルギーをトラッシュするワザの処理（RUL-ENERGY-DISCARD-ATTACKS の範囲の最新の記述など）は、そのワザの登録と既存の `copy_problem` のままです（2.2 節）。

## 5. ムウマ「やみのひとみ」「ほろびのうた」

「やみのひとみ」「相手を「ねむり」状態にする。」

「ほろびのうた」「このワザを受ける相手が「ねむり」状態で、前の自分の番に「やみのひとみ」を受けていたなら、相手は「きぜつ」する。」

### 5.1 やみのひとみ

- ダメージなしで相手をねむりにする既存の型（`PutToSleep`）です。バリアー・とうめい・効果だけを無効にする効果・［めんえき］などは、通常の効果の経路（`kernel.reaches`・
  `conditions.put_to_sleep`）を通り、受けた記録の受けた要素・受けなかった要素にも、v0.62 からの意味で残ります。もとからねむりの相手は、受けた要素 sleep（二重のねむりにはならない）。

### 5.2 ほろびのうたの順番

1. 相手の対戦ポケモン（このワザを受ける相手）が今ねむりでなければ、何もしない（「とうめい」も評価しない。v0.72 の「めざめのキッス」と同じ順番。受けた記録も読まない）
2. 前の自分の番（今の番の 2 つ前）に「やみのひとみ」を受けていたかを、相手のポケモンの受けた記録で照らす（5.3 節）。受けていなければ何もしない。決まらなければ PSG1
3. 相手がこのワザの中で HP 以上なら処理の対象がない（こんじょうを使えるなら既存の G37）
4. 相手への効果として「ワザをうけない」状態・「とうめい」・効果だけを無効にする効果を評価する（`KNOCK_OUT_ELEMENT`。`opponent_effect_elements` に宣言し、先読み・G37 の確かめを飛ばさない）
5. 受けるなら、ダメージによらず「きぜつ」させる（6 章）

- 1・2 は別々に読みます。今のねむりを、過去にやみのひとみを受けた証拠にしません（ほかのワザでねむった相手は「きぜつ」しない）。受けた記録を、今のねむりの代わりにしません（目を
  覚ました相手は「きぜつ」しない）。文面にない「同じムウマから受けた」「途中で一度も目を覚ましていない」の条件は置きません（別のムウマのやみのひとみでもよい）。片方だけなら「きぜつ」
  させず、ワザを使うための条件にもしません（ログ `knock_out_condition` に今ねむりか・受けていたか）。
- ダメージだけを防ぐ状態（ディフェンダー・「ダメージを受けない」状態など）では防がれません（効果）。前の相手の番につけたエフェクトガードがあれば受けません（ログ `effect_prevented`）。

### 5.3 「やみのひとみを受けていた」（PSG1）

受けた記録（v0.62。`AttackReceived`）の意味で読みます（`history.named_attack_received`）。使った記録だけで「受けた」とみなしません。

| 前の自分の番の受けた記録 | 読み | 根拠 |
|---|---|---|
| 処理したワザの名前が「やみのひとみ」で、効果の要素を受けた（ねむりになった・もとからねむり） | 受けた | 受けた記録の C |
| 同じで、［めんえき］でねむりにならなかった | 受けた（今ねむりでないので、ほろびのうたでは「きぜつ」しない） | v0.62 の記録の意味（効果の要素は受けたが特殊状態にならなかった。ピジョンの「受けた」と同じ） |
| 「ワザをうけない」状態（バリアー）・「とうめい」で、どの要素も受けなかった | 受けていない | v0.62 の「どの要素も受けなかった」（ピジョンのオウムがえしは何もしない） |
| 効果だけを無効にする効果（エフェクトガードなど）で受けなかった | 決まらない（今ねむりなら PSG1） | v0.62 のピジョンで、一部の要素だけを受けなかった記録を MM1 にしたのと同じ記録の性質 |
| 宣言したワザと処理したワザが違う（ゆびをふる・スケッチでまねた「やみのひとみ」） | 決まらない（今ねむりなら PSG1） | 同じ（受けたワザが、宣言したワザか処理したワザか） |
| ほかのワザ・記録がない・2 つ前より前の番 | 受けていない | 文面（前の自分の番の「やみのひとみ」） |

- 照らすのは処理したワザの名前（同じ名前の別のカードのワザも同じ）で、カードの id・ワザの位置・使ったムウマに限りません。
- 記録は「このカード」のもの（進化・退化したら別のポケモン。v0.62）です。前の自分の番に受けた相手がバトル場をはなれて別の個体になったら、今の相手は受けていません。
- PSG1（`UNRESOLVED_PERISH_SONG_RECEIVED_ATTACK`）は、今ねむりの相手について、受けたかで「きぜつ」するかが変わる場面だけです。今ねむりでなければ、どの記録でも「きぜつ」しないことが
  決まるので止めません（`PerishSongTest.test_effect_only_voided_night_eyes_is_psg1`・`test_copied_night_eyes_is_psg1`）。

### 5.4 借りたほろびのうた

- ゆびをふる・スケッチで使うほろびのうたは、使うプレイヤーの「前の自分の番」と、今の相手の対戦ポケモンの受けた記録を読みます。印刷したムウマ自身やその持ち主の履歴に固定しません（相手の
  ムウマのほろびのうたをピッピがゆびをふるで使うと、前の自分の番に自分のムウマのやみのひとみを受けた相手のムウマが「きぜつ」する。
  `PerishSongTest.test_metronome_reads_the_user_and_the_current_target`）。

## 6. ワザの効果による「きぜつ」（共通の処理）

v0.99 までの `Resolution.forced`（v0.31）は「みちづれ」のためのもので、原因の枠がない「きぜつ」を特別に扱っていました。これを使うだけでは、こんじょうの候補を求める処理が、相手の番の相手の
ポケモンの「ダメージを受けたときの写しがない」として内部エラーにしていました（盤面で確かめた。`PerishSongTest.test_guts_final_beam_and_rebirth_are_not_offered` は、ガードを外すとこの
内部エラーになる）。

- `kernel.knock_out_by_effect`（新）: ワザの効果で相手のポケモンを「きぜつ」させます。ダメージ・ダメージカウンターをのせず（残りHPぶんの架空のダメージにしない）、ダメージの計算・弱点・
  抵抗力・ダメージを受けたときの効果（はんげきなど）・［ずらかる］・ワザのダメージで HP 以上になった記録（`knocked_by`・`damage_ko`）は起こりません。`res.forced` に加え、原因（ワザを使った
  プレイヤー・ワザを使ったポケモン）を `res.effect_ko` に残します。ログ `effect_knock_out`（そのあとのきぜつの処理は既存の `knock_out`）。
- きぜつの判定・処理は、ワザのあとの既存の処理（`flow._finish_attack`）で HP 以上のポケモンといっしょに扱います（同じワザの中のきぜつは同時。p.324）。サイド・場からのトラッシュ・
  リサイクルエネルギー（持ち主の手札にもどる）・勝ち負け・バトル場に出す決定・きぜつしたときの特殊能力（ふしちょう）・「みちづれ」の判定は、その既存の判定につながります
  （`PerishSongTest.test_recycle_energy_returns_and_last_prize_wins`）。
- 原因の問い合わせ（`kernel.ko_cause`）は、効果の「きぜつ」に (ワザを使ったプレイヤー, ワザを使ったポケモン, ワザの分類) を返します。
  - こんじょう（「相手のワザによるダメージで…「きぜつ」する時」）・きあいのハチマキ（「相手のワザによるダメージで」）・学習装置（「ワザによるダメージを受けて「きぜつ」するとき」）は、
    文面がダメージに限るので候補にしません（`ko_prevention_offers` は効果の「きぜつ」を「ダメージで」ではないとして飛ばす。ハチマキ・学習装置はダメージの記録 `damage_ko` で決める既存のまま）。
  - ［ファイナルビーム］（「相手のワザによって「きぜつ」する時」）は、ダメージに限らないので、原因のワザを使ったポケモンを「きぜつ」させたポケモンとして候補にできます。ほろびのうたの相手は
    ねむりなので、「ねむり・マヒ・こんらん」状態のまま「きぜつ」する時は使えない既存の確かめで使えません。ふしちょうも同じです。
  - 「みちづれ」（原因の枠がない）は v0.31 の扱いのまま（`effect_ko` に入れない。HC2 の未解決を、この共通の処理で解決したことにしていない）。
- 決定をまたいで運びます: ワザの途中の決定の続きの情報の `frame` の `effect_ko`（`AttackRun.suspend`・`restore`）と、きぜつの判定の決定の続きの情報の `effect_ko`（`flow._finish_attack`・
  `_resume_ko_check`。［ファイナルビーム］の決定の不変条件は、効果の「きぜつ」のポケモンに HP 以上のダメージを求めない）。どちらも、なければ書きません（v0.99 までの決定の形は変えない）。
  今の写しでは、ほろびのうたのあとに、きぜつの判定の決定・ワザの途中の決定は起こらないので、運ぶ・もどす関数を直接確かめました（`EffectKnockOutCauseTest`）。
- ほろびのうたと「みちづれ」が同じきぜつの判定で重なる場面（みちづれを使ったゴースが、次の番にねむりで、前の番にやみのひとみを受けている）は、今の写しでは起こりにくく、確かめていません。
  起これば既存の `_destiny_bond` の判定（HC2）を通ります。

## 7. 決定・保存・観測・互換性

- 新しい決定の種類・コマンドはありません。公開の API の呼び方も変えていません。
- 書き出しの形式 26（`serialize.FORMAT_VERSIONS` の最後）: 最上位に `turn_history`（`{"kind": "turn_attack", "turn", "player", "pokemon_id", "card", "declared", "processed"}` と
  `{"kind": "turn_field", "turn", "player", "cards", "face_down"}` の並び）を加えました。プレイヤーの記録は形式 25 までのどこにも表せないので、形式を上げる理由になりました（形式 25 の
  維持のために記録を捨てない）。
  - 形式 1〜25 への書き出し: 記録があると `ValueError`（黙って落とさない）。記録がない対戦（スケッチのない対戦）の書き出しは v0.99 と同じで、全旧形式を一律に拒否しません。
  - 形式 25 までの書き出しを読む側は、記録がないことを「前の番にワザを使わなかった」と読まないこと（serialize.py の説明）。pickle で残した v0.99 までの状態は項目がなく、既定値の空になり、
    スケッチが記録を読む場面だけを `UNSUPPORTED_HISTORY_TURN_RECORD_MISSING` で止めます。v0.99 の［PERFORM］の場所の分からない記録の扱い（`UNSUPPORTED_HISTORY_DAMAGE_PLACE_UNKNOWN`）も
    変えていません。過去の版の形式の期待を、最新の番号へ置きかえていません。
  - 状態の複製（`GameState.clone`。記録は変えないタプルで共有）・deepcopy・pickle で記録を保ちます。新しい汎用の JSON の読込み API は作っていません。
  - ログの監査（`tests/log_audit.py`）の形式の番号（`LATEST_FORMAT`）と項目の表（`TOP_FIELDS_SINCE` の `turn_history`）は、実装から取らずに独立して 26 にしました。
- 観測（`observation.observe`）の最上位に `turn_history`（書き出しと同じ形）を、どの見る人にも書きます。使ったワザ・場にいたカードは、両方のプレイヤーが見た表の情報です。うらのカードの
  uid は書かず（数だけ）、新しい記録・ログ・観測に、非公開の山札・手札の中身を混ぜません。SK1 のうらのカードの場面は、うらのカードの正体を読まず、正体によらない同じ答えです
  （FD1 の場面にしない。`SketchPresenceTest.test_face_down_card_last_turn_is_sk1_without_reading_it`）。新しいログ `sketch_none`・`knock_out_condition`・`effect_knock_out` は公開です
  （`observation.PUBLIC_EVENTS`）。
- 先読み（宣言の前に状態の複製の上で試す処理）は、記録・途中の決定も含めて複製の中で行い、実際の状態・ログ・乱数を変えません。`MAX_BRANCHES` などの上限は変えていません。新しい停止は
  どれも先読みが宣言の前に見つけ、コマンドを受け付けません（状態・乱数・ログを変えない。対戦を HALTED にしない）。
