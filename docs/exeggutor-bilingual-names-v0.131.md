# v0.131: ナッシー[Exeggutor] 2 枚と、日英併記の名前の扱い（利用者の指定）

v0.131（版 0.131.0）は、日本語と英語を併記したプロモのナッシー（PR1-075・PR1-077。写しの名前「ナッシー［Exeggutor］」）を登録する版です。英語の併記が名前の一部かは
kyuura の論点 UQ-BILINGUAL-NAME-GLOSS（未解決）で、原典では決まっていません。この版は、**利用者が指定した扱い**（対象 2 枚の英語の併記は翻訳の表示として扱い、判定に使わない）を
採ります（3 章）。これは公式の裁定ではない記録で、最新の説明・エラッタ・転記の訂正としても記録せず、UQ-BILINGUAL-NAME-GLOSS は解決済みにしません。`engine.py`・`resolution/` に
カードの id による分岐は加えていません。すべてのカードの括弧書き・英語を一律に除く正規化も加えていません。

## 3. 利用者が指定した名前の扱い（USER-BILINGUAL-NAME-JAPANESE）

利用者の指定（2026-11-01。この版の依頼）は「対象2枚の英語併記は翻訳表示として扱い、判定に使いません。」です。内容は次のとおりです。

- カード名は「ナッシー」として扱う。通常のナッシーと合わせて同じ名前 4 枚の制限を当てはめる。
- 進化元は「タマタマ」として扱う。
- ワザ名は日本語の部分で判定する。
- カードの名前を答えるクイズでは「ナッシー」を正解として扱う。
- 名前以外の性能（HP・タイプ・必要なエネルギー・ワザの内容など）は通常のナッシーに置きかえず、それぞれのカードのデータにしたがう。
- 原文・表示用の英語の併記・出典は残す。

記録と範囲:

- 対象は PR1-075・PR1-077 の 2 枚だけで、欄は名前（`name.ja`）・進化元（`pokemon.evolves_from.ja`）・ワザ名（`pokemon.attacks[0].name.ja`）の 3 つです。ほかのカードの括弧書き

## 4. 表示名と判定用の名前

調べた今の構造: 名前を比べる処理は、どれもカードの定義の `CardDefinition.name_ja`（ワザ名は `Attack.name_ja`、進化元は `CardDefinition.evolves_from`）を読みます。デッキの同じ名前
（`deck.deck_problems` の `deck.same_name`。v0.71 の `SAME_NAME_SPELLINGS` は「ポケモン図鑑HANDY505」の空白 1 組だけを読み替える表）、進化（`evolution.evolution_block` の
`current.name_ja != definition.evolves_from`・`effects.self_deck_evolution_cards`・`reactions` の進化の反応）、名前を指定する効果（`effects` の名前の値を持つ型。山札から名前で選ぶ・
場の名前の数を数える・名前で進化カードを選ぶなど）、同じ名前を比べる効果（スロットゲームの `effects.same_name_groups`）、カツラのクイズ その3（`effects.quiz_answer_names` の候補と
`BlainesQuiz.resume` の正誤・伝えるワザ名）・その1（伝える名前 `quiz_name_hint`）、名前の候補（マチスの秘策の試すカード `engine._identity_candidates`・2 進化の系統
`cards._with_stage1_lineage`・名前のグループ `cards._with_name_groups`）、ワザ名で比べる効果（`target_attack_name` などを持つ型）、変身・コピー（`effects.form_def` は今の姿のカードの
定義。ゆびをふるなどは相手のカードの `Attack`）、ログ（ワザのログの `attack` など）・観測。

v0.131 の変更（共通の処理。カードの id によらない）:

- `cards._user_specified_names`: 写しを読むとき（`cards.classify_record`）に、`effects.USER_SPECIFIED_NAMES` の `<カード id>/name` の登録があるカードだけ、判定に使う値を
  `CardDefinition.name_ja`・`CardDefinition.evolves_from`・`Attack.name_ja` に入れ、写しの値（原文）を新しい欄 `CardDefinition.printed_name_ja`・`Attack.printed_name_ja` に残します。
  登録のないカードの値は今までどおり写しのまま（原文の欄は None）です。上の参照先はすべて判定に使う値を読むので、参照先ごとに読み替えを加えていません（`deck.SAME_NAME_SPELLINGS`
  にも加えていない。表に加えるとデッキの数え方だけが変わり、進化・クイズ・効果の比べに英語の併記が残るため）。
- 登録の欄ごとの写しの値が、そのカードの写しの値とちょうど同じときだけ当てはめます。違えば（写しが変わった・別のカード）何も置きかえず、カードを未対応にします
  （「利用者が指定した名前の扱い（…）の記録の写しの値が、このカードの写しの値と違う」）。
- 写しの値・ワザの説明（英語の文を含む）は書き換えません。`kyuura_engine/data/kyuura_cards.json` は抽出スクリプトで作り直しただけです（2 章の値のまま）。
- 名前の候補: クイズの答えの名前の候補は、2 枚が「ナッシー」になったので、英語の併記の別の候補を持ちません（「ナッシー」は通常のナッシーと同じ 1 つの名前）。マチスの秘策の試すカード
  （`engine._behavior_key`）は、表示用の原文（`printed_name_ja`）を処理の比べから除きます（処理は判定に使う名前で決まる。英語の欄・図鑑番号を除くのと同じ）。
- 表示の欄: 観測は、提示する日本語名（`name_ja`。判定に使う名前）と、原文（`printed_name_ja`）を別の欄に書きます（7 章）。

## 5. ワザ（ふみつけ）

- 写しの値（2 枚とも同じ）: 無色 2 個・「20+」・説明（2 章）。日本語の文は「コインを1枚投げる。もし「おもて」なら、このワザは20+10ダメージを与える。もし「うら」なら、このワザは
  20ダメージを与える。」で、英語の文は同じ内容の翻訳です（数も同じ）。処理は日本語の文にしたがいます。kyuura に最新の説明・照合の記録はないので、処理に使う文面は印刷の文面
  （写しの全文）です（`play_text_ja` も全文。英語の文を消していない）。
- 登録: 既存の型 `CoinBonusDamage(10)`（コインを 1 枚投げ、「おもて」なら基本となるダメージに 10 を加える。ギャロップ PMCG2-019・ケンタロス・ベロリンガなどのふみつけと同じ型・値）。
  名前の指定だけでワザが同じとは推測していません: 写しの必要なエネルギー・ダメージの目安・説明を調べ、通常のナッシー（PMCG2-012。テレポート・たまなげMAX）・ナッシー SI-013
  （ねらいだま）・エリカのナッシー（ふみつけ 30+）のワザとは違う、ギャロップなどのふみつけ（無無・20+・「おもて」で 10 を追加）と同じ処理であることを確かめました。
- 型の照らしの拡張: `CoinBonusDamage.check` の文面の照らしは「コインを投げて「おもて」なら、Nダメージ（を）追加する。」の全文の一致だけでした。日本語と英語の文を交互に書くこの書き方
  （`BILINGUAL_COIN_BONUS_PATTERN`）も全文で照らすようにしました（日本語の文の基本となるダメージがダメージの目安の数字、追加が登録の `bonus`、英語の文の 3 つの数も同じ）。今までの書き方の
  照らしは変えていません。登録の値・ダメージの目安・英語の文の数・「うら」の文が違えば受け付けないことをテストで確かめました。
- 2 枚の登録は同じ値です（`SAME_DATA_CARDS_V0_131`: PR1-077 → PR1-075。v0.70 の `_with_shared_entries` で、id ごとに書いた登録が同じことを確かめてからまとめる）。採用の記録・名前の扱いの
  記録は id ごとに持ちます（印刷の確認の範囲が違うため）。
- 先読み・こんらん・弱点・抵抗力・プラスパワーなどは、既存の `CoinBonusDamage` の処理のままです（解決の基盤の要素 `Damage(OPP, HeadsBonus(10))`）。新しい停止はありません。ワザに独立した
  未解決の事項は見つかりませんでした。

## 7. 観測・ログ・保存

- 観測（`observe`）の場のポケモン・今の姿（`form`）・うらのカードの本当のカード（`real`）・ワザの一覧は、提示する日本語名 `name_ja`（判定に使う名前「ナッシー」「ふみつけ」）と、
  原文の欄 `printed_name_ja`（「ナッシー［Exeggutor］」「ふみつけ[Stomp]」）を分けて書きます。原文の欄は、利用者が指定した名前の扱いのカード・ワザだけが持ち、ほかのカードでは
  書きません（v0.130 までの観測の形のまま）。場のカードはおもてで公開の情報なので、原文の欄も同じ見える範囲です（新しい見える情報はない）。
- ログ: ワザのログの `attack`・クイズの `quiz_hint`・`quiz_reveal` の `name` などは判定に使う名前です。カードの id（`card_id`）は今までどおり書くので、どのカードかはログから分かります。
- 保存: 書き出し（`state_to_dict`）はカードの id を持ち、定義は読み込むときに写しと登録から作り直すので、**書き出しの形式は変えていません**（最新は 33 のまま）。書き出しの `name`
  （場のポケモンの名前の表示）は判定に使う名前です。原文は写しとカードの id から決まるので、旧形式で落ちる情報はありません。pickle・deepcopy・clone のあとも同じ判定になります
  （単体のテスト）。
