# v0.1 のレビュー（v0.2 の前）

v0.1（コミット 03766e0）を、第三者のレビューのつもりで、仕様（docs）・実装（kyuura_engine）・テスト（tests）を突き合わせて調べた記録です。新しい機能は加えていません。

- 調べた日: 2026-10-12
- kyuura の基準コミット: `ecb2d694e6280ec5dc9ddd2a8f709cea16a6b691`（読むだけ。変更していない）
- 原典: 『ポケモンカードオフィシャルブック2000』pp.306〜326 のスキャン [J38] を、疑わしい箇所について画像で読み直した

## 調べ方

1. ルールの各項目を、docs/rules-2000-02-14.md・実装・テストの 3 つで突き合わせた。ルールの解釈は、テストではなく原文（画像）と照らした。
2. 状態遷移を、`GameState` と `apply_command` を中心に読み直し、疑わしい点はまず小さなスクリプトで再現を試みた。
3. でたらめなコマンド（正しいもの・不正なものを混ぜる）を送り続ける検査を、60 局・約 1.1 万コマンド行った。エンジンの例外以外の例外、渡した状態の変化、不変条件の破れを探した。
4. 見つけた不具合は、先に再現テストを書いて失敗することを確かめてから直した。設計の変更が大きいものは直さず、ここに記録した。

## A. 発見事項

重さの区分: critical（対戦の結果を誤る・状態が壊れる）、high（よく起こる誤動作）、medium（特定の使い方で失敗する、または v0.2 の作業を妨げる）、low（まれ・影響が小さい）、note（問題ではないが記録しておくこと）。

なし。公式ルールの解釈の誤りと、通常の対戦で状態が壊れる不具合は見つかりませんでした（N1・N5）。

## D. v0.2 の前に直すべき項目

必須のものだけです。

1. **M5（効果の登録）**: 効果のあるワザ・トレーナーを 1 つでも加える前に、「説明文がある＝未対応」という分類を、「効果の実装が登録されているものだけ対応」に変える。これを先にしないと、効果を実装したつもりで、効果のないワザとして処理される危険がある。
2. **M4（保留中の決定の一般化）**: コイン・対象の選択を伴う効果を加える前に、処理の途中でプレイヤーの決定を待つ仕組みを作る。サイド・交代の 2 つを個別の段階で作っている今の形のまま効果を足すと、段階が増え続ける。
3. **M3（場のポケモンの識別子）**: 進化を加える前に、場のポケモンを一番上のカードの uid ではなく、場に出たときに決まる識別子で指す形にする。

M1・M2 と low の修正済みの項目は、このレビューで直しました。M6・L9〜L15 は、それぞれの機能（オンライン対戦・画面・サドン・デス・性能）に着手するときで間に合います。

## E. v0.2 で着手してよい項目

アーキテクチャの上で安全に加えられる順に並べています。

1. **段階 1 の残りのトレーナー（きずぐすり・ポケモンいれかえ・マサキ）**: D-1・D-2 を済ませたうえで。対象の選択（どのポケモンか）が保留中の決定の最初の例になる。カードは kyuura の写しに加え、『オフィシャルブック2000』の「最新の説明」と照合してから。
2. **コイン**: 乱数は `GameState.rng` の 1 本だけで、serialize に乱数の状態が入ったので、コインを加えても再現性を保てる。コインの結果はログに残す。
