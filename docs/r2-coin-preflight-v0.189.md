# v0.189: おもてにしたうらの使い手のワザの先読みの複製の元の修正

2026-11-16。`kyuura_engine` の版は 0.189.0。原因の調査と修正の設計は [r2-coin-preflight-design.md](r2-coin-preflight-design.md) で、その 9 章・10 章に採用と結果を書きました。

## 1. 変えたこと

`resolution/flow.py` の `_use_attack` だけを変えました（8 行の追加・2 行の変更）。

- 既定の先読み `derived` は、実際の処理のあと、ほかの結果を「複製の元」の上で試します。
- 0.188.0 まで、複製の元はいつも `ctx.original`（コマンドの入口の状態）でした。このコマンドの入口でうらのバトル場のポケモン（マチスの秘策）をおもてにした場合、`ctx.original` では使い手がまだうらです。そのため、本処理では存在しない状態の上で使い手のうらのカードの最大HPを読み、FD1（`UNRESOLVED_SECRET_PLAN_HIDDEN_PROPERTY`）で拒否していました。
- 0.189.0 では、`ctx.original` で使い手がうらだったときだけ、複製の元を handler の入口の状態の複製にします。この時点は次をすべて満たします。
  - おもてにして変身の状態を固定したあと
  - `check_use_attack`（確かめだけで状態を変えない）のあと
  - 実際の処理（費用・コイン・ダメージ・効果）の前
- 上限を超えたときの v0.13 の止める関数（`legacy_after_limit`）にも、同じ複製の元を渡します。
- 結果として、`derived` の試す状態が `derived_full`・`legacy` と同じになります。
- ほかのワザ（おもての使い手）は今までどおり `ctx.original` です。

**変えていないこと:**
- `ctx.original` の意味（ほかの handler の `dormant_scram` など）
- 公開の処理・たねでないカードのトラッシュ
- `FaceDownDefinition`（FD1 の定義）と、使い手以外のうらのカードの扱い（複製の元でもうらのまま）
- VM1 などの未裁定、宣言の選択、API の契約
- judge・検証用 AI・GUI

## 2. 結果

### 32 ワザの再計測

0.188.0 の保存結果と同じ盤面・入力・コインで、修正のあとに 1 回測りました（`probe_engine_coin.py` の写し）。

| 群（r2-coin-preflight-design の分類） | 0.188.0 → 0.189.0 |
|---|---|
| G0（相手へのダメージのないワザ。7 ワザ・28 回） | 変化なし（受理） |
| G1a（6 ワザ） | コインつきの 12 回が FD1 → 受理。コインなしの 12 回は受理のまま |
| G1b（18 ワザ） | 72 回すべてが FD1 → 受理 |
| G2（かまいたち） | コインつきの 2 回は VM1 のまま。コインなしの「うら」の 1 回が FD1 → 受理（G1c。実際のコインの面で受理・拒否が変わらなくなった） |
| たねでない 10 枚の 16 ワザ（64 回） | 変化なし |

- FD1 は 85 回から 0 回になり、VM1 は 2 回のまま。予想外の差はありませんでした。
- たねの 128 回すべてで、同じ状態で先におもてにした対照（公開の後の双子）と結果が一致しました（受理なら状態・乱数・ログの要約、拒否ならコード）。受理したものの公開のイベントは 1 回です。
- この盤面では G1 がすべて受理になりましたが、すべて受理は合格の条件ではありません。ほかの盤面で別の問いで止まるワザは、そのコードで止まります。

### テスト

- `tests/test_preflight_face_down_attacker_v0_189.py`（15）は、修正の前に 15 とも失敗し、修正のあとは全件成功しました。
  - 確かめた内容: 複製の元、`derived`・`derived_full`・`legacy` の等価、公開の後の双子との一致、G1c の面による差の解消、公開 1 回、コインの数、直接と API の一致、拒否の不変。
  - 秘密の保護: 使い手以外のうらのカード（相手・自分のベンチ）は複製の元でもうらで、項目を読むと FD1。相手のうらのカードの本当のカードだけを変えても、本人の結果・観測は同じ。
  - 上限の経路: `MAX_BRANCHES` を小さくした人工の条件で、v0.13 の止める関数に、おもてにした複製の元が渡ることを確かめました。
- `tests/test_legal_actions_r2_stadium_coin_v0_188.py` のたいあたり（コインつき）の期待を、REJECTED（FD1）から ACCEPTED に更新しました（原因はこの修正）。
