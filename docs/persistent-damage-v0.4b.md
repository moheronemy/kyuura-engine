# 持続する効果とダメージ計算（v0.4b）

「かたまる」の効果（「次の相手の番、このカードはダメージを受けない。（ダメージ以外の効果は受ける）」）を、ワザのダメージの計算（p.321 の 8 段階）とどう関係させたかの記録です。持続する効果の規定は [persistent-effects-v0.4b.md](persistent-effects-v0.4b.md)、カードは [harden-v0.4b.md](harden-v0.4b.md)。

## 1. ダメージ計算の 8 段階（p.321）

`damage.calculate_attack_damage` が、次の順に計算する（v0.2c〜v0.2f。v0.4b で変えていない）。

1. 基本となるダメージ（ワザの説明にしたがって計算）
2. ワザを使うポケモンの「ダメージを変更する効果」（ストライクの「つるぎのまい」の例。持続する状態の効果）。ここまでで 0 以下なら計算を終え、「ダメージを与えなかった」
3. 弱点（2 倍）
4. 抵抗力（−30 など）
5. ワザを使うポケモンについているトレーナーカード・エネルギーカードの効果（プラスパワー +10。v0.2c）
6. 場にはたらいている効果（スタジアムなど。対応カードにない）
7. ワザを受けるポケモンについているトレーナーカード・エネルギーカードの効果（ディフェンダー −20。v0.2e）
8. ワザを受けるポケモンが持っている「ダメージを変更する効果」（例はイワークのワザ「かたくなる」、バリヤードの特殊能力「なぞのかべ」）

変更効果は `damage.DamageModifier`（段階と加える数）で渡す（CLAUDE.md）。v0.4b で `DamageModifier` も 8 段階の計算も変えていない。

## 2. プラスパワー・ディフェンダー

v0.2c・v0.2e のまま。どちらもポケモンについているカードの効果で、5 段階・7 段階の加算（`AttachedAttackBonus`・`AttachedDamageReduction`）。カードはそれぞれの有効期限（番の終わり）にトラッシュする。進化しても受け継ぎ、効果も続く（v0.4a の E8'）。ワザによる持続する効果とは別のもの（カードであり、消える契機も違う。[persistent-effects-v0.4b.md](persistent-effects-v0.4b.md) 3 章）。

## 3. ワザによる防御効果: 段階ではなく、ワザの要素を無効にする

p.321 は、8 段階の前（ワザの要素の説明の続き）に次のように書く。

> ワザを使ったとき、それを受けたポケモンが「ダメージを受けない」状態だったら、そのポケモンにダメージを与える「ワザの要素」は無効になります。ただし、そのポケモン以外へダメージを与える「ワザの要素」は、有効です。また、ダメージ以外の効果をもたらす「ワザの要素」も有効です。

「かたまる」の最新の説明は「次の相手の番、このカードはダメージを受けない。（ダメージ以外の効果は受ける）」で、その番の間このポケモンは「ダメージを受けない」状態にある。そこで、

| 事項 | 分類 | 実装 |
|---|---|---|
| このポケモンにダメージを与えるワザの要素は無効。ほかのポケモンへのダメージの要素・ダメージ以外の効果の要素は有効 | CONFIRMED（p.321。最新の説明の「（ダメージ以外の効果は受ける）」とも同じ） | `effects.deal_attack_damage` の最初で `persistent.damage_prevention` を見て、はたらいていれば計算せずに戻る。ワザの実装は続けて残りの要素（コイン・特殊状態・自分へのダメージ）を処理する |
| 無効の要素は、8 段階のどこかで 0 にするのではなく、計算しない（弱点・抵抗力・プラスパワー・ディフェンダーも計算しない） | SUPPORTED（「ワザの要素」が無効。8 段階の「ダメージを変更する効果」の例（8 段階の「かたくなる」「なぞのかべ」）は、ダメージの量で働くかが決まる効果で、量に関係なく「ダメージを受けない」状態とは書き方が違う） | `DamageModifier` に大きな負の数を入れる形・ディフェンダーと同じ 7 段階の形にはしない。結果はどちらに読んでも同じ（このポケモンのダメージは変わらない）。違いが出るのは、量をコインで決める要素だけ（5 章） |

なぜ 8 段階（「かたくなる」「なぞのかべ」）ではないか: 「なぞのかべ」の最新の説明は「このカードがワザによってダメージを受けるとき、そのダメージが30以上なら、このカードはダメージを受けない」で、受けるかどうかが計算したダメージの量で決まるので、量を計算する段階（8 段階）に置かれている。「かたまる」は量に関係なく「ダメージを受けない」ので、p.321 のワザの要素の規定（要素が無効）にあたる。

## 4. 「ダメージ 0」と「ダメージを受けない」・ワザの失敗

| 区別 | v0.4b の扱い |
|---|---|
| ダメージを減らす（ディフェンダー） | 7 段階の加算（v0.2e） |
| 計算の結果が 0 以下（抵抗力・ディフェンダーなど） | 「ダメージを受けなかった（与えなかった）」（p.319・p.321）。ログ `damage` の `amount` は 0（v0.2d の 2 段階までの 0 は `stopped_after_step_2`） |
| ダメージを受けない（「かたまる」） | ダメージの要素が無効。計算しない。ログは `damage_prevented`（`amount` を書かない。計算していないので、防いだダメージの量はない） |
| ダメージ以外の効果も受けない（「効果を受けない」状態。p.321） | 対応カードにない（未実装） |
| 追加効果だけを防ぐ | 対応カードにない |
| ワザそのものの失敗（p.323「12」） | 対応カードにない。「かたまる」の「うら」・ダメージの無効は、どちらもワザの失敗ではない（ワザは使ったことになる） |

ダメージが無効になっても、ワザの要素の処理は続く（p.309「それ以降の内容を無視してはいけません」・p.321）。ワザを使ったことになり、番は終わる。

## 5. 追加効果との関係と、原典で決められない場合

| ワザの要素の形 | 例 | 扱い |
|---|---|---|
| ダメージ → コイン → 特殊状態 | どくばり・いとをはく・あやしいひかり・しびれごな・どくのこな・れいとうビーム | ダメージの要素だけ無効。コインは特殊状態の要素のもの（有効）なので投げ、「おもて」なら特殊状態にする |
| ダメージ → コイン → 自分へのダメージ | でんげき | 相手への要素だけ無効。コインと自分への 10 は有効 |
| ダメージの要素がない | キノコのほうし | 影響しない（ねむりになる） |
| コインの結果でダメージの量を決める要素だけ | みだれづき（「コインを2枚投げ、「おもて」の数×10のダメージ。」） | **UNRESOLVED**。下の理由で、コインの前に止める |

みだれづきの要素は「コインを2枚投げ、「おもて」の数×10のダメージ」の 1 つだけで、コインはダメージの量を決めるためだけに投げる。p.321 はこの要素が無効になるとだけ書き、無効になった要素の中のコインを投げるかを書かない。

- 読み方 A: 要素が無効なので、要素の処理（コインを含む）をしない。コインを投げない。
- 読み方 B: ワザの説明にしたがってコインを投げ（p.309 の手順 6・p.319）、計算したダメージを与える部分だけが無効。

結果のダメージはどちらも同じ（受けない）が、コインを投げるかどうかで乱数の続き（この先のコインの結果）とログが変わる。原典で決められないので、推測で実装せず、ワザの宣言の前（こんらんのコインの前）に `UnsupportedError`（`UNRESOLVED_PREVENTED_COIN_DAMAGE`。`CoinFlipDamage.problem`）にする。状態も乱数も変わらない。効果がはたらいていない相手には、今までどおり使える。自然な対戦（tests/test_harden_games_v0_4b.py の 40 局）で 13 回起こる（その番はワザを使わない手順にしている）。

同じ理由で、コインを投げる前に分かる「原典で決められない場合」は `AttackEffect.problem` で返す（v0.3c からの約束）。受け付けるか・拒否のコードがコインの結果で変わらないことを、tests/test_effect_preflight_v0_3d.py の `CoinIndependenceTest` に、「かたまる」（`PreventDamageOnHeads`）と「ダメージを受けない」状態の相手の盤面を加えて確かめた。

将来、「ダメージを与えたら」起こる効果（バタフリーの「メガドレイン」「相手にダメージを与えたら、その半分（切り上げ）のダメージカウンターを、自分からとりのぞく。」p.19）を加えるときは、その効果の発生条件に「実際にダメージを与えたか」が含まれるかをカードごとに照合する。v0.4b の追加効果（特殊状態）とは同じ扱いにしない。

## 6. ポケモンチェックとの関係

| 事項 | 分類 | 実装 |
|---|---|---|
| ポケモンチェックはどちらの番でもないので、「次の相手の番にダメージを受けない」ポケモンも、ポケモンチェックの中のダメージ（どく）は受ける | CONFIRMED（p.323「15」。p.236 のワザ解説も「どく状態のダメージは、相手の番ではないので受けることになります」） | どくのダメージ（`engine._pokemon_check`）は v0.3a のまま（ワザのダメージの計算を通さず、効果も見ない）。効果を与えた直後のポケモンチェックでは効果はまだはたらいておらず、次の相手の番のあとのポケモンチェックの前には効果は消えている |
| どくのダメージできぜつしたら、効果も消える | CONFIRMED（p.322 の「場をはなれたら」） | `_knock_out` → `remove_persistent_effects(..., KNOCK_OUT)` |

## 7. 複数の効果の順番

- p.321 は、同じ段階の複数の効果の計算の順番を、5〜6 段階はワザを使うプレイヤー、7 段階はワザを受けるプレイヤーが決めるとする（v0.2c・v0.2e。加算だけなので順番で結果が変わらず、選ばせていない。`DAMAGE_STEP_CHOOSER`）。
- 「ダメージを受けない」状態は段階の計算の前に要素を無効にするので、ほかの変更効果（プラスパワー・ディフェンダー）と順番を比べる必要がない。
- 1 匹のポケモンが複数の持続する効果を受けることはある（p.323）が、v0.4b の対応カードで受けるのは「かたまる」の効果だけ。ダメージの量を変える持続する効果（8 段階の「かたくなる」など）を加えるときは、8 段階の `DamageModifier` か、加算でなければ順番を決める決定（`DAMAGE_STEP_CHOOSER`）を使う。

## 8. 未解決の裁定

| コード | 内容 | 止める場所 |
|---|---|---|
| `UNRESOLVED_PREVENTED_COIN_DAMAGE`（v0.4b） | 「ダメージを受けない」状態の相手に、コインでダメージの量を決める要素だけのワザ（みだれづき）を使うとき、そのコインを投げるか | ワザの宣言の前（`CoinFlipDamage.problem`）。状態・乱数は変わらない |
| `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS`（v0.3c。変えていない） | こんらんの 20 にプラスパワー・ディフェンダーを計算するか | こんらんのコインの前 |

こんらんの 20（自分へのダメージ）と「ダメージを受けない」状態: 効果がはたらくのは、効果を受けたポケモンの持ち主の相手の番だけで、その番にそのポケモンはワザを使わない。そのため、こんらんの 20 を「ダメージを受けない」状態のポケモンが受けることは起こらない（不変条件: 効果を与えた番は持ち主の番、はたらく番は次の番）。こんらんの 20 が「ワザによるダメージ」かは v0.3c からの未解決のままで、この効果との関係も決めていない（起こったら確かめ直す）。
