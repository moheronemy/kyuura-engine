- `reveal_face_down` がすることは次の 3 つだけです。

### 3.3 効果型ごとの分類

区分の意味:
- **A**: 公開前の本人向け・公開情報だけで必要条件を確定できる。
- **B**: 公開後に変わる条件があるが、限定条件で安全に扱える可能性がある。
- **C**: 公開・試行・非公開情報なしでは確定できず、今回は提示しない。
- **D**: この宣言経路では起こらない。

| 型（定義の行） | カード | 種類 | R2 の使い手として | 自己持ち主（R3） |
|---|---|---|---|---|
| `CoinsUntilTailsBonusToGroupAttack`（45745） | X | ワザといっしょに使う力 | A（選ばなければ使わない） | **B** |
| `CounterBonusToGroupAttack`（47869） | A | 同上 | A | **B**（追加はいつも 0） |
| `ReduceOwnGroupDamageFromType`（40581） | N・D・M | 常にはたらく（場） | A（受けるダメージだけ。宣言には D） | — |
| `VoidOpponentEnergyDiscardOnGroup`（41242） | K | 常にはたらく（場） | A（宣言には D） | — |
| `CountersOnOpponentRetreatWhileActive`（45045） | C | 常にはたらく（バトル場） | A（相手のにげるだけ。宣言には D） | — |
| `AddActiveDamageReceivedToNamedAttack`（40992） | P | 常にはたらく（場） | A（ダメージの量だけ。宣言には D） | — |
| `ZeroGroupRetreatCostFromBench`（13031） | Z | 常にはたらく（ベンチ） | A（バトル場でははたらかない） | — |
| `BenchNameGroupFromDeckOnEntry`（40413）ほか場に出したとき 4 型 | I・V・E・R | 場に出したとき | A（公開は場に出すことではない。D） | — |

- 各型の 7 観点の行は、機械可読の表の `types[].aspects` にあります。
- 「場に出したとき」の 4 型は `BenchNameGroupFromDeckOnEntry`・`CoinReturnOtherGroupToHandOnEntry`・`EachPlayerMayReturnHandThenDrawOnEntry`・`HealAllNameGroupOnEntry` です。
- ［PERFORM］は、うらのあいだダメージを受けない（受ける時におもてにする）ので、公開の直後の追加は 0 の見込みです（静的。未実行）。いずれにしても宣言の可否にはかかわりません。

**型の性質だけで安全としない点:**
- 22 型のどれも、公開の時点で姿・名前のグループ・力の有効性・宣言のコインを変えない、とコードで読めました。ただし、この結論は今の登録の型の実装に依存します。新しい型・新しいアンノーンが加われば成り立ちません。
- そのため推奨（6 章）では、**分類済みの型の集合**を条件にします。新しい型を含むカードは示しません。あわせて、登録の全件を数えるテストで分類漏れを止めます。

### 3.4 経路ごとの分類

| 経路 | 区分 | 理由 |
|---|---|---|
| R2-X（別の持ち主の［XXXXX］） | **A** | 持ち主の条件（おもて・力が消えていない・使えない効果なし・この番の記録）は公開の場で決まり、公開で変わらない。使い手の条件は本当のカードの印刷の `name_group` とワザの名前。コインによる停止は submit で起こりうる（予告しない） |
| R2-A（別の持ち主の［ANGER］） | **A** | 同上。コインなし。追加の量は持ち主のダメージカウンター（公開） |
| R3-X・R3-A（自己持ち主） | **B** | 下の説明を参照 |
| TF（本当のカードがメタモン 2 枚。`TransformIntoDefender` 1・`SuperTransformPower` 1） | **C** | 相手のバトル場がアンノーンなら、公開のあとにアンノーンの姿になりうる。変身の条件（TF1 の残る部分）で決まり、R4 と同じく対象外 |
| うらの持ち主（使い手と別）・相手の場の持ち主・力が消えている・使えない・この番にほかの X を使った | **D** | エンジンが拒否する（`ATTACK_POWER_NOT_AVAILABLE`・`POWER_SUPPRESSED`・`POWER_USE_PREVENTED`・`POWER_ALREADY_USED`）。示さない |
| 本当のカードがアンノーンでない・ワザが「めざめるパワー」でない | **D** | `usable_for` が拒否する。示さない |

**R3（自己持ち主）が B の理由:**
- 公開の前は、持ち主の力がありません（`group_attack_power_slot` はうらに None）。
- そのため、本当のカードの力を仮に評価する新しい経路が要ります。
- その評価が公開のあとの値と同じになることは、静的には言えます。`power_suppressed` は、うらの持ち主に対して次のように振る舞います。
  - `powers_stopped`: 持続する効果がないので None。
  - `scared_by`: 空。
  - 場の記録: 公開で変わらない。
- ただし、それは不変条件 4 つと、本当のカードがベイビィでも力を消す型でもないことに依存します。
- さらに、うらの場の位置を持ち主として表示することになります。

## 6. 推奨する次の 1 単位: R2（別のおもての持ち主の［XXXXX］・［ANGER］）

根拠が同じ処理群として、［XXXXX］と［ANGER］をいっしょに扱います。根拠は 3 点です。
- どちらも `usable_for` が同じです（名前のグループとワザの名前）。
- 持ち主の確かめは `group_attack_power_check` で共通です。
- 公開のあとの影響の分類（3 章）が同じです。

［XXXXX］だけに加わるのは、コインによる既存の停止（5 章）です。これは送信のときの既存の未裁定で、おもてでも同じなので、範囲を分ける理由にしません。小さくしたい場合の代案は「［ANGER］だけ」です（D-R2U-1）。

**使い手の条件（すべて満たすとき）:**
- 番のプレイヤーの main で、本人のバトル場のポケモンがうら（呼び出し元の条件）。
- `printed_def(active.card)` がポケモンで、`name_group` が持ち主の力の `group`（型の値。カード ID の一覧は作らない）と同じ。
- 本当のカードの特殊能力の型が、すべて分類済みの 22 型のどれか（[r2-unown-design.json](r2-unown-design.json) の `types`）。
  - 新しい型・変身の型を持つカードは示しません。
  - 登録の全件（`name_group` が「アンノーン」のカード）の型が分類済みであることをテストで確かめ、分類漏れは止めます。
- 選んだワザの印刷の名前が、力の `attack_name`（「めざめるパワー」）と同じ。
  - `options_by_choice` をワザごとにし、組（`pairs`）もそのワザだけにします。
  - 今の 26 枚はワザが 1 つなので、結果はどのワザにも同じです。

**持ち主の条件:**
- 自分の場のおもてのポケモンで、使い手と別。
- `group_attack_power_slot` が `CoinsUntilTailsBonusToGroupAttack` か `CounterBonusToGroupAttack`。
- `power_suppressed`・`powers_use_prevented`・`effect.other_use_problem(state, actor, holder_id)` のどれにも当たらない（公開の場だけ。状態を変えない既存の問い合わせ）。

**自分自身が持ち主になる場合（R3）:** 示しません（B）。おもての分岐は今どおりバトル場の持ち主も示します。

**力が使えない場合:** 無効・使用不能・この番に使用済み（ほかの X）のどれでも示しません（D と同じ扱い）。

**複数の持ち主:**
- 場の並び（使い手のバトル場を除くのでベンチの並び）で、持ち主ごとに 1 つ示します。
- 値・表示はおもての `_addon_specs` の `with_power` と同じです（`addon`・持ち主の場の表示・`power`）。
- 並びはコイン → ［めいれい］・［XXXXX］・［ANGER］の場の並びです。
- 使い手の条件が違うので、今の登録では［めいれい］とアンノーンの力は同時に出ません。

**段と選択数:**
- 2 段目に置きます。`count` は 0〜選択肢の数、`order: significant`（選んだ順に宣言）、`distinct`・`decline` は今の契約のままです。
- 違う力（［XXXXX］と［ANGER］）は同時に選べます。

**eligible・processability・reason:**
- 条件を満たしたものだけを出します。
- 選択肢と候補は `unverified`、理由は `face_down_reveal_not_evaluated`。

**check:**
- 形を確かめます: ワザ 1 つ・そのワザの組にある選択・重ならない。
- 同じ `exclusive_key` の 2 つは `CANDIDATE_INPUT_INVALID` にします（0.190.0 の `_face_down_verify` と同じ読み方。示した持ち主の力の登録だけを読む）。
- エンジンは呼びません。
- 保証しないこと: 受理・力の使用・コイン・追加の量・XP1・NT1・v0.4b の停止がないこと。

**submit:** エンジンの今の順のままです（公開 → たねなので残る → `check_use_attack`（`group_attack_powers_check`）→ 先読み → 処理）。拒否・停止は元の状態に戻ります。

**対象外と証拠不足:**
- 対象外: R3、変身の経路（TF・R4）、分類にない型を持つカード、名前のグループが読めないカード、持ち主がうらのとき。今までどおり示しません。
- 型の定義が見つからない（登録にない）ときも示しません。

**保証の文と note:** `GUARANTEE_FACE_DOWN_ATTACK` と 2 段目の note を実装に合わせて直します。
- 保証の文はどの本当のカードでも同じにします。
- `test_legal_actions_f1_v0_180` の固定の sha256 は、原因を記録して更新します。
- コインだけ・［めいれい］だけのときの今の note の文は変えません。

**採らない案:**
- 宣言の選択を受理のあとへ移す: 選ぶ時点が変わるため。
- R3 を含める。
- XP1・NT1 を候補で予測して外す: エンジンの条件の写しになり、ずれる危険があるため。
