## 3. 場をはなれるカードと行き先（共通の処理）

どのカードも同じ uid・同じ持ち主のまま動かします（複製しない）。場のポケモンの番号は場をはなれたら無効になり、使い回しません（手札・山札から場に出し直したら、`zones.enter_play`
で新しい番号を付け、場に出た番は今の番。前に場にいたときのダメージ・特殊状態・ついていたカード・持続する効果・使用の記録・進化の記録は引き継がない）。印刷の定義・共有の
`CardDefinition` は書きかえません。`engine.py`・`resolution/` にカード id の分岐はありません。

| カード・もの | フジろうじん（`zones.return_in_play_to_deck`。`trainer`） | ポケモン回収（`zones.return_basic_to_hand`。新しい関数） | つれさる（`zones.return_in_play_to_deck`。`effect`。自分と相手） |
| --- | --- | --- | --- |
| 重なりのいちばん下のカード（たねポケモン・場のなにかの化石／ピッピ人形のトレーナーカード） | 持ち主の山札 | 持ち主の手札 | それぞれの持ち主の山札 |
| 重なった進化カード（ポケモン育て屋さんで重ねた 2 進化カードも） | 持ち主の山札 | 持ち主のトラッシュ（「進化カードは全てはがしてすてる」） | 持ち主の山札 |
| 「ばける」でのせた進化カード（`PokemonInPlay.disguise`） | 持ち主の山札（「それについているカード全て」） | 持ち主のトラッシュ（進化カードなので「進化カードは全てはがしてすてる」に当たる。実装上の読み方） | 持ち主の山札（「それらについているすべてのカード」） |
| エネルギーカード | 持ち主の山札 | 持ち主のトラッシュ | 持ち主の山札 |
| ついているトレーナーカード（プラスパワー・ディフェンダー） | 持ち主の山札 | 文面にない（SU1 で止める） | 持ち主の山札 |
| ダメージカウンター・特殊状態・持続する効果・にげるの失敗の記録など | なくなる | なくなる | なくなる |
| 山札を切る | 自分の山札を 1 回 | 切らない | もどした側の山札を、自分 → 相手の順に 1 回ずつ |

- ［へんしん］のメタモンは、実際のカード（メタモン）が動きます（今の姿の相手のカードではない）。もどしたあと、ほかのポケモンの今の姿・今有効な最大HP・ワザの一覧は、今の場から
  求め直されます（状態に持たない。v0.48・v0.49）。
- ポケモン回収で手札にもどしたなにかの化石・ピッピ人形は、手札ではトレーナーカードです（v0.47）。オムナイトなどがのっていれば、化石が手札、オムナイトがトラッシュです。

  トラッシュ。進化カードは動かさない）を使わないのは、動かし方が文面と違うからです（新しい関数 `zones.return_basic_to_hand` で、手札へのカードとトラッシュへのカードを分けて

- 使ったプレイヤーと持ち主: フジろうじん・ポケモン回収は自分のポケモンだけを選ぶので同じプレイヤーです。つれさるは、自分のポケモンは自分の山札、相手の対戦ポケモンは相手の
  山札（持ち主）にもどします。

## 4. 場をはなれたあとの進行

- **トレーナー（ポケモン回収）**: 効果の途中（決定を待つ間）は使用中のカード（`trainer_in_use`）を残し、バトル場に出す決定を出しません。使い終えて（カードをトラッシュして）から、
  `engine._finish_trainer` が `resolution.after_trainer` を呼びます（`TrainerEffect.empties_active`。v0.50 の `may_knock_out` と並ぶ印。カード id で分けない）。`after_trainer` は
  v0.52 から、きぜつがなくバトル場が空いたプレイヤーがいれば、勝ち負けの判定（場にポケモンがいない。p.311）→ バトル場に出す決定（`promote_active`。使ったプレイヤーが自分の控え
  から選ぶ）→ 同じ番の `Phase.MAIN`（`CONTINUE_TURN`）に進みます（v0.42 の `after_power` と同じ形）。v0.50 のきぜつの処理は変えていません。退化スプレーなど、`may_knock_out`
  のトレーナーの動きは v0.51 と同じです。フジろうじんは控えだけを選ぶのでバトル場は空かず、この処理を呼びません。不変条件（`engine._power_aftermath_problems`）は、続き
  `continue_turn` の決定の前の今の番の最後の宣言が、`empties_active` のトレーナーで、そのあとにバトル場のポケモンを手札にもどしたログ（`return_basic_to_hand` の `zone`
  `active`）があることを確かめます。
- **ワザ（つれさる）**: もどす処理はワザの要素の中で完結し、自分がもどったあとも相手の処理を続けます（ワザの処理を打ち切らない）。空いたバトル場は、ワザのあとの既存の勝ち負けの
  判定・バトル場に出す決定（番でないプレイヤー → 番のプレイヤーの順。p.323〜p.324）でうめ、そのあと番が終わります。両方のバトル場が空いても、勝ち負けの判定は 2 匹を
  もどしたあとに 1 回だけ行います（途中で勝者を決めて、残りの効果を落とさない）。両方とも場にポケモンがいなくなれば、p.311 の表でサドンデスです。片方だけなら、その
  プレイヤーの負けです。
- 決定・拒否: 拒否（`IllegalActionError`・`UnsupportedError`）では状態・乱数・ログは変わりません。答えのない決定は残しません（どの答えも止まるポケモン回収は、v0.49 の
  `engine._trainer_dead_end` が使う前に受け付けない）。使用中のトレーナーを残したまま止まりません。

## 5. つれさるの処理の順番とふぶきの書き方

**つれさる**（要素 `programs.ReturnBothActivesToDeck`）:

1. 対象: ワザを使ったポケモン（自分）と相手の対戦ポケモン。このワザの中で HP 以上になっていればその側は処理の対象がない（このワザにダメージの要素はないので、今の対応カードでは
   起こらない）。同じワザで HP 以上になったポケモンがいれば v0.36 の RD9（今の対応カードでは起こらない）。
2. 自分 → 相手の順に、受けるか（「ワザをうけない」状態・「とうめい」。`kernel.reaches`。両方が「とうめい」なら T27）を評価し、受けるなら山札にもどして持続する効果を消す。
   受けない側はもどさず、その山札も切らない（片方だけがもどる）。
3. もどした側の山札を、自分 → 相手の順に切る（先読みでは切らない）。

ルールが決めているのは「それぞれの山札にもどし、それぞれの山札をよく切る」ことだけです。2 匹をもどす順番・2 つの山札を切る順番は、どちらの山札にどのカードが入るかを変えないので、
説明の書かれた順（自分 → 相手）にしました（実装上の判断。乱数の使い方だけが決まる）。受けるかの評価をもどす処理と交互にするのも実装上の判断です（対象は効果を処理し始めた
ときの 2 匹で、自分をもどしても相手の対戦ポケモンは変わらない）。英語版の「Then, your opponent …」は根拠にしていません。相手に控えがいなくても使えます（わるいカイリキーの
「つまみだす」の「相手に控えがいない時、このワザは使えない」を持ち込まない）。

**ふぶきの書き方**: 型の `check` が受け付ける説明に、エリカのハクリューの書き方「コインを投げ、「おもて」なら…、「弱点・抵抗力」に関係なく、それぞれ10ダメージ。」を加えました
（v0.38 のフリーザーは「コインを投げて「おもて」なら…、(「弱点・抵抗力」に関係なく)それぞれ…」）。違いは読点・かっこだけで、1 枚のコインの「おもて」で相手の控え全員・「うら」で
自分の控え全員に、弱点・抵抗力を計算しない同じ数のダメージを与える同じ意味です。ほかの書き方（対象・数・弱点・抵抗力の記述が違う）は受け付けません（テストで確かめる）。

## 6. 未解決・技術的な制限・実装上の仮定

新しい停止コードは 3 件です（どれも kyuura の未解決の一覧にない `not_in_kyuura`。研究の対応表の `stop_codes`）。

| 番号 | 停止コード | 場面 | 止める時点 |
| --- | --- | --- | --- |
| FJ1 | `UNRESOLVED_MR_FUJI_WITHOUT_BENCH` | 自分に控えポケモンがいないときにフジろうじんを使えるか。印刷の文面は「自分の控えポケモンを1匹選び、…」で、選べないときの記述がない（「使えない」と書かれていない）。ほかのカードの「対象がない」ときの問い（突風の GW5・サカキの TR1・元気のかけらの RV1）の答えを流用しない | 使う前（`check_playable`。トレーナーの使用の禁止 `TRAINER_PREVENTED` より後） |

- ポケモン回収・フジろうじんでほかのポケモンの最大HPが下がり、のっているダメージ以下になる（たとえば相手の［へんしん］のメタモンが、こちらのバトル場のポケモンを回収されて
  同じカードとしてあつかう相手がいなくなる）: v0.48 の MH1（トレーナーの効果で最大HPが下がる場面。その答えを受け付けない。ほかの答えは受け付ける）。
- 相手の［へんしん］のメタモンが、写す特殊能力を持つポケモン（エリカのミニリュウの［ふしぎなバリアー］など）を同じカードとしてあつかう: v0.49 の TF1（対戦準備でも起こる。
  検証用デッキの組で D49 を使わなかった理由。8 章）。
- つれさるで両方が「とうめい」: v0.9 の T27。同じワザで HP 以上になったポケモン: v0.36 の RD9。どちらも今の対応カードでは起こらない（ふぶき・つれさるの持ち主に「とうめい」は
  なく、つれさるにダメージの要素はない）。

技術的な制限: ありません（このバッチで新しく到達した、エンジンが扱えない場面は見つかっていない）。

実装上の仮定・判断:

- 「ばける」でのせたカードは進化カードなので、ポケモン回収の「進化カードは全てはがしてすてる」に当たる（トラッシュ）。フジろうじん・つれさるでは「ついているカード全て」に当たる
  （山札）。
- つれさるの処理の順番（自分 → 相手。受けるかの評価ともどす処理を交互に。山札を切るのはもどしたあと）。5 章。
- つれさるで受けなかった側（「ワザをうけない」「とうめい」）の山札は切らない（もどしていない山札を切ることは説明の「それぞれの山札」に当たらない。v0.40 のつまみだすと同じ）。
- フジろうじんでもどしたカードを山札の一番下に置く（そのあと必ず切るので結果は変わらない。v0.24 の PT7・v0.36 と同じ）。
- 相互作用（tests/test_field_return_v0_52.py が確かめる）: 場をはなれたかがくへんかガスのベトベトン・［げんしのちから］のプテラ・［アレルギーかふん］のわるいラフレシア・
  ［サイコリンク］に超のワザを供給していたポケモンは、その時点から効果がなくなる（はたらいているかは今の場から求める。状態を書きかえない）。思い出させるの記録（今の番だけ）は、
  記録したポケモンが山札にもどったあと、バトル場に出す決定を待つ間も残ってよく、番の終わりに消える。トレーナーの使用の禁止は、トレーナーの効果の途中では変わらない
  （ポケモン回収で［アレルギーかふん］のわるいラフレシアを回収できるのは、ねむりなどでその力が消えているときだけで、回収したあとは今の場から求めて禁止はない）。
  ピッピの「ゆびをふる」・ピクシーの「ちょうのうりょく」でつれさるをまねたら、もどるのはまねたポケモン（ワザを使ったポケモン）と相手の対戦ポケモン。

## 7. API・ログ・観測・状態・書き出しへの影響

- 公開の API の呼び方・コマンドは変えていません。状態の項目・書き出しの形式（15）は変えていません（監査の `LATEST_FORMAT` も 15。次の新しい形式は 16）。
- `zones.return_in_play_to_deck` に `trainer`（トレーナーの出どころ。ログの `trainer_card`）を加えました（`effect` とどちらか一方。ワザのログの形は v0.51 と同じ）。
  `zones.return_basic_to_hand` を加えました。
- `TrainerEffect.empties_active`（既定は偽）を加えました。`resolution.after_trainer` は、きぜつがなくバトル場が空いたプレイヤーがいれば勝ち負けの判定 → バトル場に出す決定に
  進みます（`may_knock_out` だけのトレーナーの動きは v0.51 と同じ）。
- 新しいログのイベントは `return_basic_to_hand`（`player`・`pokemon`（いちばん上のカード）・`pokemon_id`・`zone`・`trainer_card`・`card`（手札にもどしたカード）・
  `discarded`・`evolution_cards`・`energy`・`damage`、「ばける」のときだけ `disguise`。公開。観測の `PUBLIC_EVENTS` に加えた）。`return_in_play_to_deck` はトレーナーの
  ときだけ `effect` の代わりに `trainer_card` を書きます（ワザのログは変わらない）。山札を切るログ `shuffle` はカードの並びを書きません（観測の山札は枚数だけ）。
- 新しい決定の種類・拒否のコードはありません（`select_pokemon`・`promote_active` を使う）。
- ログの監査（tests/log_audit.py）は、`return_basic_to_hand`（持ち主・使用中のポケモン回収・`zone`・手札とトラッシュの組み立て直し・「ばける」のカード）、フジろうじんの
  `return_in_play_to_deck`（使用中のフジろうじん・控えのポケモン・そのあとの山札を切るログ）、つれさるの 2 つの `return_in_play_to_deck`（ワザを使ったポケモンと相手の
  ポケモン。1 回のワザで 2 回まで。そのあとに、もどした順に同じワザの `shuffle`）を確かめ、手札・トラッシュ・場の組み立て直しに含めます。
