# v0.5（ポケモンパワー・フシギバナの「エナジートランス」）の準備の評価（v0.4e の時点）

v0.4e の総合監査のあとで、v0.5 でポケモンパワー（特殊能力）と、その最初のカードとしてフシギバナ（PMCG1-011）の「エナジートランス」を加えるときの準備を評価した記録です。**v0.4e ではポケモンパワーの基盤を先行して実装していません。** ここに書いた設計は提案で、原典（『ポケモンカードオフィシャルブック2000』[P43]）の照合の前の見込みです。原典で確かめるまで、どれも「公式ルール」として実装しないでください。

## 3. コマンド（`UsePokemonPower`）

今は `kyuura_engine/commands.py` に `UsePokemonPower(player, pokemon)` があり、`UNSUPPORTED_COMMANDS` に入っています。受け取ると、状態を変えずに `UnsupportedError("UNSUPPORTED_ACTION")` です（`apply_command` の最初。段階・番も見ない）。tests/test_state_integrity.py の `ALLOWED`・`sample_commands` にもこの形で入っています。

v0.5 で対応するときの提案:

- `pokemon` は場のポケモンの番号（`pokemon_id`。v0.4a の `EvolvePokemon.target` と同じ）にする。v0.1 からの uid の形にはしない（ベンチのポケモンも指せ、進化しても変わらない）。ポケモンパワーが 2 つ以上あるカードは旧裏の範囲にもあるので、パワーの位置（`power_index`）を加えるかを B2 のあとで決める（今の形を変えるので、`command_from_dict` の互換を確かめる）
- `UNSUPPORTED_COMMANDS` から外したら、tests/test_state_integrity.py の `ALLOWED`（どの段階で受け付けるか）を更新する

## 4. 効果の登録表の拡張点

| 今 | v0.5 で要るもの |
|---|---|
| ワザ `AttackKey(カード id, 位置)` → `AttackEntry`、トレーナー カード id → `TrainerEntry` | ポケモンパワー `PowerKey(カード id, 位置)` → `PowerEntry(effect, name_ja, text_ja, play_text_ja, source)`。kyuura の写しの文面（照合用）と、実装がしたがう最新の説明・出典（`card_verification.json` の `latest_description_ja`）を持つ（v0.2b のトレーナー・v0.2d のワザと同じ） |
| `cards.py` は `powers` があれば「ポケモンパワーは未実装」で拒否 | 登録されたパワーだけを対応にする（登録のないパワーを持つカードは拒否のまま。説明文を実装がある証拠にしない） |
| `AttackEffect`・`TrainerEffect` の `check`・`problem`/`check_playable`・`resolve`・`resume`・`decision_problems` | `PowerEffect` を同じ形で: `check`（データの形）・`check_usable`（使えるか。原典で決められない場合は `UNRESOLVED_…` を状態を変える前に）・`resolve`・`resume`・`decision_problems`（v0.4e のトレーナーと同じく決定の形を宣言する） |

宣言で持つと良いもの（実装ごとに書かせる）: 使える場所（バトル場だけか・ベンチもか）、使えなくなる特殊状態（カードの文面。エナジートランスは「ねむり・マヒ・こんらん」）、1 番に使える回数（「好きなだけ」なら数えない）。どれも B1・B2 の照合のあとで決める。

## 5. 特殊状態とポケモンパワー

- 今のエンジンでワザ・にげるを止める特殊状態の確認は `engine._require_not_asleep_or_paralyzed`（ねむり・マヒ）で、こんらんはワザ・にげるのあとのコイン（v0.3c）。エナジートランスの「ねむり・マヒ・こんらん」状態で使えないは、これとは別の、カードの文面による確認として `check_usable` に書く（ワザの確認を流用しない）。
- 特殊状態になるのはバトル場のポケモンだけ（p.322）なので、ベンチのフシギバナは特殊状態にならない。ベンチから使えるかは B1。
- どくのときに使えるか: カードの文面（kyuura の写し）は「ねむり・マヒ・こんらん」だけを挙げる。英語版のあとの規定の変更（EN-2002-STATUS-POWERS。すべての特殊状態で使えない）は日本の 2000.02.14版の規定ではないので使わない。B2 で最新の説明を確かめる。

## 6. 使った回数

エナジートランス（「好きなだけ」）は回数を数えなくてよい見込みです。1 番に 1 回などの制限のあるパワーを加えるときは、状態に回数を持つ（`PokemonInPlay` か `GameState` の新しい項目）必要があり、書き出しに新しい形式（形式 9）と不変条件が要ります。ログから数える形にはしないでください（ログは記録で、状態の正本ではない）。v0.4e では形式 9 を加えていません。

## 7. エネルギーの移動とカードの保存則

- 移すのはエネルギーカードの uid を、ある場のポケモンの `energy` から別の場のポケモンの `energy` に移すことで、カードの保存則（`check_invariants`）はそのまま成り立つ（場のカードの数は変わらない）。持ち主の場の中だけで動かす（相手のポケモンへは移さない。B2 で確かめる）。
- ついているのは基本エネルギーだけ（不変条件）。「草」エネルギーだけを動かすのはカードの文面の条件で、実装の `check_usable`・決定の選べるもので守る。
- ログ（例: `move_energy`。`player`・`energy`・`from_pokemon_id`・`to_pokemon_id`・`power`）を加えたら、tests/log_audit.py の組み立て直し（場のポケモンのエネルギー）にこのイベントを加える。加えないと、v0.4e のログの監査が状態との違いとして報告する（監査の確認になる）。
- にげるエネルギー・ワザのエネルギーの確認は、移したあとの `energy` で行う（今の処理のまま）。
- 「1 番に 1 枚」のエネルギーをつける制限（p.310。`energy_attachments_this_turn`）は手札からつけることの制限で、場の中で移すことは数えない見込み（B1・B2 で確かめる）。

## 8. 乱数・ログ・互換性

- エナジートランスは乱数を使わない見込み。コインを投げるパワーを加えるときは `flip_coins` だけを使う（CLAUDE.md）。
- フシギダネ・フシギソウ・フシギバナを使えるようにするには、`scripts/extract_kyuura_cards.py` に v0.5 のカードの組（`pool_v0_5`）を加えて写しを作り直す（参照コミット `ecb2d694` のまま）。写しの変更で、`card_verification.json`・tests/test_cards.py の固定値を見直す。
- フシギバナのいない対戦の結果は変わらないはず。v0.4e の道具で、v0.4e のコミットを基準に比べる（`python3 tools/compare_engine_versions.py --base <v0.4e のコミット>`）。駆動（tools/compat_driver.py）はポケモンパワーのコマンドを送らないので、そのまま使える。フシギバナを入れた組を駆動に加えるときは、参照データを基準の版から作り直す。

## 9. 壊さない固定値

- tests/test_reproducibility.py の固定値、各対戦のテストの `GOLDEN_DIGEST`・`EXPECTED_COUNTS`（デッキにフシギバナを入れない限り変わらない）
- tests/fixtures/v0_1_reference.json（作り直さない）、tests/fixtures/compat_base_4bd97bf.json（基準の版から作る）
- 書き出しの形式 1〜8 の形（ポケモンパワーで状態の項目を加えるなら形式 9。加えない設計を先に検討する）
