# 与えたダメージと、それに応じた回復（v0.4d）: バタフリーの「メガドレイン」

v0.4d で、ワザのダメージの要素の結果（`effects.DamageResult`）を後の要素に渡す仕組みと、与えたダメージの半分のダメージカウンターを自分からとりのぞくワザ（バタフリー PMCG2-007 の「メガドレイン」）を加えました。この文書は、「与えたダメージ」の定義、回復の条件と量、きぜつ・ダメージの防止との関係を、原典・実装・テストと対応づけた記録です。カードの照合は [butterfree-v0.4d.md](butterfree-v0.4d.md)、設計は [architecture-v0.4d.md](architecture-v0.4d.md) にあります。

- 照合の方法: Internet Archive のスキャン [J38] の PDF からページを画像（300〜400dpi）にし、目で読んだ（2026-10-12）。
- 分類: CONFIRMED・SUPPORTED・UNRESOLVED・CONFLICT（[forced-switch-v0.4d.md](forced-switch-v0.4d.md) と同じ）。
- 英語版の文面（kyuura の "(after applying Weakness and Resistance) (rounded up to the nearest 10)"）では決めていない。

## 2. ダメージの 4 つの量

| 量 | 定義 | メガドレインでの扱い |
|---|---|---|
| A. 基本ダメージ | カードに印刷されたダメージの目安（40）。p.321 の 1 段階 | 回復の計算には使わない |
| B. 最終計算ダメージ | p.321 の 8 段階（弱点・抵抗力・プラスパワー・ディフェンダーなど）を計算した数。0 以下なら 0 | — |
| C. 実際に与えたダメージ | B のこと（p.319「与えたダメージ」はあくまでも計算した数）。最終ダメージが 0 以下なら「与えなかった」。「ダメージを受けない」状態でダメージの要素が無効なら、計算せず、与えていない | 回復の条件（C > 0）と量（C の半分）に使う |
| D. 相手がきぜつするまでに必要だった残りの HP | 相手の HP − のっていたダメージ | 使わない。p.319 の例（HP 30 に 50 → 与えたダメージは 50）で、C は D で上限を付けない |

エンジンでは、C を `DamageResult.dealt` で表します（`amount` が B（防いだときは None）、`prevented` が「ダメージを受けない」状態で無効になったこと）。

## 3. DamageResult（ダメージの結果の受け渡し）

`effects.deal_attack_damage`（と `damage_opponent_active`）が、v0.4d から次の結果を返します。

```python
@dataclass(frozen=True)
class DamageResult:
    target: str          # OPPONENT_ACTIVE / SELF
    player: int          # 受けたポケモンの持ち主
    pokemon_id: int      # 受けたポケモン（場のポケモンの番号）
    prevented: bool      # 「ダメージを受けない」状態で、この要素が無効になった（計算していない）
    amount: int | None   # 最終ダメージ（0 以下は 0）。prevented なら None
    knocked_out: bool    # この要素のあと、受けたポケモンのダメージが HP 以上

    @property
    def dealt(self) -> int: ...  # 与えたダメージ。amount（None なら 0）
```

- 発生源はいつもワザを使うポケモン（`AttackUse.pokemon_id`）なので、結果には重ねて持たない。
- 計算した結果の 0（`prevented=False, amount=0`）と、ダメージを防いだこと（`prevented=True, amount=None`）を区別する。どちらも `dealt` は 0（「与えなかった」）だが、後の要素がどちらを同じに扱うかはカードごとの原典にしたがう（メガドレインはどちらも回復しない）。
- ログを読み直して直前のダメージを推定しない（ログは記録で、ルールの判断に使わない）。結果は状態に残さない（ワザの処理の中でだけ使う）。
- ダメージの値・計算の段階・ログ `damage`・`damage_prevented` の形・乱数（使わない）・きぜつの判定の時点は v0.4c と同じ。v0.4c までの呼び出し側は戻り値を使わず、動きは変わらない（[architecture-v0.4d.md](architecture-v0.4d.md) 14 章の比較）。

検討した方法と判断:

| 方法 | 判断 |
|---|---|
| 1. `deal_attack_damage` が結果を返す | 採用（2 と合わせて）。呼び出し側が結果を持つ |
| 2. 専用のダメージ結果型を加える | 採用（`DamageResult`）。必要な項目だけ（受けたポケモン・防いだか・最終ダメージ・きぜつするか） |
| 3. 今のダメージ計算（`DamageCalculation`）を再利用する | 採らない。防いだとき（計算しない）を表せず、受けたポケモン・きぜつを持たない |
| 4. ログを読み直す | 採らない（指示書 8.1・ログは記録） |

## 4. 回復の裁定

| # | 事項 | 分類 | 根拠 | 実装 |
|---|---|---|---|---|
| D1 | 「与えたダメージ」は最終ダメージ（弱点・抵抗力・プラスパワー・ディフェンダーを計算した数）。基本ダメージ 40 ではない | CONFIRMED | p.319（最終的なダメージ）、p.321（計算の順番） | `DamageResult.dealt` |
| D2 | 相手の残りの HP より大きいダメージでも、与えたダメージは計算した数（HP で上限を付けない） | CONFIRMED | p.319「HPが30しかないからといって、「与えたダメージ」が30になるのではありません」 | 残り 10 の相手に 40 → 与えたダメージ 40 → 回復 2 個 |
| D3 | 最終ダメージが 0 以下なら「ダメージを与えなかった」ので、回復しない | CONFIRMED | p.319（0 ダメージを与えたのではなく与えなかった。「ダメージを受けたら」の能力の例）、最新の説明「相手にダメージを与えたら」 | 回復しない（ログ `drain_heal` もない） |
| D4 | 「ダメージを受けない」状態の相手（ダメージの要素が無効）には、ダメージを与えていないので回復しない | SUPPORTED | p.321（ダメージの要素は無効）、p.319（与えなかった場合の条件の例）、最新の説明「相手にダメージを与えたら」 | 回復しない。p.321 の「ダメージ以外の効果は有効」は、回復の条件（ダメージを与えたこと）を満たすことにはならない（条件のない追加効果（どく・マヒ）とは違う。docs/persistent-damage-v0.4b.md 5 章） |
| D5 | 回復するカウンターの数は、与えたダメージの半分を、ダメージカウンター（10）の単位で切り上げた数 | CONFIRMED | 最新の説明「その半分（切り上げ）のダメージカウンター」、p.319（カウンター 1 個 = 10 ダメージ。ダメージはいつも 10 の倍数） | `(dealt // 10 + 1) // 2`。半分のダメージを 10 単位に切り上げても、与えたカウンターの数の半分を切り上げても同じ数になる（10 → 1、20 → 1、30 → 2、40 → 2、50 → 3、60 → 3、80 → 4、90 → 5） |
| D6 | とりのぞくのはワザを使ったポケモン（バタフリー）自身のダメージカウンター | CONFIRMED | 最新の説明「自分から」、p.19 の解説「この「バタフリー」自身から」 | 場のポケモンの番号（`AttackUse.pokemon_id`）で引く。ベンチのポケモン・下に重なったカード（トランセル）は別のポケモンではない |
| D7 | のっている数より多くはとりのぞかない（のっていなければ 0 個） | CONFIRMED（導出） | p.320（すべて取りのぞいたら、それ以上の回復はできない。v0.2b の「きずぐすり」の 1 個のときと同じ） | `min(回復の数, のっている数)`。0 個でもログ `drain_heal`（`counters` 0）を残す（ダメージを与えたので回復の内容は処理した） |
| D8 | 相手がこのダメージできぜつしても回復する | SUPPORTED | p.309（対象がいなくなった内容だけを無視する。回復の対象は自分で、いなくなっていない）、D2 | 回復のあとで、ワザのあとのきぜつ・サイド・交代（`_finish_attack`） |
| D9 | 回復はきぜつの判定の前（ワザの要素の 1 つ） | SUPPORTED（v0.2f のきぜつの判定の時点のまま） | p.309（ワザの要素をすべて処理する）・p.324 | ダメージ → 回復 → `_finish_attack` |
| D10 | こんらんのコインが「うら」なら、ダメージも回復もない（自分に 20） | CONFIRMED | p.309 の手順 5（もとのワザの内容に関わらず） | エンジンがワザの処理（`resolve`）を呼ばない（v0.3c） |

新しい未解決の裁定（`UNRESOLVED_…`）はありません。指示書 11.2 の候補（ダメージの防止・HP を超えるダメージ・与えたダメージ 0・特定のダメージ変更効果）は、どれも上の表で決まります（特定のダメージ変更効果は、p.321 の 8 段階の計算の中のもので、与えたダメージはその結果）。`DamageAndDrain.problem` は既定の None で、こんらんのコインの結果で受け付けるか・拒否のコードは変わりません（tests/test_effect_preflight_v0_3d.py `CoinIndependenceTest`）。プラスパワー・ディフェンダーがついたこんらん状態のバタフリーは、v0.3c の `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS`（こんらんの 20 にそれらを計算するか）で、コインの前に止まります（どのワザでも同じ。メガドレインのために変えていない）。

## 5. 処理（DamageAndDrain）

```
DamageAndDrain.resolve
  1. result = damage_opponent_active(state, use, 40)      # p.321 の順番。防いだら damage_prevented、そうでなければ damage
  2. result.dealt <= 0 なら終わり（与えなかった）          # D3・D4
  3. drain = (result.dealt // 10 + 1) // 2                  # D5
  4. removed = min(drain, バタフリーのダメージ // 10)      # D6・D7
  5. バタフリーのダメージ -= removed × 10、ログ drain_heal
→ エンジンが _finish_attack（きぜつ・サイド・交代・番の終わり）
```

ログ `drain_heal`: `player`（ワザを使ったプレイヤー）・`pokemon`・`pokemon_id`（バタフリー）・`effect`（`"PMCG2-007#1"`）・`dealt`（回復の計算のもとにした与えたダメージ）・`drain_counters`（半分の切り上げ）・`counters`（実際にとりのぞいた数）・`amount`（とりのぞいたダメージ）・`damage_before`・`total_damage`（とりのぞいたあと）。トレーナーの「きずぐすり」のログ `remove_damage_counters`（`player`・`pokemon`・`pokemon_id`・`counters`・`total_damage`）の形は変えていません（回復の計算のもとにした量などが要るので別のイベントにした）。

## 6. 計算の例

| 盤面 | 最終ダメージ（与えたダメージ） | 半分の切り上げ | バタフリーのダメージ 60 から |
|---|---|---|---|
| 相手ガーディ（弱点・抵抗力が草に関係しない） | 40 | 2 個 | 40 |
| 抵抗力 草 −30（テスト専用のカード） | 10 | 1 個 | 50 |
| ディフェンダー −20 | 20 | 1 個 | 50 |
| 抵抗力 −30 + プラスパワー +10 | 20 | 1 個 | 50 |
| プラスパワー +10・ディフェンダー −20 | 30 | 2 個 | 40 |
| プラスパワー +10 | 50 | 3 個 | 30 |
| 相手ディグダ（弱点 草 ×2）・ディフェンダー −20 | 60 | 3 個 | 30 |
| 相手ディグダ（弱点 草 ×2） | 80（ディグダの HP 30 を超える。D2） | 4 個 | 20 |
| 相手ディグダ・プラスパワー | 90 | 5 個 | 10 |
| 抵抗力 −30・ディフェンダー −20 | 0（40 − 30 − 20 = −10。与えなかった） | 回復しない | 60 |
| 「ダメージを受けない」状態の相手 | 計算しない（与えなかった） | 回復しない | 60 |

バタフリーのダメージで上限を付ける例（与えたダメージ 40、半分 2 個）: 0 → 0 個、10 → 1 個、20 → 2 個、30 → 2 個。

## 7. きぜつ・勝ち負け

- メガドレインで相手がきぜつする場合も、回復はワザの要素として先に処理し、ワザのあとできぜつ → サイド → 勝ち負けの判定 → 交代（v0.2f）。最後のサイドを取って勝つ場合も、回復は済んでいる。
- 回復でバタフリーのダメージが減っても、きぜつの判定はワザのあと（回復で HP を超えることはない。のっている数までしかとりのぞかない）。
- バタフリーがきぜつしたら（相手のワザ・ポケモンチェックのどく）、キャタピー・トランセル・バタフリーの 3 枚とついているカードをトラッシュし、相手はサイドを 1 枚取る（v0.4c のまま）。

## 8. 原典で決められない場合

なし（4 章）。v0.4c の [architecture-v0.4c.md](architecture-v0.4c.md) 14.2 の 9・10（ダメージ 0・ダメージを受けない相手のときの回復）は、p.319 の記述と最新の説明（「相手にダメージを与えたら」）で決まったので、止める必要がありませんでした（推測で決めたのではなく、0 と防止はどちらも「与えなかった」にあたる）。
