## 3. 処理の順序と情報源

### 3.1 送信のときの順序（静的。`8163910`）

1. **コマンドの入口:** `engine._apply_checked`。型の確かめのあと、状態を複製します（`new`）。
2. **姿の固定（入口）:** `engine.py:915` の `freeze_forms(new)`。**うらのカードをおもてにする前**です。
   - うらの使い手の定義は `FaceDownDefinition` で、特殊能力がありません。そのため、`transform_capable` は偽になり、固定の対象に入りません。
   - 場にほかの変身できるポケモンがいなければ、固定は空の並び（`()`）になります。
3. **公開:** `engine._reveal_for_action` → `zones.reveal_face_down`。
   - 本当のカードがたねでなければトラッシュし、コマンドを受け付けて番にもどります。L1・D1 はここで終わり、ハンドラ（ワザの確かめ）は呼ばれません。
   - 直接のコマンドで `attack_power=True` を付けても、確かめられずに受け付けられます（静的。保存結果なし）。
4. **公開のあとの姿:** 状態に持たず、問い合わせのたびに求めます（`current_form` → `live_form` → `transform_defender`）。
   - ［へんしん］は、バトル場にいて、特殊状態がなく、力が消えていなければはたらきます。
   - はたらくと、今の姿は相手のバトル場のいちばん上のカードです。
5. **ワザと力の特定:** `flow.check_use_attack` → `checks.attack_request` → `find_attack_option(card=None, attack_index)`。
   - ワザは、今の姿のカードのワザ（`ROUTE_FORM`）から位置で選ばれます。
   - ［すいりょくはつでん］は `effects.attack_power_check` が確かめます。`attack_power_slot` は `powers_of`（写した力をふくむ）から、同じカードのワザ名の力を探します。
   - 場の力は `effects.group_attack_powers_check` が確かめます（`group_attack_power_slot` も `powers_of` を読む）。
6. **使用の確かめのあとの固定:** `flow._use_attack` の `body` の `E.freeze_forms(res.state)`（`flow.py:167`）。
   - 入口の固定が空なら、ここで公開したメタモンの姿を固定します。
   - **入口の固定が空でなければ**（場にほかの変身できるポケモンがいた）、何もしません（`if state.frozen_forms: return`）。
7. **先読みと本処理:** v0.189 から、先読みの複製の元は handler の入口の状態（公開と確かめのあと）です。

### 3.2 公開の前に示すワザ番号が指す定義

- **今の値:** うらの候補のワザは、`("attack", 印刷の位置, None)` → `UseAttack(attack_index=位置, card=None)` です（`legal_actions._attack_command`）。
- **公開のあと:** `card=None` は**今の姿のカード**のワザの位置です。
  - 変身しない本当のカードは、今の姿が印刷のカードなので、印刷のワザと同じものを指します。
  - 変身できる本当のカード（メタモン 2 枚）は、印刷のワザがありません。そのため、今の候補は段なしで、番号を出していません。
- **構造上の注意（今の登録では起こらない）:** 印刷のワザを持ち、公開のあとに［へんしん］がはたらく登録がもし加わると、印刷の位置で示した番号が相手のカードのワザを指します。今は、登録の事実（メタモンにワザがない）だけで守られています。これを確かめる専用のテストは見当たりませんでした（grep）。
- **印刷のワザと変身のあとのワザ:** 対応はありません。変身のあとのワザは、相手のおもてのカードの印刷のワザの並びです。数・順序・必要なエネルギーは、そのカードのものです。支払いはどの色でもできます（`attack_cost_payable`）。

### 3.3 ［すいりょくはつでん］をワザといっしょに使える条件

`attack_power_check`（`effects.py:37446`）で、どれも状態を変えません。

- 使い手が、ワザのカードと同じカードの力で、説明の名前のワザ（まぶしいひかり）を使うこと（`attack_power_slot`）。
- 使い手がねむり・マヒ・こんらんでないこと。
- 力が消えていないこと（`power_suppressed`）。使えない効果がないこと（`powers_use_prevented`）。
- エネルギーの数え方が決まること（RB1・BZ2・MEC1・CE1・CE2）。

**変身の経路で、静的に分かった点（エンジンの未確認。今回は直していない）:**

1. **写した力の確かめを通らない:** v0.124 の文書（3.1 節）では、写すことを確かめていない宣言する特殊能力は未対応（`UNSUPPORTED_TRANSFORM_COPIED_POWER`）です。確かめた実装は `COPY_VERIFIED_DECLARED` の 4 つで、`ExtraEnergyDamageWithAttack` は入っていません（実行確認）。
   - ただし、その確かめ（`copied_declared_power_problem`）を呼ぶのは `UsePokemonPower` の経路（`engine.py:2494`）だけです。
   - `attack_power_check` と `group_attack_powers_check` は呼びません（ソースの確かめ。実行確認）。
   - そのため、メタモンが写した［すいりょくはつでん］（T1-L）と、写した［XXXXX］・［ANGER］の自己持ち主（T1-U）は、この確かめなしに受け付けられうると読めます。受け付けるかは実行していません。
2. **TE1 を聞かない:** ［へんしん］のメタモンのエネルギーは「どの色のエネルギーとしても」使えます。ワザの説明が色のエネルギーを数えるときは、TE1（`UNRESOLVED_TRANSFORM_ENERGY_COUNT`）で止めます（`programs.transform_energy_question`）。
   - ［すいりょくはつでん］の数（`extra_units`）は、ついている「水」の単位をそのまま数え、TE1 を聞きません。
   - `ExtraEnergyDamageWithAttack` の説明の文は「［へんしん］で写した特殊能力は TF1」です。v0.124 で写した特殊能力を持つことが決まったあとの扱いは書かれていません。
3. **公開したメタモンの姿の固定:** 3.1 節の 2 と 6 のとおりです。場にほかの変身できるポケモンがいると、公開したメタモンの姿は、ワザのあいだ固定されないと読めます（CR-TRANSFORM-FROZEN-DURING-ACTION）。
   - おもてのメタモンは入口で固定されるので、うらから公開したときだけの差です。
   - ワザの途中で相手のバトル場が変わる（入れ替え・きぜつ）と、姿が変わりうると読めます。実行していません。

### 3.4 v0.192 の仮の評価を変身へ流用しない理由

- **v0.192 の根拠:** 公開のあとの姿が印刷のカードであることです（22 型に変身の型がなく、「ばける」もない）。
- **変身の経路では、この根拠が成り立ちません:**
  - 本人が知るのは「本当のカードがメタモン」ということだけです。
  - 公開のあとの定義（名前・ワザ・力）は、相手のバトル場のカードと、公開の場の抑止で決まります。
  - 印刷の定義の力（［へんしん］）は、宣言といっしょの力ではありません。
- **「本当のカードを知る」ことと「変身のあとの定義を知る」ことは別です:**
  - 前者は本人だけの知識です（観測の `real`）。
  - 後者は、相手のバトル場がおもてなら公開のカードから計算できます。ただし、公開の場の抑止と、写す相手の状態（TF1〜TF3）の評価が要ります。
  - 相手のバトル場がうらなら、相手の秘密が要ります（O1）。

### 3.5 相手の状態が変わったとき

| 変化 | 公開のあとの姿・適格性 |
|---|---|
| 相手がバトル場を入れ替える・きぜつのあと出す | 写す相手が変わる。ワザの並び・力・名前のグループが変わる |
| 相手のバトル場がうらになる（うらのカードが出る） | FD1 で止まる（O1） |
| 相手の場にかがくへんかガス・ふしぎなガスなどが出る | ［へんしん］が消えて印刷のまま（ワザなし。O5）。写す力も消えうる |
| 相手のバトル場がばける・トレーナーをポケモンとして出す | TF2・TF3（O3） |
| 相手のバトル場がベイビィで、相手の場に［いあつ］ | TF1 の残る部分（O4） |
| 相手のバトル場の特殊状態・ダメージ | 写さない（メタモンのもの）。適格性は変わらない |

### 3.6 姿の固定の処理を、候補の作成で参照できるか

- **`freeze_forms`・`release_frozen_forms`:** 状態を書き換えます。候補の作成（状態・乱数・ログを変えない約束）では呼べません。
- **`live_form`・`current_form`:** 問い合わせで、状態を変えません。ただし、うらの使い手では `FaceDownDefinition` を読むので、公開のあとの姿にはなりません。
  - うらの間は特殊能力がないので、［へんしん］が見つからず、印刷（うらのカード）の姿が返ります。
- そのため、公開の前に公開のあとの姿を求めるには、本当のカードの登録から［へんしん］を読み、相手のバトル場のカードを写す、**別の仮の評価**が要ります。
  - その評価が送信のときのエンジンと一致するかは、3.3 節の 3 点（写した力の確かめ・TE1・固定の時点）が決まらないと言えません。
