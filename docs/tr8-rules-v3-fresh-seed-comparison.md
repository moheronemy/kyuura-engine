# 未使用 seed の C1 での rules-v2 と rules-v3 の比較

2026-11-24。文書の基点 `claude/tr8-swap-loop-rules-v3` の `6473eda`、方策の実装は `001210f`（固定）。[前回の実験](tr8-damage-swap-loop-experiment.md) は既知の seed 9023・9022・9024 での比較だった。
今回は、未使用の 8 seed の C1（L67-U どうし）で方策だけを変えて 16 局を比べた。機械可読の値は同名の JSON にある。

## 0. 要約

- **完了した組**: 8 組中 8 組（16 局すべて完了。未完了・未着手 0、打ち切りなし、停止方針の発動なし）。
- **方策別の完走率**: `rules-v2` 8/8、`rules-v3` 8/8（すべて `game_over`）。組の区分は両側完走 8・v2 だけ 0・v3 だけ 0・両側非完走 0。
- **往復**: ダメージの配置に戻った操作は 316 → 33。［ダメージスワップ］の受理は 409 → 79、受理の総数は 1,140 → 799。
- **有効な手への影響**: `rules-v3` が下げた 15 回とも、次に選んだ「にげる」は組み立てられず（`total_units_unreachable`）、番の終了に進んだ。下げた時点にほかの順位 5 の候補はなかった。
  `rules-v2` だけで見られた［ダメージスワップ］→ にげる・トレーナーの例（9032 の 3 例・9034 の 1 例）は、どれも分岐のあとで、その局面は `rules-v3` の局に現れなかったので、失った有効な手には数えない（0 件）。
  ワザの受理は両側とも合計 131。
- 4 組（9027・9030・9031・9033）は［ダメージスワップ］を使わず、両側の局が同じだった。
- 対象は C1 の 8 組だけで、全デッキの完走率や既定化の妥当性はこの結果だけでは判断しない。

## 1. seed の選定

保存先 30 か所のすべての `plan.json`（86）と局の `header.json`（418）、seed を書いた docs の JSON（14）を読み、seed を集めた（読めないファイル 0）。
使用済みの最大は 9026 で、9027 以上で連続 8 値がすべて未使用の最初の組は **9027〜9034**。実行の順は seed の昇順、各 seed で `rules-v2` → `rules-v3`（16 回）。
seed・順・両方の `plan.sha256` は初局の前に固定した（証跡 `out/seeds.json`・`out/plan_sha256_all.txt`）。

  分岐のあとで旧局面が出なかったので、失った有効な手には数えない。

## 5. 判定

- **往復が減ったか**: 減った。［ダメージスワップ］を使った 4 組すべてで、配置の戻りが 144 → 13・68 → 10・93 → 4・11 → 6、観測の一致の検出が 52 → 5・33 → 5・41 → 2・8 → 3。
- **完走に差があったか**: なかった。両側とも 8/8 が `game_over`。番の数は 9028 で 65 → 69、9032 で 33 → 27、ほかは同じ。
- **有効な手を妨げた証拠があるか**: 見つからなかった。下げた 15 回とも代わりに組み立てられる手は番の終了だけで、v2 だけの［ダメージスワップ］→ にげる・トレーナーの例は分岐のあとの、v3 に現れない局面だった。
  ただし、下げた時点にほかの組み立てられる手があった場面は 1 回もなく、その場合の影響は観測していない（6 章）。

## 6. 未確認事項

- C1 の 8 組だけ。ほかの条件（C2〜C4）・デッキでの完走率と既定化の妥当性は判断しない。
- 4 組は［ダメージスワップ］を使わず、方策の差を比べられなかった。
- 下げた時点に、番の終了のほかに組み立てられる手があった例がない。
- 9023 の旧停滞に途中から入る検証は別の単位。
- 続き: 下げたあとに組み立てられる別の手がある場合は、構築盤面で [tr8-rules-v3-buildable-alternatives](tr8-rules-v3-buildable-alternatives.md) で確かめた（にげる・トレーナーを選んで受理。同じ持ち主の別の移動も下がる制約あり）。

## 7. 既知の不安定なテスト

`tests.test_verification_ai_prestop` の `test_rows_1mib_counts_utf8_bytes_and_newlines_before_writing` は、行に実測の経過時間が入るため全体の実行で失敗することがある（[前回](tr8-damage-swap-loop-experiment.md) 3 章。基点でも同じ）。
この単位はコードを変えず、このテストは走らせていない。対戦記録の照合（完了記録・ハッシュ・観測・prestop の要約と照合式・judge・replay・キャッシュ）とは別のもので、16 局の照合はすべて成り立った。

## 8. 失敗の記録

- F1: 計画の sha256 の一覧を書く PowerShell の手順で、変数 `$r`（sha256）が `$R`（作業記録のパス。PowerShell は大文字と小文字を区別しない）を上書きし、r3 の計画の写しを本体の checkout の中の
  名前が sha256 のフォルダに書いた。この単位が作ったフォルダなので中身（plan.json・plan.sha256 の写しだけ）を確かめて消し、別の変数名でやり直した。計画・局のファイルには影響なし。
