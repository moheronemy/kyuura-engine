## 2. 資料と判断

- 根拠は kyuura の `data/cards.json` の印刷の文面（採用の記録 `kyuura_engine/data/card_sources.json` の PMCG3-034・037・038。`basis: kyuura_data`・`adopted`・処理に使う文面は `kyuura_printed_text`・研究の対応表の `adopted_printed_text`）。kyuura の研究の基準のコミットに、3 枚の最新の説明・エラッタ・裁定・論点・照合の記録はありません。
- pcg-search.com の同じ版のページ（第3弾 拡張パック「化石の秘密」の 035/048・036/048・037/048。名前・段階・進化元・HP・タイプ・弱点・抵抗力・にげる・ワザの名前・エネルギー・ダメージ・説明文）と照らし、3 枚とも `match` でした（2026-10-18）。kyuura の日本語の文面の転記元は pcg-search.com ではない（`ja_text_source`）ので、独立した照合です。カードの画像は読んでいません。

### 2.1 書き方の違い（明示的に加えた 1 通りずつ）

- かたくなる: イワークの「次の相手の番に受けるダメージが0になる。ただしダメージが40以上の場合は、そのままダメージをうける。」に、ゴローンの「次の相手の番にこのカードが受ける30以下のダメージは0になる。(ダメージ以外の効果はそのまま)。40以上のダメージはそのまま受ける。」を加えました（`effects.zero_damage_below_texts`）。「30以下」と「40以上」はダメージカウンターの単位で隣り合い、あいだのダメージはありません。「(ダメージ以外の効果はそのまま)」は v0.45 の `ZERO_IF_BELOW`（8 段階の計算の結果が 0 でもダメージ以外の効果は受ける）と同じ扱いです。「ダメージを受けない」状態（`PreventDamage`）としては登録していません。かっこの全角・しきい値の違い・「(ダメージ以外の効果はそのまま)」を落とした文は受け付けません（`RegistrationTest.test_text_variants_are_limited`）。
- じばく: 化石の秘密のレアコイルの「…「弱点・抵抗力」に関係なく、それぞれ20ダメージ。」に、ゴローニャの読点のない「…に関係なくそれぞれ20ダメージ。」を加えました（`SELF_DESTRUCT_TEXTS[True]` の 2 つめ）。読点を一律に取り除く比べ方にしていません（読点の位置が違う文・空白のある文は受け付けない）。スタジアムをトラッシュする「じばく」（タケシのゴローンの「ばくれつ」）の書き方には、読点のない書き方を加えていません。

## 3. れんぞくいしなげと先読みの有限の組

### 3.1 実際のコイン

- 「うら」が出るまで 1 枚ずつ投げます（`coins.flip_until_tails`。1 枚 1 回 `getrandbits(1)`）。枚数・ダメージに上限はなく、決まった枚数で打ち切らず、分布が同じ別の乱数の使い方にもしていません。
- 「おもて」の数 × 10 が p.321 の 1 段階（基本となるダメージ）で、そのあとの段階（弱点・抵抗力・プラスパワー・ディフェンダー・持続する効果・常にはたらく特殊能力・スタジアム・順番の決定）・防ぐ効果（「ダメージを受けない」状態・「とうめい」・「かげぶんしん」）・ダメージを受けたときの効果は、ほかのダメージの要素と同じ `kernel.deal_damage` です。
- 1 枚目が「うら」なら基本となるダメージは 0 で、2 段階で計算を終える「ダメージを与えなかった」です（ログ `damage` の `amount` 0・`stopped_after_step_2`）。ワザの失敗（`attack_failed`）にはしません（v0.2d の「おもて」の数 × のワザと同じ）。
- 手順 4 のコイン（すなかけなど）・こんらんのコインでワザが止まったら、このコインは投げません。コインはダメージの量だけを決めるので、「ダメージを受けない」状態・「ワザをうけない」状態の相手には、コインの前に v0.4b の `UNRESOLVED_PREVENTED_COIN_DAMAGE` で止めます（状態・乱数・ログは変わらない）。
- ログは 1 枚ごとの `coin_flip`（`number`・`count` は投げた枚数・新しい項目 `until` は `"tails"`）。投げ終えてからまとめて残します（投げている間にほかの処理はない）。
- ワザの履歴（v0.62）・ログには実際のダメージが残ります。
- 順番の決定（v0.35）をまたいでも、基本となるダメージを決定の続きの情報で運び、投げ直しません（`Damage.resume`）。保存と復元（pickle）のあとも同じに続きます。

### 3.2 先読みの有限の組（`resolution/unbounded.py`）

先読みは、コインのすべての結果を 1 つずつ試せません（「おもて」の数 h に上限がない）。そこで h を有限の組に分け、組ごとにいちばん小さい h（代表）だけを試します。代表の値は先読みの複製の上だけで使い、実際のダメージ・ログ・履歴には使いません。

**h が後の処理に入る場所**: このワザの要素は `Damage(OPP, HeadsUntilTails(10))` だけで、h が入るのは、基本となるダメージ b = 10h を `deal_damage` に渡すところだけです。そのあとの処理が b から受け取るのは、次の 2 つだけです。

1. p.321 の計算の結果: 最終ダメージ d、2 段階で終えたか、順番の決定が要るか（要るなら選べる順番ごとの結果）、色の読み方（VS1）で結果が変わるか。d > 0 のときだけ「とうめい」・「かげぶんしん」・受けるときの窓（送る効果）がはたらく。d は受けるポケモンのダメージ（きぜつ・［ずらかる］の「ちょうど 10」・こんじょう・［ファイナルビーム］・キョウのどく・同時のきぜつ）に入る。
2. 受けたダメージで量が決まる返す効果（こうらがえし・クロスカウンター。`state.Retaliation` の `basis` が受けたダメージ）: 返すダメージの基本となるダメージは d × 倍数で、それをワザを使ったポケモンへのワザのダメージとして計算する（無効・CP1・順番の決定（返す効果の枠では出せないので止まる）・色の読み方・最終ダメージ r）。r はワザを使ったポケモンのきぜつ・同時のきぜつ（W24）に入る。量の決まった返す効果（ほのおのかべ）・特殊能力のダメージ（はんげき・わるいねぞう）・［ぼうぎょかふん］は、d > 0 かどうかだけで決まる。

受けたダメージの量そのものはログとワザの履歴にも残りますが、先読みの範囲（宣言からきぜつの判定まで）では読まれません。

**組の key**: `key(h)` は、実際の処理と同じ関数（`kernel.attack_modifiers_of`・`with_stadium_coin`・`compute_damage`・`calming_retaliation_differs`・`deferred_receivers`。v0.64 で `deal_damage`・`calming_retaliation_question`・`receiving` から分けた。動きは変えていない）で求めた、次の値です。

- 受けるポケモンの計算の木（順番の決定なら段階と選べる順番ごとの子、色の読み方で変わるなら `readings`）。葉は (min(d, 受けるポケモンの残りの HP), 2 段階で終えたか, d > 0 なら返す効果ごとの結果)。
- 返す効果ごとの結果は、与える相手がすでに HP 以上なら `skipped`、無効なら `void`、CP1 なら `cp1`、順番の決定なら `order`、色の読み方なら `readings`、ほかは (min(r, ワザを使ったポケモンの残りの HP), 2 段階で終えたか)（`kernel.attack_damage_to_damage_source`・`deal_damage` と同じ順番）。

d が残りの HP 以上なら、どれもきぜつし、［ずらかる］の「ちょうど 10」も起こらないので、残りの HP にまとめます。まとめるのは組を分けるためだけです。同じ key の h は、先読みの範囲のどの結果（当たる問い・場の状態）も同じになります。

**有限であることの根拠**: 計算の各段階の操作（`damage.DAMAGE_OPERATIONS`。加える・その数にする・かける・しきい値より小さければ 0・しきい値以上なら 0・しきい値以上ならその数・半分（切り上げ・切りすて））と弱点（× 2）・抵抗力（− 数）・最後の 0 での下限は、どれも「入力が十分大きければ、一定か、入力について減らない」操作です。段階・変更効果の数は場で決まり有限なので、次がいえます。

- 変更効果の数・しきい値・その数・抵抗力・飽和の値（残りの HP など）の和を T、半分にする効果の数を m（P = 2^m）、かける数（弱点を含む）の積を K とします（どれもダメージカウンターの単位の倍数であることを確かめる）。
- 道が 1 つなら b ≥ P·T、2 つ以上（同じ段階に加算でない効果を含む 2 つ以上の効果・色の読み方・CP1 の 2 つの読み方）なら b ≥ 3·K·P²·T で、どの道も「一定」か「P 枚ごとに同じ数だけ増え、飽和の値以上」の形になります（増える道の傾き α は 1/P の倍数で、2 つの道の値の差は K·P·T を超えないので、傾きの違う道は 2·K·P²·T を超えると等しくならない。傾きの同じ道の差は P を周期とする。半分の切りすての余りも、P 枚ごとに同じ数だけ増えるので周期 P で同じになる）。
- 返す効果があれば、受けたダメージの飽和の値を、返す効果の計算の B を倍数で割った値まで上げ、周期を両方の P の積にします（返す計算の入力は、P 枚ごとに 10·P_返す の倍数だけ増える）。

したがって h ≥ h_s = ⌈B / 10⌉ では key(h) = key(h + P) で、h = 0 〜 h_s + P − 1 の key で、すべての h の key が尽くせます。組の代表は、その中のいちばん小さい h です（どの問いでも、当たるいちばん小さい h は代表なので、止める問いと理由の文の値も、1 つずつ試したときと同じ）。

**先読みでの使い方**: 先読みの乱数（`preflight.Oracle`）の `coin_run` が台本の 1 つの値で代表を選びます（値の小さい順 = h の小さい順）。組は、1 回の先読み（`explore`）の中で、それまでに使った台本の値が同じなら同じ（複製の上の処理は台本の値だけで決まる）ので、使った値の並びで覚えて求め直しません。`derived` の実際の処理（`RecordingRandom.record_run`）は元の乱数で 1 枚ずつ投げ、実際の h の key がどの組かを 1 つの値として記録します（`sibling_roots` がほかの組を試す）。実際の h の key が組にない（根拠の定理が成り立たない）なら `RuntimeError` です。`MAX_BRANCHES`（4,096）は変えていません。

**対応する計算と前提**: `SUPPORTED_OPERATIONS` の 8 つの計算、整数の弱点の倍数、ダメージカウンターの単位の倍数の変更効果の数・しきい値・抵抗力・残りの HP、要素の項目が既定（相手の対戦ポケモンへ・弱点と抵抗力を計算する・相手の効果を受ける）。満たさない場は推測せずに止めます（問い `unbounded_coin_preflight`・`UNSUPPORTED_UNBOUNDED_COIN_PREFLIGHT`。エンジンの未対応で、ルールの未解決ではない。研究の対応表の停止コードに入れていない。今の写しでは起こらない）。

**v0.13 の止める関数**: `damage_profile` は候補を並べられないので `NotImplementedError` にし、`v013_checks.VERIFIED` には入れていません（比べる方法 `legacy` も、この型はすべての結果を試す方法で確かめる）。

### 3.3 確かめたこと（単体テスト）

- h = 0・1・2・7・8・9・30 と 250 枚の「おもて」のあとの「うら」（`tests/helpers.py` の `with_coin_bits`。乱数の内部の状態を直接決め、seed を探さない）: コインの数・ログ・乱数の使い方（h + 1 回）・実際のダメージ。3 つの先読みの方法で同じ。
- プラスパワー・ディフェンダー・なぞのかべ（30 以上は 0）・草の弱点のない相手、「ダメージを受けない」相手のコインの前の停止、こんらんの「うら」でコインを投げないこと、ワザの履歴の実際のダメージ。
- 有限の組: イワーク・バリヤード・ディフェンダー・プラスパワー・こうらがえし（2 つの盤面）・サカキのカイリキー（こんじょう）・タケシのオコリザル（［ずらかる］の 60 が組を分ける）で、h_s から 30 周期の key の周期性と、組の代表だけの先読みと 0 〜 N − 1 のすべての h を試す先読みの答え（受け付けるか・止める問い・理由の文）が同じこと。今の写しにない計算（その数にする + 加える・半分（切り上げ）+ しきい値より小さければ 0・2 つの半分（周期 4））は盤面を直接作って確かめた。根拠の前提を満たさない計算（5 を加える）は止まり、状態は変わらない。
- こんじょうの決定の保存と復元・不正な答え、ピッピの「ゆびをふる」・ピジョンの「オウムがえし」（ワザを使うのはまねたポケモン。コインは新しく投げる。エネルギーを払えなければ既存の MM2）。

有限のテストだけでは根拠になりません。根拠は 3.2 節の議論で、テストは議論の前提（key に入れた値が実際の処理の値と同じ・周期性・代表と全数の答えの一致）を境界・代表・中間の値で確かめたものです。

### 3.4 費用

組の key は h = 0 〜 h_s + P − 1 について求めます。道が 1 つの盤面では h_s は 10 前後で、先読みのワザ 1 回は数ミリ秒です。2 つの半分と順番の決定のある盤面（直接作った）では h_s が 1,536 になり、組を求めるのに 0.3〜0.6 秒かかります（1 回の先読みの中で覚えるので、試す結果ごとには求め直さない）。今の写しにこの盤面を作るカードの組み合わせはありません。

## 4. ゴローンのかたくなる

- 効果は自分自身の持続する効果 `state.ZeroDamageBelow(threshold=40)`。次の相手の番に受けるワザのダメージの p.321 の 8 段階で、その段階のダメージが 40 より小さければ 0、40 以上ならそのまま（30 は 0、40 は 40、50 は 50。テスト）。ダメージ以外の効果は受けます（ビードルのどくばりの「おもて」で、ダメージ 0 のままどく状態になる）。期限・進化・入れ替えは v0.45 の処理のままです。イワークの登録・動きは変えていません。

## 5. ゴローニャのじばく

- 相手 → 自分 → 相手の控え全員 → 自分の控え全員（v0.39）。自分への 100 は、ワザによる自分へのダメージの通常の計算で、残りの HP に関係なく自分をきぜつさせる処理ではありません（ディフェンダーがあれば 80 で計算する。テスト）。控えへの 20 は「弱点・抵抗力」に関係なく。
- きぜつ・サイド・勝ち負け・バトル場に出すのはワザのあとにまとめて（同時のきぜつ。4 匹きぜつの盤面をテスト）。T27・C34/C35・G40・SC1 は既存の範囲のまま当てはまります（新しいコードにしていない）。
