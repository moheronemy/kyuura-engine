### 3.2 修正（`effects.bench_entry_unconfirmed`）

- 本人に見えない自分のカード（v0.137 の `unseen_card_pool`）のうち、アンノーン（たね。`CardFilter("basic_pokemon", name_group="アンノーン")`）で**ベンチに出しても止めない**
  （`goop_gas_entry_check` に当たらない）カードが U 枚、山札の外の見えないカードが C 枚なら、山札のうらに少なくとも max(0, U − C) 枚ある（鳩の巣の原理。v0.137 の下限を、カードの id の
  条件からカード 1 枚ずつの条件に広げた共通処理 `effects.deck_lower_bound_where`）
- 止めるかは、カードの定義（`in_play_def` の特殊能力の有無）・公開の場の効果（ベトベトガス・ふしぎなガス・やみのはどう）・カードの持ち主だけで決まり、カードの場所を読まない。U は持ち主が
  知っている集合、C は公開の枚数なので、結果は配分によらない
- U − C が 1 以上なら受け付ける（山札に止めないカードがかならずあり、段階 4 の決定に止めない答えがかならずある）。1 より少なければ、本人に見えないアンノーンのうち止めるカードのコード
  （いちばん小さい文字列。持ち主が知っている集合だけで決まる。ふつうは 1 つ）で止める。理由の文は「そのコードの決まった理由（`GOOP_GAS_SCOPE_REASON` など）」＋
  `BENCH_ENTRY_UNCONFIRMED_DETAIL`（カードの名前・uid・特殊能力の名前・枚数・位置を書かない）
- 止める効果がはたらいていなければ None（段階 2 の ST1 が先）

### 3.3 公開の情報を消していないこと

理由の文から消したのは、山札の見えないカードを指す値（uid・名前・特殊能力の名前）だけ。どの効果で止めるか（コード・そのコードの理由の文）は残した（場の効果は公開のログにある）。ベンチの
空き（`BENCH_FULL`）の文は変えていない。

### 3.4 使える条件・増えた制限

- 写しのアンノーン 26 種はどれも特殊能力を持つので、ガスのもとでは U = 0 で、受け付ける場面はない（修正の前も、山札に 1 枚以上あれば全部止めるので拒否。受理・拒否・コードは
  修正の前と同じ。変わったのは理由の文だけ）。ガスがなければ U = K で、v0.137 の ST1 の条件と同じ
- 止めないカードと止めるカードが混ざる候補（今の写しにはない。共通処理のテスト `BenchEntryHelperTest` で `CardFilter("basic_pokemon")` のコラッタ・ドガースで確かめる）では、止めない
  カードが実際には山札にあっても下限が足りなければ止める（**保守的な制限**。修正の前の確かめなら受け付けた配分がある）。遺跡の石版の登録では起こらない

### 5.4 受理が相手・観戦者に伝える情報（残る性質）

- 拒否: 状態・乱数・ログを変えないので、相手・観戦者の観測・ログの写しには何も残らない。送ったのが使ったプレイヤーなら、その人はもとから K・C を知っているので、新しく分かることはない
- 受理: 使った事実と、段階 3 でもどしたカード（見せる）は公開。特殊エネルギーカードをもどしたなら、相手・観戦者に「使ったプレイヤーの見えない基本エネルギーカードが C + 1 枚以上ある」
  ことが伝わる（修正の前は「山札に基本エネルギーカードがある」）。どちらも使ったプレイヤーの非公開の情報（デッキの構成）の 1 ビットで、相手は試せない（相手は使う宣言・段階 2 の答えを

### 5.5 状態と決定の安全性

- 使う前の拒否（段階 1）は、手札から出す前・状態の複製の上の確かめ（`check_playable`）で、状態・乱数・ログを変えない。カードを動かしてから例外でもどして受理・拒否を返す処理は作っていない

  止めない答えを送れる（`test_rejections_are_pure_and_repeatable`）。使ったあと（`play_trainer` は公開）の状態と、使う前の状態は区別していて、どちらの拒否も配分によらない
- 切る（段階 4・6）・コイン（段階 5）は受け付けた答えのあとだけ乱数を使う。乱数を使う回数は修正の前と同じ（もどす → 切る → コイン →「おもて」なら選ぶ → 切る）
- 先読み・決定の継続・探索の上限は変えていない。未探索の枝を成功扱いにしていない
