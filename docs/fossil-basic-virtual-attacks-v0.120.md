# v0.120: 化石の復活と仮想ワザの供給

v0.120（版 0.120.0）は、先行修正 A0（ナツメのESPとコピー前後のコインの内部エラー）と、化石の復活（進化カードを進化元を重ねずに出し、場ではたねポケモンとしてあつかう）・
ワザの供給（ワザを選んで自分のワザとして使うワザ・「使ってよい」「使うことができる」と書く許可で使うワザ）を使う 11 枚（ポケモン 10・トレーナー 1。ワザ 15・特殊能力 5）を、
kyuura データの採用で登録する版です。共通の処理（ワザの持ち方と支払うポケモン・選ぶワザの範囲と合わせた支払い・場の分類・復活の配置・保存の形式）に加え、カードの登録は登録の側に
置きました。`engine.py`・`resolution/` にカードの id による分岐は加えていません。

## 2. A0: ナツメのESPと、コピー前後のコイン

### 2.1 再現（固定した v0.119）

- 盤面: 超・水のついたナツメのフーディン（PMCG6-053）が、超の色マーカーをのせたベンチのカスミのコダック（PMCG5-021）から［サイコリンク］で「ちょうのうりょく」を使う。ナツメのESP
  （PMCG6-087）は通常の `PlayTrainer`・`ResolveDecision` でフーディンにつけた。相手のバトル場はラッキー（PMCG1-068。まるまる: コイン 1 枚・すてみタックル）。tests の
  `test_variable_coins_search_attachments_v0_113.esp_board("PMCG5-021", energy=(PS, W), opponent=mon("PMCG1-068"))` と `provider_card` で作り、`attack(state, 0, HD, HD, HD, card=...)` を実行した。
- 固定した v0.119 では、宣言の前の先読みが「おもて」3 枚 → ラッキーの「まるまる」に入り、まるまるのコインでコードのない問い `esp_separate_coin_tosses`（ES0）に当たって
  `RuntimeError`（「今の対応カードでは起こらないはずの問い」）になった。
- 隣の例: ESPをつけない同じ組み合わせはワザを選ぶ決定まで、相手をコインのないワザ 2 つのエビワラー（PMCG1-058）にした盤面はESPの決定 → ワザを選ぶ決定まで進んだ。
- この再現は組み立てた盤面で、`new_game` からの対戦ではない。

### 2.2 原因（エンジンの不具合と、裁定の不足を分ける）

1. **前提の誤り（エンジン）**: v0.66 は ES0 を「どのワザも説明文のコイントスは 1 回にまとまっている」として、今の写しでは起こらないコードのない問いにした。ちょうのうりょくの
   「おもて」3 枚（・ゆびをふる）で自分のワザとして使った別のワザのコインは、この前提に入っていなかった。
2. **続きの情報の欠け（エンジン）**: やり直しを聞いたこと（`AttackRun.esp_done`。真偽値）を、決定をまたいで運んでいなかった。ちょうのうりょくのコインでやり直しを聞いたあとの
   ワザを選ぶ決定（`SELECT_ATTACK`）をまたぐと、実際の処理は聞いたことを忘れ、まるまるのコインでもう一度ふつうのやり直しを聞いた（「各回やり直せる」を根拠なしに選んでいた）。先読みは
   決定をまたがずに続けるので ES0 に当たり、先読みと実際の処理が食い違っていた。
3. **裁定の不足（研究上の未解決）**: ナツメのESPの「そのワザの説明文に書かれているすべてのコイントスを、もう1度やり直してよい」が、宣言したワザ（ちょうのうりょく）の説明文のコインの
   ほかに、自分のワザとして使った別のワザ（まるまる）の説明文のコインも含むか、含むなら先のコインのやり直しのあとにもう一度やり直せるか（まとめて 1 回か、コイントスごとか）は、
   印刷の文面・2000.02.14 版の公式ルール・kyuura の記録から決められない。

### 2.3 直し方

- やり直しを聞いたことを、要素の並びのワザ（`AttackRun.esp_asked`。処理しているワザの `AttackKey` の並び）として持ち、ESPのやり直しの決定でない決定の続きの情報 `esp_asked` で運ぶ
  （聞いていなければ書かない。v0.119 までの決定の形は変えない）。ESPのやり直しの決定は、答えのあとに処理している並びのワザを記録し直す（`apply_esp_redo`）ので書かない。
- 説明文のコインを投げたときの確かめ（`AttackRun._esp_begin`。`flip`・`flip_chain`・`flip_until_tails`・`flip_each` の共通）:
  - 同じワザ（要素の並び）で 2 回目に聞く: 今までどおり ES0（コードのない問い。今の写しでは起こらない）。
  - 宣言したワザで聞いたあとに、自分のワザとして使った別のワザのコインを投げた: やり直しの決定を出し、**やり直すは選ぶと止める**（EC1 `UNRESOLVED_ESP_COPIED_ATTACK_COINS`。
    `unresolved_choices`）。やり直さないは、どの読み方でも答えになる（ESPは「のぞむなら」）。v0.66 の ES1〜ES3 と同じ形で、合法な隣の経路（やり直さない）を残す。
  - それ以外は v0.66 のまま（ES1〜ES3）。
- 先読みは、EC1 の決定でやり直さないだけを試す（止める選択は試さない）。宣言を拒否しない。
- ちょうのうりょくのコインのやり直し（1 回目）は、v0.66 のとおり投げた直後・結果を使う前に聞く（コピーするかがこのコインで決まり、コピー先のコインはまだ投げていない）。
  コピー元のコインのない「ゆびをふる」（ピクシー・ピッピ）でコピー先のコインを聞くのは、v0.66 からの既存の扱いで、今回変えていない。
- 直さなかったこと: `RuntimeError` を握りつぶす・すべてのESPやコピーを禁止する・先読みの上限（4,096）を上げることはしていない。
- 不変条件（`engine._esp_redo_decision_problems`）: EC1 の決定は、自分のワザとして使った別のワザ（続きの情報の `copied`）の中の、やり直すを選ぶと止める決定。

### 2.4 記号

EC1 は、基点の木とすべての参照（`git rev-list --all` の 226 コミット）の差分に現れない記号を選びました。kyuura の UQ-ESP-REDO の事例 ES0 は同じワザの 2 回のコイントスで、別の問いです
（研究の対応表の `kyuura_disposition` は `not_in_kyuura`。kyuura への報告事項）。A0 は独立したコミット（`4a790ba`）です。

## 4. 許可で使うワザ（［げんしのきおく］・［にんぎょうつかい］・［ものまね］）

### 4.1 持ち方の共通の処理

- ワザの持ち方（v0.49 の `AttackOption`）に、v0.120 の持ち方 `ROUTE_PREHISTORIC`・`ROUTE_PUPPET`・`ROUTE_MIMIC` と、2 つの欄を加えました。
  - `payer`: 必要なエネルギー（ワザの通常のコスト）を、ついているエネルギーで満たすポケモンの番号。None ならワザを使うポケモン自身（v0.119 までのすべての持ち方と、［げんしのきおく］・
    ［ものまね］）。［にんぎょうつかい］だけがスリーパーを指す。既存の `provider`（ワザを供給する場のポケモン）は支払う元の意味ではなく、［サイコリンク］などは今までどおりワザを使う
    ポケモンが払う（支払う元をすべての供給元へ移していない）。
  - `grantors`: 許可を与える特殊能力を持つ場のポケモンの番号（2 匹以上が同じワザを許可しても 1 つの選択）。
- 宣言したワザ（`UseAttack.card`・`attack_index`。印刷のカードの uid と位置）・処理しているワザの `AttackKey`・ワザを供給する個体・実際にワザを使うポケモン・支払うポケモン・許可を与える
  特殊能力を分けて持ちます。公開のコマンドは変えていません（既存の `UseAttack.card` で印刷のカードの uid を指す）。
- 必要なエネルギーの確かめ（`checks.attack_request`）は `payer` のポケモンで照らします（無色2個・ミラクルエネルギー・［きせきのかぜ］などの既存の照合をそのまま通る。エネルギーは
  トラッシュしない）。足りなければ `INSUFFICIENT_ENERGY`（理由の文に支払うポケモンを書く）。説明が書くほかの支払い（このカードのエネルギーのトラッシュなど）・ワザの処理（タイプ・ダメージ・
  弱点・抵抗力・「このカード」・`Incoming` の発生元の進化の分類）は、ワザを使うポケモンです。
- 宣言の時点で持ち方を決め（`find_attack_option`）、支払い・止める理由を確かめてログに残します（`attack` の `route`・`provider`・`payer`・`grantors`）。処理（決定をまたぐ再開を含む）は宣言した
  ワザとワザを使うポケモンで続け、許可を与えた力・供給元のその後の変化（変わり身の術・位置・姿・力の消失）で、使い始めたワザや使い手を別のものに置きかえません（v0.49 の持ち方と同じ）。
- 同じ印刷のカードの同じワザは 1 つの選択にまとめます（`_distinct_options`。止める理由のないものを先に）。印刷したカードの uid が違えば別の選択なので、同じ印刷のスリーパーが 2 匹いて
  エネルギーが違っても、払える供給元を失いません（4.3 節）。
- 「持っているワザ」（`held_attack_keys`）には、許可で使えるワザ（`PERMISSION_ROUTES`。v0.120 の 3 つと「思い出させる」）を入れません。ほかの効果（ゆびをふる・おおきくゆびをふる・
  サイコデュープ・［ものまね］・ちょうのうりょく・ドわすれなど）がそれを「持っているワザ」「相手のワザ」として選べるかは決まらない（VP1。選べるが選ぶと止める。10 章）。持っているもの
  とする［サイコリンク］のワザは今までどおり選べます。これで許可どうしの循環（ウソッキーどうし・［サイコリンク］と［ものまね］）は、印刷のワザに基づく有限の列挙になり、無限の再帰・隠れた
  カードの参照・理由のない候補の削除はありません。
- ベンチのポケモンが持つワザは、共通の問い合わせ（今の姿のカードのワザと［サイコリンク］で持つワザ）で答えます。バトル場だけの許可（［ものまね］）・バトル場の対戦ポケモンへの許可
  （［げんしのきおく］）をベンチで持つ扱いにはしません。

### 4.2 ［げんしのきおく］（プテラ）

- 常にはたらく許可（宣言しない。使う回数の制限はない）。プテラが場のどこにいてもはたらき、ねむり・マヒ・こんらん・かがくへんかガスで消えます（共通の確かめ）。プテラが場をはなれれば
  なくなります。
- 対象は、おたがいのバトル場のポケモンのうち、場の分類（`field_stage`）が「進化ポケモン」のもの。ベイビィから進化したたねポケモンはふくみ、復活してたねポケモンとしてあつかう進化カードは
  ふくみません（その上に進化したポケモンはふくむ。6 章）。
- 使えるのは、実際に重なっている進化前のカードに印刷されたワザ（`recall_stack_attacks`）。すぐ下のカードのワザは使え、2 進化のいちばん下のカードのワザは PE1（選べるが選ぶと止める）です。
  ポケモン育て屋さんで飛ばした進化カード・進化する前に許可で持っていたワザは補いません。「思い出させる」の RC2 は、この文面で同じ問いが決まる根拠がないので解除していません。
- そのポケモンのワザとして使います（ワザを宣言するポケモン・必要なエネルギーを払うポケモン・ワザの処理はそのポケモン）。

### 4.3 ［にんぎょうつかい］（スリーパー）

- 自分のバトル場の、今の名前が「ピッピ人形」のポケモンが、スリーパーの持っているワザ（今の姿のカードのワザ）を使います。ワザを使うのはピッピ人形で、タイプ・ダメージの計算・ワザの効果・
  通常のコスト以外の支払い・`Incoming` の進化の分類は人形です（ミュウの［ニュートラルシールド］にも人形を発生元として渡すので、場ではたねの人形のワザは受ける。スリーパー自身のワザは
  受けない）。
- 必要なエネルギーはスリーパーについているエネルギーで満たします（`payer`）。人形のエネルギーで不足を補いません。日本語版の人形には、エネルギー・特殊状態の禁止の文がありません。
- ［にんぎょうつかい］の文には、スリーパーのねむり・マヒ・こんらんで使えない・消えるという文がありません。ほかの特殊能力の文を写さず、はたらきます（`blocked_by_status` は偽）。
  かがくへんかガスで消えるのは特殊能力の共通の規定です。
- 同じ印刷のスリーパーが 2 匹いれば、印刷したカードの uid ごとに別の支払い元として選べます。エネルギーの足りないスリーパーのワザは受け付けません。

### 4.4 ［ものまね］（ウソッキー）

- バトル場にいて、ねむり・マヒ・こんらんでなく、かがくへんかガスで消えていないときの許可です（宣言する特殊能力にしない）。相手の対戦ポケモンの持っているワザ（今の姿のカードのワザと
  ［サイコリンク］で持つワザ）を使え、相手の対戦ポケモンが許可で使えるワザは VP1 です。
- 必要なエネルギーはウソッキーで満たします（借りるワザのコストだけ。たたきつけるの無色 2 個を足さない）。力が消えても、印刷のたたきつけるは今までどおり使えます。

## 5. ワザを選んで自分のワザとして使うワザ

| おおきくゆびをふる（neo1-071） | 相手の場にいるポケモンの持っているワザ（`COPY_FROM_OPPONENT_FIELD`。バトル場 → ベンチ。ワザごとに 1 つ） | 先に 1 枚 | このワザの無色 1 個だけ |

## 6. 場ではたねポケモンとしてあつかう進化カード

- ［なかまのふっかつ］・［かせきのふっかつ］・たまごの化石で出した進化カードは、進化元を重ねずにベンチに出します（`zones.bench_as_basic`）。架空のなにかの化石・カードの uid は作りません。
- 場のポケモンに持つ事実 `PokemonInPlay.basic_entry`（`state.BasicEntry`: 出したカード・出した効果・効果のカード・あった場所（山札・手札）・出した番）で表し、印刷のカードの段階・進化元は
  変えません（山札・手札・対戦準備・デッキのたねの枚数は印刷の分類）。単に空の重なりを置くだけでは表しません（v0.114 の `field_stage` は、下にカードのない進化カードを進化ポケモンとする）。
- 場の分類の共通の問い合わせ `field_stage` だけが、いちばん上のカードが出したカードのとき（今の姿が［へんしん］・「ばける」でないとき）に `FIELD_BASIC` を返します（`treated_as_basic`）。
  ［ニュートラルシールド］・進化ポケモンを対象にする効果・たねを対象にする効果・ベイビィの分類・［げんしのきおく］の対象は、この共通の答えを使います。
- ベンチ・バトル場の移動、出した効果の特殊能力が消える・発生源が場をはなれることでは消えません（ワザの持続する効果 `persistent_effects` とは別に持つ）。手札・山札・トラッシュへ出れば
  場のポケモンごとなくなります。実際のポケモンなので、なにかの化石・ピッピ人形の「きぜつの数に数えない」扱いを移さず、きぜつすれば相手はサイドを取ります。
- 通常の進化は印刷の名前・系統で重ねます（復活したカブト → カブトプス）。出した番には進化できない（`PLAYED_THIS_TURN`。場に出た番の既存の規定）。進化しても `basic_entry` は残り（元の出し方を
  判断する情報）、その上に進化したポケモンは `FIELD_EVOLVED` です。
- 退化: その上に進化したポケモンが退化して、出したカードがまたいちばん上になる場面は、たねとしてのあつかいが続くかが決まらないので止めます（FE1。退化スプレー・たいかビームなどの決定では
  選べるが選ぶと止める選択、`evolution.devolve` は状態を変える前に止める）。退化スプレーのはがす枚数の決定は、止める選択が FE1 だけなら決定のコード・理由もそのもの（DV1 のときは
  v0.50 からのまま）。いちばん下のカードなので、退化で根元のない取り除き方はしません。
- ポケモン育て屋さんは、印刷のたねポケモンのカードだけを見る既存の判定のままです。復活したカード（印刷の 1 進化）から 1 進化を飛ばす 2 進化カードは今の写しにない（カブト・オムナイト・
  プテラから進化する 1 進化はない）ので、場での分類で結果が変わる場面はありません。v0.47 の PF3（場のなにかの化石に重ねる組）は外していません。
- ［へんしん］のメタモンの相手の対戦ポケモンが、たねとしてあつかう進化カードになる操作は受け付けません（TF3。同じにあつかうのが印刷の進化カードか、場での分類かが決まらない。v0.49 の
  TF2 と同じ形の別の問い）。
- 手札から・山札から出た事実は既存の入口へつなぎます（場に出た時の特殊能力の機会 `_placed_entry_followup`・`placed_entry_power_guard`、まきちらせ!ベトベトガスなどの `goop_gas_entry_check`）。
  手札から出すたまごの化石のカードが［ヒートプレート］の「自分の手札から「たねポケモン」を出すたび」に当たるかは決まらない（FE2。出すときのカードは印刷の進化カードで、たねとしてあつかうのは
  場に出したあと）。爆発ジム（「「たねポケモン」のカード」）はカードの分類なので当たりません。山札から出す経路は「手札から」に当たりません。

## 7. 化石 3 枚・複数の進化・残るワザ

### 7.1 ［なかまのふっかつ］・［かせきのふっかつ］

- 宣言して使う特殊能力で、場のポケモンごとに自分の番に 1 回（`once_per_turn`。宣言のときに記録し、「うら」でも使ったことになる。新しく出した別の個体の回数は消費しない）。ねむり・
  マヒ・こんらん・ベンチに空きがない（`BENCH_FULL`）は宣言の前に拒否します。
- 「おもて」なら、山札にカードがあれば山札を見て、選べるカード（［なかまのふっかつ］は名前が完全に同じ「カブト」、［かせきのふっかつ］は「なにかの化石」を進化させる進化カード）が
  あれば 1 枚を選ぶ決定（`BENCH_FROM_DECK`。1〜1 枚）、なければ選べるもののない決定（0 枚）を出します（見えない山札の中身で、決定の有無・選ぶ数の境界・拒否の種類を変えない。v0.84 の A3）。
  山札が 0 枚（公開の情報）なら見ないので、決定を出さず切りません（ログ `revive_none` の `deck_empty`）。見たあとは、選んだか・選べるカードがあったかによらず山札を切ります。

### 7.2 たまごの化石

- ベンチに空きがなければ使えない（`BENCH_FULL`）。「うら」なら何もしない。
- 「おもて」: 山札にカードがあれば、手札から選ぶ（0。手札に選べるカードがあるときだけ）か山札を見る（1）かを決めます（`REVIVE_SOURCE`）。手札だけを選ぶのに山札を見ない・切らない。
  山札を見たら、山札と手札の選べるカードから 1 枚を選び（`BENCH_FROM_DECK_OR_HAND`。選べるカードがなければ選べるもののない決定）、見たので、手札のカードを選んでも山札を切ります
  （ログ `look_at_deck`）。山札が 0 枚（公開）なら、手札の選べるカードを選ぶ決定（`SELECT_EVOLUTION_CARD`。なければ何もしない）。
- 手札のどのカードも止める（FE2 など）なら、手札から選ぶ（0）を選ぶと止める選択にします（`unresolved_choices`）。山札を見る（1）は止めず、山札のカードを選べます。
- どの決定も、選べるもの・数を相手に見せません（観測の `HIDDEN_COUNT_KINDS`。手札に出せるカードがあるかも漏らさない）。

### 7.3 しんかのほうし（ワタッコ）

- 自分の場の「ハネッコ」「ポポッコ」（今の姿の名前の完全一致。ワザを使うポケモン自身も、相手のワザとして使ったならワザを使うポケモンの場）を先に好きなだけ選び（`SELECT_POKEMON`。
  0〜その数。ログ `evolve_targets`）、そのあと選んだポケモンごとに、山札からそのポケモンから進化するカードを 1 枚ずつ選んで重ねます（`SEARCH_DECK`。カードの uid を二重に使わない。対象と
  進化カードを組にする）。山札を見た場合は、すべての進化のあとに 1 回だけ切ります。
- 「好きなだけ」の 0 匹は v0.31 の HC5（答えのときに止める。0 を勝手に許したり、最小 1 にして候補を隠したりしない）。選んだポケモンのカードがそろわなければ、そのポケモンは
  `evolve_from_deck_none`。山札を見る前に公開の情報だけで決まる問い（DV2・GV1・［れんさしんか］の PW4）のあるポケモンは選べるが選ぶと止めます。手札からの進化の禁止をワザに広げていません。

### 7.4 たつまき（キングドラ）

- 同じ 2 枚の確定したコインで、すべて「うら」ならワザは失敗し、1 枚以上「おもて」なら目安の 50 と、「おもて」の数の相手のエネルギーカードのトラッシュ（ワザを使ったプレイヤーが選ぶ。
  `DISCARD_OPPONENT_ENERGY`。ちょうど「おもて」の数）を処理します。
- ついているエネルギーカードが 1 枚以上で「おもて」の数より少ないときは、選べるだけ選ぶとは決まらない（v0.44 の FC1 `UNRESOLVED_STATED_CARDS_SHORT`。min で丸めない。有限の不足で、

### 7.5 ちからをあわせる（カブト）

- コインの「おもて」で、自分のベンチ（バトル場はふくまない）のオムナイト・オムスター・カブト・カブトプス・プテラ（今の姿の名前の完全一致。下のカード・持ち主の名前のついた別の名前は
  数えない）の数 × 10 を目安の 10 に足します。「うら」は 10。名前の読めないうらのカードは既存の FD1 です。

### 7.6 再利用した既存の型

## 11. ログの監査と対戦の道具

tests/log_audit.py の `v120_problems`・`v120_close` と本体の分岐が、エンジンの登録・計算を読まずに、処理したワザ・特殊能力・トレーナーの印刷の文面（kyuura の日本語）と、ログから組み立てた
場・コイン・カードの動きで確かめます。

- 選ぶワザ: `copy_attack` の `copy_source` が文面の範囲で、選んだワザが、ログから組み立てた範囲（相手の対戦ポケモン・相手の場のポケモンの今の姿のワザ・すぐ下の進化前のカードのワザ）にある。
  コインを投げる文面は「おもて」1 回のあとだけ。合わせた支払いの文面は、両方のワザに必要なエネルギーを、ワザを使うポケモンのエネルギーで払える（基本エネルギーと無色2個エネルギーで
  決まるときだけ。［へんしん］はどの色にもなる）。

  あり、バトル場の進化ポケモンのすぐ下のカードのワザ。［にんぎょうつかい］はバトル場の文面の名前のポケモンが、はたらく力のスリーパー（`grantors`・`provider`・`payer` が同じ）の今のカードの
