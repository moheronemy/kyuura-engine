# R団のファイヤーの「ふしちょう」の原典の照合と裁定（v0.12）

v0.12 で R団のファイヤー（PMCG5-020。ジム拡張第1弾 リーダーズスタジアム）のポケモンパワー「ふしちょう」を対戦で使えるようにするために、『ポケモンカードオフィシャルブック2000』[P43] で確かめた記録です。ワザ「ほのおのかべ」は [rocket-moltres-v0.12.md](rocket-moltres-v0.12.md)、きぜつの処理のあとに特殊能力の使用を挟む仕組みは [post-knockout-powers-v0.12.md](post-knockout-powers-v0.12.md)、設計は [architecture-v0.12.md](architecture-v0.12.md)、確かめた結果は [v0.12-verification.md](v0.12-verification.md) です。照合の記録は kyuura_engine/data/card_verification.json の PMCG5-020。

## 1. 確かめ方と使わなかった資料

- Internet Archive のスキャンの PDF からページを画像にし（300dpi。カードの図版と最新の説明は拡大）、目で読んだ。PDF の文字（OCR）は、ページの位置を探すのに使っただけ（「ふしちょう」「ほのおのかべ」「トラッシュから」「手札に加える」などの語）。PDF のページ = 誌面のページ + 2。
- 照合したのは p.82 の中ほどの「たねポケモン R団のファイヤー LV.26／HP60」「ジム拡張第1弾リーダーズスタジアム」のカード。同じページの上のファイヤー（化石の秘密。LV.35／HP80。「ドライアップ」「ほのおのつばさ」）と、カツラのファイヤー（PMCG6-035）は名前が違う別のカードで、代わりにしていない。後年の「R団のファイヤーex」とも別のカード。
- 依頼の候補の id（PMCG5-017）は kyuura の写しでは別のカードで、R団のファイヤーは PMCG5-020（リポジトリを正とした）。
- 「ふしちょう」の解説は p.82 の解説だけ。公式ルール（p.323「14 ポケモンの特殊能力」）に［ふしちょう］の例はない。使うかを決める一般規定は p.311「ポケモンの特殊能力を使う」、きぜつの処理は p.323〜p.324「16 ポケモンの「きぜつ」」、同じタイミングのことがらの順番は p.325「23」、持続する効果が消えることは p.322〜p.323「11」。v0.11 で読んだ「使える」と書く特殊能力の解説（p.100 の［にげこむ］・p.193 の［こんじょう］）も使った。
- 当時の公式の Q&A・訂正は、ウェブの検索（「R団のファイヤー ふしちょう ほのおのかべ 裁定 旧裏」「"ふしちょう" "R団のファイヤー" サイド きぜつ Q&A ポケモンカード」）では見つけられなかった（見つかったのは中古の販売ページと、別のカード「R団のファイヤーex」だけ）。この本の最新の説明と解説を当時の公式の説明として使った。
- 二次資料（旧裏の研究 Wiki）の手がかり（きぜつしたときに使う・ファイヤー自身を手札に戻す）は、この本で確かめた範囲だけを使い、それ以上は採っていない。
- 使わなかった資料: 英語版の文面（kyuura の `text.en`。「When Rocket's Moltres is Knocked Out, you may return it to your hand after discarding it. …」。日本語版の処理の根拠にしない）、kyuura の rule_history.json・rule_differences.json のポケモンパワーの記録（第4版の冊子のもの。CLAUDE.md）、後年の英語版の規定、現代の「特性」のルール、v0.11 の［こんじょう］の処理（条件も時点も違う。4.1 の P4）。

## 3. 印刷の文面と最新の説明の違い

印刷の文面（kyuura の写し）は「「きぜつ」した時だけ、使える」「トラッシュからとり出し、手札に加える」、最新の説明（p.82）は「「きぜつ」したとき、使える」「トラッシュからとり出し、相手プレイヤーに見せてから、手札に加える」。p.6 により最新の説明にしたがう（`PowerEntry.play_text_ja`）。kyuura の写しの値は登録の照合（`PowerEntry.text_ja`）にだけ使う。

- 「した時だけ」と「したとき」: どちらも、使えるのはきぜつしたときだけと読める（p.311「決められたときにしか使用を宣言できないもの」）。処理は同じ。
- 「相手プレイヤーに見せてから」: 最新の説明が加えた手順。手札に加えるカードを相手に見せる（公開の情報になる）。エンジンのログは内部の完全な記録で、トラッシュのカードもともと公開の情報なので、ログ `return_to_hand` の `revealed`（True）で手順を表すだけにした（P31）。

v0.11 の［こんじょう］は「相手のワザによるダメージで、このカードが「きぜつ」するとき」（きぜつの処理の前。きぜつを防ぐ）、［ふしちょう］は「このカードが「きぜつ」したとき」（きぜつの処理のあと。トラッシュからとり出す）で、条件も時点も違う。［こんじょう］の処理（`_ko_prevention_offer`・`KO_PREVENTION`）は流用していない（[post-knockout-powers-v0.12.md](post-knockout-powers-v0.12.md) 1 章）。

## 4. 裁定（P1〜P35）

分類は次のとおり（v0.11 と同じ）。

- CONFIRMED: 原文がそのまま決めている
- SUPPORTED: 原文と解説から強く支持される。ほかの読み方の余地が小さい
- UNRESOLVED: 原文で決められない（エンジンは推測で処理せず止めるか、結果が変わらないことを示して正規化する）

「実装上の仮定」は、規定ではなく実装の都合で決めたこと。「未到達」は、規定は確かめたが v0.12 の対応カードでは起こらないこと。テストは tests/test_phoenix_v0_12.py（盤面を直接作る。`Registration`・`Offer`・`Cause`・`SpecialCondition`・`Gas`・`GameEnd`・`AtomicityAndSave` の各 `…Test`）・tests/test_moltres_games_v0_12.py（`new_game` からの自然な対戦）。

- kyuura の写しの「ふしちょう」の文面（`pokemon.powers[0].text.ja`）は印刷の文面で、最新の説明（「したとき」「相手プレイヤーに見せてから」）と区別した記録がない。誤りとは決めない（照合の記録の `mismatches`）。
