## 1. 方策の仕様（`rules-v9` = `rules-v8` ＋ 拒否済みの入力の回避）

| 項目 | 内容 |
|---|---|
| 対象 | `submit` の拒否のうち、公開の結果の分類が未裁定（`unresolved_ruling`）で `continuable` が真のもの。`check` の invalid・組み立ての失敗・続けられない拒否は記録しない（今までどおり） |
| 記録の単位 | 同じ主体・同じエピソード（同じ局面）。キーは (候補の中身（番号を除く）, 入力の意味の署名)。署名はランナーの `tried` と同じ `canonical([candidate_key, meaning])` で、候補・選べるものの番号が振り直されても同じ選択を見分ける |
| 拒否の直後 | 同じ応答の段から作れる入力をすべて列挙し（`actions.enumerate_inputs`。乱数を使わない）、署名を方策に渡す。すべてが拒否済みなら、その候補をエピソードの残りで順位 8（`end_turn`・順位 7 より後ろ）にする |
| 次に同じ候補を選んだとき | 作れる入力から拒否済みを除き、残りから選ぶ（2 つ以上なら方策の均等な選択）。残りがなければ組み立てずに順位 8 にする（`build` は `refused_inputs_all`。何も送らない） |
| 未取得の入力 | 候補を選んで inputs を取得し、列挙してから判定する。取得していない入力をまとめて外さない |
| 別の候補 | 既存の順位のまま（ワザ 4・にげる 5・番の終わり 6）。同順位の抽選・理由の接頭辞は `rules-v8` と同じで、当たったときだけ `:refused_excluded`・`:refused_no_alternative` を注記する |
| 再評価 | 受理で新しいエピソードになると記録を消す（受理のあとの決定も新しいエピソード） |
| 代わりがない場合 | 順位 8 の候補しか残らなければそれを選ぶが、送らない。既存の上限（`draws_per_position` 64）の `no_progress` で終わる |
| 評価しない場合 | 列挙の上限を超える場合や、`rules-v4`〜`rules-v8` の入力の制限がある場合は、今までの組み立てに戻る。この場合も、拒否済みの署名は `tried` で送らない |

**実装:**

- `policies.RefusedInputRulePolicy`（`REFUSED_INPUT_AVOIDANCE`・`REFUSED_RANK`・`REFUSED_ALL`）
- `runner`: `_input_tuples`・`_input_signatures`・`_refused_filter`、拒否のあとの `input_refused`。試みの行に `refused_input`・`refused_filter` を記録する
- `batch`: 方式 `rules-v9`（既定にしない）、計画の方策の記録の `refused_input_avoidance`、`TOOL_VERSION` 20
- `run_v1`: 閾値の記録に版 9

**ルールの側は変えていません。** 拒否はエンジンのまま、判定は judge のまま、停止は計画の停止方針のままです。
