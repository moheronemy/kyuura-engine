## 3. 判定の方法

閲覧者（回答者・相手・観戦者）ごとに、その閲覧者の閲覧用記録（`observe/view-<閲覧者>.json`）だけを根拠にしました。これは、配信・保存された観測と出来事です。

| 区分 | 定義 |
|---|---|
| uid が見える | 回答の項目の出来事の uid の項目に、そのカードの uid が出る |
| 識別できる | 回答の項目まで（同時点をふくむ）の観測・出来事に、同じ uid と `card_id` を同じ辞書に持つ値がある（前か同時点か、観測か出来事かを分けた） |
| 別個体だけ | 同じ `card_id` が別の uid とともに見えるだけ（識別に数えない） |
| 後で初めて識別できる | 回答の項目より後にだけ組が出る（当時の識別に数えない） |
| 本人の秘密でしか分からない | その閲覧者の記録に組がない |

- 監査する側は、本当の `card_id` を回答者の記録の組から知ります。これは「別個体だけ」の照合にだけ使い、相手・観戦者の判定には使っていません。
- 公開のログの uid だけでは「見せた」としませんでした。後の公開・既知の固定デッキ・ホストの uid の対応表・完全な記録・カードの定義も使っていません。
- 分類ごとの追加の確かめ:
  - 回答者の項目の出来事の uid と回答の uid の一致（記録の整合）
  - 回答者に選べるものが `card_id` とともに正当に見えていたか（回答の前の観測の決定の `options`）
  - 公開の更新の観測と閲覧用記録の観測の一致（`rows.jsonl` の `observation_same_as_after_view`）
  - 相手・観戦者の観測で、回答者の手札が伏せたままか
  - トラッシュ・回収とトラッシュの対応
- 補いの確かめ（`scripts/extra_checks.py`）:
  - 相手・観戦者の回答の項目のどこか（観測・出来事・決定の `value`）に uid が出るか
  - 出来事の uid の集まりが回答と同じか
  - 相手・観戦者に決定の選べるものが渡っていないか
