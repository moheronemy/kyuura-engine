# ワザによる相手の強制交代（v0.4d）: バタフリーの「ふきとばし」

v0.4d で、ワザの効果で相手の対戦ポケモンをベンチにもどし、相手が選んだ控えポケモンと入れ替える処理（バタフリー PMCG2-007 の「ふきとばし」）を加えました。この文書は、原典で確かめたこと・原典から導いたこと・実装上の仮定・実装・テストを対応づけた記録です。カードの照合は [butterfree-v0.4d.md](butterfree-v0.4d.md)、設計は [architecture-v0.4d.md](architecture-v0.4d.md) にあります。

- 照合の方法: Internet Archive のスキャン [J38] の PDF からページを画像（300〜400dpi）にし、目で読んだ（2026-10-12）。OCR の文字はページを探すのに使っただけ。
- 分類: CONFIRMED（原典に直接書かれている）・SUPPORTED（確かめた規定から導いた）・UNRESOLVED（原典では決められない）・CONFLICT（資料の間で食い違う）。実装の都合で決めたことは「実装上の仮定」と書く。
- 根拠は『ポケモンカードオフィシャルブック2000』[P43]（kyuura の `NEO-2000-OFFICIAL-RULES`）。現代のルール・英語版の文面（kyuura の英語の説明 "(Do the damage before switching the Pokémon.)"）では決めていない。

## 3. ダメージと入れ替えの順番

```
UseAttack（バタフリーの「ふきとばし」）
  → 宣言の確認（ねむり・マヒ・必要なエネルギー）→ AttackEffect.problem（None）→ こんらんならコイン（v0.3c）
  → ログ attack
  → DamageAndForceSwitch.resolve
       1. 相手の対戦ポケモンに 20（p.321 の順番。DamageResult を受け取る）
       2. きぜつする（DamageResult.knocked_out）→ forced_switch_skipped（knocked_out）→ 終わり
       3. 相手に控えがいない → forced_switch_skipped（no_bench）→ 終わり
       4. push_attack_decision(kind=FORCED_SWITCH, player=相手, options=相手のベンチの番号, context=(use, target))
          → Phase.DECISION で止まる（_finish_attack を呼ばない。番のプレイヤーはワザを使ったプレイヤーのまま）
  → ResolveDecision(相手, 決定の番号, (選んだ控えの番号,))
       → 確認（決定するプレイヤー・決定の番号・選ぶ数・重複・選べるもの）。誤りなら状態を変えずに拒否
       → _resolve が決定を閉じる → _resume_attack → DamageAndForceSwitch.resume
            入れ替え（場のポケモンごと）→ ログ forced_switch → 特殊状態・持続する効果を消す
       → _finish_attack（きぜつ・サイド・交代）→ _end_turn（ついているトレーナーの期限・持続する効果の期限・ポケモンチェック）→ 次の番
```

ワザの宣言・エネルギーの確認・こんらんのコイン・20 ダメージは、決定を出す前に 1 回だけ処理します。再開（`resume`）は入れ替えだけを処理し、宣言・ダメージ・コインを繰り返しません。決定は `_resolve` が閉じてから再開するので、同じ決定で二度は再開しません。

## 4. 致死ダメージとの関係（F5）

「ふきとばし」の 20 ダメージで、相手の対戦ポケモンが HP 以上のダメージを受ける場合です。原典の読み方を 2 つ比べました。

| 読み方 | 処理 |
|---|---|
| A（採用） | 20 ダメージで HP 以上になった相手の対戦ポケモンは、そのダメージできぜつする（p.323）。入れ替え（相手の対戦ポケモンをベンチにもどす）の内容は、対象がいなくなったので無視する（p.309）。ワザのあと、きぜつ → サイド → 相手がベンチから新しい対戦ポケモンを選んで出す（p.323） |
| B | ワザの要素をすべて処理してからきぜつを判定するので、HP 以上のダメージを受けたポケモンをベンチにもどし、相手が選んだ控えがバトル場に出てから、ベンチのポケモンがきぜつする |

A を採った根拠:

1. p.213・p.159: このワザの効果の対象は相手の対戦ポケモンで、効果はそれをベンチにもどすこと。入れ替えそのものは効果ではない。
2. p.89: ワザのダメージの要素のあとの効果は、相手が「そのダメージできぜつしなければ」及ぶ（「スターブーメラン」の例。ダメージを受けたポケモンがそのダメージできぜつしたら、あとの効果（手札にもどる）は起こらない）。ダメージできぜつしたポケモンは、ワザの残りの要素の対象ではない。
3. p.309: 処理の対象がいなくなった内容は無視し、次の内容を処理する（それ以降の内容を無視してはいけない）。「ふきとばし」には入れ替えのあとの内容はない。
4. v0.3a 以来、同じ規定で、ワザのダメージできぜつした相手には追加効果（どく・マヒ・こんらんのコイン）を処理していない（`PoisonOnHeads`・`ParalyzeOnHeads`・`ConfuseOnHeads`。docs/weedle-v0.3a.md）。

分類は SUPPORTED です（「ふきとばし」の 20 ダメージできぜつする場合を直接書いた記述は見つからなかった）。なお、A と B で、対戦の結果は同じになります: どちらも、相手が自分のベンチの控えから 1 匹を選んでバトル場に出し（選ぶのは同じプレイヤー、選べるものも同じ）、きぜつしたポケモンとついていたカードはトラッシュされ、ワザを使ったプレイヤーがサイドを 1 枚取り、特殊状態・持続する効果は残らない。違うのは、ログ（`forced_switch_skipped`・`knock_out`・`promote_active` か、`forced_switch`・`knock_out` か）・決定の種類（`PROMOTE_ACTIVE` か `FORCED_SWITCH` か）と、サイドを取る順番（A はサイドを取ってから相手が選ぶ。最後のサイドなら相手は選ばずに対戦が終わる）だけで、勝ち負け・場・トラッシュ・手札は変わりません。読み方が分かれても結果が変わらないことも、推測で「公式ルール」を決めたことにならない理由です。

既存の `_finish_attack`（ワザの要素をすべて処理してから、場のすべてのポケモンのきぜつを判定する。v0.2f）は変えていません。A は「ふきとばしの実装が、ダメージの結果のきぜつを見て、入れ替えの内容を処理しない」ことで表し、きぜつの処理（トラッシュ・サイド・交代）は今までどおりワザのあとにまとめて行います。docs/rules-2000-02-14.md 5 章の「ワザの途中で対象がいなくなることに意味があるカードを加えるときは見直す」の見直しにあたります（6 章）。

## 5. 決定（PendingDecision）

| 項目 | 値 |
|---|---|
| `kind` | `FORCED_SWITCH`（`"forced_switch"`。v0.4d） |
| `player` | 相手（`1 - use.player`）。ワザを使ったプレイヤーではない |
| `options` | 相手のベンチのポケモンの番号（`pokemon_id`。カードの uid ではない）。ベンチの順 |
| `min_choices`・`max_choices` | 1・1 |
| `resume` | `"attack"`（v0.2a） |
| `context` | `("use", (ワザを使ったプレイヤー, バタフリーの番号, "PMCG2-007", 0))`（v0.2a の形）、`("target", 相手の対戦ポケモンの番号)` |
| 段階 | `Phase.DECISION`（v0.2a。新しい段階は加えていない） |
| `current_player`・`turn_number` | ワザを使ったプレイヤー・ワザを使った番のまま |

拒否する答え（どれも状態・決定・乱数・ログを変えない。`apply_command` は複製した状態で処理する）:

| 答え | コード |
|---|---|
| ワザを使ったプレイヤー（決定するプレイヤーでない）が答える | `NOT_YOUR_DECISION` |
| 0・1 以外のプレイヤー | `INVALID_PLAYER` |
| 古い・違う決定の番号 | `WRONG_DECISION` |
| ない番号・相手の対戦ポケモン（もどすポケモン）・ワザを使ったプレイヤーのポケモン | `INVALID_CHOICE` |
| 2 匹以上・何も選ばない・同じ番号を 2 回（1 匹だけ選ぶので数で拒否） | `INVALID_CHOICE_COUNT` |
| 決定がないとき（ワザの前・入れ替えのあと）の答え | `WRONG_PHASE` |

決定を待つ間の `AttachEnergy`・`PlayTrainer`・`EvolvePokemon`・`Retreat`・`UseAttack`・`EndTurn`・`PlayBasicToBench`・`TakePrize`・`PromoteActive` は、どちらのプレイヤーからでも `WRONG_PHASE`（`_require_turn` は `Phase.MAIN` だけを受け付ける。v0.2a のまま）。

不変条件（`engine._attack_decision_problems`・`DamageAndForceSwitch.decision_problems`）: 続きの情報があり、ワザを使ったプレイヤーが番のプレイヤーで、バタフリーがそのバトル場にいて、今の番にそのワザのログ `attack` が 1 回ある。決定の種類が `FORCED_SWITCH`、決定するのが相手、1 匹だけ選ぶ、`target` が相手の対戦ポケモン、選べるものが相手のベンチのポケモンの番号と同じ。

## 6. 入れ替え（resume）とログ

```
forced_switch: player（入れ替えられたプレイヤー = 相手）・attacker（ワザを使ったプレイヤー）・attacker_pokemon_id（バタフリー）・
               effect（"PMCG2-007#0"）・old_active・new_active（カードの uid）・old_active_pokemon_id・new_active_pokemon_id
forced_switch_skipped: player・attacker・attacker_pokemon_id・effect・pokemon・pokemon_id（入れ替えなかった相手の対戦ポケモン）・
                       reason（"knocked_out" / "no_bench"）
special_conditions_removed / persistent_effect_removed: reason "forced_switch"
```

交代の理由は、イベントの種類（`forced_switch` = 相手のワザの効果による入れ替え）と `effect`（どのワザか）で表します。トレーナーの「ポケモンいれかえ」のログ `switch`（`player`・`old_active`・`new_active`・`old_active_pokemon_id`・`new_active_pokemon_id`）の形は変えていません（`player` が自分のポケモンを入れ替えたプレイヤーで、ワザを使ったプレイヤーと入れ替えられたプレイヤーを区別する項目がないため、別のイベントにした）。持続する効果の不変条件（ログとの対応）は、`forced_switch` のあとに残っている効果を違反として見つけます。

ベンチにもどったポケモンは、選ばれた控えがいた位置に入ります（「ポケモンいれかえ」と同じ。ベンチの順番は原典に規定がなく、結果に関係しない）。

## 7. 「にげる」・ポケモンいれかえとの違い

| 項目 | にげる（p.310〜311） | ポケモンいれかえ（p.254） | ふきとばし（p.19） |
|---|---|---|---|
| 入れ替えるポケモン | 自分の対戦ポケモン | 自分の対戦ポケモン | 相手の対戦ポケモン |
| 選ぶプレイヤー | 自分（コマンドで指定） | 自分（決定） | 相手（決定。番は変えない） |
| にげるエネルギー | 払う | 払わない | 払わない |
| こんらんのコイン | 投げる | 投げない | 投げない |
| ねむり・マヒ | 宣言できない | 入れ替える | 入れ替える |
| 控えがいない | 宣言できない（`NO_BENCH`） | 使えるか決められない（`UNRESOLVED_SWITCH_WITHOUT_BENCH`） | 入れ替えない（ダメージだけ） |
| 特殊状態・持続する効果 | 消える（`retreat`） | 消える（`switch`） | 消える（`forced_switch`） |
| ログ | `retreat`・`retreat_failed` | `switch` | `forced_switch`・`forced_switch_skipped` |

## 8. 乱数・原子性

- 「ふきとばし」・相手の選択・入れ替えは乱数を使わない（コインは、こんらん状態のバタフリーのこんらんのコインだけ）。総合テストで、対戦準備のあとの乱数がコインだけであることを確かめた。
- 拒否された答え・コマンドは、状態・決定・乱数・ログを変えない（tests/test_forced_switch_v0_4d.py `InvalidAnswerTest`、tests/test_butterfree_games_v0_4d.py `RandomCommandsWithButterfreeTest`）。

## 9. 原典で決められない場合

「ふきとばし」で新しく止める盤面はありません（`DamageAndForceSwitch.problem` は既定の None）。指示書 11.1 の 3 つの候補は次のとおりです。

| 候補 | 判断 |
|---|---|
| 致死ダメージと強制交代の順番 | SUPPORTED（4 章）。読み方が分かれても結果は同じ |
| 相手のバトル場が変わる場合 | 決定を待つ間はほかの操作ができない（F15）ので、決定のあとで相手のバトル場が `target` と違うことはない（不変条件で確かめる） |
| 入れ替え対象がなくなる場合 | きぜつ（F5）・控えなし（F4）のどちらも、決定を出す前に分かる。決定のあとで控えがいなくなることはない |

こんらん状態のバタフリーの「ふきとばし」は、こんらんのコインの結果で受け付けるか・拒否のコードが変わらない（tests/test_effect_preflight_v0_3d.py `CoinIndependenceTest` に加えた）。
