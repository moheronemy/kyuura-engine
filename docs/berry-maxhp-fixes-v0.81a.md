## 2. ポケモンチェックの 1 の読み方（A・B・B'・C）

ポケモンチェックの 1 の「指示されたこと」（悪エネルギーの効果・きのみ）の順番は、公式ルール 2000.02.14版（GR-2000-P323-POKEMON-CHECK）と記録から決まりません。ポケモンチェックは
どちらの番でもないので、番のプレイヤーが順番を決める規定（GR-2000-P325-SAME-TIMING）も当てはめません（v0.81 の BY1 と同じ立場。順番は決めていない）。

v0.81a では、`procedures._step_one_readings` が、決まらない順番の読み方ごとに、状態の複製の上で 1 を処理します。

- 読み方は「先に処理するきのみの組（場のポケモンの番号）→ 悪エネルギーの効果 → 残りのきのみ」です。最初の読み方は、きのみを先にしない（悪エネルギーが先。実際の処理の順番）。
- どの効果も、それを処理する時点の場で判断します。悪エネルギーの効果の対象（「悪」「わるい」ポケモンか）・量・DE1・［ベンチガード］の未対応・VS1、きのみがはたらくか、を前の場の
  答えで使い回しません。
- 悪エネルギーの効果どうしはまとめて処理します（のせるダメージ・カウンターが、ほかの悪エネルギーの効果の対象・量を変えないため）。きのみどうしもまとめます（ダメージ・特殊状態を
  変えるのはつけているポケモンだけ）。受け付けられない状態の確かめ（`effects.state_stop_after`。決められない姿・MH1・MH2・SC2）は、まとめたきのみの前後で行います（番の終わりの
  期限の確かめと同じ形）。
- 場に悪エネルギーの効果があり、きのみがあるときは、先に処理するきのみの組をすべて比べます（きのみの数を k として 2^k 通り。場のポケモンの数までなので有限）。悪エネルギーの効果が
  なければ読み方は 1 つです。

止め方（`procedures._step_one_stop`）:

- 読み方で結果（のっているダメージ・特殊状態・残るきのみ）か止める理由のコードが変わる、または悪エネルギーのあとに HP 以上になってからきのみで HP より小さくなるなら、BY1。
- どの読み方も同じ理由で止まるなら、その理由（DE1・VS1・MH1・MH2 など）。悪エネルギーの効果のところで止まった理由の文は v0.78 と同じ（「ポケモンチェックの悪エネルギーで: 」）。
- 止まらなければ、悪エネルギーの効果 → きのみの順で実際に処理します（どの読み方も結果が同じ）。

2 の「どく」・きぜつの判定は、1 のあとの場（最初の読み方の結果）で判断します。どく状態のポケモン（きせきのみで回復したポケモンは入らない）・KA1・PK1
（`mid_check_knockout_divergence` は 1 のあとの状態を受け取るようにした）・［ずらかる］の SC1（処理ごとに、その時点の最大HP・［ずらかる］がはたらくかを記録する。v0.81 は 1 の前の
最大HPで比べていた）・両方のプレイヤーのきぜつ。

## 3. 最大HPを決まった数にする効果と大きくする効果（MH2）

「きょだいか」（キョウのメタモン PMCG6-072）の「最大HPは「80」になる」と、ロケット団のアジト（neo3-057）の「「わるい」ポケモンの最大HPは、それぞれ20大きくなる」（と［ガスのからだ］）が
同じポケモンに同時にはたらくとき、最大HP が 80 か 100 かは、印刷の文面・公式ルール 2000.02.14版・kyuura の研究の基準のコミット（`7d3f4ca`）の記録から決まりません（ダメージの
計算の順番 GR-2000-P321-DAMAGE-ORDER は最大HPの規定ではない。kyuura の card_differences のキョウのメタモンの記録は「はたく」の条件の記録で、順番を書かない）。v0.81a は 80 にも
100 にもせず、新しい問い MH2（`UNRESOLVED_MAX_HP_SET_AND_INCREASE`。kyuura の未解決の一覧にない `not_in_kyuura`）にしました。MH1（最大HPがのっているダメージ以下に下がる）とは別の問いです。

v0.81 で届いた経路: 自分のメタモン（基本エネルギー 2 枚）が相手のキョウのメタモンに［へんしん］ → ロケット団のアジトを出す → 今の姿の「きょだいか」で「おもて」（最大HP 80）→ 番が相手に
移る → 相手のベンチにわるいアーボック（PMCG4-008。アーボ PMCG4-001 から進化）、手札にポケモンいれかえ（PMCG1-073）→ ポケモンいれかえを使う → `switch_max_hp_drop_check` →
`max_hp_drops` → `max_hp` の `RuntimeError`。

v0.81a の処理:

- `effects.max_hp` は、その状態の最大HPを読むと `MaxHpOrderUndetermined`（`UnsupportedError`。コード MH2）を投げます（`RuntimeError` を投げない）。大きくする数は `max_hp_bonus`
  （［ガスのからだ］とロケット団のアジト）で求めます。
- `effects.form_problems` が、その状態を決められない状態として数えます（v0.49 の TF1・TF2・DG1、v0.58 の RB1 と同じ表）。そのため `engine._apply` は、コマンドでその状態になるなら
  受け付けず、決定への答え（バトル場に出すなど）でどの答えでもそうなるなら、その前の状態で対戦を止めます（答えのない決定を残さない）。処理の途中で最大HPを読んで
  `MaxHpOrderUndetermined` が出たときも、同じ扱いです。ポケモンチェック・番の終わりの確かめ（`state_stop_after`）も同じ表を使います。
- ポケモンいれかえ・突風（`switch_max_hp_drop_check`）は、入れ替えたあと MH2 になる控えを選べない控えとして数えます。安全な控えが 1 つでもあれば使え、MH2 になる答えだけを
  受け付けません。どの控えでも止まるなら、手札から出す前に止めます。
- 「きょだいか」（`programs.SelfMaxHp`）を、大きくする効果がはたらいているポケモンが使うなら、コインの前に MH2 で止めます（コインの結果で受け付けるかを変えない）。今の写しのワザの
  組み合わせでは、「きょだいか」を使うポケモン（キョウのメタモンと、それに［へんしん］したメタモン）の今の姿は「わるい」ではじまらず、［ガスのからだ］も持たないので起こりません
  （ゆびをふる・オウムがえしなどの、ほかのワザとして使う経路まで、すべての組を数え上げてはいない）。

回帰の例とふつうの側（tests/test_berry_maxhp_fixes_v0_81a.py）:

| 盤面 | v0.81 | v0.81a |
|---|---|---|

## 4. ログの監査

`tests/log_audit._effective_from_state`（観測の最大HP・色・弱点・抵抗力を、エンジンの問い合わせとは別に状態から求める）に、ロケット団のアジトの + 20（今の姿の名前が「わるい」で
はじまる）を加えました。v0.81 は、ログから組み立てる `max_hp_now` だけに加えていて、観測を照らす監査が、ロケット団のアジトのある場のふつうのわるいアーボックの観測の 80 を 60 と
比べていました（v0.81 のロケット団のアジトのテストは、この監査（`observation_problems`）を呼んでいなかった）。アジトのある・ない両方のテストを加えました。

## 5. 残した問い・実装上の読み方

- BY1・KA1・MH1・PK1・DE1・SC1 の問いそのものは解決していません（止める場面を、回復したあとの場の結果で正しく決めるようにしただけ）。どの問いも、まとめて止めたり外したりしていません。
- MH2 は新しい未解決の裁定です。エンジンが止める `UNRESOLVED_…` は 179 件、未解決の裁定は 181 件。
- きのみどうしの途中の状態（2 つ以上のきのみを 1 つずつ処理したときの、きのみとほかのきのみのあいだの状態）は、別に確かめていません。まとめたきのみの前後で確かめます（実装上の読み方。
  2 章）。きのみどうしの最後の状態は順番によらず同じです。
- 先に処理するきのみの組は、場に悪エネルギーの効果があるときだけ 2^k 通り比べます（すべての並び（順列）は数え上げない。悪エネルギーの効果どうし・きのみどうしは、まとめても結果が
  変わらないため。2 章）。
