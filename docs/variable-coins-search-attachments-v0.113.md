# v0.113: 可変枚数のコインと、山札の検索・つける・場全体のトラッシュの 6 枚

v0.113 は、ピッピ（neo1-063）・デンリュウ（neo3-028）・ヤミカラス（neo3-043）・ヘルガー（neo3-044）・わるいバクフーン（neo4-022）・ロケット団のニャース（PR1-078）の 6 枚を、ワザ 11 と
ともに登録する版です。6 枚を同じ便で登録し、コインの枚数の生成元と結果の使い方を分けた共通処理を整えました。おうふくビンタは既存の `CoinFlipDamage(2, 10)`、つめできりさくは
`DAMAGE_ONLY`、残る 9 つのワザは新しい 9 つの型（どれも既存の要素と新しい 2 つの要素の組み合わせ）です。

共通処理として、ワザ全体のコイン `programs.Coin` に、場のポケモンの数だけ投げる項目 `per_pokemon`（範囲と名前。数え方は既存の `programs.counted_pokemon`）を加えました。お互いの場の数は
ピッピとロケット団のニャースで同じ値 `programs.FIELD_POKEMON` を共有します。山札から選ぶ要素 `RevealTrainerFromDeck` に「おもて」の数以下を選ぶ `heads_of`、山札からベンチに出す要素
`BenchFromDeck` にベンチに空きがないときの扱い `when_full`（`BENCH_FULL_FAIL`）、トラッシュからつける要素 `AttachFromDiscard` に場の外のカードとしての種類・色で選ぶ `typed_cards`
（`effects.off_field_typed_energy_card`）を加え、新しい要素 `AttachFromDeckByHeads`（「おもて」の数ぶんを山札から選び、自分の場の色の合うポケモンに好きなようにつける）と
`DiscardFieldEnergyAnyNumber`（自分の場全体から好きなだけトラッシュ）を加えました。既存の項目（`Coin.count`・`per_attached`・`per_opponent_energy`・`per_own_typed`、
`RevealTrainerFromDeck.local_coin`・`category`・`required`、`BenchFromDeck` の既定の「使えない」、`AttachFromDiscard` の既定の基本エネルギーカード）の意味と既定の動きは変えていません。

ナツメのESPのやり直しの続きの情報に、やり直しのあとの要素が読むトラッシュの結果（`discarded_results`）とダメージの結果（既存の `damage_results`）を運ぶようにしました。これで、v0.112 まで
［サイコリンク］で到達して内部エラーになっていた既存のワザ（確かめたのはマチスのエレブーの「ほうでん」・キョウのドガースの「くもがくれガス」。同じ結果を読むワザも同じ修正の範囲）も
直りました（9.1 節）。新しい停止コード・状態の項目はなく、写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）、書き出しの形式は 26 のままです。

## 3. コインの枚数の生成元と結果の使い方

N を投げる枚数、H を「おもて」の数、T = N − H を「うら」の数とします。

| ワザ | N の生成元 | 結果の使い方 | コインの要素 |
|---|---|---|---|
| みんなでおどる | お互いの場のポケモンの数（`Coin.per_pokemon=FIELD_POKEMON`） | H 以下の基本エネルギーカードを山札から見せて手札に | ワザ全体のコイン |
| ゆうでん | 決まった 3 枚（`Coin.count=3`） | H 枚ちょうどの「雷」エネルギーカードを山札から選び、自分の場の「雷」ポケモンに好きなように | ワザ全体のコイン（ダメージのあと） |
| むれでつつく | 自分のベンチの、今の姿の名前が「ヤミカラス」のポケモンの数（`Coin.per_pokemon=(SCOPE_OWN_BENCH, (ヤミカラス,))`） | 目安 10 + 10H | ワザ全体のコイン |
| くろいキバ | 実際の使い手の「悪」エネルギーの個数（`Coin.per_own_typed=悪`・`typed_units_for`） | 目安 30 + 10H | ワザ全体のコイン |
| ファイヤーラッシュ | 実際にトラッシュした「炎」エネルギーカードの枚数（`HeadsOfDiscarded`・`Discarded`） | 基本となるダメージ 40H | ダメージの要素の中のコイン |
| だいぎゃくてん？ | お互いの場のポケモンの数（`FIELD_POKEMON`。みんなでおどると共有） | 相手に 10H、その後、自分に 10T | ワザ全体のコイン（1 組） |
| おうふくビンタ（既存） | 決まった 2 枚 | 10H | ダメージの要素の中のコイン |
| ギガボルト | 1 枚 | 「おもて」で +20、「うら」でマヒ | ワザ全体のコイン（ダメージの前） |

- 数える場（`counted_pokemon`）: バトル場とベンチの場のポケモン（GR-2000-P312-FIELD）。進化して重なったカード・ついているカード（エネルギー・どうぐ）を別の 1 匹にしません。うらのカード
  （マチスの秘策）・場でポケモンとしてあつかうトレーナー（なにかの化石など）も、既存の場の表現のとおり 1 匹です。数だけを使う範囲（名前でしぼらない）では正体（名前・タイプ）を読まず、
  FD1 で止めません（相手のうらのカードも同じ）。名前でしぼる範囲（むれでつつくの自分のベンチ）に名前の読めないうらのカードがあれば、既存の FD1（`HiddenPropertyRead`）で止めます（数だけの場合と
  分ける。`CoinSourceTest`）。
- 数えるのはコインの要素を処理する時点の場で、同じコインをあとの要素で投げ直したり、別の時点の場で数え直したりしません。決まった N と結果は、既存の続きの情報（ワザ全体のコインの結果
  `fs.coins`・ESPの `esp`）で決定や保存をまたいで運びます。トラッシュした N は `Discarded`（ESPのやり直しのあとは `discarded_results`。5 章）で運びます。
- 実際の対戦では N 枚を 1 枚ずつ投げます。結果は「おもて」の数だけを使うので（`by_heads`）、先読みは `Oracle.coin_group` で N + 1 通りにまとめます（H と T を別の結果として試さない）。まとめない
  先読みと同じ答えで（結果の数は少ないか同じ）、3 つの方法（derived・derived_full・legacy）で同じ結果です（`test_preflight_groups_by_heads_and_modes_agree`）。新しい型は v0.13 の止める関数の
  確かめた型（`VERIFIED`）ではないので、legacy でもすべての結果を試します（旧 legacy に黙って落とさない）。`MAX_BRANCHES` は 4096 のままです。
- コインが決める要素と受けるもの（`coin_dependent`・`coin_receiver`・`has_target`）: みんなでおどるの検索・ゆうでんのつける・だいぎゃくてん？の自分へのダメージは相手の対戦ポケモンへの要素で
  ないので、相手の「ダメージを受けない」「ワザをうけない」状態でもコインを投げます（v0.34 の `void_coin_question`。HC3・T19b・G37 に当てはまらない）。むれでつつく・くろいキバ・ファイヤーラッシュの
  コインは相手へのダメージの量だけを決めるので、相手が「ダメージを受けない」状態なら既存の v0.4b の問いで止めます（N = 0 なら投げないので止めない）。ギガボルトのコインは相手へのダメージとマヒの
  両方を決めるので、「ダメージを受けない」状態でも投げ、「ワザをうけない」状態なら HC3 で止めます。相手への効果の宣言（`opponent_effect_elements`）はギガボルトのマヒだけで、G37 の一覧に加えました。

## 4. 各カードの処理

### 4.1 ピッピ

- おうふくビンタは既存の `CoinFlipDamage(2, 10)`（コイン 2 枚の「おもて」の数 × 10。ダメージの要素の中のコイン）。
- みんなでおどる（要素 `Coin(per_pokemon=FIELD_POKEMON)` → `RevealTrainerFromDeck(category="basic_energy", heads_of="coin")`）: N 枚を投げてから、0〜H 枚の基本エネルギーカードを選び、
  選んだカードだけを見せて（ログ `reveal_from_deck`）手札に加え、山札を 1 回切ります。「以下」の 0 枚は既存のせいでんき（v0.85）と同じ読み方として扱い、個別の公式の裁定を見つけたのではありません
  （0 枚ならログ `reveal_from_deck_declined`）。
- H = 0 なら選ぶカードがないので決定を出しませんが、説明の最後の「その後、その山札をよく切る」にしたがって 1 回切ります（せいでんきの数 0・ひなたぼっこの「どの場合も切る」と同じ読み方。
  GR-2000-P312-DECK-HAND-DISCARD の「特に指示されない限り切らない」の指示がある）。トレーナーのエネルギーアーク（v0.80）の「おもて」0 枚で切らない読み方（MB1 の延長）と FC1 の扱いは移して
  いません。
- H が正なら、山札に選べるカードがなくても決定を出して答えを待ちます。最大の枚数は H のままで、選べるカードの数で小さくしません（山札の中身で相手から見た進み方を変えない。v0.84 の A3）。
  相手・観戦者には決定の種類と決めるプレイヤーだけを見せます（既存の `HIDDEN_COUNT_KINDS` の `SEARCH_DECK`）。特殊エネルギーカード（無色2個エネルギー・レインボーエネルギーなど）は山札では
  「基本エネルギーカード」ではありません。山札の上から引く `Draw` ではありません。

### 4.2 デンリュウ

- ゆうでん（要素 `Damage(OPP)` → `Coin(count=3)` → `AttachFromDeckByHeads(雷, "coin")`）: 目安の「相手に20ダメージ。」は説明の最初に省略されている（GR-2000-P320-DAMAGE-FIGURE）ので、
  ダメージが先です（GR-2000-P309-ATTACK-PROCEDURE）。そのあと 3 枚のコインを投げ、「おもて」の数 H ちょうどの「雷」エネルギーカード（山札の「雷」の基本エネルギーカード）を選び、選んだカード
  1 枚ずつ（山札の uid の小さい順）につける先を選びます（決定 `ATTACH_FROM_DECK` → `SELECT_POKEMON` を H 回。続きの情報に `heads`・`cards`・`assigned`・`card`）。すべて決めてから山札から
  直接つけ（手札を通さない。手札からつける通常の操作・1 枚ずつのエネルギー操作に数えない）、山札を 1 回切ります。1 匹に 2 枚以上をつけてもよく（「好きなように」）、決める間、カードは
  山札にあります（印刷の文面にない手札への追加や、選んだカードの事前の公開をしない。つけたカードはログ `attach_energy_from_deck` で公開）。
- 「H 枚ぶん」はピッピの「H 枚以下」と分け、英語の欄の「may」を根拠に 0 枚や任意の効果にしていません。
- つけられるポケモン: 自分の場（バトル場・ベンチ）の、今有効な色（`effects.type_readings`。色マーカー・［へんしょく］なども）が「雷」のポケモン。名前・印刷のタイプで固定しません。エネルギーカードを
  つけることができない（クリスタルビーム）ポケモン・このワザの中で HP 以上になった（相手の［はんげき］など。p.309）ポケモンは選べません。色の読み方で「雷」かが決まらない（VS1・CE1・CE2・CM1）
  ポケモン・うらのカード（タイプが読めない。FD1）は選べますが、選ぶと止めます（`unresolved_detail`。ほかのつける先は止めない）。止めないつける先がなければ、その理由で止めます。
- 場面ごとの扱い（`AttractCurrentTest`）:
  - H = 0（投げなかったときを含む）: 選ぶカードはなく、1 回切る（ログ `attach_energy_from_deck_none` の `reason` は `no_heads`）。ワザの失敗ではない
  - つけられる「雷」ポケモンがいない: 処理の対象がない（p.309）。有無は公開の情報なので、コインも投げない（v0.38 の `has_target`。山札の中身では決めない）。1 回切る（`no_target`）
  - 山札の「雷」エネルギーカードが 0 枚: 選び出す内容の対象がない（p.309）が、決定を出して 0 枚の答えを待つ（A3。`no_candidates`）。1 回切る
  - 0 < 山札の枚数 < H: 説明の枚数より少ないので FC1（kyuura の UQ-STATED-COUNT-SHORT。`stated_cards_short`）。コインの結果で受け付けるかを変えない約束（先読みはすべての結果を試す）のため、
    足りない H がありうる山札（1・2 枚）では宣言の前に止まります。山札に 3 枚以上あれば、どの結果でも H 枚を選べます。山札 0 枚は p.309 で止めない点で、エネルギーアークの「コインの枚数より少なければ
    止める」を一律に移したのではありません。「おもて」の数によって受け付けるかを変えることは、今の先読みの約束ではできない（エンジンの制限。12 章）
  - 山札のレインボーエネルギー: RB2。「雷」エネルギーカードが H 枚以上あれば、選べるが選ぶと止める。レインボーを選ばないと H 枚にならないなら止める
- つけるのはワザの効果なので、つける先の「とうめい」を評価します（`reaches`。受けないならカードは持ち主のトラッシュ。v0.75 のエナジーサポートと同じ読み方。ログ `deck_energy_evaded`）。つけたら
  `effects.after_energy_attached`。使い手が反撃で HP 以上になっても、別の自分のポケモンへのつけるは処理します（使い手だけの早期の return をしない）。
- ギガボルト（要素 `Coin` → `Damage(OPP, PrintedPlusBonus(coin, 20))` → `Status(PARALYSIS, gate=うら, reparalysis_check=True)`）: 1 枚の共有のコインをダメージの計算の前に投げ、「おもて」なら
  基本となるダメージ 60（マヒなし）、「うら」なら 40 とマヒ。v0.8 の `CoinBonusDamageAndParalyze`（「おもて」で追加してマヒ）とは面の意味が違う別の型です。マヒの要素・無効化・反応は既存の順番と、
  実際の使い手の `Incoming` を通します。

### 4.6 ロケット団のニャース

- だいぎゃくてん？（要素 `Coin(per_pokemon=FIELD_POKEMON)` → `Damage(OPP, HeadsOfCoin(coin, 10))` → `Damage(SELF, TailsOfCoin(coin, 10), name="self_damage")`）: 目安は null のまま登録し、
  印刷の文面から相手に 10H、その後、自分に 10T を基本となるダメージにします（固定の目安を足さない。自分もおもての数にしない）。N 枚を 1 組として 1 回だけ投げ、同じ組の H と T を使います
  （v0.35 のぜんりょくとっしんと同じ組の形で、枚数だけがお互いの場のポケモンの数。先読みでも相手と自分の結果の組を保つ）。
- 相手へのダメージが無効でも自分へのダメージは残ります。自分へのダメージは既存のワザの自分へのダメージの経路（ワザによるダメージ。p.321）で、反応・きぜつ・同時のきぜつ・生き残る効果を独自に
  先取りしません。決定や保存をまたいでも、どちらのダメージも 1 回だけです。

## 5. ESPの実在する経路と続きの情報

- v0.112 の文書とテストの説明にあった「ESPを持てるナツメのポケモンにこのワザを使えるものは今の写しにない」は誤りでした（v0.112 の文書の 3.4 節・11 章とテスト
  `test_esp_redo_draws_once_from_the_final_result` の説明を訂正した）。超の色マーカーがのったドククラゲ（SI-016）をベンチに置けば、ナツメのフーディンが［サイコリンク］でしょくしゅをつかうを持ち、
  ESPをつけて使えます。これは文書の訂正で、エンジンの処理は変えていません（エンジンの不具合の修正とは分けて記録する。9.1 節）。
- 通常の登録・操作（手札のナツメのESPを `PlayTrainer`・`ResolveDecision` でフーディンにつけ、`UseAttack` の供給元のカードを色マーカーのポケモンにする。ESPの関数・解決の部品を差しかえない）を通る
  代表のテストを加えました（`EspRealPathTest`）。進化済みのフーディンに水 2 個、超の色マーカーの進化済みドククラゲでは、2 枚のコインのあとESPの決定（決定の前は 0 枚）、やり直さないで 2 枚、両方
  「おもて」にやり直して 4 枚を引きます。これは直接作った盤面の確かめで、正式な対戦の使用実績ではありません。v0.112 の mock による仕組みの確かめは残しています。
- 新しい共有のコインも、ESPで結果を確定してから後続の検索・配分・ダメージを処理します。ロケット団のニャースを供給元にした代表で、やり直した同じ最終の H・T が相手（10H）と自分（10T）の両方に使われる
  ことを確かめました。やり直しの決定は clone・deepcopy・pickle から同じ答えで同じ続きになり、不正な答え（決めるプレイヤーの違い・選べない値・重複）は状態・乱数・ログ・決定を変えません。
- ESPの答えのあとは、コインを投げた要素をもう一度処理します。v0.112 までは、その要素（とそのあと）が前の要素の結果を名前で読んでも、続きの情報に運んでいませんでした。v0.113 から、やり直しのあとの
  要素が読むトラッシュの結果を `discarded_results`（(名前, トラッシュしたカード, 扱い)）、ダメージの結果を境目の決定と同じ `damage_results` で運びます（読まなければ書かない。v0.112 までの決定の
  形は変えない）。ファイヤーラッシュのダメージの要素の中のコインがこれを使います（9.1 節の不具合の修正）。

## 6. 保存・観測・不変条件

- 新しい状態の項目・持続する効果の種類・決定の種類・公開の API はありません。新しい要素の項目（`Coin.per_pokemon`・`RevealTrainerFromDeck.heads_of`・`BenchFromDeck.when_full`・
  `AttachFromDiscard.typed_cards`）は要素の並びの値で、要素の並びは登録の型から作るので保存の形は変わりません。新しい続きの情報（ゆうでんの `stage`・`heads`・`cards`・`assigned`・`card`、ESPの
  `discarded_results`）は決定の `context` の値で、形式 26 で書き出せます（旧形式で表せない情報を落とさない。どれも既存の `context` の書き方）。書き出しの形式は 26 のまま（監査の `LATEST_FORMAT` も
  26）。clone・deepcopy・pickle から同じ答えで同じ続きになります（各テストの `same_answers`）。
- 観測: みんなでおどるの `SEARCH_DECK`・ゆうでんの `ATTACH_FROM_DECK` は既存の `HIDDEN_COUNT_KINDS` で、相手・観戦者には決定の種類と決めるプレイヤーだけ。ゆうでんのつける先の `SELECT_POKEMON` は
  公開の場の情報（選べる数を見せる既存の扱い）。見せて手札に加えたカード・つけたカードは既存の公開のログです。
- 不変条件: 新しい型の `decision_problems` が決定の形（種類・決めるプレイヤー・選べるもの・選ぶ数・運んだ「おもて」の数・つける先が自分の場の「雷」ポケモンか）を照らします。
- ログは既存の種類だけです（`attach_energy_from_deck_none` の `reason` に `no_heads`・`no_target` を加えた。`attack_failed` の `reason` に `bench_full` を加えた）。

### 9.1 直した不具合（エンジン）

### 9.2 見つけたが直していないもの

- ESPのやり直しのあとの要素が読む結果のうち、ほかの種類の結果（入れ替えた控えの番号など）は運んでいません。わるいアリアドス（neo4-011）の「からめとる」を［サイコリンク］で使うナツメのフーディンに
