# v0.108: 持続するダメージの変更・特殊状態を参照する 5 枚

v0.108 は、ヘルガー（neo2-041）・チョンチー（neo3-024）・トゲピー（neo4-088）・わるいプクリン（neo4-091）・アーボック（ES3-001）の 5 枚を、ワザ 10 とともに登録する版です。
4 つのワザは既存の型（`CoinBonusDamage(10)`・`DamageAndSelfDamage(10)`・`ParalyzeOnHeads`・`DiscardEnergyThenDamage(炎)`）、わるいうたは `StatusByCoinWithoutDamage` の
(ねむり, こんらん) の組だけの書き方（`DARK_SONG_TEXTS`）を明示して加えました。残る 5 つのワザは新しい 5 つの小さな型です: マイナスイオン（`DamageThenDealtDamageReduction`）・あまえる
（`DealtDamageReductionWithoutDamage`）・かみくだく（`DamageThenReceivedAttackDamageBonus`）・もうどく（`PlusIfDefenderPoisonedThenPoison`）・たたきおこす（`PlusIfDefenderStatusThenCure`）。

共通処理として、相手に与える「使うワザによるダメージを減らす」持続する効果 `state.DealtAttackDamageReduction`（期間を明示した効果の型。要素 `OpponentDealtDamageReduction`・
問い合わせ `persistent.dealt_attack_damage_reductions`・p.321 の 2 段階の減算）、相手の対戦ポケモンの特殊状態の確かめ `OpponentStatusCheck` と値 `PlusIfResult`、相手の特殊状態の回復
`CureOpponentConditions` を加えました。かみくだくの +20 は v0.92 の `OpponentDamageTakenBonus`（`ReceivedAttackDamageBonus`）をそのまま使います。新しい停止コード・決定の種類・ログの種類は
ありません。写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）、書き出しの形式は 26 のままです（新しい持続する効果の種類の値を加えただけ。7 章）。

## 4. マイナスイオン・あまえる（使うワザのダメージの -10）

- 要素: マイナスイオンは `Damage(OPP)` → `OpponentDealtDamageReduction(10)`、あまえるは `OpponentDealtDamageReduction(10)` だけ（ダメージの要素・ログ `damage` はない。括弧の「ダメージ
  以外の効果はそのまま」は、減らすのがダメージだけで、受けたポケモンのワザのほかの効果を変えないこと）。
- 持続する効果 `state.DealtAttackDamageReduction`（種類 `dealt_attack_damage_reduction`）は期間を明示した効果の型（`PERIOD_EFFECT_TYPES`）で、相手に与え（`on_opponent`）、与えた番 + 1（次の
  相手の番）だけはたらきます（`active_turn` = `end_turn` = 与えた番 + 1。与えた番の続きにははたらかず、その番の終わりに `expired` で消える）。発生源は実際にワザを使ったポケモンとプレイヤー
  （`source_card`・`source_player`・`source_pokemon`。ゆびをふるで使ったなら使ったピクシー）で、数は登録の `period_terms`（`(DealtAttackDamageReduction, 1, 1, False, (), 10)`）と照らします。
- はたらき方: 受けたポケモンが使うワザによるダメージを、p.321 の 2 段階（ワザを使うポケモンの持っている「ダメージを変更する効果」。GR-2000-P321-DAMAGE-ORDER）で 10 減らします
  （`effects.attack_damage_modifiers`）。弱点の後の減算・受ける側の 8 段階の軽減にしません（ワンリキーのけたぐり 20 はチョンチー（弱点 闘）に (20 - 10) × 2 = 20）。2 段階までで 0 以下なら
  計算を終えるので、あとの悪エネルギー（5 段階）・受ける側の +20（8 段階）でダメージを復活させません。
- 範囲: v0.34 のなきつく（`ReducedDamageToSource`）・v0.76 のなきごえ（`ReducedDamageToSourceNextTurn`）は「このカード」（元の使い手）に与えるダメージだけを減らし、控えのこのカードへの
  ダメージは NK5 で止めます。今回の説明にはその限定がないので、別の型・別の問い合わせ（`persistent.dealt_attack_damage_reductions`）にし、受けるのがだれでも当てはめます: 元の使い手以外の
  対戦ポケモン（突風で入れ替わったポケモン）・控え（クヌギダマのとつぜんじばくの控えへの 10 → 0）・自分へのダメージ（とつぜんじばくの自分への 40 → 30）・返す効果のダメージ
  （GR-2000-P321-ATTACK-DAMAGE の「返す効果のダメージはワザの分類」。受けた効果が受けたポケモンの番にはたらくので、今の写しで重なる場面は見つけていない）。旧なきつく・なきごえの範囲は
  広げず（NK5 も旧カードのまま）、新しい型は旧問い合わせ `reduced_damage_to_source` に拾われません（部分型にしない。元の使い手へのダメージを二重に減らさない）。両方を受けたポケモンは、
  なきごえの発生源のカードへは 2 つ（-20）、ほかへは -10 だけです（`test_old_growl_scope_is_unchanged_and_not_doubled`）。
- 当てはめないもの: 特殊能力のダメージ（カイリキーの［はんげき］）・どくのダメージ・トレーナーのダメージ（どれも「使うワザによるダメージ」ではない。`attack` を渡さない経路）。こんらんの 20 が
  「使うワザによるダメージ」かは決まらないので、効果を受けたポケモンのワザがこんらんしうるときは、既存の問い `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS` でコインの前に止めます
  （`procedures.confusion_damage_problem`。v0.92 のいやなおとと同じ。解決済みにしない）。
- 与えるとき: 相手に与える効果なので、「ワザをうけない」状態・「とうめい」・ワザによるダメージ以外の効果を受けない効果（ひかりのはどう）・ミュウの［ニュートラルシールド］（実際の使い手の今の姿の
  段階。たねのチョンチー・トゲピーのワザには、はたらかない）を評価します（`reaches` の要素 `DEALT_DAMAGE_ELEMENT`（`dealt_damage`）。v0.34 の `REDUCED_DAMAGE_ELEMENT` とは別の要素）。相手が
  このワザのダメージで HP 以上なら与えません（こんじょうを使えるなら G37）。
- 消える契機: 受けたポケモンがベンチにもどる・進化・退化・きぜつ・場をはなれると消えます（一般の規定）。元の使い手（発生源）が場をはなれただけでは消さず、今の対戦ポケモンへ移しません
  （説明に書かれていない。`ends_on` は空）。スピードスター（受けるポケモンの持っている効果を除く）でも、ワザを使う側の効果なので黙って消しません（SS1 などの除く範囲の問いは変えない）。
- 同じ 2 段階の効果との順番: つるぎのまい（その数にする）・きあいだめ（数をかける）と重なると、計算の順番で結果が変わるので、v0.35 の順番の決定（`DAMAGE_STEP_ORDER`。ワザを使うプレイヤー）に
  なります。加算どうし（なきつく・なきごえ・2 つの -10）は決定を出しません。旧なきつくの NK5（「このカード」が控えで受ける場合の問い）を、今回の広い範囲に機械的に持ち込んでいません（今回の
  範囲では控えへのダメージも当てはめると決まっている）。

## 5. かみくだく（30 と受けるダメージの +20）

- 要素は `Damage(OPP)` → `OpponentDamageTakenBonus(20, 1, 2)`（v0.92 の要素・持続する効果 `ReceivedAttackDamageBonus`）。目安 30 のあとに相手へ与え、その 30 で相手が HP 以上なら与えず、
  効果だけを受けない相手（ひかりのはどう）にも与えません（ダメージは受ける）。1 進化のヘルガーのワザは、ミュウの［ニュートラルシールド］でダメージも効果も受けません。
- +20 は受ける側の 8 段階の加算で、与えた番 + 1（次の相手の番）と + 2（次の自分の番）にはたらきます。今回の最初の 30 には加えません（悪エネルギーの 5 段階の +10 で 40）。基本となるダメージ・
  使い手側の 2 段階にしません。受けたポケモン自身のワザの自分へのダメージ（ラッキーのすてみタックルの自分への 80 → 100）・返す効果のダメージもワザによるダメージなので加え、2 段階までで 0 以下
  なら加えません（いやなおとと同じ根拠・同じ処理）。重なった +20 はそれぞれ加え（p.323）、同じ 8 段階のリフレクター（半分）・かたくなると順番で結果が変わるときは受けるプレイヤーが順番を選びます
  （40 → 半分 20 → +20 = 40、または +20 = 60 → 半分 30）。
- 消える契機はいやなおとと同じです（受けたポケモンがバトル場をはなれる・進化・退化・きぜつで消え、発生源のヘルガーがはなれても消えない）。期間・数は登録の `period_terms`
  （`(ReceivedAttackDamageBonus, 1, 2, False, (), 20)`）と照らします。

## 6. 相手の特殊状態を参照する 2 つのワザ

### 6.1 もうどく

- ワザの名前は「もうどく」ですが、説明は通常のどくです（ポケモンチェックのダメージの指定がない）。名前で特殊などく（`Status.poison_damage`）に登録していません。
- 要素は `OpponentStatusCheck("opponent_status_before", (どく,))` → `Damage(OPP, PlusIfResult(…, 10))` → `Status(POISON)`。確かめは並びの最初（ワザの内容を処理するとき。こんらん・手順 4 の
  コインのあと、ダメージの前）に 1 回だけで、どく状態か（通常・特殊のどちらでも。量ではない）を見ます。このワザを受ける前からどくなら基本 40（p.321 の 1 段階）、そうでなければ 30。新しく
  どくにしてから状態を読む（いつも 40）処理にしていません。コインはありません。
- ダメージのあと、相手を通常のどくにします。ダメージを与えたことを条件にせず、対象が残るか・受ける判定で決めます（「ダメージを受けない」状態（かたまる）ならダメージだけが無効で、どくは受ける）。
  特殊などくの相手は通常のどくになります（既存の `conditions.poison` と p.322。特殊などく同士の未解決（v0.3a の #15）は解決済みにしていない）。［めんえき］のカビゴンはどくにならず、HP 以上の
  相手はどくにしません（こんじょうなら G37）。キョウ（トレーナー）のどく（通常のどく。KG1 は特殊などくだけの問い）・途中の反応・決定で相手の状態が変わっても、確定した基本値を計算し直しません。
- 宣言の前の候補（`damage_profile`）は、宣言の時点の相手の状態で決めます（宣言のあと、ワザの内容を処理するまでに相手の対戦ポケモンの特殊状態は変わらない。v0.40 の
  `DamagePlusIfDefenderDamaged` と同じ）。

### 6.2 たたきおこす

- 要素は `OpponentStatusCheck("opponent_status_before", (ねむり, こんらん))` → `Damage(OPP, PlusIfResult(…, 20))` → `CureOpponentConditions((ねむり, こんらん))`。相手がねむりまたはこんらんなら
  基本 40、どちらでもなければ 20（失敗にしない。どく・マヒだけでは追加しない）。条件は回復の前に確かめ、追加量は 1 段階で決めます（回復のあとに計算し直さない）。
- ダメージのあと、相手のねむり・こんらんを回復させます（任意ではない。「ダメージを与えたら」の条件もない）。説明が書く 2 つだけを回復させ、どく・マヒ・ダメージカウンター・マーカー・持続する
  効果は消しません（`conditions.cure_conditions`。ログ `special_conditions_removed` の reason `cured`）。回復させる状態がなければ処理の対象がないので何もしません（「とうめい」なども評価しない。
  v0.72 の `WakeOpponent` と同じ既存の扱い）。
- 相手への効果なので、回復させる前に「ワザをうけない」状態・「とうめい」・効果を無効にする効果を評価します（`reaches` の `CURE_ELEMENT`。有益な効果でも防護を無視しない。回復は特殊状態に
  する効果ではないので、［めんえき］・特殊状態にならない効果は見ない）。ダメージだけが防がれても（かたまる）回復は受ける判定で決めます。HP 以上の相手は回復させません（こんじょうなら G37）。
  v0.90 の `CureOwnConditions`（自分への要素）の対象・`reach` の既定は変えていません。
- 回復で相手の特殊能力が再びはたらきます（今の状態から求める。v0.8 の G13）: ねむりのベトベトンを回復させると、かがくへんかガスがまたはたらき、自分の控えのカイリキーの［はんげき］が消えます。
  こんらんのゴーストの「とうめい」もまたはたらきます。回復させたあとの状態が受け付けられない（決められない姿・［ずらかる］の力がもどる。`effects.attack_state_stop_after`）なら止め、宣言の前に
  先読みが見つけます（状態・乱数・ログを変えない）。最大HP が下がるのは、ワザのあとのきぜつの判定が扱います（既存の処理）。ねむり・こんらんのミュウの［ニュートラルシールド］は特殊状態で
  はたらいていないので、ダメージを受けます（HP 40 のミュウは 40 できぜつし、回復の対象はいない）。

## 7. 共通処理・発生元・決定・保存・互換性

- 条件を調べる相手・持続する効果を受ける個体・発生源・期間は、実際に使ったポケモンとプレイヤーから決めます（`run.opponent_active()`・`run.attacker()`。コピー元の個体・印刷元の持ち主では
  計算しない）。無効にする効果の判定は v0.103 の `Incoming` と今の姿の問い合わせで、ミュウの［ニュートラルシールド］も実際の使い手がたねか進化かで決めます。
- 相手への効果の宣言（`opponent_effect_elements`）: マイナスイオン・あまえるは `dealt_damage`、かみくだくは `damage_taken`、もうどくはどく、たたきおこすは `cure`（並びから求めた値と同じ。G37 の
  確かめが使う）。ダメージ以外の効果を無効にする場合の境界・HP 以上の相手の扱い・FD1 は既存のままです。
- ダメージとその後の効果の時点・反応の窓は既存の順番です。お上品攻撃（`DAMAGE_REDUCTION`）・同じ段階の順番（`DAMAGE_STEP_ORDER`）・［にげこむ］・［ぶんれつ］の決定をまたいでも、確定した
  基本となるダメージは続きの情報の `base` で運び（状態の確かめの結果を後の要素が読まないので、運べない結果はない。`_uncarried_results_used_later`）、ダメージ・どく・付与・回復を重ねません
  （代表: もうどくとお上品攻撃・［ぶんれつ］・［にげこむ］、かみくだくの +20 とリフレクターの順番）。［にげこむ］で入れ替えたら、そのワザの残りの効果（どく）は受けません（かわりに出たポケモンに
  移さない）。不正な答えは状態・乱数・ログ・決定を変えずに拒否し、clone・deepcopy・pickle から同じ続きにもどれます。新しい型はどれも解決の対応表（`BUILDERS`）にあり、表せない処理を
  `legacy` 方式に落としていません（先読みの 3 つの方法は同じ結果）。
- 保存形式: 新しい持続する効果は、形式 8 の `persistent_effects` の種類の値 `dealt_attack_damage_reduction` と、期間を明示した効果の項目（`end_turn`・`source_pokemon`）と数 `amount` を加えた
  だけです（v0.84・v0.86・v0.92・v0.93 と同じ扱い。数を持つ期間の型をまとめた `state.PERIOD_AMOUNT_TYPES` を書き出し・不変条件・与えたログが読む）。旧形式へ情報を落として出さず、
  形式 7 以下は持続する効果を表せないので既存のとおり拒否します。v0.107 までの書き出しを読む側は、知らない種類として拒否すること。形式は 26 のまま（監査の項目表 `LATEST_FORMAT` も 26）。
  観測は持続する効果の種類を書きます（既存）。
