## 3. 共通の処理（トラッシュのたねポケモンを持ち主のベンチに出す）

3 枚の出す処理は `zones.bench_from_discard(state, card, *, counters=0)` だけで行います（3 枚で共通。ほかのゾーンから場に出す処理と同じく 1 か所の関数）。

- **持ち主**: カードの持ち主・カードを置いていたトラッシュ・出すベンチは、いつも同じプレイヤー（カードは持ち主のトラッシュにしか置かれない）。効果を使ったプレイヤー・
  選んだプレイヤーとは別に決まります（ポケモンの笛は、使ったプレイヤーが選び、カードの持ち主（相手）のベンチに出る）。カードの持ち主は変えません。
- **場のポケモン**: 手札・山札から出すときと同じ `zones.enter_play` で作ります（新しい場のポケモンの番号・場に出た番は今の番）。ベンチの最後に置きます。
- **引き継がないもの**: ダメージ・特殊状態・ついていたカード（エネルギー・トレーナー。きぜつしたときにトラッシュに置かれている）・持続する効果・1 度だけ使えるワザの記録・
  サカキの許可・場のポケモンの番号。カードだけを動かします（複製しない）。
- **`counters`**: ベンチに出す前に、そのポケモンにのせておくダメージカウンターの数（元気のかけら）。0 ならのせない（よみがえらせるは出したあとに呼ぶ側がのせる）。
- **しないこと**: 手札を通さない・山札を切らない・ログを書かない（ログは呼ぶ側）・乱数を使わない。
- **確かめ**: 出してよいか（カードの種類・決定・ベンチの空き）は呼ぶ側が先に確かめます。カードが持ち主のトラッシュにない・トラッシュにある間の定義がたねポケモンでない・
  持ち主のベンチに空きがない・のせる数が負・知らない uid は、確認の漏れとして `RuntimeError`（状態を変える前）。

選べるカードは `effects.bench_from_discard_candidates(state, players)`（`players` の順に、それぞれのトラッシュの並びで、`effects.discard_basic_pokemon` のカードのうち
持ち主のベンチに空きがあるもの。`effects.bench_has_space`）で、3 枚が同じ関数を使います。ダメージカウンターの数は `effects.half_hp_counters`（HP がダメージカウンターの単位の
正の倍数でなければ `RuntimeError`）。

**場に出たときの特殊能力**: 場に出たときに使える特殊能力（v0.43 の `EntryPower`）を持つカードは、今の対応カードではどれも進化カードです（tests が登録のすべてを確かめる）。
トラッシュから出せるたねポケモンにはないので、トラッシュから出すときに使う機会は起こりません。トラッシュから出したことを、手札から出したこと（ログ `play_to_bench`）として
記録しません（ログは `bench_from_discard`）。「手札から出した時」の特殊能力（`from_hand_only`）は経路が合わないので機会がなく、「場に出た時」の特殊能力のカードを
トラッシュから出すことになったら、`effects.discard_entry_power_guard` が状態を変える前に `RuntimeError` で止めます（使う機会を出すかを決めていない。その場面を作るカードを
加えるときに決める）。

**ログ** `bench_from_discard`（公開。トラッシュと場は公開の情報）: `player`（カードの持ち主）・`by_player`（効果を使って選んだプレイヤー）・`card`（出したカードの uid）・
`from_zone`（`discard`）・`to_zone`（`bench`）・`to_pokemon_id`（新しい場のポケモンの番号）・効果の出どころ（ワザなら `pokemon`・`pokemon_id`（ワザを使ったポケモン）・`effect`
（ワザの `AttackKey`）、トレーナーなら `trainer_card`・`trainer`）・元気のかけらだけ `counters`・`damage`（出す前にのせた数と、そのダメージ）。場に出た番はこのログの番
（`played_turn` と同じ）。よみがえらせるのダメージカウンターは、すぐあとの `place_damage_counters`（v0.41 と同じ形）です。

## 4. 元気のかけら・ポケモンの笛と、トレーナーの進行

- **共通の部分**（`effects._BenchBasicFromDiscardTrainer`）: 使ったプレイヤーが決定 `bench_from_discard`（再開先 `trainer`。0〜1 枚。選べるものは `from_player` の
  トラッシュの、持ち主のベンチに出せるたねポケモンのカード）で選びます。決定を待つ間は場が変わらないので、答えのときにも同じ選べるものです。
- **元気のかけら**: `from_player` は使ったプレイヤー（RB10）。のせる数は、そのカードのトラッシュにある間の定義の HP の半分（RB11）。カウンターをのせた状態でベンチに出し
  （`bench_from_discard` の `counters`）、ログ `bench_from_discard` に `counters`・`damage` を書きます（別の `place_damage_counters` はない）。
- **ポケモンの笛**: `from_player` は相手。ダメージカウンターはのせません（ほかの 2 枚の処理を当てはめない）。
- **元気のかけらとよみがえらせるの順番の違い**（RB11）: 元気のかけらは出す前の HP、よみがえらせるは出したあとの今有効な最大HP（v0.48 の `max_hp`）で数えます。今の対応カードの
  たねポケモンは、どれもベンチに出した直後の今有効な最大HPが印刷の HP と同じです（ナツメのゴースの［ガスのからだ］は、ついているエネルギーカードで大きくなるが、出した直後は
  0 枚。［へんしん］のメタモンはバトル場にいないので印刷の姿）。tests（`test_printed_hp_equals_effective_max_hp_on_entry_for_every_basic`）が登録の 100 枚を超えるすべての
  たねポケモンで確かめます。違いが結果を変えるのは、ベンチに出しただけで最大HPが変わるたねポケモン（場にいるだけで最大HPを変える常にはたらく特殊能力など）を加えたときです。
- **使う前の確かめの順番**: トレーナーの使用の禁止（［アレルギーかふん］・ずつう・こうしゅうは）は、エンジンの共通の入口（`engine._play_trainer`）が手札から出す前に
  `TRAINER_PREVENTED` で拒否します（RV1・FT1 より先）。そのあと `check_playable` が、選べるカードがなければ RV1・FT1 で止めます（手札から出す前。状態・乱数・ログを
  変えない）。
- **使い終えたあと**: エンジンがカードをトラッシュし（ログ `discard_trainer`）、同じ番の `Phase.MAIN` にもどります。出したポケモンはきぜつしない（元気のかけらのカウンターは
  HP の半分。ポケモンの笛はのせない）ので、`may_knock_out` は偽で、v0.50 の `resolution.after_trainer` は呼びません（トレーナーのあとの処理を一律に当てはめない）。
- 答えのない決定は残りません（使う前に選べるカードが 1 枚以上あることを確かめ、0 枚の答えもある）。

## 5. ナツメのスリーパーと、既存の処理との組み合わせ

**よみがえらせる**（要素 `programs.BenchFromEitherDiscard`）:

- 出せるカードがなければ、ログ `bench_from_discard_none`（`player`・`pokemon`・`pokemon_id`・`effect`）だけを残し、決定を出しません（RB6）。元気のかけら・ポケモンの笛の
  RV1・FT1 とは別の扱いです（ワザの処理の対象がないことの規定は GR-2000-P309-ATTACK-PROCEDURE にあり、トレーナーを使えるかの規定ではない。ワザとトレーナーの「対象なし」を
  一律に扱わない）。
- 出す処理は 3 章の共通の処理。そのあと、出したポケモンの今有効な最大HPの半分のダメージカウンターをのせます。場のポケモンへのワザの効果なので、のせる前に「ワザをうけない」
  状態・「とうめい」を評価します（`reaches` の要素の種類 `damage_counters`。自分のポケモンでも相手のポケモンでも。v0.41 と同じ分類）。出したばかりのたねポケモンは持続する
  効果を持たず、「とうめい」のカード（化石の秘密のゴースト）は 1 進化でトラッシュから出せないので、今の対応カードでは受けないことはありません（受けない場合の分岐は tests が
  `reaches` を差しかえて確かめる）。半分なので HP 以上にはならず、きぜつしません。
- 先読みは、選べるすべてのカードを試します（`all_answers`。選んだカードは場のポケモンになるので、v0.44 の `card_id_answers` でカード id ごとにまとめない）。
- 新しい止める処理はありません。

**ふりこののろい**（値 `programs.HeadsPerDefenderCounters`）:

- コインの枚数は相手の対戦ポケモンのダメージカウンターの数（PC1）。「おもて」の数 × 20 が基本となるダメージ（PC2）。v0.11 の「いかりのスーパーパンチ」（コイン 1 枚・自分の
  カウンター × 20。`HeadsOwnCounters`）・v0.32 の「じたばた」（コインなし）とは別の型です。
- 先読みは「おもて」の数でまとめます（`by_heads`。v0.35。カウンター n 個なら n + 1 通り）。実際の対戦では 1 枚ずつ投げます（乱数・ログ `coin_flip` は 1 枚ごと）。HP 120 の
  ラッキーに 11 個のカウンターがあっても、どの先読みの方法でも同じ結果です。
- 「ダメージを受けない」相手（かたまるなど）にカウンターがあれば `UNRESOLVED_PREVENTED_COIN_DAMAGE`（既存のコード。どの先読みの方法でもコインの前に止める）。カウンターが
  なければコインを投げないので止めず、ダメージの要素は「ダメージを受けない」状態でダメージを与えない（ログ `damage_prevented`）。

**依頼の相互作用**（どれも tests/test_discard_to_bench_v0_51.py で確かめた）:

1. **なにかの化石・ピッピ人形**: トラッシュではトレーナーカード（v0.47）なので、3 枚のどの効果でも選べるものに入りません（共通の関数 `discard_basic_pokemon`）。
2. **場に出たときの特殊能力**: 3 章。手札から出したことにしない・ログを手札から出したログにしない。
3. **進化の制限**: 出したポケモンは場に出た番が今の番なので、その番には進化できません（`PLAYED_THIS_TURN`。共通の進化の判定 `evolution.evolution_block`）。サカキの許可が
   あれば進化できます（元気のかけらで出したサカキのコイキングにサカキを使い、サカキのギャラドスに進化）。ポケモンの笛で相手のベンチに出したポケモンは、相手の次の番に
   進化できます。
4. **［サイコリンク］**: ナツメのフーディンが［サイコリンク］で持つよみがえらせるは、ワザを使うフーディンが必要なエネルギー（超）を払います（免除しない。エネルギーがなければ
   `INSUFFICIENT_ENERGY`）。ログの出どころ（`pokemon`・`pokemon_id`）はフーディン、`effect` は印刷したカードのワザです。
5. **［へんしん］**: ナツメのスリーパーの姿のメタモンは、よみがえらせるを使えます（どの色としても使えるエネルギーで払う。v0.49）。トラッシュから出したメタモンはベンチでは
   印刷の姿（HP 50 → 2 個）です。
6. **相手のワザとして使う**: ピッピの「ゆびをふる」などで、よみがえらせる・ふりこののろいを使えます（選ぶのはまねたプレイヤー。よみがえらせるの選べるものは、まねた
   プレイヤーのトラッシュ → 相手のトラッシュ。ふりこののろいの枚数は、まねたプレイヤーから見た相手の対戦ポケモンのカウンター）。どちらも要素の `copy_problem` は既定
   （使える）で、ピクシー・ピッピ・カスミのコダックの説明の条件（v0.31）にかかる条件はありません（ワザに説明の使うための条件がない）。
7. **トレーナーの使用の禁止**: 4 章（共通の入口。RV1・FT1 より先）。
8. **使用中のトレーナー・決定・続き**: トレーナーの決定は既存の再開先 `trainer`（`trainer_in_use` にカードを置いたまま）、よみがえらせるは既存の再開先 `attack` です。
   新しい段階・コマンド・保留中のリストはありません。
9. **きぜつしたポケモン**: きぜつしてトラッシュに置かれたポケモン（ダメージ・どく・エネルギーがあった）を元気のかけらで出すと、新しい場のポケモンの番号で、HP の半分の
   カウンターだけがのります（エネルギーはトラッシュに残る。RB8）。

## 6. 未解決・技術的な制限・実装上の仮定

新しい停止コードは 2 件（どちらも kyuura の未解決の一覧にない。研究の対応表の `stop_codes` で `kyuura_disposition: not_in_kyuura`。エンジンの停止コード 80 → 82、未解決の
裁定 81 → 83）。止めるのはどちらも状態を変える前（トレーナーを手札から出す前）です。

| 番号 | コード | 決まらないこと | 止める場所 |
| --- | --- | --- | --- |
| RV1 | `UNRESOLVED_REVIVE_WITHOUT_TARGET` | 自分のトラッシュにたねポケモンのカードがない・自分のベンチに空きがないとき、元気のかけらを使えるか。印刷の文面（「…ベンチに出すことができる。」）に出せないときの記述がない | 使う前（`check_playable`。トレーナーの使用の禁止の確かめのあと） |
| FT1 | `UNRESOLVED_POKEMON_FLUTE_WITHOUT_TARGET` | 相手のトラッシュにたねポケモンのカードがない・相手のベンチに空きがないとき、ポケモンの笛を使えるか（RV1 と同じ形の問いだが、別のカードの問い） | 使う前（`check_playable`） |

- 推測で決めていません: RV1・FT1 は「効果のないトレーナーとして使える」にも「使えない」にもしていません（v0.21 の突風の GW5・v0.50 の退化スプレーの DV4 と同じ扱い）。
  元気のかけらには kyuura の再録の文面の書き換えの記録（ポケモンジム第1弾の版で「トラッシュにたねポケモンがない時・ベンチに空きがない時は使えないこと」を加えた。区分
  「書き方だけ」。docs/cards/reprints.md）がありますが、v0.21 の GW5 と同じく、処理に使う文面を補う根拠にしていません（区分は文面の違いの分類で、第1弾の文面の処理を
  決めた裁定ではない）。英語版の「(You can't play … if … Bench is full.)」も根拠にしていません。RV1 の答えで FT1 を決めない・ほかのカードの停止コード（v0.43 の PW3 など）を
  流用しない、別の問いとして記録しました。
- RV1・FT1 は「使えるか」の問いで、選べるカードがあるときの 0 枚（「ことができる」の、出さないこと）とは別です。
- **技術的な制限**: なし（v0.51 で新しくエンジンの未対応にしたものはない）。「場に出た時」の特殊能力を持つたねポケモンを加えるときは、トラッシュから出す経路の使う機会を
  決めてから `discard_entry_power_guard` を置きかえてください（今は起こらないので `RuntimeError`）。
- **実装上の仮定**（原典で確かめた規定ではない）: RB3（持ち主のベンチに空きのないカードは選べるものに入らない）・RB10（元気のかけらは自分のトラッシュ・自分のベンチ）・
  選べるものの並び（使ったプレイヤーのトラッシュ → 相手のトラッシュ、それぞれトラッシュの並び）・出したポケモンをベンチの最後に置くこと・よみがえらせるの自分のポケモンにも
  「とうめい」を評価すること（v0.50 のたいかビームと同じ）。

## 7. API・ログ・観測・状態・書き出し

- **API**: 公開の呼び方（`apply_command`・コマンドの形）は変えていません。新しいコマンドはありません。新しい決定の種類は `bench_from_discard`（観測の選べるものの意味は
  カード `card`。トラッシュは公開の情報なので、決めるプレイヤーにはカード id も見える）。新しい内部の部品は `zones.bench_from_discard` と `effects` の共通の関数
  （`discard_basic_pokemon`・`bench_has_space`・`bench_from_discard_candidates`・`half_hp_counters`・`discard_entry_power_guard`・`log_bench_from_discard`）です。
- **状態**: 項目を加えていません（出したポケモンは、場に出た番を持つふつうの場のポケモン）。
- **ログ**: 新しいイベントは `bench_from_discard`・`bench_from_discard_declined`（トレーナーで 0 枚）・`bench_from_discard_none`（よみがえらせるで出せるカードがない）。どれも
  公開（`PUBLIC_EVENTS`）。よみがえらせるのダメージカウンターは既存の `place_damage_counters`。
- **ログの監査**（tests/log_audit.py）: `bench_from_discard` を組み立て直し（持ち主のトラッシュ → 持ち主のベンチ。カードの保存）、出どころ（ワザ・トレーナー）・持ち主・
  たねポケモン・ベンチの数・新しい場のポケモンの番号・元気のかけらのカウンター（印刷の HP の半分）を確かめます。よみがえらせるの `place_damage_counters` は、そのワザで出した

  よみがえらせるの中にあり、そのとき（ログから組み立てた場とトラッシュで）出せるカードがなかったこと、`bench_from_discard_declined` は、使っている最中の元気のかけら・
  ポケモンの笛の中にあることを確かめます。
- **観測**: 出したポケモンは場のポケモンとして全員に見え、トラッシュから出したログも全員に見えます。決定の選べるものは決めるプレイヤーだけ（v0.47 からの決まり）。

  確かめます。
- **書き出し**: 形式 15 のまま（監査の `LATEST_FORMAT` も 15）。出したポケモンは古い形式でも書き出せます（場に出た番はログから分かる）。次の新しい形式は 16。
