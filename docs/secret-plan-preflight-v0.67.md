## 3. うらにして出す（`PlaceFaceDownOnBench`）

- 決定 `secret_plan_card`（決めるのは使ったプレイヤー。選べるものは手札のカード（どの種類でもよい）。0〜1 枚）。選べるもの・選ぶ数は使ったプレイヤーだけが見ます。
- 0 枚は「出してよい」の出さないこと（ログ `secret_plan_declined`）。手札にカードがない・ベンチに空きがない（`stadiums.bench_has_room`。せまいジム）なら、決定を出さずに何もしない
  （ログ `secret_plan_none` の `reason` が `no_cards`・`bench_full`）。日本語の文面に「使えない」はないので、使うための条件にしていません（実装上の読み方。6 章）。
- 選んだカードは `zones.place_face_down` で同じ uid のまま、ベンチの最後のうらの場のポケモンにします（場に出た番は今の番。新しい場のポケモンの番号）。ログ `secret_plan_placed`
  （`card` は持ち主だけが見る）。
- うらのカードの一覧は `GameState.face_down_cards`（uid の並び）だけに持ちます。`GameState.is_face_down(pokemon)` はこの一覧を読みます。v0.63 の一時的に置いておくカード
  （`SetAsideCards`）とは別の状態です（うらのカードは場のポケモン。置いておくカードは場にない）。
- うらのあいだ、`GameState.card_def(uid)` は `cards.FACE_DOWN_DEFINITION`（`FaceDownDefinition`）を返します。種類は「ポケモン」、段階は「たね」、特殊能力はなし。名前・HP・
  タイプ・弱点・抵抗力・にげる・ワザ・カードの id（`FACE_DOWN_HIDDEN_FIELDS`）を読むと `HiddenPropertyRead`（FD1）。印刷の定義（`printed_def`）・共有する `CardDefinition`・
  カードの id は書きかえていません。

## 4. おもてにする時

| 時 | 処理 | ログの `cause` |
|---|---|---|
| 自分の番の `MAIN` に選んで（「のぞむなら、…いつでも」） | 新しいコマンド `RevealFaceDown(player, pokemon)` | `choice` |
| うらのカードがワザを使う・にげる | `UseAttack`・`Retreat` のバトル場のポケモンがうらなら、処理の前に | `attack`・`retreat` |
| うらのカードが特殊能力を使う | `UsePokemonPower` のポケモンがうらなら（うらのあいだは特殊能力がないので、ふつうは使えない） | `power` |
| うらのカードを進化させる | `EvolvePokemon` の対象がうらなら | `evolve` |
| ダメージを受ける | 解決の基盤の `kernel.deal_damage`（ワザ）・`effects.trainer_damage`（トレーナー）がのせる前に | `damage` |
| 効果を受ける（効果の対象として指定された） | 解決の基盤の `kernel.reaches`・特殊状態にする処理（`conditions._prevented`）・トレーナー・特殊能力・スタジアムの決定の答え（`engine._designate_answer`）・特殊能力の選ばせるもの・トレーナーをつける・つけたときの効果のある特殊エネルギーをつける | `effect`・`power` |

- おもてにするのは `zones.reveal_face_down`（ログ `secret_plan_revealed`。公開）。本当のカードが「たねポケモン」（`printed_def` の種類と段階。なにかの化石・ピッピ人形は
  トレーナーカード）なら、同じ場のポケモン（番号・ついているカード・場に出た番）のまま。おもてにしたことは場に出したことではありません（場に出たときの特殊能力の機会はない）。
- 「たねポケモン」でなければ、そのカードとついているすべてのカード（エネルギーは持ち主、トレーナーはつけたプレイヤーのトラッシュ）をトラッシュします（ログ `secret_plan_discarded`
  の `cards`・`energy`・`trainers`・`zone`）。きぜつではありません（ログ `knock_out` はなく、相手はサイドを取らず、きぜつしたときの特殊能力はない）。
- 自分の操作（ワザ・にげる・特殊能力・進化）: 番・段階を確かめてからおもてにします。「たねポケモン」なら、おもてにしたあと、そのコマンドをふつうに処理し、受け付けられなければ
  コマンドごと拒否します（状態を変えない。持ち主は本当のカードを知っているので、拒否の理由で相手の情報は漏れない）。「たねポケモン」でなければトラッシュして、そのコマンドの操作は
  おこらず（進化カードは手札に残る・ワザの宣言はない）、空いたバトル場の勝ち負け・交代（`resolution.after_power`）のあと同じ番にもどります（コマンドは受け付けた）。
- うらにして出した番に進化はできません（場に出た番が今の番。p.310 の進化の制限は変えていない）。
- ワザの途中: `kernel.designate` がおもてにし、トラッシュしたら `Resolution.secret_lost`（{場のポケモンの番号: (持ち主, ポケモン, バトル場にいたか)}）に記録します。ダメージの要素は
  `DamageResult.lost`（ダメージを与えなかった。「ダメージを与えた後」の効果は Z23 の場合 d として止める）、効果の要素は受けないとします。相手の対戦ポケモンをいなくなったポケモンで
  たずねる要素は、記録したポケモンを使います（`AttackRun.opponent_active`・`receiver_of`）。記録はワザの途中の決定をまたいで続きの情報（`frame`）で運びます。
- トレーナーの効果の対象がいなくなった場合: 1 匹だけを指定して、対象がいなくなったら効果が終わるトレーナー（`TrainerEffect.ends_on_lost_target`。ポケモンいれかえ・突風）は、
  ログ `secret_plan_target_lost` のあとトレーナーを使い終えます。ほかの効果で、そのあとの処理を扱えないものは、おもてにする前に `UNSUPPORTED_SECRET_PLAN_LOST_TARGET`
  （エンジンの未対応）で止めます。
- 全体に働く効果（場のすべてのポケモンを調べる・スタジアム・番の終わり・ポケモンチェック・常にはたらく特殊能力）では、おもてにしません（7 章の記録）。場のポケモンを調べる共通の処理
  （`effects.knocked_by_hp`・`max_hp_drops`・`kernel.knocked_out`）はうらのカードを飛ばします（うらのあいだはダメージがない）。
- うらのあいだのポケモンには、ダメージ・特殊状態・持続する効果・ついているトレーナー・重なり・のせたカード・ほかの記録がないことを、不変条件
  （`engine._face_down_pokemon_problems`・`_face_down_list_problems`）で確かめます。エネルギーカードはつけられます（つけても指定ではない。つけたときの効果のある特殊エネルギーは指定）。

- ［へんしん］のメタモン（v0.49）: 相手の対戦ポケモンがうらのカードなら、写すカードが決まらない（v0.49 の TF2 と同じ形の問い）ので、そうなる操作（うらのカードをバトル場に出す）を

  - `UNSUPPORTED_SECRET_PLAN_LOST_TARGET`: おもてにしたら対象がいなくなる指定のうち、そのあとの処理を扱えないもの（4 章）。
  - `UNSUPPORTED_SECRET_PLAN_IDENTITIES`: 6 章の確かめで、ありうるカードの組が上限（256）を超える。
  - `UNSUPPORTED_LEGACY_PREFLIGHT`: 8 章。
- エンジンが止める `UNRESOLVED_…` は 147 件、未解決の裁定は 149 件です。

## 6. 見えない情報と、受け付けるかを本当のカードによらないものにする

- 観測（`observation.observe`）: うらのカードは `face_down: True`・場のポケモンの番号・ダメージ・ついているエネルギーとトレーナー・特殊状態・持続する効果だけ。本当のカード
  （`real` の uid・カードの id・名前）は持ち主だけに見えます。HP・タイプ・ワザなどは、持ち主にも書きません（エンジンが読まない値）。
- ログの写し（`visible_log`）: 見る人の相手の今うらのカードの uid を、カードの uid を書く項目（`observation.UID_FIELDS` と `…_card`・`…_cards`）から除きます（uid はデッキの並びから
  カードがわかる）。おもてにしたら、前のイベントの項目も見えます。`secret_plan_placed` の `card` は持ち主だけの項目です。
- 相手のうらのカードがあり、相手のコマンドの処理が本当のカードを使った（おもてにした・おもてにしたら残るかを見た。`zones.IDENTITY_CONSULTED`）とき、`engine._identity_independent` が、
  うらのカードを持ち主のデッキのカードの id のどれに置きかえても同じコマンドを受け付けるか・同じ種類とコードで拒否するかを確かめます（`_with_identities` は確かめのための複製。返す状態は
  本当の処理の結果）。どれかで拒否するなら、カードの id の順で最初に拒否する組の種類とコードで、本当のカードによらない理由の文で拒否します。組が 256 を超えたら
  `UNSUPPORTED_SECRET_PLAN_IDENTITIES`。本当のカードで拒否したのに、すべての組で受け付けたらエンジンの不具合（RuntimeError）。
- テスト: うらのカードだけが違う 2 つの状態で、相手・観戦者の観測とログの写しが同じ（`HiddenInformationTest`）。相手の［のろい］の対象・突風の対象（`IdentityIndependenceTest`）。
  ログの監査（tests/log_audit.py の `observation_problems`）は、うらのカードの観測と、ログの写しの uid の除き方を、状態から別に求めて照らします。

## 8. 先読みのフォールバックの修正（v0.66 の文書 2.5 節）

- v0.66 まで、ワザの宣言の前の先読みで試す結果の数が上限（`preflight.MAX_BRANCHES` = 4,096）を超えたとき、ワザの型が `v013_checks.VERIFIED` なら v0.13 の止める関数で確かめて
  いました。v0.13 の止める関数は、お上品攻撃（v0.66）の減らす量（`preview_attack_damage` は 0 として計算する）と、うらのカード（v0.67）を知りません。
- v0.67 から `flow.legacy_unknown_features(state, attacker)` が、ワザを使うポケモンについているお上品攻撃（`reduces_attack_damage`）と場のうらのカードを見つけたら:
  - 上限を超えたら、`VERIFIED` の型でも v0.13 の止める関数で確かめず、`UNSUPPORTED_PREFLIGHT_LIMIT` で拒否します（理由の文にその選択・役割を書く）。
  - 比べる方法 `legacy` は、すべての結果を試す方法（`derived_full`）で確かめます。
  - v0.13 の約束で書いた実装（アダプタ）は `UNSUPPORTED_LEGACY_PREFLIGHT`（エンジンの未対応）。
- 上限の数（4,096）は上げていません。新しい `UNRESOLVED_…` もありません。どちらもない盤面は、今までどおり上限を超えたら v0.13 の止める関数で確かめます（方法 `legacy_after_limit`）。
- テスト（`PreflightFallbackTest`）: 上限を小さくした盤面（`mock.patch.object(preflight, "MAX_BRANCHES", 1)`。ドードーのみだれづき）で、どちらもない盤面は `legacy_after_limit`、
  お上品攻撃・うらのカードがある盤面は `UNSUPPORTED_PREFLIGHT_LIMIT`（状態を変えない）、上限の中なら受け付けること、方法 `legacy` がすべての結果を試す方法に変わること。

## 9. 実装上の判断（裁定ではない）

- 手札にカードがない・ベンチに空きがないときは何もせずに使い終わる（使うための条件にしない。3 章）。
- おもてにする時の表（4 章）のうち、トレーナー・特殊能力・スタジアムの決定の答えで「指定した」とみなすのは、選べるものが場のポケモンの決定で選んだポケモンと、選んだエネルギー・
  トレーナーカードがついているポケモン。
- うらのカードの持ち主が自分で操作して受け付けられない場合（おもてにしたら、たねポケモンで、進化の制限などで受け付けられない）は、コマンドごと拒否し、うらのまま（持ち主は本当のカードを
  知っている）。
- 6 章の確かめで、置きかえるカードの候補は持ち主のデッキのカードの id（デッキは公開ではないが、相手が知りうる範囲の上界として使う。本当のカードはその中にある）。

## 10. 形式・API・ログ・観測

- 書き出しの形式 22 = 形式 21 + 最上位の `face_down_cards`（形式 1〜21 は、うらのカードがあると `ValueError`）。監査の `LATEST_FORMAT` は 22。次の新しい形式は 23。
  うらのカードの場のポケモンの書き出しは、カードの定義を読まない（`in_play_def`）。
- 新しいコマンド: `RevealFaceDown(player, pokemon)`（辞書の種類 `reveal_face_down`）。新しい拒否のコード: `NOT_FACE_DOWN`。
- 新しい決定の種類: `secret_plan_card`（観測の意味は `card`）。
- 新しいログのイベント: `secret_plan_placed`（`card` は持ち主だけ）・`secret_plan_none`・`secret_plan_declined`・`secret_plan_revealed`・`secret_plan_discarded`・
  `secret_plan_target_lost`（公開）。
- 公開の API の呼び方は変えていません。
