# v0.191: R-2 のアンノーンの［XXXXX］・［ANGER］の限定提示（うらのバトル場のワザの宣言）

2026-11-17。設計は [r2-unown-design.md](r2-unown-design.md)（11 章に採用と結果）。基点は `claude/r2-unown-design`（`eaf2e1c`。0.190.0）。

この版は **別のおもての持ち主の 2 能力（［XXXXX］・［ANGER］）だけ** に対応しました。R-2 全体の解消ではありません。示す選択肢は実行を保証しない入力の提示で、GUI の表示・送信と、通常の対戦（new_game から）でこの場面に来るかは確かめていません。

## 1. 変えたこと

`kyuura_engine/legal_actions.py` だけです（エンジンのゲーム処理・裁定・規約・judge・検証用 AI の方策・GUI は変えていません）。

- **提示:** うらのバトル場のポケモンのワザの候補（`_face_down_attack_candidate`）の 2 段目に、次のすべてを満たすとき、持ち主ごとに `with_power` を示します（新しい `_face_down_group_power_specs`）。
  - 本人が知る本当のカード（`printed_def`）の名前のグループが、力の `group`（アンノーン）と同じ。
  - 本当のカードの特殊能力の型が、すべて分類済みの 22 型（`FACE_DOWN_GROUP_POWER_ATTACKER_TYPES`。設計の `types`）のどれか。型の名前と effects のクラスそのものを照らします。未知の型・登録のない特殊能力は示しません。
  - ワザの印刷の名前が、力の `attack_name`（めざめるパワー）と同じ。示すのはそのワザの `options_by_choice` と組（`pairs`）だけです。
  - 持ち主は自分の場のおもてのポケモンで、使い手と別。力が `CoinsUntilTailsBonusToGroupAttack`・`CounterBonusToGroupAttack` のどちらかで、消えていない（`power_suppressed`）・使えない効果を受けていない（`powers_use_prevented`）・この番のほかの個体の使用の記録がない（`other_use_problem`）。
- **値・表示:** おもての宣言（`_addon_specs`）と同じです（`addon`・持ち主の場の表示・`power`）。並びは場の並びです。
- **区分:** 選択肢と候補は `unverified`、理由は `face_down_reveal_not_evaluated` のままです。
- **check:** 形と、同じ力（`exclusive_key`）を 2 つ選ぶ組の `CANDIDATE_INPUT_INVALID` だけです（0.190.0 の `_face_down_verify` と同じ。エンジンは呼びません）。
- **note:** ［XXXXX］・［ANGER］を示すときだけ、新しい `NOTE_FACE_DOWN_GROUP_POWERS` を使います。コインだけ・［めいれい］のときの文は変えていません。
- **保証の文（`GUARANTEE_FACE_DOWN_ATTACK`）:** preconditions に v0.191 の条件を、acceptance に「［XXXXX］・［ANGER］を選んで受理されてもダメージが増えたことを意味しない」「［XXXXX］は既存の未裁定の停止で拒否されうる」を加えました。F-1 の固定の sha256 は `4accf876…` → `28f68001…` です（旧値はテストの説明に残しました）。
- **対象外:** 自己持ち主（使い手自身の力）、変身の経路（メタモン 2 種）、［すいりょくはつでん］、分類にない型。今までどおり示しません。
- **変えていないこと:** submit の順（おもてにする → 確かめ → 先読み → 処理）、拒否のときの巻き戻し、XP1・NT1・v0.4b の既存の停止（候補で予測して外しません）、コイン（0.188.0）と［めいれい］（0.190.0）の提示、おもての宣言。

候補の作成で使うのは、本人の本当のカードの印刷の情報・登録の型と、公開の場（おもての持ち主・その力・場の記録）だけです。公開・エンジンの確かめ・複製の上の試行・乱数・相手の非公開の情報は使いません。

## 2. 直接のコマンドの前提確認（入力の提示を変える前）

0.190.0 のエンジンに構築盤面から `UseAttack(0, 0, with_power / with_powers)` を送りました。55 ケースのうち受理 41・拒否 14 で、どれも設計の見込みどおりでした（差はありませんでした）。

| 確かめたこと | 結果 |
|---|---|
| うらのアンノーンから、別の持ち主の［XXXXX］ | 受理。「おもて」2 枚で 10 → 30（6 段階）。0 枚なら 10 |
| 同じく［ANGER］（持ち主のダメージ 20） | 受理。10 → 30（6 段階）。0 個なら 10 |
| 力なし・あり、おもて・うら | 同じ盤面・同じコインで、おもてとうらのダメージが同じ |
| 両方・同じ力 2 匹・同じ持ち主 2 回 | 両方は 50。同じ力 2 匹は `POWER_ALREADY_USED`、同じ持ち主 2 回は `DUPLICATE_POWER` |
| 使い手の型の原因群（宣言・場に出したとき・X・A・［PERFORM］） | どれも受理・同じ値。［PERFORM］の公開の直後の追加は 0（設計の前提どおり） |
| 持ち主の側の拒否 | かがくへんかガス `POWER_SUPPRESSED`・使えない効果（注入）`POWER_USE_PREVENTED`・この番のほかの X（注入）`POWER_ALREADY_USED`・相手の場とうらの持ち主 `ATTACK_POWER_NOT_AVAILABLE` |
| 維持する未裁定 | 相手のバトル場のベイビィで XP1、変わり身の術で NT1、ダメージを受けない状態（注入）で `UNRESOLVED_PREVENTED_COIN_DAMAGE`。［ANGER］だけ・力なしは止まらない |
| 拒否のとき | 14 件とも状態・乱数・ログ・決定の通し番号が不変 |
| 対象外（記録だけ） | 自己持ち主は X・A ともエンジンが受け付ける（公開のあと）。メタモン（へんしん）は相手のアンノーンXの姿で受理、すごいへんしんは `INVALID_ATTACK`、アンノーンでない使い手は `ATTACK_POWER_NOT_AVAILABLE`。どれも提示しない（設計の B・C） |

## 3. テスト

- **新しいテスト:** `tests/test_legal_actions_r2_unown_v0_191.py`（36 件）。
  - 修正の前は 18 件が失敗し（どれも提示に関わる期待の差）、修正のあとは全件が成功しました。
  - 範囲: 提示（X・A・両方・複数の持ち主・場の並び・原因群）、check、送信（U7・API と直接のコマンドの一致、おもてとうらの値、既存の停止で拒否されたときの不変と非通知）、対象外（自己持ち主・変身・アンノーンでない・持ち主がうら／相手の場／力が消えている／使えない／使用済み）、登録と分類、情報境界（双子・状態不変・公開とエンジンの確かめを呼ばない）、回帰。
  - 人工のケースは名前に `artificial`、注入は `injected` をつけて、実在のカードのケースと分けました（2 つめのワザを持つアンノーン、分類の集合から 1 型を除く、分類にない型の検出）。
- **登録と分類:** 名前のグループがアンノーンのカード 26・能力名 26・効果型 22 を照合しました。全件が分類済みで、分類表（設計の JSON）・実装の範囲・登録の型の 3 つが一致します。人工的に足した未分類の型・登録のない特殊能力は、検査が見つけます。
- **関連テスト:** 68 モジュールを 1 つずつ別のプロセスで流しました。
  - 版の更新の前は 67 成功・1 失敗でした。失敗は `test_legal_actions_f1_v0_180` の固定の sha256 だけで、文の検査は成功していました（原因は保証の文の変更）。旧値を記録して更新したあと成功しました。
  - 版の更新のあとは 68 とも成功しました。
- **停止の方針の台帳:** 新しいテストが既存の停止コード 3 つ（XP1・NT1・v0.4b）に触れたので、テストの参照の数と一覧（10 か所。うち 1 か所は先頭 20 件の表示の入れ替わり）だけが変わりました。分類は 10 件ともテストの参照・未分類 0 で、既存の生成器で同期しました。場面の索引・診断のカタログ・設計案は変わっていません。
