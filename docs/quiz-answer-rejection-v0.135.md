### 2.2 仕組み

正解なら相手プレイヤー、正解でないなら使ったプレイヤーが引く（その2 は 2 枚、その3・性格判定は 3 枚。引けるだけ）。フラッシュ（v0.126）で山札の上がおもてになっていると、
いちばん上より下のおもてのカードをまとめて引くことは FU3（`UNRESOLVED_FACE_UP_DECK_HIDDEN_TAKE`）で止める。片方の山札だけが FU3 に当たると、答えを送った段で、正誤によって受理か
FU3 かが分かれる。拒否は状態を変えないので、相手は答えを替えて送り直し、受理・拒否から置いたカード（相手に見えない）を探せた。

## 4. 修正

`effects.quiz_draw_outcome_stop(state, user, draw)` を加え、その2・その3・性格判定の `check_playable` が、使うための条件の確かめのあとに呼ぶ（`face_up_draw_stop`）。
v0.129 のカツラのクイズ その1（GD5-016）の `BlainesHeightQuiz.face_up_draw_stop` の中身をこの関数にし、その1 もこれを呼ぶ（その1 の動きは同じ）。

- おもてのカードがなければ何もしない（`None`）
- 使ったプレイヤー → 相手プレイヤーの順に、状態の複製の上で `draw` 枚（引けるだけ）引き、`zones.draw_cards` の FU3（例外）か `faceup.command_problem`（FU3〜FU6）に当たれば、
  その (コード, 理由) を返す。その1 では、試しに引いたときの FU3 の例外をそのまま上げていた。この版は捕まえて (コード, 理由) で返す（コードと理由の文は同じ）
- `check_playable` が `UnsupportedError` で止める。`check_playable` は手札から出す前に呼ばれる（`engine._play_trainer`）ので、止めたときは手札から出さない・置くカードを選ばない・
  ヒントを伝えない・答えを求めない・おもてにしない。状態・乱数・ログは変わらない（コマンドは複製の上で処理する）

`engine.py`・`resolution/` は変えていない（カードの id による分岐を加えていない）。止めるかどうかは登録の効果の `draw` と状態だけで決まる。

## 5. 使う前に止める制限（情報漏れを防ぐための保守的な制限）

**片方の結果だけなら進められる場面も、使う前に止める。** 例: 使ったプレイヤーの山札だけが上から 4 枚おもてなら、正解（相手が引く）なら進められるが、使う前に FU3 で止める。
答えのあとで止める方法（どの答えも同じに拒否する・理由の文を隠す・答えを補正する・拒否したあとで正解だけ替える）は採らなかった。拒否が状態を変えない以上、答えの段で
止まりうることそのものが、正誤の手がかりになるため。

- これは**エンジンの制限**で、研究の未解決（FU3 の UQ-FLASH-FACE-UP-DECK）を解決したのではない。止めるコードは既存の FU3 のまま（新しいコードは作っていない）
- 「おもてのカードがある」だけで止めない。止めるのは、どちらかの山札で引く枚数（引けるだけ）が 2 枚以上で、いちばん上より下におもてのカードがかかる（おもてが 2 枚以上）ときだけ
- 既存のコードとの違い: v0.134 までは、答えの段で（正誤で引くプレイヤーの山札が当たったときだけ）FU3 で止めていた。v0.135 は使う段で、両方の引き方のどちらかが当たれば止める
- 受け付ける場面（テストで確かめた）: おもてのカードがない・いちばん上だけがおもて（使ったプレイヤー・相手・両方）・山札 0 枚・1 枚・引く枚数より少ない（おもてが 1 枚以下）・
  引く枚数以上。受け付けたら、正解・正解でないのどちらでも、引く → 置いたカードを手札にもどす まで進む

## 6. 監査（比べる検査）・対戦の道具

### 6.1 比べる検査

正常なログの検査は 1 つの対戦のログだけを見るので、拒否（状態を変えない）から見えない情報が漏れても見つけられない。`tests/log_audit.py` に次を加えた。

- `public_view(state, viewer)`: 見る人の観測とログの写し
- `command_outcome(state, command)`: コマンドの結果の印（受理、または (例外の種類, コード, 理由の文)）。拒否のときに渡した状態が変わっていないことも確かめる
- `twin_command_problems(states, commands, viewers)`: 見る人の公開の情報が同じで見えない情報だけが違う状態に、同じコマンドの並びを送り、段ごとの受理・拒否・コード・理由の文が
  状態によって違えば問題として返す。受け付けたあと公開の情報が分かれた段（説明どおりにおもてにした段）で比べるのをやめる

修正の前の木では、この検査が 12 の組（3 枚 × 合法な経路 4 つ）のすべてで違いを返した（受理と FU3 の逆転、または FU3 どうしの理由の文の違い）。既存のおもての山札の監査
（`observation_problems`・`face_up_deck_from_log` など）は緩めていない。

### 6.2 対戦の道具（`tools/existing_effect_games.py`）

- v0.63 の方策（その3 の答え）は、置いたカードの名前を状態から読んで正解・不正解を選び、受け付けるまで候補を試していた。v0.135 から、答えるプレイヤーの観測（伝えたワザの名前・
  答えの候補）と公開のカードの一覧（同梱の写しの定義）だけで決める（`v063_public_answer`。伝えたワザを持つ名前を当てにいく `guess`・持たない名前の `avoid` を回す）。受け付けるかを
  試して選び直さない（拒否されれば想定外の拒否として数える）
- v0.80 の方策（その2・性格判定・カードめくりゲームの答え）は、置いたカードを読まずに候補を回していたが、受け付けない答えは次の候補を試していた。答えの決定（`quiz_answer`）だけ、回した 1 つをそのまま送る
  （今は拒否が起きないので、対戦の進み方は変わらない）

## 7. 錯乱ジム・［ちえくらべ］・サイキックコントロール・サドン・デス

- **錯乱ジム**: 使ったプレイヤーの確かめ（手札から出す前）で止めるので、錯乱ジムのコインを投げない。「うら」で相手が借りて使うときは、借りたプレイヤー（実際に使うプレイヤー
  `use.player`）で `check_playable` を確かめる（v0.57 の `borrow_unusable_reason`）。引くのは正誤でどちらかのプレイヤーで枚数も同じなので、借りたプレイヤーで確かめても結果は同じ。
  錯乱ジムのコインのあいだに山札は変わらないので、もとの使ったプレイヤーの確かめを通ったなら、借りるときに新しく止まらない（テストで確かめた）
- **［ちえくらべ］**（v0.132 の利用者の指定「1. 状態を変えずに使えるかを確かめる（使えないカードの宣言には選択もコインもない）」）: 止める盤面では、［ちえくらべ］を使うかの決定も
  コインもない。使わないときの続きの先読み（`engine._trainer_reaction_decline_check`）は変えていない。止めない盤面では、使わない答えのあとクイズが通常どおり進む（テストで確かめた）
- **サイキックコントロール**（v0.58。トラッシュのクイズを使う）: 選べるカードの確かめ（`discard_trainer_use_choices`）が `check_playable` の `UnsupportedError` を「選ぶと止める」に
  する既存の扱いのまま
- **サドン・デスの延長戦**（v0.134）: 確かめが読むのは今の状態の山札・おもての印（`face_up_deck`）・ログだけで、区間の記録（`segments`）は読まない。延長戦を始めるとおもての印は
  空になる（`SEGMENT_FIELD_POLICY` の reset）。テストは、前の区間でフラッシュを使って止まる盤面から延長戦を始め、新しい区間ではクイズを使え、新しい区間でフラッシュを使うと今の区間の
  印で止まることを確かめる

合法な実カードの経路とテスト専用の改変は分けた。合法な経路: フラッシュ・パソコン通信（山札を切って印を消す）・番の最初のドロー（いちばん上のおもてのカードを 1 枚ずつ引く）・
錯乱ジム・ヤドキング・サドン・デスの延長戦。テスト専用の改変（`ShapeMatrixTest` の `shaped`）: 山札の枚数とおもての印を直接決めた盤面（組み合わせを網羅するためだけ）。
