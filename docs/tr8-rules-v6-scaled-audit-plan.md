## 5. 記録と集計の設計

項目ごとに別々に数えます。0 であることや多いことを、どの項目でも合否の条件にしません。数えるのは、完了した局の試行で照合に通ったものです。未完了の試行と未着手の局は「未実行」として別にします。

**集計の範囲は、先行・各ブロック（B1〜B4）・本実行の累計（そのときまでのブロックの和）を分けます。**

### 5.1 局の終了と完走率

| 分類 | 数え方 | 証拠の出所 |
|---|---|---|
| `game_over` | 局の終わり方 | `result.json` の `termination.class`・完了マーカーの `summary.termination`・`summary.judge.termination` |
| 未裁定による終了 | `halted_known` で `detail.halt.category` が `unresolved_ruling`。`diagnostic_id` を実測のコードとして数える | `result.json`・`trace.jsonl` |
| `no_progress` | 同じ状態の引き直しの上限。直前の拒否のコードと最後の局面の候補の処理可能性を併記 | 同上・試みの行 |
| 単局の上限 | `limit_operations`・`limit_accepted`・`limit_turns`・`limit_time` を別に。受理のうち［エナジートランス］・［ダメージスワップ］の数と、1 番あたりの最大を併記 | 同上・5.2 節・5.3 節 |
| 異常 | 完了マーカーの `stop`（`prestop:*`・観測の問題・`inconsistency`・`suspect`・`api_contract_unknown`・`state_integrity`・`exception` ほか）と、外側の照合の問題 | 完了マーカー・台帳・外側の照合の出力 |
| バッチの停止 | 停止方針の発動・実行や照合の異常・予算の不足で、次の局を呼ばなかったこと。未着手の局の数として、局の終わり方とは別に数える | 計画の台帳の `session_end` の `status`・外側の台帳 |

- **件数は 5 つを別に数えます:** 予定・着手・完了・未完了（`INCOMPLETE.json`）・未着手。条件ごと（C1〜C4）と全体を出します。
- **完走率 ＝ `game_over` の局の数 ÷ 着手した局の数**です。必ず件数を併記します（例「23／24」）。
  - 未着手は分母に入れません。未完了は分母に入り、`game_over` には入りません。
  - 先行（分母 4）・各ブロック（分母はそのブロックの着手、最大 24）・本実行の累計（最大 96）を分けます。
  - rules-v5 の監査の 24／24 は参考の列だけに置きます。seed が違うので、差を `rules-v6` の効果として扱いません。
