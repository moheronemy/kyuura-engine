# v0.66: お上品攻撃・ナツメのESP・カスミの勝負

v0.66 は、3 枚のトレーナーを対応にした版です（版 0.66.0）。3 枚とも、ワザ・トレーナーの処理の途中でプレイヤーが「のぞむなら」選ぶ、または両方のプレイヤーが選ぶ効果です。既存の決定・ついているトレーナー・ダメージの計算・コインの仕組みを広げて実装しました。

- 3 枚のカード:
  - お上品攻撃 PMCG5-074（リーダーズスタジアム）
  - ナツメのESP PMCG6-087（闇からの挑戦）
  - カスミの勝負 PMCG5-068（リーダーズスタジアム）
- 基準は v0.65 のコミット `1e54e3a`（ブランチ `claude/v0.65-reactive-decisions`。`main` はこのコミットを含んでいない）。
- 作業ブランチは `claude/v0.66-optional-trainers`。

公式ガイドブックのキャプチャ・OCR・読み直しは行っていません。kyuura のデータ・記録は変えていません。カードの写しの元（`ecb2d69`）と研究の基準（`3f34908`）も変えていません。

## 2. お上品攻撃

### 2.1 つける・もどす

- 自分のバトル場のポケモンにつけます（選ぶものがないので決定は出さない。プラスパワーと同じ）。ついているトレーナーの共通の処理（`zones.attach_trainer`）です。
- 有効期限は次の相手の番の終わり（`discard_turn_offset = 1`）です。
  - kyuura の data/curation/card_differences.json の PMCG5-074 を、カード id で引いて再利用しました（確度: 確実。日本語の文面とカードの画像・『オフィシャルブック2000』p.279 の最新の説明が「相手の番が終わったら、手札にもどす」）。
  - 英語版の「at the end of your turn」にしていません。
- 期限の番の終わりに、トラッシュではなく持ち主の手札にもどします（`procedures.discard_expired_attachments`。ログ `return_attached_trainer`）。
  - 行き先は、トレーナーの実装の `expiry_destination`（`EXPIRE_TO_DISCARD`・`EXPIRE_TO_HAND`）で決めます。カード id で分けていません。
  - もどす手札は、つけたプレイヤー（`AttachedTrainer.player`）のものです。つけたプレイヤーとカードの持ち主が違えばエンジンの不具合（`RuntimeError`）。お上品攻撃はついたまま場に残るトレーナーなので、ナツメのサイキックコントロールで相手のトラッシュから使えません（v0.58）。
- きぜつしたら、ポケモンといっしょにトラッシュします（共通の処理。「(そのポケモンが「きぜつ」したときは、このカードもトラッシュする)」）。

### 2.2 ダメージの計算（CH-R1・CH-R2・CH-R3）

- 小さくするのは、つけたポケモンのワザが相手の対戦ポケモンに与えるダメージです。相手の控え・自分へのダメージには当てはめません（「相手の対戦ポケモンにダメージを与える時」）。
- CH-R1（kyuura GR-2000-P321-DAMAGE-ORDER）: ワザを使うポケモンについているトレーナーカードの効果なので p.321 の 5 段階です。
  - `effects.attack_damage_modifiers` が、計算の操作 `damage.REDUCE_CHOICE`（5 段階・量 0）を加えます。
  - 同じ 5 段階のプラスパワー（加算）を先に当てはめ、そのあとで減らします。加算の効果だけなら、どちらを先にしても選べる最終ダメージの集まりは同じです（減らす量は 0 から好きなだけ選べる）。
  - 6〜8 段階（ディフェンダー・なぞのかべ・ふしぎなバリアー・リフレクターなど）は、減らしたあとのダメージで計算します。
  - 最終ダメージから差し引く形にしていません。
- CH-R3（kyuura GR-2000-P319-HP-AND-DAMAGE）: 減らす量は、ダメージカウンターの単位（10）ずつ、0（減らさない）から 5 段階のダメージまでです（実装上の読み方）。英語版の「rounded to the nearest 10」は根拠にしていません。
- 減らす量は、ワザを使ったプレイヤーが決定 `damage_reduction` で選びます（選べるものは減らす量。観測の意味は `number`）。
  - 5 段階のダメージが 0 以下なら、選べるものは 0 だけなので決定を出しません（ダメージのログは v0.65 と同じ形）。
  - 減らしたときだけ、ログ `damage` に `damage_reduced`（`((5, お上品攻撃のカード, 減らした量),)`）と、`steps` に `5 お上品攻撃` を書きます。
- CH-R2（kyuura CR-SHELL-ATTACK-ATTACKER-PLUSPOWER。SUPPORTED）: 減らしたダメージは、受けたダメージで量が決まる返す効果（こうらがえし・クロスカウンター）の「受けたダメージ」に含まれます（受けたダメージは p.321 の計算の最終的なダメージ）。

### 2.3 決定と続きの情報

- ダメージの要素（`programs.Damage`）が計算の途中で `damage.DamageReductionRequired` を受け取り、決定を出します（v0.35 の計算の順番の決定と同じ形）。
- 決定の `context` に、決定を出した要素の位置・基本となるダメージ・選んだ計算の順番・受けるポケモン・弱点と抵抗力の扱い・変更効果を明示的なデータで運びます（`carry=True`。`PendingDecision` に項目を加えていない）。
- 再開は、選んだ量で計算し直すだけです。コインを投げ直しません。
- 不正な答え（選べるものにない量・2 つ以上・決める人が違う）は、状態を変えずに拒否します。
- 同じダメージで、6〜8 段階の計算の順番の決定も要る場合は、減らす量を先に選び、続きの情報で運んでから順番を選びます。

### 2.4 「うら」が出るまで投げるコイン（v0.64）

- れんぞくいしなげにお上品攻撃をつけた場合、選べる量は出た「おもて」の数に応じて増えます。実際の対戦では、残りの HP などで上限をつけていません。
- 宣言の前の先読み（`resolution/unbounded.py`）の「おもて」の数の組の key に、減らす量の選び方を加えました。
  - 減らす量があると、5 段階のあとの段階（6〜8 段階）の上限と、5 段階の前の変更効果から、組を分ける境目を求めます。
  - key は、選べる量ごとの計算の木の集まり（`("reduce", …)`）、0 より小さくなりうるなら `("below_zero",)` です。
  - 組を分ける根拠は v0.64 と同じです（計算の操作が、入力が十分大きければ一定か減らない）。
- 実際の対戦の投げ方（`coins.flip_until_tails`）・乱数・ログは変えていません。先読みの組はゲームの結果に使いません。

### 2.5 先読みと、止める関数

- 宣言の前の先読み（`derived`）は、減らす量の答えのうち計算の結果（最終ダメージ・2 段階で終えるか・順番の決定の要否）が同じものをまとめ、いちばん小さい量だけを試します（`programs.reduction_answers`）。
- v0.13 の止める関数（`legacy` の先読み・上限を超えたときの `VERIFIED`）が使う `effects.preview_attack_damage` は、減らす量を 0 として計算します。これらの経路では、減らしたときだけ起こる問いを見落としえます（技術的な制限。標準の `derived` では試す）。

## 3. ナツメのESP

### 3.1 やり直すコインと、時点

- つける先は、今の姿の名前が「ナツメの」で始まる自分の場のポケモン（バトル場・ベンチ）です。1 匹でも選ぶ決定 `select_pokemon` を出します。いなければ v0.44 の TR1。
- 有効期限は使った番の終わり（`discard_turn_offset = 0`）で、トラッシュします。
- やり直せるのは「そのワザの説明文に書かれているすべてのコイントス」です。解決の基盤の `AttackRun.flip`（ワザの説明文のコイン）だけを対象にしました。
  - 次のコインは含めません: こんらん（手順 5）、すなかけなど手順 4 の効果、クチバシティジムなどスタジアムの効果のコイン、「とうめい」、［はんこう］、ポケモンチェックのねむり。
- 時点は、説明文のコインを投げた直後、その結果を使う前です。
  - ワザを使ったプレイヤーに決定 `esp_redo`（選べるものは `1`。0〜1 個）で聞きます。
  - やり直すなら、同じ枚数を同じプレイヤーがすべて投げ直し、やり直した結果だけを使います（一部だけを投げ直さない）。
  - ログ `esp_redo` に、最初の結果（`original`）とやり直した結果（`redone`）を書きます。どちらの `coin_flip` もログに残ります。やり直さないならログ `esp_redo_declined`。
  - 結果を使う前に聞くので、最初の結果で選んだカードの答え（はかいビームのエネルギーなど）を、やり直したあとに使い回す場面はありません。
- 今の写しで「ナツメのポケモン」が使える説明文のコインのワザは、どれもコイントスを 1 回の `flip` にまとめて投げます:

| ナツメのモルフォン PMCG6-022 | かいふくりんぷん | 3 枚 | 「おもて」の数ぶん、自分と控え全員から回復 |
| | げんかくおんぱ | 2 枚 | 1 枚でも「おもて」ならこんらん |
| ナツメのスリープ PMCG6-045 | あんじをかける | 1 枚 | 次の相手の番にワザを使えない |

### 3.2 続きの情報と、二重の処理

- 決定は解決の基盤の `programs.suspend_esp_redo` が出します（`carry=True`）。
- 続きの情報（決定の `context` の `esp`）は、要素の位置・枚数・まとめ方・投げたプレイヤー・最初の結果・ESPのカードです。オブジェクトへの参照を持ちません。
- 再開（`programs.apply_esp_redo` → `flow._resume_attack`）は、答えを当てはめてから、決定を出した要素からもう一度処理します。
  - その要素の `flip` は、決定の前に投げたコイン（やり直したなら、やり直したコイン）の結果を使い、投げ直しません（`AttackRun.esp_preset`）。
  - もう一度処理した要素が、決定の前と違う枚数を投げる・ログを変えていたら、エンジンの不具合として止めます（`RuntimeError`）。
  - やり直しを聞くのは 1 つのワザで 1 回です（`AttackRun.esp_done`）。
- 宣言の前の先読みは、やり直す・やり直さないの両方を試します（止める選択は試さない）。
- 不変条件 `engine._esp_redo_decision_problems` が、決める人・選べるもの・続きの情報を確かめます。

### 3.3 組み合わせ

- 2 枚以上のESP（ES2）・説明が相手プレイヤーに投げさせるコイン（ES1。わるいスリーパーの「ベンチをあやつる」を［サイコリンク］で使う）・つけたあとに今の姿の名前が「ナツメの」で始まらなくなった（ES3。［へんしん］のメタモンの写す相手が変わったなど）は、記録で決まりません。
  - どれも「やり直す」を選べるが選ぶと止める形です（`unresolved_choices`）。「やり直さない」はいつも答えになります（決定の不変条件の例外にこの決定を加えた。広げない）。
- ［サイコリンク］（ナツメのフーディン）で持つワザ: ワザを実行するのはナツメのフーディンなので、ナツメのフーディンについているESPでやり直せます。説明が相手に投げさせるコインなら ES1。
- 名前: つけるとき・聞くときに、今の姿の名前（`form_def`）を見ます。

## 4. カスミの勝負

### 4.1 じゃんけん

- 使ったプレイヤー → 相手プレイヤーの順に、手を 1 つずつ決めます（決定 `janken_hand`。選べるもの 0 グー・1 チョキ・2 パー。観測の意味は `janken`）。順番は実装上の判断で、どちらが先でも手は同時に出したのと同じに扱います。
- 1 人目の手は、2 人目の決定の続きの情報（`context` の `first`）にだけ持ちます。観測（`observe`）は続きの情報を見せないので、2 人目と公開のログには、両方が決めるまで 1 人目の手は見えません（tests `MistysDuelTest.test_first_hand_is_hidden_until_both_choose` が、1 人目の手だけが違う 2 つの状態の観測が同じことを確かめる）。
- 両方が決めたら、ログ `duel_janken`（公開。両方の手・勝ったプレイヤー・何回目か）を書きます。対戦準備のじゃんけんのログ `janken` とは別のイベントです。
- あいこなら、同じ順番でもう一度決めます（`round` を 1 つ増やす）。回数の上限はありません。勝ち負けをコイン・乱数で決めず（英語版の「flip a coin」を持ち込まない）、手をカードとして表していません。

### 4.2 勝ったプレイヤーの手札

- 勝ったプレイヤーの手札（使っているこのカードは含まない。手札から出ている）をすべて山札にもどし（`zones.return_hand_cards_to_deck`。ログ `hand_to_deck` の `cards` は持ち主だけ）→ その山札を切る（`zones.shuffle_deck`）→ 5 枚引く（山札が足りなければ引けるだけ。p.312。v0.54 と同じ）。
- 手札が 0 枚でも、山札を切って引きます（もどすログはない）。
- 使ったプレイヤー（`TrainerUse.player`）・カードの持ち主（ナツメのサイキックコントロールで相手のトラッシュから使う）・勝ったプレイヤーは別の値です。相手が勝てば、相手の手札・山札が変わります。
- 同じ番にもう一度使えます（使用の回数の制限はない）。
- 場を変えないので、トレーナーの答えの続きを試す確かめ（`engine._trainer_dead_end`）をしません（`TrainerEffect.changes_field = False`。あいこのくり返しを深く試さない）。
