## 3. 共通の処理

### 3.1 山札からつける（`AttachFromDeck` の明示的な項目）

v0.41 の要素 `AttachFromDeck` に、説明ごとの違いを明示した項目を加えました。既定の値の動き（ひなたぼっこ）は変えていません。

| 項目 | 意味 | ひなたぼっこ・じゅうでん | もえあがる | しおまねき |
|---|---|---|---|---|
| `max_cards` | つける最大の枚数 | 1 | 1 | 3 |
| `zero` | 0 枚の答え | `allowed`（「つけてよい」） | `required`（ちょうど 1 枚） | `unresolved`（HC7） |
| `local_coin` | この要素のコイン | なし | なし | 「おもて」 |
| `shuffle` | 山札を切るか | 切る | 切る | 切らない |

- 色・枚数・選ばなくてよいか・つける先・コイン・山札を切るかを、カードごとの分岐にせず項目で分けます。
- もえあがるの「…1枚を選び出し、自分につける」は「てよい」がないので、選べるものがあればちょうど 1 枚です（0 枚の答えは `INVALID_CHOICE_COUNT`）。
- しおまねきの「最大3枚選び出し」の 0 枚は、v0.31 の HC7 と同じ問いです（答えのときに止め、決定は待ったまま）。
- しおまねきの説明には「その後、その山札をよく切る」がないので、山札を切りません（GR-2000-P312-DECK-HAND-DISCARD。山札を見ても、切るのは効果が書いたときだけ）。
- しおまねきのコインは山札の中身によらず投げます（自分の山札への効果。投げるかどうかで山札の中身を漏らさない）。つけることができない（v0.59 のクリスタルビーム。公開の情報）なら、
  処理の対象がないので投げません。
- 2 枚以上をつけるときは山札の uid の小さい順につけます（選んだ順によらない）。先読みは、同じカード id の基本エネルギーカードを uid だけが違う答えとしてまとめます（v0.46 の
  せいちょうと同じ）。0 枚が問いになる説明では 0 枚を試しません。
- 「「○」エネルギーカード」を選ぶので、山札のレインボーエネルギーは v0.58 の RB2 です（色を選ぶ効果だけ）。

### 3.2 トラッシュからつける（エネルギーきゅうしゅう）

- 要素 `AttachFromDiscard` の `energy_type` を None にすると「エネルギーカード」（種類・タイプを問わない。特殊エネルギー・レインボーエネルギーも選べる）です。
- カードの枚数で数えます（無色2個エネルギーも 1 枚）。色を選ぶ効果ではないので RB2 に当たりません。
- トラッシュにエネルギーカードがあるときの 0 枚は HC7 と同じ問いです。トラッシュにエネルギーカードがなければ、処理の対象がないので決定を出しません（HC7 とは別）。
- トラッシュから場につける効果（トラッシュから手札に加える効果ではない）なので、ポケモンタワー（v0.74）では消えません。

### 3.3 つける経路の共通の約束

どれも v0.41 からの約束のままです。

- 手札からつける通常の操作の回数（`energy_attachments_this_turn`）・特殊能力でつけた枚数には数えません。
- つけたら `effects.after_energy_attached` を聞きます。特殊エネルギーのつけたときの効果（レインボーエネルギーの 10 など）は、手札から出してつけたときだけで、山札・トラッシュからでは起こりません。
- つけることができない効果（v0.59）は、どの経路でも聞きます（エナジーサポートは、そのポケモンを選べるものに入れない）。

### 3.4 エナジーサポート（山札から控えにつける）

- kyuura の日本語の文面は「自分の山札から「超」エネルギーカードを1枚選び出し、自分の控えポケモンにつける。その後、山札をよく切る。」です。英語の欄は「Show that card to your opponent,
  then put it into your hand」で、処理が違います。日本語にしたがいます（kyuura への報告事項。11 章）。
- 決定は 2 つです: つけるカード（`ATTACH_FROM_DECK`。`stage` は `card`。ちょうど 1 枚）→ つける控え（`ATTACH_TO_BENCH`。`stage` は `bench`。1 匹）。2 つの決定のあいだ、カードは山札にあります。
- 控えポケモンがいない・山札に選べるカードがないなら、つけずに山札を切ります（p.309。説明の「その後、山札をよく切る」に条件がない）。
- つけるのはワザの効果なので、つける控えの「とうめい」を評価します。受けないなら、カードは持ち主のトラッシュに置きます（ログ `deck_energy_evaded`）。v0.45 の「じりょくせん」・
  CR-TRANSPARENCY-ENERGY-BOMB と同じ読み方で、実装上の判断です。

### 3.5 山札の名前の決まったポケモンを好きなだけ（くらげのむれ）

- 選べるものは、山札の、名前（その場所の印刷の名前）が 4 つ（メノクラゲ・ドククラゲ・カスミのメノクラゲ・カスミのドククラゲ）のどれかと完全に同じポケモンのカードです。
  段階は問いません。同じ名前の別の id のカード（PMCG5-030 と GD2-003 など）も選べます。名前の一部・始まりでは選びません。
- 「好きなだけ」「手札に加えてよい」なので、0 枚・一部・すべてを選べます。0 枚は「てよい」の、加えないことです（ログ `reveal_from_deck_declined`）。v0.39 の GS1（「最大3匹」）・
  v0.31 の HC7（「最大2枚」）の問いとは書き方が違うので、当てはめていません。
- 同じカードを 2 回選ぶ答え・山札にないカードは、決定の確かめが拒否します（状態・乱数・ログ・決定は変わらない）。
- 選んだカードだけを見せて手札に加えます（v0.24 の `zones.reveal_deck_to_hand`。1 枚に 1 つのログ `reveal_from_deck`。山札の uid の小さい順）。選べたほかのカードはログに書きません。
  そのあと山札を 1 回だけ切ります。
- 先読みのまとめ方: 選んだカードは手札に入るだけで、このあとの要素はありません（ワザの最後の要素。山札の並びを使う要素もない）。同じカード id のカードは内容が同じなので、uid だけが違う
  答えをまとめます（v0.44 の `card_id_answers`）。選ぶ枚数・カード id の組み合わせは、すべて試します（1 つの代表にまとめない。選べるものの数を制限しない。上限の 4,096 は変えない）。
  小さい山札で、まとめた答えの結果の集まりがすべての答え（`all_answers`）の結果の集まりと同じことを、tests の `test_preflight_grouping_matches_full_enumeration` が確かめます。
  選べるものが 16 枚の山札でも宣言でき、すべてを選べることを `test_many_candidates_are_legal` が確かめます。

### 3.6 「おもて」の数ぶんのトラッシュのカード（おにびあつめ）

- コイン 3 枚（ワザ全体のコイン。「おもて」の数でまとめて先読みする）→ 「おもて」の数ぶんの「炎」エネルギーカード（自分のトラッシュの「炎」の基本エネルギーカード）を手札に加えます。
- 「おもて」が 0 なら何もしません。ワザの失敗ではありません（ログ `attack_failed` はない）。
- 「おもての数ぶん」を「最大」と読みかえていません。選べるものの数が「おもて」の数以上なら、ちょうど「おもて」の数を選びます（決定 `RECOVER_ENERGY`。最小と最大が同じ）。
- 選べるものが 1 枚以上で「おもて」の数より少ないときは、説明の枚数を選べないので決められません。v0.44 の FC1（`stated_cards_short`。kyuura の UQ-STATED-COUNT-SHORT）です。
  p.309 の「処理の対象がなくなってしまっている場合」は対象がないときの規定で、足りないときを書きません。先読みがコインの結果ごとに確かめるので、宣言の前に止まります（コインを投げない）。
- 選べるものがなければ処理の対象がないので、コインを投げません（v0.38 の `has_target`。トラッシュは公開の情報）。
- トラッシュのレインボーエネルギーが「「炎」エネルギーカード」に当たるかは決まりません（RB5。6 章）。
- ポケモンタワー（v0.74）の場では、この要素（トラッシュから手札に加える）の効果が消えます。処理の対象がないのでコインを投げず、ログ `discard_to_hand_suppressed` を残します。
  レインボーエネルギーがあっても RB5 で止めません（効果が消えるので選ばない）。

### 3.7 しらせる

- 「自分に控えがいない時、このワザは使えない」はワザを使うための条件です（`usage_problem`。`NO_BENCH`）。必要なエネルギーの確認のあと・こんらんのコインの前・引く前に拒否します。
- 引くのは効果で引くときなので、山札が足りなければ引けるだけ引きます（p.312。0 枚でも負けではない）。そのあと v0.34 の「テレポート」と同じ入れ替え（1 匹。にげるではない）です。
- 相手のワザとして使うとき（ゆびをふる・ちょうのうりょく）は、要素 `SelfSwitch(required=True)` の `copy_problem` が、v0.32 の「なかまをよぶ」と同じ扱いをします（ピッピ・ピクシーでは選べず、
  カスミのコダックでは HC9）。

### 3.8 たすけをよぶ・ほうしをとばす

- たすけをよぶ（カスミのコダック）は v0.45 の型のままです。「おもて」のあと 0〜1 枚を選べ、0 枚でも山札を切ります。忍者ジム（v0.74）のちょうど 1 枚は持ち込んでいません。
- ほうしをとばすは名前が「パラス」と完全に同じたねポケモンだけです（エリカのパラスは選べない。相手のワザとして使うときも同じ）。ベンチに空きがなければワザを使えません（`BENCH_FULL`）。

### 3.9 ひのこ・10まんボルト

- ひのこ（ガーディ）の「自分についている「炎」エネルギーカードを1枚トラッシュしなければ、このワザは使えない。」は、炎エネルギーカードをトラッシュするワザです。トラッシュの時点は
  RUL-ENERGY-DISCARD-ATTACKS の範囲としてワザの効果です（こんらんの「うら」ならトラッシュしない）。文面は印刷の文面で、v0.31 のカツラのウインディの「ほのおのあらし」と同じ扱いです。
- 10まんボルト（ピカチュウ）の「このカードについているエネルギーカードを全てはがし、トラッシュする。」は、ついているエネルギーカードをすべて（種類を問わない）トラッシュして 50 です。
  炎でないので RUL-ENERGY-DISCARD-ATTACKS の範囲ではなく、トラッシュの時点は決められません（v0.31 の HC1。こんらん状態で使うときだけ止める）。v0.31 の第1弾のサンダーの
  「10まんボルト」と同じ扱いです。トラッシュできないときの「ダメージは 0」（v0.71 のプロモのリザードン）は持ち込んでいません。

### 3.10 もろばバサミ（受けるダメージが 2 倍）

- 自分自身に与える持続する効果 `state.DoubledDamage`（種類 `doubled_damage`）です。はたらく番は次の相手の番で、消える契機は v0.4b と同じです（期限・ベンチ・進化・きぜつ）。
- はたらく番に受けるワザのダメージは、p.321 の 8 段階（ワザを受けるポケモンの持っている「ダメージを変更する効果」。GR-2000-P321-DAMAGE-ORDER）で 2 倍です（`damage.MULTIPLY`）。
  同じ段階にほかの効果があり順番で結果が変わるときは、v0.35 の決定（受けるポケモンの持ち主が選ぶ）です。最終ダメージを直接 2 倍にしていません。
- ワザでないダメージに当てはめるかは、印刷の文面（「受けるダメージ」）・kyuura の記録から決まりません。推測で広げていません:
  - トレーナーのダメージ（バトル場は穴だらけ!）: v0.61 の TD1（同じ問い）。
  - 特殊能力のダメージ（こっそりかみつくなど）: DB1（新しい停止コード。`effects.received_power_damage` が量を変える前に止める）。
  - ポケモンチェックのどく: 効果が番の終わり（ポケモンチェックの前）に消えるので当たりません。
- 不変条件は、効果を与えたワザの登録の `doubled_terms()` と照らします（`engine._terms_problems`）。書き出しは形式 8 からの持続する効果の種類として書けます（形式は増やしていない）。

## 4. ポケモンタワーでの P19 の過剰な停止（v0.74 の不具合）の修正

- v0.74 の `resolution/kernel.py` の `capture_post_knockout` は、きぜつしたときに使える特殊能力（ふしちょう）を候補にするとき、P19（ガスの発生源がいっしょにきぜつする）の問いを、
  ポケモンタワーの確かめより先に投げていました。
- ポケモンタワーの場では、ふしちょう（トラッシュから手札に加える効果。CR-PHOENIX-RETURN）は使っても状態が同じなので、v0.74 から機会を出していません。ガスの発生源がいっしょに
