## 5. 方策の変更の案と推奨

候補の選択の順番だけを変える案です。合法性・処理可能性の判定、単局の上限、反復の抑制の既存の規則は変えません。

| 案 | 内容 | 9023 での効果の目安（推定） | 失う手 |
|---|---|---|---|
| A. 現状維持 | 変えない | 受理 1,000（上限のまま） | なし |
| B. 直前の逆操作だけを一時的に下げる | 受理のあとの観測が、1 つ前の受理の前の観測と同じなら、いま受理した候補を下げる | 区間の受理 775 → 243、局の受理 約 468 | 9022・9024 でも区間の途中で止まる（9022 は 38 → 29） |
| **C. 確認できた周期まで下げる（推奨）** | 受理のあとの観測が、同じ番の中で前に見た観測と同じなら（長さを問わない）、その周期の受理をした候補を下げる | 区間の受理 775 → 190、局の受理 約 415 | 9022 は 38 → 21。9024 の番 23 の正当な例は残る |

- 目安は、記録の区間が「最初に配置が戻った手で止まっていたら」の受理の数です（`out/forecast.json`）。方策の乱数の並びが変わるので、実際の手順は変わります。比較対戦の代わりにはなりません。
- 9023 で配置が戻った区間は 43 のうち 38 です。C の目安で残る手は 190（1 区間あたり平均 4.4 手）でした。往復（174）だけを見る B では、3 手以上の周期（427）が残ります。
- C で受理が 400 程度に減れば、山札（7 枚・6 枚）が尽きる番 85 前後まで進んでも 1,000 に届かない見込みです（ワザのない番の受理は［ダメージスワップ］のほかに 1 番 2〜3 件）。この見込みは推定で、次の単位で確かめます。

**推奨: C（確認できた周期まで優先度ダウン）。** 仕様は次のとおりです。

| 項目 | 指定 |
|---|---|
| 対象となる観測 | 主体の本人の観測（`view` の `observation`）。受理のたびに、同じ番の中の観測を正準な JSON で記録する（番の始めの観測をふくむ）。観測には内部の状態をふくめない（本人に見える値だけ）。9023 の番 69 では、配置が戻った 14 組のうち 13 組で観測の全体が一致し、残りの 1 組は実際に状態が違った |
| 対象となる操作 | 主体の番の中の受理（番の操作。決定の回答・ホストは対象にしない）。種類は限らない（［ダメージスワップ］に限った規則にしない） |
| 抑える条件 | 受理のあとの観測が、同じ番の中で前に記録した観測と同じとき、その観測から今までの受理をした候補（`candidate_identity`）を「下げた候補」にする |
| 抑え方 | 下げた候補は順位 7（番の終了より後ろ。既存の `DEMOTED_RANK`）。候補を消さず、処理可能性を書き換えない |
| 履歴を消す時点 | 番が変わったとき（既存の `RepeatMemory` の数と同じ）。エピソードの始めでは消さない（今の `demoted` と違う点） |
| ほかに組み立てられる手がない場合 | 下げた候補しか選べないなら、それを選ぶ（既存の `rule2:no_alternative` と同じ扱い。対戦を止めない）。番の終了がある場面では番の終了が先に選ばれる |
| 記録 | 選択の理由に `rule2:demoted:cycle` のような印を付け、下げた候補と、戻った観測の番号を trace に残す（次の単位で比べるため） |
| 変えないもの | 合法性・処理可能性・既存の反復の抑制（2 回・下げる 2 回）・単局の上限・入力の均等の選び方 |

- **別に記録しておく小さな論点（推奨の外）:** 鍵が使うポケモンをふくむため、同じ効果の特殊能力を持つポケモンが 2 匹いると鍵が分かれます（4 番で 48 件）。C では観測の一致で下げるので、この点は直さなくても周期は止まります。

| 往復の数（この文書の 2 章と同じ定義） | 番ごとに、最初に観測が戻ったあと、同じ番で下げた候補が選ばれていないこと（`no_alternative` を除く） |
| ワザ・番の終了に進んだ回数 | 番の終了が、下げた直後か同順位の選択で選ばれていること（理由の印で数える） |
| 拒否・異常 | 拒否 0 のままか、増えたら原因を記録する。異常 0 |

- 同じ seed でも、方策の乱数の並びが変わるので、局は番 40 より前から違いえます。比べるのは、膠着の番の繰り返しの形と、局全体の数です。

**回帰確認（対照 5 局から）:** 9022 と 9024 を同じ条件で方策だけを変えて走らせ、次を確かめます。
- 9024 の番 23 の型（1 回の移動のあと、にげる → ワザ）が、下げる条件に当たらないこと（観測が戻っていないので、下げられない）
- 9022 の正味の移動の区間で、下げたのが観測が戻ったあとの候補だけであること
- 9021・9025・9026 は［ダメージスワップ］の受理がなく（9026 は提示だけ）、比べる価値が小さいので任意とする

## 7. 未確認・限界

- 配置の一致は、自分の場のダメージ（と、番 69 の 14 組での観測の全体）で確かめた範囲です。山札の順・相手の手札など、観測に出ない状態の一致は確かめていません。C の規則は本人の観測だけを使うので、この範囲で十分と見ていますが、観測に出ない差がある周期を「戻った」と見なす誤りはありえます。
- 方策のコードの説明（3 章の 1〜5）は、コードを読んだ結果と記録の並びの一致によります。方策を動かして確かめてはいません。
- 5 章の受理の目安・山札の尽きる番は推定です。乱数の並びが変われば、膠着そのものが起きないこともありえます。
- 膠着（ワザを使えない番が続く）の原因は、デッキの構成と引きです（L67-U のエネルギーと、フーディンのワザの費用）。この調査では扱いません。
- C1 以外の条件（C2〜C4）に［ダメージスワップ］を持つカードがあるかは調べていません（TR8 の本監査の C1 以外の局では、この形の区間を数えていない）。
