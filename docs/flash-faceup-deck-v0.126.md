  kyuura が画像と同じことを確かめた）は照合だけに使い、別に持ちます（`effects.FLASH_PRINTED_TEXT`・`FLASH_LATEST_TEXT`）。句読点・括弧を一般的に正規化して 2 つを一致させていません。

## 4. 状態・知っている情報・公開の範囲（設計）

実装の前に、次の分け方を決めてから共通の処理に組み込みました（新しい部品 `kyuura_engine/faceup.py`。`engine.py`・`resolution/` にカード id による分岐は加えていません）。

| 区分 | 持ち方 | 内容 |
|---|---|---|
| 向き（物理的な状態） | `GameState.face_up_deck`（uid の並び） | フラッシュで置かれた具体的なカードの印。番・プレイヤーへの持続効果ではない。カードが山札をはなれたら、そのカードの印を消す（`drop_left_marks`。別のカードへずれない）。切る前に、その山札の印をすべて消す |
| 本人が知っている情報 | 観測が状態から求める（`known_face_up`。持ち主だけ） | 並べ替えた本人は、自分の山札のおもてのカードの位置とカードを知っている（自分で並べた）。新しく確かめたのではない |
| いま公開されている範囲 | 観測が状態から求める（`face_up_top`・`face_up_count`。全員） | いちばん上がおもてなら、そのカードの id。おもての枚数（おもてにした枚数と、そのあとの公開の移動から決まる）。2 枚目より下のカードは見せない |
| 以前に公開されたカードの記憶 | 公開のログ（`flash_face_up`・`face_up_deck_top`） | 知ったカードの種類は忘れさせない。手札に移ったカードは山札の上に公開し続けず、手札の通常の観測（持ち主だけ）にもどる。切ったあとの位置は分からない |
| 新しく知ろうとする要求 | コマンド `CheckFaceUpDeckCard`（受け付けない） | いちばん上は `ALREADY_VISIBLE`、持ち主は `ALREADY_KNOWN`、おもてでない位置は `NOT_FACE_UP`、相手の 2 枚目より下は FU2（UQ-FLASH-FACE-UP-DECK）で止める |

- おもてのカードは、いつも山札の上から続く並びになります（置くのはフラッシュだけで、上から引く・取る・トラッシュする、下に置く操作は並びを保ち、上に置く・並べ替える操作は止める）。
  `check_invariants` が `faceup.prefix_problems` で確かめます（印が重ならない・山札にある・上から続く・5 枚まで・おもてにしたログがある）。
- 観測（`observation.observe`）の山札は、おもてのカードがなければ v0.125 までと同じ `{"count"}` だけです。あれば `face_up_count`・`face_up_top`（カードの id。uid は書かない）を全員に、
  `known_face_up`（位置・カードの id）を持ち主にだけ加えます。uid を書かないのは、uid の付け方がデッキの並びで決まり、手札に移ったあとも同じカードを追えてしまうためです（v0.122 の隠れた uid の
  保護と同じ考え）。観戦者は、プレイヤーが見られるという裁定から両方の非公開の 5 枚を見せることにせず、公開の範囲（いちばん上と枚数）だけを見ます。
- `CheckFaceUpDeckCard` は、原典が新しい自由行動を定めたのではなく、2 枚目より下を新しく知ろうとする操作を通常のコマンドとして識別して止めるための、実装上の最小限の入口です
  （どの答えでも状態・乱数・ログを変えず、カードの中身を返さない。理由の文にもカードを書かない）。下の閲覧を禁止と裁定したのではありません。

## 5. フラッシュの手順（`effects.FlashTrainer`）

1. 使うための確認（手札から出す前）: どちらの山札も 5 枚以上。片方でも 5 枚より少なければ（0 枚をふくむ）FU1（UQ-STATED-COUNT-SHORT）で止めます。見られるだけに丸めず、片方だけを処理しません。
   錯乱ジムで相手がかわりに使うときも、使うプレイヤー（`use.player`）から見た相手で同じ確かめをします（借りて使う側の確認は v0.57 の `borrow_unusable_reason` が `check_playable` を呼ぶ）。
2. 既存のトレーナーの手順（p.310 の手順 1・2。使用中 `trainer_in_use`）のあと、段階 0: 使った側の相手が自分の山札の上の 5 枚を見て（ログ `look_at_deck_top` の `cards` はその人だけ）、
   並べ替える（決定 `ARRANGE_DECK_TOP`。選べるものは見た 5 枚、ちょうど 5 枚）。答えの並びで山札の上を置きかえ、その 5 枚に印を付けます（ログ `arrange_deck_top` の `cards` は並べた人だけ、
   `flash_face_up` は公開でいちばん上のカードの id だけ）。
3. 段階 1: 使ったプレイヤーが同じことをします。相手のいちばん上は段階 1 の決定の前に観測に出ています（あとの決定で使える）。
4. 決定がなくなったら、エンジンが使用中のカードを 1 回だけトラッシュします。同じ並びの答えでも、おもてにすることに意味があるので空振りにしません。この処理では切りません。

- 答えの確かめは既存の決定の共通の確かめ（選べるものの中から、重ならず、ちょうど 5 枚。決めるプレイヤーだけ）を使います。別のカード・重なり・不足・余分・別の人の答えは拒否され、状態・乱数・
  ログは変わりません（コマンドは状態の複製の上で処理する）。
- 検査の範囲: 1 つの側の答えは 5! = 120 通りで、両側の直積は 14,400 通りです。先読みの上限 4,096 を上げたり、並べ方を一部に削ったりはしていません。2 つの決定は順に出し、次の性質で、それぞれの
  側を別に確かめます: (a) 相手の答えは、使ったプレイヤーの決定の選べるもの（自分の山札の上の 5 枚）・選ぶ数・決めるプレイヤーを変えない（相手の山札の並びだけを変える）。(b) どの答えも
  場のポケモン・HP・姿・手札・トラッシュ・乱数を変えず、止まる答えがない（フラッシュは `changes_field` でなく、`_trainer_dead_end` の答えの先読みに入らない。どの答えでも受け付けるので、
  答えのない決定の確かめ `_decision_has_unstopped_answer` も呼ばれない）。テストは、相手の 120 通りと、相手の答えを 2 つにしぼったときの使ったプレイヤーの 120 通りを確かめ、直積は展開しません。
- 決定の間・保存のあとも、使った人（`trainer_in_use`）、並べる人（決定の `player`）、対象の 5 枚（決定の `options`）、終えた側（続きの情報の `stage` とログの `flash_face_up`）、表向きの印、
  公開・既知の情報（観測が状態とログから求める）を持ちます。`decision_problems` は、段階と決める人・選べるものが山札の上の 5 枚・その前の見たログ・終えた側の順を確かめます。

## 6. 操作ごとの確定経路と停止の境界

山札にかかわる処理は、コマンドの終わりに前後の状態とそのコマンドのログで分類します（`faceup.command_problem`。`engine._apply_once` が呼ぶ）。加えて、コイン・選択の前に止めるべき効果は、
それぞれの確かめ（`check_playable`・`check_usable`・ワザの要素の `on_declare`）で先に止めます。決定への答えで、どの答えでも止まるときは、答えのない決定を残さずにその前の状態で対戦を止めます
（既存の `_decision_has_unstopped_answer` の止め方に、この分類を加えた）。

| 操作 | どの読みでも同じか | 実装 |
|---|---|---|
| 最上位の参照（観測・効果） | 同じ（CR-FLASH-TOP-CARD-SEEN） | 観測の `face_up_top` と効果は同じ状態（山札の上の印）を読む。サカキのニャースのてつだうふりは、見えている相手のいちばん上をそのまま動かす（トレーナーならトラッシュ、ほかは手札）。［スパイ］がいちばん上のおもてのカードを見るのも、動かさないので受け付ける |
| 番の最初の 1 枚ドロー・1 枚の効果のドロー | 同じ | 見えているいちばん上を引く（p.312「カードを引く」は一番上から取る。既存の `zones.draw_cards`）。引いたカードの印を消し、次のおもてのカードがいちばん上になれば公開する（ログ `face_up_deck_top`）。引いたカードは手札の通常の観測にもどる |

| 上へのカード追加（手札・トラッシュから） | 分かれる（置いたカードの向き・下のおもてが見えるか） | FU4（ポケモン再転送・リサイクルなど山札の上へ置くトレーナー・［トランスポート］・わるいいたずらは、使う前・宣言・コインの前）。おもてのない山札には v0.125 までと同じ |

| 見る・並べ替える・順番を変えずにもどす | 範囲におもてがあれば分かれる | FU5（ポケモン図鑑は 1 枚以上見る答えを選ぶと止める・0 枚を選べない版は使う前、ラジオとうは見る答え、みらいよちは選ぶと止める山札の持ち主、［OBSERVE］・［わるぢえ］・もやすは宣言・コインの前） |
| もう一度フラッシュ | 5 枚より下におもてが残れば分かれる | おもてのカードはいつも 5 枚以内で上から続くので、5 枚より下には残らない（FU5 の確かめは置いた）。並べ替えた 5 枚が新しいおもて |
| 山札を切る | 同じ（印刷・最新の説明） | `zones.shuffle_deck`（全てのシャッフルの入口。山札をさがしたあと・もどしたあと・トレーナー・特殊能力・ワザ・スタジアムが通る）で、切る前に印を消す（ログ `shuffle` の `face_up_cleared`。印がなければ書かない）。乱数の使い方は印の有無で変わらない |
| 分類していない変わり方 | — | `UNSUPPORTED_FACE_UP_DECK_PATH`（エンジンの未対応。資料の未解決に偽装しない） |

- 通常の 1 枚ドローの根拠と読み方: 既存の規定（p.312「カードを引くときは山札の一番上から取る」。`docs/rules-2000-02-14.md`）と CR-FLASH-TOP-CARD-SEEN だけで決まる範囲を実装しました。
  引いたカードはどの読みでも直前まで全員に見えていたいちばん上のカードで、次のおもてのカードは引いたあとにいちばん上として見えます。新しく情報の差が出る操作（2 枚以上をまとめて引く）は通していません。

- 一般の正常経路（両方の山札が 5 枚以上で使う → 両側が並べ替える → 最上位を見て行動する → 番の 1 枚ドローで進む → 山札を切って印を消す）は、単体のテストと正式な対戦で動きます（10 章）。
  フラッシュを使っただけで止まる・次の通常ドローが必ず止まる登録にはしていません。
