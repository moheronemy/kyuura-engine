# v0.92: 能力の消去・続く制限の 8 枚

v0.92 は、特殊能力を止める効果・続く「にげる」とワザの禁止・受けるダメージを増やす効果を持つポケモン 8 枚（イトマル neo1-004・アリアドス neo1-011・イワーク neo1-050・
ヤミカラス neo1-055・ゴルバット neo3-004・ヨーギラス neo4-073・ナツメのゲンガー GD6-008・ハッサム PRN-025）のワザ 16 を、kyuura データの採用で 1 回にまとめて登録した版です。
特殊能力の消去、ワザ・「にげる」の禁止、受けるダメージの変更を、効果ごとの「はたらく期間」と「消える契機」で表す共通の扱いにまとめ、与えたダメージの半分を回復する型の文面の
照合を直しました。目的は模擬戦で使えるカードを増やすことで、強さ・勝率・釣り合いは評価していません。

- 開始点: 調査の基点は v0.91（`d28e912b80403892374ece3f58e1e08f9cf267e6`）。最新の `main` は `8de7bbb19736f8664ce64ec1b843ca759dc3c001`（v0.91 を含まない）。作業ブランチ

## 4. 期間と消える契機の共通の扱い

### 4.1 型と値

- 期間を明示した持続する効果の型を 3 つ加えました（`state.PERIOD_EFFECT_TYPES`）: `PeriodRetreatLock`（「にげる」ことができない）・`PeriodAttackLock`（ワザを使えない）・
  `ReceivedAttackDamageBonus`（受けるワザによるダメージを増やす。`amount` は 10 の正の倍数）。どれも相手に与える効果（`on_opponent`）です。
- 値: `created_turn`（与えた番）・`active_turn`（はたらき始める番）・`end_turn`（はたらく最後の番。`None` は期限なし。いやなおとは必ず期限がある）・`source_card`・`source_player`・
  `source_pokemon`（発生源の場の番号）・`while_source_active`（「このカードがバトル場にいるかぎり」）・`ends_on`（説明に明記された消える契機。今は `SOURCE_LEAVES_ACTIVE` だけ）。
  `created_turn ≤ active_turn ≤ end_turn`・知らない契機は作るときに `ValueError`。
- 期間の問い合わせ（`persistent.period_active`）: 今の番が `active_turn`〜`end_turn` にあり、`while_source_active` なら `source_player` のバトル場のポケモンの場の番号が
  `source_pokemon` と同じとき（問い合わせのときに確かめる。同じ位置に出た別のポケモンを発生源にしない）。
- 期限による消去（`persistent.remove_expired_persistent_effects`）は `persistent.end_turn` で決めます。既存の型は v0.91 までと同じ値（はたらく番の終わり、「それ以後」は期限なし、
  「なきつく」は次の番の始め）のままで、既定の値を変えていません（`LifetimeTest.test_existing_types_keep_their_expiry`）。

### 4.2 「いるかぎり」と「はなれたとき消える」を分ける

- **問い合わせのときの確かめ**（`while_source_active`）: 発生源がバトル場にいないあいだ、効果ははたらきません。ハッサムの「にらみつける」（v0.76 の
  `AttackLockWhileSourceActiveOnHeads`。持続する効果は v0.40 の `CannotAttackWhileSourceActive`）は、この確かめだけを持つ既存の型で、発生源がはなれても効果は残り、同じ番にもどす選択は SG1（`UNRESOLVED_ATTACK_LOCK_SOURCE_RETURNED`）のまま止めます。
- **はなれた時点の消去**（`ends_on` の `SOURCE_LEAVES_ACTIVE`）: 説明が「このカード（自分）が…バトル場をはなれたとき、この効果は消える」と書く効果だけ、発生源がバトル場を
  はなれた時点で消します（ログ `persistent_effect_removed` の理由 `source_left_active`。`persistent.remove_source_left_effects`）。消えた効果は、発生源が同じ番にもどっても復活しません。
- 消去を呼ぶのは、バトル場をはなれるすべての経路です: 「にげる」（`engine._retreat`）、自分・相手のトレーナーとワザ・特殊能力の入れ替え（`effects._switch_active_with_bench`）、
  相手を入れ替えるワザの要素（`ForceSwitch`）、きぜつ（`procedures.knock_out`）、場から山札・手札・トラッシュ（`zones.return_in_play_to_deck`・`return_basic_to_hand`・
  `return_in_play_to_hand`・`discard_from_play`）、手札のたねポケモンをバトル場に出して前のポケモンを動かすトレーナー（`zones.hand_basic_to_active`）、うらのカードをおもてにして
  トラッシュ（`zones.reveal_face_down`）。
  消すのは受けたポケモンの持つ効果のうち、発生源（`source_player`・`source_pokemon`）がはなれたポケモンと同じものだけです。
- 説明に発生源の消える契機のない効果（クモのす・いやなおと・かげしばり・こわいかお・既存の型）は、発生源がはなれても消しません。受けたポケモンがバトル場をはなれる・進化・退化・
  きぜつで消えるのは一般の規定（p.310・p.322・p.324）で、既存の処理のままです。
- まねたワザ（ゆびをふる）の発生源は、まねたポケモン（実際にワザを使ったポケモン）です。ワザの出どころ（`effect` のカード id と位置）はまねたワザのままです
  （`MeanLookTest.test_copied_source_is_the_copier_and_its_evolution_is_ml1`）。

### 4.3 重なり・「にげる」の禁止の範囲

- 期間を明示した効果は、期間の重なる同じ種類の効果を持てます（p.323「持続する効果は重複することがある」）。同じ種類・同じはたらき始める番は 1 つまで（不変条件）。
- 「にげる」の禁止は「にげる」だけを止め、入れ替え（トレーナー・ワザ）は止めません（p.325）。拒否はエネルギーのトラッシュ・こんらんのコインの前です（`RETREAT_PREVENTED`）。

## 5. イトマル・アリアドス・ヤミカラスの禁止と、きゅうけつどく

### 5.1 こわいかお（イトマル）

- 要素は `Coin` → `OpponentCannotAttack(gate=おもて)` → `OpponentRetreatLock(gate=おもて)`。1 枚のコインで、次の相手の番のワザと「にげる」の両方を止めます（要素ごとに投げ直さない）。
  与える効果は既存の `CannotAttack`・`CannotRetreat`（次の相手の番だけ）です。「うら」なら何も与えず、ワザの失敗ではありません。
- 相手に与える効果なので、コインの前に「とうめい」で受けないと決まった相手は T19b、「ワザをうけない」相手は HC3（v0.34 の `void_coin_question`）です（`ScaryFaceTest`）。
- 1 回のワザで同じポケモンに種類の違う 2 つの持続する効果を与える初めての登録なので、ログの監査の持続する効果の鍵に種類を加えました（11 章）。

### 5.2 いとをはく（イトマル）

- 既存の `ParalyzeOnHeads`（v0.9 の T19b の一覧に加えた）。

### 5.3 クモのす（アリアドス）

- 「おもて」なら、与えた番から期限なしで「にげる」を止めます（`PeriodRetreatLock`。`end_turn` は `None`）。番の終わりでは消えません。
- 「(相手がバトル場をはなれたとき、この効果は消える。)」は一般の規定と同じ内容で、発生源の消える契機ではありません。アリアドスがバトル場をはなれても消えず、受けたポケモンが
  はなれる・進化・退化で消え、同じ番にもどっても復活しません（`SpiderWebTest`）。

### 5.4 くろいまなざし（ヤミカラス）

- コインなしで、与えた番から期限なし、発生源のヤミカラスがバトル場にいるかぎり「にげる」を止めます（`while_source_active`）。「(自分か相手がバトル場をはなれたとき、この効果は消える)」
  なので、発生源か受けたポケモンがバトル場をはなれた時点で消えます（`SOURCE_LEAVES_ACTIVE`）。ヤミカラスがにげて、同じ番にもどっても復活しません（`MeanLookTest`）。
- クモのすとの違い: クモのすは発生源がはなれても残り、くろいまなざしは発生源がはなれたら消えます。
- 発生源が進化・退化するとき、「このカード」がバトル場にいることになるのかは決まりません（ML1。10 章）。

### 5.5 きゅうけつどく（アリアドス・ゴルバット）

- 要素は `Damage(OPP)` → `Drain("damage")` → `Status(POISON, after_damage="damage")`。回復の量は与えた最終ダメージの半分（切り上げ。v0.4d のメガドレインと同じ。相手の残りHP で上限を
  付けない。自分にのっている数より多くはとりのぞかない）。相手が HP 以上になっても自分は回復し、相手はどくにしません（p.309。対象がいない）。最終ダメージの結果は決定の続きにも運びます
  （v0.87 の `damage_results`）。
- ダメージを与えなかったとき（ダメージの要素が無効・計算の結果が 0 など）、「その後、」のどくが回復の条件の中か（与えたときだけ）、順番だけか（いつも）は文面・記録から決まらない
  v0.17b の Z23（`UNRESOLVED_EFFECT_AFTER_NO_DAMAGE`）と同じ問いです。どくにならないポケモンなら、どちらでも同じなので止めません。
- どくは相手に与える効果として宣言しています（`opponent_effect_elements` に `POISON`）。

## 6. いやなおと（イワーク・ゴルバット）

- 期間は文面ごとに違い、同じ全文として扱いません: イワークは「次の相手の番と、次の自分の番」（与えた番 + 1〜+ 2）、ゴルバットは「次の自分の番が終わるまで」（与えた番〜+ 2）。
  型は `ReceivedAttackDamageBonus`（要素 `OpponentDamageTakenBonus`）で、相手に与える効果として「とうめい」・「ワザをうけない」状態を評価します。
- はたらき方は p.321 の 8 段階（受けるポケモンの持っている効果）の加算 +20 です（`effects.attack_damage_modifiers`）。基本となるダメージ・ワザを使う側の効果・ダメージカウンターの
  直接の配置にはしません。2 段階までで 0 以下なら計算を終えるので加えません（ダメージの要素のないワザ・「ダメージを受けない」状態にも加えない）。同じ 8 段階に加算でない効果
  （かたくなる・リフレクターなど）があり順番で結果が変わるときは、既存の `damage_step_order` の決定で受けるポケモンの持ち主が選びます（`ScreechTest.test_same_step_order_decision_with_zero_below`）。
- 「ワザによるダメージ」なら、だれの番かで決めず、記録された p.321 の計算に当てはめます: 相手のワザ、受けたポケモン自身のワザの自分へのダメージ（でんげきの「うら」）、
  返す効果のダメージ（p.321 の計算をするもの）。どくのダメージはワザによるダメージではないので加えません。
- こんらんの 20 が「ワザによるダメージ」かは決まらない既存の問いで、こんらんのコインの前に `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS` で止めます（`procedures.confusion_damage_problem`）。
- 受けたポケモンがバトル場をはなれる・進化・退化・きぜつで消えます。発生源だけがはなれても消えません（説明に書かれていない）。重なった 2 つはそれぞれ +20 です。
- いかり（イワーク）は既存の `DamagePlusOwnCounters(10)`。

## 7. だましうち（ヤミカラス）・にらみつける（ヨーギラス・ハッサム）・かげしばり

### 7.1 だましうち（ヤミカラス）

- 要素は v0.89 の `ChooseTarget` → `TargetDamage(defender_effects=False, ignore_scope=IGNORE_HELD)`。説明が「そのポケモンの持っている「弱点・抵抗力・特殊能力・その他の効果」に
  関係なく」と書くので、除くのは選んだポケモン自身の持っている効果（弱点・抵抗力・ついているカード・持続する効果・自分の特殊能力・「とうめい」など）だけです。持ち主の場のほかの
  ポケモンの効果（［ベンチガード］）・ワザを使う側（悪エネルギーの +10）・スタジアム・プレイヤーの効果は除きません（`FeintAttackHeldTest`）。
- 「持っている」と書かない v0.89 のブラッキーの「だましうち」（`ChooseOpponentPokemonDamageIgnoringEffects`。除く範囲が決まらず FA1）とは別の型で、FA1 の判定は付けません。

### 7.2 にらみつける（ヨーギラス）

- 「おもて」なら次の相手の番だけワザを使えなくします（`PeriodAttackLock`。`active_turn` = `end_turn` = 与えた番 + 1）。「(このカード、またはこのワザを受けた相手がバトル場を
  はなれたとき、この効果は消える。)」なので、発生源のヨーギラスか受けたポケモンがバトル場をはなれた時点で消えます（`SOURCE_LEAVES_ACTIVE`）。「にげる」は止めません。

## 9. メタルニッパー（ハッサム）と、「うら」が出るまで投げるコインの先読み

- 基本となるダメージは `30 + 10 × おもての数`（1 枚目が「うら」でも 30）。要素は `Damage(OPP, HeadsUntilTails(10, fixed=30))`。v0.64 の `CoinsUntilTailsDamage`（目安が「×」で
  `per × おもての数`）とは別の型で、`per` の倍数に読み替えず、最後に最終ダメージへ足しません（p.321 の 1 段階の値）。
- 実際の対戦では「うら」が出るまで 1 枚ずつ投げます（上限なし）。先読み（`resolution.unbounded`）は「おもて」の数の有限の組の代表だけを試し、代表の値を実際のログ・乱数・履歴に
  使いません。`MAX_BRANCHES` は上げていません。
- 実際のダメージ・組を分けるキー・有限の境界は同じ式 `HeadsUntilTails.damage_for(h) = fixed + per × h` で求めます。根拠（v0.64 の 3.2 節）は基本となるダメージ b の値についての主張
  （b ≥ B で各道が一定か、P 枚ごとに同じ数だけ増える）で、固定の値はそのままでは崩しません: b(h + P) − b(h) = per × P は h によらず（周期はそのまま P）、b(h) ≥ B ⟺
  h ≥ ⌈(B − fixed) / per⌉（0 より小さければ 0）。加える前提は、固定の値が 0 以上でダメージカウンターの単位の倍数であること（満たさなければエンジンの未対応
  `UNSUPPORTED_UNBOUNDED_COIN_PREFLIGHT`）。キーを `per × h` のまま作ると、組の代表の実際のダメージとずれる（同じ組の h で結果が変わりうる）ので、そうしません
  （`MetalPincerTest.test_key_and_bound_use_the_same_formula`・`test_representatives_agree_with_enumeration`）。
- v0.13 の止める関数（`damage_profile`）は候補を並べられないので使いません（呼ばれたら `NotImplementedError`）。計算の順番の決定のあとにコインを投げ直さず、保存から再開できます。
