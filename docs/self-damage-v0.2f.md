# 自分へのワザのダメージ（v0.2f）: 原典照合と実装

ワザを使ったポケモンが、そのワザで自分自身に与えるダメージ（ピカチュウの「でんげき」の「「うら」なら、自分にも10ダメージ」など）について、原典で確かめたこと、決められなかったこと、実装、テストを対応づけた記録です。カードの照合は [pikachu-v0.2f.md](pikachu-v0.2f.md)、同時のきぜつは [simultaneous-ko-v0.2f.md](simultaneous-ko-v0.2f.md)、設計は [architecture-v0.2f.md](architecture-v0.2f.md) にあります。

- 基準のルール: 「ポケットモンスターカードゲーム公式ルール 2000.02.14版」（『ポケモンカードオフィシャルブック2000』pp.306〜326 [P43]、kyuura `NEO-2000-OFFICIAL-RULES`）
- 照合の方法: Internet Archive のスキャン [J38] の PDF からページを画像にし（200〜300dpi）、目で読んだ（2026-10-12）。OCR の文字は位置を探すのに使っただけ
- 読んだページ: p.309（ワザを使う手順 6）、p.320（ワザの説明・ワザの要素）、p.321（8 ワザによるダメージと効果、9 ワザによるダメージ計算の順番）、p.322（こんらん）、p.257（プラスパワー・ディフェンダーの解説）、p.315（弱点・抵抗力の定義）
- kyuura の参照コミットの data/rule_history.json・rule_differences.json に、2000年のルールでのワザによる自分へのダメージの記録はない（`confusion_attack` は 1997〜1998年のこんらんの記録）

分類は CONFIRMED（原典に直接の根拠がある）・SUPPORTED（確定した規則から導出できる）・UNRESOLVED（決められない）・CONFLICT（資料のあいだで矛盾）です。

## 1. 原典の記述

| ページ | 記述（画像で読んだ） |
|---|---|
| p.309 手順 6 | 「ワザの説明がある場合は、そこに書かれている順番にしたがって、その内容を処理します。」「ワザが、ダメージとそれ以外の効果の両方をもたらすときは、まず、ダメージの処理をおこない、次に「それ以外の効果」を処理してください。」「途中で処理の対象となるポケモンなどがいなくなってしまっていることがあります。処理の対象がなくなってしまっている場合、その内容は無視して、次の内容の処理をおこなってください。それ以降の内容を無視してはいけません。」 |
| p.320 ワザの説明 | 「「ダメージの目安」に「×」記号が書かれている場合をのぞいて、「ワザの説明」では、最初に書かれているべき「相手の対戦ポケモンに○○ダメージ。」という文が省略されます。」「ワザの説明の中に複数の「ワザの要素」が書かれている場合、その順番のとおりにおこなわなくてはなりません。」「それぞれの「ワザの要素」は、「ダメージ」または「効果」のどちらかに分類されます。」ダメージ:「(1) 相手の対戦ポケモンへのダメージ。(2) 相手の控えポケモンへのダメージ。(3) このワザを使うポケモンへのダメージ。(4) 自分の控えポケモンへのダメージ。」 |
| p.321「8 ワザによるダメージと効果」 | 「ワザによってもたらされたダメージは、「ワザによるダメージ」と呼ばれます。」「ワザによってもたらされた効果が、ポケモンにダメージをもたらしたときも、その効果は、おおもとになったワザによるダメージとしてあつかわれます。」「ただし、ワザによってどく状態になったポケモンがポケモンチェックで受ける「どく」のダメージは、「ワザによるダメージ」としてはあつかわれません。」 |
| p.321「9 ワザによるダメージ計算の順番」 | 1 基本となるダメージ → 2 ワザを使うポケモンの「ダメージを変更する効果」（ここまでで 0 以下なら計算を終える）→ 3「ワザを使うポケモンのタイプが、ワザを受けるポケモンの「弱点」となるタイプなら、ダメージを2倍」→ 4 抵抗力 → 5「ワザを使うポケモンについている「トレーナーカード」や「エネルギーカード」による効果（「プラスパワー」…）」→ 6 → 7「ワザを受けるポケモンについている…効果（「ディフェンダー」…）」→ 8。「ダメージを計算している途中で、その数が0やマイナスの数字になってもかまいません。」 |
| p.322 こんらん | 「「うら」が出たら、そのワザの内容がどのようなものであっても、ワザを使ったポケモン自身に、20ダメージを与えます。」「このダメージは「弱点・抵抗力」の影響を受けます。」 |
| p.257 プラスパワーの解説 | 「自分自身へもダメージを与えるワザを使うときに「プラスパワー」をつけると、そのダメージもプラス10されるので気をつけましょう。」最新の説明「このカードをつけているポケモンのワザが、対戦ポケモンにダメージを与えるとき、そのダメージは「+10」される。(控えポケモンへのダメージは、そのまま)」 |
| p.257 ディフェンダーの解説 | 「ワザを使ったポケモンもダメージを受けるようなワザを使うときに「ディフェンダー」をそのポケモンにつけておくと、そのワザで受けるダメージもマイナス20されます。」最新の説明「このカードをつけているポケモンがワザによるダメージを受けるとき、そのダメージは「-20」される。」 |
| p.125 でんげき | 最新の説明「コインを投げて「うら」なら、自分にも10ダメージ。」（太字の自分は「自分の対戦ポケモン」。p.321 の上の段） |

## 2. 裁定の分類

| # | 事項 | 分類 | 根拠 | 判断・実装 |
|---|---|---|---|---|
| 1 | 自分へのダメージは「ワザのダメージ」か | CONFIRMED | p.320 のダメージの (3)、p.321「8」 | ワザの要素の「ダメージ」で、「ワザによるダメージ」。ワザの「効果」ではない |
| 2 | 計算の順番 | SUPPORTED | p.321「9」はワザによるダメージの計算の順番 | 相手へのダメージと同じ 8 段階で計算する（`deal_attack_damage`）。ダメージを与えるのはワザを使うポケモン、受けるのはそのポケモン自身 |
| 3 | 弱点・抵抗力 | **UNRESOLVED**（関係する場合だけ） | p.321 の 3・4 段階は「ワザを使うポケモンのタイプが、ワザを受けるポケモンの弱点（抵抗力）のタイプなら」。こんらんの自分へのダメージは「弱点・抵抗力」の影響を受けると明記（p.322）。ワザの説明による自分へのダメージには書かれていない | ワザを使うポケモンのタイプが自分の弱点・抵抗力のタイプと違えば、どちらに決めても結果は同じ（計算できる）。同じなら決められないので `UnsupportedError`（`UNRESOLVED_SELF_DAMAGE_WEAKNESS_RESISTANCE`）。コインを投げる前に止める。ピカチュウ（雷・弱点 闘・抵抗力なし）では起こらない |
| 4 | プラスパワー | CONFIRMED（解説） | p.257 の解説、最新の説明（自分の対戦ポケモンも「対戦ポケモン」）、p.321 の 5 段階（ワザを使うポケモンについているカード）。v0.2c の [pluspower-v0.2c.md](pluspower-v0.2c.md) #4b は、最新の説明からの導出として SUPPORTED と分類した。解説に明記されているので、ここでは CONFIRMED（解説）とする（ディフェンダーの [defender-v0.2e.md](defender-v0.2e.md) #13 と同じ扱い） | 自分へのダメージも 5 段階で +10（複数枚ならそれぞれ）。控えへのダメージには加えない（最新の説明。控えへのダメージは未実装） |
| 5 | ディフェンダー | CONFIRMED（解説） | p.257 の解説、最新の説明、p.321「8」（自分へのダメージもワザによるダメージ）、7 段階（ワザを受けるポケモンについているカード） | ワザを使うポケモン自身についているディフェンダーは、自分へのダメージを 7 段階で −20（複数枚ならそれぞれ）。使った番から効く（同じ番のでんげきの自分へのダメージにも、次の相手の番のワザにも。p.257 の解説の「2度にわたりその効果を受ける」、[defender-v0.2e.md](defender-v0.2e.md) #13）。相手についているディフェンダーは自分へのダメージを変えない |
| 6 | 同じポケモンにプラスパワーとディフェンダー | SUPPORTED | p.321 は 5 段階を「ワザを使うポケモンについている」、7 段階を「ワザを受けるポケモンについている」で分ける | 自分へのダメージでは同じポケモンが両方の立場になる。プラスパワーは使う側（5 段階）、ディフェンダーは受ける側（7 段階）の効果で、それぞれ 1 回だけ計算する（二重に数えない） |
| 7 | 0 以下 | CONFIRMED | p.321 | 途中の 0・マイナスはそのまま。最後に 0 以下なら 0（「ダメージを受けなかった」）。2 段階までで 0 以下なら計算を終える（「でんげき」の 10 では起こらない） |
| 8 | 自分へのダメージのタイミング | CONFIRMED | p.309 手順 6、p.320 | ワザの説明に書かれている順番。でんげきは「相手に30ダメージ」（省略されている。最初）→ コイン → 自分に 10。p.309 の「まずダメージ、次に効果」は、どちらもダメージの要素なので書かれている順番どおり |
| 9 | 相手へのダメージとの順番 | CONFIRMED | p.320 | 相手へのダメージが先 |
| 10 | ワザの効果によるダメージとの区別 | CONFIRMED | p.321「8」 | 効果がもたらしたダメージもおおもとのワザによるダメージ。どくはワザによるダメージではない（特殊状態は未実装） |
| 11 | ワザの途中で相手がきぜつしたら | CONFIRMED（残りの要素）・SUPPORTED（きぜつの処理の時点） | p.309「それ以降の内容を無視してはいけません」、p.324（1 つのワザによるきぜつは同時） | 自分へのダメージの要素は処理する。きぜつの処理（トラッシュ・サイド・判定・交代）は、ワザの要素をすべて処理してからまとめて行う（でんげきでは、相手のポケモンがいなくなっても残りの要素の対象（自分）は変わらないので、途中で処理しても結果は同じ） |
| 12 | 自分がきぜつしたら | CONFIRMED | p.323 | 自分のポケモンとついているすべてのカードをトラッシュし、**相手側のプレイヤー**がサイドを 1 枚取る（ワザを使ったプレイヤーではない）。バトル場に出せなければ負け |
| 13 | ダメージ 0（ディフェンダーで防いだ） | CONFIRMED | p.321 | ダメージの記録は `amount` 0。段階の記録にマイナスが残る。きぜつしない |

## 3. 実装

| 部品 | 内容 |
|---|---|
| `effects.OPPONENT_ACTIVE`・`SELF` | ダメージを受けるポケモンの種類（p.320 のダメージの (1)・(3)）。控え（(2)・(4)）は未実装 |
| `effects.deal_attack_damage(state, use, target, base)` | ワザのダメージを 1 つ与える。発生源はいつもワザを使うポケモン。受けるポケモンは `target` で決める。変更効果は `attack_damage_modifiers(attacker, receiver)`（自分へのダメージでは同じポケモン）。p.321 の順番で計算し、ダメージカウンターをのせ、ログを残す |
| `effects.damage_opponent_active` | `deal_attack_damage(…, OPPONENT_ACTIVE, …)`（v0.2c からの関数。ログの形は同じ） |
| `effects.self_damage_problem` | 自分へのダメージに弱点・抵抗力が関係する場合の `UnsupportedError` |
| `effects.SelfDamageOnTails` | でんげきの実装（相手 → コイン → 「うら」なら自分） |

ログ: 自分へのダメージの `damage` には、`target: "self"`・`pokemon_id`（受けたポケモン）・`effect`（ワザの識別子）が加わります。相手の対戦ポケモンへのダメージの記録は v0.1 と同じ形のままです（`target` は出ない）。
