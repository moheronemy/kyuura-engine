**利用者が指定した簡略化**（交換が成立した 2 枚は、受け取ったプレイヤーが所有者になる）を採ります（3 章）。これは公式の裁定ではない記録で、エラッタ・印刷の訂正・最新の説明としても

## 3. 利用者が指定した所有者の簡略化（USER-SWAP-OWNERSHIP-RECEIVER）

利用者の指定（2026-11-01。この版の依頼）は「交換が成立した2枚は、対戦終了まで、それぞれの受取側が所有者になります。」です。kyuura には 2026-10-31 に、利用者の採用
（「とりかえっこプリーズについて簡略化仕様を採用します。」）と仕様の案が記録されています（kyuura `docs/engine-user-swap-ownership.md` 3 章。研究の記録の読み B に当たる処理）。

- 当てはめるのは、「オーケーなら、カードを交換して、それぞれの手札に加える」で交換が成立した 2 枚の、**対戦の中の所有者**だけです。2 枚それぞれの所有者を、交換と一体で受け取った
  プレイヤーにします（片方だけを変えない）。以後その対戦の終わりまで、手札・山札・トラッシュ・サイド・場に置く処理は新しい所有者を基準にします。
- オーケーでないときは所有者を変えず、説明どおり使ったプレイヤーが山札から 2 枚引きます。とりかえっこプリーズ自身の所有者は変えません（使い終わったら持ち主のトラッシュ）。
- 再交換も同じ規則です（もとの所有者へ自動では戻さない）。デッキの構築の制限（同じ名前 4 枚など）は交換のたびに当てはめ直しません。
- 元の出所（対戦開始時のデッキのプレイヤー）は追跡用に残します。uid は付け直しません。**実物の所有権を変える意味はありません**（CR-SWAP-PLEASE-REAL-TRADE-SEPARATE のまま）。次の対戦の
  所有者も変えません。
- 交換以外の処理（使うための条件・手順・交換したカードを使ってよいこと）は、印刷の文面・最新の説明と既存の裁定にしたがいます（4 章・5 章）。
- 公式の裁定ではない記録です。エラッタ・印刷の訂正・最新の説明としても記録しません。**UQ-SWAP-PLEASE-OWNERSHIP は歴史資料上は未解決のまま**で、エンジンが採る読み方が決まったことと、
  公式の裁定がわかったことは別です。
- この指定で決めていないこと: 錯乱ジムでかわりに使うときの「あなた」「相手」（UQ-CHAOS-GYM-BORROWED-TURN。6 章で止める）、ヤドキングの［ちえくらべ］との組み合わせ（未登録。確かめていない）。
- 記録: 対象ごとの記録 `effects.USER_SPECIFIED_RULES`（`UserSpecifiedRule`。対象 `PR1-027/trainer`・種類 `USER-SWAP-OWNERSHIP-RECEIVER`・印刷の文面・処理に使う文面（最新の説明）・当てはめる
  場面・規則・範囲・決めないこと・利用者の指定の文・kyuura の記録の場所・記録しない扱い・解決済みにしない論点・指定した主体 `user`・日 2026-11-01）。v0.127 の簡略ルール

## 4. 所有者・使っているプレイヤー・出所の構造

調べた今の構造: カードの表（`GameState.cards`。uid → `CardInstance(uid, card_id, owner)`）の `owner` は「そのカードを置くゾーンの持ち主」で、不変条件（`engine.check_invariants`）は
どのカードも `owner` のゾーン（山札・手札・サイド・トラッシュ・場・使用中のトレーナー・置いておく場所・スタジアム）にあることを確かめます。手札・トラッシュ・山札・場への移動は、どれも
`owner`（または移す先のプレイヤーと `owner` の一致）で行き先を決めます（`zones.py` の 46 か所・`engine.py`・`resolution/`）。対戦開始時の持ち主は、デッキの保存則（デッキリストとの
一致）だけが `owner` で数えていました。カードを使っているプレイヤーは別に持ちます（錯乱ジムで借りて使う `TrainerInUse.user`、サイキックコントロール `TrainerInUse.via`）。

v0.130 の変更（共通処理。カードの id によらない）:

- `CardInstance.origin`: 対戦開始時のデッキのプレイヤー（追跡用の出所）。所有者の変わったカードだけが持ち、None は `owner` と同じ（v0.129 までの値）。`deck_owner` は出所（なければ所有者）。
- `GameState.ownership_changes`: 所有者の変更（`OwnershipChange`。カード・カードの id・前の所有者・後の所有者・出所・番・使ったトレーナー・交換の通し番号）の並び。消さない。
- `zones.exchange_hand_cards`: 2 枚の移動・所有者の変更・出所・記録・ログ `cards_exchanged` を 1 回で行います。どちらかが手札にない・所有者が違う・同じカードなら、状態を変える前に
  `RuntimeError` です（片方だけ動いた状態を作らない）。カードの表は置きかえます（複製と共有している表を書きかえない）。
- 所有者を基準にする既存の処理は、`owner` を新しい所有者にするだけで、新しい所有者のゾーンに置きます（トラッシュ・山札・サイド・場・きぜつ・退化・手札にもどす・付属カードをまとめて
  移す）。**所有者が変わるのは交換した 2 枚だけ**で、あとから重ねた進化カード・つけたエネルギー・どうぐは、それぞれ自分の所有者（場に出したプレイヤー）のままです。
- 出所を参照すべき場面は、デッキの保存則（対戦開始時のデッキと同じカードの組か）だけでした。`deck_owner` で数えるように直しました。ほかに uid の範囲・デッキリストから持ち主を求める
  コードはありません（`decklists` を読むのは保存則と進化・退化のログの確かめだけ）。
- 不変条件 `engine._ownership_problems`: 変更は交換ごとに 2 つ（番号は 1 から順・同じ番・同じトレーナー・2 人のあいだの 1 枚ずつ）、カードごとに前の所有者が 1 つ前の値・出所が同じ、
  カードの表の所有者・出所が最後の値と同じ、変更のないカードは出所を持たない、交換のログと記録が同じ。
- 通常の対戦（所有者の変わらない対戦）の状態・ログ・書き出しは v0.129 と同じです（出所は None・記録は空。10 章の lockstep）。

## 5. カードの処理

登録は `SwapPleaseTrainer`（`effects.py`。写しの組 `pool_v0_130`）。

1. 使うための条件（CR-SWAP-PLEASE-USE-CONDITION）: このカードを除いた使ったプレイヤーの手札と、相手の手札が、どちらも 1 枚以上。満たさなければ手札から出す前に、状態・乱数・ログを変えずに
   `NO_OTHER_CARDS_IN_HAND`・`OPPONENT_HAND_EMPTY` で拒否します（どれも `IllegalActionError`。説明に書かれた使える条件なので、未解決の停止ではない）。
2. 使ったプレイヤーが相手の手札を見る（`zones.look_at_hand`。ログの `cards` は見たプレイヤーと持ち主だけ）。1 枚選ぶ（決定 `SELECT_EXCHANGE_CARD`・段階 `take`。選べるものは相手の手札の
   どのカードでも。説明は種類を限らない）。
3. 「相手プレイヤーにあなたの手札を見せ」: 相手プレイヤーが使ったプレイヤーの手札を見る（同じ `look_at_hand`。見せる相手は相手プレイヤーだけで、観戦者には見せない）。相手が 1 枚選ぶ
   （同じ決定・段階 `give`。選べるものは使ったプレイヤーの手札のどのカードでも）。
4. 相手プレイヤーにたずねる（決定 `ACCEPT_REQUEST`。v0.56 の「…かどうか、相手プレイヤーにたずねる」と同じ形。1 個: オーケー・0 個: オーケーでない）。
5. オーケーなら `zones.exchange_hand_cards`（3 章・4 章）。オーケーでないなら使ったプレイヤーが山札から 2 枚引く（効果で引く。山札が足りなければ引けるだけで、0 枚でも負けではない。p.312。
   v0.63・v0.129 のクイズと同じ規定）。
6. 使い終わったカードは持ち主のトラッシュ（既存の処理）。

- 決定の不変条件（`decision_problems`）: 段階ごとに、決めるプレイヤー・選べるもの（その時点の手札そのもの）・選ぶ数・続きの情報の項目（`use`・`stage`・`taken`・`given` だけ）・前の
  ログ（見た手札・選んだカードが説明の順）・選んだカードがまだその手札にあること。
- 不正な答え（決めるプレイヤーでない・選べるものの外・0 個・2 つ以上・オーケーの答えが 1 以外）は、状態・乱数・ログを変えずに拒否します（既存の決定の確かめ）。
- 場を変えない（`changes_field = False`。答えの続きを試す確かめをしない）。決定はすべて選べるもののどれを選んでも続けられます。

## 6. 錯乱ジム・おもての山札・ほかの経路

- **錯乱ジム（UQ-CHAOS-GYM-BORROWED-TURN）**: 「うら」で相手プレイヤーがかわりに使うと、説明の「あなた」「相手プレイヤー」（見る・選ぶ・見せて選ばせる・たずねる・2 枚引く）と「おたがいに
  手札が1枚以上」をだれから見て読むかが決まりません。所有者の簡略化はこの問いを決めないので、相手が使うことを選ぶと、状態・乱数・ログを変えずに既存の
  `UNRESOLVED_CHAOS_GYM_BORROWED_TURN`（CH1 のコード）で止めます（`SwapPleaseTrainer.borrow_problem`。選ぶと止める選択）。相手が使わないことを選べば、カードは持ち主のトラッシュです。
  「おもて」なら通常どおり使います。研究の対応表の事例（UQ-CHAOS-GYM-BORROWED-TURN の PR1-027）はこの停止コードに結び、停止コードの数は変えていません（313 のまま）。
- 交換で受け取ったトレーナーカードを錯乱ジムで使えなかった・使わなかったときの「持ち主のトラッシュ」（UQ-SWAP-PLEASE-OWNERSHIP の PMCG5-087 の事例）は、所有者の簡略化の所有者
  （受け取ったプレイヤー）のトラッシュです。研究の対応表の事例の扱いは、新しい種類 `user_specified_rule`（利用者が指定した規則で処理する。論点は解決済みにしない。
  `scripts/check_research_links.py` の `unlinked_case_problems`）にしました。UQ-SWAP-PLEASE-OWNERSHIP の PR1-027 の事例も同じです。
- ナツメのサイキックコントロール（v0.58）で相手のトラッシュのとりかえっこプリーズを使う経路は、既存の扱い（「あなたの手札にあるものとみなして」使うプレイヤーが「あなた」・使い終わったら
  持ち主のトラッシュ）のままです。この版で新しい確かめは加えていません（単体のテストもない。12 章の制限）。
- **ちえくらべ（ヤドキング neo1-049）**は登録していないので、交換で受け取ったトレーナーへのちえくらべ（UQ-SWAP-PLEASE-OWNERSHIP の neo1-049 の事例）は起こりません。この版の実装だけで
  確かめたことにしていません（事例の扱いは unregistered のまま）。
- **おもてのカードのある山札（v0.126。フラッシュ）**: オーケーでないときに使ったプレイヤーが引くと既存の止め方（`faceup.command_problem`。FU3 など）に当たるなら、使う前にそのコードで止めます
  （`face_up_draw_stop`。v0.129 のその1と同じ形。相手の答えを拒否して答えを強いない）。いちばん上だけがおもての山札なら使えます。新しい問いにしていません。

## 7. 保存・書き出し

- 書き出しの形式 33（新しい形式）: `cards` の、所有者の変わったカードに `origin` を加え、最上位に `ownership_changes` と `user_ownership_rules` を加えました。所有者の変更がある状態を形式 1〜32 で
  書くと `owner` が受け取ったプレイヤーになり、出所と変更の記録が落ちて対戦開始時のデッキと区別できないので、`ValueError` にします（黙って落とさない）。変更のない状態の形式 1〜32 の書き出しは
  v0.129 と同じです（`cards` の項目も同じ）。
- 交換への答えを待っている状態は、既存の項目（使用中のトレーナー・決定の `context`）で書けます（形式 3 以上。交換の前は所有者が変わっていない）。
- pickle・deepcopy・clone で、決定をまたいでも同じ状態になり、その先の答えも同じ結果になります。v0.129 までの状態の写し（項目のない pickle）は、変更のない状態として読めます。

## 8. 見える範囲

- 使う前と選ぶ決定のあいだ、相手・観戦者に見せるのは、使ったこと・手札を見たこと（`look_at_hand` の `cards` は見たプレイヤーと持ち主だけ）・決定の種類と決めるプレイヤーと選ぶ数だけです。
  選べるもののカードは決めるプレイヤーにだけ渡し（見た相手の手札。`LOOKED_HAND_KINDS`）、ほかの人には渡しません。
- 選んだカード（ログ `exchange_selected` の `card`・`card_id`）は、選んだプレイヤーと手札の持ち主だけに見えます（答える相手は両方の選んだカードを知っている）。
- 交換したカード・所有者の変更（ログ `cards_exchanged` の `given_card`・`taken_card`・`card_ids`・`ownership`）は、交換した 2 人だけに見えます。観戦者には、交換が成立したこと・番号・枚数だけ
  です。オーケーでないときに引いたカードは、既存のドローと同じく引いたプレイヤーだけです。
- 観測（`observe`）の手札は、今までどおり持ち主にだけカードが見えます。受け取ったカードが相手の手札に移ったあと、相手の観測には枚数だけで、そのカードの uid・id を相手の手札の中に
  示しません（相手が交換で知った事実は、自分の見たログに残るだけ）。出所（`origin`）・所有者の変更の記録は観測に出しません。
- 決定の候補・拒否の文・停止の理由に、交換と関係のない手札の中身を書きません。使ったプレイヤーの手札の交換と関係のないカードだけが違う 2 つの盤面は、観戦者の観測とログで区別できません
  （uid を除いて比べる。`tests/test_trade_please_v0_130.py`）。

## 9. 監査

- ログの監査（`tests/log_audit.py`）は、エンジンの所有者の値を読まずに組み立て直します: 対戦開始時の持ち主はデッキリストの並びの uid の付け方から求め（`initial_owners`）、交換のログの
  2 枚だけを受け取ったプレイヤーに変えます。手札の組み立て直し（`log_problems`）も交換のログで 2 枚を移し、そのあとのログの持ち主の確かめ（場に出す・トラッシュ・サイドなど）は組み立て
  直した持ち主で行います。
- `v130_problems`: 使ってからトラッシュするまでの並び（見る → 選ぶ → 見る → 選ぶ → 答え → 交換か引く → トラッシュ。錯乱ジムで使えず相手も使わなければトラッシュだけ）、選んだカードが
  見た相手の手札のもの、オーケーなら選んだ 2 枚の交換、オーケーでないなら使ったプレイヤーの 2 枚までのドロー、組み立て直した所有者と、今の状態のカードのあるゾーンの持ち主・カードの表の
  所有者・出所・変更の記録が同じこと。所有者の値・行き先（出所のプレイヤーのゾーン）・交換の記録をわざと誤らせた状態を見つけることを確かめました（`AuditTamperingTest`）。
- 観測の監査（`observation_problems`）は、新しいログの見える人を、イベントの意味から書き直した規則（`_sees_private`）で照らします。
