## 3. 参照（`UseAttack.card` とワザ番号）の照合

### 3.1 コードの読み取り

1. うらの候補のワザの値は、今は `("attack", 印刷の位置, None)` → `UseAttack(card=None)` です。化石のメタモンには印刷のワザがないので、選択肢がなく保留です（`no_printed_attack`）。
2. `UseAttack.card` は「そのワザを印刷したカードの uid」で、None なら今の姿のカードです。［へんしん］なら相手の対戦ポケモンのカードです（`commands.UseAttack` の説明）。
3. 送信のとき、エンジンは入口で番と決定を確かめ、うらの使い手をおもてにします（`_reveal_for_action`）。メタモンはたねなので場に残ります。ワザの宣言なら、そのあとすぐ C-TF2 の `freeze_revealed_form` が、公開した使い手の今の姿（`live_form`）を固定に足します。
4. そのあとの使用の確かめ（`checks.attack_request` → `find_attack_option`）は、公開のあとの今の姿でワザを探します。
   - `card=None` なら、今の姿のカードの位置（`ROUTE_FORM`）です。
   - `card=uid` なら、その uid のカードのワザです。
   - ［へんしん］がはたらいていれば、どちらも相手の対戦ポケモンのいちばん上のカードの、同じ位置のワザを指します。
5. おもての化石のメタモンの候補（`_attack_candidate`）は、段 1 の `card` に `available_attacks` の `card`、つまり写す相手のいちばん上のカードの uid を入れます。保存済みの実応答では、`tf1_copy_x` が `card 19`（相手のアンノーンX）・`card_id neo4-065`・`route form`、`tf1_copy_lanturn` が `card 21`・`neo1-040` です。

### 3.2 保存済みの直接のコマンド（PT2）

盤面は、うらの化石のメタモン（バトル場）と、相手のおもてのバトル場（ランターン 1 ワザ・ラプラス 2 ワザ・R団のミュウツー 3 ワザ）です。

| 比べたもの | 結果 |
|---|---|
| `card=None` と `card=写す相手のいちばん上の uid`（同じ番号。うら 9 組・おもて 3 組） | 12 組すべてで、受理・拒否、相手へのダメージ、公開のあとの姿、固定、乱数、盤面、出来事（相手の観測を含む）、診断が一致 |
| 受理したうらの組 | 公開のあとの姿は写す相手の `card_id`（`neo1-040`・`PMCG3-022`・`PMCG6-055`）。ワザの本体の時点の固定に `transform` の姿が入り、処理のあとは空 |
| メタモン自身の uid・相手のベンチのカードの uid | `INVALID_ATTACK`（3 盤面とも） |
| 写す相手のワザの数を超える番号 | `INVALID_ATTACK`（ランターン・ラプラス） |
| エネルギーが足りないワザ（R団のミュウツーの 3 つめ） | `INSUFFICIENT_ENERGY`（`card=None`・`card=uid` とも） |

- 記録を取ったコードと `7ee1501` のパッケージの差は、版の文字列だけです（1 章）。
- これで、示す値 `("attack", 写す相手のワザの位置, 写す相手のいちばん上の uid)` が、直接のコマンドで同じワザを指すことを確かめたとします。取り違えた uid・番号は、別の定義のワザを指さずに拒否されます。

## 4. 示す条件と保留

### 4.1 公開の前に使える情報

| 情報 | 分類 | 使い道 |
|---|---|---|
| 本当のカードの印刷の定義（化石のメタモン `PMCG3-042`。特殊能力は［へんしん］だけ・たね・ベイビィでない・ワザなし） | 本人の知識（観測の `real`。本人の応答にだけ出る） | 対象かどうか（T1。拡張シートのメタモンは T2） |
| 相手のバトル場がいるか・おもてか | 公開 | O1・O2 |
| 相手のおもてのバトル場のいちばん上のカードの uid・`card_id`・印刷のワザ・特殊能力 | 公開（観測の場のポケモンの `card`・`card_id`・`attacks`） | 段 1 の選択肢・写す相手の適格性 |
| 写す相手がばけている・ポケモンとして出したトレーナー・進化元なし | 公開 | O3（TF2・TF3） |
| 場の抑止（かがくへんかガス・まきちらせ!ベトベトガス・ワザの効果の抑止・ふしぎなガス・［いあつ］） | 公開 | O4・O5 |
| うらの使い手のダメージ・特殊状態・持続する効果・重なり | うらのあいだはない（`zones.reveal_face_down` の不変条件） | 確かめるだけ（あれば保留） |
| 相手のうらのカード・手札・山札・サイド | 相手の非公開情報 | 使わない |

うらのあいだは、`card_def` が中立の定義（`FACE_DOWN_DEFINITION`）を返すので、`transform_works`・`current_form`・`copied_form_problems` は公開のあとの姿を返しません（前の設計の 3.6 節）。
公開の前に姿を求めるには、本当のカードの登録から［へんしん］を読み、写す相手を引数に取る判定が要ります。**実装では、その判定をエンジンの `copied_form_problems` と同じ関数で行う**ように分けます（判定を写して二重に持たない。受け入れ条件 AC-T1-6）。

### 4.3 保留のときの形

当たらない条件があれば、今と同じ形のままです（`not_implemented`・reasons `face_down_reveal_not_evaluated`・`no_printed_attack`・`stages: []`。check は `CANDIDATE_NOT_EXECUTABLE`）。
理由を細かく分ける reason は足しません（相手・観戦者には候補が出ず、本人にも、どの条件で保留したかを示す必要はない）。

## 5. 示すときの候補の形

| 項目 | 値 |
|---|---|
| 段 1 の選択肢 | 写す相手のいちばん上のカードの印刷のワザを、印刷の順に。`id`（`o1`〜）・`card`（写す相手のいちばん上の uid）・`card_id`（写す相手のカード ID）・`attack_index`・`name_ja`・`cost`・`damage`・`text_ja`（写す相手の印刷）・`face_down: true` |
| 値 | `("attack", 写す相手のワザの位置, 写す相手のいちばん上の uid)` → `UseAttack(actor, attack_index, card=uid)` |
| 処理可能性 | 選択肢・候補とも `unverified`、reasons `face_down_reveal_not_evaluated`（今のうらの候補と同じ） |
| 段 2 | 空（`count {0,0}`・`options: []`・`options_by_choice` はワザごとに空。今の「示さない」ときと同じ形と注記） |
| 契約の表の語彙 | 新しい項目・reason・処理可能性の値は足さない（GUI の `attack_option_keys`・`reason_codes` の範囲のまま）。`route` はうらの選択肢に今どおり付けない |

- `card` を None にしない理由: 3.2 節のとおり結果はどちらでも一致します。uid を入れると、示した公開のカードと送るコマンドが同じカードを指し、おもてのメタモンの候補（3.1 節の 5）と同じ値になります（D-T1-2）。
- **`card_id` の意味が変わります。** 今のうらの選択肢の `card_id` は「本人が知る本当のカード」ですが、この選択肢では「写す相手のカード（公開）」です。本人の本当のカード（メタモン）は、今どおり観測の `real` にだけあります。GUI の契約の文書と表示は、この意味に追従が要ります（D-T1-5）。

## 6. check と submit

- **check:** 今のうらの候補と同じく、形と組（ワザの番号が 1 つで、段 2 に何も選ばない）だけを確かめます。公開・エンジンの確かめ・状態の複製の上の試行は呼びません。示していない番号は、U7-4 の 4.1 節の番号と組の段で `CANDIDATE_INPUT_INVALID` です。check が valid でも、受理は保証しません。
- **submit（参照が合わないときを含む）:** 入力 API は示した値から `UseAttack(card=uid)` を作り、エンジンのコマンドの入口に渡します。
  - 候補を作ったあとに状態が変わっていれば、取っ手は `CANDIDATES_STALE` で、候補の取り直しを求めます（既存の扱い。受理のたびに取っ手はすべて失効する）。
  - エンジンが公開のあとに、その uid・番号のワザを見つけなければ `INVALID_ATTACK` で拒否します（3.2 節）。エネルギーが足りなければ `INSUFFICIENT_ENERGY`、ワザを使えない効果・未裁定の停止（FD1・TF1 の残る部分・RX1・TE1 など）も、エンジンの既存のコード・区分のままです。
  - 拒否は公開をふくめて元にもどし、状態・乱数・ログ・決定を変えません（C-TF0 の 9.1 節: 拒否 26 件すべて不変）。拒否の診断は送った本人にだけ出ます（既存）。
- 受理のあとの効果・決定（入れ替え・コイン・TE1 で止まる数え方など）は評価しません（`after_acceptance` は今どおり）。

## 8. 情報境界

- 候補は本人の応答にだけ出ます。相手・観戦者の応答・観測・更新は、本人の本当のカードによりません（今のうらの分岐と同じ）。
- 選択肢の有無・数・順は、本人の本当のカード（本人の知識）と、相手のおもてのバトル場・場の抑止（公開）だけで決まります。相手のバトル場がうらなら、正体によらず保留です。
- 候補の作成と check は、状態・乱数・ログを変えません。
