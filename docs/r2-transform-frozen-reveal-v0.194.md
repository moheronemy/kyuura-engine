## 1. 何を直したか

CR-TRANSFORM-FROZEN-DURING-ACTION（CONFIRMED）は、ワザが終わるまでメタモンは「使い始めたときの姿のまま」です。0.193.0 までの固定は 2 か所でした。

- コマンドの入口の固定（`engine._apply_once` の `freeze_forms`）は、うらの使い手を公開する前です。うらのカードは変身の特殊能力を持たないので、使い手は入りません。
- ワザの始めの固定（`flow._use_attack` の `body` の `freeze_forms`）は、固定が空のときだけ動きます。

そのため、場（どちらの側でも）にほかの変身できるポケモンがいると、公開したメタモンの姿は固定されませんでした。ワザの途中の入れ替えで姿が変わるので、RX1（`UNRESOLVED_REACTIVE_SWITCH_TRANSFORMED_ATTACKER`）で止まっていました（SF3）。

| 盤面（構築盤面。new_game からの到達ではない） | 0.193.0 | 0.194.0 | おもての対照 |
|---|---|---|---|
| うらのメタモン＋自分のベンチのメタモン、ロコンのきつねびでフシギダネ／ゼニガメへ入れ替え | RX1 で拒否（決定の `unresolved_choices` に 2 匹） | 受理、20／10 | 20／10 |
| うらのメタモン、相手の控えにメタモン（フシギダネ／メタモンへ入れ替え） | RX1 で拒否 | 受理、20／10 | 20／10（修正前に実測） |
| 両方の側にメタモン | フシギダネへの入れ替えは RX1 | 受理、20。固定の並びは対照と同じ | 20 |
| うらのメタモン＋ベンチのメタモン、サイドンのげきとつ（入れ替えのあと自分にも 20。控え 1 匹） | ワザの宣言ごと RX1 で拒否 | 受理、50 → 入れ替え → 自分に 20 | 同じ |
| 入れ替えない答え・ほかがいない盤面・最初からおもて | 受理、10 など | 変わらない | — |

## 2. 変えたところ

- `effects.freeze_revealed_form(state, pokemon)`（新）: 既に固定している・ばけている・変身する特殊能力を持たないポケモンなら何もしません。そうでなければ `live_form` の今の姿を 1 項目として加えます。
  - 既存の項目は値も対応も変えません。並びは `freeze_forms` と同じ（プレイヤー → `in_play()`）で、安定な並べかえで差しこみます（場にいない項目があっても落としません）。
  - ログ・乱数を変えません。内部の例外（不変条件の確かめ）は加えていません（停止の台帳の内部の確かめの数を変えない）。
- `engine._reveal_for_action`: うらの使い手を公開して「たねポケモン」で残り、コマンドが `UseAttack` のときだけ呼びます。
  - 時点は公開の直後で、handler（ワザの使用の確かめ・先読み・コスト・コイン・効果）の前です。
  - 「たねポケモン」でなければ（L1・D1）今のとおりトラッシュして受理し、固定を足しません。
  - 宣言する特殊能力・進化・にげるの公開は対象外です（SF3-P は別の単位）。

**先読み・決定・拒否との関係:**

- 通常の先読みの複製の元（v0.189 の `base = state.clone()`）と、上限を超えたときの確かめ（`on_limit` の `v013_checks.check(base, …)`）は、同じ handler の入口の状態から作るので、足した項目を含みます。ワザの始めの `freeze_forms` は固定が空でないので何もしません。
- 決定待ちの状態は、足した項目を既存の形式のまま保存します（snapshot の往復で同じ）。再開では作り直しません。解除は既存の位置（ワザの終わり・決定のないコマンドの終わり）です。
- 拒否は複製ごと捨てるので、公開と固定の追加は元の状態に残りません（状態・乱数・ログ・決定は不変）。
