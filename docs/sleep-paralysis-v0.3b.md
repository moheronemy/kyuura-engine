# ねむり・マヒ（v0.3b）: 原典照合と実装

ねむり状態・マヒ状態について、原典で確かめたこと、決められなかったこと、実装、テストを対応づけた記録です。ポケモンチェックの 3（ねむり）・4（マヒ）と、2（どく）のきぜつとの順番は [pokemon-check-v0.3b.md](pokemon-check-v0.3b.md)、カード（キャタピー・パラス）は [cards-v0.3b.md](cards-v0.3b.md)、設計は [architecture-v0.3b.md](architecture-v0.3b.md) にあります。特殊状態の共通基盤とどくは [special-conditions-v0.3a.md](special-conditions-v0.3a.md) です。

- 基準のルール: 「ポケットモンスターカードゲーム公式ルール 2000.02.14版」（『ポケモンカードオフィシャルブック2000』pp.306〜326 [P43]、kyuura `NEO-2000-OFFICIAL-RULES`）
- 照合の方法: スキャン [J38] のページ画像を目で読んだ（2026-10-12。p.309・p.322・p.323 は 220〜300dpi）。OCR の文字はページの位置を探すのに使っただけ。読んだページは p.309、p.311、p.313、p.320、p.322、p.323、p.325 と、カードのページ p.17・p.38
- 現代のルール・第4版の冊子・後年の裁定では補っていない。kyuura の研究記録（`sleep`・`paralysis`・`pokemon_check_order`。参照コミット `ecb2d69`）は照合の手がかりにだけ使い、2000.02.14版の行が原典と同じであることを確かめた（6 章）

## 3. 原典で決められない事項（UNRESOLVED）

### 3.1 マヒの再付与で回復する番が変わる場合（P10）

p.322 は「二重のマヒ状態になるわけではありません」とだけ書き、回復する番（「マヒ状態になった番」の次の自分の番）を、最初にマヒ状態になった番で数えるのか、あとで効果を受けた番で数えるのかを書いていません。

- 回復する番が同じになる場合は、どちらで数えても結果は同じなので処理します（状態を変えず、ログに `already`）。相手の番に、相手の効果で再びマヒを受ける場合はいつもこれにあたります（どちらの番から数えても、持ち主の次の番は同じ）。
- 違う場合は `UnsupportedError("UNRESOLVED_REPARALYSIS_RECOVERY_TURN")` にします。例: 2 番（相手の番）にマヒ状態になり 3 番（持ち主の番）の終わりに回復するポケモンが、3 番に持ち主の側の効果でマヒを受けると、あとの番で数えれば 5 番になります。
- v0.3b の対応カードでは起こりません: マヒにするワザ（いとをはく）は相手の対戦ポケモンにだけ効き、マヒ状態のポケモンは持ち主の次の番の終わりに回復するので、相手の番にマヒ状態のままでいることがありません（その番より前にマヒを受けたポケモンは回復している）。不変条件（期限の過ぎたマヒは残らない）がこれを確かめます。
- コインを投げる効果（`ParalyzeOnHeads`）は、コインの前に `paralysis_problem` で確かめます。

### 3.2 両方の対戦ポケモンがねむり状態のときのコインの順番

[pokemon-check-v0.3b.md](pokemon-check-v0.3b.md) 4 章。コインを投げる前に止めます（`UNRESOLVED_POKEMON_CHECK_SLEEP_COIN_ORDER`）。

## 4. ダメージを与えないワザ

パラスの「キノコのほうし」はダメージの目安の数字がなく（データの `damage` は None）、p.38 の解説は「ダメージを与えることはできません」です。次のように区別します。

| 種類 | 例 | 実装 |
|---|---|---|
| ダメージの要素がないワザ | キノコのほうし | `PutToSleep`: ダメージの計算（p.321）をせず、`damage` のログもない。プラスパワー（「ワザが、対戦ポケモンにダメージを与えるとき」p.257）・弱点・抵抗力は関係しない |
| ダメージが 0 になったワザ | みだれづきで「おもて」が 0 枚（v0.2d）、ディフェンダーで 0 | ダメージの計算をし、`damage`（`amount: 0`）を残す（「ダメージを与えなかった」。p.321） |
| ワザの失敗 | 対応カードにない | p.323（失敗しても使ったことになる）。v0.3b でも未実装 |
| 追加効果だけを処理する | キノコのほうし（説明の「効果」だけ） | ワザの説明にしたがって効果だけを処理する（p.309 の手順 6） |

`DamageOnly` に 0 を渡す登録はしません（`DamageOnly.check` が拒否する）。説明文のあるワザを `DamageOnly` に登録することもできません。

## 9. 負荷テスト

正しい操作（`status_policy_command`）とでたらめな操作を混ぜる検査を、5 組のデッキ（キャタピー・パラス・ビードルのデッキどうし、ビードル・ピカチュウ・ディフェンダーのデッキとの組）× 400 seed（約 13 万コマンド）で行いました（作業用の検査。リポジトリには縮小版 `RandomCommandsWithStatusDecksTest` を固定 seed で入れた）。不変条件の違反・カードの消失や重複・状態の不正な重複・ポケモンチェックの二重実行・乱数の余計な消費（対戦準備のあとはコインだけ）・期限の過ぎたマヒ・拒否された操作による状態や乱数の変化・予期しない例外は 0 件でした。止まった対戦は原典の未解決（`UNRESOLVED_POKEMON_CHECK_DOUBLE_KNOCKOUT`）だけで、エンジンの破綻と分けて数えています。
