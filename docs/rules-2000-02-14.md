## 4. ダメージ・きぜつ・勝ち負け

### ダメージ計算の順番（p.321）

`damage.calculate_attack_damage` が、次の順に計算します。

1. 基本となるダメージ（ワザの説明にしたがって計算する。v0.1 のワザは説明がないので、目安の数字そのもの）
2. ワザを使うポケモンの「ダメージを変更する効果」（v0.1 の対応カードにはない）。ここまでで 0 以下なら計算を終え、「ダメージを与えなかった」
3. ワザを使うポケモンのタイプが、ワザを受けるポケモンの弱点のタイプなら 2 倍
4. ワザを使うポケモンのタイプが、ワザを受けるポケモンの抵抗力のタイプなら、抵抗力の数字をマイナス
5. ワザを使うポケモンについているトレーナーカード・エネルギーカードの効果（v0.1 にはない）
6. 場にはたらいている効果（v0.1 にはない）
7. ワザを受けるポケモンについているトレーナーカード・エネルギーカードの効果（v0.1 にはない）
8. ワザを受けるポケモンの「ダメージを変更する効果」（v0.1 にはない）

最終的に 0 以下なら「ダメージを受けなかった」（0 ダメージ）。計算の途中で 0 以下になってもよい（p.319「ダメージ」）。

| 規定 | 根拠 | kyuura | テスト |
|---|---|---|---|
| 弱点のタイプのポケモンからダメージを受けるとき 2 倍 | p.315、p.321 | weakness_resistance | test_combat.py `test_weakness_doubles` |
| 抵抗力のタイプのポケモンからダメージを受けるとき、抵抗力の大きさ分マイナス | p.315、p.321 | weakness_resistance | test_combat.py `test_resistance_subtracts_and_floors_at_zero` |
| 弱点を先、抵抗力を後に計算する | p.321 | weakness_resistance、NEO-2000-PLAYRULE | test_combat.py `test_weakness_is_calculated_before_resistance` |
| ダメージは蓄積する（ダメージカウンター） | p.319 | — | test_combat.py `test_damage_accumulates` |

### ポケモンチェック（p.323）

番と番のあいだに、どちらの番でもないものとして行います。順番は「指示されたこと → どく → ねむり → マヒ」で、きぜつの判定は含みません。v0.1 の対応カードには特殊状態にする効果も「ポケモンチェックで〜する」効果もないので、`_pokemon_check` はログに記録するだけで何もしません。特殊状態を加えるときに、ここへ順番どおりに処理を加えます。

## 5. 実装上の決め事（史料の規定ではないもの）

公式ルールには書かれていない、コンピューターで動かすための決め事です。ルールの内容を変えるものではありません。

| 決め事 | 理由 |
|---|---|
| カード 1 枚ごとに対戦内の番号（uid）を付け、コマンドは uid でカード・ポケモンを指定する | 同じカードが複数あるため |
| 「デッキを切る」は、seed から作った乱数での並べ替え 1 回で表す。切り直しのときも同じ | 結果を再現できるようにするため（同じデッキ・seed・操作列なら同じ結果） |
| ジャンケンの結果は外から受け取る（`ReportJankenResult`）。エンジンは乱数で決めない | ジャンケンはカードの外の出来事なので |
| 対戦準備でポケモンを出す順番（どちらのプレイヤーが先にコマンドを送るか）は問わない | ルールでは同時に裏にして出す |
| 切り直しの補償は、切り直し 1 回ぶんごとに 0〜2 枚を選ぶ（`DrawMulliganCards` を回数ぶん送る） | 文面は「切り直しになったら…最大2枚」「このときも…最大2枚」。合計で 0〜2×回数 枚引けるのと同じ |
| 切り直しの補償で引くのは、サイドをセットした後、ジャンケンの前 | 文面は「サイドカードをセットする」の後とする。ジャンケンとの前後は書かれていないが、見出しの順（サイド → 先攻後攻）に合わせた |
| サイドは「位置」で選ぶ（`TakePrize.index`） | 表を見ないで 1 枚を選ぶため |
| 裏向き・表向き、相手に見せる・見せないといった情報の区別は持たない | v0.1 は画面や通信がなく、隠れた情報の管理をしていない（`state_to_dict` はすべてを含む） |
| 両方が同時にサイドを取るとき、どちらが先に取ってもよい | 同じタイミングのことがらの順番は番のプレイヤーが決める（p.325）が、サイドはプレイヤーごとに別なので結果は変わらない。v0.1 では起こらない |
