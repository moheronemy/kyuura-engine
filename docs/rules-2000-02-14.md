# ルールの仕様: 公式ルール 2000.02.14版（v0.1〜v0.2c で実装した範囲）

kyuura-engine v0.1〜v0.2c が実装した処理を、公式ルールの項目ごとに説明します。トレーナーカードのカードごとの裁定は [trainers-v0.2b.md](trainers-v0.2b.md)（マサキ・きずぐすり・ポケモンいれかえ）と [pluspower-v0.2c.md](pluspower-v0.2c.md)（プラスパワー）にあります。各項目に、根拠（誌面のページ）、kyuura の記録 id、実装の場所、テストを対応させています。

ルールとは別に、`new_game`・`apply_command` は、返す状態がカードの保存則（すべてのカードがどこか 1 か所にだけある）と場の形を満たすことを毎回確かめます（`check_invariants`。満たさなければ `StateIntegrityError`）。v0.1 のレビューの記録は [review-v0.1.md](review-v0.1.md) にあります。

## 4. ダメージ・きぜつ・勝ち負け

### ダメージ計算の順番（p.321）

`damage.calculate_attack_damage` が、次の順に計算します。

1. 基本となるダメージ（ワザの説明にしたがって計算する。v0.1 のワザは説明がないので、目安の数字そのもの）
2. ワザを使うポケモンの「ダメージを変更する効果」（v0.1 の対応カードにはない）。ここまでで 0 以下なら計算を終え、「ダメージを与えなかった」
3. ワザを使うポケモンのタイプが、ワザを受けるポケモンの弱点のタイプなら 2 倍
4. ワザを使うポケモンのタイプが、ワザを受けるポケモンの抵抗力のタイプなら、抵抗力の数字をマイナス
5. ワザを使うポケモンについているトレーナーカード・エネルギーカードの効果（v0.2c: プラスパワーの +10）
6. 場にはたらいている効果（対応カードにはない）
7. ワザを受けるポケモンについているトレーナーカード・エネルギーカードの効果（対応カードにはない。集める処理はある）
8. ワザを受けるポケモンの「ダメージを変更する効果」（対応カードにはない）

最終的に 0 以下なら「ダメージを受けなかった」（0 ダメージ）。計算の途中で 0 以下になってもよい（p.319「ダメージ」、p.321「ダメージを計算している途中で、その数が0やマイナスの数字になってもかまいません」）。2・5〜8 段階の効果は `DamageModifier`（加算）で渡す（v0.2c）。同じ段階に複数の効果があるときの順番は、2・5・6 段階はワザを使うプレイヤー、7・8 段階は受けるプレイヤーが決める（p.321）が、加算どうしは順番で結果が変わらないので、選ぶ決定はまだない。

### ポケモンチェック（p.323）

番と番のあいだに、どちらの番でもないものとして行います。順番は「指示されたこと → どく → ねむり → マヒ」で、きぜつの判定は含みません。v0.1 の対応カードには特殊状態にする効果も「ポケモンチェックで〜する」効果もないので、`_pokemon_check` はログに記録するだけで何もしません。特殊状態を加えるときに、ここへ順番どおりに処理を加えます。

## 5. 実装上の決め事（史料の規定ではないもの）

公式ルールには書かれていない、コンピューターで動かすための決め事です。ルールの内容を変えるものではありません。

| 決め事 | 理由 |
|---|---|
| カード 1 枚ごとに対戦内の番号（uid）を付け、コマンドは uid でカード・ポケモンを指定する | 同じカードが複数あるため |
| 「デッキを切る」は、seed（0 以上の整数）から作った乱数での並べ替え 1 回で表す。切り直しのときも同じ | 結果を再現できるようにするため（同じデッキ・seed・操作列なら同じ結果） |
| ジャンケンの結果は外から受け取る（`ReportJankenResult`）。エンジンは乱数で決めない | ジャンケンはカードの外の出来事なので |
| 対戦準備でポケモンを出す順番（どちらのプレイヤーが先にコマンドを送るか）は問わない | ルールでは同時に裏にして出す |
| 切り直しの補償は、切り直し 1 回ぶんごとに 0〜2 枚を選ぶ（`DrawMulliganCards` を回数ぶん送る） | 文面は「切り直しになったら…最大2枚」「このときも…最大2枚」。合計で 0〜2×回数 枚引けるのと同じ |
| 切り直しの補償で引くのは、サイドをセットした後、ジャンケンの前 | 文面は「サイドカードをセットする」の後とする。ジャンケンとの前後は書かれていないが、見出しの順（サイド → 先攻後攻）に合わせた |
| サイドは「位置」で選ぶ（`TakePrize.index`） | 表を見ないで 1 枚を選ぶため |
| きぜつのあとは、サイドを取ってから、勝ち負けを判定し、それからバトル場にポケモンを出す | p.323 の記述の順（サイドを取る → 取り終えたら勝ち → 代わりを出す）。p.313 の「すぐに代わりのポケモンを出さなくてはいけません」とも両立する。v0.1 では、どちらの順でも勝ち負けは変わらない |
| 取るサイドの枚数が残りより多いときは、残りだけを取る | v0.1 では起こらない（サイドを取り終えた時点で勝ち負けが決まる） |
| 裏向き・表向き、相手に見せる・見せないといった情報の区別は持たない | v0.1 は画面や通信がなく、隠れた情報の管理をしていない（`state_to_dict` はすべてを含む） |
| 両方が同時にサイドを取るときは、番のプレイヤーから順に取る（v0.2a。v0.1 ではどちらからでもよかった）。**確定したルールではない** | サイドを取る順番の明文はない。p.325「23 同じタイミングで起こったことの順番」（特に指示がないかぎり番のプレイヤーが順番を決める）に当たると読めるが、その選択は未実装。サイドはプレイヤーごとに別で、勝ち負けは取り終えてから判定するので結果は変わらない。対応カード（v0.2b を含む）では起こらない（[trainers-v0.2b.md 6 章](trainers-v0.2b.md)） |
| 使用中のトレーナーカードは、決定を待つ間 `GameState.trainer_in_use` に置き、説明にしたがい終わったらトラッシュする（v0.2b） | p.310 は「使った」カードをトラッシュするとだけ書く。3 枚では、トラッシュの時点で結果は変わらない |
| マサキで引いたカードは、山札の上から順に手札の後ろに加える（v0.2b） | 手札の並びにルール上の意味はない（番の最初のドローと同じ） |
| きずぐすり・ポケモンいれかえの対象は、場のポケモンの番号で選ぶ。対象が 1 匹でも決定を出す（v0.2b） | 選ぶ手順を省かない。カードの uid は進化で変わりうるため |
| ポケモンいれかえで、もとのバトル場のポケモンは、選んだ控えがいたベンチの位置に入る（v0.2b） | ベンチの並びにルール上の意味はない（にげると同じ） |
| 原典で扱いを決められない選択は、決定の選べるものに入れたうえで、選ぶと `UnsupportedError` にする（v0.2b。`unresolved_choices`） | 「ルールで不正」（`IllegalActionError`）と「原典で決められない」を区別するため |
| 番の終わりのトラッシュ（プラスパワーなど）は、ログ `turn_end` の前に行う。番のプレイヤーの場（バトル場 → ベンチ）、相手の場の順（v0.2c） | 番の終わりはポケモンチェックの前（p.309・p.323）。トラッシュに順番はない（p.312） |
| 勝敗が決まった番は、番の終わりの処理をしない（ついているプラスパワーはそのまま残る）（v0.2c） | 対戦はその時点で終わる（p.311・p.323）。番の終わりが来ない |
| 複数のプラスパワーは、ついた順に 5 段階で加える（v0.2c） | 順番はワザを使うプレイヤーが決める（p.321）が、加算なので結果は変わらない |

### kyuura の記録との違い（報告事項）

- kyuura の docs/engine-readiness.md 4章は、ダメージ計算で同じ段階に複数の効果があるときの順番を「ワザを使うプレイヤーが決める」とまとめています。誌面（p.321〜322）を画像で読むと、2・5・6 段階は「ワザを使うプレイヤー」、7・8 段階は「ワザを受けるプレイヤー」です。kyuura 側で確かめてください（このリポジトリからは kyuura を変更していません）。
- カードの照合の食い違い（ポニータのワザ名、v0.2b のきずぐすり・ポケモンいれかえの文面）は [カードデータの由来](data-provenance.md) と [trainers-v0.2b.md 7 章](trainers-v0.2b.md) にあります。
