## 4. ダメージ・きぜつ・勝ち負け

### ダメージ計算の順番（p.321）

`damage.calculate_attack_damage` が、次の順に計算します。

1. 基本となるダメージ（ワザの説明にしたがって計算する。v0.1 のワザは説明がないので、目安の数字そのもの。v0.2d のみだれづきは「おもて」の数 × 10。v0.2f のでんげきは相手へ 30、「うら」のときの自分へ 10）
2. ワザを使うポケモンの「ダメージを変更する効果」（v0.27: ストライクの「つるぎのまい」の効果で、そのストライクの「きりさく」のダメージを「60」にする。p.321 の 2 段階の例と図「ワザを使うポケモンの持続する状態の効果」。v0.35: マチスのコラッタ・ラッタの「きあいだめ」の効果で、そのワザのダメージを 2 倍にする（「数をかける」効果）。v0.34: カラカラの「なきつく」を受けたポケモンがカラカラに与えるダメージを −20）。ここまでで 0 以下なら計算を終え、「ダメージを与えなかった」。2 段階に効果が重なれば計算の順番はワザを使うプレイヤーが決める（p.321）。v0.35 から、順番によって結果が変わるときだけ、ワザを使うプレイヤーに順番を選ぶ決定（`damage_step_order`）を出す（[coin-groups-damage-order-v0.35.md](coin-groups-damage-order-v0.35.md) 3 章）
3. ワザを使うポケモンのタイプが、ワザを受けるポケモンの弱点のタイプなら 2 倍
4. ワザを使うポケモンのタイプが、ワザを受けるポケモンの抵抗力のタイプなら、抵抗力の数字をマイナス
5. ワザを使うポケモンについているトレーナーカード・エネルギーカードの効果（v0.2c: プラスパワーの +10）
6. 場にはたらいている効果（対応カードにはない）
7. ワザを受けるポケモンについているトレーナーカード・エネルギーカードの効果（v0.2e: ディフェンダーの −20）
8. ワザを受けるポケモンの「ダメージを変更する効果」（対応カードにはない）

最終的に 0 以下なら「ダメージを受けなかった」（0 ダメージ）。計算の途中で 0 以下になってもよい（p.319「ダメージ」、p.321「ダメージを計算している途中で、その数が0やマイナスの数字になってもかまいません」）。2・5〜8 段階の効果は `DamageModifier`（加算。v0.27 から「その数にする」、v0.35 から「数をかける」）で渡す（v0.2c）。同じ段階に複数の効果があるときの順番は、2・5・6 段階はワザを使うプレイヤー、7・8 段階は受けるプレイヤーが決める（p.321）。加算どうしなど、順番で結果（最終ダメージと 2 段階で終えるか）が変わらないときは選ばせない。変わるときは、v0.35 から、そのプレイヤーに順番を選ぶ決定を出す（決定を出せない処理では `UNSUPPORTED_DAMAGE_STEP_ORDER` で止める）。

「ダメージを受けない」状態（v0.4b。「かたまる」の効果）は、この 8 段階のどこかで数を変える効果ではない。p.321 のとおり、その状態のポケモンにダメージを与えるワザの要素は無効なので、計算そのものをしない（`DamageModifier` は使わない。[persistent-damage-v0.4b.md](persistent-damage-v0.4b.md)）。

## 5. 実装上の決め事（史料の規定ではないもの）

公式ルールには書かれていない、コンピューターで動かすための決め事です。ルールの内容を変えるものではありません。

| 決め事 | 理由 |
|---|---|
| カード 1 枚ごとに対戦内の番号（uid）を付け、コマンドは uid でカード・ポケモンを指定する | 同じカードが複数あるため |
| 「デッキを切る」は、seed（0 以上の整数）から作った乱数での並べ替え 1 回で表す。切り直しのときも同じ | 結果を再現できるようにするため（同じデッキ・seed・操作列なら同じ結果） |
| ジャンケンの結果は外から受け取る（`ReportJankenResult`）。エンジンは乱数で決めない | ジャンケンはカードの外の出来事なので |
| 対戦準備でポケモンを出す順番（どちらのプレイヤーが先にコマンドを送るか）は問わない | ルールでは同時に裏にして出す |
| 切り直しの補償は、切り直し 1 回ぶんごとに 0〜2 枚を選ぶ（`DrawMulliganCards` を回数ぶん送る） | 文面は「切り直しになったら…最大2枚」「このときも…最大2枚」。合計で 0〜2×回数 枚引けるのと同じ |
| 切り直しの補償で引くのは、サイドをセットした後、ジャンケンの前 | 文面は「サイドカードをセットする」の後とする。ジャンケンとの前後は書かれていないが、見出しの順（サイド → 先攻後攻）に合わせた |
| サイドは「位置」で選ぶ（`TakePrize.index`） | 表を見ないで 1 枚を選ぶため |
| きぜつのあとは、サイドを取ってから、勝ち負けを判定し、それからバトル場にポケモンを出す | p.323 の記述の順（サイドを取る → 取り終えたら勝ち → 代わりを出す）。p.313 の「すぐに代わりのポケモンを出さなくてはいけません」とも両立する。v0.1 では、どちらの順でも勝ち負けは変わらない |
| 取るサイドの枚数が残りより多いときは、残りだけを取る | v0.1 では起こらない（サイドを取り終えた時点で勝ち負けが決まる） |
| 裏向き・表向き、相手に見せる・見せないといった情報の区別は持たない | v0.1 は画面や通信がなく、隠れた情報の管理をしていない（`state_to_dict` はすべてを含む） |
| 両方が同時にサイドを取るときは、番のプレイヤーから順に取る（v0.2a。v0.2f で実際に起こるようになった）。**「番のプレイヤーが先に取る」というルールではなく、選択の正規化** | サイドを取る順番の明文はない。p.325「23」（特に指示がないかぎり番のプレイヤーが順番を決める）に当たる（SUPPORTED）が、その選択は出さない。サイドは自分のサイドから表を見ないで選び、取ったカードを相手に見せる必要はなく（p.312）、勝ち負けはすべて取ってから判定するので、どちらの順でも選べるもの・情報・結果は変わらない（v0.2f で確かめた。[simultaneous-ko-v0.2f.md 5 章](simultaneous-ko-v0.2f.md)、test_simultaneous_ko.py `PrizeOrderTest`）。サイドに関わるカードを加えるときは見直す |
| ワザの要素（相手へのダメージ・コイン・自分へのダメージ）をすべて処理してから、きぜつを判定し、トラッシュ・サイド・判定・交代をまとめて行う（v0.2f） | p.309 は要素を無視しないことを、p.324 は 1 つのワザによるきぜつは同時であることを決める。きぜつしたポケモンをトラッシュする時点（ダメージの直後か、ワザのあとか）は書かれていないが、でんげきでは残りの要素の対象（自分）とその計算（相手のディフェンダーは自分へのダメージを変えない）が変わらないので、結果は同じ（SUPPORTED）。ワザの途中で対象がいなくなることに意味があるカードを加えるときは見直す。v0.4d で見直した: ふきとばしの 20 で相手がきぜつする場合、入れ替えの内容は対象がいないので処理しない（p.309・p.89・p.213）。これはワザの実装がダメージの結果（`DamageResult.knocked_out`）で判断し、トラッシュ・サイド・交代の時点（ワザのあと）は変えていない。ワザの途中でトラッシュする読み方とも、対戦の結果（場・トラッシュ・サイド・勝ち負け・選ぶプレイヤー）は同じ（[forced-switch-v0.4d.md](forced-switch-v0.4d.md) 4 章） |
