# ルールの仕様: 公式ルール 2000.02.14版（v0.1〜v0.4d で実装した範囲）

kyuura-engine v0.1〜v0.4d が実装した処理を、公式ルールの項目ごとに説明します（題の版が v0.4a・v0.4b でも「v0.3c まで」のままだったので、v0.4c で実装の範囲に合わせて直した。v0.4d で v0.4d までにした）。トレーナーカードのカードごとの裁定は [trainers-v0.2b.md](trainers-v0.2b.md)（マサキ・きずぐすり・ポケモンいれかえ）、[pluspower-v0.2c.md](pluspower-v0.2c.md)（プラスパワー）、[defender-v0.2e.md](defender-v0.2e.md)（ディフェンダー）、コイントスの裁定は [coin-rules-v0.2d.md](coin-rules-v0.2d.md)、コインを投げるワザ（ドードーの「みだれづき」）は [coin-attacks-v0.2d.md](coin-attacks-v0.2d.md)、自分へのワザのダメージは [self-damage-v0.2f.md](self-damage-v0.2f.md)、同時のきぜつは [simultaneous-ko-v0.2f.md](simultaneous-ko-v0.2f.md)、ピカチュウは [pikachu-v0.2f.md](pikachu-v0.2f.md)、特殊状態とどくは [special-conditions-v0.3a.md](special-conditions-v0.3a.md)、ポケモンチェックは [pokemon-check-v0.3a.md](pokemon-check-v0.3a.md)、ビードルは [weedle-v0.3a.md](weedle-v0.3a.md)、ねむり・マヒは [sleep-paralysis-v0.3b.md](sleep-paralysis-v0.3b.md)、ポケモンチェックの 3・4 は [pokemon-check-v0.3b.md](pokemon-check-v0.3b.md)、キャタピー・パラスは [cards-v0.3b.md](cards-v0.3b.md)、こんらんは [confusion-v0.3c.md](confusion-v0.3c.md)、こんらん状態のポケモンのワザとロコンは [confusion-attacks-v0.3c.md](confusion-attacks-v0.3c.md)、こんらん状態のポケモンのにげるは [retreat-confusion-v0.3c.md](retreat-confusion-v0.3c.md)、進化（たね → 1 進化）は [evolution-rules-v0.4a.md](evolution-rules-v0.4a.md)、ワザによる持続する効果は [persistent-effects-v0.4b.md](persistent-effects-v0.4b.md)、2 進化は [stage2-evolution-v0.4c.md](stage2-evolution-v0.4c.md)、スピアーは [beedrill-v0.4c.md](beedrill-v0.4c.md)、ワザによる相手の強制交代（ふきとばし）は [forced-switch-v0.4d.md](forced-switch-v0.4d.md)、与えたダメージに応じた回復（メガドレイン）は [damage-drain-v0.4d.md](damage-drain-v0.4d.md)、バタフリーは [butterfree-v0.4d.md](butterfree-v0.4d.md) にあります。各項目に、根拠（誌面のページ）、kyuura の記録 id、実装の場所、テストを対応させています。

ページは誌面のノンブルです。「テスト」の列のファイルは `tests/` の下にあります。

ルールとは別に、`new_game`・`apply_command` は、返す状態がカードの保存則（すべてのカードがどこか 1 か所にだけある）と場の形を満たすことを毎回確かめます（`check_invariants`。満たさなければ `StateIntegrityError`）。v0.1 のレビューの記録は [review-v0.1.md](review-v0.1.md) にあります。

### ダメージ計算の順番（p.321）

`damage.calculate_attack_damage` が、次の順に計算します。

1. 基本となるダメージ（ワザの説明にしたがって計算する。v0.1 のワザは説明がないので、目安の数字そのもの。v0.2d のみだれづきは「おもて」の数 × 10。v0.2f のでんげきは相手へ 30、「うら」のときの自分へ 10）
2. ワザを使うポケモンの「ダメージを変更する効果」（v0.1 の対応カードにはない）。ここまでで 0 以下なら計算を終え、「ダメージを与えなかった」
3. ワザを使うポケモンのタイプが、ワザを受けるポケモンの弱点のタイプなら 2 倍
4. ワザを使うポケモンのタイプが、ワザを受けるポケモンの抵抗力のタイプなら、抵抗力の数字をマイナス
5. ワザを使うポケモンについているトレーナーカード・エネルギーカードの効果（v0.2c: プラスパワーの +10）
6. 場にはたらいている効果（対応カードにはない）
7. ワザを受けるポケモンについているトレーナーカード・エネルギーカードの効果（v0.2e: ディフェンダーの −20）
8. ワザを受けるポケモンの「ダメージを変更する効果」（対応カードにはない）

最終的に 0 以下なら「ダメージを受けなかった」（0 ダメージ）。計算の途中で 0 以下になってもよい（p.319「ダメージ」、p.321「ダメージを計算している途中で、その数が0やマイナスの数字になってもかまいません」）。2・5〜8 段階の効果は `DamageModifier`（加算）で渡す（v0.2c）。同じ段階に複数の効果があるときの順番は、2・5・6 段階はワザを使うプレイヤー、7・8 段階は受けるプレイヤーが決める（p.321）が、加算どうしは順番で結果が変わらないので、選ぶ決定はまだない。

「ダメージを受けない」状態（v0.4b。「かたまる」の効果）は、この 8 段階のどこかで数を変える効果ではない。p.321 のとおり、その状態のポケモンにダメージを与えるワザの要素は無効なので、計算そのものをしない（`DamageModifier` は使わない。[persistent-damage-v0.4b.md](persistent-damage-v0.4b.md)）。

## 5. 実装上の決め事（史料の規定ではないもの）

公式ルールには書かれていない、コンピューターで動かすための決め事です。ルールの内容を変えるものではありません。

| 決め事 | 理由 |
|---|---|
| カード 1 枚ごとに対戦内の番号（uid）を付け、コマンドは uid でカード・ポケモンを指定する | 同じカードが複数あるため |
| 「デッキを切る」は、seed（0 以上の整数）から作った乱数での並べ替え 1 回で表す。切り直しのときも同じ | 結果を再現できるようにするため（同じデッキ・seed・操作列なら同じ結果） |
| ジャンケンの結果は外から受け取る（`ReportJankenResult`）。エンジンは乱数で決めない | ジャンケンはカードの外の出来事なので |
| 対戦準備でポケモンを出す順番（どちらのプレイヤーが先にコマンドを送るか）は問わない | ルールでは同時に裏にして出す |
| 切り直しの補償は、切り直し 1 回ぶんごとに 0〜2 枚を選ぶ（`DrawMulliganCards` を回数ぶん送る） | 文面は「切り直しになったら…最大2枚」「このときも…最大2枚」。合計で 0〜2×回数 枚引けるのと同じ |
