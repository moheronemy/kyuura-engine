## 2. ガルーラの「こどものおつかい」の修正

- kyuura の文面（`ja_text_source` は nazonobasho.com）は「コインを投げて「おもて」なら、自分の山札の上からカードを1枚ひいて、手札に加える。」です。
- 利用者が 2026-10-19 の依頼で、実物のカード画像（ガルーラ LV.40 HP90）を確かめた、と示しました。こどものおつかいは「自分の山札の上からカードを1枚ひいて、手札に加える。」で、コインはありません。先頭の「コインを投げて「おもて」なら、」は転記の誤りです。
- **エンジンは画像を見ていません。** 確かめたのは利用者です。
- v0.34 の pcg-search.com の照合（2026-10-16）も、コインの記載のない文面でした（照合の記録はそのまま。同じ結果ですが、別の照合として数えません）。

写しへの当てはめ方:

- v0.62 の `CONFIRMED_CORRECTIONS`（kyuura が確定した修正）と同じく、写しの書き出しで欄だけを直します（`scripts/extract_kyuura_cards.py` の `USER_PROVIDED_CORRECTIONS`）。
- `CONFIRMED_CORRECTIONS` とは分けて持ち、書き出しの別の欄 `user_provided_corrections` に、欄・前・後・`basis: user_provided`・示した日・`engine_saw_image: false` を残します。
- kyuura の照合の記録（CC-）・最新の説明（LD-）・修正のコミットはありません。記録の id・コミットを書くと書き出しを拒否します（`user_correction_problems`）。エラッタ・別の版の文面としても扱いません。
- 直すのはワザ 0 の説明文（`pokemon.attacks[0].text.ja`）だけです。書き出すたびに、写しの元の値が `before` であることを確かめます。作り直しても修正は残ります。

## 3. キョウのベトベトンの［だつりょくえき］（採用の仕様）

### 3.1 採用した仕様

| 論点（docs/kogas-muk-event-design-v0.17c.md） | v0.68 の扱い |
|---|---|
| DR1 宣言するか | **採用の仕様:** 自動的にはたらく。条件を満たしたらコインは必ず投げる。使わない選択はない |
| DR6 処理する時点 | **採用の仕様:** そのワザのダメージの処理（すべての対象へのダメージ）のあと、ワザを使ったポケモンのダメージ以外の効果の前 |
| DR12 「おもて」のあとトラッシュしないことを選べるか | DR1 の採用にふくまれる（選べない） |
| DR2・DR4・DR5・DR9・DR15・DR17 | 既存の記録（kyuura の CR-ENERGY-DRAIN-*）のとおり |
| DR3 返すダメージ | ほのおのかべ・こうらがえしなどの返すダメージでもはたらく。ダメージを与えたポケモンは返す効果を持つポケモン（CR-ENERGY-DRAIN-RETURN-DAMAGE） |
| DR7・DR10 コイン・選ぶのは持ち主 | 既存の記録のとおり |
| DR8 処理する時点でダメージを与えたポケモンが HP 以上 | **止める:** `UNRESOLVED_ENERGY_DRAIN_ATTACKER_KNOCKED_OUT` |
| DR13 ダメージを与えたポケモンにエネルギーカードがない | **止める:** `UNRESOLVED_ENERGY_DRAIN_NO_ENERGY` |
| DR14 処理する前に場をはなれる | 今の写しでは起こらない（処理はダメージの要素のまとまりのすぐあと）。起こればエンジンの不具合として止まる |
| DR16 かがくへんかガス | 受けるときに消えていればはたらかない（まきちらせ!ベトベトガスも同じ） |
| DR18 ほかの「ダメージを受けたとき」の効果と重なる | 既存の C34・C35 と同じ問い（`UNRESOLVED_MULTIPLE_DAMAGE_TRIGGERS`） |
| DR19 1 つのワザで 2 回以上受ける | 既存の問いと同じ（1 つのワザで送る効果が 2 つ以上なら止める）。DR19 の「そのたびに」は処理しない（実装の制限） |

DR1 の根拠:

- kyuura の `MIX-POWER-ERRATA`（2002-05-24 の公式サイトの Q&A。ポケボディーとして扱う一覧に、キョウのベトベトンのだつりょくえきがある）。
- kyuura の `MIX-POWER-SPLIT`（『トレーナーズ』Vol.13 の定義「自動的にはたらく特殊体質の「ポケボディー」」）。

これは**この特殊能力に限って採用した**仕様です。2000.02.14 版の裁定として決まったことにはしません。kyuura の UQ-ENERGY-DRAIN-DECLARATION は UNRESOLVED のままです。2002 年のほかの変更（サポーター・特殊状態の範囲を広げる大会のルール）は持ち込みません。

DR6 の根拠:

- docs/shell-attack-v0.13.md の p.89 の「こうらがえし」の解説（ダメージのあと・追加の効果の前）の時点を、だつりょくえきに当てはめた**類推**です。
- すべての対象へのダメージのあとにする順番も、採用の仕様です。
- DR6（UQ-ENERGY-DRAIN-TIMING）を公式に決めたことにはしません。

### 3.2 処理

- 効果の定義は `catalog.ENERGY_DRAIN`（はんげきと同じ窓。`Timing.DEFER`）、処理は `kernel.drain_energy_from_damage_source` です。
- 受けるときに候補にします（`kernel.receiving`）。
  - 相手のワザの分類のダメージ（ワザのダメージ・返す効果のダメージ）で、最終ダメージが 0 より大きいときだけです。
  - どく・こんらんの 20・特殊能力のダメージ・ダメージカウンターの移動ではありません。
  - ねむり・マヒ・こんらん・かがくへんかガス・まきちらせ!ベトベトガスは、受けるときの状態で決めます。どくは関係しません。
  - バトル場でもベンチでもはたらきます。
- 「ショックアイ」（宣言して使う特殊能力の使用だけを止める）は、自動的にはたらくこの特殊能力を止めません。力を消すこと（ガス）と、使用の禁止は別です。
- 処理は、そのワザのダメージの要素のまとまりのあとの窓（`programs.fire_or_suspend`）で行います。
  1. DR8・DR13 を確かめる（当たれば止める。宣言の前の先読みが見つけるので、状態は変わらない）。
  2. 持ち主がコインを 1 枚投げる（ログ `energy_drain_check`）。
  3. 「おもて」なら、持ち主に決定 `energy_drain_discard` を出す。選べるものは、ダメージを与えたポケモンについているエネルギーカード（ついている順。種類を問わない。1 枚でも出す）で、ちょうど 1 つ。
  4. 答えのあと、選んだカードをそのカードの持ち主のトラッシュに置く（ログ `energy_drain_discard`）。
- 決定をまたぐ続きの情報は、決定の `context` の明示的なデータです。
  - "boundary"（次に処理する要素の位置）
  - "drain"（持ち主・ベトベトンの番号・カード id・特殊能力の位置・ダメージを与えたポケモンの番号）
  - 枠の値（"frame"）
- 再開では、宣言・コイン・ダメージ・送る効果・きぜつの判定をくり返しません。v0.65 の要素のあいだの決定と同じ持ち方です。
- 決定の形は不変条件（`engine._reaction_decision_problems`）で確かめます。不正な答え（選べないカード・0 個・2 個・ちがうプレイヤー）は、状態を変えずに拒否します。
- 返す効果のダメージ（入れ子の枠）の中で「おもて」になった場合も、同じ決定を出して、もとのワザの次の要素の位置から続けます。
- v0.13 の約束で書いたワザの実装（テスト専用）が、自分で窓を開いて決定が要る場合は、エンジンの未対応 `UNSUPPORTED_ENERGY_DRAIN_DECISION` で止めます。
- v0.13 の止める関数（`v013_checks`）はだつりょくえきを知らないので、場にだつりょくえきを持つポケモンがいるときは、上限を超えたときに v0.13 の止める関数で確かめません（`flow.legacy_unknown_features`）。

ワザでダメージとダメージ以外の効果を交互に与える並び（「げきとつ」など）の順番は、変えていません（既存の GK1 の問いのまま）。

## 4. イマクニ？のドードー（簡略化した仕様）

印刷の文面はデータのまま持ち、照合に使います。処理は次の簡略化した仕様で、公式の裁定・エラッタではありません。

- ハモるの処理に使う文面: 「相手に30ダメージを与える。」
  - ふつうのワザとして、使ったらすぐに相手の対戦ポケモンに 30 ダメージを与えます。
  - 必要なエネルギー（無色 2 個）・こんらんなどの使うときの確認・弱点・抵抗力・ダメージを変える効果は、ほかのワザと同じです。
  - 歌を歌う状態・歌い終わりの通知・音声の認識・非同期の処理は作りません。相手のワザとして使っても 30 です。
- ［にげまくり］の処理に使う文面: 「(カードを投げる動作は対戦の処理にふくめない。にげるときは、ふつうの「にげる」として処理する。)」
  - カードを投げる物理的な動作は処理にふくめません。
  - この特殊能力は状態・ログ・乱数を変えず、宣言もできません（`POWER_NOT_DECLARABLE`）。
  - にげるはふつうの規定のまま（印刷のにげるエネルギー 0。ねむり・マヒではにげられない）です。
  - 存在しない動作（投げた・投げなかった）を記録・数えることはしません。

`SimplifiedSongDamage`・`SimplifiedRunAway` の型は、このカードの印刷の文面と同じときだけ登録できます。未対応のワザ・特殊能力を効果のないものとして受け付ける、一般の仕組みではありません（`RegistrationTest.test_simplified_types_only_accept_their_printed_text`）。出典は `kyuura-engine docs/final-pmcg-cards-v0.68.md#4` です。

## 5. マチスの秘策の情報漏れの修正

### 5.1 再現例（利用者の例）

両方のデッキは 60 枚です。

- プレイヤー 0: バトル場は闘 2 枚のエビワラー。手札はマチスの秘策 3 枚とディグダ 3 枚、サイドは炎 6 枚。
  - デッキ A: 山札にコラッタ 1 枚と炎 44 枚。
  - デッキ B: デッキ A の見えない炎 1 枚をドードーに置きかえたもの。
- プレイヤー 1: バトル場は闘 1 枚のエビワラー。手札は突風 1 枚、サイドは炎 6 枚、山札は炎 51 枚。
- プレイヤー 0 がディグダ 3 枚をうらにしてベンチに出し、番を終える。プレイヤー 1 が突風でうらのディグダを選ぶ。

v0.67 では、デッキ A はカードの種類が 6 で 6³ = 216 となり受け付けました。デッキ B は 7 種類で 7³ = 343 > 256 となり、`UNSUPPORTED_SECRET_PLAN_IDENTITIES` で拒否しました。

### 5.2 原因

v0.67 の `engine._identity_independent` は、次のように作っていました。

- ありうるカードを、うらのカードの持ち主の**本当のデッキのカード**から作った。
- コマンドが指定していないうらのカードもふくめた組の数を、上限と比べた。

そのため、見えないデッキの中身で、受け付けるかが変わりました。理由の文から数を除いても、受け付けるか・拒否するかそのものが情報になります。

### 5.3 修正

公開の情報だけで決まる確かめに直しました（`engine._identity_independent`・`zones.IDENTITY_ORACLE`）。

- **ありうるカードは公開の情報から作ります。** 対応しているカードの一覧（`_public_pool`。効果の登録表ごとに 1 つ）を使い、デッキ・山札・手札の中身は使いません。
- **試すのは、このコマンドが効果の対象として指定した（おもてにした）相手のうらのカードだけです。** 指定するまでの処理はうらのカードを読めない（FD1）ので、どのカードを指定するかは公開の情報で決まります。
- 確かめの状態では、相手のうらのカードを「割り当てる前」の印にしておきます。指定された順に、ありうるカードを割り当てます。
  - 割り当てる前の印を、指定せずに読めばエンジンの不具合として止まります。
- 「たねポケモン」でないカードは、おもてにするとトラッシュします。
  - トラッシュしたあとにほかの項目を読まなければ、どのカードでも同じ結果なので、1 回だけ試します（「たねポケモンでない」とだけ決めた印）。
  - 読んだら、たねポケモンでないカードをひとつずつ試します。
- どの割り当てでも受け付けるなら、本当の結果を返します。どれかで拒否するなら、同じ種類・コードで拒否します（理由の文に割り当てたカードを書かない）。
- 試す回数の上限は 512 です。
  - 指定された相手のうらのカードが 1 枚なら、おさまります（たねポケモン 185 種類と「たねポケモンでない」の 1 つ）。
  - 2 枚以上なら超えるので、`UNSUPPORTED_SECRET_PLAN_IDENTITIES`（エンジンの未対応）です。試すカードの一覧は公開の情報だけで決まるので、超えるかも本当のカード・デッキの中身によりません。

公開の情報が同じなら、表にする前に受け付けるかは同じです。デッキの一覧は公開しません。突風は、表にすることで正しく処理できるので、両方のデッキで受け付けます（両方を拒否する直し方にはしていません）。

正当に公開される情報と、表にする前に漏れてはいけない情報は、次のように分かれます。

- 対象として指定され、処理されたうらのカードは、その処理でおもてになります（ログ `secret_plan_revealed`）。これは正当な公開です。
- コマンドを拒否したときは、何もおもてにならないので、拒否するかが本当のカードで変わってはいけません。

### 5.4 ほかの経路の点検

うらのカードを指定する経路を点検しました（`zones.designate_face_down` を呼ぶところ）。

- ワザのダメージ・効果（`kernel.designate`）
- 特殊能力の選ばせるもの（ゲンガーの［のろい］など）
- 決定の答えの指定（`engine._designate_answer`）
- トレーナーをつける・つけたときの効果のある特殊エネルギー

どれも同じ確かめを通ります。1 つのコマンドで 2 枚以上の相手のうらのカードを指定する経路（控え全員へのダメージなど）は、5.3 の上限で受け付けません（実装の制限）。

ただし、指定する前にうらのカードの項目を読む処理は、v0.67 のとおり FD1（`UNRESOLVED_SECRET_PLAN_HIDDEN_PROPERTY`）で止まります。たとえば第1弾のコイルのじばく（説明に「弱点・抵抗力」に関係なくがない控えへのダメージ）は、
JS1 の確かめで控えの HP を読むので、ダメージを与える前に FD1 です。この拒否も、どのデッキでも同じ種類・コード・理由の文です
（`SecretPlanLeakTest.test_two_face_down_targets_are_refused_for_both_hidden_decks`。「弱点・抵抗力」に関係なくと書かれた化石の秘密のレアコイルのじばくは、
2 枚を指定するので `UNSUPPORTED_SECRET_PLAN_IDENTITIES`）。

これは公式の未解決の裁定ではありません（研究の対応表の停止コードに入れていません）。

## 7. 残る未解決と実装の制限

- DR1・DR6 は kyuura では UNRESOLVED のままです。エンジンは採用の仕様で処理しますが、裁定として決まったわけではありません。
- DR8・DR13 は止めます。
- DR18・DR19（1 つのワザで送る効果が 2 つ以上）は、既存の C34・C35 の問いで止めます。
- 相手のうらのカードを 2 枚以上指定するコマンドは、受け付けません（5.3）。v0.67 では、見えないデッキの種類が少なければ受け付けていたもの（8.3 の表の 2 行目）も、v0.68 では受け付けません。自然な対戦でも起こります: `--batch v0.67` の `L67` 対 `G64` の seed 2 では、化石の秘密のゴローニャのじばく（相手の控えにうらのカードが 2 枚以上）が 4 つの番で
