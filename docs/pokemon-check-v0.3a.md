# ポケモンチェック（v0.3a）: 原典照合と実装

番と番のあいだに、プレイヤーの操作なしにエンジンが行う処理（ポケモンチェック）について、原典で確かめたこと、決められなかったこと、実装、テストを対応づけた記録です。v0.3a でポケモンチェックの中で起こるのは「どく」のダメージと、それによるきぜつだけです。特殊状態の規定は [special-conditions-v0.3a.md](special-conditions-v0.3a.md)、設計は [architecture-v0.3a.md](architecture-v0.3a.md) にあります。

- 基準のルール: 「ポケットモンスターカードゲーム公式ルール 2000.02.14版」（『ポケモンカードオフィシャルブック2000』pp.306〜326 [P43]、kyuura `NEO-2000-OFFICIAL-RULES`・`knockout_timing`）
- 照合の方法: スキャン [J38] のページ画像を目で読んだ（2026-10-12。p.323 は 300dpi）。読んだページは p.309、p.311、p.312、p.313、p.321、p.322、p.323、p.324、p.325
- 時期の違い: kyuura `knockout_timing` によると、第1〜2版ではきぜつをポケモンチェックで判定していた（会報 Vol.3 の「前のルール ポケモンチェックでは特殊状態のチェックと「きぜつ」状態のチェックとその処理の2つを行う」）。2000.02.14版のポケモンチェックの手順にはきぜつの段階がない。v0.3a は 2000.02.14版だけにしたがう

## 3. 両方がどくできぜつする場合（UNRESOLVED）

v0.2f の「1 つのワザで両方がきぜつする」場合と比べて、ポケモンチェックでは次の 3 つが原典から決められません。

1. **同時のきぜつか**: p.324 は「1つのワザや特殊能力などによって引き起こされることがら」による複数のきぜつを「同時」とする。ポケモンチェックの 2 は「どく状態になっているポケモンに、それぞれ10ダメージを与えます」で、どくはそれぞれ別のワザが与えたもの。これが「1つの…ことがら」かどうかは書かれていない。同時でなければ、先に処理したきぜつで勝敗が決まることがあり（最後のサイド、出せない）、どちらを先にするかも書かれていない。
2. **バトル場に出す順番**: pp.323〜324 は「今が自分の番でないプレイヤーがまず…今が自分の番のプレイヤーは、それを見てから」とする。ポケモンチェックは「どちらのプレイヤーの番でもありません」（p.323）なので、この規定をそのまま当てはめられない（両方が「自分の番でないプレイヤー」になる）。p.323 の 1 の順番には「このポケモンチェックの前に番をおこなったプレイヤー」と書き分けているので、それを交代の順番に読みかえる根拠もない。
3. **サイドを取る順番を決めるプレイヤー**: p.325 は「そのとき番をおこなっているプレイヤー」が決めるとする。ポケモンチェックの中では、番をおこなっているプレイヤーがいない。

1 によって勝敗が変わる例: 両方が最後のサイドなら、同時ならサドン・デス（p.311）、同時でなければ先に処理したほうの相手の勝ち。両方ともベンチがなければ、同時ならサドン・デス（p.311・p.324）、同時でなければ先に処理したほうの持ち主の負け。自分だけ最後のサイドで自分は出せない場合は、同時ならサドン・デス（p.311 の表の 1 行目）、同時でなければ順番で勝ち・負けが入れかわる。勝敗が変わらない場合（両方ともベンチがあり、サイドも残る）でも、2 の交代の順番が決まらない。

そのため、ポケモンチェックの 2 で両方のプレイヤーのポケモンがきぜつするとき（どくのダメージを足して HP 以上になるポケモンが両方の場にあるとき）は、**ダメージを与える前に**対戦を止めます（`Phase.HALTED`、`UNRESOLVED_POKEMON_CHECK_DOUBLE_KNOCKOUT`。ログ `turn_end` → `pokemon_check` → `halted`）。止めた状態では、ダメージ・サイド・場は番の終わりのまま変わらず、以後のコマンドは `UnsupportedError`（同じコード）です。勝敗（`GAME_OVER`）・サドン・デス（`SUDDEN_DEATH`）とは区別します。

両方がどく状態でも、きぜつするのが片方だけなら決まる（相手側がサイドを取り、持ち主が出す）ので、止めません。

## 4. ターン進行との関係（状態遷移）

```
（番のプレイヤーの操作）
  │ EndTurn ／ ワザ（→ きぜつ → サイド → 判定 → 交代。決定を待つことがある）
  ▼
_end_turn: 期限のきたトレーナーをトラッシュ → turn_end
  ▼
_pokemon_check: pokemon_check
  ├ 2. どく: 両方がきぜつする → HALTED（止める）
  │          それ以外 → それぞれ poison_damage
  ├ （3・4: v0.3a ではなし）
  ├ きぜつがない → _begin_turn（次の番: turn_start → draw）
  └ きぜつがある → knock_out（timing: pokemon_check）→ _after_knockouts(then=NEXT_TURN)
        ├ TAKE_PRIZE の決定（相手側）    ┐ 決定の context の "then" = "next_turn"
        ├ 判定（p.311）→ 決まれば GAME_OVER（次の番は来ない）
        ├ PROMOTE_ACTIVE の決定（持ち主）┘
        └ _begin_turn（次の番）
```

- ポケモンチェックの中の決定を待っている間は、`phase` が `TAKE_PRIZE`・`PROMOTE_ACTIVE`、`current_player`・`turn_number` は番を終えたプレイヤーの番のまま（次の番はまだ始まっていない）。決定に答えるコマンドだけを受け付ける。
- 決定の `context` の `"then"` が `"next_turn"` なら、交代のあとで次の番を始める（番の終わり・ポケモンチェックはもうしたので、二度しない）。ワザのあとの決定には `"then"` がなく（v0.2f と同じ形）、交代のあとで番を終える。
- 不変条件（`_progress_problems`）: 前の番の始まりから今の番の始まりまでに `turn_end` → `pokemon_check` がちょうど 1 回ずつ。ポケモンチェックの中の決定なら、今の番のあとに 1 回ずつ。番の途中ならまだない。
