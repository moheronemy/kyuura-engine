v0.37（`beb7b0d`。版 0.37.0）から作業ブランチ `claude/v0.38-bench-switch-combined` を作り、依頼の 15 枚を加えました（版 0.38.0）。

   対応ポケモン 179 → 194、ワザの登録 314 → 343（特殊能力 12 のまま）、写し 200 → 215 枚。
2. 必要な共通の処理を、既存の要素の組み合わせと、要素の小さな項目の追加で加えた（3 章）。新しい要素は、ワザを使ったポケモンが場をはなれたあとに
   かわりの対戦ポケモンを出す `PromoteFromBench` と、山札からポケモンを見せて手札に加える `RevealPokemonFromDeck` の 2 つだけ。今回のカード群に必要な
   共通の処理の制限（コインが決める要素に対象がないとき・要素のコイン・場をはなれたあとの決定など）は、同じ作業で解消した（3.5 節）。
3. サイドンの「げきとつ」で、相手の対戦ポケモンへのダメージで「ダメージを受けたとき」の効果がはたらく場面は、その効果を処理する時点が記録から決まらない

## 3. 共通の処理

### 3.1 新しく加えた型

どれも解決の基盤の要素の並び（`programs.BUILDERS`）で表し、v0.13 の約束（`resolve`・`resume`）では書いていません。tests/helpers.py の
`ATTACK_TYPES_SINCE_V0_17` に加え、`v013_checks.VERIFIED` には入れていません。説明の文面は、登録したワザの印刷の文面と完全に同じものだけを受け付けます
（`_check_exact_text`。`TextTest` が、条件の文の有無・ダメージの数・対象の違う書き方を拒否することを確かめる）。

| 型 | ワザ | 要素の並び | 区別したこと |
|---|---|---|---|
| `ChooseOpponentBenchDamage(damage, requires_bench)` | のびるキック・のびるつる | `ChosenBenchDamage(Fixed, local_coin=None, required=requires_bench)` | 相手の対戦ポケモンにはダメージなし。「使えない」の文の有無を `requires_bench` で区別（BC1・BC2） |

### 3.3 ゾーンの関数とログ

- `zones.discard_attached_cards`（新）: 場のポケモンについているカード（エネルギー → トレーナーの順）を持ち主のトラッシュに置く。ログ `discard_attached_cards`
  （`player`・`pokemon`・`pokemon_id`・`effect`・`energy`・`trainers`。公開）。重なったカードは動かさない（ポケモン自身のカード。v0.36 の RD2）。
- `zones.promote_from_bench`（新）: ベンチのポケモンを空いたバトル場に出す（ログ `promote_active`）。きぜつのあとのバトル場に出す決定（`resolution.flow._resume_promote`）
  の本体をそのまま関数にし、でんれいと共通にした。ワザの効果で出したときだけ、ログに `effect`（ワザ）を加える（きぜつのあとのログの形は v0.37 と同じ）。
- `zones.reveal_deck_to_hand`: ワザの効果で見せるときだけ、ログ `reveal_from_deck` に `effect` を加える（ポケモン交換おじさんのログの形は v0.24 と同じ）。
- 決定の種類は増やしていません。でんれいの山札をさがす決定は、v0.22・v0.24 と同じ `SEARCH_DECK`（再開先は `"attack"`）です。

### 3.4 不変条件

- `engine._returned_attacker`: ワザの途中の決定で、ワザを使ったポケモンが場にいないときだけ、続きのワザ（まねたワザならそのワザ）の実装が
  `leaves_play_before_decisions`（でんれい）で、今の番にそのプレイヤーのワザの宣言がちょうど 1 回あり、そのあとに、同じポケモン（番号・いちばん上の
  カード）を同じワザの効果で山札にもどしたログ `return_in_play_to_deck` がちょうど 1 回あることを確かめて、場のかわりにログで続きの情報を確かめる。
- バトル場が空のままの決定は、上の場合の番のプレイヤーだけ許す（でんれいの、かわりの対戦ポケモンを出す決定と、控えがいないときの山札をさがす決定）。
- どちらも狭い例外で、広げていません。ログの監査（tests/log_audit.py）は、でんれいのイベントの並び（`return_in_play_to_deck` → `promote_active`（同じ
  `effect`）→ `reveal_from_deck`／`reveal_from_deck_none` → `shuffle`）と、`discard_attached_cards`（ワザを使ったポケモン・エネルギー・カウンターが 0）を
  組み立て直します。

### 3.5 解消した制限・再利用したもの

今回のカード群で必要になり、同じ作業で解消した制限:

1. コインが決める要素のどれにも対象がないとき、コインを投げていた（ふぶき）→ 投げない（`Element.has_target`）。
2. 入れ替えの要素（`ForceSwitch`・`SelfSwitch`）に要素のコインがなかった（いかくこうげき・けりにげ）→ `local_coin` を加え、対象がなければ投げない。
3. 自分への持続する効果の要素がワザ全体のコインを使えなかった（こうそくひこう）→ `SelfPersistent.gate`。
4. 相手の控えを選ぶダメージに、ワザを使うための条件の文があるワザを表せなかった（のびるキック）→ `ChosenBenchDamage.required`・`usage_problem`・`copy_problem`。
5. 山札にもどす要素が、ついているカードをトラッシュする形・途中で切らない形を表せなかった（いなくなる・でんれい）→ `discard_attached`・`shuffle`。
6. ワザを使ったポケモンが場をはなれたあとに、ワザの途中の決定を出せなかった（でんれい）→ 続きの情報を枠の番号で持ち、不変条件の狭い例外を加えた。
7. ワザの途中で、きぜつ以外の理由でバトル場に出す処理がなかった（でんれい）→ `PromoteFromBench`（`zones.promote_from_bench` をきぜつのあとの処理と共通にした）。
8. 山札からポケモンを見せて手札に加えるワザがなかった（でんれい）→ `RevealPokemonFromDeck`（v0.24 の `reveal_deck_to_hand` と `SEARCH_DECK` を再利用）。

再利用したもの: 既存の型 `ParalyzeOnHeads`・`PutToSleep`・`PoisonOpponent`・`CoinFlipDamage`・`DamageOnly`。要素 `ChosenBenchDamage`（v0.33）・`BenchDamage`・
`Damage`（v0.31〜v0.37）・`ForceSwitch`（v0.4d）・`SelfSwitch`（v0.34）・`SelfPersistent`（`AttackBarrier` v0.31・`DamageReduction` v0.31）・`Status` の `otherwise`
（v0.34）・`ReturnSelfToDeck`（v0.36）・`Coin`（ワザ全体のコイン）・`void_coin_question`（v0.34）・送る効果を決定をまたいで運ぶ処理（v0.34）。ゾーンの
`return_in_play_to_deck`（v0.36）・`reveal_deck_to_hand`（v0.24）・`shuffle_deck`。持続する効果の型・書き出しの形式・決定の種類は増やしていません。

## 5. GK1: 入れ替えをはさんで自分にダメージを与えるワザと「ダメージを受けたとき」の効果

| 項目 | 内容 |
|---|---|
| 問い | サイドンの「げきとつ」（相手へのダメージ → 入れ替え → 自分にも 20）で、相手の対戦ポケモンへのダメージで「ダメージを受けたとき」の効果（はんげき・わるいねぞう・ほのおのかべ・こうらがえし）がはたらくとき、その効果をいつ処理するか |
| 記録 | kyuura の CR-COUNTERATTACK-TIMING・CR-FIRE-WALL-TIMING・CR-SHELL-ATTACK-TIMING（ワザのダメージの処理（自分へのダメージを含む）をすべてのせたあと、かつダメージ以外の効果の前。p.89 のこうらがえしの解説の例）。エンジンの v0.10 の C1〜C43・v0.12 の W1〜W30・v0.13 の S1〜S49 も同じ時点 |
| 判断 | げきとつの並びでは、ダメージ以外の効果（入れ替え）のあとにダメージ（自分への 20）があるので、「ダメージの処理をすべてのせたあと」と「ダメージ以外の効果の前」を同時に満たす時点がない。入れ替えの前に処理するか、自分への 20 のあとに処理するかで、ワザを使ったポケモンが「はんげき」の 10 と自分への 20 のどちらで先に HP 以上になるか（同時のきぜつ・C15 の扱い）や、入れ替えの決定の前に効果を与えるかが変わりうる。記録で決まらないので UNRESOLVED（GK1）。新しいコード `UNRESOLVED_DAMAGE_TRIGGER_TIMING`（問い `damage_trigger_timing`。kyuura の未解決の一覧にない。`not_in_kyuura`） |
| 止める場面 | 解決の基盤が、ダメージ以外の効果の要素に進むときに「ダメージを受けたとき」の効果が残っていて、並びのあとにダメージの要素があるときだけ（`programs.run_elements`）。先読みが宣言の前に見つけるので、どの先読みの方法でも宣言の前に止まり、状態・乱数・ログは変わらない。例: はたらいている「はんげき」を持つカイリキー・ほのおのかべの持続する効果を持つ R団のファイヤー |
| 止めない場面 | 「ダメージを受けたとき」の効果がはたらかない（カイリキーがねむり・こんらん・マヒ・かがくへんかガスで消えている・相手が「はんげき」を持たない）。ほかのワザ（どくばりタックルは自分へのダメージが効果の前にあるので、記録の時点がある） |
| まねるワザ | ピクシー・ピッピ・カスミのコダックがまねたげきとつも、同じ並びなので同じ問いで止まる |
| 影響の範囲 | 今の対応カードでは、げきとつ（サイドン・それをまねるワザ）だけ。「ダメージ → 効果 → ダメージ」の並びのワザを加えるときは、同じ問いに当たる |
| テスト | `RamTest.test_damage_trigger_stops_before_the_declaration`・`test_proceeds_without_a_damage_trigger`・`IntegrityTest.test_rejections_keep_the_state` |

同じ問いをカード別のコードにしないため、問いは要素の並び（効果の要素のあとのダメージの要素）と送る効果の有無で決め、カード id では決めていません。
既存の問い（C18・W24 など、そろってのきぜつ）は「時点が決まっている」前提の問いなので、GK1 の代わりに使っていません。

## 6. まねるワザ

相手のワザを自分のワザとして使う効果（ピクシー・ピッピの「ゆびをふる」・カスミのコダックの「ちょうのうりょく」）で、v0.38 のワザはどれも、まねたポケモンの
ワザとして処理します（内部エラーにならない）。

- のびるキック（相手に控えがいない）: ピクシー（ほかに必要な条件がたりなければ使えない）・ピッピ（説明にしたがう）では選べず、カスミのコダック（条件を
  書かない）では選べるが、選ぶと HC9（`UNRESOLVED_COPIED_ATTACK`）。v0.32 のなかまをよぶ・v0.31 のぼーっとすると同じ `copy_problem`
- でんれい・いなくなる: まねたポケモン（進化していれば重なったカード全体。LP3）を山札にもどす。でんれいの決定は、場をはなれたまねたポケモンのワザの続き
  （不変条件はまねたワザで確かめる）
- げきとつ（自分への 20 はまねたポケモン）・ふぶき（「うら」は、まねたポケモンの側の控え）・GK1 も、まねたポケモンの側で同じ
- エンジンの未対応として残るまねるワザは、v0.38 のワザにはありません（ドわすれのまねは v0.36 からの `UNSUPPORTED_COPIED_ATTACK` のまま）
