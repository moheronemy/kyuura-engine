# v0.89: 対象を選ぶダメージ・選べる回復のポケモン 17 枚

v0.89 は、場のポケモンを選んでダメージを与えるワザ（選んでからコインを投げる・コインのあとに選ぶ・相手プレイヤーが選ぶ・選んだ個体のエネルギーカードもトラッシュさせる・自分の場から選ぶ）と、
おたがいの場から選ぶ回復のワザを持つポケモン 17 枚（ワザ 26）を、kyuura データの採用で登録した版です。選ぶ対象の範囲・選ぶプレイヤー・選ぶ時点を別々に表し、選んだ個体を番号と持ち主で
決定の前後に運ぶ共通の処理（選ぶ要素と選んだ個体へのダメージの要素）を加え、v0.43〜v0.88 の相手の場のポケモンを選ぶダメージもこの処理に移しました。「弱点・抵抗力・特殊能力・その他の
効果」に関係なく与えるダメージ（ブラッキーの「だましうち」）は、v0.60 のスピードスターの処理を控えポケモンへのダメージにも通し、除く効果の範囲の読み方で結果が変わる場面を新しい問い FA1 で
止めます。目的は模擬戦で使えるカードを増やすことで、強さ・勝率・釣り合いは評価していません。

- 基点: `8de7bbb`（main。PR #16 のマージ。v0.88 と、テストの整理 `902647a`・CLAUDE.md の整理 `1b3a1b1` を含む）。作業ブランチ `claude/v0.89-selected-target-damage` は、このコミットから作りました
  （開始時に未コミットの変更はなかった）。
- 写しの元・研究の基準: kyuura `7d3f4ca76c084774efb4ac6a1d3a943387e183c3`（変えていない）。ルールの基準は 2000.02.14 版のまま。

## 3. 選ぶ対象の共通の処理

### 3.1 選ぶ要素と選んだ個体

- ワザの説明が選ばせる場のポケモンは、どちらの場から（`effects.TARGET_SIDES`: 相手・自分・おたがい）・対戦ポケモンと控えポケモンか控えポケモンだけか（`TARGET_SCOPES`）・選ぶプレイヤー
  （`TARGET_CHOOSERS`: ワザを使ったプレイヤー・相手プレイヤー）を別々の値で表します。選べるものは `effects.target_candidates` が求め（場ごとにバトル場 → ベンチ。おたがいの場はワザを使った
  プレイヤーの場 → 相手の場）、決定の不変条件（`effects.target_decision_problems`）と選ぶ要素が同じ関数を使います。
- 選ぶ要素は `programs.ChooseTarget`（ダメージの要素のまとまりの中。`Phase.DAMAGE`）と `ChooseEffectTarget`（効果の対象。`Phase.EFFECT`）で、選ぶ時点は並びの位置と `gate`（ワザ全体のコインの面）・
  `local_coin`（この要素で 1 枚投げる）で表します。選んだ個体は `fs.results[name]` の `ChosenTarget(番号, 持ち主)` に置き、あとの要素（`TargetDamage`・`TargetHeal`・`DiscardOpponentEnergy` の
  `chosen`）が名前で読みます。名前の既定は `target`（v0.83 の `ChooseOpponentBench` の名前 `chosen`・v0.82 の `DiscardEachType` の続きの情報の `chosen` とは重ならない）。
- 決定をまたぐときは、続きの情報の `chosen_targets` に (名前, 番号, 持ち主) で運びます（v0.83 の (名前, 番号) の形もそのまま読む）。不変条件（`engine._carried_flee_problems`）が形・名前の重なり・
  持ち主とそのポケモンの今の持ち主が同じことを確かめます。順番の決定・お上品攻撃の減らす量の決定・［ベンチガード］・ナツメのESP の決定のあとも、選んだ個体を選び直しません。
- 選んだ個体が場をはなれていたら、あとの要素は何もしません（コインも投げない）。今の対戦ポケモン・同じ名前の別のポケモンにすり替えません。うらのカード（マチスの秘策）は、選べるものに
  入り、ダメージを受ける時におもてにしてから処理します（v0.67 と同じ。「たねポケモン」でなくトラッシュしたら、対象はいない）。
- 選ぶのが相手プレイヤーでも、番のプレイヤー（`current_player`）・番の番号は変えません。決める人が相手であることは、その決定の形（`target_decision_problems` の `chooser`）だけが許します。
- 選べるポケモンがいなければ選ばずに何もしません（p.309）。説明が「…いないとき、このワザは使えない」と書くワザ（ロングショット）は、実装の `usage_problem`（`NO_OPPONENT_BENCH`。こんらんの
  コインの前）で拒否し、選ぶ要素の `required` は確かめの漏れをエンジンの不具合として止めます。相手のワザとして使うときは選ぶ要素の `copy_problem`。

### 3.2 選ぶと止めるポケモン

あとの要素（`TargetDamage`・`DiscardOpponentEnergy`）の `choice_problem` が、そのポケモンを選ぶと決められない場合を返したら、そのポケモンは「選べるが選ぶと止める」（決定の
`unresolved_choices`）です。どの候補もそうなら、または違う問いが混ざるなら、選ぶ前に止めます。先読みは選ぶと止めるポケモンを試しません（`dry_choices`）。今の問い:

| 場合 | 問い | 例 |
|---|---|---|
| コインが選んだ個体へのダメージだけを決め、その個体がダメージを受けない | v0.4b `UNRESOLVED_PREVENTED_COIN_DAMAGE`（「とうめい」で受けないと決まっていれば T19b） | ロングショット・だくりゅう・マジックダーツ・ねらいだま で見えない壁の控え |
| 説明が控えへのダメージの弱点・抵抗力を書かず、計算するかで量が変わる | JS1 | ねこパンチ |
| 除く効果の範囲の読み方で受けるダメージが変わる | FA1（4 章） | だましうち |
| 選んだポケモンのエネルギーの数え方が決まらない | TE1・RB1・BZ2・MEC1・CE1・CE2 | ろうでん |
| コインが選んだ個体のエネルギーカードのトラッシュだけを決め、その個体が効果を受けない・「とうめい」で受けないと決まりうる | HC3・T19b | マイクロウェーブ |

- 選ぶ前に投げる要素のコイン（のびるベロ・こばんなげ・きあいだま の `local_coin`）は、選べるどのポケモンでもそのダメージが無効なら投げるかが決められないので、v0.4b の問いでコインの前に
  止めます（選べるのが相手の対戦ポケモンだけなら v0.44 と同じ `void_coin_question`）。

### 3.3 選んだ個体へのダメージ

- `programs.TargetDamage` は、選んだ個体の今の場所で受けるポケモンの種類を決めます（相手の対戦ポケモンは p.320 の (1)、相手の控えは (2)、ワザを使ったポケモン自身は (3)、自分の控えは (4)。
  `target_kind`）。対戦ポケモン・自分へのダメージは `Damage` と同じ経路で、同じ段階の順番の決定（v0.35）・お上品攻撃の減らす量の決定（v0.66）を出せます（`programs.element_target`）。
  控えポケモンへのダメージは `guarded_damages`（v0.65 の［ベンチガード］。自分の控えへのダメージでも聞く）。
- 項目: `weakness_resistance`（偽なら「弱点・抵抗力」に関係なく）・`wr_unstated`（JS1）・`local_gate`（「その後、コインを投げて「おもて」なら」）・`gate`（ワザ全体のコイン）・
  `defender_effects`・`ignore_scope`（4 章）。基本となるダメージの値のコイン（マジックダーツ・ねらいだま）は選んでから投げます。
- 決定を出す要素より前の結果のうち、続きの情報で運ばないものをあとの要素が読むかの確かめ（v0.35。`programs._uncarried_results_used_later`）は、運ぶ `ChosenTarget`・`ChosenColor` を
  数えないようにしました（6 章）。
- `programs.TargetHeal`（きずをなめる）: のっている数までとりのぞき、0 個のポケモンは効果を受けません（GR-2000-P320-RECOVERY）。とりのぞく前に「ワザをうけない」状態・「とうめい」を評価します
  （`reaches` の `heal`。自分のポケモンでも）。ログは v0.41 と同じ `attack_heal`（相手のポケモンなら `attacker` つき）。

## 4. 「弱点・抵抗力・特殊能力・その他の効果」に関係なく与えるダメージ（だましうち）と FA1

### 4.1 控えポケモンへのダメージにも除く指定を通す

v0.60 のスピードスター（`Damage` の `defender_effects=False`）は相手の対戦ポケモンへのダメージだけでした。v0.89 から、`kernel.deal_damage` は相手の控えポケモンへのダメージにも
`defender_effects=False` を受け付け、`guarded_damages`・［ベンチガード］の続きの情報（並びの 5 つめ。4 つの並びは v0.88 までの形のまま読む）・`resume_guarded` も同じ指定で計算します。
除くのは今までどおり受けるポケモン自身の持っている効果（弱点・抵抗力・ついているカード・持続する効果・特殊能力・「とうめい」・かげぶんしん）で、ワザを使うポケモン・プレイヤー・スタジアムの
効果と、ダメージを受けたあとの反応（はんげき・返す効果・こんじょう）は今までどおりです（実装上の読み方。v0.60 と同じ）。

### 4.2 除く範囲の 2 つの書き方

- `kernel.IGNORE_HELD`: 説明が「相手の持っている」と書く（スピードスター）。v0.60 の処理のままで、相手の場のほかのポケモンの特殊能力を含むかは SS1（コードのない問い）。
- `kernel.IGNORE_UNSTATED`: 説明がだれの効果かを書かない（だましうち）。読み方で結果が変われば FA1。

### 4.3 FA1（`UNRESOLVED_IGNORED_EFFECTS_SCOPE`。問い `ignored_effects_scope`）

だましうちの「「弱点・抵抗力・特殊能力・その他の効果」に関係なく」（「相手の持っている」「そのポケモンの持っている」のない書き方）が除く範囲は、印刷の文面・kyuura の記録から決められません。
`kernel.ignored_effects_scope_difference` が 3 つの読み方の受けるダメージを比べ（どれも弱点・抵抗力は計算しない。状態を変えず、乱数を使わない）、変わるときだけ止めます。

- A: 受けるポケモン自身の持っている効果だけを除く（スピードスターと同じ。実際に与えるのはこの読み方の量）
- A': 受けるポケモンの持ち主の場のポケモンの持っている効果も除く（SS1 と同じ比べ）
- B: すべての効果を除く（基本となるダメージのまま）

受けるポケモン自身の持っていない、ダメージの要素を無効にする効果（見えない壁・こおりのはしら・［オーロラヴェール］など）・［ベンチガード］は A だけにあるので、当てはまれば変わります。
お上品攻撃の減らす量・順番の決定が要る計算は B と変わります。

- 止める時点: 選ぶ決定で、読み方で変わるポケモンは選べるが選ぶと止める（その答えを受け付けない）。どのポケモンでも変わるなら、ワザの宣言の前に止めます（先読みが見つける）。うらのカードを
  おもてにしたあとなど、選ぶ前に確かめられなかった場合は、ダメージを与える直前（`kernel.deal_damage`）の確かめが同じ問いで止め、先読みがこれもワザの宣言の前に見つけます。どれも状態・乱数・
  ログを変えません。
- だましうちは「悪」エネルギー 2 個が要るので、悪エネルギー（v0.78）をつけていれば、相手の対戦ポケモンへのダメージは A の 5 段階の + 10 で B と変わり、選ぶと止めます。相手の控えへのダメージは
  悪エネルギーの + 10 が当たらない（v0.78 の 1.2 節）ので、ほかの効果がなければ止めません。［エナジーコンバーター］で「悪」にした基本エネルギーカード・ミラクルエネルギーで払ったときは、相手の
  対戦ポケモンへのダメージも止めないことがあります。
- 読み方で変わらなかったときのダメージのログには `ignore_effects_scope: "unstated"` を書きます（スピードスターのログの形は変えていない）。
- kyuura の未解決の一覧にない論点です（研究の対応表の `not_in_kyuura`）。
