# 固定のデッキの第2版（v0.26）

v0.26 で、v0.20 の固定のデッキ（第1版）に並べて、第2版を 2 つ加えました。どれも対応済みのカードだけを使います。第1版の識別子と中身は変えていません。

- **試作の構成です。** 大会のデッキ・最適化したデッキではなく、人間どうしで勝率の釣り合いを確かめた構成でもありません。下の対戦の数字は、決まった手順（対戦相手の AI ではない）どうしの結果です。デッキの強さを示すものではありません。勝率を 50% に近づけることは目標にしていません。
- 新しいカードの効果・裁定は加えていません。次のものも変えていません。
  - `engine.py`・`resolution/`・カードの効果
  - 公開のログ・状態・書き出しの形式
  - 固定した参照データ（tests/fixtures/）
  - 研究資料（`3f34908`）とカードの写し（`ecb2d69`）の参照コミット
  - 原典の画像（読み直していない）
- 対戦の手順（tools/preset_deck_games.py の `make_policy`）も変えていません。第1版と第2版は同じ手順で比べました（5 章）。

## 1. 識別子と使い方

| 識別子 | 名前 | 版 | 枚数 |
|---|---|---|---|
| `hitmonchan-dewgong` | エビワラー・ジュゴン（デッキ A1） | 第1版（v0.20） | 60 |
| `venusaur-parasect` | フシギバナ・パラセクト（デッキ B1） | 第1版（v0.20） | 60 |
| `hitmonchan-dewgong-v2` | エビワラー・ジュゴン（第2版）（デッキ A2） | 第2版（v0.26） | 60 |
| `venusaur-parasect-v2` | フシギバナ・パラセクト（第2版）（デッキ B2） | 第2版（v0.26） | 60 |

```python
from kyuura_engine import new_game, preset_deck, preset_deck_ids, validate_deck

print(preset_deck_ids())   # ('hitmonchan-dewgong', 'venusaur-parasect', 'hitmonchan-dewgong-v2', 'venusaur-parasect-v2')

deck1 = preset_deck("venusaur-parasect-v2").cards()
validate_deck(deck0); validate_deck(deck1)
state = new_game(deck0, deck1, seed=1)
```

```bash

python3 examples/start_preset_game.py --list
python3 examples/start_preset_game.py --deck0 hitmonchan-dewgong-v2 --deck1 venusaur-parasect-v2 --seed 1 --first 0

# 決まった手順で対戦させる（--deck-a・--deck-b で組み合わせを選ぶ。既定は第1版どうし。第2版は --variant preset（既定）だけ）
python3 tools/preset_deck_games.py --games 20 --deck-a hitmonchan-dewgong-v2 --deck-b venusaur-parasect-v2 --out <結果の JSON>

# 4 組（A1 対 B1・A2 対 B1・A1 対 B2・A2 対 B2）を同じ seed・席の入れかえ・同じ手順で比べる（5 章）
python3 tools/preset_deck_comparison.py --seeds 10 --out <結果の JSON>    # 80 局（約 7 秒）
```

  - 登録とデッキは書きかえられません。
  - 知らない識別子は `KeyError`（選べる識別子を示す）です。

## 4. 第2版の変更の理由と、初期案からの調整（1 回）

### 4.1 変更の理由（第1版の対戦で分かっていたこと。docs/preset-decks-v0.20.md 4.3）

| 改善したい点 | 第1版で分かっていたこと | 第2版で入れたもの |
|---|---|---|
| 必要なたね・進化先・エネルギーを探せること | どちらのデッキにも探す手段がない | パソコン通信 3（両方）、ポケモン交換おじさん（B2） |
| デッキ B のたね不足と進化カードの余り | たねポケモン 8 枚で引き直しが多い。ベンチが空のまま負ける。使わない進化カードが 1 局あたり約 5 枚残る | たね 10 枚（モンジャラ 2）、フシギソウ 4 → 2・パラセクト 3 → 2 |
| オーキドはかせで捨てたエネルギーの再利用 | オーキドはかせで捨てたエネルギーを戻せない | エネルギー回収 2（両方） |
| 育て屋さんと通常の進化の使い分け | フシギバナが出るまで時間がかかる | フシギソウ 2 を残し、ポケモン育て屋さん 2（B2） |

ディフェンダーは、この 4 つの目的に関わらないので外しました。強さを比べて外したのではありません。

## 5. 比べ方

- **組と局**: A1 対 B1・A2 対 B1・A1 対 B2・A2 対 B2 の 4 組です。
  - 主な比較は、どの組も同じ 10 個の seed（0〜9）を、デッキ A がプレイヤー 0 の席と 1 の席で 1 局ずつ使った 20 局、合計 80 局です。
  - 先攻・後攻は seed の偶奇です（tools/preset_deck_games.py と同じ）。
  - 補足に 320 局（seed 0〜39。7 章）を 1 回だけ走らせました。
- **手順は 4 組とも同じです**: tools/preset_deck_games.py の `play`（変種 `preset`。`observe=True` は数えるだけで、選ぶ操作を変えない。tests/test_preset_decks_v0_26.py が確かめる）。
  - 手順には、v0.21〜v0.25 で加えたカードの手順（突風・パソコン通信・エネルギー回収・ポケモン交換おじさん・ポケモン育て屋さん）がいつも入っています。手札にないカードの手順は何もしません。
  - そのため、第1版も第2版も同じ手順（同じ関数）で測りました。比較のために手順は変えていません。既存の 7 つの変種の結果は v0.25 と同じです（docs/v0.26-verification.md）。
- **同じ seed の意味**: 山札の切り方はデッキの中身によらず、並びの位置で決まります。A1 と A2 は並びの最初の 14 枚（ポケモン）が同じなので、同じ seed では手札・山札のポケモンの位置が同じです。そのため、引き直しも同じです。トレーナー・エネルギーの位置は違います。B1 と B2 はポケモンの並びが違うので、そろいません。
- **数え方**（tools/preset_deck_comparison.py）:
  - **ログから数えるもの**: 切り直し・番・ワザ・ワザを使わずに終えた番・エネルギー（タイプとつけた先）・進化（ログ `evolve` の `trainer_card` で、ポケモン育て屋さん経由かを分ける）・トレーナー・エナジートランス・きぜつ・山札切れ・負けた条件。
  - **「攻撃できなかった番」**: 受け付けた操作の列を `new_game` からやり直し、ワザを使わずに番を終えた直前の状態で、バトル場のポケモンのすべてのワザの `UseAttack` をエンジンに渡しました。受け付けたら「攻撃できた」、拒否されたらそのコードを理由にします。手順が攻撃しなかったことから理由を推測していません。
  - **エネルギー不足の内訳**: いちばん少ないエネルギーで使えるワザについて、次の 3 つに分けました。
    - 色（枚数は足りるがタイプが足りない）
    - 枚数（タイプは足りるが枚数が足りない）
    - 両方
- **終わり方の分類**: 次のものを分けて数えました。
  - 通常の勝敗（山札切れの内訳つき）・サドンデス
  - 既知の未解決の裁定による停止（`halted`）
  - `UNRESOLVED_…` の拒否のあと続けた回数
  - 手数の上限・想定外の拒否・内部エラー
  - 監査の失敗（不変条件・ログの監査・書き出しの監査・トレーナーのログの並び・決定ごとの持ち主と使用中のカード・やり直しの一致）
- **分母**: 表ごとに書きました。
  - 「回数（局数）」は、その組の番のあった局で数えた回数と、1 回以上あった局の数です。1 局に何回も起こる出来事（使用・進化・攻撃）は回数で、局数と混ぜていません。
  - 対戦準備で止まった局（既知の停止）には番がないので、番を数える指標の分母に入りません。引き直しは対戦準備の出来事なので、すべての局で数えました。

## 9. 自動操作の限界（この比較の数字を読むときの注意）

- **AI ではない**: 手順は既存の統合テストの決まった手順（tests/test_dark_wartortle_games_v0_13.py の `policy_command`）に、v0.20〜v0.25 の手順を重ねたものです（docs/preset-decks-v0.20.md 5 章・tools/preset_deck_games.py の説明）。対戦相手の AI ではなく、合法手の一覧も作っていません。
- **攻撃を逃していない**: 比べた対戦では、手順はワザを使える番にワザを使わずに終えることはありませんでした（「攻撃できた」番は 0）。そのため、「ワザを使わずに終えた番」は、その時点のバトル場のポケモンでは攻撃できなかった番です。ただし、その番のほかの操作（エネルギーのつけ先・にげる・入れ替え）を変えれば攻撃できたかは確かめていません。
- **コラッタを交代役に使えていない**: コラッタはにげるエネルギーが 0 の交代役のつもりですが、手順はコラッタを交代役として十分に使えていません。
  - コラッタからにげた回数は 80 局で 0 でした。
  - コラッタがバトル場に出たのは、ポケモンいれかえ・バトル場に出すときの「ベンチの先頭」の選び方によるもので、出たあとはかみつくで攻撃していました。
- **育て屋さんの使い方**: 育て屋さんの手順は、通常の進化を含むその番のほかの操作のあとで考えます。そのため、手札にフシギソウもあれば、先にフシギソウに進化させます。
  - 320 局の B2 の局で、フシギソウへの進化 167 回のうち、手札にフシギバナと育て屋さんがあった進化は 3 回でした。
  - パソコン通信・ポケモン交換おじさんの手順は、場のポケモンから通常の進化でつながる進化カードしか探しません。そのため、育て屋さんと組み合わせるためにフシギバナを探すことはしません。手札の育て屋さんは、組がなくて使わなかった番が多い（320 局で 635 回の判断、使ったのは 37 回）です。
- **使う前の確かめ**: 既存の駆動の方針は変えていません。原典で決められない場合に当たらないよう、使う前に対象があるかを確かめています。
  - エネルギー回収は、トラッシュに基本エネルギーがなければ使いません。
  - 突風は、相手に控えがいなければ使いません。
  - パソコン通信は、山札が 0 枚なら使いません。
  - そのため、`UNRESOLVED_…` の拒否は 0 回でした。
- **既知の停止**: 対戦準備の切り直しでは、既知の未解決の裁定（`UNRESOLVED_MULLIGAN_COMPENSATION`）で止まる局があります（80 局で 2 局・320 局で 20 局）。避けるためにデッキ・ルールを変えていません。
