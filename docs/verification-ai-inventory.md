# 検証用 AI の V0〜V3-3 と U7 の残件の一覧（v0.173 の時点）

検証用 AI の V0〜V3-3（[V0](verification-ai-v0.md)・[V1](verification-ai-v1.md)・[V2](verification-ai-v2.md)・[V2 の補完](verification-ai-v2-repeat.md)・[V3 の設計](verification-ai-v3-design.md)・
[V3-1](verification-ai-v3-1.md)・[V3-2](verification-ai-v3-2.md)・[V3-3](verification-ai-v3-3.md)）と、U7（[U7-5f・U7-5g](legal-actions-u7-5fg.md)・
[U7 の総合検証](u7-integration-verification-plan.md)）の文書・実装・既存の証跡から、残件をまとめました。棚卸しだけで、ここに挙げた残件の実装は始めていません。

読み方:

- 「未到達」は、実装・API はあるが、実際の対戦（new_game から）で届いていないもの。未実装とは分ける
- 「確かめた」は、証跡（`C:/dev/kyuura-engine-verification-vai/`）やテストの実行の記録があるものだけ。文書に書いてあるだけのものは確かめたとしない
- 優先度は、ゲームの進行・情報境界・公開の API の利用への影響で決めた（AI の仕組みを増やすことは優先の理由にしない）

## 9. 次に進める重要な項目（最大 3 件）

1. **R-5（入力を返さない決定・候補）の監査を進める**: 回答者が U7 で答えられないと対戦が止まり、GUI などのクライアントが公開の API だけで進められない。ゲームの進行と公開の API の
   利用への影響がいちばん大きい。最初の作業は、`DISCLOSURE_CONFIRMED_KINDS` にない決定の種類と出る場面の静的な索引（エンジンは変えない）
2. **準備の停止（`UNRESOLVED_MULLIGAN_COMPENSATION`）の扱いを規約集合ごとに確かめる**: 固定デッキの対戦が seed によって開始の時点で止まる（V1・V2）。ゲームの進行に直結する。
   最初の作業は、S2A・PO の規約集合での同じ seed の開始だけの確かめと記録（続行の規約の採用は利用者の判断）
3. **R-2・R-3・UP-5t（うらのカードと、状態の複製の上の試行の読む先）の情報境界の監査**: 本人の知識だけで決められる入力の範囲と、候補の作成が秘密を読まないことの確かめが一部
   残っている。情報境界への影響があるので、AI の機能より先に読む先の記録を作る
