## 2. バリアーに対するコインの扱い

### 2.1 何がずれていたか

v0.33 までは、要素の並びのコインが、受ける側の状態を次のように見ていました。

- パルシェンの「からではさむ」（`FailOnTails` の `with_effect`。v0.33）: バリアーの相手には、宣言の前に HC3（`UNRESOLVED_PREVENTED_EFFECT_COIN`）で止める。
- ロケット団のベトベターの「ねばりつく」・サカキのゴーリキーの「じごくがため」（`CoinBonusDamageAndParalyze`。要素 `Coin` → 追加のダメージ → マヒ）: バリアーの
  相手にもコインを投げ、ダメージ（`damage_prevented`）とマヒ（`effect_prevented`）がどちらも無効になる。

止めるかどうかを、ワザの型の旗（`with_effect` など）で決めていて、コインが何を決めるかを見ていなかったため、同じ形のワザで扱いがそろっていませんでした。

### 2.3 直し方（カード id で分けない）

要素の並びのコイン（`Coin`）と、失敗するコイン（`FailOnTails`）は、投げる前に `programs.void_coin_question` を呼びます。

- コインの結果で処理が決まる要素を、要素の並びから求める（`Element.coin_dependent`: ワザ全体のコインの `gate`・ダメージの量の値が使うコイン・
  「おもて」の数でトラッシュする数。`FailOnTails` は、そのあとの要素すべて）。
- それぞれの要素が相手の対戦ポケモンへのものか（`Element.coin_receiver`: 相手へのダメージの要素は `"damage"`、相手への効果の要素は `"effect"`、ほかは None）。
- どれかが None（自分へのダメージ・自分への効果・トラッシュ・ドローなど）なら投げる。すべてが相手の対戦ポケモンへの要素なら、
  - 前の要素の「とうめい」で受けないと決まっていれば T19b（`UNRESOLVED_EVADED_EFFECT_COIN`）
  - 効果の要素を含み、相手が効果の要素も無効にする状態（バリアー）なら HC3
  - ダメージの要素だけで、相手がダメージの要素を無効にする状態（かたまる・バリアー）なら v0.4b の `UNRESOLVED_PREVENTED_COIN_DAMAGE`
  - どれでもなければ投げる

先読みがすべての結果を試すので、どの場合も宣言の前に止まります（状態・乱数・ログは変わらない）。`FailOnTails` の旗（`only_damage`・`with_effect`）は外しました
（要素の並びから同じ答えが出る。v0.33 の `test_programs` を直した）。

製品の登録表で、バリアーの相手に止まるコインを持つ型は `CoinBonusDamageAndParalyze`・`DamageAndParalyzeOnHeadsElseFail`・`FailOnTailsDamage` の 3 つで、
ほかのコインを持つ型（`CoinBonusDamageThenDiscardAll`・`CoinBonusDiscardThenDamage`・`CoinBonusOrSelfDamage`・`CoinsDiscardThenSpreadDamage`・
`CoinsPerEnergyDamageThenDiscard`・`FailOnTailsDiscardThenDamage`・`SelfDamageInsteadOnTails`・`ThreeCoinPsychicPower`）は投げます
（tests/test_barrier_resume_coin_bonus_v0_34.py `BarrierCoinTest.test_stopping_types_follow_from_the_programs` が要素の並びから求めて確かめる）。

### 2.4 変わる既存の動作

ねばりつく・じごくがためをバリアーのミュウツーに使う場面だけが変わります（コインを投げてダメージとマヒが無効 → 宣言の前に HC3）。同じ形のからではさむ（v0.33）と
同じ扱いになりました。8 章の比較の対戦には出ないので、固定した v0.33 の木と今の木で、同じ盤面を 1 つずつ確かめました（8.3）。

## 3. ダメージのあとの決定をまたぐ処理

### 3.1 何が足りなかったか

v0.33 のかけぬける（カツラのサイホーン）は、相手の対戦ポケモンへのダメージのあと、コインが「おもて」なら相手の控えを選ぶ決定を出します。相手の対戦ポケモンが
カイリキー（「はんげき」）なら、「はんげき」は送る効果（`fs.pending`）としてダメージの要素のあとの窓（p.89）まで待ちますが、決定を出すと枠の値がなくなるので、
v0.33 はエンジンの未対応として宣言の前に止めていました（`UNSUPPORTED_DECISION_AFTER_DAMAGE_TRIGGER`）。ルールの問いではなく、エンジンが続きの情報を持てない
ことによる技術的な未対応でした。

### 3.2 運ぶもの

決定は今までどおり 1 つで、続きの情報は既存の決定の `context` の `frame`（v0.31 の `carry`）に明示的なデータで持ちます（`PendingDecision` に項目を加えていない。
書き出しの形式 10 のまま）。v0.34 で加えたのは `frame` の `pending` だけです（送る効果があるときだけ。ないときは v0.33 と同じ形）。

| 項目 | 中身 | 再開のとき |
|---|---|---|
| `reception`（v0.31） | 「とうめい」の結果（1 つのワザで 1 匹 1 回。T4） | 同じ結果を使う（投げ直さない） |
| `fired`（v0.31） | この枠で処理した送る効果の数（C34・C35） | 2 つ目は C34・C35 の問い |
| `guts`（v0.31） | こんじょうを使えるかの写し（受けたときの特殊状態） | きぜつの判定で使う |
| `pending`（v0.34） | まだ処理していない送る効果ごとに (持ち主, 持つポケモンの番号, 効果の定義の名前, 受けたダメージ) | `kernel.restore_deferred` が今の場の効果から作り直す（同じポケモンに同じ名前の送る効果がちょうど 1 つ。なければ続きの情報の誤り） |
| `coins`（v0.31） | ワザ全体のコインの結果 | 投げ直さない |

受けたときの「はたらいているか」（特殊状態の「すでに」・かがくへんかガス・はたらく番）は受けたときに確かめたので、再開のときに確かめ直しません。決定を待つ間は
場が変わらないので、作り直した効果は受けたときと同じです。エンジンの不変条件（`engine._carried_deferred_problems`）が、運んでいる効果ごとに、形・重複・場の
ポケモンと持ち主・その効果があること・「相手のワザによって」の効果の持ち主・今のワザのダメージのログ（同じポケモン・受けたダメージと同じ量）を確かめます。

### 3.3 順番

うしろなげ（v0.34）・かけぬける（v0.33）の順番は、相手の対戦ポケモンへのダメージ → コイン → 控えを選ぶ決定 → 控えへのダメージ → 送る効果（はんげきなど）→
（ダメージ以外の効果の要素）→ きぜつの判定（`_finish_attack`）です。「ダメージを受けたとき」の効果は、そのワザのダメージの要素（控えへのダメージを含む）が
すべて終わったあとに処理する（p.89 の「こうらがえし」の解説。v0.10 からの規定）ので、決定の前には処理しません。きぜつの判定は今までどおりすべての処理の
あとです。

### 3.4 確かめたこと

- 不正な答え（相手のプレイヤー・相手の控え・2 匹・0 匹・古い決定 id）は拒否し、決定と運んでいる効果はそのまま（状態・乱数・ログが変わらない）。
- 再開しても、ダメージ・コイン・送る効果を繰り返さない（はんげきは 1 回、コインは 1 枚）。
- 決定を待つ状態を複製（`clone`・`deepcopy`・`pickle`）して再開しても結果は同じ。書き出しの監査も通る。
- 運んでいる効果の記録を壊すと不変条件の違反になる（受けたダメージ・持ち主・効果の名前）。
- 宣言の前の先読みは、ワザの全体（決定のすべての答え）を 1 つの解決の中で試すので、決定をまたいでも C18（`UNRESOLVED_COUNTERATTACK_DOUBLE_KNOCKOUT`）などを
  宣言の前に見つける。先読みの方法（`derived`・`derived_full`・`legacy`）で結果が同じ。
- ルールの問いは今までどおり止める: 選んだ相手の控えも「はんげき」を持つ（1 つのワザで 2 つの「はんげき」）なら C34・C35
  （`UNRESOLVED_MULTIPLE_DAMAGE_TRIGGERS`）。これはエンジンの未対応ではなく、原典で決められない順番なので、推測で処理しない。

テストは tests/test_barrier_resume_coin_bonus_v0_34.py `CarryAcrossDecisionTest`（うしろなげ）と tests/test_cd4_opponent_energy_coins_v0_33.py
`test_decision_after_damage_trigger_is_carried`（かけぬける。v0.33 の止まるテストを、処理するテストに置きかえた）。tests/test_mid_window_decisions_v0_18d.py の
設計の前提（`carry` でない決定の前に送る効果が残っていればエンジンの不具合）は変えていません（変異 V02 の定義を、今のコードに同じ誤りを入れる形に直した）。

pcg-search.com の同じ版（第2弾 044/048）と照らすと、こどものおつかいの文面が違いました。

- kyuura:「コインを投げて「おもて」なら、自分の山札の上からカードを1枚ひいて、手札に加える。」
- pcg-search.com:「自分の山札の上からカードを1枚ひいて、手札に加える。」

コインの有無で、引くかどうかと乱数の使い方が変わる（挙動に影響する）ので、このカードだけを保留にしました（`card_sources.json` の `on_hold`。論点を記録。登録
しない）。kyuura の日本語の文面の元（`ja_text_source`）は nazonobasho.com で、どちらが正しいかは記録では決まりません。ガイドブックは読んでいません（方針）。
kyuura のデータ・写しは直していません（kyuura への報告事項）。れんぞくパンチの違い（サイトの脱字）は処理に影響しません。写しには保留の記録のために入れて
います（対戦には使えない）。

### 4.3 ブースターの「かえんほうしゃ」

印刷の文面は「このカードについている「炎」エネルギーカードを1枚はがしてすてなければ、このワザは失敗する。」です。

- 炎エネルギーカードをトラッシュして大きなダメージを与えるワザで、ワザの名前も kyuura の RUL-ENERGY-DISCARD-ATTACKS（確実）が挙げる「かえんほうしゃ」なので、
  トラッシュの時点は記録の範囲としてワザの効果にしました（v0.31 のカツラのウインディの「ほのおのあらし」と同じ扱い）。こんらんの「うら」ではトラッシュしません
  （HC1 で止めない）。
- 記録の最新の説明（「…トラッシュできないとき、このワザのダメージはなくなる。」）は、印刷の文面が第1弾のウインディと同じカードに当てはめるもので、この
  カードの印刷の文面は違う（トラッシュできなければ失敗）ので、処理に使う文面は印刷の文面です（研究の対応表の `adopted_printed_text`。`errata_text` にしない）。
- トラッシュできない場合は、ワザに必要なエネルギーから、相手のワザとして使うとき（ゆびをふる）だけ起こり、ワザの失敗（p.323）になります。
- 記録の `cards` にこのカードがないことは kyuura への報告事項です（v0.30 のヒトカゲ・リザード・ブーバーと同じ）。

## 5. 特殊などく（ニドキングの「どくどく」）

「相手に「どく」カウンターを2個のせ、ポケモンチェックごとに20の「どく」ダメージ。」

| id | 場面 | 処理 | 根拠・分類 |
|---|---|---|---|
| TP1 | どく状態でないポケモン | どく状態（受けるダメージ 20。`Poison(damage=20)`）にする。ポケモンチェックで 20 | p.322「どく状態にかかる」もの（docs/special-conditions-v0.3a.md の 13。CONFIRMED）。通常のどくを 2 回にする処理ではない |
| TP2 | 特殊などくのポケモンが通常のどくを受ける | 通常のどく状態（10）になる（既存の `conditions.poison`） | p.322（v0.3a の 14。CONFIRMED） |
| TP3 | 通常のどく（10）のポケモン・受けるダメージの違う特殊などくのポケモンが、どくどくを受ける | 宣言の前に `UNRESOLVED_SPECIAL_POISON_OVERWRITE` で止める | p.322 は TP2 の向きだけを書く（v0.3a の 15。UNRESOLVED）。どちらの量にするかを推測しない |
| TP4 | 同じ 20 のどく状態のポケモン | 変わらない（ログ `special_condition` の `already`） | p.322「どく状態が積み重なることはありません」 |

- どくはほかの特殊状態と重複する（p.322）ので、ねむり・マヒ・こんらんを置きかえません。ベンチにもどる・進化・きぜつで消えます（既存の処理）。
- ポケモンチェックは、ポケモンごとのどくの量（`Poison.damage`）を与えます（v0.3a から）。両方の対戦ポケモンがどくできぜつする場合は、量が違っても v0.3a の
  `UNRESOLVED_POKEMON_CHECK_DOUBLE_KNOCKOUT` で止めます。
- ログは `special_condition` の `damage`（20）と `poison_damage` の `amount`（20）。書き出しは形式 5 からどくの量を書きます（変えていない。形式 1〜4 は
  特殊状態を書き出せない）。ログの監査（tests/log_audit.py）は、どく状態にしたワザの登録の量・`already`・TP3 の向きがないこと・ポケモンチェックの量が
  組み立て直したどくの量と同じことを確かめます。
- 通常のどくの動きは変えていません（`conditions.poison` の `damage` の既定は 10。8 章の比較で食い違い 0）。

## 6. カードごとの論点

### 6.1 同じコインで決める（投げ直さない）

かみなりパンチ・あばれる（要素 `Coin` → 「おもて」の追加ダメージ → 「うら」の自分へのダメージ）、くさいガス（要素 `Status` の `otherwise`: 同じコインの
「うら」の特殊状態）は、どれも 1 枚のコインで決めます。からではさむ（v0.33）と同じく、効果のためにコインを投げ直しません。

### 6.2 なきつく（カラカラ）

「「なきつく」を受けた相手は、このカードにワザを使う時、与えるダメージが20へる。この状態は次の自分の番の始めに消える。」

| id | 処理 | 根拠・分類 |
|---|---|---|
| NK1 | 効果は相手の対戦ポケモンに与える持続する効果 `ReducedDamageToSource`（発生源のカード・量・はたらく番 = 次の相手の番）。相手に与える効果なので、「ワザをうけない」状態（バリアー）なら無効、「とうめい」を評価する | 印刷の文面（「受けた相手は」）。v0.31 のしっぽをふると同じ置き場所 |
| NK2 | 受けたポケモンが「このカード」にワザでダメージを与えるとき、p.321 の 2 段階で 20 へらす（0 以下になったら計算を終え、ダメージを与えなかったことになる） | 効果を持つのはワザを使うポケモン（受けた相手）なので、p.321 の 2 段階「ワザを使うポケモンの持っている「ダメージを変更する効果」」。8 段階（受けるポケモンの効果）にしない |
| NK3 | 効果は、なきつくを使ったプレイヤーの次の番の始め（`turn_start` のすぐあと）に消える。ベンチにもどる・進化・きぜつでも消える | 印刷の文面（「次の自分の番の始めに消える」）。ほかの持続する効果（次の相手の番の終わり）と期限が違うので、型の `expires_at_turn_start` で表す |
| NK4 | 「このカード」は、なきつくを使ったカラカラのカード（発生源のカード）。効果がはたらくのは相手の番だけなので、その間にカラカラが進化・にげることはない | 番の進み方 |
| NK5 | カラカラが（突風などで）控えにいるとき、受けたポケモンのワザが控えにダメージを与えうる（かけぬけるなど）なら、決められないので宣言の前に `UNRESOLVED_REDUCED_DAMAGE_BENCH_TARGET` で止める | 「このカードにワザを使う時」に控えポケモンへのダメージを含むかが書かれていない（UNRESOLVED） |

- ワザによらないダメージ（はんげき・どく・こんらんの 20）はへらしません（こんらんの 20 は `attack_damage_modifiers` に `attack` を渡さない）。
- 同じ 2 段階に「その数にする」効果（ストライクの「つるぎのまい」）と「なきつく」が重なると、計算の順番はワザを使うプレイヤーが決める（p.321）が、その決定は
  エンジンの未対応なので、宣言の前に `UNSUPPORTED_DAMAGE_STEP_ORDER` で止めます（研究の対応表の停止コードには入れない）。
- ログ `damage` の `steps` に `("2 カラカラ（reduced_damage_to_source）", へらしたあとの数)`、`modifiers` に `(2, 発生源のカード, -20)` が入ります。ログの監査は、
  組み立て直した効果とワザのダメージごとの 2 段階の記録を照らし、期限（次の番の始め・`turn_start` のすぐあと）を確かめます。
- 書き出しは形式 8 から（持続する効果の種類 `reduced_damage_to_source`。量 `amount` を書く）。

### 6.3 持続する効果の比べ

| 効果 | 型 | 置き場所 | はたらく番 | 消える | はたらき |
|---|---|---|---|---|---|
| バリアー（ミュウツー。v0.31） | `AttackBarrier` | 自分 | 次の相手の番 | その番の終わり・ベンチ・進化・きぜつ | 相手のワザのダメージと効果の要素を無効 |
| こうそくいどう（ギャロップ。v0.34） | `AttackBarrier`（同じ型） | 自分 | 次の相手の番 | 同じ | 同じ（印刷の文面「ワザをうけない」はバリアーと同じ言い方） |
| ちいさくなる（ピクシー。v0.31） | `DamageReduction` | 自分 | 次の相手の番 | 同じ | p.321 の 8 段階で 20 へらす |
| なきつく（カラカラ。v0.34） | `ReducedDamageToSource` | 相手 | 次の相手の番 | 次の自分の番の始め・ベンチ・進化・きぜつ | 受けた相手がこのカードに与えるダメージを 2 段階で 20 へらす |

こうそくいどうのコインはダメージのあと（説明の順）で、自分への効果なので、相手がダメージを受けない状態でも投げます。ワザを使ったポケモンが相手の「はんげき」
などで HP 以上になったら、処理の対象がいないので投げません（p.309）。

### 6.4 テレポート（ナッシー）

ワザを使ったプレイヤーが自分の控えを 1 匹選び（決定 `select_pokemon`。1 匹でも出す）、ワザを使ったポケモンと入れ替えます。入れ替えはポケモンいれかえと同じ処理
（`effects._switch_active_with_bench`。にげるではない。ベンチにもどったナッシーの特殊状態・持続する効果は理由 `switch` で消える。p.311・p.322）で、ログ `switch`
に入れ替えたワザ `effect` を加えます（トレーナーの入れ替えのログは v0.33 と同じ形）。控えがいなければ何もしません（p.309。ワザは使ったことになり番は終わる）。
相手のワザとして使える（ゆびをふる）。

### 6.5 たまなげMAX（ナッシー）

「自分についているエネルギーの数だけコインを投げて「おもて」の数×20のダメージ。」

- エネルギーの数は、ワザを使うポケモンについているエネルギーの数（`state.energy_types` の数）。今の写しのエネルギーカードはどれも基本エネルギーで 1 枚が 1 つ
  なので、ついているエネルギーカードの枚数と同じです（2 つぶんのエネルギーになる特殊エネルギーを加えるときは数え方を確かめる）。
- コインはダメージの要素の中（ダメージの量だけを決める）なので、相手が「ダメージを受けない」状態なら v0.4b の `UNRESOLVED_PREVENTED_COIN_DAMAGE`。
- 先読みは既存の仕組みのまま、コインの並びのすべて（2 のエネルギーの数乗）を試します（v0.31 のれんぞくファイヤーボールと同じ）。12 枚（4,096 通り）までは
  受け付け、13 枚からは `UNSUPPORTED_PREFLIGHT_LIMIT`（v0.34 の型は `v013_checks.VERIFIED` に入れていない）。ふだんの対戦のエネルギーの数（1〜6）では 2〜64 通りで、
  上限まで調べ尽くす場面は起こりにくい。「おもて」の数だけが結果を決めることを使って結果をまとめる最適化は、先読みの共通の仕組みを変えることになるので、今回の
  範囲に入れていません。

### 6.6 たすけをよぶ（ガラガラ）

「自分の山札から「闘」ポケモンを1匹選んでベンチにだす。その後、その山札をよくきる。進化カードは選べない。自分のベンチに空きがなければ使えない。」

- v0.32 の「なかまをよぶ」（名前で選ぶ）と同じ要素 `BenchFromDeck` の、タイプで選ぶ形（`pokemon_type`）。選べるのは山札の、タイプが闘のたねポケモン
  （`bench_from_deck_candidates`）。進化カード・ほかのタイプのたねポケモンは選べません。
- ベンチに空きがないことはワザを使うための条件（`BENCH_FULL`。こんらんのコインの前）。山札に選べるものがなければ出さずに切ります（p.309。ログ
  `bench_from_deck_none` に `pokemon_type`）。山札を切るのは既存の `zones.shuffle_deck` で、先読みでは切りません。

## 8. 既存のカードへの影響と互換性

### 8.1 公開の API・ログ・形式の変更

- 公開の API・書き出しの形式（10）・決定の種類・ログのイベントの種類は変えていません。
- ログ: `switch` に `effect`（テレポートのときだけ）、`special_condition`（どく）の `damage` が 20 のことがある（どくどく）、`bench_from_deck_none` に
  `pokemon_type`（たすけをよぶのときだけ）、`damage` の `steps`・`modifiers` に 2 段階の「なきつく」。
- 持続する効果の種類 `reduced_damage_to_source`（`state.ReducedDamageToSource`。形式 8 から。量を書く）。ワザの要素の種類 `reduced_damage`（`ATTACK_ELEMENTS`）。
- ワザの途中の決定の `context` の `frame` に `pending`（送る効果を運ぶときだけ）。
- 内部の関数: `conditions.poison` に `damage`（既定 10）、`effects._switch_active_with_bench` に `effect`（既定 None）、`effects.bench_from_deck_candidates` に
  `pokemon_type`、`DiscardEnergyBeforeDamage` の `when_lacking` に `"fail"`、`CoinBonusDamage.check` が説明の追加ダメージの数を照らす（既存の登録はどれも合う）。
- 問いの表: `special_poison_overwrite`（TP3）・`reduced_damage_bench_target`（NK5）・`damage_step_order`（`UNSUPPORTED_`）を加え、`decision_after_damage_trigger`
  を外した。

### 8.2 固定した v0.33 との比較

固定した v0.33（`382fed4`。`tools/engine_lockstep.py tree` で展開した木）と、別のプロセスで比べました（最終のコード）。

  前の版のカードは上の比較の対戦にほとんど出ないので、tools/existing_effect_games.py の `--batch v0.30`・`v0.31`・`v0.32`・`v0.33`（各組・各席 5 seed。130 局・

### 8.3 変えた既存の動作の個別の確かめ

上の対戦には、2.4 と 3 章の場面が出ませんでした（どのデッキにもねばりつく・じごくがためとバリアーの組がなく、かけぬけるの場面も seed 0〜4 で起こらなかった）。
