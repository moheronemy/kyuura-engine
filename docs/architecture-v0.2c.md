# v0.2c のアーキテクチャ（プラスパワーと、場に残るトレーナー）

v0.2c は、プラスパワー（PMCG1-081）を実装し、そのために「ポケモンについて場に残るトレーナーカード」「有効期限と終わるときの処理」「ダメージ計算の段階への効果の適用」を加えた版です。原典の照合と裁定は [pluspower-v0.2c.md](pluspower-v0.2c.md) にあります。

## 1. 目的と範囲

- プラスパワーの効果を、『オフィシャルブック2000』p.257 の最新の説明と p.321 のダメージ計算の順番どおりに処理する。
- 場に残るトレーナーカードを、カードの保存則の中で管理する。
- 効果の始まり（つける）・適用（ダメージ計算）・終わり（番の終わり・場を離れる）を分ける。
- 既存の対戦結果・再現性・カードの保存則を変えない。

作らなかったもの: 汎用のカード効果の記述言語、持続する効果（ワザによる「すなかけ」など）の仕組み、加算でないダメージ変更効果とその順番の選択、スタジアム・ポケモンのどうぐ全般。

## 2. 変更の概要

| 項目 | v0.2b | v0.2c |
|---|---|---|
| トレーナーの行き先 | 使い終わったらトラッシュ（使いすて） | `TrainerEffect.stays_in_play` が真なら、説明にしたがって場のポケモンにつき、トラッシュしない |
| 場のポケモン | カード・エネルギー・ダメージ・番号 | `PokemonInPlay.trainers`（ついているトレーナー、`AttachedTrainer` のリスト）を加えた |
| 番の終わり | ログ `turn_end` → ポケモンチェック | その前に、有効期限が今の番のついているトレーナーをトラッシュする（`_discard_expired_attachments`） |
| きぜつ | ポケモンとエネルギーをトラッシュ | ついているトレーナーもトラッシュ（ログ `knock_out` に `discarded_trainers`。あるときだけ） |
| ダメージ計算 | 1・3・4 段階 | 2・5〜8 段階に加算の変更効果（`DamageModifier`）を渡せる。プラスパワーは 5 段階 |
| 効果の登録表 | id `kyuura-engine-0.2b`、トレーナー 3 枚 | id `kyuura-engine-0.2c`、プラスパワーを加えて 4 枚 |
| 状態の辞書 | 形式 1〜3 | 形式 4（場のポケモンごとの `trainers`）。形式 1〜3 は、ついているトレーナーがあると `ValueError` |
| カードデータの写し | — | `pool_v0_2c`（PMCG1-081） |

新しいファイルはありません（`state.AttachedTrainer`、`zones.attach_trainer`、`damage.DamageModifier`、`effects.AttachedAttackBonus` を既存のモジュールに加えた）。

## 3. カードのライフサイクル

```
使いすて（マサキ・きずぐすり・ポケモンいれかえ）:
  手札 ──PlayTrainer──▶ 使用中（trainer_in_use）──説明にしたがう（決定を待つこともある）──▶ トラッシュ

つけて使う（プラスパワー）:
  手札 ──PlayTrainer──▶ 使用中（trainer_in_use）──resolve: attach_trainer──▶ ポケモンについている（PokemonInPlay.trainers）
       ├─ ワザ: ダメージ計算の 5 段階で効果を出す（何度でも。番の中でワザは 1 回）
       ├─ にげる・ポケモンいれかえ: ポケモンといっしょに移る
       ├─ 番の終わり（discard_at_end_of_turn の番）: トラッシュ（discard_attached_trainer）
       ├─ きぜつ: ポケモンといっしょにトラッシュ（knock_out.discarded_trainers）
       └─ 勝敗が決まる: 対戦が終わる（番の終わりは来ない。ついたまま最後の状態に残る）
```

- 使用中（`trainer_in_use`、v0.2b）と、ついている（`PokemonInPlay.trainers`）は別の領域です。`attach_trainer` は使用中から外してからつけるので、同じカードが 2 か所にある状態を作りません。
- `_finish_trainer` は、使いすての実装ならトラッシュし、場に残る実装なら、カードがもう使用中にないこと（ついたこと）を確かめます（ついていなければエンジンの不具合として止める）。

## 4. 状態の作り（効果の保存場所）

### 検討した案

| 案 | 長所 | 短所 |
|---|---|---|
| A. `PokemonInPlay` がついているカードを持つ（採用） | 原典の「ついているトレーナーは、そのポケモンのいる場所にある」（p.313）をそのまま表す。にげる・入れ替え・進化（場のポケモンの番号が変わらない）でいっしょに動き、きぜつ・場を離れるときにいっしょに処理できる。効果の情報とカードの場所がずれない | ポケモンについていない持続する効果（ワザによる「すなかけ」など）は表せない |
| B. `GameState` が持続する効果を一か所で持つ（対象は `pokemon_id`） | ワザによる持続する効果も同じ形で持てる | カードの場所（ポケモン）と効果の記録を別々に持つので、きぜつ・入れ替えのたびに両方を合わせる必要があり、ずれやすい |
| C. カードの領域と効果の情報を分ける（ついているカードは A、効果の一覧は B） | 両方を表せる | 今の対応カード（プラスパワーだけ）には、必要のない仕組みが増える |

A を採用しました。プラスパワーの効果は、カードがついている間だけあり、カードから離れて残ることがないからです。効果の内容はカード id で効果の登録表から引くので、状態にはカードの uid・持ち主・有効期限だけを持ちます。

ワザによる持続する効果（「すなかけ」「まるまる」など。ベンチに戻ると消える、進化すると消える、カウンター・マーカー型は残る。pp.322〜323）を加えるときは、B の形（`GameState` の一覧、対象は `pokemon_id`、発生源・終わる条件を持つ）を別に加えます。ついているカードの効果（5・7 段階）と持続する状態の効果（2・8 段階）は、p.321 でも別の段階です。

### `AttachedTrainer`

| 項目 | 内容 |
|---|---|
| `card` | トレーナーカードの uid（効果の発生源） |
| `player` | 使ったプレイヤー（カードの持ち主。トラッシュはこのプレイヤーのトラッシュへ） |
| `discard_at_end_of_turn` | この番（`GameState.turn_number`）の終わりにトラッシュする（有効期限） |
| 対象 | ついているポケモン（入れ物の `PokemonInPlay`。`pokemon_id` で識別。カードの uid とは別） |
| 効果の内容 | カード id で効果の登録表から引く（`TrainerEntry.effect.damage_modifiers`） |

frozen の値なので、`clone`・`deepcopy`・`pickle` で共有しても書き換わりません。`PokemonInPlay.clone()` はリストを複製します。

## 5. 効果の始まり・適用・終わり

| 段階 | 処理 | 場所 |
|---|---|---|
| 始まり | `PlayTrainer` → `AttachedAttackBonus.resolve` → `zones.attach_trainer`（ログ `attach_trainer`） | effects.py、zones.py |
| 適用 | ワザのダメージ計算で、ワザを使うポケモンについているカード（5 段階）・受けるポケモンについているカード（7 段階）の `damage_modifiers` を集める（`effects.attack_damage_modifiers`） | effects.py、damage.py |
| 終わり（番の終わり） | `_end_turn` の最初に `_discard_expired_attachments`（ログ `discard_attached_trainer`、`reason="end_of_turn"`） | engine.py |
| 終わり（場を離れる） | `_knock_out` でポケモンといっしょにトラッシュ | engine.py |
| 終わり（対戦の終わり） | 何もしない（番の終わりが来ない。勝敗のあとに効果の処理をしない） | engine.py `_finish` |

終わるタイミングとして明示したのは「番の終わり」と「場を離れる（きぜつ）」だけです。原典にない処理（たとえば「ワザを使ったらトラッシュ」）は作っていません。

二重の処理の防止:

- 番の終わりの処理は `_end_turn` で 1 回だけ。トラッシュしたカードはポケモンから外すので、次の番に 2 回目は起こらない。
- きぜつでトラッシュしたカードは、ポケモンといっしょに場を離れるので、番の終わりに 2 回目は起こらない。
- 有効期限の過ぎたついているカードが残っている状態は、不変条件で拒否する（終わった対戦は除く）。
- 対戦が終わったあとは、どのコマンドも受け付けない（v0.1 から）ので、効果の処理は起こらない。

## 6. ダメージ計算

`damage.calculate_attack_damage(base, attacker, defender, rules, modifiers=())` に、変更効果 `DamageModifier(step, amount, label, source)` を渡します。

- `step` は 2・5・6・7・8 のどれか（p.321）。2 段階の変更のあとで 0 以下なら計算を終えます。3・4 段階（弱点・抵抗力）は今までどおり。
- 途中の 0・マイナスはそのまま次の段階に進み、最後に 0 以下なら「ダメージを与えなかった」。
- 段階の記録（ログ `damage` の `steps`）には、変更効果ごとに `("5 プラスパワー", 値)` が加わります。変更効果がなければ v0.1 と同じ記録です（固定値・互換性のテストで確かめている）。
- ログ `damage` に、変更効果があるときだけ `modifiers`（`(段階, カードの uid, 加えた数)` の組）を加えます。

### 同じ段階の順番を決めるプレイヤー

p.321: 2・5・6 段階はワザを使うプレイヤー、7・8 段階はワザを受けるプレイヤーが、同じ段階の複数の効果の計算の順番を決めます（`damage.DAMAGE_STEP_CHOOSER`。v0.1 のレビューの照合と同じ）。`DamageModifier` は加算だけを表し、加算どうしは順番で結果が変わらないので、v0.2c では選ぶ決定を出しません。加算でない変更効果（「ダメージは 0 になる」「30 以上なら受けない」など）を加えるときは、同じ段階に 2 つ以上あれば、`DAMAGE_STEP_CHOOSER` のプレイヤーに保留中の決定で順番を選ばせます。この形は、その選択権を失わないためのものです。

## 7. 保存則と不変条件

`check_invariants` に次を加えました（`_attached_trainer_problems`）。

- ついているトレーナーは、ついているポケモンの持ち主の場のカードとして数える（1 枚のカードは 1 か所だけ。消えない）。
- ついているカードはトレーナーカードで、使ったプレイヤーはポケモンの持ち主と同じ。
- 効果の登録表に、場に残る実装（`stays_in_play`）が登録されたカードだけがつく。
- 有効期限（`discard_at_end_of_turn`）が今の番より前のものは残らない（終わった対戦は除く）。

場にいないポケモンを指す効果は、構造上残りません（効果はポケモンについているカードにしかない）。

## 8. 状態の書き出し（形式 4）

| 形式 | ついているトレーナーがあるとき |
|---|---|
| 1〜3 | `ValueError`（カードを黙って落とさない） |
| 4 | 場のポケモンごとに `trainers`（`card`・`card_id`・`player`・`discard_at_end_of_turn`）を書く。ほかは形式 3 と同じ |

ついているトレーナーがない状態は、形式 1〜3 も今までどおり書き出せます（v0.1 の固定値・参照データは形式 1 のまま）。

## 9. ログと非公開の情報

加えたイベント: `attach_trainer`（`player`・`card`・`pokemon`・`pokemon_id`・`discard_at_end_of_turn`）、`discard_attached_trainer`（同じ項目と `reason`）、`damage` の `modifiers`（あるときだけ）、`knock_out` の `discarded_trainers`（あるときだけ）。どれも場・トラッシュの公開の情報です。

ログは今も内部の完全な記録です（`draw` の `cards` などの隠れた情報を含む）。見る人ごとのログはありません。公開の通信に安全なログとして使わないでください（[architecture-v0.2b.md 9 章](architecture-v0.2b.md)）。

## 10. 互換性

- v0.1 の参照データ（変えていない）の再生: 受け付けた 951 のコマンドと最後の状態（ログを含む）は同じ。エラーコードが変わるのは v0.2b と同じ `play_trainer` 38 件だけ。
- 乱数の固定値: 変わらない（プラスパワーは乱数を使わない）。
- v0.2b のトレーナー: 処理と未解決の場面（`UNRESOLVED_POTION_*`・`UNRESOLVED_SWITCH_WITHOUT_BENCH`）は変えていない。
- 既存のログの意味と順序は変えていない。ついているトレーナーがない対戦では、新しいイベント・項目は出ない。

| 将来の機能 | v0.2c の土台 | 加えるもの |

## 12. 設計上のトレードオフ

| 判断 | 理由 | 代償 |
|---|---|---|
| ついているトレーナーを `PokemonInPlay` に持たせた | 原典の「ポケモンのいる場所にある」（p.313）をそのまま表す。動き・きぜつで効果とカードがずれない | ポケモンについていない持続する効果は、別の仕組みが要る |
| 有効期限を「番号の番の終わり」だけで表した | プラスパワー（使った番）とディフェンダー（次の相手の番）を同じ形で表せる | 「次に〜するまで」のような条件で終わる効果は表せない |
| 変更効果を加算だけにした | プラスパワーに必要な範囲。加算は順番で結果が変わらない | 加算でない効果を加えるときに、型と順番の決定を加える |
| 形式 4 を加え、形式 1〜3 は拒否する | カードが消えたように見える辞書を作らない | トレーナーのある対戦では形式 4 を使う必要がある |
| 番の終わりのトラッシュを、ログ `turn_end` の前にした | 番の終わり（その番の中）の処理で、ポケモンチェックより前（p.309・p.323） | — |
