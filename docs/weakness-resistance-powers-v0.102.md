# v0.102: トランセル・バリヤードと、弱点・抵抗力の影響を受けない特殊能力の共通の問い合わせ

v0.102 は、トランセル（［グリーンシールド］・「ふしぎなこな」）2 枚とバリヤード（［ニュートラルダメージ］・「ジャグリング」）2 枚を、ワザ 4・特殊能力 4 とともに登録する版です。ワザは既存の型
（`ConfuseOnHeads`・`CoinFlipDamage(4, 10)`）を使います。2 つの特殊能力のために、ダメージの計算で弱点・抵抗力（p.321 の 3・4 段階）を当てはめるかを、受ける個体・持ち主・場所・
今のタイプの読み方・力の発生源・除く効果の範囲から答える共通の問い合わせ（`effects.weakness_resistance_ignored`。受ける個体の文脈は `effects.Receiving`）を加え、ワザのダメージを計算する
すべての所（`effects.calculate_with_stadium`）・こんらんのダメージ・ワザでないダメージで弱点・抵抗力を計算するかの比べ（Z9）が同じ答えを使うようにしました。写しの元と研究の基準は
v0.97 のまま（kyuura `73a1690`）、書き出しの形式は 26 のままです。

## 3. 2 つの特殊能力の条件

どちらも常にはたらく特殊能力（`ContinuousPower` の部分型 `WeaknessResistancePower`）で、宣言・コイン・使った記録はありません（`UsePokemonPower` は既存の `POWER_NOT_DECLARABLE`）。
はたらいているかは問い合わせのたびに今の場から求めます（`continuous_powers`: いちばん上のカードの今の姿の特殊能力・場所・特殊状態・かがくへんかガス・まきちらせ!ベトベトガス・ふしぎなガス・
スタンウェーブ・オールクリアなどの共通の確かめ）。状態に「はたらいている」印を持たないので、進化・入れ替え・場をはなれる・特殊状態の変化・抑止とその復帰・保存と復元のあとも、その時点の
場から同じ答えになります。カード id による分岐を `engine.py`・`resolution/` に加えていません。

### 3.1 ［グリーンシールド］（`IgnoreWeaknessForOwnType`）

- 発生源: このカードが場（バトル場・ベンチ）にいればはたらきます（「場にいる限り」）。このカード（発生源）がねむり・マヒ・こんらんなら力は消えます（`blocked_by_status`）。受けるポケモンの
  特殊状態ではありません（受けるマダツボミがねむりでも、ベンチのトランセルの力ははたらく。`GreenShieldTest.test_holder_status_removes_the_power_but_receiver_status_does_not`）。
- 当てはまる受け手: このカードの持ち主の場のポケモンで、今のタイプ（色の読み方ごと。色マーカー・［へんしょく］などで変わったタイプ）が「草」のもの。このカード自身も含みます。相手の
  草ポケモン、自分の草以外のポケモンには当てはまりません。色マーカーで「草」になったポケモンは守り、「草」でなくなったポケモンは守りません（`test_type_changes_use_the_current_type`）。
- 影響を受けないのは弱点（3 段階）だけです。抵抗力（4 段階）は当てはめます（`test_resistance_is_kept`）。

### 3.2 ［ニュートラルダメージ］（`IgnoreWeaknessResistanceForActives`）

- 発生源: このカードがベンチにいるときだけはたらきます（`CONTINUOUS_BENCH`）。バトル場に出たら、このカードの力は当てはまりません（ほかのベンチのバリヤードの力は残る）。日本語の文面に
  特殊状態の条件はないので、条件を加えていません（`blocked_by_status` は偽）。
- 当てはまる受け手: お互いのプレイヤーのバトル場のポケモン（ダメージを受ける時の今の場所）。受け手の持ち主・ワザを使う側のどちらのベンチの力も当てはまります。控えの受け手には
  当てはまりません。弱点（3 段階）・抵抗力（4 段階）の両方の影響を受けないので、抵抗力の分だけ最終ダメージが増える場合もあります（コラッタ（抵抗力 超 -30）がスリープの 10 を受けると、
  0 ではなく 10。`NeutralDamageTest.test_ignoring_resistance_can_raise_the_damage`）。

### 3.3 複数の発生源・場にいる HP 以上のポケモン

- 発生源が 2 つ以上でも、弱点・抵抗力の影響を受けないのは 1 回です（同じ弱点を 2 回計算しない・重ねて加減しない）。ログには、残っているはたらく力をすべて書きます。1 匹の力が消えても、
  ほかの有効な発生源の条件は問い合わせのたびにそれぞれ確かめます（バトル場のトランセルがこんらんでも、ベンチのもう 1 匹の力で守る。`GreenShieldTest.test_two_shields_and_one_confused`）。
  v0.97 の DF1（「自分の場のほかの…がはたらいているとき、この力ははたらかない」の同時に多くても 1 つ）は、文面の違うこの 2 つの力に持ち込んでいません（`self_excluding` は偽）。
- 同じワザのダメージで HP 以上になった発生源も、きぜつの処理（ワザのあと。p.323）の前は場にいるので、その力ははたらきます（`continuous_powers` は場のポケモンを数える。v0.101 の［KEEP］の
  K と同じ読み方。ダメージを受けたときの窓の既存の扱いとも同じ）。実装上の読み方です（8 章）。

## 4. ダメージの計算の共通の処理

### 4.1 性質と、計算で当てはめるか

- 弱点・抵抗力の影響を受けないことは、その弱点・抵抗力を持たなくなることではありません。カードの定義・今有効な弱点・抵抗力（`weakness_of`・`resistance_of`・`definition_views`）・観測の値・
  テクスチャー・抵抗力低下ジム・のろいマーカーは変えず、ダメージごとに「その計算で 3・4 段階を当てはめるか」だけを答えます（`GreenShieldTest.test_own_grass_active_ignores_weakness` は、
  ダメージのあとも弱点が「炎」のままで観測も変わらないことを確かめる）。
- 問い合わせ `effects.weakness_resistance_ignored(state, receiving, receiver_type)` は、受ける個体の文脈 `effects.Receiving(owner, pokemon, exclude)`（持ち主・場の個体・除く効果の範囲）と、
  その個体の今のタイプの読み方 `receiver_type` を受け取り、影響を受けない弱点・抵抗力とそうする力（(持つポケモンの番号, `PowerKey`) の並び。`IgnoredWeaknessResistance`）を返します。
  場所（バトル場・ベンチ）は今の場から読み、カードの定義だけで個体の場所・持ち主を推測しません。持ち主が今の場と合わなければエンジンの不具合として止めます。
- `effects.calculate_with_stadium` は `receiving` を省略できない引数にしました（呼ぶ所をすべて直し、渡し忘れを型の誤りにする。12 か所）。ワザの説明（「弱点・抵抗力」に関係なく・
  「抵抗力」の影響を受けない）・スタジアム（グレンタウンジム・ニビシティジム）・ピントレンズですでに計算しない段階はそのままにし、力で計算し直しません。その上で、力が当てはまる段階を、
  既存の `calculate_attack_damage` の `weakness`・`resistance` の引数（v0.45・v0.57 の算術）で計算しません。6・8 段階で後から割る・足す・引く処理や、0 の `DamageModifier` で代用していません。
  2 段階で 0 以下になり終える計算、5 段階以降の加算・順番の決定、のろいマーカーの「×4」（弱点を当てはめるときだけ）はそのままです（`CalculationTest`）。
- 計算の結果（`damage.DamageCalculation`）の `weakness_ignored_by`・`resistance_ignored_by` に、力がなければ当てはめていた段階（ワザを使うポケモンのタイプが受けるポケモンの弱点・
  抵抗力で、ほかの理由で計算しない段階ではなく、2 段階で終えていない）の力だけを書き、ログ `damage`・`confusion_damage` の `weakness_ignored_by_powers`・`resistance_ignored_by_powers` に
  写します（なければ書かない。v0.101 までのログの形は変えない）。
- 色の読み方（VS1 など）ごとの計算（`same_for_type_readings`）では、読み方ごとに受けるポケモンのタイプが違うので、［グリーンシールド］が当てはまるかも読み方ごとに決まります。読み方で最終
  結果が変わるかの既存の扱い（変われば VS1 などで止める）はそのままです。

### 4.2 先読み・比べる処理と、除く効果の範囲

- 実際のダメージ（`kernel.compute_damage`・`deal_damage`）、宣言の前の先読み（`effects.preview_attack_damage`。比べる方法 `legacy` の v0.13 の止める関数も使う）、返す効果のダメージ、
  順番・減らす量の決定の不変条件（`engine._damage_order_decision_problems`・`_damage_reduction_decision_problems`）、比べる問い（JS1・FA1・SS1・DF1・MS1・CP1・［ベンチガード］の
  BG1）、「うら」が出るまでのコインの先読み（`resolution/unbounded.py`）が、どれも `calculate_with_stadium`（`compute_damage`）を通るので、同じ問い合わせを使います
  （`CalculationTest.test_preview_and_actual_use_the_same_answer`・`OtherPathsTest.test_every_preflight_mode_uses_the_same_query`）。比べる方法 `legacy` も同じ問い合わせを通るので、
  扱えない古い経路への切りかえはありません（`legacy_unknown_features` に加えていない）。
- 除く効果の範囲: 量を変える効果の一覧（`DamageModifier`）には弱点・抵抗力の力が出ないので、一覧から推測せず、範囲を `Receiving.exclude` で問い合わせまで運びます。
  `EXCLUDE_DEFENDER_HELD`（受けるポケモン自身の持っている効果）なら受けるポケモン自身の力を、`EXCLUDE_DEFENDER_SIDE`（SS1 の比べ）ならそのうえ受けるポケモンの持ち主の場の力を当てはめず、
  ワザを使う側のベンチの［ニュートラルダメージ］は当てはめます（`CalculationTest.test_receiving_context_is_explicit`）。今の写しで効果を除くワザ（スピードスター・だましうち）は、どれも
  弱点・抵抗力を計算しない（v0.60・v0.89）ので、力が答えを変える場面はありません（ログにも書かない。`test_stopped_at_step_two_and_effect_excluding_attacks`）。FA1・SS1・DF1 の比べは
  今までどおりです。
- 「うら」が出るまでのコイン（`unbounded.py`）: 組を分ける `key(h)` は実際の `compute_damage` で計算するので、力の当てはまり方が組の値に入ります。有限の組の上限（3.2 節の根拠）は、
  抵抗力の数と弱点の倍数を上の限りとして使っているので、力で弱点・抵抗力を当てはめない道（倍数 1・抵抗力 0）もその範囲に入ります（上限を増やしていない・実際のコインを代表の値で
  置きかえていない。`OtherPathsTest.test_unbounded_coins_use_the_actual_calculation`）。

### 4.3 ワザでないダメージと、既存の問い

- 力の説明の「ダメージを受ける時」はワザのダメージに限りませんが、すべてのダメージで弱点・抵抗力を計算し始めるものではありません。弱点・抵抗力を計算するかは、ダメージの分類ごとの既存の
  規定のままです。
  - こんらんの 20（p.322 で「弱点・抵抗力」の影響を受ける）: 計算するダメージなので、力を当てはめます（`effects.confusion_damage_calculation`。スリープ（弱点 超）の 20 は、ベンチの
    バリヤードがいれば 40 ではなく 20）。力の当てはまり方は、こんらんが「ワザによるダメージ」かの問い（`UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS`）によらない（説明が「ワザ」と書かない）
    ので、新しい問いにしていません。のろいマーカーの「×4」が当てはまりうる場合の既存の問い（v0.90）は、弱点が当てはまるかを同じ計算で見るので、力で弱点が当てはまらなければ、
    どちらの読み方でも同じ 20 になり止めません（隣の例: 力がなければ止める。`OtherPathsTest.test_confusion_with_curse_no_longer_differs`）。
  - 特殊能力のダメージ（Z9。説明に「弱点・抵抗力」に関係なく、と書かれていない［ファイナルビーム］・［わるいねぞう］・［ショックボム］）: 弱点・抵抗力を計算するかは決まらないままです。
    比べる 2 つの読み方のうち「計算する」読み方でも、力がはたらけば影響を受けないので、その弱点・抵抗力を比べから外しました（`effects.weakness_resistance_readings`。両方の読み方で量が
    同じなら止めない）。Z9 を解決したのではなく、量が同じ場面まで止めないようにしただけです（`OtherPathsTest.test_z9_power_damage_compares_with_the_powers`）。
  - どく・トレーナー（バトル場は穴だらけ!・ロケット団の爆発ジム）・ほかの特殊能力のダメージ（説明に「弱点・抵抗力」に関係なく）は、既存の規定で弱点・抵抗力を計算しないので、力は
    何も変えません。ダメージカウンターをのせる・移す効果、ほろびのうたの直接のきぜつにも、弱点・抵抗力の計算を加えていません。
- JS1（説明に弱点・抵抗力のない控えへのダメージ）: 2 つの読み方の比べ（`kernel.weakness_resistance_matters`）も同じ問い合わせを使います。［グリーンシールド］が弱点を当てはめなくても、
  抵抗力で量が変わる控えは JS1 のまま止めます。［ニュートラルダメージ］は控えの受け手に当てはまらないので、ベンチにバリヤードがいるだけでは JS1 を外しません
  （`OtherPathsTest.test_js1_bench_damage_uses_the_same_query`・`NeutralDamageTest.test_active_holder_and_bench_receivers`）。
- 返す効果のダメージ（こうらがえし・ほのおのかべ・クロスカウンター・カウンター。ワザによるダメージ）: 返す枠の受け手（ワザを使ったバトル場のポケモン）に力が当てはまれば、弱点・抵抗力を
  当てはめません（`OtherPathsTest.test_counter_return_damage`）。
