# v0.2e のアーキテクチャ（ディフェンダーと、相手の番にまたがる持続効果）

v0.2e は、ディフェンダー（PMCG1-079）を実装し、そのために「自分の場のポケモンを選んでつけるトレーナー」「防御側のダメージ変更（p.321 の 7 段階）」「使った番を越えて相手の番の終わりまで続く有効期限」を加えた版です。原典の照合と裁定は [defender-v0.2e.md](defender-v0.2e.md) にあります。v0.2c の設計（[architecture-v0.2c.md](architecture-v0.2c.md)）の上に作っています。

## 1. 目的と範囲

- ディフェンダーの効果を、『オフィシャルブック2000』p.257 の最新の説明と p.321 のダメージ計算の順番どおりに処理する。
- 効果の発生源（カード）・対象（ついているポケモン）・持ち主（使ったプレイヤー）・適用の条件（そのポケモンがワザのダメージを受けるとき）・段階（7）・有効期限（次の相手の番の終わり）・トラッシュの時点を区別する。
- プラスパワー（使った番の終わり）とディフェンダー（次の相手の番の終わり）を、同じ仕組みで別々の期限として管理する。
- 既存の対戦結果・再現性・カードの保存則を変えない。

作らなかったもの: 汎用のカード効果の記述言語、イベントの仕組み、ワザによる持続する効果（すなかけなど）、加算でないダメージ変更効果と、その順番を選ぶ決定、自分・ベンチへのダメージ。

## 2. v0.2c からの変更

| 項目 | v0.2c（プラスパワー） | v0.2e |
|---|---|---|
| つける対象 | 自分の対戦ポケモン（決定なし） | ディフェンダーは自分の場のポケモンを選ぶ（`SELECT_POKEMON` の決定。v0.2b の仕組み） |
| 有効期限の決め方 | `resolve` が `state.turn_number` を渡す | 実装が `TrainerEffect.discard_turn_offset`（使った番からいくつ後の番か）を宣言し、`attachment_discard_turn(state)`（= 使った番 + offset）で決める。プラスパワー 0、ディフェンダー 1 |
| ダメージ計算 | 5 段階（ワザを使うポケモンについているカード）に値がある | 7 段階（ワザを受けるポケモンについているカード）にも値がある。計算器は変えていない |
| 不変条件 | 有効期限が過ぎたカードが残らない | 加えて、期限が「今の番 + offset」より先でない、使った番が使ったプレイヤーの番、番の順番（番のプレイヤー = その番号の番の持ち主） |
| 効果の登録表 | id `kyuura-engine-0.2c` | id `kyuura-engine-0.2e`、トレーナーにディフェンダーを加えて 5 枚 |
| カードデータの写し | — | `pool_v0_2e`（PMCG1-079） |
| 状態の形・書き出しの形式 | 形式 1〜4 | 変えていない（形式 4 で表せる） |

新しいファイルはありません（`effects.AttachedDamageReduction`、`TrainerEffect.discard_turn_offset`・`attachment_discard_turn`、`engine.turn_owner`・`SETUP_PHASES` を既存のモジュールに加えた）。

## 3. カードのライフサイクル

```
ディフェンダー（自分の番 n に使う）:
  手札 ──PlayTrainer──▶ 使用中（trainer_in_use）──resolve: 選ぶ決定（自分の場のポケモンの番号）
       ──ResolveDecision──▶ resume: attach_trainer（discard_at_end_of_turn = n + 1）──▶ ポケモンについている
       ├─ 番 n の終わり: そのまま（プラスパワーはここでトラッシュ）
       ├─ 相手の番 n + 1 のワザ: ついているポケモンが受けるダメージに 7 段階で -20
       ├─ にげる・ポケモンいれかえ: ポケモンといっしょに移る（期限は変わらない）
       ├─ きぜつ: ポケモンといっしょにトラッシュ（knock_out.discarded_trainers）
       ├─ 番 n + 1 の終わり: トラッシュ（discard_attached_trainer、reason="end_of_turn"）
       └─ 勝敗が決まる: 対戦が終わる（番の終わりは来ない。ついたまま最後の状態に残る）
```

- 選ぶ決定を待つ間、カードは使用中（`trainer_in_use`）にあり、手札にも場にもありません。不正な選択（相手のポケモン・存在しない番号・古い決定の番号など）は拒否し、状態は変わりません（`apply_command` は複製してから処理する）。
- 選んだら、`attach_trainer` が使用中から外してポケモンにつけます。同じカードが 2 か所にある瞬間はありません。`_finish_trainer` は、場に残る実装でカードが使用中に残っていたらエンジンの不具合として止めます（v0.2c）。

## 4. 防御側のダメージ変更

- ダメージ計算器（`damage.calculate_attack_damage`）は変えていません。段階ごとに `DamageModifier(step, amount, label, source)` を適用するだけで、カード id を知りません。
- 変更効果を集めるのは `effects.attack_damage_modifiers(state, attacker, defender)`（v0.2c）です。ワザを使うポケモンについているカードには `role="attacker"`、ワザを受けるポケモンについているカードには `role="defender"` で、効果の実装の `damage_modifiers` を呼びます。
  - プラスパワー（`AttachedAttackBonus`）は `attacker` のときだけ 5 段階の +10
  - ディフェンダー（`AttachedDamageReduction`）は `defender` のときだけ 7 段階の −20
- 同じ段階に複数の効果があるときの順番は、5 段階はワザを使うプレイヤー、7 段階はワザを受けるプレイヤーが決めます（p.321。`DAMAGE_STEP_CHOOSER`）。どれも加算なので、順番で結果は変わらず、決定は出しません。
- ログ `damage` の `modifiers` は `(段階, カードの uid, 加えた数)` の組（v0.2c と同じ形）。ディフェンダーは `(7, uid, -20)`。段階の記録には `("7 ディフェンダー", 値)` が加わります。

### `DamageModifier` を広げなかった理由

指示では、発生源・対象・段階・数・適用の条件を表せるようにすることが求められました。v0.2e では、次のように今の形で表せるので、項目を加えていません。

| 情報 | 表し方 |
|---|---|
| 発生源 | `source`（カードの uid）。`label` はカード名 |
| 対象 | 変更効果は、計算しているダメージ（あるワザで、あるポケモンが受けるダメージ）ごとに集めるので、対象は暗に決まる。どのポケモンについているかは `PokemonInPlay.trainers` にある |
| 段階 | `step`（2・5・6・7・8） |
| 増減 | `amount`（マイナスなら減らす） |
| 適用の条件 | 効果の実装の `damage_modifiers(state, attached, role)` が決める（ディフェンダーは「受けるとき」だけ） |

項目を加えると、v0.2c からのログ（`modifiers` の組）の形が変わります。自分・ベンチへのダメージを加えるときに、対象の種類（相手の対戦ポケモン・ベンチ・自分）を `role` か新しい引数で渡すことを検討します（11 章）。

## 5. 有効期限のモデル

### 検討した案

| 案 | 長所 | 短所 |
|---|---|---|
| A. 「この番号の番の終わりにトラッシュ」の整数 1 つ（v0.2c の `discard_at_end_of_turn`。採用） | 状態の形・形式 4 を変えない。プラスパワー（n）とディフェンダー（n + 1）を同じ形で表せる | 番が交互に 1 つずつ進むことが前提（下で確かめた） |
| B. 「どのプレイヤーの、何回目の番の終わり」（プレイヤーと回数） | 番の番号に頼らない | 状態の形と形式が変わる。今のルールでは A と同じ結果 |
| C. 効果の期限とカードの期限を別に持つ | 第1弾の印刷の文面（効果は相手の番の終わりまで、カードは次の自分の番の最初にはがす）を表せる | 最新の説明では同じ時点なので、今は使わない項目が増える |

A を採用しました。番号の足し算で足りるかは、既存の番の進行で確かめました。

- `turn_number` は、番の始まり（`_begin_turn`）で 1 だけ増え、番のプレイヤーは毎回入れ替わる（p.309「交互にくりかえし」）。番を飛ばす・続けて 2 回行う処理はない。サドン・デスは対戦を止める（`Phase.SUDDEN_DEATH`）。
- ワザのあとのきぜつ・サイド・交代の決定を待つ間、`turn_number` は変わらない。番の終わり（`_end_turn`）は決定がすべて終わってから 1 回だけ来る。したがって「番 n + 1 の終わり」は、相手の番のワザ・サイド・交代がすべて終わったあと。
- 勝敗が決まったら `_finish` で対戦が終わり、番の終わりは来ない（ついたまま残る。不変条件は終わった対戦では期限を見ない）。
- トレーナーは自分の番（MAIN）にしか使えないので、使った番 n は使ったプレイヤーの番。次の相手の番は n + 1。

この前提を不変条件にしました（7 章）: 番のプレイヤーは、その番号の番の持ち主（`turn_owner(state, n)`: 奇数番は先攻、偶数番は後攻）。

### 効果の期限とトラッシュの時点

最新の説明では、ディフェンダーの効果は「このカードをつけているポケモン」に働き、カードは次の相手の番の終わりにトラッシュするので、効果の終わりとトラッシュの時点は同じです（[defender-v0.2e.md](defender-v0.2e.md) 1 章の CONFLICT）。エンジンでは、効果はついているカードからしか出ず（`attack_damage_modifiers` はついているカードだけを見る）、期限の番の終わりにカードをトラッシュするので、期限を過ぎた効果が働くことはありません。きぜつ（場を離れる）は期限とは別の処理で、ポケモンといっしょにすぐトラッシュします。勝敗が決まったときは何もしません。

| 区別するもの | 処理 |
|---|---|
| 効果の有効期限 | カードがついている間（トラッシュで終わる） |
| カードのトラッシュの時点（期限） | `discard_at_end_of_turn` の番の終わり（`_discard_expired_attachments`。ログ `turn_end`・ポケモンチェックの前） |
| きぜつ | `_knock_out` ですぐにトラッシュ（期限の処理と重ならない。場を離れたので番の終わりに見つからない） |
| 勝敗の決定 | 何もしない（番の終わりが来ない） |

## 6. PendingDecision との統合

- 決定は v0.2b の `push_trainer_decision`（`kind="select_pokemon"`、`resume="trainer"`）。選べるものは自分の場のポケモンの番号（バトル場、ベンチの順）。1 匹しかいなくても決定を出す（v0.2b と同じ）。
- 原典で扱いを決められない選択（`unresolved_choices`）はない。
- 拒否する答え: 相手のポケモン・存在しない番号・選べるものにないカードの uid（`INVALID_CHOICE`）、数の誤り（`INVALID_CHOICE_COUNT`）、古い・先の決定の番号（`WRONG_DECISION`）、別のプレイヤー（`NOT_YOUR_DECISION`）、答えたあとの二度目（`WRONG_PHASE`）。決定を待つ間のほかの操作は `WRONG_PHASE`。
- `resume` は、選んだポケモンが使ったプレイヤーの場にいることを確かめてからつける（選べるものの検査をすり抜けたら、エンジンの不具合として止める）。

## 7. カードの保存則と不変条件

`check_invariants` に加えたもの:

| 不変条件 | 内容 |
|---|---|
| 番の順番 | 対戦準備・終わった対戦以外では、先攻が 0 か 1、`turn_number ≥ 1`、番のプレイヤー = `turn_owner(state, turn_number)` |
| 有効期限の上限 | ついているトレーナーの `discard_at_end_of_turn` が、今の番 + その実装の `discard_turn_offset` より先でない（「使った番」が今の番より後にならない） |
| 使った番の持ち主 | `discard_at_end_of_turn − discard_turn_offset`（使った番）が、使ったプレイヤーの番 |

v0.2c からあるもの（ついているカードを持ち主の場のカードとして数える、使ったプレイヤー = ポケモンの持ち主、場に残る実装が登録されている、有効期限が過ぎたものは残らない）はそのままです。期限切れのカードが効果を出さないことは、「有効期限が過ぎたものは残らない」で保証されます。

## 8. 状態の書き出し

形式 4（v0.2c）は、場のポケモンごとに `trainers`（`card`・`card_id`・`player`・`discard_at_end_of_turn`）を書くので、ディフェンダーの発生源・持ち主・対象（そのポケモンの `pokemon_id`）・期限・複数枚をそのまま表せます。**形式 5 は加えていません。** 形式 1〜3 は、ついているトレーナーがあると `ValueError`（v0.2c から。黙って落とさない）。決定を待つ間の使用中のカードは、形式 1・2 では `ValueError`、形式 3 以上で書き出せます（v0.2b から）。

`state_to_dict` は書き出し専用です。辞書や JSON からゲーム状態を読み込む機能はありません（乱数だけは `rng.rng_state_to_json`・`rng_from_json` で保存・復元できる。v0.2d）。

## 11. 将来の拡張方針

| 将来の機能 | v0.2e の土台 | 加えるもの |
|---|---|---|

## 12. 設計上のトレードオフ

| 判断 | 理由 | 代償 |
|---|---|---|
| 期限を整数 1 つ（番号）のままにした | 状態の形・形式 4 を変えない。番の進行の前提を不変条件で確かめた | 番を飛ばす・続ける効果を加えるときは、期限の表し方を見直す |
| 期限の長さを実装の属性（`discard_turn_offset`）にした | カードごとの期限が 1 か所に書かれ、不変条件で確かめられる | 期限が状況で変わるカードには使えない |
| ディフェンダーを 1 匹でも選ばせる | v0.2b と同じ手順。選ぶ手順を省かない | 操作が 1 回増える |
| `DamageModifier` に対象の項目を加えなかった | ログの形を変えない。今は対象が暗に決まる | 自分・ベンチへのダメージを加えるときに見直す |
