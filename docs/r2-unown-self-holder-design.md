### 3.3 公開の前の情報だけで、公開のあとの適格性を構造的に決められるか（静的）

**結論:** 決められます。ただし、次の「仮の力」の評価を新しく定義し、その前提を前提テストで確かめることが条件です。

**仮の力:** 本人が知る本当のカードの定義 `definition`（`printed_def`）の特殊能力を、登録（`state.effects.power_entry(definition.id, i)`）から読んだものです。
- 公開のあとにエンジンが読む力（`group_attack_power_slot(revealed)` = `powers_of` の最初の `AttackDeclaredPower`）と同じものにするため、印刷の並びで**最初の `AttackDeclaredPower` 型の力**を取ります。
- その型が `_FACE_DOWN_GROUP_POWERS` のどちらかでなければ示しません。

公開のあとの `group_attack_power_check` の各項目との対応:

| エンジンの確かめ（公開のあと） | 公開の前の評価 | 同じになる根拠 |
|---|---|---|
| 持ち主が自分の場にいる | 使い手は自分のバトル場（番の本人） | 公開で場の番号・持ち主は変わらない |
| `group_attack_power_slot` が力を返す | 上の仮の力（最初の `AttackDeclaredPower` が持ち主の型） | 公開のあとの `powers_of` は `card_power_slots(card)` で、印刷の定義の力（「ばける」・変身の記録は不変条件と 22 型でない） |
| `usable_for`: 今の姿の `name_group` が `group`、ワザの名前が `attack_name` | `definition.name_group == effect.group`、印刷のワザの名前 | 22 型に変身の型がなく、「ばける」もないので、公開のあとの姿は印刷のカード（v0.191 の R2 と同じ根拠） |
| `power_suppressed(state, power, holder)` の個体の部分（`powers_stopped`・`scared_by`） | 使い手の `persistent_effects` が空で、本当のカードがベイビィでないことを確かめる | 不変条件で持続する効果はなく、公開で加わらない。`scared_by` はベイビィだけ（X・A はベイビィでない） |
| `power_suppressed` の場の部分（ベトベトガス・オールクリア・やみのはどう・`suppressors_of(power)`・ふしぎなガス） | `power_suppressed(state, 仮の力の Power, None, owner=actor)` | 公開は `trainer_effects` を変えない。公開で場に加わる力は使い手の印刷の力だけで、X・A は力を消す型でない。うらのカードは公開の前も力を消さない（力がない） |
| `powers_use_prevented(holder)` | 使い手の `persistent_effects` が空 | 不変条件（ショックアイなどは対象の指定でおもてにしてから受ける） |
| `other_use_problem(state, player, holder_id)` | 同じ関数を、使い手の `pokemon_id` で呼ぶ（読むのは公開の記録 `GROUP_ATTACK_POWER_USED` と記録のカードの定義） | 公開で記録・場の番号は変わらない。うらの使い手自身の記録はありえない |
| `concurrent_use_problem`（同じ力を 2 つ） | 仮の力の `exclusive_key` と、別の持ち主の `exclusive_key` を比べる | 同じ型・同じパラメータなら同じ値 |

**依存する前提（実装の前に確かめる）:**
- 不変条件（ダメージ・持続する効果・「ばける」・進化の記録がない）。
- 本当のカードがベイビィでなく、たね（公開で残る）であること。
- 持ち主の型が力を消す型・変身の型でないこと。
- 公開が場の力の問い合わせに、使い手の印刷の力のほかに何も加えないこと。

これらは今の登録（X・A の 2 枚）で成り立ちます。ただし、新しい型・新しいカードでは成り立つと限りません。そのため、候補の条件にも「ベイビィでない・たね」と閉じた型を入れます（5 章）。

**候補の作成で呼ばないもの:** おもてにする処理・コイン・エンジンの確かめ（`check_use_attack`・`group_attack_power_check`）・複製の上の試行。`usable_for` も呼びません（うらの使い手では読めないので、印刷の値で同じ比較をする）。

## 4. 情報境界と［ANGER］の扱い

### 4.1 情報境界

| 情報 | 分類 | R3 の評価で使うか |
|---|---|---|
| 本当のカードの印刷の名前のグループ・段階・ベイビィか・特殊能力とその登録の型・パラメータ・ワザの名前 | 本人が知る（本人の応答にだけ出る。v0.191 でも使う） | 使う |
| 使い手の場の番号・バトル場であること・`persistent_effects` が空であること | 公開 | 使う |
| 場の力を消す効果（ガス・ふしぎなガス・やみのはどうなど）・この番の［XXXXX］の記録 | 公開 | 使う（状態を変えない既存の問い合わせ。R2 と同じ） |
| 使い手のダメージカウンター | 公開（うらのあいだはいつも 0） | 量は予告しない（4.2） |
| 公開のあとのコイン・XP1・NT1・v0.4b の停止 | 送信のときに決まる | 使わない |
| 相手のうらのカード・山札・手札・サイド | 相手の秘密 | 使わない |

**本人・相手・観戦者に分かること:**
- **本人:** 自己持ち主の選択肢（有無・数・並び・reason・processability）は本人の応答にだけ出ます。
  - 本当のカードが X か A かという本人の知識が、選択肢の形で本人にもう一度見えるだけです。v0.191 でも、ワザの選択肢に本当のカードの `card_id` が出ています。
- **相手・観戦者:** 候補・入力・check の応答は本人だけのものです。相手・観戦者の応答と更新は、本当のカードだけを変えても変わりません（実装のときに双子で確かめる）。
- **送信の後:** 受理されたら、公開・宣言のログ（`group_attack_power`・`group_attack_power_counters`/`_coins`）はおもてにしたあとの公開の情報です。拒否されたら、公開ごと戻り、ほかの人に知らせません（R2 と同じ）。
- **区分:** `processability`・`reason` は、R2 と同じくいつも `unverified`・`face_down_reveal_not_evaluated` です。本当のカードによって変えません。
- **表示:** 自己持ち主の選択肢は `_pokemon_option(active, "active")` の形です（`face_down: true`、`card_id` なし）。これに `power`（本当のカードの印刷の力の名前）を加えます。新しい語彙は加えません。

### 4.2 ［ANGER］の自己持ち主: 追加はいつも 0

**不変条件の根拠（静的）:**
- うらのあいだのダメージ 0 は、`_face_down_pokemon_problems`（`pokemon.damage` を問題にする）と `check_invariants` が保証します。
- ダメージを受ける時はおもてにします（`designate_face_down`。「そのカードが「ダメージや効果」を受ける時も、そのカードをおもてにする」）。
- `reveal_face_down` はダメージを変えません。

**宣言から数えるまでに、使い手にダメージがのる経路（静的）:**
- ［ANGER］を数えるのは、宣言のときではなく、相手の対戦ポケモンへのダメージの要素の始めです（`declared_power_amounts`）。
- その間の処理（3.1 の 5）のうち、使い手のダメージを変えうるのは、こんらんの自分へのダメージだけです。不変条件でこんらんはなく、こんらんなら数えずにワザが終わります。
  - ベイビィのコイン・すなかけ（持続する効果がない）・クチバシティジム（アンノーンはマチスのポケモンでない）・変わり身の術（相手の入れ替え）は、使い手にダメージをのせません。
- めざめるパワーの要素は `[Damage]` だけです（実行確認。ダメージの前の要素はありません）。
- 「相手がワザを使う時」に使い手へダメージカウンターをのせる効果は、この経路の中に見つかりませんでした（静的。前提テストの対象）。

**既存の処理の、効果 0 の宣言の扱い:**
- **エンジン:** 0 個でも使うことを不正にしません（`CounterBonusToGroupAttack` の説明。既存テスト `test_anger_counts_the_holder_and_allows_zero` が 0 個の受理と `(counters, amount) = (0, 0)` を確かめる）。
- **おもての API:** `_addon_specs` は量で選択肢を絞りません。おもてのバトル場の A 自身（ダメージ 0）も、エンジンの確かめを通れば示します。
- **R2（v0.191）:** カウンター 0 個の別の持ち主の A も示します（量を予告しない。保存結果 `B_fd_N_with_A_zero_counters` は受理・追加 0）。
- 既存の API は効果 0 の選択を除いていません。R3-A だけ量で除くと、新しい除外の原則になります。

**0 ダメージのほかの影響（静的。保存結果 `E_fd_self_A` と一致）:**
- **公開のログ:** `group_attack_power`（宣言）と `group_attack_power_counters`（`counters: 0`・`amount: 0`・`step: 2`）が残ります。
- **使った記録:** 書きません（`records_turn_use` が偽）。
- **同じ宣言の制限:** ほかの A の［ANGER］は、同じ宣言でいっしょに選べません（`exclusive_key` が同じ。エンジンは `POWER_ALREADY_USED`、check は `CANDIDATE_INPUT_INVALID`）。ベンチのダメージのある A のかわりに自分の A を選ぶと、追加を失います。
- **先読み:** `holders` があるので、v0.13 の止める関数を使わない経路になります（`flow.py:175`）。上限を超えたときは推測せずに拒否します。`[Damage]` だけのワザでは上限に届かない見込みです（静的）。
- **未裁定:** コインがないので、XP1・NT1・v0.4b の条件には入りません（力なしと同じ）。

### 5.2 推奨する次の 1 単位: R3（自己持ち主の［XXXXX］・［ANGER］をいっしょに）

**同じ根拠で扱える理由:**
- 持ち主が使い手自身であるという構造が同じです。
- 適格性の評価（仮の力・3.3 の対応表）も、エンジンの確かめ（`group_attack_power_check`）も同じです。
- 違いは受理のあとの処理だけです（［XXXXX］はコインと既存の停止、［ANGER］は追加 0）。これは R2 で、候補では予測しないと決めたものと同じ種類です。

**小さくする代案:** 「［XXXXX］だけ」（D-R3-1）。このとき［ANGER］は A（今のまま）とし、効果 0 であることを除外の理由として文書に残します。

**使い手と仮の力の条件（すべて満たすとき）:**
- 番のプレイヤーの main で、本人のバトル場のポケモンがうら（呼び出し元の条件）。
- v0.191 の `_classified_group_attacker(state, definition)` が真（特殊能力がすべて登録済みで、22 型の範囲）。**閉じた範囲は広げません。**
- `definition` がたねで、ベイビィでない（`is_baby_pokemon` が偽）。今の 2 枚では常に成り立ちます。新しいカードで崩れたら示しません。
- 印刷の並びで最初の `AttackDeclaredPower` 型の力の型が `_FACE_DOWN_GROUP_POWERS` のどちらかで、`effect.group == definition.name_group`。
- 印刷のワザの名前が `effect.attack_name` のワザがある（`options_by_choice` はそのワザだけ。v0.191 と同じ）。

**公開の場から確かめる抑制・使用制限:**
- `powers_stopped(state, active) is None` と `powers_use_prevented(state, active) is None`。不変条件で必ず None ですが、念のため確かめます。
- `power_suppressed(state, 仮の力の Power, None, owner=actor)` が偽。
- `effect.other_use_problem(state, actor, active.pokemon_id) is None`（［XXXXX］だけ意味がある）。

**参照値と表示:**
- 値は `(ADDON_WITH_POWER, active.pokemon_id)` です（送信は今の `_attack_command` のまま `with_power` / `with_powers`）。
- 表示は `{"addon": "with_power", **_pokemon_option(active, "active"), "power": 印刷の力の名前}` です（`face_down: true`、`card_id` なし）。
- 区分は `unverified`・`face_down_reveal_not_evaluated` です。

**列挙順:** おもての `_addon_specs` と同じ場の並び（バトル場 → ベンチ）にします。自己持ち主が最初で、そのあとが v0.191 の別の持ち主（ベンチの並び）です。
- 今の登録では、R3 の使い手（X・A）には［めいれい］・コインは出ません（特殊能力を持つため）。
- 本当のカードが X・A のときだけ、別の持ち主の選択肢の番号が 1 つ後ろにずれます。

**同じ力の複数指定・重なり:**
- 自分の X ＋ ベンチの X、自分の A ＋ ベンチの A は、`exclusive_key` が同じなので check が `CANDIDATE_INPUT_INVALID` にします（おもてと同じ）。
- 自分の X ＋ ベンチの A は選べます。
- 同じ選択肢を 2 回選ぶ入力は、今の形の検査が拒否します。
- `_face_down_verify` は、自己持ち主の `exclusive_key` を仮の力の登録から読むように直します（場から読むと落ちるため）。

**保証の文と note:**
- `GUARANTEE_FACE_DOWN_ATTACK` の preconditions に、次の 1 文を加えます: 「v0.192 から、使い手自身の［XXXXX］・［ANGER］を、本人が知る本当のカードの登録の力・公開の場から、同じ条件で示す」。acceptance の既存の文（ダメージが増えたことを意味しない・XP1 などで拒否されうる）はそのまま当てはまります。
- F-1 の固定の sha256 は、原因を記録して更新します（旧値 `28f68001…` を残す）。
- note は、自己持ち主を示すときだけ新しい文を使います。R2 だけ・コイン・［めいれい］のときの文は変えません。量（［ANGER］が 0 であること）を予告するかは D-R3-3 です。推奨は予告しないことです（R2 と同じく量を示さない。「ダメージが増えることは保証しない」で足りる）。

**check の範囲:** 形と、同じ `exclusive_key` の組だけです。エンジンは呼びません。保証しないのは、受理・力の使用・コイン・追加の量・停止がないことです。

**submit で初めて決まるもの:**
- 公開のあとの `group_attack_power_check`。3.3 の同値性が崩れていれば、ここで `ATTACK_POWER_NOT_AVAILABLE`・`POWER_SUPPRESSED` などで拒否されます。
- ［XXXXX］のコインの結果と、XP1（相手のバトル場のベイビィ）・NT1（変わり身の術）・v0.4b（ダメージを受けない状態）の停止。
- 先読みの上限。
- **拒否のとき:** コマンドごと元に戻ります（公開・状態・乱数・ログ・決定は不変で、ほかの人に知らせない）。R2 と同じです。

**採らない案:**
- 宣言の選択を受理のあとへ移す: 選ぶ時点が変わるため。
- XP1 などを候補で予測して外す: エンジンの条件の写しになるため。
- 複製の上でおもてにして試す: 情報境界と、候補でエンジンを呼ばない方針のため。
- 22 型の範囲・持ち主の型を広げる: 不要なため。
