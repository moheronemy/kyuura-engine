# 進化したポケモンの状態（v0.4a）

1 匹の場のポケモンが複数の物理カードで構成されるようになったときの、状態の持ち方・識別子・番の記録・受け継ぐもの・消えるもの・きぜつ・カードの保存則の記録です。ルールの根拠は [evolution-rules-v0.4a.md](evolution-rules-v0.4a.md)、設計の全体は [architecture-v0.4a.md](architecture-v0.4a.md) にあります。

## 1. 区別するもの

| 区別 | 内容 |
|---|---|
| 物理カードの uid と場のポケモンの番号 | uid（`GameState.cards` の番号）は 1 枚のカード。場のポケモンの番号（`pokemon_id`）は場の 1 匹。進化しても番号は変わらず、いちばん上のカードの uid は変わる |
| 場のポケモンと、その構成カード | 場のポケモン（`PokemonInPlay`）は、いちばん上のカード（`card`）と下のカード（`evolution_stack`）で構成される。下のカードは場のポケモンとして数えない |
| 進化前と進化後のポケモン | ルールの上では別のポケモン（p.310）。エンジンでは同じ `PokemonInPlay`（同じ番号）で、別のポケモンであることの帰結を項目で表す（2 章） |
| 内部の識別子とルールの上の同一性 | `pokemon_id` が同じでも、ルールの上で同じポケモンとは限らない |
| 場に出た番と進化した番 | `played_turn`（場に出た番。対戦準備は 0）と `evolved_turn`（いまの姿に進化した番） |
| 特殊状態の解除と持続する効果の解除 | 特殊状態は `conditions`（`clear_special_conditions` の `EVOLVE`）。持続する効果は対応カードにない（加えるときは進化の処理で消す） |
| ついているカードの受け継ぎと効果の継続 | カード（`trainers`）は受け継ぐ。効果も続く（ついているカードの効果で、持続する効果ではない。SUPPORTED） |
| にげるの失敗の記録と特殊状態 | 記録（`retreat_failed_turn`）は特殊状態ではない。進化の処理が別に消す |
| 進化したポケモンのきぜつと構成カードのトラッシュ | きぜつは 1 匹（サイド 1 枚）。トラッシュするカードは重なったすべてのカード |

## 2. 場のポケモンの番号（`pokemon_id`）

**進化しても変えない**（実装上の仮定。v0.3d の調査の案 A）。

- 理由: 進化しても受け継ぐもの（ダメージカウンター・エネルギー・ついているトレーナーとその有効期限）と、決定・ログが指すポケモンを、番号でそのまま追える。v0.2a の移行の方針（[architecture-v0.2a.md](architecture-v0.2a.md) 5 章）と合う。
- 「別のポケモン」（p.310）の帰結は、次の項目で表す:

| 帰結 | 表し方 |
|---|---|
| 進化前のカードの内容は無効、進化カードの内容がそのポケモンを表す（ワザ・HP・タイプ・弱点・抵抗力・にげる） | いちばん上のカード（`card`）の定義だけを使う |
| 「その番の最初」には場にいなかったことになる（同じ番にもう一度は進化できない） | `evolved_turn` |
| 特殊状態・持続する効果から回復する | `conditions` を消す（持続する効果は対応カードにない） |
| こんらんで「にげる」に失敗した記録 | `retreat_failed_turn` を消す |

- 将来、「同じポケモン」「進化前のポケモン」を参照するカード（進化をまたぐ効果）を加えるときは、`pokemon_id` だけで裁定しない。必要なら「いまの姿」を区別する情報（たとえば `evolved_turn` とトップのカード）で判断し、決められなければ止める。今は使わない識別子の仕組みは作っていない。

## 3. カードの重なり

```python
@dataclass
class PokemonInPlay:
    card: int                              # いちばん上のカード（そのポケモンを表す。p.310）
    ...
    evolution_stack: tuple[int, ...] = ()  # 下のカード（下から順。いちばん下がたねポケモン）
    played_turn: int = 0                   # 場に出た番（対戦準備は 0）
    evolved_turn: int | None = None        # いまの姿に進化した番
```

| 判断 | 理由 |
|---|---|
| `card` はいちばん上のカードのまま | v0.1 からのすべての処理（ワザ・HP・弱点・にげる・ログ・コマンドの uid）がいちばん上のカードを見る。進化カードの内容がそのポケモンを表す（p.310）ので、そのまま正しい |
| 下のカードを別の項目に持つ | 下のカードはトラッシュしない（p.310）が、内容は使わず、場のポケモンとして数えない。きぜつで構成カードをすべてトラッシュする（p.313）ために要る |
| 下から順のタプル | 2 進化（v0.4b 以降）でも同じ形で表せる（たね、1 進化の順）。タプルなので、複製で共有しても書きかえられない（置きかえるときは新しいタプル） |
| `cards()`（下から順にトップまで） | きぜつのトラッシュ・カードの保存則で使う |

v0.4a は 1 進化だけなので、重なりは 0 枚か 1 枚（不変条件）。2 進化の操作は実装していません。

## 4. 場に出た番・進化した番

| 方式 | 内容 | 判断 |
|---|---|---|
| A. ログから求める | 進化を確かめるたびに、`place_starting_pokemon`・`play_to_bench`・`evolve` のログをさかのぼる | 採らない。ログを全部さかのぼる処理を、コマンドの検査・不変条件で毎回することになる（v0.1 のログはカードの uid で書かれ、場のポケモンの番号がない）。場をはなれて同じカードがまた出た場合の区別も複雑 |
| B. 明示的な項目で持つ | `played_turn`・`evolved_turn` | **採った**。検査が直接で、不変条件で範囲を確かめられる。状態の形が増える代わりに、書き出しの形式 7 に加える |

- `played_turn`: `_enter_play`（対戦準備・ベンチに出す）で今の番の番号（対戦準備は 0）。にげる・ポケモンいれかえ・きぜつのあとにベンチから出すことでは変わらない（場をはなれていない。p.313）。
- `evolved_turn`: 進化した番。`current_form_turn`（`evolved_turn`、なければ `played_turn`）が今の番なら、そのポケモンは「その番の最初から場に出ていた」ポケモンではない（p.310）。
- 最初の番（p.310）は、番は先攻から交互に進む（不変条件）ので、1 番・2 番。
- 互換性: 進化していないポケモンの `played_turn` は、どの形式にも入っているログ（`place_starting_pokemon`・`play_to_bench` の番）から分かる。そのため形式 1〜6 では書き出さず、進化していない状態の書き出しは v0.3d と同じ（v0.1 の参照データとも同じ）。

## 5. 受け継ぐもの・消えるもの

| もの | 進化で | 根拠 |
|---|---|---|
| ダメージカウンター（`damage`） | そのまま | p.310（CONFIRMED） |
| エネルギー（`energy`。uid と順番） | そのまま | p.310（CONFIRMED） |
| ついているトレーナー（`trainers`。プラスパワー・ディフェンダー） | そのまま。効果も有効期限も変わらない | p.310（カード。CONFIRMED）、p.257・p.321・p.322（効果。SUPPORTED） |
| 場のポケモンの番号（`pokemon_id`）・場に出た番（`played_turn`） | そのまま | 実装上の仮定（2 章） |
| 特殊状態（`conditions`） | すべて消える（ログ `special_conditions_removed`、`reason: "evolve"`） | p.310・p.322（CONFIRMED） |
| 持続する効果 | 消える（対応カードにない） | p.310・p.323（CONFIRMED） |
| マーカー・カウンター（ダメージカウンター以外） | 取りのぞく（対応カードにない） | p.310・p.323（CONFIRMED） |
| にげるの失敗の記録（`retreat_failed_turn`） | 消える（ログ `retreat_failure_cleared`） | p.310・p.311・p.322（SUPPORTED） |

ベンチのポケモンには特殊状態がない（p.322）ので、ベンチで進化しても特殊状態の解除は起こりません。

## 6. きぜつ

- 進化したポケモンがきぜつしたら、いちばん上のカード・下のカード・エネルギー・ついているトレーナーをすべてトラッシュする（p.313・p.323）。トラッシュに順番はない（p.312）が、下のカード → いちばん上のカード → エネルギーの順に入れる（進化していなければ v0.3d と同じ）。
- 相手が取るサイドは 1 枚（きぜつしたのは 1 匹。重なったカードの数では増えない）。
- ログ `knock_out` の `pokemon` はいちばん上のカード、`evolution_stack` は下のカード（進化していないポケモンのログには、この項目を加えない）。
- 場の番号は無効になり、特殊状態もなくなる。
- ワザ・自分へのダメージ・こんらんの 20・ポケモンチェックのどくのどれできぜつしても同じ処理（`_knock_out`）。

## 7. カードの保存則と不変条件

カードの保存則（`check_invariants`）で、次のすべてを持ち主のゾーンとして数えます: 山札・手札・サイド・トラッシュ・場のポケモンのいちばん上のカード・**下のカード（v0.4a）**・ついているエネルギー・ついているトレーナー・使用中のトレーナー。すべてのカードがちょうど 1 か所にあります。

v0.4a で加えた不変条件（`engine._evolution_problems`）:

| 不変条件 |
|---|
| 重なりは整数のタプルで、v0.4a は 0 枚か 1 枚 |
| 進化していなければ、いちばん上はたねポケモン、進化した番はない |
| 進化していれば、いちばん下はたねポケモン、いちばん上は 1 進化で、その「○○から進化」が下のカードの名前。進化した番がある |
| 場に出た番は 0〜今の番。進化した番は、場に出た番より後・今の番まで・持ち主の番・3 番以降 |
| 今の番に進化したポケモンに、進化のあとで付けられたもの以外の特殊状態が残っていない（ログの `evolve` と `special_condition` の順で確かめる） |
| にげるの失敗の記録は、同じポケモンの進化（ログ `evolve`）より後の `retreat_failed` と対応する（`_retreat_failure_problems`） |
| 場のポケモンの番号は重ならない（v0.2a から） |
| ついているトレーナーの有効期限は妥当（v0.2c・v0.2e から。進化で変わらない） |

## 8. 書き出し（形式 7）

| 形式 | 進化したポケモン | 進化していないポケモン |
|---|---|---|
| 1〜6 | 表せない（`ValueError`。黙って落とさない） | v0.3d と同じ |
| 7 | 場のポケモンごとに `evolution_stack`（下から順に `{"card", "card_id"}`）・`played_turn`・`evolved_turn` を加える。`card`・`card_id`・`name`・`hp` はいちばん上のカード | 同じ項目（`evolution_stack: []`、`evolved_turn: None`） |

進化したポケモンがきぜつしてトラッシュに移れば、重なりはなくなるので、形式 1〜6 でも書き出せます（カードはトラッシュの uid）。`clone`・`copy.deepcopy`・`pickle` は重なりと番を保ちます（テストで確かめた。タプルなので共有しても書きかえられない）。

## 9. ログ

| イベント | 項目 |

| `evolve`（v0.4a） | `player`・`pokemon_id`・`from_card`（進化前のいちばん上のカードの uid）・`from_card_id`・`to_card`（進化カードの uid）・`to_card_id`。番はログの `turn` |

## 10. 新しい対戦からの総合テスト

tests/test_evolution_games_v0_4a.py。60 枚のデッキ・サイド 6 枚の正式な開始（`new_game`）から勝敗まで。

| デッキ | 内容 |
|---|---|
| A | パラス 4・パラセクト 3・パウワウ 4・ジュゴン 3・ビードル 3・キャタピー 2・プラスパワー 2・ディフェンダー 2・ポケモンいれかえ 2・マサキ 2・きずぐすり 2・草 17・水 14 |
| B | パラス 4・パラセクト 3・パウワウ 3・ジュゴン 2・キャタピー 3・ロコン 3・ビードル 3・ディフェンダー 2・ポケモンいれかえ 2・マサキ 2・草 17・炎 8・水 8 |

手順は v0.3c の手順に、進化（ワザを使う・番を終える前に、進化できるポケモンがいれば進化。いなければ名前の合うポケモンに一度だけ試して拒否を確かめる）と、パラセクト（キノコのほうし）・ジュゴン（れいとうビーム）のワザの選び方を加えたもの。直す手順 20 局（seed 0〜19）・直さない手順 20 局（seed 300〜319）で数えた回数:

| 項目 | 回数 | 項目 | 回数 |
|---|---|---|---|
| 進化した（パラセクト・ジュゴン） | 230（124・106） | バトル場・ベンチで進化 | 47・183 |
| 進化を拒否（最初の番・今の番に出した） | 28・85 | ダメージのあるポケモンの進化 | 31 |
| エネルギーのついたポケモンの進化 | 98 | ついているトレーナーのあるポケモンの進化 | 4 |
| 進化で消えた特殊状態（マヒ・どく・ねむり） | 4・2・3 | 進化したポケモンのワザ | 197 |
| うちキノコのほうし・きりさく・オーロラビーム・れいとうビーム | 103・60・10・24 | 進化したポケモンのきぜつ（うちポケモンチェック） | 62（23） |
| たねポケモンのきぜつ | 196 | サイドを取った | 258 |

- こんらん・にげるの失敗の記録からの進化は、この 40 局では起こらない（負荷テストでは起こった。単体テストで確かめる）。

## 11. 負荷テスト・変異テスト

作業用のスクリプト（リポジトリには入れない）で確かめました。

**自然な対戦 400 局**（seed 4000〜4399。直す手順と直さない手順を交互）: 勝敗が決まった 392 局、止まった 8 局（`UNRESOLVED_POKEMON_CHECK_DOUBLE_KNOCKOUT` 6・`UNRESOLVED_MULLIGAN_COMPENSATION` 2。どちらも v0.3 までの未解決）。進化 2,371 回（バトル場 430・ベンチ 1,941）、進化で消えた特殊状態 77 回（こんらん 3・どく + こんらん 1 を含む）、にげるの失敗の記録を消した進化 1 回、進化したポケモンのワザ 1,930 回、進化したポケモンのきぜつ 755 回（うちポケモンチェック 265）。最初の 40 局は、同じ seed で 2 回動かして同じ状態になった。

**でたらめな操作を混ぜた 200 局**（seed 9000〜9199。正しい手順 50%・でたらめな進化 25%・でたらめな「にげる」10%・でたらめなコマンド 15%）: 内部の例外 0。進化 866 回、進化したポケモンのきぜつ 136 回。進化の拒否は `NOT_YOUR_TURN` 8,123・`PLAYED_THIS_TURN` 5,241・`INVALID_PLAYER` 4,158・`CARD_NOT_IN_HAND` 3,719・`FIRST_TURN_EVOLUTION` 3,085・`NOT_EVOLUTION_CARD` 1,500・`WRONG_PHASE` 1,376・`TARGET_NOT_YOURS` 1,185・`EVOLUTION_NAME_MISMATCH` 868・`TARGET_NOT_IN_PLAY` 681。**すべての拒否で、渡した状態と乱数が変わらなかった。** 受け付けた操作のあとの状態は、すべて不変条件（カードの保存則・重なり・番・番号の重なり）を満たした。

**変異テスト**（実装を 1 か所ずつ壊し、進化のテスト・書き出しのテスト・段階のテストが失敗するかを見る。構文・名前の誤りで失敗した変異は数えない）: 22 種類すべてを検出した。最初の番でも進化できる・今の番に出したポケモンが進化できる・同じ番に再進化できる・名前の確認を省略する・進化元のカードをトラッシュする・ダメージが消える・エネルギーが消える・特殊状態が残る・場の番号が変わる・きぜつで進化元のカードをトラッシュしない・サイドを 2 枚取る・旧形式で重なりを落とす・にげるの失敗の記録を消さない・進化した番を正しく記録しない・ついているトレーナーを落とす・HP の未解決を通す・進化カードでないカードを受け付ける・未対応の進化カードを受け付ける・相手のポケモンも進化させられる・2 進化カードを対応にする・進化の不変条件を確かめない・重なったカードをカードの保存則で数えない。
