### 3.2 処理順序（`f5a71bb` の静的な追跡）

1. **コマンドの入口**（`engine._apply_once`、888 行）: 状態を複製します（`new`）。
2. **入口の固定**（915 行の `freeze_forms(new)`）: `UseAttack`・`UsePokemonPower`・`PlayTrainer`・`UseStadium` だけが対象です。
   - `freeze_forms`（`effects.py:15297`）は、`state.frozen_forms` が空でなければ何もしません。
   - 空なら、場の `transform_capable` なポケモン全部（プレイヤー → `in_play()` の並び）の `live_form` を記録します。
   - うらのカードは `FaceDownDefinition` で特殊能力がないので、`transform_capable` が偽です。そのため、**うらの使い手は入りません。**
3. **裏向きの攻撃者の公開**（`_reveal_for_action`、1099 行）: 公開は入口の固定のあとです。
   - 本当のカードがたねでなければトラッシュし、コマンドを受け付けます（L1・D1。ハンドラは呼ばれない）。
   - たねなら公開し、ハンドラへ進みます。
4. **公開後に決まる変身先:** 状態には持たず、`current_form`（15256 行）→ `live_form`（15279 行）→ `transform_defender` で求めます。
   - ［へんしん］がはたらくのは、バトル場にいて、特殊状態がなく、力が消えていないときです。
   - はたらくと、相手のバトル場のポケモンが写す先になります。公開した時点で決まります。
5. **flow の入口の固定**（`flow.py:167`）: `body` の最初の `E.freeze_forms(res.state)` です。
   - **固定情報が空のとき（`()`）だけ**、公開した使い手を含めて全部を固定します。PT5 の no_other の経路です。
   - 空でなければ何もしません。そのため、ほかの変身できるポケモンがいると、使い手は固定されません。
6. **別の変身できるポケモンがいる場合の固定情報:** そのポケモンの項目だけがあります。
   - **「固定情報が空でない」** は、場のどれかが固定されているという意味です。
   - **「公開した攻撃者の姿も固定済み」** は、`form_frozen(state, attacker)` が真という意味で、別の条件です。
   - 今の `freeze_forms` は前者しか見ません。SF3 は、前者が真で後者が偽の状態です。
7. **攻撃中の交代と、決定への回答:**

   - 回答でその控えを選ぶと RX1（`UNRESOLVED_REACTIVE_SWITCH_TRANSFORMED_ATTACKER`）で拒否します。
   - 変わり身の術・［にげこむ］も、`_switch_changes_attacker`（962 行）で同じ形です。
   - 固定されていれば、どちらも `()`・偽を返します（v0.124 の 3.5 節「RX1 は起こらなくなり」）。
8. **ダメージ計算が参照する姿:** `current_form` です。固定があれば固定した姿、なければ今の場から求めます。
   - 修正しないまま RX1 の判定だけを外すと、入れ替えのあとの相手（フシギダネ・ゼニガメ）を写した姿でタイプを読みます。これは CR-TRANSFORM-FROZEN-DURING-ACTION に反します。

**「条件を外して `freeze_forms` を呼び直す」案が安全と言えない理由:**

- `freeze_forms` の「すでに固定していれば何もしない」は、決定のあとの続き・トレーナーの入れ子・先読みの試行で、固定を作り直さないための約束です。
- 条件を外すと、既存の項目（ほかのメタモンの姿）をその時点の姿で上書きします。入れ子では、外側の処理の途中の姿で上書きしえます。
- 再開のたびに呼べば、処理の途中の姿（入れ替えのあと）で作り直してしまいます。
