### 2.3 カードの画像による修正（根拠 `card_image_check`）

v0.96 までの検査は、根拠 `kyuura_source_check`（kyuura の照合の記録 CC-）・`user_provided`（利用者が示した訂正）・`kyuura_existing_record`（kyuura の前の判定）だけを扱えました。
アンノーンI・D・F のルール文は、kyuura が 2026-10-24 にカードの画像（pcg-search.com となぞのばしょの 2 つのサイト）を読んで埋めたもので、根拠は `card_image_check` です。
この根拠を、ほかの根拠を広げずに、次のように確かめるようにしました（`card_image_check_problems`）。

- 画像を見たのは kyuura（`kyuura_saw_image` が真）で、エンジンは画像・公式の書籍を見ていない（`engine_saw_image` が偽）。
- 台帳に、画像ごとの画像の URL（https）・ページの URL・sha256（64 桁の 16 進数）・取得日（決めた日まで）、カードの識別（`identification`）・確かめた範囲（`scope`）・エラッタで
  ないこと（`not_errata`）・誤りの出どころ・根拠の説明がある。写しの記録の画像（`evidence`。URL・sha256・取得日）が台帳の画像と同じ。
- kyuura の照合の記録（CC-）・最新の説明（LD-）・修正のコミットを書かない（作らない）。照合の記録がその欄を照合していない。照合の記録を変えない（`card_checks_affected` が空）。
- 修正はその段で入った（段の前のコミットの台帳にない）。

2 つのサイトの画像は、kyuura の台帳の `scope` のとおり独立した 2 枚の実物の照合として数えず、CC-・LD- の代わりにもしていません。kyuura の id とサイトの番号の違い（neo2-025 が D・
サイトは 026、neo2-026 が F・サイトは 025）と、なぞのばしょの D のページの名前の既存の誤記（「アンノーン[I]」。kyuura の既存の判定）は、kyuura の記録のままです。

## 5. デッキの規定と文字

- v0.96 の名前のグループ（`CardDefinition.name_group`・`name_letter`・`deck_group_limit`）を、訂正されたルール文を持つ I・D・F にもそのまま当てはめます。ルール文が写しに入ったので、
  3 枚は自分のルール文で上限 4 を持ちます（v0.96 の「ルール文のないアンノーン」の扱いは I・D・F には要らない。M・U・A は空のままで、写しにない）。デッキのアンノーンは文字・商品に
  かかわらず合わせて 4 枚まで（`CR-UNOWN-DECK-LIMIT-ALL-LETTERS`。SUPPORTED）。I・D・F だけの 4 枚は通り、5 枚は拒否します（`DeckLimitTest`）。同じ名前の 4 枚・ひかるポケモンの 1 枚は
  今までどおり別に数えます。P39・P40・P10 を根拠にしていない点、データの名前の書き方（「アンノーンI」「アンノーン[N]」）を印刷の名前として扱わない点は v0.96 と同じです。
- デッキの物理的なカード（印刷の定義）と、場の今の姿・文字を分けます。「自分のベンチに…アンノーン「I」「N」「D」がいる」の文字は、場のポケモンの今の姿のカード（`form_def`）の
  名前のグループと文字で決めます（`effects.bench_group_letters`）。

## 6. ［INCREASE］（アンノーンI）

- 「この力は、このカードを手札から場に出したとき、1回だけ使える」（v0.43 の `EntryPower`。`from_hand_only`）。使う機会は、手札からベンチに出す操作と、トレーナーの効果で手札から
  場に出したとき（エリカの香水・マチス。v0.86・v0.96 の経路。持ち主に機会があり、持ち主の番でなくても続ける）だけで、持ち主が使うかを決めます（決定 `entry_power`）。山札から出した
  I・E・R（遺跡の石版・この力）には「手札から」の機会がありません。かがくへんかガスなどで消えていれば機会はありません（共通の確かめ）。
- 「自分のベンチに空きがないとき、この力は使えない」: 場に出したあと（機会を出す時点）のベンチで決めます。このカードを出してベンチがいっぱいになったら、機会を出しません（場に出すこと
  自体は拒否しない）。共通の処理として `EntryPower.entry_blocked` を加え、`applicable_entry_power` が見ます（v0.96 までの場に出たときの特殊能力は既定の「成り立たない」）。
- 使ったら、山札の、印刷の定義の名前のグループが「アンノーン」のたねポケモンのカード（文字を問わない。遺跡の石版と同じ `CardFilter`。uid の小さい順）からちょうど 1 枚を選び（決定
  `bench_from_deck`。選べるものの数は使ったプレイヤーだけが見る）、手札を通さずにベンチの最後へ出し（ログ `bench_from_deck` の `power`）、山札を 1 回切ります（ログ `shuffle` の `power`）。
- 山札に選べるカードがない（山札 0 枚を含む）: kyuura の `UQ-CARD-USE-WITHOUT-TARGET` の事例です。エンジンは、同じ「1枚選び出し」で選ぶカードが 0 枚になる場合の v0.43 の PW3
  （`UNRESOLVED_POWER_ZERO_CARDS`。しんかのひかり・ボスをよぶと同じ問い・同じ時点）を使い、使う機会の決定で「使う」を選ぶと止めます（使わないは選べる）。機会の決定の形（選べるもの・
  選ぶ数）は山札の中身で変わらず、相手・観戦者に見える決定（種類・プレイヤー・数）も同じです（選ぶと止める選択は観測に出さない。`IncreaseTest.test_no_unown_in_deck_is_pw3_without_leaking_the_deck`）。
- まきちらせ!ベトベトガスのはたらく間に特殊能力を持つカードを場に出すと止まる（GG1）ので、このカード自身を出す時点で止まります。山札のアンノーンがどれも出すと止めるカードなら、使うを
  選ぶと止めます（`accept_problem`。遺跡の石版と同じ）。うらのカード・今の姿の扱いは v0.96 のままです。

## 7. ［FIND］（アンノーンF）・［JOIN］（アンノーン[J]）

- 宣言して使い、自分の番ごとに 1 回です（`once_per_turn`。宣言のときに記録する）。日本語の文面にねむり・マヒ・こんらんの条件はないので、特殊状態では止めません（ベンチのポケモンは
  特殊状態にならない。バトル場のポケモンがねむりでも使える）。特殊能力を消す効果は共通の確かめ（`POWER_SUPPRESSED`）です。
- 条件: このカードが自分のベンチにいる（`POKEMON_NOT_ON_BENCH`）こと、自分のベンチのほかのポケモンに、今の姿の名前のグループが「アンノーン」で文字が［FIND］は I・N・D、［JOIN］は
  O・I・N のポケモンがそれぞれいること（`REQUIRED_BENCH_POKEMON_MISSING`）。相手の場・バトル場のポケモンの文字は足しません。うらのカードは、おもてのポケモンで足りないときだけ読みます
  （読むと FD1）。デッキのアンノーンは合わせて 4 枚までなので、使えるデッキではちょうどその 4 文字になります。
- 選べるのは山札のカード（山札にある間の印刷の定義。uid の小さい順）。［FIND］はトレーナーカードのすべて（スタジアム・ポケモンのどうぐ・なにかの化石・ピッピ人形を含む。トレーナーの
  分類から除かない）、［JOIN］はたねポケモン・進化カード（「ベイビィポケモン」のカードは写しにない。なにかの化石・ピッピ人形は山札ではトレーナーなので入らない）。1 枚を選び（決定
  `search_deck`。選べるものの数は見せない）、見せてから手札に加え（`zones.reveal_deck_to_hand`。ログ `reveal_from_deck` は公開）、山札を 1 回切ります。
- 山札に選べるカードがない（山札 0 枚を含む）: kyuura の `UQ-CARD-USE-WITHOUT-TARGET` の事例です。エンジンは v0.43 のしんかのひかり（同じ「山札から…を1枚選び出し、相手プレイヤーに
  見せてから、手札に加える」）と同じ PW3 で、宣言の前に止めます（v0.43 からの検索の特殊能力の扱いと同じ。止めるのは使ったプレイヤーの操作の受け付けで、状態・ログは変わらないので、相手に
  山札の中身は見えない）。空振りや 0 枚の答えは許していません。

## 8. ［DARK df］（アンノーンD）・［NORMAL df］（アンノーン[N]）の共通処理

### 8.1 当てはめる範囲

- 1 つの型（`ReduceOwnGroupDamageFromType`。タイプ・文字・名前・量を引数にする）で表し、カード id の分岐を `engine.py`・`resolution/` に加えていません。常にはたらく（宣言しない）
  特殊能力で、場のどこでもはたらき、日本語の文面に特殊状態の条件はありません（`blocked_by_status` は偽）。消す効果は共通の確かめです。
- 守るのは、この力を持つポケモンの持ち主の場の、今の姿の名前のグループが「アンノーン」のポケモン全員（自身・ベンチを含む。`CR-UNOWN-DF-PROTECTS-OWN-UNOWN`。CONFIRMED）。相手の場の
  アンノーン・自分のほかの名前のポケモンは守りません。
- 当てはめるのは、ダメージを与えるポケモンの今有効なタイプが「悪」（［NORMAL df］は「無色」）のワザのダメージ（`CR-UNOWN-DF-SOURCE-TYPE`。SUPPORTED）。持ち主を限らないので、自分の
  「無色」ポケモン（エリカのハクリュー）の「ふぶき」の「うら」が自分の控えのアンノーンに与えるダメージも減らします。名前の「わるい」（わるいハクリューは「無色」）・ついているエネルギー・
  写したワザを印刷したカードのタイプでは決めません（写したワザは写して使うポケモンのタイプ）。タイプの条件は、共通の処理として変更効果に加えた `DamageModifier.attacker_type` で
  表し、色の読み方（VS1 など）ごとの計算（`damage.calculate_attack_damage` の `attacker`）で決めます（読み方で結果が変われば今までどおり VS1 などで止まる）。
- 段階（`CR-UNOWN-DF-DAMAGE-STEP`。SUPPORTED）: 受けるアンノーンがこの力を持つカード自身なら p.321 の 8 段階、ほかのアンノーンの力なら 6 段階の加算 -30。段階が違うだけでは止めません。
  同じ段階の順番で結果が変わるときは既存の順番の決定（6 段階はワザを使うプレイヤー、8 段階は受けるプレイヤー。v0.35）で、「足すだけだから常に同じ」とは決めていません（計算の比べで
  決める）。0 以下なら「ダメージを受けなかった」です。
- ダメージカウンターをのせる・移す効果はダメージではない（GR-2000-P320-COUNTER-MOVE）ので、この力を通しません。

### 8.2 同じ力が 2 匹以上のとき（DF1）

- 「自分の場のほかのアンノーン「D」の「DARK df」がはたらいているとき、この力は、はたらかない」ので、同時にはたらくのは多くても 1 つです（`CR-UNOWN-DF-AT-MOST-ONE`。CONFIRMED。-60 に
  しない）。どれがはたらくか・1 つもはたらかないのかを決める記録はありません（`UQ-SELF-EXCLUDING-POWER-COPIES`）。
- 共通の処理: 常にはたらく特殊能力に `self_excluding` を加え、はたらきうる候補を持ち主と力ごとに集めます（`effects.self_excluding_groups`）。そのダメージに当たりうる組に候補が 2 匹以上
  あれば、読み方（1 つもはたらかない・候補ごと。`effects.self_excluding_readings`）ごとに変更効果を集め（`with_copies`）、受けるダメージと要る決定（同じ段階の順番・お上品攻撃の減らす量と、
  その答えごとの結果。`kernel._damage_outcome`）を比べます。違えば DF1 `UNRESOLVED_SELF_EXCLUDING_POWER_COPIES` で止めます（状態・乱数・ログを変える前。選ぶ対象のワザでは、その対象を
  選ぶと止める）。uid・場の並び・場に出た順で代表を選びません。読み方で結果が同じなら止めず、1 つもはたらかない読み方の変更効果でログを書きます（どの読み方でも量は同じ）。
- 止めない隣の場面（単体テストで確かめた）: 対象外のタイプのワザ、アンノーンでない相手、相手の場の同じ力（「自分の場のほかの」なので組が別）、能力を消す効果（スタンウェーブ）で候補が
  1 匹だけ、ほかの効果（ディフェンダー）でどの読み方でも 0、同じ力の 2 匹がいるだけの登場・ほかの操作。
- 効果を除くワザでは、読み方の比べを除く範囲の読み方ごとに行います（9 章）。除かれる力も、はたらいている候補として数えます（能力の抑止と、あるダメージで効果を無視することは別。
  無視される力を存在しなかったことにして、ほかの候補がはたらく読み方を暗黙に選ばない）。

### 8.3 ワザでないダメージ（DF2）

- 説明は「ワザ」と書かず「「無色」ポケモンからダメージを受けるとき」と書きますが、ワザでないダメージに受けるダメージを変える効果を当てはめるかは `UQ-NON-ATTACK-DAMAGE-MODIFIERS`
  （未解決）です。特殊能力のダメージ（`effects.received_power_damage`。v0.96 までは受けるポケモン自身の力だけを集めていた）に共通の確かめ（`_non_attack_damage_question`）を加え、
  場の常にはたらく特殊能力のうち当てはめるかが決まらないもの（`ContinuousPower.non_attack_damage_modifier`。受けるポケモンでないベンチの［NORMAL df］も見る）を当てはめると最終の量が
  変わるなら、DF2 `UNRESOLVED_POWER_DAMAGE_RECEIVED_POWER` で止めます（量を変える前。v0.75 の DB1 と同じ扱い）。
- 比べ方は v0.79 の `non_attack_change_matters`（鋼エネルギー NIP1X-010 の「-10」の前・あとのすべての順番）で、0 以下は 0 にそろえます。R団のカビゴンの［わるいねぞう］の 20 を、ワザを
  使ったアンノーンが受ける場面で、自身の［NORMAL df］・ベンチの［NORMAL df］のどちらでも止まり、鋼エネルギー 2 枚でどちらの読み方でも 0 なら止めません（`DarkNormalDfTest.test_power_damage_is_df2`）。
  p.321 のワザの段階は、ワザでないダメージに移していません。「悪」のポケモンの特殊能力のダメージは kyuura のデータにないので、［DARK df］では今は起こりません。
- 関係しない既存の特殊能力のダメージ（なぞのかべ・ふしぎなバリアー・鋼エネルギー・MT1・DB1）の扱いは変えていません。
