# v0.136: カードめくりゲームの答えの受理・拒否による情報漏れの修正

カードめくりゲーム（neo1-080）で、おもてのカードのある山札（v0.126。フラッシュ）のとき、正解の答えだけが FU3 で拒否され、答えの受理・拒否から、だれにも見えない相手のサイドの種類が
分かった（v0.135 の横断調査で見つけた。v0.135 の文書 8 章）。v0.136 は、使う前に正解・正解でないの両方の結果を確かめ、どちらかが既存の止め方に当たれば使う前に止める。
**情報漏れは修正した。FU3（`UNRESOLVED_FACE_UP_DECK_HIDDEN_TAKE`。UQ-FLASH-FACE-UP-DECK）などの裁定は未解決のまま**で、この版は読み方を決めていない。

棚卸しの項目名は `GAP-CARD-FLIP-REJECTION-ORACLE`（v0.135 で新たに見つけた項目として、v0.133 の棚卸しの記録を変えずに追記した。11 章）。

## 2. 原文と登録

日本語の印刷の文面（kyuura 71d1728 の写し。`effects.CARD_FLIP_GAME_TEXT`。登録 `TrainerEntry(GuessOpponentPrizeKind(...))`。kyuura の種類 `goldenrod_game_corner`）:

> うらになっている相手の「サイドカード」を1枚選び、そのカードが「ポケモン(ベイビィポケモン・たねポケモン・進化カード)」か「トレーナーカード」か「エネルギーカード」かを答える。その後、
> そのカードをおもてにして、正解なら、あなたは山札からカードを2枚引いて、手札に加える。
> おもてにした「サイドカード」は、そのままにしておく。

ほかのクイズ（その1・その2・その3・ポケモン性格判定）と同じ手順だと仮定せず、原文と実装から確かめた違い:

| | カードめくりゲーム | その2・その3・性格判定（v0.135）・その1（v0.129） |
|---|---|---|
| 隠れているもの | 相手のうらのサイド（**だれにも**見えない。使ったプレイヤーにも） | 使ったプレイヤーが手札から置いたカード（使ったプレイヤーには見える） |
| 選ぶ | 使ったプレイヤーが、うらの相手のサイドの位置（決定 `SELECT_OPPONENT_PRIZE`） | 使ったプレイヤーが置くカード |
| 答える | 使ったプレイヤー（決定 `QUIZ_ANSWER`。候補は 3 つの種類 `FLIP_KIND_NAMES`） | 相手プレイヤー |
| 示される情報 | 選んだ位置だけ（続きの情報にカードを書かない） | ワザの名前（その3）など |
| おもてにする | サイドをおもてにして、そのまま（`zones.reveal_prize`。`face_up_prizes`） | 置いたカードをおもてにして、手札にもどす |
| 正解 | 使ったプレイヤーが 2 枚引く（引けるだけ） | 相手プレイヤーが引く |
| 正解でない | **何もしない（引かない）** | 使ったプレイヤーが引く |

## 3. 再現（修正の前の基点の木）

再現の手順（`tests/test_quiz_answer_rejection_v0_135.py` の合法な経路の盤面の作り方を使う）: プレイヤー 0 の手札にフラッシュ・カードめくりゲーム、相手のサイドの位置 0 だけが違う（エビワラー
＝ポケモン／きずぐすり＝トレーナーカード／草エネルギー＝エネルギーカード）3 つの状態で、フラッシュのあと、カードめくりゲームを使う → 位置 0 を選ぶ → 「ポケモン」と答える。

| 盤面（おもての印。v0.135 の `legal_marks` と同じ作り方） | 結果（基点の木） |
|---|---|
| none（フラッシュなし） | 3 状態とも受理（漏れなし） |
| both（両方の山札の上から 5 枚） | サイドがポケモンなら答えで FU3、ほかは受理（**漏れ**） |
| user_only（使ったプレイヤーの山札だけ上から 4 枚） | 同上（**漏れ**） |
| opponent_only（相手の山札だけ上から 5 枚） | 3 状態とも受理（相手は引かないので当たらない） |
| second（両方の上から 2 枚） | 同上（**漏れ**） |
| top_only（両方のいちばん上の 1 枚だけ） | 3 状態とも受理（1 枚目はいちばん上なので FU3 にならない） |

`tests/log_audit.py` の `twin_command_problems` は、漏れのある 3 つの盤面で「段 2: 同じ公開の情報から同じ操作 … をしたのに、受理・拒否・理由が状態によって違う:
[('UnsupportedError', 'UNRESOLVED_FACE_UP_DECK_HIDDEN_TAKE'), ('accepted',)]」を返した。拒否は状態・乱数・ログを変えないので、使ったプレイヤーは「ポケモン」を送って拒否されれば
サイドがポケモンだと分かり、別の答え（正解でない）を送り直せた。サイドの種類は相手にも見えないので、相手の秘密（サイドの中身）が使ったプレイヤーに漏れる。

## 4. 修正

`kyuura_engine/effects.py` だけを変えた（`engine.py`・`resolution/` は変えていない。カード id の分岐はない）。

- `quiz_draw_outcome_stop(state, user, draw, *, outcomes=None)`（v0.135 の共通の確かめ）に、答えの結果ごとの (引くプレイヤー, 枚数) の並び `outcomes` を加えた。既定（`None`）は v0.135 と
  同じ ((`user`, `draw`), (相手, `draw`))。枚数 0 は「その結果では引かない」で、試さない（山札が変わらないので止め方に当たらない）。ほかのクイズ 4 種類は既定のまま呼ぶ（動きは同じ）
- `GuessOpponentPrizeKind.check_playable`: 既存の FC1（うらの相手のサイドがない）を先に確かめ、そのあと `face_up_draw_stop` が止め方を返せば `UnsupportedError(コード, 理由)`。
  `face_up_draw_stop` は `outcomes=((使ったプレイヤー, 2), (使ったプレイヤー, 0))`（正解なら使ったプレイヤーが 2 枚、正解でないなら引かない）を渡す。ドローの枚数・効果は変えていない
- 錯乱ジムで借りる（v0.57。`borrow_unusable_reason` が借りたプレイヤーで `check_playable` を呼ぶ）・［ちえくらべ］（v0.132。使えるかの確かめが反応の決定より前）は、同じ
  `check_playable` を通るので、新しい処理は加えていない（7 章）

## 5. 使う前に止める制限（情報漏れを防ぐための保守的な制限）

使ったプレイヤーの山札で、正解の引き方（2 枚。引けるだけ）が既存の止め方に当たるなら、正解でない（引かない）なら進められても、カードを使う前に止める。止める盤面は、使ったプレイヤーの
山札で「引く枚数（min(2, 山札の枚数)）が 2 以上で、おもての印が 2 枚以上」（2 枚目がおもて）のとき。相手の山札のおもての印では止めない（相手は引かない）。

- これは情報漏れを防ぐための**エンジンの保守的な制限**で、裁定ではない。FU3（UQ-FLASH-FACE-UP-DECK）の読み方を決めておらず、解決済みにしない
- v0.135 までより使えない場面が増えるのは、使ったプレイヤーの山札の 2 枚目がおもての盤面で、サイドの種類と答えが合わない（正解でない）場合（v0.135 までは進めた）
- 山札の枚数の不足を新しい拒否の理由にしていない（引けるだけ引く。山札 0 枚・1 枚は受け付ける）
- 拒否は使う前（`PlayTrainer`）。手札から出す・サイドを選ぶ・答える・おもてにする・錯乱ジムのコイン・［ちえくらべ］の決定のどれも起こらず、状態・乱数・ログは変わらない

## 7. 錯乱ジム・［ちえくらべ］・サドン・デス

- 錯乱ジム（v0.57）: 使ったプレイヤーの山札で止める盤面では、手札から出す前（錯乱ジムのコインの前）に止め、コインを投げない（`ChaosGymTest.test_stops_before_the_chaos_coin`）。
  「うら」で相手が借りて使うとき、確かめるのは借りたプレイヤー（そのプレイヤーが選び・答え・正解なら引く）の山札。相手の山札の 2 枚目だけがおもての盤面では、使ったプレイヤーは使えて、

  フラッシュを使えば、今の区間の印で止める（`SuddenDeathSegmentTest`）
- ナツメのサイキックコントロール（v0.58。相手のトラッシュのトレーナーを使う）: 選べるカードの確かめ（`discard_trainer_use_choices`）が `check_playable` の `UnsupportedError` を
