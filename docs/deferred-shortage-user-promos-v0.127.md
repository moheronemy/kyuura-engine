# v0.127: 枚数不足の途中停止と、利用者指定の簡略ルールのプロモ 3 枚

v0.127（版 0.127.0）は、共通の数量処理の **途中停止**（説明の枚数に足りないと分かった時点で、実際のコインとそこまでの処理を残して対戦を止める終端の状態）の基盤を作り、それを使う
ファイヤー 2 枚（ドライアップ）・怪電波マシーンを登録する版です。加えて、利用者が明示的に指定したエンジン固有の簡略ルールで、_のピカチュウ 2 枚とハマちゃんのヤドキングを登録します。
合計 6 枚（ポケモン 5・トレーナー 1、ワザ 8・特殊能力 0）です。`engine.py`・`resolution/` にカードの id による分岐は加えていません。

**途中停止は公式の裁定の解決ではありません。** kyuura の UQ-STATED-COUNT-SHORT（書かれた枚数に足りないときの扱い）は未解決のままで、エンジンは足りない要素をどう処理するかを
決めずに、その手前で止めます。**プロモ 3 枚の処理は、利用者が指定した簡略ルールです。** 公式の裁定・最新の説明・エラッタではありません（4 章）。

## 4. 利用者が指定した簡略ルール（プロモ 3 枚）

### 4.1 指定と範囲

利用者の指定（2026-11-01）は「のピカチュウについては誕生日の確認をせずに通常のコイントスのみ」「ハマちゃんのヤドキングに関しては発話要件を無視して実装」です。公式の裁定・最新の
説明・エラッタではなく、エンジン固有の簡略ルールです。今回の登録では、この簡略化を通常の動作として採用します（厳密な処理との切り替え・追加の承認の画面は作っていない）。

- 省くのは、誕生日の条件と、2 つのワザの発話の条件だけです。コスト・番・こんらんの宣言のあとのコイン・ワザの効果の到達・弱点・抵抗力・ナツメのESP・きぜつ・進化などは通常どおりです。
- 誕生日の入力・実名・記入名・日付・OS の時計は使いません（どの日も同じコインの処理）。「いつも誕生日である」とは記録せず、誕生日の条件を省く仕様として記録します。
- 発話済みの申告・回数のカウンター・音声の認識・確認の決定・UI は作りません。発話していないことを拒否・失敗の理由にしません。

## 5. 途中停止の結果と、従来の拒否

| 結果 | 契約 |
|---|---|
| 従来の拒否 | `IllegalActionError`・`UnsupportedError`。入力の状態・乱数・ログは変わらず、別の合法な操作を選べる |
| 通常の受理 | 正常な次の `GameState` |
| 途中停止 | 実際のコインと、そこまでに一意に決まった処理を残した **終端の `GameState`**（`Phase.HALTED` と `Halt.interruption`）。再試行・別のワザ・裁定を選んでの再開はできない |

- 公開の API は `apply_command` のまま（`GameState` を返す）。渡した状態は変えません（処理はコマンドの入口の複製の上）。
- 途中停止にしてよいのは、共通の数量処理の明示的なチェック地点（`interruption.check_quantity`）だけです。そこまでの処理がどの読み方でも同じで、足りない要素をまだ処理しておらず、数を
  知るのに秘密の情報を使っていない地点です（ドライアップ: 選んだポケモンの場のエネルギーカード。怪電波マシーン: 相手の対戦ポケモンのエネルギーカード。どちらも公開の情報）。
- チェック地点は `DeferredShortage` を投げます。これは `UnsupportedError`・`OpenQuestion` の子ではなく、コマンドの入口（`engine._apply_once`）だけが捕まえて終端の状態にします。一般の
  `UnsupportedError`・問い・内部エラーを包括的に捕まえて途中停止に変えていません。UQ の名前・例外の名前だけで既存の呼び出し（HC6・FC1 など）を新しい方式に切り替えていません。
- 必要な数 > 処理できる数が分かったら、その要素を処理しません。あるだけ処理する・失敗として番を終える・効果なしで続ける、のどれにも決めません。
- 残すもの: 宣言・選んだ対象・実際のコイン・ナツメのESPの最後の選択・乱数の位置・そこまでのログ。使用中のトレーナー（`trainer_in_use`・`trainer_stack`）と固定した変身の姿
  （`frozen_forms`）は在途のまま残します（既存の停止 `procedures.halt` は使わない。コマンドの終わりの解除・トラッシュ・番の進行をしない）。カードを片付けず、番・ポケモンチェック・
  サイドを進めません。
- 中断の記録 `state.Interruption`: 中断の種類（`stated_count_short`）・停止コード・kyuura の論点・発生元（ワザ・トレーナーの登録のキー）・使ったプレイヤー・対象の持ち主と場のポケモンの番号・
  止まった要素（`discard_water_energy_cards`・`return_energy_cards_to_hand`）・必要な数・処理できる数・未完了の処理・在途のカード・ログの位置。どれも公開の情報で、診断用の文は `Halt.message`
  に分けます。ログの最後に `halted`（`interrupted` と公開の項目）を残します。
- 観測は、途中停止の状態だけ `interruption`（公開の記録）を加えます（ワザ・トレーナーを使い終えた盤面と表示しない）。再開の機能は作っていませんが、保存・観測・診断はできます。
- 中断のあとは、どの対戦のコマンドも受け付けません（`HALTED` の既存の拒否）。待っていた決定はなく（チェック地点では決定を出していない）、終端から写しても続けられません。clone・deepcopy・
  pickle・書き出しで同じ状態になります。
- 答えの続きを試す確かめ（`_decision_has_unstopped_answer`・`_trainer_dead_end`）は、途中停止になる続きを受け付けられる続きとして数えます（拒否されたので別の答えを試す扱いにしない）。
- v0.126 の表向きの山札: 止める時点までに変わった山札は、通常と同じに分類します（`faceup.command_problem`。読み方で分かれる変わり方なら、途中停止にせずに受け付けない）。FU1〜FU6 と隠れた
  カードの問いは包括的に後に回していません。ドライアップ・怪電波マシーンはチェック地点までに山札を動かしません。

## 6. 先読み・上限なしコイン・ナツメのESP

- 宣言の前の先読み（`resolution.preflight.explore`）は、通常の完了・従来の拒否（問い）・チェック地点での途中停止の終端を分けて数えます。途中停止の枝があることだけで宣言を拒否しません。
  ほかの枝の問いは今までどおり見つけ、宣言を拒否します。`derived` の方法（実際の処理を先に行う）でも、実際の処理の途中停止は、残りの枝を試したあとに問いがなければそのまま終端になります。
- 「おもて」の数 H が数の比べにだけ使われ、処理できる数 N がコインの前に決まる要素（ドライアップ）では、先読みの組（`programs.shortage_classes`）は h = 0, 1, …, N と N + 1 です。N + 1 は
  「N より多い」すべての h の代表です。h > N では要素がチェック地点で必ず途中停止し、そのあとの処理（トラッシュ・きぜつの判定）をしないので、どの h でも終端の分類（停止コード・止まった要素・
  処理できる数・在途の状態）は同じです（h はログと記録の必要な数にだけ残り、先読みの範囲では読まれない）。H = N（ちょうど全部）と H = N + 1（途中停止）は別の組です。H がダメージなど
  ほかの処理にも使われる要素には、この組を使いません（ダメージの組 `unbounded.head_classes` はそのまま）。
- 実際のコインは最後の「うら」まで投げ、実際の H・ログ・乱数を残します。資源の数で打ち切らず、min(H, N) に丸めず、先読みの代表を実際の結果にしません。
- ナツメのESP（ワザのコインだけ）は、最初のまとまりを投げ終えて、やり直すかを聞いてから、最後の並びの H で判断します。N = 2 で最初の H = 3 でも、やり直して H = 1 ならトラッシュし、
  やり直さない・やり直しても多いなら途中停止です。足りるまで投げ直しません。怪電波マシーンはトレーナーのコインなので、ESPは当たりません。
- トラッシュするカードの選び方（0 < H < N の決定）は、実際の決定ではちょうど H 枚のすべての組を選べます。先読みは、カードの種類（カード id と、この番の色の記録・エネルギーとしての役割の
  有無）の組ごとに 1 つの答えだけを試します（同じ種類のカードは、入れかえても先読みの範囲の結果が同じ）。開発中の対戦（seed 90）で、「水」エネルギーカード 10 枚以上のポケモンを選べる
  場が先読みの上限で `UNSUPPORTED_PREFLIGHT_LIMIT` になったので、こうしました（上限 4,096・秘策の上限 512 は増やしていない。選べるものを削っていない）。対象を選ぶ決定・ESPの答えは
  今までどおりすべて試します。途中停止でない未検証の枝を「同じ終端」とまとめていません。

## 7. ファイヤー（ドライアップ）・怪電波マシーン

### 7.1 ドライアップ（DU1）

- 最新の説明「相手の場にいるポケモンを1匹選ぶ。その後、「うら」が出るまでコインを投げ続け、「おもて」の数ぶんの「水」エネルギーカードを、そのポケモンからトラッシュする。」
  （LD-ES2-005-ATK0・LD-QSG-055-ATK0）と CR-DRY-UP-PROCEDURE・CR-UNTIL-TAILS-NOT-CAPPED にしたがいます。ダメージはありません。
- 要素: `ChooseEffectTarget`（相手の場。選ぶのはワザを実際に使ったプレイヤー）→ `DiscardChosenTypedEnergyUntilTails`。選んでからコインを投げます（H を見て選び直さない）。
- N は選んだポケモンの「水」エネルギーカードの枚数（カードとしての種類・タイプ `attached_typed_energy_cards`。枚数で数え、個数で数えない）。H ≤ N なら、ちょうど H 枚をトラッシュします
  （H = 0 は何もしない。H = N は全部（決定なし）。0 < H < N は、ちょうど H 枚の決定 `DISCARD_OPPONENT_ENERGY`）。トラッシュの前に効果の到達（`reaches`）を評価し、トラッシュは既存の
  `discard_energy_from_play`（リサイクルエネルギーなどのもどる処理）です。
- **DU1**（`UNRESOLVED_DRY_UP_WATER_ENERGY_SHORT`。UQ-STATED-COUNT-SHORT）: H > N（N = 0 をふくむ）なら、トラッシュする前に途中停止します。選んだポケモン・コインは残ります。
- 選べるが選ぶと止めるポケモン（既存の問い。黙って選べるものから除かない）: 「水」エネルギーカードの数え方が色の読み方で変わる（レインボーエネルギー・［エネエネ］・［へんしん］・ミラクル
  エネルギー・色を変えたカード。`transform_energy_question`）・コインが決めるトラッシュが効果を受けない（タケシの保護・「ワザをうけない」など `prevented_effect_coin`、［KEEP］
  `keep_voided_discard_coin`、「とうめい」を持つ `evaded_effect_coin`）・トラッシュしたあと手札にもどるかが決まらないカード（エコロジムの TE2 など）。どの相手のポケモンを選んでも止まるなら
  宣言の前に止めます。水の 0 枚のポケモンは止めずに選べ（N = 0）、H = 0 なら何もせず、H ≥ 1 なら DU1 です（CR-DRY-UP-PROCEDURE が 0 枚を UQ-STATED-COUNT-SHORT に挙げるので、使えるかの
  別の問いにはしていない）。

### 7.2 怪電波マシーン（TW1・TW2）

- kyuura の印刷の文面と CR-THOUGHT-WAVE-MACHINE-PROCEDURE・CR-UNTIL-TAILS-NOT-CAPPED にしたがいます。トレーナーのコインを「うら」まで投げ、「おもて」の数ぶんの「エネルギーカード」（特殊
  エネルギーも 1 枚）を、相手の **対戦ポケモン** からはがし、相手の **手札** にもどします（トラッシュではない）。選ぶのは使ったプレイヤーです（0 < H < N のときだけ決定 `RETURN_ENERGY`）。
  ログ `trainer_return_energy` の `user` が使ったプレイヤーです（持ち主が使うエネルギーサーキュレートのログは v0.126 と同じ）。
- 使い終えたら、エンジンが使用中のカードをトラッシュしてから既存の `END_TURN` の経路で番を終えます（H = 0 でも番を終える）。
- **TW1**（`UNRESOLVED_THOUGHT_WAVE_MACHINE_ENERGY_SHORT`。UQ-STATED-COUNT-SHORT）: H > N なら、もどす前に途中停止します。もどさず、使用中のカードを片付けず、番を終えません。
- **TW2**（`UNRESOLVED_THOUGHT_WAVE_MACHINE_WITHOUT_TARGET`。UQ-CARD-USE-WITHOUT-TARGET）: 相手の対戦ポケモンにはがせるエネルギーカードがない（ついていない・タケシの保護）なら、手札から出す前に
  止めます（従来の拒否）。［でんせつのからだ］でトレーナーの効果を受けない相手の対戦ポケモンなら、コインの前に既存の LB1 で止めます。錯乱ジムで相手がかわりに使うと CH1 です。

### 7.3 解決していない問い

途中停止の基盤を作っても、0 枚・対象なし・無効化・色の読み方・コインを投げるかなどの問いがすべて解決するわけではありません。受け付ける通常の経路（H ≤ N）・途中停止（DU1・TW1）・
事前に止める範囲（TW2・選ぶと止めるポケモン・既存の問い）を、上のとおり分けて記録しました。
