## 3. 状態と処理の順（コードの位置は `spec/order.md`）

**実際の処理（0.188.0）:**

1. `engine._apply_once`（engine.py 907〜917）。入口の状態 `state` を複製して `new` を作り（907）、`ctx = _context(state, ...)` で **`ctx.original` = 入口の状態**にします（910。うらのまま）。`freeze_forms(new)`（915）のあと、`_reveal_for_action(new, …)`（917）が `new` の上でおもてにします。
2. `zones.reveal_face_down`（zones.py 82〜）。同じ場のポケモン（同じ番号）のまま、`face_down_cards` から外し、ログ `secret_plan_revealed`（公開）を書きます。乱数は使いません。
   - たねでなければ、トラッシュして受理し、ワザの処理に入りません（`_reveal_for_action` が True）。
   - たねなら、`new` の上で handler に進みます。以後、`new` の `card_def` は本当のカードの定義になります。
3. `flow._use_attack(ctx, state=new, cmd)`（flow.py 149〜）。`check_use_attack` が、おもてにした `new` の上で、ワザ・要素の並び・クチバシティジム（今の姿の名前）を確かめます。`body` はこれらの値と番号 `pid` を閉じ込めます（160）。
4. 先読み `derived`（既定。flow.py 195 `P.after_real_run(state, ctx.original, …)`）:
   - **実際の処理:** `new` の上で先に処理します（preflight.py 244〜。乱数は `RecordingRandom` で記録）。
   - **ほかの結果:**
     - スタジアムのコインやワザのコインを投げたら `siblings` です。決定・コイン以外の乱数・例外があれば `full` です（preflight.py 254〜256）。
     - **ほかの結果は `ctx.original` の複製**（preflight.py 125。乱数は `Oracle`）で、`body` を最初から試します。
     - この複製では、使い手はまだうらです。
5. 複製の中で相手の対戦ポケモンへダメージを与えると、`kernel.deal_damage`（kernel.py 1028 は受けるポケモンがうらならおもてにする）→ `compute_damage`（1107）→ `effects.same_for_type_readings`（14351）→ `definition_views`（14302）→ `max_hp`（14128）と進みます。そこで **使い手（自分のうらのカード）の `FaceDownDefinition.hp`** を読み、`HiddenPropertyRead`（FD1）になります。
   - 受けるポケモンは公開のおもてのカードです。
   - 自分へのダメージ（スタジアムの「うら」の 10）なら、使い手が受けるポケモンとして 1028 でおもてになるので読めます。G0 がコインつきでも通る理由です。
6. `explore` は問い（`OpenQuestion`）・`DryRunComplete`・`NeedToken` などだけを捕まえます。`HiddenPropertyRead`（`UnsupportedError`）は `after_real_run` の外へ出て、コマンドの拒否になります。
7. 拒否の巻き戻し: `_apply_once` は `new` を返さずに例外を投げます。入口の状態（乱数・ログ）は変わりません（0.188.0 のテスト `test_basic_target_rejected_by_the_engine_same_as_direct` で確かめ済み）。先読みの複製・乱数（`Oracle`）・解決の記録は捨てられ、状態に残りません。

**区別すること:**
- 先読みは公開の**あと**に始まります（`_use_attack` はおもてにした `new` で呼ばれる）。
- しかし、ほかの結果を試す複製の元は公開の**前**の `ctx.original` です。

公開の後に始まる先読みが、公開前の状態を使っています。

**同じ先読みのほかの方法との食い違い:**
- `derived_full`（flow.py 205 `P.derived(state, …)`）と `legacy`（`v013_checks.check(state, …)`）は、handler に渡された `new`（おもてにしたあと）から試します。
- `derived` が `ctx.original` を使う理由は、v0.15c の設計（docs/preflight-optimization-v0.15c.md 2 章）では「実際の処理で変わる前の状態から、ほかの結果を試す」ためです。そのうえで `derived` は `derived_full` と同じ結果（受理・拒否・コード・理由・状態）になることを、等価性のテストで固定していました。
- v0.67 で handler の前に状態を変える処理（うらのカードをおもてにする）が入りました。そのため、うらの使い手のときだけ、この等価性が崩れています。
- 確認した範囲では、ワザ（`UseAttack`）の handler の前に入口の状態と `new` が違う点は、`freeze_forms`（`body` の始めにもう一度する）と、おもてにすることだけです。`open_probe` はワザでは呼びません（engine.py 1170〜 `_probes_receipts`）。

## 4. 停止の性質と情報の境界

| 群 | 分類 | 理由 |
|---|---|---|
| G1a・G1b・G1c（24 ワザ・コインなしの 1 面） | **B（処理の順の不整合）** | 下の 6 点 |
| G2 のコインつき（VM1） | **A（既存の未裁定）** | `_stadium_attack_coin` が実際の処理で、コインの前に `vermilion_attack_order`（ワザ自身の失敗とスタジアムのコインの順番。stadiums-v0.57 の VM1）で止める。おもての使い手でも同じで、うらかによらない |
| 読んだ要素がワザごとに 1 つか | **C（未特定）** | 投げた場所の保存は 1 件だけ。群の所属は静的な推論で決まるが、ワザごとの最初の読み取りの位置は実装の単位のテストで確かめる |

G1 を B とする理由:

1. 読んだのは、ワザを使う本人のうらのカードの HP です。相手のカードではありません（盤面の相手のカードはどれもおもて）。
2. 実際の処理では、そのカードはワザの処理の前に公開（`secret_plan_revealed`）しています。宣言の後のどの結果でも、すでに公開の情報です。マチスの秘策の扱い（ワザを使う時はその前におもてにする。engine.py `_FACE_DOWN_ACTIONS`・`_reveal_for_action`）とも合います。
3. 読んだ状態は、本処理では存在しない状態です（公開の後に始まった先読みが、公開前の複製を使った）。
4. `derived_full`・`legacy` はこの読み取りをしません。等価のはずの方法で結果が変わります。
5. G1c では、コインなしのかまいたちの受理・拒否が、実際の処理のコインの面で変わります（「おもて」なら受理、「うら」なら FD1）。
   - 拒否から次のコインの面（秘密の乱数）が本人に分かります。情報漏れの候補です。
   - `after_real_run` が、ほかの結果の問いは実際の結果によらず同じにする（`siblings+full`）という約束にも反します。
6. FD1 の本来の目的（errors.py `HiddenPropertyRead`: 公開していないカードの項目を読んで、相手の知らない値で結果を変えないこと）は、ここでは守る対象がありません。

**維持する停止:**
- 相手のうらのカード、自分の公開していないほかのうらのカード（ベンチ）の項目を読む FD1 は維持します。修正の後の複製でもうらのままで、`FaceDownDefinition` は変えません。
- 本人が本当のカードを知ることと、エンジンがそれを使えることは別です。エンジンが使えるのは、コマンドの処理で公開した後だけです。公開の前（候補の作成・入力の検査）には使いません（R-2 の設計のまま）。

**先読みが外へ漏れない仕組み（変えない）:**
- 複製は捨てます。乱数は `Oracle`（実際の乱数を読まない）です。
- 解決の記録は状態に保存しません。拒否の理由は本人の応答だけに出ます。

### 推奨（案 1）の実装仕様

- **修正する共通経路:** `kyuura_engine/resolution/flow.py` の `_use_attack` だけです。engine.py・preflight.py・kernel.py・effects.py・cards.py・zones.py は変えません。
- **状態の受け渡し:**
  - `check_use_attack` の後、`after_real_run` の前に、`ctx.original` の同じ番号のポケモン（`ctx.original.find_pokemon(pid)`）がうらかを見ます。
  - うらなら、複製の元を `base = state.clone()` にし、そうでなければ `base = ctx.original`（今までどおり）にします。
  - `P.after_real_run(state, base, …)` に渡し、`on_limit` の `v013_checks.check` にも同じ `base` とその中の使い手を渡します。
  - `ctx.original` そのものは変えません。ほかの handler の `dormant_scram(ctx.original)` などはそのままです。
- **維持する停止と対象外:**
  - FD1 の定義、相手・自分のほかのうらのカードの FD1、VM1（A）、`UNSUPPORTED_PREFLIGHT_LIMIT` は維持します。
  - たねでない本当のカード（handler に入らない）は変わりません。
  - 特殊能力の宣言（`UsePokemonPower`）・にげる・進化は対象外です（この先読みを通らない）。
  - カード名・ワザの一覧による例外は作りません。
- **期待する変化:**
  - うらのたねの使い手のワザの結果が、「同じ状態で先におもてにしてから同じコマンドを送った結果」（公開の後の双子）と同じになります。
  - 保存した盤面では、G1a・G1b と G1c の面で FD1 は 0 件の見込みです。受理になるかは公開の後の双子の結果しだいで、ほかの問いで止まるワザがあればそのコードになります。
  - G0 は受理のまま、G2 のコインつきは VM1 のままです。
- **不変条件:**
  - 実際の処理の乱数の使い方とログは変わりません。受理されるコマンドの結果は、公開の後の双子と同じになります。
  - 拒否のときは、状態・乱数・ログ・決定の通し番号が変わりません。
  - 先読みの複製・`Oracle`・記録は状態に残りません。
  - おもての使い手のワザは、複製の元・結果ともに 0.188.0 と同じです。
- **裁定・選ぶ時点:** どちらも変えません。クチバシティジムのコインを宣言で選ぶこと、VM1 の止め方、FD1 の意味はそのままです。利用者の裁定の判断は要りません。
