## 4. 局面の比較

試み（主体の記録の候補・選択・入力・`check`・`submit`）を n の順に並べ、TR7 と TR8 を比べました。

### 4.1 最初の候補の差（試み 147）

- **場所:** position 102・番 35・主体 0。旧局の番 35 と同じ場所です。番の番号だけで対応づけてはいません。
- **同じ局面であることの確かめ:**
  - その前の公開の出来事（284 件）が、TR7 と TR8 で同じでした。
  - 番 35 の出来事は、どちらも次の順でした。主体 0 がラッキースタジアム（カード 56）を使った（`stadium_used`・コイン「おもて」）→ 手札のラッキースタジアム（カード 57）を出した → カード 57 がカード 56 と入れかわった（`stadium_placed`・`stadium_discarded`）。
  - 直前の受理のあとの観測は、どちらも場のスタジアムがカード 57（PRN-015・持ち主 0・番 35 に置いた）、この番の使用の記録が `[[0, 56]]` でした。
- **候補の一覧:** `end_turn`（c1）・`retreat`（c2）は同じでした。違ったのは c3 の `use_stadium`（カード 57・PRN-015）だけです。

| | TR7 | TR8 |
|---|---|---|
| 処理可能性 | `unresolved_ruling` | `may_stop_later` |
| 理由 | `stops_before_acceptance` | `continuation_not_evaluated` |
| 入力の段 | なし | なし |
| 方策に渡る範囲 | 外（除外） | 内 |

- 試み 147 では、どちらも `retreat` を選び、入力を組み立てられませんでした（`total_units_unreachable`。送信なし）。
  - TR8 の選択の理由は `rule2:priority5:retreat:tie2` でした。同じ優先度の `use_stadium` と並んだうえで `retreat` を選んでいます。
  - TR7 の理由は `rule2:priority5:retreat` で、並ぶ候補はありませんでした。

### 4.2 最初の操作の差（試み 148）

- 同じ position 102 の取り直しです。
  - TR7: `end_turn`（`rule2:priority6:end_turn`）を選び、受理されました。
  - TR8: `use_stadium`（c3。`rule2:priority5:use_stadium`）を選びました。
- 送信の結果は、どちらも `check` valid・`submit` accepted です。並びがそろっている範囲では、送信の結果（`check`・受理・診断）に差はありません。違ったのは、選んで送った操作です。
