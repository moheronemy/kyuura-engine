# v0.73: 拡張パック以外の商品の、検索・回収・ドローのトレーナー 18 枚

拡張パック以外の商品（ポケモンジム・ポケモンカードゲーム拡張シート（ES）・クイックスターターギフト・イントロパック・プロモ・イントロパック★neo）のトレーナー 18 枚
（10 の処理）を、kyuura データの採用で登録して対応にしました。既存の選択・カードの移動・見せる・引く・番を終える処理を使い、要る分だけ共通の処理を広げています。
目的は対応するカードを増やすことで、カードの強さ・勝率・デッキの釣り合いは評価していません。

- 基準: v0.72（`9ac7b57d4496fe24a55ed5af584a2a6163666abc`）。作業ブランチ `claude/v0.73-search-recovery-trainers`（v0.72 から作った）。開始時に作業ツリーに変更はなく、
  `main`（`1b890ee`）は v0.72 の祖先で、取り込むものはありませんでした。
- カードの写しの元・研究の基準は、どちらも kyuura `7d3f4ca76c084774efb4ac6a1d3a943387e183c3` のまま。kyuura は変えていません。固定の参照データは作り直していません。
- ルールの基準は 2000.02.14 版のままです。英語版の文面（「(You can't play … if your Bench is full.)」「in order to」など）・現代のルール・2002 年のサポーターの規定
  （kyuura `MIX-SUPPORTER-ERRATA`）で日本語の不足を補っていません。
- 公式ガイドブック（『オフィシャルブック2000』）のキャプチャ・OCR・読み直しはしていません。pcg-search.com との新しい外部照合もしていません（18 枚とも kyuura の日本語の文面が
  pcg-search.com の転記（`ja_text_source`）で、同じサイトでの照合は独立した照合にならない）。読んでいない原典を確かめたことにする記録は作っていません。
- 書き出しの形式（22）・公開の API の呼び方・状態の項目は変えていません。FH2・PD2（v0.72）・PR1-069 の名前の訂正（v0.70）・既存の簡略化した仕様と停止コードはそのままです。

### 2.1 元気のかたまり

- 使うための条件のカードは、このカードを除く手札のエネルギーカードだけ（手札にある間の印刷の定義。基本・特殊のどちらも 1 枚 1 枚。無色2個エネルギーも 1 枚）。トレーナーカード・
  ポケモンのカードでは払えません（決定 `discard_from_hand` の選べるものはエネルギーカードだけ。足りなければ手札から出す前に `INSUFFICIENT_ENERGY_CARDS_IN_HAND`）。
- 段階 2 は既存の決定 `bench_from_discard`（ちょうど 1 枚。「選び出し、…出す」に選ばなくてよいと書かれていない）と v0.51 の `zones.bench_from_discard`（同じ uid・新しい場のポケモンの
  番号・場に出た番は今の番なのでその番には進化できない）。ダメージカウンターはのせません（元気のかけらの HP の半分を持ち込まない）。ベンチの上限は `stadiums.bench_limit`。
  場に出たときの特殊能力の確かめ（`discard_entry_power_guard`）・まきちらせ!ベトベトガスの GG1 の確かめ（`zones.enter_play`）は、トラッシュから出す既存の経路のままです。
- ES2-034 だけが印刷の文面に「(あなたのベンチに空きがない時、このカードは使えない)」を持つので、ベンチに空きがなければ手札から出す前に `BENCH_FULL`（エネルギーカードを
  トラッシュする前）。GD5-019 にこの条件を持ち込みません。
- MR1（新規。`UNRESOLVED_MAX_REVIVE_WITHOUT_TARGET`）: 自分のトラッシュにたねポケモンがない（両方の版）・GD5-019 でベンチに空きがないときに使えるかは、印刷の文面・kyuura の記録で
  決まりません。使うための条件の確認のあと、状態を変える前に止めます。元気のかけらの RV1・ポケモンの笛の FT1・ポケモンジム第1弾の元気のかけらの使うための条件の答えは
  流用していません。トラッシュするのはエネルギーカード（たねポケモンではない）なので、使うための条件で選べるものは変わりません。
- 段階 2 の不正な答えで、段階 1 のトラッシュは取り消しません。

### 2.2 熱血!

- 山札の上から 3 枚を `zones.deck_top_to_discard`（v0.55。ログ `deck_top_to_discard` は公開）でトラッシュし、返された uid のうち「炎」の基本エネルギーカードだけを
  `zones.return_discard_to_hand` で手札に加えます（新しいログ `milled_to_hand`。トラッシュから動いたので公開。0 枚でも書く）。前からトラッシュにあった炎のカードは加えません。
  山札は切りません。
- 「炎」エネルギーカードに、印刷の文面にない「基本」の条件を書き足していません。無色2個エネルギーなど炎を出さない特殊エネルギーは加えません。
- レインボーエネルギー（場の外の特殊エネルギーカード）が「「炎」エネルギーカード」に当たるかは決まりません（FV1。新規。`UNRESOLVED_FERVOR_RAINBOW_ENERGY`。RB1〜RB3 と同じ種類の
  別の場面の問い）。トラッシュするまで山札の上のカードは分からないので、持ち主に見えないカード（山札・サイド）にレインボーエネルギーがあれば、使う前に止めます（止めるかが、
  山札の上の並びという見えない情報で変わらない）。
- 山札が 3 枚より少ないとき（0 枚を含む）は、v0.31 の HC6（「山札の上から決まった枚数をトラッシュする効果で、山札の枚数が足りない場合」。`UNRESOLVED_DISCARD_DECK_SHORT`。kyuura の
  `UQ-STATED-COUNT-SHORT`）と同じ問いなので、同じコードで、山札を変える前に止めます。「引けるだけ」は当てはめません。

### 2.3 マスターボール

- 山札全体はさがしません（v0.53 の `SearchDeckTrainer` ではない）。上の 7 枚だけを見て（ログ `look_at_deck_top` の `cards` は使ったプレイヤーだけ）、そのうちのたねポケモンのカード・
  進化カード（山札にある間の印刷の定義。なにかの化石・ピッピ人形はトレーナーカード）から選びます。8 枚目より下のカードは選べません。
- ポケモンのカードがあれば、ちょうど 1 枚（新しい決定 `take_looked_pokemon`。「あれば、1枚を選び」で、あるのに選ばない答えはない）→ 見せて手札へ（`zones.reveal_deck_to_hand`）。
  選ばなかったカードは見せず、山札に残します（トラッシュしない。v0.55 のカスミのいかり `LookTopTakeRestDiscardTrainer` ではない）。なければ何もせず（ログ `trainer_take_none` の
  理由は使ったプレイヤーだけ）、どちらのときも山札を 1 回切ります。
- ML1（新規。`UNRESOLVED_MASTER_BALL_SHORT_DECK`）: 山札が 7 枚より少ないとき（0 枚を含む）は、使えるか・あるだけ見るかが決まらないので、使う前に止めます。カスミのいかりの MW1 は
  同じ形の別のカードの問いで、流用していません。「カードを引く」ときの「引けるだけ」も当てはめていません。
- 2 つの組（GD6-023・ES2-036・QSG-058 の「7枚を見る」と NIP1-021・NIP2-022 の「カードを7枚見る」）は印刷の文面が違うので、登録の値をまとめていません（処理は同じ型）。

### 2.4 化石の発掘・月の石・ポケモン再転送

- `CardFilter`（v0.53）に、名前の完全一致 `name`（化石の発掘の「「なにかの化石」」）とポケモンの印刷のタイプ `pokemon_type`（月の石の「「無色」ポケモンへの「進化カード」」。
  進化カード自身のタイプ）を加えました。v0.72 までの `energy_type` は基本エネルギーカードの色の条件で、`CardFilter("pokemon", energy_type=…)` は色を黙って無視していた（フシギバナにも
  当たった）ので、意味のない組み合わせ（ポケモンに `energy_type`・エネルギーに `pokemon_type`・トレーナーに `evolution_only`・`name` と `name_prefix` の両方）は作るときに
  `ValueError` にしました（既存の登録にこの組み合わせはない）。`SearchDeckTrainer.check` は文面の「「X」ポケモンへの「進化カード」」の X と `pokemon_type` を照らします。
- 化石の発掘: 選べるものは山札の「なにかの化石」（uid の小さい順）→ トラッシュの「なにかの化石」（トラッシュの並び）で、合わせて 0〜1 枚（新しい決定 `search_deck_or_discard`）。
  ピッピ人形は選べません。山札のカードは見せて手札へ（`reveal_from_deck`）、トラッシュのカードは手札へ（`retrieve_trainer`。トラッシュは公開）。選んでも選ばなくても、選べるカードが
  なくても、いつも自分の山札を 1 回切ります（「その後、あなたの山札をよく切る」）。
- 月の石: v0.53 の `SearchDeckTrainer`（1 枚・選ばなくてよい・見せる・切る）に、無色の進化カードの条件だけを渡します。無色のたねポケモン・ほかの色の進化カードは選べません。
- ポケモン再転送: v0.53 の `TakeFromDiscardTrainer`（行き先 `TO_DECK_TOP`。切らない・コインなし）。`check` が「自分の山札の上に置く」もリサイクルの「山札の1番上に置く」と同じ
  行き先として受け付けます（正規表現 `山札の(1番)?上に置く`。ほかの書き方は受け付けない）。トラッシュに進化カードがないときは、v0.53 の ST1（「説明が山札・トラッシュから
  決まったカードを1枚選ばせる（「てよい」「ことができる」と書かれていない）トレーナーで、選べるカードがないとき」）と同じ問いなので、同じコードで使う前に止めます。

### 2.5 スーパーポケモン回収

- コイン 1 枚（使ったプレイヤー）を、使うための確認のあと・選ぶ前に投げます（決定のあとで投げ直さない）。「うら」なら何もしません。
- 「おもて」なら自分の場のポケモン（バトル場 → ベンチ）から 1 匹を選び、v0.42 の `zones.return_in_play_to_hand`（重なったカード（進化カード・「ばける」でのせた進化カード）・
  エネルギーカード・トレーナーカードのすべてを同じ uid のまま手札へ。ダメージカウンター・特殊状態はなくなる）→ 持続する効果を理由 `return_in_play_to_hand` で消します。
  ポケモン回収の `return_basic_to_hand`（いちばん下だけ手札へ）は使いません。［へんしん］のメタモンは、もどすのはメタモン自身のカードです（写した姿はカードではない）。
  変わり身の術の NT2 の確かめは `return_in_play_to_hand` の中のままです。きぜつではないので、サイドは取られません。
- バトル場のポケモンを手札にもどせるので `empties_active`。使い終えて（このカードをトラッシュして）から、v0.52 の `resolution.after_trainer` が勝ち負けの判定・バトル場に出す決定を
  します。不変条件（`engine._power_aftermath_problems`）がこれを確かめられるよう、`return_in_play_to_hand` に `log_zone` を加え、このカードのときだけログに `zone`
  （`active`・`bench`）を書きます（ほかの呼び出しのログの形は v0.72 と同じ）。
- 控えがいないときにバトル場のポケモンを選ぶと、代わりのポケモンを出せないので、その判定で負けます（p.311 の規定のまま。v0.36 のくもがくれガス・v0.42 のおくびょうと同じ）。
  ポケモン回収の SU2 は、その文面の「ベンチからポケモンをバトル場にだす」をしたがえない問いで、このカードの文面にはないので持ち込んでいません。同じく、トレーナーカードは文面の
  「それについているすべてのカード」なので、ポケモン回収の SU1 は当たりません。
- マチスの秘策で選んだ自分のうらのカードが「たねポケモン」でなくトラッシュしたら、もどすポケモンがいないので効果は終わります（`ends_on_lost_target`）。

### 2.6 マサキの転送装置

- コイン 1 枚。「おもて」なら 4 枚を「カードを引く」（p.312。山札が足りなければ引けるだけ。0 枚でも負けではない。マサキ・オーキドはかせと同じ規定。v0.54 の `_draw_up_to`）。
  引いたカードは引いたプレイヤーだけが見ます。「うら」なら何もしません。

### 2.7 パソコン大暴走！

- 引く処理は v0.54 のエリカ（`EachPlayerMayDraw`）と同じです: 使ったプレイヤー → 相手プレイヤーの順に、それぞれ自分で 0〜min(5, 自分の山札の枚数) 枚を決めて引く（決定
  `select_draw_count`。相手は使ったプレイヤーが引き終わってから決める。山札が 0 枚のプレイヤーには決定を出さない（`trainer_draw_declined` の `empty_deck`）ので、答えのない決定は
  残らない）。引いたカードは引いたプレイヤーだけ、枚数は公開です。
- 両方の処理が終わったら（両方が 0 枚でも）`END_TURN` を返し、エンジンがこのカードをトラッシュしてから、使ったプレイヤーの番を終えます（v0.56 の `may_end_turn`・
  `engine._finish_trainer`・`resolution.end_turn_after_trainer`。ログ `trainer_turn_end`）。ナツメのサイキックコントロールで相手のトラッシュから使ったときも、番を終えるのは実際に
  使ったプレイヤー（v0.63 の `using_player`）で、カードは持ち主のトラッシュにもどります。説明が使ったプレイヤーの番を書くので `refers_to_user_turn`（錯乱ジムで相手が借りると CH1）。
- エリカは番を終えません（`EachPlayerMayDraw` の `_offer` が決定を出したかを返すようにしただけで、エリカの動きは変えていない）。

## 3. 超エネルギー回収（PR1-009）とエラッタ

- 印刷の文面（kyuura の写し）: 「このカードを使うためには、手札からカードを2枚選んで捨てなければならない。その後、自分のトラッシュから最大4枚のエネルギーカードを選び、手札に加える。
  ただし、いま捨てたカードは選べない。」。写しは書き換えていません（登録の `text_ja` は照合だけに使う）。
- 処理に使う文面（登録の `play_text_ja`。出典 `ERR-SUPER-ENERGY-RETRIEVAL`）: kyuura の data/rule_history.json の ERR-SUPER-ENERGY-RETRIEVAL（研究の基準のコミット）の notes が引用する
  最新の説明「手札からカードを2枚選んでトラッシュしなければ、このカードは使えない。あなたのトラッシュから「基本エネルギーカード」を最大4枚選び出し、手札に加える。ただし、このカードを
  使うためにトラッシュしたカードを選ぶことはできない。」（記録の note が『ポケモンカードオフィシャルブック2000』p.292 の引用として書いたもの。エンジンはガイドブックを読み直して
  いない。記録の引用の再利用）。
- エラッタの適用開始日は、記録のとおり「未確認」のままです。会報 Vol.5 の発行日（1998-06-10）は公表の日で、1997 年の付録カードへの適用開始日ではありません（記録の
  `effective_from`）。遅くとも『オフィシャルブック2000』（2000-02-29）の時点では基本エネルギーだけを拾うものとされている、という記録の範囲で、2000.02.14 版の基準の対戦に当てはめて
  います。
- 処理: 使うための条件はこのカードを除く手札のどのカード 2 枚でもよい（足りなければ手札から出す前に `INSUFFICIENT_CARDS_IN_HAND`）→ 決定 `discard_from_hand` → トラッシュの基本
  エネルギーカード（場の外の特殊エネルギーカードは基本エネルギーカードではない。ERR-ENERGY-RETRIEVAL の読み方。トラッシュしたカードを除く）を 1〜min(4, 数) 枚（決定 `retrieve_energy`）。
  エネルギー回収（v0.23 の `DiscardFromHandThenRetrieveEnergy`）と同じ処理で、枚数と決められない場面のコードだけを変えます（決められない場面の (コード, 理由) をクラスの値
  `WITHOUT_TARGET`・`ZERO_CHOICE` にした。エネルギー回収のコードと理由は v0.72 と同じ）。
- SR1・SR2（新規）: トラッシュに選べる基本エネルギーカードがない（`UNRESOLVED_SUPER_ENERGY_RETRIEVAL_WITHOUT_TARGET`。使う前）・選べるのに 0 枚を選ぶ
