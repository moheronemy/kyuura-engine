# v0.111: 場のエネルギーカードの枚数とワザの使用条件の 4 枚

v0.111 は、ミュウツー（ES1-022・QSG-032）・ナツメのケーシィ（GD6-001・PR1-060）の 4 枚（同じデータの 2 組）を、ワザ 8 とともに登録する版です。ちょうねんりき・はたくは説明文がなく既存の
`DAMAGE_ONLY`、サイコクラッシュとシンクロウェーブはそれぞれ新しい小さな型です。

- サイコクラッシュ（`DamageTimesOpponentFieldEnergyCards(超, 10)`）: ワザを実際に使ったプレイヤーの相手の場（バトル場と控え）のポケモンについている「超」エネルギーカードの枚数 × 10 を、
  p.321 の 1 段階の基本となるダメージにします（要素 `Damage(OPP, OpponentFieldEnergyCardsTimes(超, 10))`。数え方 `effects.field_energy_cards_of_type`）。カードとしての色が決まらないカードは、
  既存の問い（TE1・RB1・BZ2・MEC1・CE3）でポケモンごとに止めます（`effects.field_energy_card_ambiguities`・`programs.transform_energy_question`）。
- シンクロウェーブ（`DamageRequiringEqualEnergyCards`）: 「自分と相手に同じ数のエネルギーカードがついている時だけ、このワザは使える。」を、ワザを使うための条件（宣言の確かめ。
  `AttackEffect.usage_problem`・拒否のコード `ENERGY_CARD_COUNTS_DIFFER`）として扱います。比べるのは実際にワザを使うポケモンと相手の対戦ポケモンについているエネルギーカードの枚数
  （`effects.energy_card_counts`。既存の `attached_energy_cards` の数え方）。相手のワザとして使うときは要素 `EqualEnergyCardsRequired` の `copy_problem` が同じ比べ方をします。

写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）、ルールの基準は公式ルール 2000.02.14 版、書き出しの形式は 26 のままです（新しい状態の項目はない）。

## 3. サイコクラッシュ（相手の場の「超」エネルギーカードの枚数）

### 3.1 型と要素

- 型 `DamageTimesOpponentFieldEnergyCards(energy_type, per)`: 確かめ（`check`）は、ダメージの目安が「×」つきで目安の数字が `per` と同じこと、全文が
  `OPPONENT_FIELD_ENERGY_CARDS_TEXT`（「相手の場のポケモンについている「{色}」エネルギーカードの数×{per}のダメージ。」）と同じことです。色・数の違う文面、v0.50 のミュウのサイコウェーブ
  （「相手についているエネルギーカード×10のダメージ。」）は受け付けません。「無色」・10 の倍数でない数は作れません。
- 要素は `Damage(OPP, OpponentFieldEnergyCardsTimes(超, 10))` の 1 つです。値は p.321 の 1 段階の基本となるダメージそのもの（目安の数字 10 を加えない。最終ダメージを固定しない）で、弱点・
  抵抗力・ほかの変更はそのあと（2 段階〜）に既存の計算で当てはまります。0 枚なら基本となるダメージ 0 で、2 段階までで 0 以下なのでダメージを与えません（GR-2000-P321-ATTACK-DAMAGE）。
- v0.50 の `DamageTimesDefenderEnergyCards`（相手の対戦ポケモン 1 匹・色を問わない）とは範囲と色が違う別の型で、そちらの意味・既定は変えていません。

### 3.2 数える範囲

- 数えるのは、ワザを実際に使ったプレイヤー（`AttackRun.player`）の相手の場のポケモン（バトル場と控え）についている、その色の基本エネルギーカードの枚数です（`field_energy_cards_of_type`。
  `attached_basic_energy` の和）。数える時点はダメージの要素を処理する時点。
- 自分の場・手札・山札・トラッシュのカードは数えません。つけているポケモンのタイプでしぼりません。カードの枚数で、出すエネルギーの個数ではありません（無色2個エネルギーは「超」エネルギー
  カードではなく、2 個でも数えない）。
- 数えることは控えへのワザの効果ではないので、控えの「とうめい」（ゴーストの［とうめい］）・「ワザをうけない」状態・控えへのダメージを防ぐ効果を評価しません（数から除かない。コインも投げない。
  `test_bench_protection_does_not_remove_cards_from_the_count`）。ダメージを受けるのは相手の対戦ポケモンだけです。
- うらのカード（マチスの秘策）は、エネルギーカードがつかない（つけるとおもてになる）ので、数えるために名前・定義を読みません（FD1 で止めない。本当のカードによらず同じ結果。
  `test_face_down_cards_do_not_stop_or_leak`）。

### 3.3 色の決まらないカード

- 説明の「「超」エネルギーカード」に当たるかが決まらないカード（`field_energy_card_ambiguities`）があれば、そのポケモンごとに既存の問いで止めます（`transform_energy_question(..., cards=True,
  wild=False)`。状態・乱数・ログを変えない）: ［へんしん］の読み方（TE1）・レインボーエネルギー（RB1）・［エネエネ］で「超」になったカード（BZ2）・ミラクルエネルギー（MEC1）・エナジー
  コンバーター・こうごうせいで色の変わったカード（CE3）。問いは範囲（相手の場）ごとに既存のものを当てはめ、新しい停止コードは加えていません。［エネエネ］でほかの色になったカードは当たらない
  ので問いません。
- ［おいしげる］の「草」2 個ぶんの問い（`wild_growth_question`）は、「超」エネルギーカードの枚数に関係しないので聞きません（`wild=False`。`test_unrelated_wild_growth_is_not_asked`）。
- エナジートランスの HC10（`UNRESOLVED_ENERGY_BURN_TRANSFER`。エナジーバーンで「炎」になった「草」エネルギーカード）の名前は使っていません。同じ形の問い（カードの種類と今のエネルギーの色で
  答えが違う）は `field_energy_card_ambiguities` が候補にしますが、エナジーバーンは使った番の自分のポケモンにだけ起こるので、相手の場には起こりません（起これば処理はエンジンの不具合として
  止まる）。HC10 と同じ問いとして扱うかは、到達する場面がないので決めていません。
- 受ける相手の対戦ポケモンにとってこのダメージの要素が無効（`kernel.first_void`。かたまるの「ダメージを受けない」・バリアー・［ニュートラルシールド］など）なら、量は使われない（計算しない）ので、
  色の問いで止めずに無効にします（`test_void_damage_does_not_ask`）。
- `damage_profile`（v0.13 の止める関数・契約の確かめで使う基本となるダメージの候補）は同じ数え方で、色の決まらないカードは数える・数えないの両方を候補にします。

## 4. シンクロウェーブ（ワザを使うための条件）

### 4.1 宣言の確かめ

- 条件はワザの実装の `usage_problem` です。`checks.attack_request` の順番（番 → ワザの選択肢 → ねむり・マヒ → ワザの使用の制限 → 登録 → 1 度だけ → 必要なエネルギー → `usage_problem` → …）の
  とおり、必要なエネルギーの確認のあと・こんらんのコインの前に確かめます。枚数が違えば `ENERGY_CARD_COUNTS_DIFFER`（通常の不正な操作。研究上の未解決ではない）で拒否し、状態・乱数・ログ・
  番を変えません（`test_unequal_counts_are_rejected_before_anything`。こんらんしていてもコインを投げない）。
- どちらも 0 枚でも、必要なエネルギー（超無）の確かめが先です（`INSUFFICIENT_ENERGY`）。

### 4.2 数え方

- 比べるのは、実際にワザを使うポケモンと、その持ち主の相手の対戦ポケモンについているエネルギーカードの枚数です（`energy_card_counts`。v0.50 の `attached_energy_cards`）。色・出す個数・
  タイプは見ません。無色2個エネルギーは 1 枚、［エネエネ］で場でエネルギーカードとしてあつかうカードも 1 枚（`test_units_and_buzzap_cards_count_as_cards`）。控えのポケモンの枚数は比べません。
  相手の対戦ポケモンがいなければ 0 枚です。
- 「自分と相手」を相手の対戦ポケモンと読むのは、ワザの説明の「相手」をワザを受ける相手の対戦ポケモンとする既存の読み方の当てはめです（英語の欄で補っていない）。

### 4.3 宣言のあと

- 宣言のあとは比べ直しません（要素 `EqualEnergyCardsRequired` の `run` は何もしない）。相手が変わり身の術で宣言のあとに控え（枚数の違うポケモン）と入れ替えても、ワザは宣言のときの条件で
  使われ、ダメージは入れ替えたあとのポケモンが受けます（変わり身の術の「そのワザのダメージや効果は、入れ替えの後でおこる」。宣言はやり直さない。実装上の読み方。
  `test_ninja_trick_switch_after_declaration_is_not_rechecked`）。

### 4.4 v0.83 のやさしいモルフォンとの違い

- v0.83 のやさしいモルフォン（neo4-006）のシンクロウェーブ（`FailUnlessEqualEnergyCardsDamage`。「自分と相手に、同じ枚数の「エネルギーカード」がついていないとき、このワザは失敗する。」）は、
  使ってから失敗する別の文面で、変えていません（`test_old_gentle_venomoth_still_fails_after_use`。宣言を受け付け、失敗し、番は進む）。2 つの型の確かめは互いの文面を受け付けません。

## 11. 残る制限・行っていない検証

- 4 枚とも外部照合・カードの画像との照合はしていません（kyuura データの採用）。公式ガイドブックの新しい読み直しもしていません。
- 相手の場の［エネエネ］で「超」になったカード（BZ2）・ミラクルエネルギー（MEC1）・色の変わったカード（CE3）・［へんしん］（TE1）でサイコクラッシュが止まる場面は単体のテストだけで確かめ、
  正式な対戦では RB1 だけが起こりました（9.3 節）。変わり身の術の入れ替えのあとのシンクロウェーブも単体のテストだけです。
- 全変異試験・性能の測定・複数の Python での追加の実行はしていません。
