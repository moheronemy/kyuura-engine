## 0. 先に結論

- **保存記録:** TR3 の本実行で報告した 8 局・13 局面をすべて照合できました（欠け・矛盾 0）。13 局面とも、直前の受理された操作が自分の手札からのきずぐすりの使用で、その決定と入力の応答が対応し、未裁定の選択肢 37 個はすべて、選ぶときの本人の観測で**ダメージ 0 の自分の場のポケモン**でした。どの局面にもダメージのある対象が 1 匹以上残り、方策はそれを選び、13 回とも受理されて続きました。
- **改善の範囲:** 今の方策は未裁定の選択肢をすでに選ぶ範囲から外しています（13 局面とも、方策が選んだ範囲の数 = ダメージのある対象の数）。このため、**規約で使える対象が増えるとは評価しません。** 保存記録の上で減らせるのは**未裁定の選択肢の表示（13 局面・37 個）だけ**で、入力を作れない・拒否・対戦の終了は、この場面では 0 件でした。
- **推奨案:** 明示して選んだプレイ用の集合でだけ、ダメージ 0 の対象を「規約による使用不可」（`eligible` 偽・`convention` に規約 ID）として示し、送れば規約による不正な操作として拒否して、同じ決定に答え直せるようにします。新しい続行規約 `PC-POTION-UNDAMAGED-TARGET@1`（案）を、新しい開発用の集合 `CS-KYUURA-PLAY-TR4@1`（案）に入れます。厳密側と既存の `CS-KYUURA-PLAY-TR3@1` は版も内容も変えません。

## 2. 今の扱い（ソースから。3853c5c）

### 2.1 2 つの場面の境界

| 場面 | 時点 | 停止コード | 今の扱い | TR3 |
|---|---|---|---|---|
| ダメージのあるポケモンがいない | 使う宣言の前（`check_playable`） | `UNRESOLVED_POTION_WITHOUT_DAMAGE` | 厳密側は未裁定の停止 | `PC-POTION-WITHOUT-DAMAGE@1`: 規約による不正な操作（`NO_DAMAGE_COUNTERS`。カードは手札のまま） |
| ダメージのないポケモンを対象に選ぶ | 使用を受理したあとの対象の決定（`resolve` の決定の答え） | `UNRESOLVED_POTION_UNDAMAGED_TARGET` | 選べるものに入れるが、選ぶと未裁定の停止 | 対象外（規約の内容の `unchanged` に「受理のあとの未裁定。停止のまま」と書いてある） |

- 2 つは時点が違い、片方がもう片方に含まれません。どちらの集合でも、対象の決定に来るのは、使う宣言の時点でダメージのあるポケモンが 1 匹以上いるときだけです（厳密側はいなければ使う前に止まり、TR3 は使う前に拒否する）。

### 2.2 決定の作り方と答えの確かめ

- `RemoveDamageCounters.resolve`（`kyuura_engine/effects.py`）: `push_trainer_decision` に、選べるもの＝使う人の場のすべてのポケモン、`unresolved_choices`＝その中のダメージ 0 のポケモン、`unresolved_code`＝`UNRESOLVED_POTION_UNDAMAGED_TARGET` を渡します。このコードを使うのはこの 1 か所だけです。
- `push_trainer_decision`（`kyuura_engine/decisions.py`）: ［でんせつのからだ］で効果を受けないポケモンを、選ぶと止める選択として加え、選択ごとの理由（`unresolved_detail`。LB1）を書きます。**同じ決定に LB1 の停止が混ざることがあります。**
- `check_choices`（同）: 選んだものが `unresolved_detail` にあればその理由、`unresolved_choices` にあれば `unresolved_code` で `UnsupportedError`。状態を変える前なので、決定は待ったままです（答え直せる）。
- 状態の確かめ（`engine.py` の決定の不変条件）: 選ぶと止める選択を除いて、答えに要る数の選択が残ること。
- 入力の候補（`legal_actions.py` の決定の入力）: 未裁定の選択肢の `processability` を停止コードから決めます（`unresolved_ruling`）。`check` は実行できない選択肢を `CANDIDATE_NOT_EXECUTABLE` で断ります。

### 2.3 規約を当てる今の仕組み（前例）

- `continuation_for(state, code)`: 状態の規約集合に、その場面（停止コード）の続行規約があれば照会の結果、なければ None（呼ぶ側は今までどおり止める。`stop_without_continuation` で規約がないことを確かめる）。カード ID・規約の名前で分岐しません。
- 規約による除外の示し方（前例）: 準備の化石・人形（v0.143）と TR3 の手札のトレーナー（v0.186）は、選択肢に `eligible` 偽・`convention`（`"ID@版"`）を書き、`processability` は書きません。候補全体の区分には数えません。送れば `IllegalActionError`（属性 `convention`）で拒否し、状態・乱数・ログは変えず、規約を当てた記録（`convention_applied`）も残しません。
- 場面の索引: `UNRESOLVED_POTION_UNDAMAGED_TARGET` は、停止の方針の台帳の場面（事例なし）として登録されています。

### 2.4 経路（同じ決定に来るか）

| 経路 | ソースの道すじ | 同じ決定か |
|---|---|---|
| 手札から使う | `_continue_trainer_use` → `_start_trainer_use` → `_resolve_trainer` → `resolve` | 同じ（保存記録の 13 局面） |
| 錯乱ジムで相手がかわりに使う | `_resume_trainer`（`chaos`）→ `require_borrow_playable` → `_resolve_trainer(TrainerUse(借りる人, …))` → `resolve` | 同じ。使う人＝借りる人で、その人の場から選ぶ |
| サイキックコントロールで相手のトラッシュから使う | `_start_nested_trainer` → `_start_trainer_use` → `_resolve_trainer` → `resolve` | 同じ。使う人＝外側の使う人 |
| リムーブ禁止ジムの追加の条件のあと | `_resume_trainer`（`stadium_cost`）→ `_resolve_trainer` → `resolve` | 同じ（使い方の経路ではなく、手札から使うときの途中の段） |

- この型を登録しているカードはきずぐすりだけです。指定は TR3 と同じく効果の登録の型で行い、カード ID では分けません。
- 錯乱ジム・サイキックコントロールの経路は保存記録に出ていないので、実装の単位の構築盤面で確かめます（7 章）。

## 4. 推奨案 B の設計

### 4.1 規約と組み込み先

- **規約（案）:** `PC-POTION-UNDAMAGED-TARGET@1`（層 `continuation`）。場面 `UNRESOLVED_POTION_UNDAMAGED_TARGET`。
  - 文: きずぐすり（登録の型 `RemoveDamageCounters`）を使ったあとの対象の決定で、ダメージカウンターののっていない自分のポケモンは選べない（規約による不正な操作として拒否する。決定は待ったまま・状態・乱数・ログを変えない）。
  - 内容: `applies_when`（決定を出す時点で、選べるもののうちダメージ 0 のポケモン。LB1 の選択は除く）、`identification`（効果の登録の型。再録の版をふくむ）、`paths`（2.4 節）、`rejection_code`（案 `TARGET_WITHOUT_DAMAGE`）、`unchanged`（4.4 節）。
- **組み込み先（案）:** 新しい開発用の集合 `CS-KYUURA-PLAY-TR4@1` = `CS-KYUURA-PLAY-TR3@1` の 23 規約 + この 1 件（24 規約・`halts_at_undecided`）。
- **変えないもの:** `CS-KYUURA-CURRENT`・`CS-KYUURA-PLAY-TR3@1`（版・内容・照合値 `sha256:a7b800cf…`）。TR3@1 の `PC-POTION-WITHOUT-DAMAGE@1` の内容（`unchanged` の文）もそのままです。既定の集合は変えません。
- **依存:** `requires` は置きません（2.1 節のとおり、どちらの集合でも対象の決定に来るのはダメージのあるポケモンがいるときだけで、使う前の扱いに依存しない）。

### 4.2 段階ごとの扱い（B の集合のとき）

| 段階 | 扱い |
|---|---|
| 決定を出す（`resolve`） | 状態の規約集合に、この場面の続行規約があるか（`continuation_for`）を決定を出すときに照会する。あれば、ダメージ 0 のポケモン（LB1 の選択を除く）を、選ぶと止める選択ではなく「規約で選べない選択」として決定の続きの情報に書く（案: `convention_excluded` と規約 `ID@版`）。なければ今と同じ（`unresolved_choices`） |
| 候補 | 候補全体の区分は今と同じ（`answer_decision`・`may_stop_later`・`continuation_not_evaluated`） |
| 入力 | 規約で選べない選択肢は `eligible` 偽・`convention` `PC-POTION-UNDAMAGED-TARGET@1`、`processability` を書かない。実行できない選択肢として数える。ほかの選択肢は今と同じ |
| `check` | 規約で選べない選択肢を選んだ入力は `CANDIDATE_NOT_EXECUTABLE`（今と同じコード。理由の文は前例に合わせる） |
| 送信（`check_choices`） | 規約で選べない選択を選んだら `IllegalActionError`（案 `TARGET_WITHOUT_DAMAGE`・属性 `convention`）。状態を変える前なので、決定は待ったまま。規約を当てた記録は残さない |
| 状態の確かめ | 規約で選べない選択 ⊆ 選べるもの、選ぶと止める選択と重ならない、決定を出した時点のダメージ 0 の自分のポケモン（LB1 を除く）と同じ。答えに要る数の選択が残る |

- **適用を識別できる根拠:** 決定の続きの情報の規約 ID（`ID@版`）と、入力の選択肢の `convention`、拒否の属性 `convention`。どれも状態の規約集合から決まり、カード ID・モードの名前で分けません。
- **答え直せる条件:** 拒否は `check_choices` で状態を変える前に起きるので、同じ決定（同じ id・同じ選べるもの）が待ったまま残ります。ダメージのある対象を送れば受理されます。
- **ダメージの値の時点:** 決定を出すときの値で決めます。決定を待つあいだに場のダメージは変わらない（ほかの操作を受け付けない）ので、答えるときと同じです。

### 4.3 有効な対象が 0 件になりうる場合

- 規約で外したあとに残る選択（ダメージがあり LB1 でない）が 0 件になりうるのは、ダメージのあるポケモンがすべて［でんせつのからだ］で効果を受けない場合だけです（使う前の確かめで、ダメージのあるポケモンが 1 匹以上いることは決まっている）。
- この場合は**規約を当てず、今と同じ決定（ダメージ 0 も LB1 も選ぶと止める）**にします。答えられない決定を規約で作らないためです。今の扱いでこの決定がどう処理されるか（不変条件との関係）は今回は確かめていないので、実装の単位で確かめます（8 章）。

### 4.4 当てないもの（`unchanged`）

- 使う宣言の前の場面（`UNRESOLVED_POTION_WITHOUT_DAMAGE`。TR3 の `PC-POTION-WITHOUT-DAMAGE@1` のまま）
- ［でんせつのからだ］の LB1 の選択（今の停止のまま。ダメージ 0 でも LB1 が先）
- いいきずぐすり（SP1）・モーモーミルク（MK1）・サカキの切り札（GL2）など、同じ形の問いのほかのカード
- ダメージのある対象を選んだときの処理（とりのぞく数・記録）
- 厳密側・既存の集合（CURRENT・S2a・PO・TR3@1）の停止
- FD1・ER9・ER10
