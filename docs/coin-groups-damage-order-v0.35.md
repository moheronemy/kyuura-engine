# v0.35: 可変枚数のコインの先読み・ダメージの計算の順番の決定と、5 枚

v0.34（`2d0f60f`。版 0.34.0）から作業ブランチ `claude/v0.35-coin-groups-damage-order` を作り、次の 3 つをまとめて行いました（版 0.35.0）。

1. 結果を「おもて」の数だけで使うコインを、宣言の前の先読みが「おもて」の数でまとめて試すようにした（2 章）。ナッシーの「たまなげMAX」の
   エネルギー 13 枚からの `UNSUPPORTED_PREFLIGHT_LIMIT` を、上限の数（4,096）を変えずに解消した。
2. p.321 の同じ段階に順番によって結果が変わる変更効果が重なったとき、`DAMAGE_STEP_CHOOSER` のプレイヤーに順番を選ばせる決定（`damage_step_order`）を
   加えた（3 章）。v0.34 の `UNSUPPORTED_DAMAGE_STEP_ORDER`（「つるぎのまい」と「なきつく」）を、決定を出せる場面で解消した。
3. 依頼の 5 枚（マチスのコラッタ PMCG5-056・マチスのラッタ PMCG5-059・カスミのニョロモ PMCG5-022・カスミのニョロゾ PMCG5-029・カツラのケンタロス
   PMCG6-065）を、kyuura データの採用で加えた（4 章）。対応ポケモン 148 → 153、ワザの登録 257 → 267（特殊能力 12 のまま）、写し 170 → 175 枚。

開始の時点で、作業ツリーに未コミットの変更はなく、v0.34 のあとの保守の変更もありませんでした（`main` は `2d0f60f` の祖先）。ガイドブック
（『オフィシャルブック2000』）のキャプチャ・OCR・画像の読み直しは行っていません。足りない裁定を現代のルールから推測して決めていません。CD4 は
再調査していません（v0.33 の結論のまま）。研究の基準（kyuura `3f34908`）・写しの元（`ecb2d69`）・固定した参照データ・公開の固定のデッキは変えていません。

## 2. 可変枚数のコインの先読み

### 2.1 まとめる条件

宣言の前の先読み（`resolution/preflight.py`）は、コインと決定のすべての結果を状態の複製の上で試します。v0.34 までは、コイン 1 枚を 1 つの分かれ目と
して数えたので、n 枚のコインは 2 の n 乗通りでした。v0.35 から、次の条件をすべて満たすコインは、「おもて」の数（0〜n）を 1 つの分かれ目として
n + 1 通りを試します。

1. **結果の使い道が「おもて」の数だけ**（投げた順番・何枚目が「おもて」かを使わない）。どのコインがそうかは、コインを投げる要素・値が宣言します
   （`coins.flip_coins` の `by_heads`、`AttackRun.flip(count, by_heads=…)`）。カード id では分けません。
   - 基本となるダメージの値の `by_heads`（ClassVar）: `HeadsTimesAttachedEnergy`（たまなげMAX）・`PlusHeadsPerAttachedType`（ウォーターパンチ）・
     `HeadsOfDiscarded`（ほうでん）。
   - ワザ全体のコイン（`Coin`）は、2 枚以上か、枚数がエネルギーで決まるもの（`per_attached`）。あとの要素は「おもて」の数（`coin_is` の数・`heads`・
     `tails`・`heads_of`）だけを使います。あとの要素が 1 枚目の面（`CoinSide` の `gate`）を使う並びは、まとめられないので先読みの前に
     `RuntimeError` で止めます（並びで処理が変わるコインを「おもて」の数でまとめない。製品の登録にはない。テスト `test_order_dependent_coins_are_not_grouped`）。
   - 失敗するコイン（`FailOnTails`）は、すべて「おもて」かだけを使います。
2. **同じ「おもて」の数なら、そのあとの処理（相手へのダメージ・自分へのダメージ・トラッシュする枚数・当たる問い）が同じ**。1 の条件から成り立ちます。
3. **コインのあとの決定は、まとめずにすべての答えを試す**。トラッシュするカード・選ぶポケモンの違いを同じものとみなしません（れんぞくファイヤーボールの
   「おもて」の数のぶんのトラッシュするカードの選び方は、今までどおりすべて試す）。
4. **相手へのダメージと自分へのダメージを同じコインで決めるワザは、組のまま試す**（ぜんりょくとっしんは、4 枚の「おもて」の数 k で、相手へ 20k・
   自分へ 20(4 − k)。別々に数えた結果を組み合わせない。テスト `test_full_speed_charge_keeps_opponent_and_self_damage_as_pairs`）。

### 2.2 仕組み

- 先読みの乱数（`Oracle`）の `coin_group(count)`: 台本の 1 つの値（0〜count）を「おもて」の数とし、決まった並び（「うら」の数だけ 0、そのあと
  「おもて」の数だけ 1）を返す。この並びは、同じ「おもて」の数の並びのうち、1 枚ずつ試すときに最初に試す並びです。1 枚ずつ試す先読みで最初に当たる
  結果は、問いに当たる「おもて」の数のうち最小のもので、その並びがちょうどこれなので、当たる問いと理由の文が 1 枚ずつ試すときと同じになります。
- 実際の対戦の乱数（`random.Random`）は `coin_group` を持たないので、`by_heads` でも今までどおり 1 枚ずつ `getrandbits(1)` で投げます（結果・
  ログ `coin_flip`・乱数の使い方・確率は変わらない）。
- `derived` の実際の処理の前に置く記録（`RecordingRandom`）は、`coin_group` で元の乱数から 1 枚ずつ投げ（乱数の使い方は同じ）、(「おもて」の数,
  枚数 + 1) を 1 つの値として記録します。試していない結果の台本（`sibling_roots`）は、値ごとの選べる数（`arity`）で作ります。
- 先読みの方法ごとの約束は変えていません: `derived`（実際の処理 → 試していない結果）・`derived_full`（すべて試す）・`legacy`（`v013_checks.VERIFIED`
  の型は v0.13 の止める関数。v0.35 の型は `VERIFIED` に入れていないので、すべて試す）。止める・拒否する判断（問い・コード・理由の文）は同じです。
  上限の数 `MAX_BRANCHES`（4,096）と、上限を超えたときの扱い（途中までの結果を使わない）も変えていません。

製品のワザのうち、2 枚以上のコイン・枚数が状態で決まるコインを投げるもの（登録の要素の並びから求めた。カード id の表ではない）:

基準にしていることの 2 つです。1 枚のコインのワザは、まとめるものがありません。

### 2.4 まとめられないもの（残る制限）

- **れんぞくファイヤーボール**: コイン（炎エネルギーの数）はまとめましたが、そのあと「おもて」の数 k のぶんトラッシュする炎エネルギーカードを選ぶ
  決定は、カードの選び方の違いを同じものとみなせない（どのカードが残るかで、そのあとの状態が変わる）ので、すべての答えを試します。k ごとに C(n, k)
  通りで、合わせて 2 の n 乗通りのままです（炎 12 枚の 4,096 通りまで受け付け、13 枚から `UNSUPPORTED_PREFLIGHT_LIMIT`）。テスト
  `test_card_selection_after_coins_is_still_enumerated`。今のカードの炎エネルギーカードはどれも同じ種類の基本エネルギーなので、選び方の違いで結果が
  変わらない可能性はありますが、カードの番号・トラッシュの並びは違うので、同じものとみなしていません（推測で上限を回避しない）。

## 3. ダメージの計算の順番の決定

### 3.1 仕様

- p.321 の 2・5〜8 段階の変更効果の計算は、`damage.DamageModifier` の `operation` で区別します: `ADD`（加える。プラスパワー・ディフェンダー・なきつく）・
  `SET`（その数にする。つるぎのまい）・`MULTIPLY`（数をかける。v0.35 のきあいだめ。2 以上の整数）。
- 同じ段階に加算でない効果を含む 2 つ以上の効果があり、計算の順番によって結果（最終ダメージと、2 段階で 0 以下になって計算を終えるか）が変わるときだけ、
  順番を選ばせます。効果が 1 つ・加算だけ・どの順番でも結果が同じなら決めさせません（不要な決定を出さない）。コードで順番を決めて計算しません。
- 選ぶプレイヤーは段階で決まります（`DAMAGE_STEP_CHOOSER`。2・5・6 段階はワザを使うプレイヤー、7・8 段階はワザを受けるポケモンの持ち主。p.321。
  docs/scyther-v0.27.md の SC15）。今のカードで起こるのは 2 段階だけです。
- 選べるものは、その段階の変更効果の集めた順番の番号の並べかえ（`damage.step_orders(n)`。`itertools.permutations` の辞書順）の位置です。決定の選べる
  もの i が `permutations[i]` の順番に対応します（2 つなら 0: 集めた順、1: 逆）。集めた順番は `effects.attack_damage_modifiers` の順（ワザを使うポケモンの
  持続する効果 → ついているトレーナー → 受けた効果（なきつく））。

### 3.2 決定の形と続き

決定は既存の仕組みのワザの途中の決定（`resume` は `"attack"`、段階は `Phase.DECISION`）で、種類は `decisions.DAMAGE_STEP_ORDER`
（`"damage_step_order"`）、1 つを選びます。`context` には、決定を出した要素の位置（`element`）・基本となるダメージ（`base`。要素のコインを投げ直さない）・
前に選んだ段階の順番（`orders`）・段階（`step`）・受けるポケモン（`target`・`receiver`）・弱点と抵抗力を計算するか・その段階の変更効果（`modifiers`:
(名前, 発生源, 計算, 数)）・選べる順番（`permutations`）と、ワザ全体のコインと枠の値（`AttackRun.suspend(carry=True)`。v0.18d の案 B の持ち方）を書きます。
`PendingDecision` に項目を加えていません。

- ダメージはまだ与えていません。受けるときの効果・「とうめい」・はんげきの記録は、順番を決めたあとの計算で評価します。
- 再開（`flow._resume_attack`）は、続きの情報の `element` の要素（ダメージの要素。並びにダメージの要素が 2 つ以上あっても区別する）の `resume` を呼び、
  選んだ順番を `orders` に渡してもう一度計算して与えます。宣言・エネルギーの確認・コイン・それまでの要素を繰り返しません。
- 不正な答え（相手のプレイヤー・範囲外の番号・2 つ・0 個・古い決定 id・ほかのコマンド）は拒否し、決定は待ったまま（状態・乱数・ログが変わらない）。
- 不変条件（`engine._damage_order_decision_problems`）が、決定の形を場から確かめます（選ぶプレイヤー・選べるもの・選べる順番・受けるポケモン・
  その段階の変更効果を今の場から集め直し、順番によって結果が変わることも計算し直す）。
- ログ `damage` には、順番を選んだときだけ `step_orders`（(段階, その段階の効果の名前を計算した順に)）が入ります。数をかけた効果は `damage_multiplied`
  （(段階, 発生源, かける数)）。その数にする効果の `damage_set`・加える数の `modifiers` は v0.27 と同じです。`modifiers` の並びは v0.34 と同じ集めた
  順番で、順番を選んだ段階のものだけ、その段階の位置の中で選んだ順番に並べかえます。

### 3.3 例

| 場面 | 選ぶプレイヤー | 選択 → 結果 |
|---|---|---|
| マチスのコラッタ（きあいだめ）のでんこうせっか「おもて」30、カラカラのなきつく（−20） | コラッタの持ち主 | 0: ×2 → −20 = 40、1: −20 → ×2 = 20 |
| 同「うら」10 | — | 決定なし（どちらも 2 段階で 0 以下。ダメージを与えない） |
| マチスのラッタ（きあいだめ）のすてみタックル 40、なきつく | ラッタの持ち主 | 相手へ 0: 60、1: 40。自分への 20 は「きあいだめ」だけなので決定なしで 40 |
| ストライク（つるぎのまい）のきりさく 30、なきつく | ストライクの持ち主 | 0: 60 → 40 → 弱点で 80、1: 10 → 60 → 弱点で 120（v0.34 は拒否） |

### 3.4 先読みと保存

先読みは、この決定も他の決定と同じく、すべての答えを試します（`derived` は決定を出したので `full`）。3 つの先読みの方法で、決定・答えごとの結果が
同じです。決定を待つ状態を複製・deepcopy・pickle で保存して再開しても、結果（形式 10 の全体・乱数・ログ）は同じです。書き出しの監査も通ります
（決定は既存の `decision` の項目。形式 10 のまま）。

### 3.5 確かめたこと

テスト `tests/test_coin_groups_damage_order_v0_35.py` の `DamageCalculationOrderTest`（計算の単体）・`StepOrderDecisionTest`（決定）。自然な対戦（6 章）
でも、マチスのラッタのきあいだめとカラカラのなきつくの順番の決定が 1 回起こり、ログの監査（2 段階の記録と順番の記録）が通りました。

### 3.6 決定を出せない呼ぶ側

順番の決定を出すのは、解決の基盤のダメージの要素（`programs.Damage`）だけです。次の呼ぶ側は決定を出せないので、順番によって結果が変わるときは、
順番を決めずに問い `damage_step_order`（`UNSUPPORTED_DAMAGE_STEP_ORDER`。エンジンの未対応。研究の対応表の停止コードに入れない）で止めます。
今の対応カードでは、どれも起こりません。

- 控えへのダメージ（`BenchDamage`・`ChosenBenchDamage`）・返す効果のダメージ（ほのおのかべ・こうらがえし）・v0.13 の約束で書いたワザ（アダプタ）
- ダメージの要素より前の要素がすでにダメージを与えている（`applied`・`evaded`）か、前の要素の結果を決定のあとの要素が使う並び（決定をまたいで運べる
  のはワザ全体のコインと枠の値だけ）

マチスのラッタ・カスミのニョロゾは、進化元の名前（完全一致）のカードから通常の進化の操作で進化します（第1弾のコラッタ・ニョロモからは進化できない）。

### 4.1 きあいだめ

- 持続する効果は v0.27 の `state.NextTurnAttackDamage` に、変え方 `operation`（`"set"`・`"multiply"`）と `includes_self_damage` を明示した値です（v0.13 の
  `Retaliation.basis` と同じく、決め方を 1 つの型に明示する。別の型・ワザごとの処理にしない）。種類は `next_turn_attack_damage_multiplier`（つるぎのまいの
  `next_turn_attack_damage` は変えていない）。「つるぎのまい」の「その数にする」の値を 2 倍の意味に流用していません（`SET` と `MULTIPLY` は別の計算）。
- 対象のワザは、同じカードのワザの位置と名前で照らします（`card_problems`。名前では探さない）。2 倍は p.321 の 2 段階（ワザを使うポケモンの持っている
  「ダメージを変更する効果」）。弱点・抵抗力・プラスパワーなどはそのあとの段階です。
- 期間: 使った番に効果を与え、はたらくのは次の自分の番（与えた番 + 2）だけ。相手の番にははたらかず、次の自分の番の終わりに消えます（`expired`）。
  次の自分の番にもう一度使うと、前の効果はその番の終わりに消え、新しい効果がその次の自分の番にはたらきます（重ねて 4 倍にしない。v0.27 の SC7 と同じ）。
  ワザを使うと番が終わるので、効果を準備した番に 2 倍のワザは使えません。
- ベンチにもどる（にげる・ポケモンいれかえ・突風）・進化・きぜつで消えます（v0.4b と同じ消える契機）。進化したマチスのラッタのすてみタックルは、
  マチスのコラッタのきあいだめでは 2 倍になりません。
- マチスのラッタの「(自分へのダメージも2倍)」は、すてみタックルの自分への 20 の 2 段階にも同じ数をかけます（40）。自分へのダメージは、自分のタイプと
  自分の弱点・抵抗力で別に計算します（v0.3d）。マチスのコラッタの登録は自分へのダメージに当てはめません（でんこうせっかに自分へのダメージはない）。
  `includes_self_damage` と変わるワザの「自分にも」の有無が合わなければ、カードは未対応です。
- ピッピの「ゆびをふる」などで「きあいだめ」を選ぶのは、番をまたぐ効果をワザを使ったポケモンのワザの位置で記録するので、エンジンの未対応
  （`UNSUPPORTED_COPIED_ATTACK`。v0.31 の「つるぎのまい」と同じ。選ぶと拒否し、決定は待ったまま）。

### 4.2 あわあわ

- 20 ダメージのあとコインを投げ、「うら」なら、次の自分の番、このカードは「あわあわ」を使えない（持続する効果 `state.CannotUseOwnAttack`。自分自身。
  はたらく番は与えた番 + 2）。その番の間、このワザ（位置）だけを使えず（`checks.attack_request` の `IllegalActionError("ATTACK_LOCKED")`。「しっぽをふる」と
  同じ場所。宣言の前・エネルギーの確認より前）、ほかのワザ・にげるは使えます。その番の終わりに消えます。
- コインは自分への効果だけを決めるので、相手が「ダメージを受けない」「ワザをうけない」状態でも投げます（v0.34 の `void_coin_question` の読み方）。
  ワザを使ったポケモンが同じワザの中で HP 以上になっていれば、効果を与えずコインも投げません（v0.34 の「こうそくいどう」と同じ）。
- 効果を与えたカードがいちばん上のときだけはたらき、進化・ベンチにもどる・きぜつで消えます。まねる効果では未対応（4.1 と同じ）。

### 4.3 ドわすれ

- 選ぶのはワザを使ったプレイヤー（説明の「相手のワザを1つ選ぶ」）。決定 `decisions.SELECT_OPPONENT_ATTACK`（`select_opponent_attack`）の選べるものは、
  相手の対戦ポケモンのいちばん上のカードのワザの位置（1 つしかなくても決定を出す。v0.7 の K2 と同じ実装上の仮定）。`context` の `target` に相手の
  対戦ポケモンの番号。ワザは位置で表します（名前では探さない）。
- 持続する効果 `state.CannotUseAttack`（相手に与える。はたらく番は次の相手の番 = 与えた番 + 1）。その番の間、受けたポケモンはそのワザだけを使えません。
  ほかのワザ・にげる・特殊能力は制限しません。次の相手の番の終わりに消えます。
- ベンチにもどる（にげる・ポケモンいれかえ・突風・ふきとばし）・進化・きぜつで消えます（v0.4b と同じ。進化すると、いちばん上のカードのワザの位置の
  意味が変わるので、効果は残さない）。
- 相手に与える効果なので、選ぶ前に「ワザをうけない」状態・「とうめい」を評価し、受けないなら決定を出しません（v0.31 の「しっぽをふる」・相手のエネルギーの
  トラッシュと同じ順番）。ピッピの「ゆびをふる」でまねることはできます（ピッピの相手のワザを選ぶ決定が続く）。

### 4.4 はかいのうず・ウォーターパンチ

- はかいのうず: v0.33 の型 `DamageThenDiscardOpponentEnergy(on_heads=True)` を再利用しました（ダメージ → コイン → 「おもて」なら相手についている
  エネルギーカードを 1 枚、ワザを使ったプレイヤーが選んでトラッシュ）。相手にエネルギーカードがなければ、トラッシュせず、コインも投げません（p.309。
  v0.33 と同じ）。
- ウォーターパンチ: 数えるのは、ついている「水」エネルギーの数（`state.energy_types` の「水」の数。エネルギーカードの枚数ではなく、カードが出す
  エネルギー）。今の写しのエネルギーカードはどれも 1 つのエネルギーを出す基本エネルギーなので、同じ数になります。基本エネルギーでないカードが
  ついていれば、数え方を確かめていないので `RuntimeError` で止めます（特殊エネルギーを加えるときに確かめる）。水がなければコインを投げず 30。
  コインはダメージの量だけを決めるので、「ダメージを受けない」相手には v0.4b の `UNRESOLVED_PREVENTED_COIN_DAMAGE`。

### 4.5 3ぼんのしっぽ・ぜんりょくとっしん

- 3ぼんのしっぽ: 既存の `CoinFlipDamage(coins=3, damage_per_heads=10)`（コイン 3 枚の「おもて」の数 × 10）。
- ぜんりょくとっしん: 要素の並び `Coin("coin", count=4)` → `Damage(相手, HeadsOfCoin)` → `Damage(自分, TailsOfCoin)`。同じ 4 枚のコイン（1 回投げる。
  別々に投げない）の「おもて」の数 × 20 を相手に、その後「うら」の数 × 20 を自分に与えます。「おもて」0 枚なら相手へのダメージは 0（与えなかった）、
  「うら」4 枚なら自分へ 80 で HP 70 のケンタロスがきぜつします（相手がサイドを取る）。コインは自分へのダメージも決めるので、「ダメージを受けない」相手にも
  投げます。先読みは組で 5 通りを試し、はんげきの C18 も組で判定します（2.1 の 4）。
