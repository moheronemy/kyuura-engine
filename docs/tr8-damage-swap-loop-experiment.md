## 1. 試験方策の仕様（rules-v3）

`tools/verification_ai/policies.py` の `LoopRulePolicy`（`rules_version` 3、分布 `rules-v3-candidate+uniform-stage`）。バッチの方式 `rules-v3` で明示的に選んだときだけ使う。

| 項目 | 仕様 |
|---|---|
| 土台 | `rules-v2` の順位・同順位の均等の選び方・入力単位の再送抑止（閾値 2・候補の下げ）はそのまま |
| 対象 | 候補の `use_power` のうち `power.name_ja` が［ダメージスワップ］のもの |
| 区間 | 同じプレイヤー・同じ番で、本人の受理が対象の特殊能力だけで続き、次の本人の観測まで受理の通し番号が続くあいだ。ほかの操作の受理・ほかの主体の受理で切る |
| 比べる観測 | 区間の開始前と各受理のあとに本人へ返った `view` の応答の全体（正準な JSON）。除くのは観測の外の識別子（`request_id`・`operation_id`）だけ。今の応答には現れない |
| 戻ったとき | 直近の一致の観測から今回の受理までに使った対象の候補を、その番の残りで順位 7（`end_turn` の 6 より後ろ）に置く |
| 候補の鍵 | 種類 + 能力の持ち主の参照（場のポケモンの番号）。候補の番号・場所（バトル場・ベンチ）・入力（移動元・移動先）を含めない |
| 保持と消去 | 下げた候補は番が変わるまで保持。番が変われば区間と下げた候補の両方を消す |
| 進めない場合 | 拒否・入力を作れない・送信の抑止では観測を取らず、履歴を進めない。観測を取れない受理があった区間では下げない |
| 代わりがない | 下げた候補しか組み立てられなければ、順位 7 の中から既存の規則で選ぶ |
| 理由のコード | `rule3:…`。下げた候補を含む選択には `:loop_demotedN`。エピソードの行に `loop_detection`（位置・番・一致した観測の番号・周期の長さ・下げた鍵） |

ランナー（`runner.py`）は、方策が持つときだけ `observe_view`（エピソードの始めの本人の観測と受理の通し番号）と `accepted_candidate`（本人の受理の候補）を呼ぶ。
`rules-v2` の方策オブジェクトはこの 2 つを持たない。エンジン・TR8・合法性・単局上限・judge は変えていない。

## 5. 9024 の番 23 の回帰

- 方策テスト `test_net_move_then_retreat_then_attack`: 戻していない移動のあと、にげる → ワザへ進み、`rules-v2` と同じ選択（同じ乱数）のまま下げない。成功。
- 対戦: `rules-v3` は番 19（受理 77 の後）で分かれ、番 23 の旧局面（主体 0 の受理 85〜88 の本人の観測）は `rules-v3` の局のどの観測とも一致しなかった。
  `rules-v3` の番 23 にも同じ向きの移動（バトル場のダメージ 60 → 50）があったが、この局面ではにげるを組み立てられず、2 手の往復を確かめたあと番の終了に進んだ（移動の正味は残った）。
- したがって、この型は回帰テストで確かめたが、通常の対戦では確認できていない。

## 6. 採用判断に残る課題

- 3 seed だけの比較で、一般の完走率は推定しない。
- 9023 の完走は番 19 の分岐のあとの別の進行による。`rules-v2` で起きた番 41 以降の膠着（ワザがない局面）は `rules-v3` では現れず、その局面の中での `rules-v3` の動きは観測していない。
- 下げるには往復が 1 回起きる必要がある（9023 で往復 8・9022 で 7 が残る）。
- 対象は［ダメージスワップ］の名前で決めている。ほかの繰り返せる特殊能力は対象の外。
- 9024 の番 23 の型は回帰テストだけで確かめた（5 章）。
- 既定化の前に、ほかの条件（C2〜C4）と多くの seed での比較が要る。
- 続き: 未使用の 8 seed（9027〜9034）の C1 での比較は [tr8-rules-v3-fresh-seed-comparison](tr8-rules-v3-fresh-seed-comparison.md)（両側 8/8 が game_over、配置の戻り 316 → 33）。
