# v0.104: 回復のワザを持つポケモン 12 枚と、回復の量・対象・とりのぞくかの選択

v0.104 は、回復のワザを持つポケモン 12 枚（キレイハナ・ミルタンク・ヒメグマ・イノムー・フシギダネ 3 枚・ジュゴン 2 枚・プリン 2 枚・ラプラス）を、ワザ 24 とともに登録する版です。
11 のワザは既存の型（`DamageOnly`・`ParalyzeOnHeads`・`ConfuseOnHeads`・`PoisonWithoutDamage`・`DamageAndSelfDamage(20)`・`HealSelfWithoutDamage(3)`）、フシギダネの「かいふく」3 つは
既存の型 `HealSelfWithoutDamage(1)` に、対象・数・条件と結び付いた書き方（`HEAL_ONE_IF_DAMAGED_TEXTS`）を明示して加え、残る 10 のワザは 7 つの新しい型で表しました。新しい型は、v0.41・
v0.89 の回復の要素（`programs.HealCounters`・`TargetHeal`）の小さな拡張（すべて `every`・「おもて」1 枚あたりの数 `per_heads`・対象 `HEAL_BOTH_ACTIVE`・選ぶ場 `side`）と、とりのぞくかを
選ぶ要素 `programs.OptionalHealSelf`（決定 `OPTIONAL_HEAL`）、v0.90 の `CureOwnConditions` の受ける判定（`reach`）、既存の `Status`・`SelfAttackLock`・`PokemonCountTimes` の組み合わせです。
回復の要素はどれも v0.103 の `kernel.reaches` → `first_void`（発生元 `events.Incoming`）を通ります。写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）、書き出しの形式は 26 のままです。
新しい停止コード・研究上の未解決はありません。

## 3. 登録の共有と文面の確かめ

- 同じカードの組は 3 組 7 枚です。日本語の名前・pokemon 欄が同じ QSG-001（→ ES1-001）・QSG-018（→ ES2-007）・PR1-004（→ PR1-002）は、id ごとに登録したうえで v0.70 からの
  `_with_shared_entries` で同じ登録の値にまとめました（`SAME_DATA_CARDS_V0_104`。場の個体・持ち主は個体ごとに別のもの）。
- IP1-018 は同じカードの組 `SC-ES1-001` ですが、かいふくの文面の最後に句点があります（ES1-001・QSG-001 にはない。ほかの欄は同じ）。共有のために原文を直さず、IP1-018 の登録は
  その文面のまま置き、処理の値（`HealSelfWithoutDamage(1)`・`PoisonWithoutDamage()`）を ES1-001 と同じにしました（`SAME_DATA_CARDS` には入れない。採用の記録・処理に使う文面は id ごと）。
- フシギダネのかいふく「このカードにダメージカウンターがのっていれば、それを1つ取りのぞく」は、`HealSelfWithoutDamage(1)` の v0.79 の書き方（「自分にのっているダメージカウンターを、
  1個とりのぞく。」）では拒否されていました。意味を確かめ（「このカード」はワザを使ったポケモン、「それを1つ」は 1 個、「のっていれば」はのっていなければとりのぞくものがないこと）、
  1 個のときだけの書き方 `HEAL_ONE_IF_DAMAGED_TEXTS`（句点なし・あり）として明示して加えました。「のっていれば」をワザを使うための条件にしていません（0 個でも使え、何もしない）。
  一律の文面の正規化・部分一致では通していません（`RegistrationTest.test_texts_are_not_normalized`。2 個の型・句点の重なり・「とりのぞく」のひらがなは拒否）。
- 既存の型の 11 のワザ: 型の検査が形だけのもの（`ParalyzeOnHeads`・`ConfuseOnHeads`・`PoisonWithoutDamage`・`DamageAndSelfDamage`）は、同じ型・同じ文面の既存の登録があることと、
  すてみタックルの「自分にも20ダメージ。」の数が型の値と同じことを、テストで明示して照らしました（`test_reused_types_match_the_printed_text`。型の全文の検査を改める作業には広げていない）。
  ひとやすみは `HealSelfWithoutDamage(3)` の全文の検査、ひっかくは説明文のない `DamageOnly`（文面・出典を持たない）です。

## 4. 回復の共通処理とカード固有の組み合わせ

### 4.1 回復の量・対象・効果の到達

- 回復はダメージカウンターをとりのぞく効果で、ダメージではありません（GR-2000-P320-RECOVERY）。弱点・抵抗力・軽減を計算せず（`deal_damage` を通らない）、「ダメージを受けたとき」の
  反応（［はんげき］など）を起こしません（`ReachTest.test_heals_are_not_damage`）。とりのぞくのはのっている数まで（負のダメージにしない）。
- 量: 決まった数（`HealCounters(counters)`・`TargetHeal(counters)`）、すべて（v0.104 の `every`。大きな決まった数で代用しない）、「おもて」の数 × 数（`heads_of` と v0.104 の `per_heads`。
  ミルクのみは 2）、取り除くかを選ぶ 1 個（`OptionalHealSelf`）。どれか 1 つで決め、組み合わせの誤りは組み立てる時に `ValueError` にします。
- 対象: ワザを使ったポケモン（`HEAL_SELF`）、自分の場から選んだ 1 匹（`ChooseEffectTarget(side=TARGET_SIDE_OWN)` → `TargetHeal(side=TARGET_SIDE_OWN)`。自分の場だけから選ぶので相手の
  ポケモンに効果を与えない（`opponent_element` がない））、ワザを使ったポケモンと相手の対戦ポケモン（v0.104 の `HEAL_BOTH_ACTIVE`。控えは含めない）。
- 到達: とりのぞく前に、対象が場にいてこのワザで HP 以上でないこと（`run.knocked_out`）、受けるか（`reaches` の `heal`。「ワザをうけない」状態・効果だけを無効にする効果は v0.103 の
  `first_void` に発生元 `Incoming` を渡して判定し、「とうめい」は 1 匹 1 回）を、処理の時点で確かめます。自分のポケモンへの効果も「とうめい」を評価します（v0.9 の T8）。
- 0 個: のっていないポケモンからはとりのぞく処理がない（効果を受けない。「とうめい」の判定も、ログもない。v0.41 の約束のまま）。それだけで続く要素（ねむり・特殊状態の回復）を省かず、
  ワザを失敗にしません（p.309）。取り除くかを選ぶ回復は、のっていなければ決定を出しません。

### 4.2 組み合わせの順番と条件

| ワザ | 要素の並び | 条件・読み方 |
|---|---|---|
| あまいみつ | `Coin` → `ChooseEffectTarget(side=OWN, gate=おもて)` → `TargetHeal(every, gate=おもて, side=OWN)` | コインを先に投げ、「おもて」のときだけ選ぶ。選べるのは自分の場のすべて（バトル場 → ベンチ。のっていないポケモンも。0 個を選んだら何もしない）。コインは自分の回復だけを決めるので、相手の状態によらず投げる |
| フラワーダンス | `Damage(OPP, PokemonCountTimes(30, SCOPE_OWN_IN_PLAY, ("キレイハナ",)))` | 数えるのはダメージの要素の時点の自分の場で、今の姿の名前（`form_def`）が「キレイハナ」と完全に同じもの（ワザを使ったポケモン・名前の同じ別のカード PRN-043 も）。相手の場・「クサイハナ」などは数えない。0 匹なら 0 |
| ミルクのみ | `Coin("coin", count=2)` → `HealCounters(heads_of="coin", per_heads=2)` | コインはいつも 2 枚（0 個・とりのぞける数が少なくても減らさない）。「おもて」0〜2 枚で 0・2・4 個（のっている数まで）。先読みは「おもて」の数でまとめる（v0.35） |
| おひるね | `HealCounters(every)` → `Status(SLEEP, target=SELF)` | すべて → 自分をねむり。どくは残る（p.322）。こんらん・マヒはねむりで置きかわる |
| ねむる | `HealCounters(every)` → `CureOwnConditions(REST_CURES, reach=True)` → `Status(SLEEP, target=SELF)` | すべて → 説明の「どく・ねむり・マヒ・こんらん」を回復 → 自分をねむり。マーカー・持続する効果は消さない |
| かいふく（プリン） | `OptionalHealSelf(1)` | 4.4 節 |
| かいふく（フシギダネ）・ひとやすみ | `HealCounters(1)`・`HealCounters(3)` | 必ずとりのぞく（選ばない）。のっている数まで |
| もうとっしん | `Damage(OPP)` → `Damage(SELF, 30)` → `SelfAttackLock(None)` | 4.6 節 |
| やさしいうた | `HealCounters(2, scope=HEAL_BOTH_ACTIVE)` → `Status(SLEEP)` | 自分 → 相手の対戦ポケモンの順に 2 個ずつ（のっている数まで）→ 相手をねむり。相手が効果を受けなくても、自分からとりのぞく効果は有効（GR-2000-P321-PREVENTED-ELEMENTS） |

### 4.3 「とうめい」・順番・その時点の問い合わせ

- 同じワザの同じ個体への受ける判定は 1 回です（v0.13 の T4。`fs.reception`）。やさしいうたで相手のゴースト（化石の秘密。［とうめい］）が「おもて」なら、とりのぞく効果とねむりの両方を
  受けず（ログ `attack_evaded` が要素ごとに 2 つ。判定 `evade_check` は 1 つ）、「うら」なら両方を受けます（`ReachTest.test_transparency_is_judged_once_for_the_heal_and_the_sleep`）。
  おひるね・ねむるの自分への回復・特殊状態の回復・ねむりも同じ 1 回の判定を共有します（とりのぞくものがなければ、最初に受ける要素のときに判定する）。
- 「それぞれ」の順番（やさしいうた）: 自分 → 相手の順に処理しますが、順番で結果が変わる場面は見つかりませんでした。回復は相手の状態・特殊能力の条件を変えず（どの回復も残りHPを増やすだけで、
  ［ずらかる］の「残りHPが「10」になった時」・きぜつの判定にかからない）、「とうめい」の判定は受けるポケモンごとに 1 回で、どちらも「とうめい」なら既存の T27
  （`UNRESOLVED_TRANSPARENCY_COIN_ORDER`。2 匹以上の「とうめい」）で止まります。片方だけなら判定は 1 つで、順番によらず同じ乱数を使います。順番はログの並びだけなので、コードの順で
  裁定を確定したことにはしていません（差の出る境界は T27 の既存の問いだけ）。
- 回復・特殊状態の回復で能力・今の姿・最大HPが変わる場合は、既存の問い合わせ（`form_def`・`max_hp`・`status_immunity`・`catalog.working`）を、その要素を処理する時点の場で評価します
  （ねむるでこんらんを回復させたあとのねむりは、その時点の［めんえき］などで判定する）。今の写しで、回復のあとに能力が変わってワザの結果が変わる組は見つかりませんでした。

### 4.4 取り除くかを選ぶ回復（プリンのかいふく）

- 「自分についているダメージカウンターを1つ取り除くことができる。」を、取り除くかどうかの選択と読みました（実装上の読み方）。ワザを使ったポケモンにのっていれば、ワザを使ったプレイヤーが
  選びます（決定 `OPTIONAL_HEAL`。選べるものはワザを使ったポケモンの番号 1 つで 0〜1 個。`context` の "counters" は取り除く数）。のっていなければ決定を出しません。
- 取り除くを選んだら、受ける前に「とうめい」などを評価して 1 個取り除きます（ログ `attack_heal`）。取り除かないを選んだら、ログ `attack_heal_declined`（取り除けた数。公開の情報）。
- v0.72 の「きゅうけつ」（`Drain` の `optional`）は参考にしましたが、「相手にダメージを与えたら」の条件・与えたダメージの結果を要求しません（相手にダメージを与える要素もない）。フシギダネの
  かいふく（必ずとりのぞく）とは別の型です。v0.42 の `REMOVE_COUNTERS`（「好きなだけ」。0 個が HC5）とも別の決定です。
- 相手のワザとして使う（ピクシーのゆびをふる）と、使ったポケモン自身から取り除くかを、使ったプレイヤーが選びます（`DecisionTest.test_copied_optional_heal_asks_the_copier`）。

### 4.5 特殊状態の回復とねむり

- おひるねは回復させる特殊状態を書かないので、ねむりの付与だけです（こんらん・マヒはねむりで置きかわる（ログ `special_conditions_removed` の `replaced`）、どくは残る）。

  の `cured`）。マーカー・持続する効果・特殊能力の記録は回復させる特殊状態ではないので残します（完全な初期化にしない。`ConditionOrderTest`）。
- v0.104 で `CureOwnConditions` に `reach`（既定は偽）を加えました。真なら、回復させる特殊状態があるときだけ、受ける前に「とうめい」などを評価します（`reaches` の `cure`。同じワザの
  回復・ねむりと同じ自分への効果の受ける判定）。v0.90 のミュウツーの「かんぜんかいふく」（`HealAllCounters` → `ClearOwnMarkers` → `CureOwnConditions`）は今までどおり評価しません（変えていない）。
- ねむり・マヒのポケモンはワザを宣言できないので（`POKEMON_ASLEEP`・`POKEMON_PARALYZED`）、合法な対戦でねむるが回復させるのはどく・こんらんだけです。相手のワザとして使うポケモンも、ワザを
  使う時にねむり・マヒではありません。ねむり・マヒからの回復は、要素を直接処理して確かめました（`test_sleep_and_paralysis_cures_are_reached_only_by_the_element`。対戦の経路と分けた）。

### 4.6 もうとっしん

## 5. v0.103 の発生元との統合

- 回復・ねむり・特殊状態の回復の要素は、どれも `reaches` → `first_void(res, incoming, …)` を通り、発生元（実際の使い手・個体・分類・ワザ）は開いたワザの枠の値です（今の番のプレイヤー・
  借りたワザの印刷元で代用しない）。
- たねのラプラス自身のやさしいうたは、相手のミュウ（［ニュートラルシールド］）も受けます（とりのぞいてねむり）。進化したピジョンが、前の相手の番に受けたやさしいうたをオウムがえしで出すと、
  使い手はピジョン（1 進化）なので、ミュウへのとりのぞく効果とねむりは無効（`effect_prevented` の `neutral_shield`。発生元はピジョン）で、ピジョン自身からとりのぞく効果は残ります。
  ワザを印刷したラプラスがたねであることで防護を外しません（`ReachTest.test_neutral_shield_follows_the_actual_user`。突風で相手のベンチのミュウをバトル場に出す合法な手順で作った）。
- 進化したジュゴン・イノムー・キレイハナのワザのダメージ・効果は、相手のミュウに無効です（v0.103 のまま）。ジュゴンのオーロラウェーブの「おもて」のこんらんだけを決めるコインは、既存の
  HC3（`UNRESOLVED_PREVENTED_EFFECT_COIN`）で止まります。
- オウムがえしの既存の境界（MM1・MM2）は変えていません。受けたワザのエネルギーをピジョンが払えなければ MM2（`UNRESOLVED_MIRROR_MOVE_ATTACK_CONDITIONS`）です。

## 6. コピー・保存の制限

- 相手のワザとして使う（ゆびをふる・オウムがえし）とき、回復の要素は使ったポケモンを「自分」として処理し、選ぶ・取り除くかを決めるのは使ったプレイヤーです。もうとっしんの使えなくする
  効果は既存の未対応（4.6 節）。
- 決定をまたいで運ぶ値: あまいみつのコインの結果（続きの情報の `coins`）・選んだ個体（`chosen_targets`）、プリンのかいふくの取り除く数（`counters`）と枠の値（`carry`）。閉包・共有される
  可変の個体の参照は保存しません。clone・deepcopy・pickle から同じ答えで続けても同じ結果になり、とりのぞく・コイン・ねむりは 1 度だけです（`DecisionTest.test_clone_copy_and_pickle_resume_once`）。
  コインは選ぶ前に投げ、決定のあとに投げ直しません。
- 不正な答え（ほかのポケモン・2 つ・答えるプレイヤーの違い）は、状態・乱数・ログ・決定を変えずに拒否します（HALTED にしない）。新しく HALTED に移る境界はありません。
- 先読みの方法（`derived`・`derived_full`・`legacy`）は同じ結果です。新しい型は v0.13 の止める関数で確かめた型（`v013_checks.VERIFIED`）ではないので、`legacy` でもすべての結果を試します
  （上限 `MAX_BRANCHES` = 4096 は変えていない）。
