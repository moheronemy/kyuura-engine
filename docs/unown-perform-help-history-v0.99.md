# v0.99: アンノーンP・H とタッツーの 3 枚と、受けたダメージの場所の履歴

v0.99 は、アンノーンP（［PERFORM］）・アンノーンH（［HELP］）・タッツー（「ひれがえし」）の 3 枚を、ワザ 3・特殊能力 2 とともに登録する版です。［PERFORM］の「前の相手の番、
このカードが、バトル場で相手のワザによるダメージを受けていたなら」のために、v0.62 の場のポケモンの履歴に、受けたダメージを受けた時の場所（バトル場・ベンチ）で分けた量を加え、
特殊能力だけが履歴を読む対戦でも記録するようにしました（書き出しの形式 25）。写しの元と研究の基準は v0.97 のまま（kyuura `73a1690`）です。

> v0.100 の訂正: この版の問い（［PERFORM］の受けた場所）の略号は、公開時の PF1 から PFM1 に改めました（PF1 は v0.47 の別の問いの略号。7 章の注記）。

## 3. 受けたダメージの場所の履歴（共通の処理）

v0.98 までの履歴（v0.62。`PokemonInPlay.history`）は、相手の番に相手のワザから受けたダメージを、その番の合計（`AttackReceived.damage`）だけで持っていました。［PERFORM］の
「バトル場で…受けていたなら、その受けたダメージと同じダメージ」には、バトル場で受けた分を、ベンチで受けた分と分けた事実が要ります。今の場所・今のダメージカウンターの数・ログの逆算では
代用しません。

| 変えたところ | 内容 |
|---|---|
| `state.AttackReceived.active_damage`（新しい項目） | `damage` のうち、ダメージの要素を受けた時（のせた時）にこのポケモンが持ち主のバトル場にいた分の合計。ベンチで受けた分は `damage - active_damage`。None は場所の分からない記録（v0.98 までの記録の写し。pickle で残した前の版の状態など）で、作り直さない |
| `history.note_received` | ダメージの要素ごとに、のせた時に受けるポケモンが持ち主のバトル場にいれば `active_damage` にも加える（新しい記録は 0 から数える）。受けた量は既存の分類と最終計算（解決の基盤の `kernel.deal_damage` の最終ダメージ。［ベンチガード］のサイドンがかわりに受けた 10 も、そのサイドンのその時の場所で）のまま |
| `history.damage_places`（新） | 受けた記録の (バトル場の分, ベンチの分)。合計が 0 なら場所の分からない記録でも (0, 0)（のせた量はどれも 0 以上なので、どの分け方でも 0）。合計が 0 より大きく場所の分からない記録は、合計をバトル場の分・0 にせず `UnsupportedError`（`UNSUPPORTED_HISTORY_DAMAGE_PLACE_UNKNOWN`） |
| `history.history_needed` | 履歴を読む効果に特殊能力（`PowerEffect.reads_history`。［PERFORM］）を加えた。対戦のカードの定義と効果の登録表だけで決め、特殊能力がはたらいているか（ガス・場所・特殊状態）では決めない |
| `engine._history_problems`（不変条件） | `active_damage` は None か、合計以下の 10 の倍数 |

- 変えていない規定: 記録するのは、番のプレイヤーのワザの枠（`FrameKind.ATTACK`）のダメージの要素が相手の場のポケモンに当たったときだけ（自分へのダメージ・返す効果のダメージ・こんらんの 20・
  特殊能力・トレーナー・ポケモンチェックのダメージ、ダメージカウンターをのせる・移す効果は入らない。GR-2000-P320-COUNTER-MOVE）。最終ダメージ 0 の要素は受けた要素として記録し、0 は
  「受けなかった」（p.319・p.321）。受けたあとの回復で記録を減らさず、残りHPで丸めない。にげる・入れ替えでは記録を消さず、場所を書きかえない（受けた事実は変わらない）。進化・退化で消し、
  場をはなれたポケモンを出し直したら別のポケモン（新しい番号・記録なし）。読むときは「このカード」（いちばん上のカードと今の姿になった番。`history._this_card`）を確かめる。番の最初に 2 つ前の
  番より古い記録を消す。
- ［PERFORM］の力が、受けた時にかがくへんかガスなどで消えていても記録します。使う時にはたらいていれば読みます（文面に「受けた時にこの力がはたらいていたこと」の条件はない。
  `PerformTest.test_gas_at_damage_time_does_not_prevent_later_use`）。
- 1 つの番に同じポケモンが受ける相手のワザは 1 つ（v0.62）で、そのワザの複数のダメージの要素は、要素ごとの場所で分けて合計します。同じワザでバトル場とベンチの両方で受けた場合の
  ［PERFORM］の量だけが決まらない境界（PFM1。4 章）で、合計・場所を落とさずに持つので、その場面だけを止められます。
- 履歴を読む効果のない対戦では、今までどおり何も記録しません（状態・乱数・ログ・観測は v0.98 と同じ）。アンノーンH だけの対戦でも記録しません（`DamagePlaceHistoryTest.test_history_is_needed_when_only_a_power_reads_it`）。

## 4. ［PERFORM］（アンノーンP）・「ひれがえし」（タッツー）のダメージ

［PERFORM］「この力は、このカードが「めざめるパワー」を使うとき、はたらく。前の相手の番、このカードが、バトル場で相手のワザによるダメージを受けていたなら、その受けたダメージと同じダメージを、
このカードが使う「めざめるパワー」のダメージに追加する。」

「ひれがえし」「前の相手の番、このカードがワザによるダメージを受けていたなら、10ダメージを追加する。」

### 4.1 基本例（実装前の文面の読み方の例。独立した新しい公式裁定の記録ではない）

| 前の相手の番 | タッツー | アンノーンP |
|---|---:|---:|
| 受けていない | 20 | 10 |
| バトル場で相手のワザから 20 受けた | 30 | 30 |
| ベンチでだけ 20（テストでは 10）受けた | 30 | 10 |

（ほかの変更がないとき。テストの盤面は弱点のある相手で、その分を含めて確かめた。`BasicExamplesTest`）

### 4.2 どちらも宣言の拒否にしない

- 条件を満たさなくても、P のめざめるパワーは 10、タッツーのひれがえしは 20 として使えます（v0.62 のドリルホールの「使っていた時だけ使える」の `usage_problem` にしない）。
- ［PERFORM］は「はたらく」常にはたらく力（`ContinuousPower`。宣言しない）です。`UsePokemonPower` で使わせず（`POWER_NOT_DECLARABLE`）、`UseAttack.attack_power`（v0.88 の［すいりょくはつでん］）で
  使うかを聞かず、回数の制限もありません。日本語の文面にねむり・マヒ・こんらんの段落はないので、似た型の既定値から禁止を加えていません（`blocked_by_status` は偽）。特殊能力を消す効果は
  ダメージを計算する時の共通の確かめ（`continuous_powers`）、めざめるパワーを使う条件（エネルギー・特殊状態・ワザの禁止）は通常のワザの共通の確かめです。

### 4.3 計算の段階

- 「ひれがえし」の追加は、ワザの説明にしたがう基本となるダメージ（p.321 の 1 段階）への加算です（v0.83 の「みずあそび」などの「…ダメージを追加する」と同じ扱い。要素の値 `programs.PlusIfDamagedLastOpponentTurn`）。
- ［PERFORM］の追加は、ワザの説明ではなくワザを使うポケモンの持つ特殊能力の効果なので、p.321 の 2 段階（ワザを使うポケモンの持っている「ダメージを変更する効果」）の加算として置きました。既存の
  v0.46 の［きょうぼう］（このカードが与えるダメージの「+」。2 段階）・v0.88 の［すいりょくはつでん］（ワザといっしょに使う特殊能力。2 段階）と同じ段階で、v0.27 の「つるぎのまい」（ワザの名前で
  限られる持続する効果。2 段階）と同じく、ワザの名前で限られます。共通の履歴を読むこと（ひれがえしと同じ記録）と、同じ計算の段階に置くことは別に決めました。弱点（3 段階）の前なので、弱点
  超の相手には (10 + 20) × 2 = 60（`PerformTest.test_step_2_is_before_weakness_and_copies_agree`）。
- 同じ段階の順番で結果が変わる効果が重なれば既存の順番の決定（`damage_step_order`）を使います。今の写しで P のめざめるパワーに重なる 2 段階の効果は加算だけ（「なきごえ」など）で、順番で結果は
  変わらず決定は出ません（P の持続する効果になる「つるぎのまい」「きあいだめ」は P のワザではない）。

### 4.4 ［PERFORM］を当てはめる範囲

- 当てはめるのは、この力を持つポケモン自身がワザを使うポケモンで、処理しているワザの名前が「めざめるパワー」で、そのワザがこのポケモンの今持つワザ（共通の問い合わせ `available_attacks`。今の姿の
  ワザ・思い出させる・［サイコリンク］）のときです。P の印刷のワザの位置（`neo4-058` の 0 番）だけを特別に扱っていません。場にいるだけで、ほかのアンノーンのめざめるパワーや、P のワザを借りた
  ポケモン（ゆびをふるのピッピ）のワザには加えません（`PerformTest.test_other_pokemon_do_not_get_the_bonus`）。今の写しで P が今持たない「めざめるパワー」を処理することはない（まねるワザを
  持たない。［へんしん］のメタモンは特殊能力を写すかが決まらない TF1 で、その姿にならない）ので、起これば止めます（エンジンの不具合）。
- 名前で限られる常にはたらく力に処理しているワザを渡すため、`ContinuousPower.attack_damage_modifiers` と `continuous_attack_damage_modifiers` に省略できない引数 `attack` を加えました（外側の
  `attack_damage_modifiers` が受けていた `AttackKey` をそのまま渡す）。宣言の前の先読み（`preview_attack_damage`）・実際の処理（`kernel.deal_damage`・`attack_modifiers_of`）・効果を除く範囲の
  比べ（SS1・FA1・DF1）・控えへのダメージの比べ（JS1）・「うら」が出るまで投げるコインの先読み（`resolution.unbounded`）・旧版の比べ（`engine` の 2 か所）はどれも同じ関数を通るので、
  履歴と当てはめる条件の見方が同じです。`attack` を None で渡すのは、こんらんの 20 の問い合わせ（`confusion_power_modifiers`）と、同じ力が 2 匹以上ではたらきうるかの問い合わせ
  （［DARK df］・［NORMAL df］だけが対象の `self_excluding_readings`）だけです（どちらも呼ぶ側で明示する）。
- こんらんの 20 は、もとのワザの内容に関わらない（p.309 の手順 5）ので、「めざめるパワー」のダメージではありません（v0.27 の「つるぎのまい」の「「きりさく」のダメージ」と同じ分類）。こんらんの
  P が「おもて」ならワザで加え、「うら」の 20（自分の弱点 超で 40）には加えず、v0.3c の `UNRESOLVED_CONFUSION_DAMAGE_MODIFIERS` でも止めません（`PerformTest.test_confusion`）。返す効果の
  ダメージ（v0.12・v0.13・v0.83）の枠のワザは返す効果を与えたワザで、P のめざめるパワーが返す効果を与えることはないので、加えることはありません。
- 量は、前の相手の番（今の番の 1 つ前）の、このカードの受けた記録のバトル場の分です。0 なら加えません。あとで回復していても加え（`PerformTest.test_healed_damage_is_still_added`）、ベンチで
  だけ受けた分は加えません。同じ相手のワザで、バトル場とベンチの両方で受けていたら、「その受けたダメージ」がバトル場で受けた分か、そのワザで受けたダメージ全体かが決まらないので、その場面
  だけを PFM1（`UNRESOLVED_PERFORM_DAMAGE_PLACES`）で止めます（宣言の前の先読みで拒否する。今の写しでは起こらない。片方の場所だけで受けた通常の場面は止めない）。

### 4.5 「ひれがえし」の範囲

- 「このカード」はワザを使うポケモンです。ゆびをふる（ピッピ）・オウムがえし（ピジョン）で相手のタッツーのひれがえしを使うときは、使うポケモンの受けた記録を読み、印刷したタッツーの記録は
  読みません（`PerformTest.test_copied_fin_slap_reads_the_user`。v0.31・v0.62 の、まねたワザの「このカード」は使うポケモンという既存の扱い）。
- 文面に場所と「相手のワザ」の限定がないので、［PERFORM］の条件をそのまま当てはめず、バトル場・ベンチのどちらで受けた分も数えます。前の相手の番に、このカードが受けうるワザによるダメージは
  相手のワザのダメージの要素だけ（返す効果のダメージ・こんらんの 20 は番のプレイヤーのポケモンが受ける）で、受けた記録の範囲と同じです。今の写しで起こらない範囲（相手の番に、相手のワザ以外の
  ワザによるダメージを受ける場面）の規定は作っていません。ワザ以外のダメージ（オニスズメの「オウムがえし」の OM2 の問い）は、文面が「ワザによるダメージ」に限るので数えません。

## 5. ［HELP］（アンノーンH）

「この力は、自分のベンチに、このカードとアンノーン「E」「L」「P」がいるとき、自分の番ごとに1回使うことができる。自分の手札の枚数を数え、それらをすべて山札にもどし、その山札をよく切る。
その後、その山札から、もどした枚数ぶんのカードを引いて、手札にする。」

- 宣言して使い、自分の番ごとに 1 回です（`once_per_turn`。宣言のときに記録する。回数は呼ぶ側の共通の確かめ `require_power_not_used`）。日本語の文面に特殊状態の条件はなく、特殊能力を消す効果は
  共通の確かめ（`POWER_SUPPRESSED`）です。選ぶものはありません（`target` などを書けば `POWER_CHOICE_NOT_USED`）。
- 条件は v0.97 の［FIND］・v0.98 の［GIVE］と同じ `require_bench_letters` に E・L・P とグループ「アンノーン」を渡して流用しました（このカードが自分のベンチにいる `POKEMON_NOT_ON_BENCH`・
  自分のベンチのほかのポケモンに今の姿のグループが「アンノーン」で文字が E・L・P のそれぞれがいる `REQUIRED_BENCH_POKEMON_MISSING`。相手の場・バトル場は数えない。うらのカードは、おもての
  ポケモンで足りないときだけ読む FD1）。F・J・G の条件と拒否は変えていません。P がバトル場でめざめるパワーを使うあいだは、P がベンチにいないので H の条件を満たしません。
- 処理は説明の順です: 処理の前の手札の枚数を数える → 手札をすべて見せずに山札の一番下にもどす（`zones.return_hand_cards_to_deck` の `power`。もどす位置はこのあと切るので実装上の仮定。ログ
  `hand_to_deck` のカードは持ち主だけ）→ 山札を 1 回切る（ログ `shuffle` の `power`）→ もどした枚数を引く（`zones.draw_cards`。もどしたあとの山札はその枚数以上なので足りる）。v0.54 の
  ナツメの眼（`ReturnHandsToDeckTrainer(draw_returned=True)`）と同じ手札・山札のゾーンの関数で、相手の手札・山札は動かさず、手札の内容は公開しません。H 自身は場にいるので、使っている最中の
  トレーナーのように手札から除くカードはありません。効果で引くのは番の最初のドローではありません（番の最初のドローの処理・記録を使わない）。手札を入れ替えても場の P の受けた記録は変わりません。
- 手札が 0 枚のとき: 必ずもどす効果（「…すべて山札にもどし、その山札をよく切る」）なので、v0.54 の HD2（もどすカードが 0 枚でも、もどすプレイヤーの山札を切る。ナツメの眼などの実装上の判断）
  を当てはめ、使えるようにしました（山札を切り、0 枚引き、回数を使う。`HelpTest.test_empty_hand_shuffles_and_draws_zero`）。これは HD2 の適用範囲（強制的にすべてもどす効果）の中の読み方で、
  公式の裁定ではありません。任意でもどす［ENGAGE］の EG1（「のぞむなら」「もどしたプレイヤーは」）をそのまま当てはめて止めることはしていません。v0.42 の［ぶっしつこうかん］の PW2 は
  「1 枚選んでトラッシュ」の選ぶカードがない問いで、［HELP］には選ぶものがないので当てはまりません。kyuura の `UQ-CARD-USE-WITHOUT-TARGET` の事例に［HELP］はなく、新しい問いは作っていません。
- 決定はないので、不正な答え・再開で、もどす・切る・引く・回数の消費が重なることはありません。不正なコマンド（ほかのプレイヤー・選ぶものを書いた・ガス）は状態・乱数・ログを変えません。

## 6. 決定・保存・観測・互換性

- 新しい決定の種類はありません。公開の API の呼び方も変えていません（`ContinuousPower.attack_damage_modifiers` の引数 `attack` は内部の実装の約束で、呼ぶ側はすべて明示した）。
