## 2. ソースの照合

### 2.1 バッチを実行したときのソースと 0.195.0

- 本実行の実行コミットは `891e1fbe146a275be1ccc6d37ec2091656b48e7e`（0.194.0）です。`891e1fb..6d9a5ac` のコードの差は `kyuura_engine/__init__.py`・`conventions.py`・`effects.py`（v0.195 の ER9 の規約）と、テスト・生成の道具だけでした。
- 差の中に `check_playable`・`WITHOUT_TARGET`・`check_play_trainer`・`_trainer_candidate` はありません。`DiscardFromHandThenRetrieveEnergy` の定義の先頭から `resolve` の前まで（`check_playable` を含む）の sha256 は、両方のコミットで同じです（`c5396321…`）。
- **ER10 の経路は、バッチの実行時と 0.195.0 で同じです。** TR4@1 の規約は回収の決定への空の答えの分岐（`resume`）だけに当たり、ER10 の確かめには届きません。

### 2.2 停止の道（`engine.check_play_trainer` の順）

| 段 | 確かめ | ER10 との関係 |
|---|---|---|
| 1 | 番・手札・トレーナーであること | 不正な操作なら候補から消える |
| 2 | トレーナーの使用の禁止（`TRAINER_PREVENTED`） | 同上 |
| 3 | 効果の登録（なければ `UNSUPPORTED_TRAINER`） | エネルギー回収は登録あり |

- 選べるもの（`_retrievable_energy`）は「自分のトラッシュの基本エネルギーカードから、このカードを使うためにトラッシュしたカードを除いたもの」です。費用でトラッシュした基本エネルギーは選べない（ER7）ので、使う前に 0 枚なら、費用を払ったあとも 0 枚です（ER11）。今の `resume` は、選べるものが 0 なら `RuntimeError`（確かめの漏れ。エンジンの不具合）にしています。
- 超エネルギー回収（`SuperEnergyRetrieval`）は同じ `check_playable` を使い、コードだけを `WITHOUT_TARGET` で上書きしています（SR1）。規約を `self.WITHOUT_TARGET[0]` のコードで引けば、超エネルギー回収には当たりません。

### 2.3 合法手 API での見え方（今）

- `legal_actions._trainer_candidate` は、手札のトレーナーごとに `check_play_trainer` を状態の複製の上で試します。不正な操作は選択肢から消し、`UnsupportedError`（停止）は選択肢として残して `unresolved_ruling`・`stops_before_acceptance` にします。規約による不正な操作（`IllegalActionError` の属性 `convention`）は、選択肢に残して `eligible` を偽にし、`convention` に規約 ID を書きます（`processability` は書かない）。
- 候補全体の区分は、実行できる選択肢があればその最良の区分（`may_stop_later` など）、なければ停止の区分（ここでは `unresolved_ruling`）です。選択肢が規約による除外だけなら `not_implemented`・`no_eligible_card` です。
- このため、**エネルギー回収のほかに実行できるトレーナーが手札にあれば「選択肢の除外」、なければ「候補全体の除外」**になります。2 つは同じ場面の別の見え方で、同じ局面で両方にはなりません（1.2 の共通 0）。
- ER10 の選択肢を選んで送ると、check・submit は公開の入口で `CANDIDATE_NOT_EXECUTABLE` と断ります。エンジンに直接 `PlayTrainer` を送ると `UnsupportedError(ER10)` です。

### 4.2 B: どこで使えないとするか

- 置く場所は `check_playable` の ER10 の分岐です。TR3 の `unresolved_or_convention_rejection` と同じ形で、規約があれば `IllegalActionError`（コードは例えば `NO_BASIC_ENERGY_IN_DISCARD`。名前は案）、なければ今の `UnsupportedError(ER10)` にします。
- **費用の前に止まります。** `check_playable` は手札から出す前に呼ばれるので、カードは手札のまま、費用は払われず、状態・乱数・ログは変わりません。
- **候補・入力・check・submit:** 候補の作成と入力は同じ関数を状態の複製で試すので、選択肢は自動で「規約による除外」になります。check・submit の断りのコードは今と同じ `CANDIDATE_NOT_EXECUTABLE` です。
- **代用の経路:** 錯乱ジム・サイキックコントロールは `borrow_condition_stop` が `IllegalActionError` を「満たせない」として扱います。そのため「使う」の答えは拒否になります（今は止める選択）。TR3 の 3 規約と同じ扱いです。
- **今も実行できない手なので、効果は表示と診断の変更だけです。** 実行できる手は増えず、拒否も減りません（もともと 0）。

### 4.3 C: 対象がなくても使えるとしたときに整理すること

| 項目 | 史料で決まる | 規約で決める（推奨値の案） |
|---|---|---|
| 費用 | 手札からカード 1 枚（種類の制限なし。ER2） | 払う。もどさない（TR4 の 0 枚と同じ。取り消しの手順は p.310 にない） |
| 費用でトラッシュした基本エネルギー | 回収の対象にならない（ER7。印刷の最新の説明） | — （史料どおり。費用で基本エネルギーを捨てても対象は 0 のまま） |
| 回収の決定 | — | **出さない**。選べるものが 0 の決定は、空の答えしかない形だけの決定になり、今の不変条件（`decision_problems` の「選べる基本エネルギーカードがない」）にも当たる。費用の決定（`discard_from_hand`）のあと、決定を出さずに使い終える |
| 使い終わり | 使ったカードはトラッシュ（p.310） | 1 枚以上の答えと同じ `_finish_trainer`（ログ `discard_trainer`）。番は続く |
| 公開ログ | 費用の `discard_from_hand` は公開（トラッシュは公開） | `play_trainer` → `discard_from_hand` → `convention_applied`（規約 ID・版・場面・コード・`player`・`available` = 0）→ `discard_trainer`。`retrieve_energy` は書かない |
| 判定する時点 | 使う前と費用のあとで選べるものは同じ（ER11） | 使う前（`check_playable`）で場面を判定し、費用のあとにもう一度 0 を確かめる |
| 使用の経路 | — | 初回は手札からの通常の使用だけ（ER9 の D4 と同じ）。錯乱ジム・サイキックコントロール・リムーブ禁止ジムの場は ER10 のまま |
| ポケモンタワー | PT1 が先 | 変えない |
| 超エネルギー回収 | 別のカードの問い（SR1） | 含めない |

**C で新しくできるようになること（回収のほかの効果）:**

1. 手札から選んだ 1 枚を、回収なしでトラッシュに置けます。手札が 2 枚減ります（エネルギー回収と費用）。
2. 費用で捨てたカードは公開のトラッシュに入り、そのあとのトラッシュからの回収の対象になりえます。たとえば、手札に 2 枚目のエネルギー回収があれば、1 枚目の費用で捨てた基本エネルギーを 2 枚目で回収できます（ER7 は「このカードを使うために」捨てたカードだけを除く）。記録では g005 の #18・#20 が、手札にエネルギー回収 2 枚・基本エネルギー 1 枚の局面でした。
3. トレーナーを使ったことになるので、使用に反応する処理（錯乱ジムのコイン・［ちえくらべ］）の対象になります。初回の範囲を手札からの通常の使用に限ると、錯乱ジムの場は外れます。
4. 番を終える前の手が 1 つ増えます。ほかに番を終えることしかできなかった 5 局面（#9・#10・#12・#15・#24）では、番を終えること以外の唯一の手になります。

これらの手に価値があるか（方策が選ぶか・対戦の進み方が変わるか）は、今回の記録では分かりません。件数から完走率の改善は推定しません。

## 5. 推奨: 現状維持

1. **判断の基準（実行できる手が増えるか・拒否や答え直しが減るか）で見ると、** 拒否と答え直しはもともと 0 で、どの案でも減りません。手が増えるのは C だけです。
2. **A で対戦は止まっていません。** 24 局面とも、ほかの操作が選ばれて受理されました。番を終えることしかできなかった 5 局面も、番を終えて対戦は続きました。
3. **B の効果は表示だけです。** そのうえ候補全体の 17 局面が「規約 ID 不明」の区分に移り、記録からカードを特定する手がかりが減ります。採る理由がありません。
4. **C は手を増やしますが、** 増える手の効果は手札 1 枚をトラッシュに置くことだけです。費用・決定・ログ・経路は史料で決まらず、規約で決めることになります。族の案 `PC-USE-WITHOUT-TARGET` の推奨（使えない）とも逆の向きです。今回の件数だけでは、採用の価値を示せません。
5. **C を選ぶ条件:** TR4 で「0 枚を選んで使い終える」ことを認めたので、対象が 0 のときにも同じ終わり方を認めてそろえたい、と利用者が判断した場合です。その場合は、手札からの通常の使用だけに限った規約を、7 章の判断を決めてから設計します。

- これで決まること: B が全経路に同じ形で当たるか、C の初回の範囲の外の経路をどう止めておくか、PT1 との順番。
- 手の価値（方策が新しい手を選ぶか・対戦の進み方）は、規約を実装したあとの比較の対戦でしか測れません（ER9 の比較のバッチと同じ方法）。
