# 番をまたいではたらくワザの効果（v0.12）

v0.12 で、ワザを使ったポケモン自身に「次の相手の番、…ダメージを受けたとき、相手にダメージを与える」持続する効果を与え、相手の番に保持・適用し、期限で消せるようにしました。最初の対応は R団のファイヤーの「ほのおのかべ」（[rocket-moltres-v0.12.md](rocket-moltres-v0.12.md)）です。v0.4b の「かたまる」（`PreventDamage`。[persistent-effects-v0.4b.md](persistent-effects-v0.4b.md)）と同じ「持続する効果」（p.322・p.323）の仕組みに、種類を 1 つ（`state.Retaliation`）加えただけで、新しい置き場所・段階・イベントの仕組みは作っていません。

## 1. 持ち方の比較（B6）

| 案 | 内容 | 採否 | 理由 |
|---|---|---|---|
| A | ワザ 1 回の中の値（`AttackUse`）だけに持つ | 採らない | 効果は「次の相手の番」にはたらく。ワザ 1 回の中の値は番をまたげない（保存・復元・決定の再開でも失われる） |
| B | 状態（`PokemonInPlay.persistent_effects`）に持つ | **採用** | v0.4b の持続する効果と同じ置き場所・同じ消える契機（期限・ベンチにもどる・進化・きぜつ。p.322・p.323）・同じログ（`persistent_effect_added`・`persistent_effect_removed`）・同じ不変条件で表せる。書き出しも形式 8 からある `persistent_effects` の項目で表せる（5 章） |
| C | ログの履歴から求め直す | 採らない | ログは記録で、状態の正本ではない（v0.4e）。進化・入れ替え・きぜつ・保存と復元で古くなる。ログの監査が組み立て直して比べる側に使う |

効果の値（`Retaliation`。frozen）:

| 項目 | 意味 |
|---|---|
| `source_card`・`source_player` | 効果を与えたワザを使ったポケモン（自分自身。p.89「効果の対象：ワザを使ったポケモン自身」）のカードと持ち主 |
| `created_turn` | 効果を与えた番（ワザを使った番） |
| `active_turn` | はたらく番（`created_turn + 1` = 次の相手の番。番は交互に進む。v0.2e・v0.4b と同じ表し方） |
| `attack_index` | 効果を与えたワザの位置（「ほのおのかべ」のダメージを、どのワザによるダメージとして計算するか。`retaliation_use`） |
| `amount` | 与えるダメージ（基本となるダメージ。10） |

効果の対象のポケモン（場のポケモンの番号）は、効果を持つポケモンそのもの（`persistent_effects` の置き場所）なので、値には持たない（v0.4b と同じ）。消える条件は種類ではなく、持続する効果の共通の契機（2 章）で決まる。

## 2. 発生・適用・継続・消失

| 段階 | いつ | 処理 | 規定 |
|---|---|---|---|
| 発生 | 「ほのおのかべ」のダメージ（と相手の「はんげき」）のあと | `DamageAndRetaliation.resolve` → `persistent.add_persistent_effect`（ログ `persistent_effect_added`）。ワザを使ったポケモンが相手の「はんげき」で HP 以上なら与えない（`persistent_effect_skipped`） | W4・W29 |
| 待機 | ワザを使った番の残り・ポケモンチェック | `persistent.retaliation` は `active_turn` が今の番のときだけ返すので、はたらかない（ワザを使った番はすぐ終わる。ポケモンチェックはどちらの番でもない。p.323） | W4 |
| 適用 | 次の相手の番、相手のワザのダメージの要素で（最終ダメージ > 0） | `deal_attack_damage` がダメージをのせる直前に記録（`AttackUse.retaliations`）し、`finish_damage_elements` が与える（`_apply_retaliation`）。与えても効果は消えない | W11〜W25 |
| 継続 | 次の相手の番の終わりまで | 特殊状態・かがくへんかガスで変わらない（W7・W18）。ワザを受けてはたらいても残る（W25） | W5・W7 |
| 失効 | 次の相手の番の終わり | `_end_turn` の `remove_expired_persistent_effects`（ついているトレーナーのトラッシュのあと・ポケモンチェックの前。ログ `persistent_effect_removed`、`reason` `expired`） | W5 |
| ベンチにもどる | ふきとばし（相手のワザの効果）・にげる・ポケモンいれかえ | `remove_persistent_effects`（`forced_switch`・`retreat`・`switch`）。持ち主は相手の番に「にげる」・トレーナーを使えないので、起こるのはふきとばし | W6 |
| きぜつ | きぜつの処理 | `_knock_out` の `remove_persistent_effects`（`knock_out`）。そのあと「ふしちょう」で手札にもどしても、再び場に出しても復活しない | W8〜W10 |
| 進化 | 進化の処理 | `remove_persistent_effects`（`evolve`）。R団のファイヤーから進化するカードはないので起こらない（共通の処理） | p.323 |
| 保存・復元 | いつでも | `GameState` の一部（pickle・deepcopy・clone）。書き出しは形式 8・9 の `persistent_effects`（5 章） | — |

消えた効果は値として残らないので、復活しない（p.322）。ワザを使った番に、効果を受けたポケモンがベンチにもどる・進化することは起こらない（ワザを使うと番が終わる）。

## 3. ダメージの計算と分類

「ほのおのかべ」のダメージは、R団のファイヤーのワザによるダメージ（p.89「「こうらがえし」で返すダメージは「ワザによるダメージ」なので」・p.82「この10ダメージは、弱点・抵抗力の影響を受けます」）。そこで、効果を持つポケモンを「ワザを使ったポケモン」、効果を与えたワザを「ワザ」とする `AttackUse`（`effects.retaliation_use`）をつくり、ふつうのワザのダメージの要素と同じ `deal_attack_damage(state, fire_use, OPPONENT_ACTIVE, amount)` で与える。

- p.321 の計算（基本となるダメージ 10 → 弱点 → 抵抗力 → プラスパワー → ディフェンダー。v0.2c・v0.2e）の発生源は R団のファイヤー、受けるのは相手の対戦ポケモン（ワザを使ったポケモン）。
- 受けるポケモンの「ダメージを受けない」状態（`damage_prevention`）・「とうめい」（`attack_reaches`。v0.9）・「はんげき」（`counterattack_power`。v0.10）・「こんじょう」の記録（v0.11）も同じ経路ではたらく。
- ログは `retaliation` のあとに、ダメージの要素のログ（`damage` に `retaliation`・`effect`・`pokemon_id` を加えたもの、または `damage_prevented`・`evade_check`・`attack_evaded`）。ログの監査は、`retaliation` のあとのダメージを別の窓（`ret`）で数え、基本となるダメージが `amount`・弱点・抵抗力の印が受けるポケモンのタイプと合うことを確かめる。
- 「ダメージを受けたとき」の判定は、きっかけのワザのダメージの要素（`deal_attack_damage`）だけで行う。ダメージが増えたことからは判定しない（こんらんの 20・どく・ダメージスワップ・「はんげき」の 10 では、はたらかない）。

## 4. 「はんげき」（v0.10）との比較（B8）

| | はんげき（カイリキー。v0.10） | ほのおのかべ（R団のファイヤー。v0.12） |
|---|---|---|
| 効果の種類 | 自動的にはたらく特殊能力（`PowerEffect`。`declared = False`） | ワザの効果（持続する効果 `Retaliation`） |
| 有効期限 | なし（場にいて、はたらいている間ずっと） | 効果を与えた次の相手の番の終わりまで（W5） |
| 置き場所 | カードの定義（登録表）から問い合わせのたびに求める | 場のポケモンの `persistent_effects`（状態） |
| 発動条件 | 相手のワザによるダメージを受けたとき（最終ダメージ > 0） | 次の相手の番に、相手のワザによるダメージを受けたとき（最終ダメージ > 0） |
| 止める状態 | ねむり・マヒ・こんらん・かがくへんかガス | なし（特殊状態・ガスで止まらない。W7・W18） |
| ダメージの分類 | 特殊能力によるダメージ（ワザによるダメージではない） | R団のファイヤーのワザによるダメージ |
| 弱点・抵抗力 | 計算しない（「「弱点・抵抗力」に関係なく」） | 計算する（p.82 の解説） |
| プラスパワー・ディフェンダー | 計算しない | 計算する（受けるポケモンのディフェンダー。W17） |
| 「とうめい」 | はたらかない（ワザではない） | はたらく（W19） |
| 受けたポケモンの「はんげき」 | はたらかない（連鎖しない） | はたらく。その「はんげき」のダメージで「ほのおのかべ」は再びはたらかない（W20） |
| 受けたポケモンの「こんじょう」 | 使えない（ワザのダメージではない。v0.11 の G5） | 使える（相手のワザによるダメージ。W26） |
| 与える時点 | `finish_damage_elements`（ダメージの処理のあと、効果の前。p.89） | 同じ（W21） |
| 与える相手 | ダメージを与えたポケモン（ワザを使ったポケモン） | 同じ（「そのダメージを与えた相手の対戦ポケモン」） |
| ワザを使ったポケモンがすでに HP 以上 | 与えない（`counterattack_skipped`。C15） | 与えない（`retaliation_skipped`。W23） |
| 両方がきぜつ（原典で決められない） | `UNRESOLVED_COUNTERATTACK_DOUBLE_KNOCKOUT`（C18） | `UNRESOLVED_RETALIATION_DOUBLE_KNOCKOUT`（W24） |

共通にしたのは、原典で同じとわかる部分（与える時点 `finish_damage_elements`・与える相手・すでに HP 以上なら与えない・1 つのワザで合わせて 2 つ以上なら `RuntimeError`・宣言の前の止め方（ダメージの候補の組 `pairs()` と `preview_attack_damage`））だけ。ダメージの計算と分類は違うので、`_apply_counterattack` は流用していない。

## 5. 保存形式（B7）

形式 9 のまま（新しい形式 10 は加えていない）。

- 形式 8（v0.4b）から、場のポケモンごとの `persistent_effects`（`{"effect": 種類, "source_card", "source_card_id", "source_player", "created_turn", "active_turn"}` の並び）がある。v0.12 は種類の値 `"retaliation"` を加え、その種類だけ `"attack_index"`・`"amount"` を加えた。ほかの種類（`"prevent_damage"`）の形と、項目の意味は変えていない。v0.3b〜v0.3c が特殊状態の種類の値を加えたときに形式を変えなかったのと同じ扱い。
- 形式 9 で表せない状態はない: 効果の値の項目はすべて書き出す（`attack_index`・`amount` を含む）。「ふしちょう」の決定・サイドを取る決定の `"post_knockout"` は、既存の `decision` の項目（形式 2 から）で表す。
- 古い形式との関係: 形式 1〜7 は持続する効果を表せないので、効果があれば `ValueError`（v0.4b と同じ）。形式 1 は「ふしちょう」の決定・`"post_knockout"` を持つサイドを取る決定があれば `ValueError`。効果も決定もない状態は、形式 1〜9 で v0.11 と同じに書き出す（tests/test_compat_v0_1.py・比較の駆動の参照データは変わらない）。
- 新しい形式から古い形式への変換: 効果・決定のない状態はそのまま。効果のある状態は形式 8・9 だけ。
- 読む側: エンジンに書き出しから状態を戻す関数（`state_from_dict`）はない（v0.11 と同じ）。書き出しを読む側は、知らない種類の効果のある辞書を拒否すること（形式の番号だけで判断しない）。
- 監査: `serialization_problems`（tests/log_audit.py）は、形式 1〜9 が表せる状態だけを書き出し、最新の形式（9）から後の項目を除いたものと同じになることを確かめる（`required_format` に、`"post_knockout"` を持つ決定は形式 2 以上を加えた）。

形式 10 が要るのは、状態に新しい項目（番ごとの回数・期限のある常にはたらく効果など）を加えるとき（CLAUDE.md）。

## 6. 不変条件

`engine._persistent_effect_problems`（v0.4b）に `Retaliation` を加えた:

- 型が `PERSISTENT_EFFECT_TYPES`（`PreventDamage`・`Retaliation`）。番・ワザの位置・量が整数
- 発生源が自分自身（いまのカード・持ち主）、効果を与えた番が持ち主の番、はたらく番が次の番、期限が過ぎていない（はたらく番の `turn_end` のあとに残らない）
- 置き場所がバトル場だけ。同じ種類は 1 つまで
- ログとの対応（`persistent_effect_added` があり、そのあとに消したはずのイベントがない）
- `Retaliation` の `attack_index` がこのカードのワザの位置で、そのワザに `DamageAndRetaliation` が登録され、`amount` がその実装の値（`_retaliation_problems`）

ワザの途中の決定（ふきとばし・じこさいせい・エナジーへんかん）を出すときに、与えていない「ほのおのかべ」が残っていたら `RuntimeError`（`push_attack_decision`。決定をまたいで記録が失われないように）。

テストで効果を置くときは `build_test_state` の `"retaliation"`（効果を与えた番）を使う（今の番 − 1 の番を渡す。期限が過ぎた効果は不変条件の違反）。

## 7. これから番をまたぐワザの効果を加えるときの約束

- 置き場所は `PokemonInPlay.persistent_effects`、付ける・消す・調べるのは kyuura_engine/persistent.py だけ（v0.4b）。種類を加えたら `PERSISTENT_EFFECT_TYPES`・書き出し（`_persistent_effect`）・不変条件・ログの監査を更新する。
- 相手に与える効果（すなかけ・からまるいと）は、発生源が自分自身という不変条件を見直す。カウンター・マーカーをのせるタイプ（ベンチにもどっても消えない）・期限のない効果は、消える契機を見直す。
- 「ダメージを受けたとき」にはたらく効果は、`deal_attack_damage` の記録と `finish_damage_elements` の時点（p.89）を使い、ダメージの分類（ワザ・特殊能力）を原典で確かめる。1 つのワザで 2 つ以上はたらく場合の順番（C34・C35 と同じ問い）は、宣言の前に止める処理を加える。
- 効果のダメージで両方がきぜつしうるなら、C18・W24 と同じく宣言の前に止める（`damage_profile` の `pairs()`）。
